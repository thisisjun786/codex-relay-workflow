# Todo 36: test_fence.py and test_takeover_candidate.py

These two class-A files are the Python tests of the final Python fence release (todo 36; docs/port/cutover.md). They assert what the retained Python writer does on its side of the cutover protocol: it refuses or queues when the other runtime owns the store, replays its own takeover inbox, answers over its own control socket, binds its own store to its first socket, and runs as the reverse-direction takeover candidate. **Converted** and **blocked** mean what they mean in the other notes; no case here is either. **Kept** means the source test stays as Python code, with the reason in its row. Every case below is kept, for one or more of these reasons:

- `relative`: the expectation is relative to the runtime under test. The case stamps the store as owned by `go`, or by `python` in phase draining or starting, and asserts that the Python writer refuses or queues. A contract fixture runs both runtimes against one expectation, and Go admits the store Python must refuse, so no shared scenario can state it.
- `interleave`: contract/README.md's live-interleave exception. The case patches a Python function, injects a failure or a clock reading at an exact point, or synchronises threads or processes mid-operation. No fixture can place that change.
- `python-api`: the case calls Python modules (inbox, ownership, takeover, stopadapter, control, RelayService) directly rather than running a program, so no run kind can drive it.
- `inbox`: the case needs an owner that replays `S/takeover-inbox`. Both runtimes replay it since todo 31, but each case injects a crash, a lock or a concurrent sender into Python internals mid-operation, so it stays a Python test with a named Go counterpart instead of a shared fixture.

Each row names the Go test that holds the same property for the Go runtime where one exists. A row marked Python-only has no Go counterpart: the behaviour belongs to the Python fence release alone. Every case stays a Python test until todo 44 removes the Python execution path, and the Python writer it fences goes with it.

Counts: test_fence.py 60 = 0 converted, 60 kept, 0 blocked. test_takeover_candidate.py 14 = 0 converted, 14 kept, 0 blocked.
