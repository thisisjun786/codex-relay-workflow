## Shared mechanism

Some recorded answers carry values derived from an absolute path: a manifest revision hashes each
artifact's declared path, event and request ids hash the revision, and a workspace key or socket
scope hashes a directory. A textual placeholder cannot move those values to another directory.

So when a test shares such a path with Python, the path is a fixed directory rather than a fresh
temporary one:

- **delivery:** `/tmp/crw-delivery-parity/<12 hex of the test name>`. See `parityTree` and
  `processParityTree` in `pyoracle_test.go`.
- **cli:** `/tmp/crw-cli-parity/...`. See `oracle_support_test.go`.

Each fixed directory is:

- held under `flock` on an adjacent `.lock` file while in use, so two test processes never share
  it;
- emptied before use and removed afterwards;
- written into recordings only as a placeholder, such as `<tree>`.

The `.lock` files stay in the fixed root. Removing a lock file that another process may be
waiting on would break the lock.

Recorded Python-created SQLite stores (the delivery CLI seed, the SR-22 store, the
omitted-capture snapshots and the selection stores) are gzip-compressed. When Python is live they
are first neutralized in place (`neutralStore`):

- the random `store_id` and the wall-clock `store_created_at` become constants;
- device and inode numbers in JSON rows become 0;
- a managed start's request fingerprint (a digest over the store's device and inode) becomes a
  constant;
- `VACUUM` lays the file out the same way every time.

The Go reader under test reads none of those values. The neutralized file is also what the Go
side runs on in record and check mode, so every mode sees the same input.

How each helper records Python's answer:

- **`runPython`** records the scenario's JSON line, with the fixture tree and home as
  placeholders. **`runPythonOut`** is the same for the 13 tests that read only Python's `out`
  block and sends (DEL-8, DEL-9, DEL-27, DEL-28, DEL-30, DEL-32, DRL-1..4, MPI-2..4). It leaves
  the tables out, and in check mode compares the answers as JSON values, because MPI-3's
  `next` dict is filled by racing threads.
- **`pythonCapture`** records each Python test's `capture.json`: its asserted values, its sends,
  and the tables a mirror compares. The re-review tables are kept only for `test_rereview_deadlock`.
  The module's tree root is a process-lifetime fixed tree. The captured Python runs its relay
  package from a copy in a fixed tree (`pythonPackageDir`). The fault sweep puts the package's
  resolved directory into every observation's evidence and digests it, so a checkout's own
  path would otherwise sit inside `evidence_digest`. The Go sweeper is given the same directory.
- **`runMarkerOps`** is keyed by a digest of the op list. A conflict's `loserProcess` pid is
  stored as `<pid>`; the comparison already treated it as one token (`withoutPID`).
- **The Python CLI side** of `cliSide`:
  - Each command's exit code and stdout are recorded under a per-side counter. Wall-clock stamps,
    staged ages and pids are stored neutral; the comparisons already masked them (`normal`,
    `ageless`, `loserProcess`).
  - The Python side's own store is created only in record and check mode.
  - The Go side's `sqlite3` one-liners (`!sql`, `sqliteDump`, the relationship-id read) are now
    Go reads and writes of the same file (`goSQLiteDump`, `goSQLiteExec`), formatted with this
    package's `json.dumps` twin.
  - The seed that Python's registry creates is recorded once as `CLISeed.json`.
- **`captureOmitted`** records `capture.json` and, for each observe call, the tree the call read,
  as a neutralized, gzip-compressed tar (`archiveSnapshot` / `restoreSnapshot`). The tar keeps
  FIFOs, symlinks and modes.
- **The selection tests** record Python's refusal bytes. The Go side's Python-created store is
  recorded (`recordedPythonStore`); it is a static fixture, not a live share.
- **`TestAMarkerRootIsTheDirectoryPythonNames` and
  `TestAWrongSocketRecovery...`** no longer call `t.Chdir`. `$PWD` still spells the alias, and
  only the Go call runs inside the alias directory (`inDirectory`), because pyoracle files
  recordings relative to the package directory. The wrong-socket subtests are named without the
  run's directory or the user's name. The passwd home and `~user` are recorded as
  `<user-home>` and `~<user>`.

The survey called `recovery_parity_test.go` and `marker_root_test.go` parity-tagged. They are
default-build tests, and they are converted.

Test25_CLI21 (verdict → sync outbox) used to have Python write the Go side's store. Its Python
half is now recorded. Its Go half stages the same acknowledged completion through this package's
own services (`stageAcknowledgedCompletion`), and the test requires both sides to stage the same
event id.

Three Python drivers were edited for determinism, with behaviour unchanged:

- `testdata/omitted_capture.py` names its fixture directories in creation order instead of at
  random.
- `testdata/sr22_render.py` accepts an optional fixed fixture tree.
- The captured Python package is copied, not edited.
