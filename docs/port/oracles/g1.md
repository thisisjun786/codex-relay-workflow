The Go tests in `internal/relay/supervisor`, `internal/relay/evidence` and
`internal/relay/managed` no longer run the Python implementation by default. Each test that
asked Python for its answer now reads the answer Python gave from a recording under its
package's `testdata/python-oracle/` (`internal/testsupport/pyoracle`). The Go half of every test
still runs live. `CRW_PYTHON_ORACLE=record` rewrites the recordings from the live Python, and
`CRW_PYTHON_ORACLE=check` compares the live Python with them. Both modes need a checkout that
still carries the Python implementation. The capture code, including the `testdata/*.py`
drivers, is unchanged and runs only in those two modes.

A test counts once however many answers it records. Subtests that ask Python themselves keep a
recording each, and those account for the extra files.

Nothing was deleted or replaced. No test in these packages reads Python source. Every test that
had Python and Go share a store or a state directory compares output parity. Python's side
effects only prepared the input for the Go half or answered after Go on the same input. The
input is now recorded, and so is the answer, as described under each package below. No test
still needs Python.

## How the answers are recorded

### evidence

- `pythonCapture` (`testdata/capture.py`, behind `whole`) records the driver's JSON answer under
  the scenario id.
- The envelope accessor oracle, the `json.dumps` byte oracle and the `repr` byte oracle are
  recorded in the parent test. Their subtests share one recording.
- `Test24_SEV_9`/`Test24_SEV_10` (`sevDirectiveBytes`) used to run Go on a SQLite backup of the
  store Python's `linkage-supervise` created. Go now runs `linkage-supervise` on its own store.
  The link id is a digest of the scope keys, so both runtimes derive the same one. Python's
  answer to each `linkage-directive` is recorded with Go's `recordedAt` as a placeholder. In
  record mode Python runs the same sequence on its own store.
- `Test24_MEE_2` reads the merge turn oracle from `testdata/merge_turn_oracle.json`, a copy of
  `packages/codex-session-relay/tests/fixtures/merge_turn_oracle.json`.

### managed

- `capturePythonManaged` (`testdata/capture.py`) records the capture with the tree it ran in as
  `<root>`. The fake host's ledger file gets a fixed device and inode (4242/777000), and a
  replaced ledger gets inode+1, which is what the Go fake is given. For `execution-cli`, the
  real CLI on a real store, each store id, the store's creation time and every other time, and
  every inode become fixed values. The tree's device becomes a token that replay turns back into
  the device of the replaying tree. The marker directory's workspace key is substituted too.
  `normalizedExecution` compares none of these except the device.
- Request fingerprints are digests of physical paths, which `normalizedManaged` compares as
  `<physical fingerprint>`. They are recorded as fixed values numbered in order of appearance.
- The two Python thread races (`reservation-threads`, `reservation-arm-release`) are checked by
  accepting any outcome the tests accept, because a rerun can change which thread wins. Their
  recordings are the only ones a rerun of the managed recording changes.
- In every mode the Go half gets the `workspace` directory that Python's run created. The
  request names it as its cwd.
- `Test27_MST_9_MissingWorkerRefusesBeforeStoreCreation` records Python's exit code and stdout.
  It used to run Python after Go on the same absent state directory. `Test27_MST_9_MissingStateOrSocketUsage`
  and the receipt-accessor and `parse_request` repr oracles are recorded in the parent test.

### supervisor

`pyoracle_tree_test.go` holds the package's recording helpers:

- `pythonOutput` and `pythonJSON` record what a Python run printed. They substitute the
  repository root and canonicalize two run-specific things:
  - each Python fixture's own temporary tree (`$TMPDIR/relay-test-XXXXXXXX`) becomes a fixed
    name of the same length, because the reports measure the bytes they render;
  - each time Python took from the wall clock during the run becomes a fixed time after
    2026-09-28 that keeps its order.

  In check mode an answer matches the recording up to a consistent renaming of hex runs of 12
  or more digits. The Python fixtures mint event ids at random, and every message id,
  revision hash and digest derived from one changes with it. In replay nothing is renamed: the
  Go half reads the recorded ids.
- `pythonTree` also records the files a Python run leaves under its root and the Go half then
  reads: the fixture's store, the snapshots the capture drivers take (`setup`, `event`,
  `pre-N`, SOS tree copies), `capture.json` and marker files. Each SQLite store is recorded as
  its rows, table by table and typed (`storeDump`). It is rebuilt on the schema Go creates,
  which must have the recorded schema digest. A database that is not a relay store is kept
  whole. Each store's random `store_id` and its creation time get fixed values. In every mode,
  record included, the directory is emptied and rebuilt from the recording, so the Go half reads
  the same tree whether Python ran or not. Mirrors, locks and WAL files are not recorded. A
  restored store gets its mirror from the ownership fixtures, as any copied store does.
- `goWallTimes` substitutes the wall-clock times Go wrote when a Python answer reads them back
  from a copy of Go's store (`supervisorBinaryPython`). The same rule covers the other values
  Go's run draws that a Python answer on a copy of its store names. For example, `devinTokens`
  substitutes the delivery tokens of Go's attempts.
- A few values are digests of a path under the capture's root, so a replay in another root has
  to derive them again instead of substituting them:
  - The SOS marker directory is the workspace key of `<root>/tree/work` (`sosWorkspaceKey`).
  - Each receipt's revision hash is the hash of a manifest that names files under the root. For
    the SOS captures (`pythonTreeRevisions`), whose replay verifies stored receipts against
    their manifests, the hash is recorded as a placeholder per event and derived again from the
    restored manifest.

Helpers converted: `pythonSupervisorCapture` and `supervisorMirror` (`testdata/capture.py`). They
keep only the snapshot the test restores, and Python's final store only for
`Test24BuiltBinaryRoundtripStoreBytes`. Also converted:

- `captureORDChannel`, `set1Capture`, `pythonSet2`, `Test24_RC_14_LegacyWholeMessage`,
  `pythonReportCapture`, `partCPython`, `partDPython`, `slfPython`, `rrCapture` (RES/RCF),
  `captureSOS` and `sosPythonCLI`;
- `selectionPython` (standing, status, envelope, event, select and select_event answers on a
  Python-owned copy of the fixture store), `supervisorBinaryPython`, `recheckPython`/`recheckCopy`,
  `compareRCLBytes`, `reportingCLIParity`;
- the `t24_devin` and `sweep24` copy-and-run helpers, the report-gate, CLI-byte and JSON
  accessor oracles.

A Python copy of a Go store that has to be taken before Go answers is taken only when Python
runs (`pyoracle.Live`).

Three tests had the runtimes take turns on one store. Each is kept as parity with the Python
answers recorded, and each passes in replay with Go answering alone:

- `Test24BuiltBinaryRoundtripStoreBytes` handed Python's final store to Go and back for five
  CLI commands.
- `Test24_ObservationFilesBuiltBinaryBytes` had both runtimes answer on one state directory in
  turn.
- `Test24_SOS_5_BuiltBinaryBytes` ran Python's read-only surfaces after Go on the same snapshot.

None of the three depends on a Python write: the Go half passes when Python never runs.

## Recordings

Recording sizes (`du -sb`):

| package | size |
|---|---:|
| evidence | 40 KB, plus the 6 KB `merge_turn_oracle.json` copy |
| managed | 412 KB |
| supervisor | 14.6 MB |

Total: 15.1 MB. The supervisor share is what its 336 tests compare, plus the store snapshots the
Go half starts from:

- the whole-table dumps of `capture.json`;
- the RES/RCF and SOS runs, which snapshot the store before every operation and dump every
  table after it.

Of the 539 supervisor files, 18 are above pyoracle's 256 KiB compression threshold and are stored
gzipped. All 539 gzipped would take about 2.1 MB, and a 32 KiB threshold would give about
6.1 MB. That would be a change to the shared helper, so it is left to its owner.

A supervisor re-record rewrites the ids the Python fixtures draw at random and the digests
derived from them. Check mode accepts such a rename.

The recordings name no path, host or user of the machine that made them. The exceptions are
fixed literals that both runtimes are handed:

- `/tmp/work`, `/tmp/markers` and `/tmp/socket` in the managed reservation identities;
- `/tmp/markers`, `/tmp/My Project` and `/tmp/s` in the supervisor fixtures;
- `/tmp/relay-test-88j4jj93`, `-op9o1h2r` and `-t6fxum9g`, which the checked-in
  `testdata/sweep24` seeds carry.
