Group g5 owns `internal/contracttest`, `internal/skill` (with `plugins/skill_assets.go` and the
crw-run skill's hook-probe replay), `internal/dev/ci` (the contract checks only),
`internal/dev/stopevents` and `internal/dev/pyload`. Beyond replacing live Python with recorded
answers (`internal/testsupport/pyoracle`), g5 removed every run-time and CI dependency these
packages had on a Python file, so that phase C can delete the Python scripts and packages without
breaking the build, the contract corpus or `crw-dev ci contracts`.

`packages/*/tests` and every `.py` under `scripts/`, `plugins/` and `contract/`, with failing
`python3`/`uv` shims first on PATH) passes every test in these packages, and `crw-dev ci contracts`
and `crw skill hook-probe replay` exit 0 there.

## internal/contracttest

The corpus is strict-clean: `CRW_CONTRACT_STRICT=1 go test ./internal/contracttest/...` prints
`skipped: 0 domains not ported`, with no skipped scenario.

- `records` (42 fixtures) is ported. `runHook` accepts it for `hook`, `stop` and `status`; a
  status run with `document: true` prints the Go installer's settings document. The new
  `agreement` runner runs `crw hook` under the checkout and the plugin-owned settings documents,
  each in its own home with its own guard peer, and requires the same printed answer and the same
  journal record apart from the six volatile fields `contract/runner/files.py` excludes
  (`configuration`, `journalledAs`, `at`, `elapsedMs`, `guardElapsedMs`, `identityScanMs`). The
  new `release` runner reads the step's shell block from `.github/workflows/release.yml` with
  `release_steps.py`'s grammar and runs it with bash in a fresh clone, beside copies of the fake
  `gh` and `git`. `set_eq` and `subset` compare an object's keys, as Python's `set()` does.
- Seven agreement scenarios expect what only the Python subprocess adapter could answer (a
  signalled guard, guard exit statuses 7 and 9, an exec error naming `relayExecutable`).
  `records.go:nativeDivergences` holds those checks, and only those, to the native answer with a
  reason each (the guard is the owner's control socket, decisions 22 and 32), and fails when a
  fixture stops making the check it replaces. The fixtures stay as the Python corpus run reads
  them; phase C should rewrite them to the native values and remove the table (contract/README.md).
- The hook runner is self-contained: `${PYTHON}` is a shell stand-in answering the status version
  probe and `${ENTRY}` a stand-in `completion_hook.py` (the fixtures observe its presence and the
  probe, never its execution); `stop_event_r1.json` is read from `contract/golden`.
- Converted to recordings (7): Test33NativeCrashAndRejectionPython,
  TestArgumentRefusals_fall_where_the_python_fence_puts_them,
  Test27_CCL1_capacity_and_region_commands_are_registered_offline_and_not_marker_commands,
  TestFaultF1CommandsBuiltCLI, TestRoutingCommandsPythonArgparseBytes,
  Test24IntentDeclareSamePathMatchesLivePythonBytes, Test24Todo24ArgparseSweepMatchesLivePythonBytes.
  The capacity, registry, linkage, mergeturn and mcp_parity tests already read committed
  recordings, and `mcp.go` runs no Python.
- Replaced: `TestDomain/sqlite-ddl` DDL compares Go's `sqlite_master` with a copy of the committed
  `contract/fixtures/sqlite-ddl/python-store.sqlite3` instead of a live Python store.
- Deleted half (cross-runtime interop): the `sqlite-ddl` `locks` check's second process was
