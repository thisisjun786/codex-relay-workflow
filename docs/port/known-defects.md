# Known defects and intentional port differences

- CRW-238: the admitted-turn scan has an open performance defect. The Go fault sweep must not silently change its scan shape as part of this port; the owning issue tracks remediation.
- Todo 22 replaces Python's dynamic `--kind-module` imports with a static fault-kind registry generated from the Python declarations in `contract/schema/fault-kinds.json`. The native binary accepts `codex_session_relay.projects`, `json`, and `os.path` as registered module names without importing Python. Arbitrary importable modules outside this registry are refused with exit 4, naming the first unregistered module. Empty and relative names retain Python's exit 3 host-error shape. This intentional compatibility difference removes dynamic publication-kind registration; it does not add a publication kind.
- Python `FaultLedger.record` only calls `_rescope` when an observation changes `scope_key`. An observation that changes scope metadata such as `issueKey` while retaining the same workspace and `projectKey` therefore leaves the old serialized scope in `fault_ledger.scope`. Go preserves this observable behavior for parity; `TestRecordReviewFindingsWholeOutput/same_target_key_does_not_update_scope_text` compares the complete CLI replies and every SQLite table with live Python.
- The development judges `crw-dev stop-events` and `crw-dev trial-ledger` read a JSON record as deep as a Python writer could have written one, not to encoding/json's 10,000: CPython 3.14.4's C scanner, which has no nesting limit of its own, stopped at 57,930 containers through `stop_events.py` (a journal row) and at 57,929 and 57,955 through `trial_startup.py ledger` (a ledger line, the start record) on the default 8 MiB stack, so the judges read 57,900 (`internal/dev/pyload.MaxNesting`) and refuse a record nested deeper as one they could not read, in encoding/json's terms (refactor R3, decision R3R-2; until then they modelled the interpreter's `RecursionError` at that edge as a reader fault). A record Python wrote between 57,900 and its edge is refused where Python read it. Only a forged record nests this deep: the fields a reader leaves untyped are copied from the relay's own verdict, a few containers deep. `TestLoadsReadsAsDeepAsAWriterWrote`, `TestSEV12_OnDiskFormIsTheWriters` and `TestLedgerReadsRecordsAsDeepAsAWriterWrote` hold the depth.
- repr() in the port (`pyvalue.StrRepr`, which is `settings.Repr`, and `store.PathRepr`) escapes what `str.isprintable()` refuses under CPython 3.14's Unicode database, 16.0.0, pinned as a table generated from that interpreter (`settings.Printable`, `go generate ./internal/bridge/settings`), not under Go's own tables (Unicode 17.0.0). The judges, the trial ledger's refusals, `crw hook`'s row details, the relay CLI's echo of an argument (argparse's `invalid choice` and every refusal naming a value) and the doctor's `socketConnect` therefore spell a path or value as CPython 3.14 does. A Python on another Unicode version spells a character assigned between the two versions otherwise: CPython 3.13 (15.1.0) escapes one assigned in 16.0.0 (U+1C89) that 3.14 and the port print, so under 3.13 `stop_events.py` reads a decision-22 row naming such a state directory as unreadable where `crw-dev stop-events` reads it TRUE. The comparisons that establish the judges' parity use CPython 3.14.4. `TestPrintableIsCPython314sIsprintable` holds the table against the interpreter on PATH when it is 3.14.
- The Go owner reads a `control.sock` request to the nesting budget of `control.py`'s `GuardServer` serving thread as measured under CPython 3.13, the interpreter the fence and the live oracle run (`hook.readRequest`, `controlDepth` 9996 with `pyjson.ErrorWithBudget`): 9996 containers are read and the 9997th raises `RecursionError`, and a refusal raised within four levels of that edge, or a `NaN`, `Infinity` or over-long integer at it, raises `RecursionError` too ([cutover.md](cutover.md), the Python control server). The fence package allows CPython 3.11 and later (`requires-python = ">=3.11"`), and the budget was measured under 3.13 only, so under 3.11 or 3.12 the fence's edge may sit a few levels away from Go's fixed 9996, and a request nested within those few levels of it can be answered `RecursionError` by one owner and read, or refused with a `JSONDecodeError`, by the other. Only a forged request nests this deep: a real client sends the host's Stop payload, a few containers deep. `TestControlReadsEveryFrameAsControlPyReadsIt` and the depth rows of `Test30ControlPeerFailuresAreAnsweredAsPythonAnswersThem` compare with the interpreter the oracle runs, so an oracle of another version fails them rather than passing (PR #203 review 4143327574).
- A relay CLI argument that is not UTF-8 (an argv byte such as 0xff, which Python holds surrogate-escaped) is refused where the fence first encodes it, in both runtimes, except in the cases listed under "Python defects not carried over" below. Every string bound on a connection opened through the relay store's guarded driver (`store.EncodeUTF8`: the store's own connections, and its read-only diagnostic reads such as `store.ReadOnlyRows` and `store.NonceLookup`) is checked as `sqlite3` binds a str, and the identities the fence hashes before it reads anything (the relationship, linkage, marker, merge-target and edit-region identities, and the managed-start request) refuse it there. Two connections open the plain driver and are not checked: `delivery.omissionReceipt`, the read-only receipt lookup behind the omission observation, and `ownership.OpenExisting`, which the takeover controller and the ownership snapshot reads open. `cli.main`'s host error (`UnicodeEncodeError: 'utf-8' codec can't encode character '\\udcff' in position N: surrogates not allowed`, exit 3) therefore names the same position, `doctor --issue` and `doctor --expect-nonce` included once the store holds the table the lookup reads (their read-only lookups catch `sqlite3.Error` only, so the error escapes; both runtimes prepare the statement before binding it, so over a file without that table, or one that is not a database, both answer the prepare failure as a reading instead), and nothing Go writes through the guarded driver is TEXT that Python's `sqlite3` cannot decode. A value the fence stores inside JSON (an artifact root, an intent marker's issue key) is stored as the same text (`"\udcff"`), and an argument echoed in a refusal prints as Python prints it. Two differences remain here, in what is printed or answered, and neither is a difference in what is stored: the artifact root's TEXT and the marker's bytes are the same from either runtime, and the repeated `intent-declare` leaves the marker's bytes unchanged in either. Go's JSON readers decode a stored `"\udXXX"` escape as U+FFFD (encoding/json), so a command that prints such a stored value back prints `\ufffd` where Python prints `\udcff` (`register`'s `authorizedScope.artifactRoots` for a non-UTF-8 `--artifact-root`). And a Go reader compares such a value unequal to the argument that wrote it: `intent-declare` repeated with the same non-UTF-8 `--issue` over the marker already published for it answers `conflict` (exit 0), where the fence answers `unchanged`, whichever runtime published the marker. Where one runtime writes and the other refuses, or the two refuse differently (a fault command's JSON argument, `emit --artifact`, and `register`'s `--parent-settings`/`--child-settings` beside `settings-record --settings`), the entries under "Python defects not carried over" say what each answers. `TestAnArgumentThatIsNotUTF8IsRefusedWherePythonEncodesIt` compares the answers to 32 command lines, and the stored artifact root, with the fence; `TestAStoreRefusesToBindAStrPythonCannotEncode` and `TestEncodeUTF8IsStrEncode` hold the check.

- `crw skill hook-probe`, `crw skill parent-title` and `crw skill start-policy` no longer emulate Python's argparse: since refactor R3 (decision R3R-3) each command reads its flags with Go's flag package (`-flag` or `--flag`, no unique-prefix abbreviation, `--` ends the flags), and a usage error exits 2 as before. The skills name these commands with fixed, fully spelled argv (`hook-probe observe` with `--sanitize`, `hook-probe replay`, `parent-title decide` and `replay`, `start-policy vocabulary`, `check` and `selftest`), which read as they did.

## Python defects not carried over

- **Python defect not carried over:** `daemon._gate` fingerprint omits the receipt turn id (`daemon.py:~993`), so an accepted receipt that gains a turn id later is never reconciled; Go includes it (`TestReconcilePass_receipt_gains_turn_id`).

- **Python defect not carried over:** `registry.bind_anchor` (`registry.py:790-822`) reads the pending anchor before beginning its transaction. Concurrent binders can overwrite a generation's dispatch turn after one has already succeeded, violating the never-rebind invariant. Go reads and decides inside the write transaction; `TestBindAnchor_concurrent_turns_never_replace_the_winner` proves only one distinct turn binds and the loser is refused.
- **Python defect not carried over:** `ack.bind_dispatched_revision` (`ack.py:1026-1035`) rejects acknowledged revisions even though `ack.bind_pending_anchors` (`ack.py:1037-1060`) selects them for recovery. This violates the invariant that every dispatched revision's pending anchor can recover after acknowledgement. Go accepts both states; `TestBindPendingAnchors_recovers_acknowledged_revision` proves the recovery binds and is idempotent.

- **Python defect not carried over:** `trial_startup.py ledger` writes a ledger line's operator fields back through the recursive `shown()` (`trial_startup.py:518-530`) when it refuses one that is not text. Under CPython 3.14.4 a `segment` or an `actor` nested 997 containers deep or more passes the interpreter's recursion limit there, and the run answers "this run raised before it could report" (`RecursionError`, raisedAt `trial_startup.py:529`), exit 2, where Python's own comment (`trial_startup.py:3031-3034`) says a structured segment is refused by name rather than raised as an internal error about something the operator wrote. At 996 and below both runtimes refuse by name. `crw-dev trial-ledger` refuses by name at every depth, exit 2 either way; only a forged ledger nests this deep. `TestALedgerFieldNestedPastPythonsRecursionLimitIsRefusedByName` pins the refusal at 1000 for a segment and an actor. The `target` and `action` fields take the same path and were not measured.

- **Python defect not carried over:** `supervisor-report-recorded --event=` satisfies argparse's required mutually-exclusive group, then the handler treats the empty event as false and calls `_observation_file(None)`, raising `TypeError` and exiting 3. Go retains a parser usage exit instead of reproducing the crash.

- **Python defect not carried over:** a lone surrogate that reaches stdout. Under the oracle's pinned stream (decision 29b, `PYTHONIOENCODING=utf-8:strict`, as on an `en_US.UTF-8` host) Python's `print` cannot encode a lone surrogate, so it raises `UnicodeEncodeError` and exits 1. Go writes the output. Only a JSON escape such as `\ud800` in a request or record can put one there, since both runtimes refuse input bytes that are not UTF-8. Two commands reach it:
  - `crw skill parent-title decide` with a lone surrogate in `observed_title`, or in the `family_candidates` and `project_labels` entry that becomes the prefix. Python writes nothing to stdout and exits 1. Its stderr is a traceback whose last line is `UnicodeEncodeError: 'utf-8' codec can't encode character '\ud800' in position 17: surrogates not allowed` for `"observed_title": "Body\ud800"`, where the position is the character's offset in the JSON reply. Go writes the whole reply to stdout and exits 0 with an empty stderr. Each lone surrogate becomes three U+FFFD (`EF BF BD` three times) in `body` and `title`, or in `prefix` and `title`, because encoding/json replaces each byte of its WTF-8 form.
  - `crw skill hook-probe replay` when a host observation records a Stop field type that is not a JSON type name, under a field whose name is a lone surrogate. The case used here has capability `required` `["\ud800"]`, observation `fields` `["\ud800"]` and `types` `{"\ud800": "s\udc00"}`. Both runtimes write the same report lines before that point and exit 1. Python's `print("HOST OBSERVATION: " + problem)` raises, so that line and any after it are missing from stdout, and stderr ends with `UnicodeEncodeError: 'utf-8' codec can't encode character '\ud800' in position 128: surrogates not allowed`. Go writes `HOST OBSERVATION: host-observation-codex-0.154.0.json: the recorded Stop field types name something that is not a JSON type for ` and then the surrogate's WTF-8 bytes `ED A0 80` to stdout, and its stderr is empty.

- **Python defect not carried over:** a fault command's JSON argument that holds a lone surrogate, as a `"\udcff"` escape or as an argv byte that is not UTF-8: `fault-observe --observation`, and `fault-queue --payload` for an extension kind such as `project_create` (`--kind-module codex_session_relay.projects`). The fence's `json.loads` keeps the surrogate and raises where it first hashes or binds it: `cli.main` answers the host error `UnicodeEncodeError: 'utf-8' codec can't encode character '\\udcff' in position N: surrogates not allowed`, exit 3, and nothing is written. Go's reader (encoding/json) decodes the escape or the byte as U+FFFD, so Go records the observation and queues its `open_record` publication, or queues the `project_create` publication with its payload, exit 0, storing U+FFFD. Go's answer is kept: what it stores is valid UTF-8 text that both runtimes read back, where the fence's refusal is an accident of its interpreter holding a string it cannot encode, not a check it states. The cost is that two observations differing only in which lone surrogate they hold are one fault in Go. `fault-observe --adopt` and `fault-queue --payload` for the built-in `append_comment` also answer exit 0 in Go where the fence raises, but only because the Go CLI does not read those two arguments at all, whatever their value: it queues `open_record` where the fence adopts the issue, and stores no comment payload. That is a separate gap, not a decision recorded here.

- **Python defect not carried over:** `emit --artifact` naming an existing file under an authorized artifact root whose path holds a byte that is not UTF-8. The fence raises where it hashes the manifest (`manifest.revision_hash` encodes each path): the host error `UnicodeEncodeError: 'utf-8' codec can't encode character '\\udcff' in position N: surrogates not allowed`, exit 3. Go hashes the path's bytes, then its receipt intake reads the manifest back from the receipt's JSON, where the byte reads as U+FFFD, so the file it verifies is not there, and it refuses the report, exit 2 `manifest_unverified`, detail `<path>: path_changed: component '<name>' of '<path>' disappeared during resolution` with `\ufffd` in place of the byte. Neither runtime records a receipt. Go's answer is kept: neither runtime can record a receipt whose manifest names this path, and Go says so as a refusal with a reason where the fence raises while hashing the path. Where no such file exists both runtimes answer the same `path_changed` refusal (exit 2).

- **Python defect not carried over:** settings text on the command line that is not UTF-8, given to `register --parent-settings` or `--child-settings`, or to `settings-record --settings`. Go refuses it before parsing, the host error `UnicodeDecodeError: 'utf-8' codec can't decode the settings`, exit 3, and writes nothing. The fence parses the surrogate-escaped str. Text that is not JSON answers the host error `JSONDecodeError: Expecting value: line 1 column 1 (char 0)`, exit 3. A JSON object whose string holds the byte is checked like any other settings: an incomplete one is refused `settings_incomplete` (exit 2), and a complete one is recorded (exit 0, by `settings-record` and `register` alike) as `json.dumps` writes it (`"m\udcff"`). Go's answer is kept: authorised settings are what a send carries to the App Server and checks its response against, and a Go reader decodes a stored `"\udcff"` as U+FFFD, which compares unequal even to the argument that wrote it (as `intent-declare` shows above). Refusing such settings before anything is written is the safe answer.

- **Python defect not carried over:** a `--socket` path, or a marker command's `--workspace` (measured with `intent-declare`), whose resolution meets a symbolic-link loop or a directory this process cannot search (mode 000). The fence's `canonical_socket` and `workspace_key` call non-strict `Path.resolve()`, which on its CPython 3.13 keeps such a component as spelled, so the fence answers from a store scope or a marker named by a path it never resolved: `store-identity` answers `store_absent` (exit 2) naming a scope directory under the XDG state root, `register` creates that store and registers (exit 0), and `intent-declare` publishes (exit 0). Go resolves both strictly (`store.ResolvePath` in `canonicalSocket` and in the marker's `resolved`, not `store.Realpath`) and answers a host error, exit 3, writing nothing: `too many symlinks resolving "<path>"` or `lstat <component>: permission denied` for the socket, and the same prefixed `RuntimeError: ` for the workspace. Go's answer is kept: the scope key and the marker digest hash the resolved path so that every spelling of one socket or workspace reaches one store and one marker, and a path whose components cannot be resolved has no canonical spelling to hash, so answering from the spelled path could split one socket's or one workspace's state across two keys. Refusing a socket or workspace path whose components cannot be resolved is the safe answer on the fenced store.
- **Python defect not carried over:** CPython 3.13's C JSON scanner spends one level of the recursion budget on each container, and its error and constant paths spend more near the end of that budget, so `json.loads` raises `RecursionError` for a document a few levels short of its nesting limit that it would otherwise refuse with a JSONDecodeError or read. Go's readers of a frozen `MANIFEST.json` (`store.frozenJSONDepth`, 9998 containers, decision 44) keep the one-level rule and do not model this band. Measured on CPython 3.13.14 where the fence reads a frozen copy (`manifest.verify_frozen_detailed` called from a script's top level, where 9998 containers are read, and `guard.evaluate`, `guard.deliverable_state` and `ReceiptIntake.accept_child_receipt` called the same way, which read it with that budget), with N the containers open where the scanner meets the fault, the outer object counted:
  - N up to 9994, or 9999 and more: both runtimes answer alike. Past 9998 both raise `RecursionError: maximum recursion depth exceeded while decoding a JSON array from a unicode string` (or `object`).
  - N from 9995 to 9998: each JSONDecodeError the C scanner raises itself, which is every message but `Expecting value` (an illegal trailing comma, an invalid `\escape`, an unterminated string, a missing `,` or `:` delimiter, a property name not in double quotes), is in the fence `RecursionError: maximum recursion depth exceeded while calling a Python object` at 9995 and 9998, and `RecursionError: maximum recursion depth exceeded` at 9996 and 9997. Go raises the JSONDecodeError with its message and position.
  - N of 9998 also: `Expecting value`, the ValueError of an integer longer than 4300 digits, and `NaN`, `Infinity` or `-Infinity` are `RecursionError: maximum recursion depth exceeded while calling a Python object` in the fence. Go raises that JSONDecodeError or ValueError, and reads the constant as a float.
  - What each reader then answers: the fence's Stop guard faults (`guard_faulted`, released, the fault that RecursionError), where Go's answers the frozen copy changed (in hold mode it blocks, `receipt_missing`) or, for a constant at 9998, current (`declared_ready_receipted`). The fence's intake answers the host error `RecursionError: ...`, and Go's the host error `JSONDecodeError: ...` or `ValueError: ...`, neither recording a refusal; for a constant at 9998 Go stores the receipt. Where `guard.deliverable_state` raises it, the fence's omission reader, which catches a RuntimeError, is `unmeasured` with `evidence_unreadable: <its words>` (decision 44), and Go's omission reader reads the deliverable as changed or current.

  Only a forged frozen copy nests this deep: a freeze writes a manifest three containers deep. The band moves with the budget left at the call, as decision 44's boundary does. The same check, `pyjson.ErrorWithLimit`, sets the nesting boundary of `service/policy.go` and `cli/merge_evidence.go`, which do not model the band either; theirs was not measured. The frozen-copy parity fixtures (`testsupport.FrozenManifests`) stage nesting that ends in a value both runtimes read alike.
