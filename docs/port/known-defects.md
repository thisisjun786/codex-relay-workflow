# Known defects and intentional port differences

- CRW-238: the admitted-turn scan has an open performance defect. The Go fault sweep must not silently change its scan shape as part of this port; the owning issue tracks remediation.
- Todo 22 replaces Python's dynamic `--kind-module` imports with a static fault-kind registry generated from the Python declarations in `contract/schema/fault-kinds.json`. The native binary accepts `codex_session_relay.projects`, `json`, and `os.path` as registered module names without importing Python. Arbitrary importable modules outside this registry are refused with exit 4, naming the first unregistered module. Empty and relative names retain Python's exit 3 host-error shape. This intentional compatibility difference removes dynamic publication-kind registration; it does not add a publication kind.
- Python `FaultLedger.record` only calls `_rescope` when an observation changes `scope_key`. An observation that changes scope metadata such as `issueKey` while retaining the same workspace and `projectKey` therefore leaves the old serialized scope in `fault_ledger.scope`. Go preserves this observable behavior for parity; `TestRecordReviewFindingsWholeOutput/same_target_key_does_not_update_scope_text` compares the complete CLI replies and every SQLite table with live Python.
- The development judges `crw-dev stop-events` and `crw-dev trial-ledger` read a JSON record as CPython 3.14's `json.loads` does except at the interpreter's stack edge. Python's C scanner has no nesting limit of its own: it recurses until the main thread's stack runs out and raises `RecursionError` there. On the default 8 MiB stack CPython 3.14.4 stopped at 57,930 containers through `stop_events.py` (a journal row) and at 57,929 and 57,955 through `trial_startup.py ledger` (a ledger line, the start record); the edge moves by tens with whatever else is on the stack, and further with `ulimit -s` (CPython 3.13 stops at 9,997). The Go judges model it as a fixed 57,900 (`internal/dev/pyload.Nesting`, in place of encoding/json's 10,000): below it both read a record alike, past the interpreter's edge both raise, and between the two Go raises where Python still reads. The raise is worded differently: Go says `maximum recursion depth exceeded while decoding a JSON array from a unicode string` where 3.14 says `Stack overflow (used N kB) while decoding ...`, and the trial ledger's refusal reports `raisedAt` null where Python names `decoder.py:361`. `stop_events.py` also re-encodes each record to compare its bytes, and CPython's encoder spends more stack per nested object than its decoder, so a row whose untyped field nests objects past about 30,000 raises there and reads in Go. Only a forged record nests this deep: the fields a reader leaves untyped are copied from the relay's own verdict, a few containers deep. `TestLoadsReadsAsDeepAsPythonAndRaisesPastIt`, `TestSEV12_OnDiskFormIsTheWriters` and `TestLedgerReadsRecordsAsDeepAsPython` hold the model.
- repr() in the port (`settings.Repr`, which `evidence.StrRepr`, `store.PyRepr` and `store.PythonRepr` are, and `store.PathRepr`) escapes what `str.isprintable()` refuses under CPython 3.14's Unicode database, 16.0.0, pinned as a table generated from that interpreter (`settings.Printable`, `go generate ./internal/bridge/settings`), not under Go's own tables (Unicode 17.0.0). The judges, the trial ledger's refusals, `crw hook`'s row details, the relay CLI's echo of an argument (argparse's `invalid choice` and every refusal naming a value), `crw skill`'s and `crw-dev ci`'s argparse and the doctor's `socketConnect` therefore spell a path or value as CPython 3.14 does. A Python on another Unicode version spells a character assigned between the two versions otherwise: CPython 3.13 (15.1.0) escapes one assigned in 16.0.0 (U+1C89) that 3.14 and the port print, so under 3.13 `stop_events.py` reads a decision-22 row naming such a state directory as unreadable where `crw-dev stop-events` reads it TRUE. The comparisons that establish the judges' parity use CPython 3.14.4. `TestPrintableIsCPython314sIsprintable` holds the table against the interpreter on PATH when it is 3.14.
- A relay CLI argument that is not UTF-8 (an argv byte such as 0xff, which Python holds surrogate-escaped) is refused where the fence first encodes it, in both runtimes. Every string a relay store connection binds is checked as `sqlite3` binds a str (`store.EncodeUTF8`, in the store's driver), and the identities the fence hashes before it reads anything (the relationship, linkage, marker, merge-target and edit-region identities, and the managed-start request) refuse it there. `cli.main`'s host error (`UnicodeEncodeError: 'utf-8' codec can't encode character '\\udcff' in position N: surrogates not allowed`, exit 3) therefore names the same position, and Go never writes TEXT that Python's `sqlite3` cannot decode. A value the fence stores inside JSON (an artifact root) is stored as the same TEXT (`"\udcff"`), and an argument echoed in a refusal prints as Python prints it. Two differences remain, and neither is a write. Go's JSON readers decode a stored `"\udXXX"` escape as U+FFFD (encoding/json), so a command that prints such a stored value back prints `\ufffd` where Python prints `\udcff` (register's `authorizedScope` for a non-UTF-8 `--artifact-root`), and a Go reader compares it unequal to the argument that wrote it: `intent-declare` over a marker the fence published for a non-UTF-8 `--issue` answers `conflict` where the fence answers `published`. And `settings-record` refuses settings text on the command line that is not UTF-8 as `UnicodeDecodeError` before parsing it, where Python parses the surrogate-escaped str. `TestAnArgumentThatIsNotUTF8IsRefusedWherePythonEncodesIt` compares the answers to 30 command lines, and the stored artifact root, with the fence; `TestAStoreRefusesToBindAStrPythonCannotEncode` and `TestEncodeUTF8IsStrEncode` hold the check.

- `crw skill hook-probe`, `crw skill parent-title` and `crw skill start-policy` emulate Python's argparse for the argv shapes `TestSkillArgparseMatchesLivePython` pins, not argparse's own prefix and cluster parser. Five further shapes get another answer. Each was run against the scripts under CPython 3.13.14. Where both refuse, they print the same usage line; the table gives each exit code and the error line or output:

The skills name these commands with fixed, fully spelled argv (`hook-probe observe` with `--sanitize`, `hook-probe replay`, `parent-title decide` and `replay`, `start-policy vocabulary`, `check` and `selftest`), and `scripts/ci/contracts.py` runs `replay` and `selftest` with nothing else: none abbreviates an option, clusters short flags, passes a lone `-`, or gives the root an argument it does not know.

## Python defects not carried over

- **Python defect not carried over:** `daemon._gate` fingerprint omits the receipt turn id (`daemon.py:~993`), so an accepted receipt that gains a turn id later is never reconciled; Go includes it (`TestReconcilePass_receipt_gains_turn_id`).

- **Python defect not carried over:** `registry.bind_anchor` (`registry.py:790-822`) reads the pending anchor before beginning its transaction. Concurrent binders can overwrite a generation's dispatch turn after one has already succeeded, violating the never-rebind invariant. Go reads and decides inside the write transaction; `TestBindAnchor_concurrent_turns_never_replace_the_winner` proves only one distinct turn binds and the loser is refused.
- **Python defect not carried over:** `ack.bind_dispatched_revision` (`ack.py:1026-1035`) rejects acknowledged revisions even though `ack.bind_pending_anchors` (`ack.py:1037-1060`) selects them for recovery. This violates the invariant that every dispatched revision's pending anchor can recover after acknowledgement. Go accepts both states; `TestBindPendingAnchors_recovers_acknowledged_revision` proves the recovery binds and is idempotent.

- **Python defect not carried over:** `trial_startup.py ledger` writes a ledger line's operator fields back through the recursive `shown()` (`trial_startup.py:518-530`) when it refuses one that is not text. Under CPython 3.14.4 a `segment` or an `actor` nested 997 containers deep or more passes the interpreter's recursion limit there, and the run answers "this run raised before it could report" (`RecursionError`, raisedAt `trial_startup.py:529`), exit 2, where Python's own comment (`trial_startup.py:3031-3034`) says a structured segment is refused by name rather than raised as an internal error about something the operator wrote. At 996 and below both runtimes refuse by name. `crw-dev trial-ledger` refuses by name at every depth, exit 2 either way; only a forged ledger nests this deep. `TestALedgerFieldNestedPastPythonsRecursionLimitIsRefusedByName` pins the refusal at 1000 for a segment and an actor. The `target` and `action` fields take the same path and were not measured.

- **Python defect not carried over:** `supervisor-report-recorded --event=` satisfies argparse's required mutually-exclusive group, then the handler treats the empty event as false and calls `_observation_file(None)`, raising `TypeError` and exiting 3. Go retains a parser usage exit instead of reproducing the crash.

- **Python defect not carried over:** a lone surrogate that reaches stdout. Under the oracle's pinned stream (decision 29b, `PYTHONIOENCODING=utf-8:strict`, as on an `en_US.UTF-8` host) Python's `print` cannot encode a lone surrogate, so it raises `UnicodeEncodeError` and exits 1. Go writes the output. Only a JSON escape such as `\ud800` in a request or record can put one there, since both runtimes refuse input bytes that are not UTF-8. Two commands reach it:
  - `crw skill parent-title decide` with a lone surrogate in `observed_title`, or in the `family_candidates` and `project_labels` entry that becomes the prefix. Python writes nothing to stdout and exits 1. Its stderr is a traceback whose last line is `UnicodeEncodeError: 'utf-8' codec can't encode character '\ud800' in position 17: surrogates not allowed` for `"observed_title": "Body\ud800"`, where the position is the character's offset in the JSON reply. Go writes the whole reply to stdout and exits 0 with an empty stderr. Each lone surrogate becomes three U+FFFD (`EF BF BD` three times) in `body` and `title`, or in `prefix` and `title`, because encoding/json replaces each byte of its WTF-8 form.
  - `crw skill hook-probe replay` when a host observation records a Stop field type that is not a JSON type name, under a field whose name is a lone surrogate. The case used here has capability `required` `["\ud800"]`, observation `fields` `["\ud800"]` and `types` `{"\ud800": "s\udc00"}`. Both runtimes write the same report lines before that point and exit 1. Python's `print("HOST OBSERVATION: " + problem)` raises, so that line and any after it are missing from stdout, and stderr ends with `UnicodeEncodeError: 'utf-8' codec can't encode character '\ud800' in position 128: surrogates not allowed`. Go writes `HOST OBSERVATION: host-observation-codex-0.154.0.json: the recorded Stop field types name something that is not a JSON type for ` and then the surrogate's WTF-8 bytes `ED A0 80` to stdout, and its stderr is empty.
