# CXC port: known defects

Behavior of CXC v0.2.40 that looks unintended and that the recorded corpus ([contract/schema/cxc](../../contract/schema/cxc/README.md); fixtures in `contract/fixtures/cxc`) keeps exactly as the oracle printed it. The port reproduces behavior first: parity with the oracle wins over repair, and a replay never takes a defect for the right answer.

- A port issue that finds a defect adds one line here and does not fix it. A defect the port reproduces on purpose keeps its line with `port: kept`. No line is deleted; a later change that repairs one edits its line to `port: fixed` and names that change.
- The one exception is `reset --help`, which deletes session state instead of printing help. The port fixes it (decision 9 of the port's Wave 0 decisions, recorded in Linear).
- Line shape: `- <what the oracle does> (<pointer>); port: <pending|kept|fixed>.` A fixture pointer is an id under `contract/fixtures/cxc/`; a source pointer is a path in the upstream repository at tag v0.2.40, with a line where one line carries the behavior.
- The defects of the earlier Python-to-Go port of the bridge and relay are in [docs/port/known-defects.md](../port/known-defects.md).

## Seeded from the corpus recording

- `cxc reset --help` is not help: the scope parser defaults to state, so it deletes session state exactly like `reset --state` and exits 0 (fixture `cli__reset__help_is_not_help_and_resets_state`); port: fixed, the one exception.
- `cxc doctor --help` is not help: the hooks option parser rejects it with `cxc-ops error: unknown hooks option: --help` and exit 1 (fixture `cli__doctor__help_is_an_unknown_option`); port: pending.
- `cxc provider` ignores every argument, even `--help`, and runs the same probe (fixture `cli__provider__detect_line_and_ignored_args`); port: pending.
- `cxc metric parse-line` cannot succeed through the dispatcher: its help says it reads stdin, but v0.2.40 parses the argv after the verb (`--session` included), and both the stdin form and an argv form exit 1 (fixture `cli__metric__record_show_kind_parse_line`); port: pending.
- `cxc plan init` ignores `--date` whatever its value: the parser reads only `--phases` and `--cwd`, skips every other `--` token and takes the first bare argument as the slug, so the unit date is a YYMMDD prefix of that argument or else the day's date, although the verb's help says `--date` is for callers that carry their own prefix (fixture `cli__plan__init_normalises_slug_and_date`, whose `--date 2026-01-01` coincides with the recorded clock's day; source `plugins/codexclaw/components/pabcd-state/src/plan-cli.ts:92`, `:95` and `:177`); port: pending.
- `cxc loop init` with a goalplans directory that is a symlink fails with a thrown error that only the CLI's generic handler prints (`codexclaw cli failed: goalplan state path must not be a symlink: ...`, exit 1) instead of a command-level refusal (fixture `cli__loop__symlinked_goalplans_root_refused`; source `plugins/codexclaw/components/pabcd-state/src/goalplan.ts:311`, `plugins/codexclaw/components/pabcd-state/src/cli.ts:531`); port: pending.
- The managed-worktree deletion guard exits 1 with empty stdout, and no deny envelope, when its stdin is oversized: its verb `worktree-guard-pretool` does not start with `pre-tool-use`, so the generic oversize deny does not apply (fixture `hook__pre-tool-use-guarding-managed-worktree-deletion__oversized_stdin_exits_1`); port: pending.
- The same guard's fallback matches the slot id as a raw substring, so `rm -rf` on an unrelated path that merely contains the slot id is denied as an unresolvable target while the same command on a neighbouring path passes (fixture `hook__pre-tool-use-guarding-managed-worktree-deletion__slot_substring_denies_unrelated_target`); port: pending.
- Write and Edit calls reach the edit lint (its matcher is `^(apply_patch|Write|Edit)$`) but are never linted, because it reads only `tool_input.command` (fixture `hook__pre-tool-use-linting-apply-patch__allowed_edits`; matcher in `contract/schema/cxc/hook-declarations.json`); port: pending.
- A subagent's patch skips the edit lint: the edit leg sits below the root-only subagent exit (fixture `hook__pre-tool-use-linting-apply-patch__subagent_payload_skips_lint`); port: pending.
- `cxc memory` and `cxc memory grant` reach recall's chat and memory usage text with exit 0 instead of the allow-write handler; only `cxc memory allow-write` reaches the pabcd-state command (fixture `cli__memory-allow-write__non_allow_write_routes_to_recall`); port: pending.
- The MCP server's default project scope is its working directory, and the plugin's MCP declaration sets that to the plugin root (source `plugins/codexclaw/components/subagent-config/src/mcp.ts:129`, `plugins/codexclaw/.mcp.json`; the recorded MCP fixtures use the global scope); port: pending.
- Recall's recovery line is cut inside the plugin path when the expanded path is long (fixture `hook__session-start-injecting-recall-context__compact_source_gets_recovery_directive`, listed as path-length dependent in `contract/schema/cxc/coverage.json`); port: pending.
- The spawn hook runs the same `git ls-files --error-unmatch` three times for a direct spawn (fixture `hook__pre-tool-use-attaching-skills__baseline_empty_workspace` records three identical git calls, and fixture `hook__pre-tool-use-attaching-skills__managed_fallback_candidate_null_effort` one for a managed dispatch; source `plugins/codexclaw/components/subagent-config/src/store.ts:322`); port: pending.
- The spawn hook never sweeps unused grants: a grant file carries a 15-minute expiry, but only a grant that is claimed is removed (fixture `hook__pre-tool-use-attaching-skills__root_recursion_request_mints_coordinator_grant`; source `plugins/codexclaw/components/subagent-config/src/spawn-attach-hook.ts:381` and `:405`); port: pending.
- `cxc disable` keeps the install manifest after reverting the flags and the managed key it recorded (fixture `cli__disable__reverts_live_flags_and_key`, whose resulting tree still holds the manifest); port: pending.

## Found by the interview tracker port

- `reconstructInterview` turns a persisted partial interview into a ready-shaped one: a dimension score missing its arrays or confidence, a confidence outside [0, 1] and absent contradictions or assumptions arrays are repaired to empty arrays and 0, so a tracker with every level `max` and one recorded scan passes `isInterviewReady` after reconstruct although the same object given directly does not (source `plugins/codexclaw/components/pabcd-state/src/interview.ts:140`, `:158-160`, `:193` and `:213` against `:271` and `:274-281`); port: kept.
- The 50-entry cap drops the oldest entries, so an old unrecorded assumption or malformed-assumption sentinel is evicted by 50 later recorded assumptions and then stops blocking readiness, in `reconstructInterview` and `normalizeInterview` alike (source `plugins/codexclaw/components/pabcd-state/src/interview.ts:212` and `:368`); port: kept.
- `MAX_AUTO_ROUNDS` is defined and `autoResolveCount` is carried through reconstruct and normalize, but no runtime decision enforces the cap or uses the count to limit auto-resolution (source `plugins/codexclaw/components/pabcd-state/src/interview.ts:33`, `:64-65`, `:220` and `:369`); port: kept.
- `normalizeInterview` caps contradictions and assumptions without re-validating their entries, unlike `reconstructInterview`, so an entry with an invalid severity written in memory is persisted as is and corrected only on the next read (source `plugins/codexclaw/components/pabcd-state/src/interview.ts:367-368` against `:185-213`); port: kept.
- A persisted assumption object with `recorded: true` whose `id` or `text` is not a string is reconstructed with an empty `id` or `text` and still counts as recorded, so readiness accepts an assumption whose content was lost (source `plugins/codexclaw/components/pabcd-state/src/interview.ts:202-204` and `:277`); port: kept.
- When only a low- or medium-severity contradiction keeps an otherwise complete interview from being ready, the gate reports `interview is not ready (dimensions/assumptions incomplete)`, which names the wrong cause: that fallback is emitted only when no other warning exists, and only high-severity contradictions are counted (source `plugins/codexclaw/components/pabcd-state/src/interview.ts:315`, `:319` and `:339`); port: kept.

## Found by the source identity port

- `captureSourceIdentity` decodes each NUL-terminated field of `git status --porcelain=v1 -z` as UTF-8 text, so a file name with invalid UTF-8 bytes turns into U+FFFD characters and the file is then read under that changed name: its content is not hashed (unless another file carries the replacement name) and two distinct names can collide (source `plugins/codexclaw/components/pabcd-state/src/source-identity.ts:102` and `:160`; port scenarios `invalid_utf8_path` and `invalid_utf8_collide` in `internal/pabcd/source/testdata/scenarios.json`); port: kept.
- Git prints the original path as one more field after a worktree-side rename (status ` R`, which `git add -N` produces), but the oracle consumes that field only when the index column is `R` or `C`, so the original path is parsed as a record of its own: one of four UTF-16 units or more becomes a bogus entry (its first two units read as the status, the rest after one unit as the path) and a shorter one is dropped by the length check (source `plugins/codexclaw/components/pabcd-state/src/source-identity.ts:109-113`; port scenarios `intent_to_add_rename` and `intent_to_add_rename_astral_split_in_xy` in `internal/pabcd/source/testdata/scenarios.json`); port: kept.
- Captured from a subdirectory of the repository, the capture reads every entry under that directory while git reports status paths relative to the repository root, so an entry has no content or takes the content of a different file with the same relative path under that directory: an edit can leave the identity unchanged and an unrelated change can move it (source `plugins/codexclaw/components/pabcd-state/src/source-identity.ts:160`, `:196` and `:208`; port scenario `modified_file_captured_from_subdirectory` in `internal/pabcd/source/testdata/scenarios.json`); port: kept.
