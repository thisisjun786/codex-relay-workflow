# CRW-645 — the UserPromptSubmit trigger branch and renderStatusLine

Source: `plugins/codexclaw/components/pabcd-state/src/hook.ts` `handleUserPromptSubmit` :755-847 and
`renderStatusLine` :849-853, with the R-11 helpers of `plugins/codexclaw/components/pabcd-state/src/transcript.ts`,
at CXC v0.2.40 (commit 3c1459ac); ported into `internal/pabcd/hook/prompt_trigger.go`, called from
`internal/pabcd/hook/prompt_submit.go` and reached through `internal/harness/legs.go` as the leg
`user-prompt-submit-checking-pabcd-trigger`.

- The trigger branch's bookkeeping write and the four passive writes each read the session state, change fields and write the whole state back with no lock, so an update a participating writer (the memory gate, the idle-edit counter, `handlePostCompact`, another hook of the same session) lands between the read and the write is overwritten by the stale copy and lost, and the write-back rebuilds the state from the reader's normalised value, so a stored record the reader cannot keep (an unverified list past its cap, a `receiptClaimed` cut at 256 UTF-16 units, a field of the wrong type, a legacy D-close marker, an interview tracker past `interview.MaxTrackerArray`) is lost with it (source `hook.ts:762-768`, `:775-780`, `:790-791`, `:810-816`, `:827-833` and `:838-843`); port: fixed (a data-loss defect, fixed by decision as the memory gate, the idle-edit counter, `handlePostCompact` and the leading section of this same handler already are: every write here goes through `promptSubmitWriteState`, which re-reads inside `state.WithSessionLock`, applies the change to that read and refuses a rewrite the reader would not keep whole; the cases are `TestPromptTriggerKeepsAParticipatingWritersUpdate` and `TestPromptTriggerLoopArmSeenSurvivesMode2` in `internal/pabcd/hook/prompt_trigger_test.go`).
- `readTranscriptTail` reads the whole transcript before slicing its last 65,536 bytes, so the R-11 guards allocate the entire file in the hook process on every passive prompt of a session with a very large transcript, and the read has no deadline (source `transcript.ts:41-46`; the Go port `internal/pabcd/host/transcript.go:21-30` mirrors the whole-file read, and this unit is the first caller that reaches it on the prompt path); port: kept.
- `hasStageMarkerForPhase` and `isContextPressureTail` match their markers as unanchored substrings of the transcript tail, so marker text that reached the transcript another way (a prompt the user pasted, a directive the model echoed) suppresses the passive re-injection although the directive for that phase was not injected this turn (source `transcript.ts:57-74`; the Go port `internal/pabcd/host/transcript.go:78-105` keeps the same rule); port: kept.
