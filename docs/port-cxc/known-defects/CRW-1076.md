# CRW-1076 — closeFixedWorkPhase finds the cursor phase with one predicate

Source: `plugins/codexclaw/components/pabcd-state/src/goalplan.ts` (`closeFixedWorkPhase` :1989-2133, the `find` at
:2081-2085) at CXC v0.2.40, commit 3c1459ac; the Go port at `internal/pabcd/goalplan/workphase.go` (:205-217). Found by the
oracle review of 2026-10-10 (finding U09-001).

- When the recorded successor is already done, the oracle keeps the cursor on the first work phase that has the cursor's id,
  is not the phase being closed, is `in_progress` and passes `workPhaseReadyConditionsMet`, all in one `find`. The port picked
  the first phase with the cursor's id and then dropped it for its status or readiness, so a plan with two phases of one id,
  the first blocked or waiting, lost the cursor (`nil`, statuses `[done, done, blocked, in_progress]`; the oracle keeps `wp3`,
  `[done, done, in_progress, in_progress]`); port: fixed (the oracle's behaviour, so no deviation remains: the port
  selects by the same predicate. A plan with a duplicate id is rejected earlier by the CLI (`cli/orchestrate_dclose.go`) and
  the chat D-close (`hook/prompt_dclose.go`), which stay as they are, so the loss was not reachable in operation).

  Pinned by `TestCRW1076_CloseFixedKeepsTheCursorOnTheRunnableDuplicate` (both orders of a blocked and a runnable duplicate,
  a plan without a duplicate, the input plan unchanged) and `TestCRW1076_CloseFixedKeepsTheCursorOnlyOnAReadyDuplicate` (the
  readiness half: a duplicate waiting on an unfinished dependency, in both orders and alone) in
  `internal/pabcd/goalplan/workphase_audit_test.go`; the expected values are the oracle's `dist/goalplan.js` on the same plans.
