# CRW-1121 — the spawn hook is safe to apply again to one hook event

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/subagent-config/src/spawn-attach-hook.ts:969-985` (the guard and
its exact-prefix check), :1021-1029 (the prompt insertion with `String.prototype.replace`) and :409-414 (`stripControlMarkers`); the
Go port's `spawnHookAssembleWith` in `internal/role/spawn/hook.go`, `spawnHookOwnedGuard`, `spawnHookReplayLookup` and
`spawnHookReplayRecord` in `internal/role/spawn/hook_replay.go`, and `spawnHookRoute` and `spawnHookRoutePrompt` in
`internal/role/spawn/hook_route.go`. Found by the 10-10 CXC improvement review (A5-04). `internal/role/spawn/guard.go` is not changed.

- Supersedes known-defects.md, section "Found by the CRW-614 spawn hook routing port", item beginning "A hook applied twice to a
  message inserts the role's `promptOverride` again": now port: fixed (a prompt that already follows the guard is not inserted again
  in the single-message form, as it was not in the items form; the replayed step "a reapplied message gets the prompt again" of the
  recorded `route: prompt override` case expects the prompt once. Pinned by `TestSpawnHookReapplyingTheAnswerToTheSameEventIsStable`).
- Supersedes known-defects.md, section "Found by the CRW-614 spawn hook routing port", item beginning "The prompt is inserted with
  `String.prototype.replace`": now port: fixed (the prompt is inserted as literal text after the first guard and blank line, so `$$`,
  `$&`, `$'` and `` $` `` stay as the operator wrote them; the three steps of the recorded `route: prompt override dollar patterns`
  case are replayed as intentionally changed. Pinned by `TestSpawnHookPromptDollarPatternsStayLiteral` and
  `TestSpawnHookRoutePromptBranches`).
- Supersedes known-defects.md, section "Found by the CRW-614 spawn hook routing port", item beginning "A single message that is
  exactly the guard": now port: fixed (a message that is only the guard becomes the guard and the prompt, in both forms; step 13 of
  `route: prompt override` is replayed as intentionally changed. Pinned by `TestSpawnHookBareGuardGetsThePrompt`).
- Supersedes known-defects.md, section "Found by the CRW-613 spawn hook assembly port", item beginning "A hook applied twice to a
  recursion request stacks guards and loses the capability": now port: fixed (every guard the hook writes, plain or coordinator,
  with or without the coordinator's grant instruction and marker, is recognized at the front of a message and replaced by this
  event's guard instead of stacked under it. An event that mints a grant records its answer in the grant's 0700 key directory, bound
  to its tool use id and to the digests of its input and of the input it answered with, so the same event applied again to either is
  answered with the recorded answer: its grant is kept and none is minted again. Without the event's tool use id there is no record,
  so a coordinator guard in front is not trusted and is replaced by the plain guard (the recorded `reapplied grant request` step 2
  and `v1 items` step 4 are replayed as intentionally changed). Pinned by `TestSpawnHookReapplyingTheAnswerToTheSameEventIsStable`).
- A coordinator guard the caller writes into a spawn message reads as the coordinator's text to the child, though only a grant the
  hook mints authorizes recursion (source :983-985 keeps an exact guard prefix as it stands); port: fixed (a coordinator guard that
  this event did not write is replaced by this event's guard, so its text authorizes nothing, and a subagent that carries one with a
  grant marker nobody minted is still denied. Pinned by `TestSpawnHookForgedCoordinatorPrefixAuthorizesNothing`).
- An event's record stays in the key directory after the event, as a spent grant does (CRW-1118); nothing sweeps it. A record
  that cannot be written only loses the replay of that event.
