# CRW-1104 — invocation-local shell analyses

Source: CRW's memory guard, `internal/pabcd/hook/memorygate.go` and `shellwrite_ir.go`. The oracle has multiple passes too, but CRW repeated two identical structural analyses.

- A readable command was analyzed five times: environment/directory twice, no-environment/directory once and no-directory twice; port: fixed. An invocation-local bundle lazily retains each context's Result and error. Destination, Python readability and command readability consumers share these read-only records. All three distinct contexts remain; there is no AST sharing or cross-event cache.
- TestCRW1104EachContextAnalyzedOnce failed with counts 2/1/2 before memoization and passes with 1/1/1. TestCRW1104CorpusParity compares every existing reproduction row's attempt and exact destinations with the uncached path. TestCRW1104CacheErrorsAndReadOnlyRecords pins error reuse and consumer immutability.
- Refresh with CRW-951: the cached environment context uses AnalyzeEnvProvenDirectory, matching the resolved destination reader and preserving failed-cd tracking. Destination consumers receive the invocation's protected-root lookup, including recursive scripts; the three contexts and invocation-local caching remain unchanged.
- Three 200 ms benchmark samples were run on the same host before/after the cache, using a short command and one close to the 64 KiB command limit. Allocations fell from 161 to 101 per short call and from 331 to 203 near the limit; bytes fell from about 36,136 to 22,184 and 1,790,530 to 1,074,814. The near-limit median was about 2.50 ms before and 1.21 ms after. Short-call timing was noisy (median 14.89 us before, 15.22 us after), so no short-call latency improvement is claimed. Raw measurement logs stay in the private handoff. Structural analyses are reduced by exactly two, from five to three; this is not a claim of end-to-end process latency reduction.
