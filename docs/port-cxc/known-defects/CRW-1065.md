# CRW-1065 — a non-JSON state file holding a lone surrogate escape: the refusal is kept and the bytes stay

Source: the CXC v0.2.40 oracle (commit 3c1459ac) `pabcd-state/dist/state.js` `readStateStrict` (:494, which answers a file that is not a JSON object with a default state and `unreadable: true`) and `writeState` (:620, which publishes the given state over the stored file); the port's `internal/pabcd/state` `write.go` `writeState` (the check of the stored bytes before any temp file is staged) and `rewrite.go` `rewriteLosslessUnpaired`. The pinned case is `unreadable-file-holding-a-lone-surrogate-escape` in `internal/dev/cxcfuzz/testdata/state/cases.json`, the single entry for this shape: CRW-711 pinned it as `open` on dev, and this issue retags that same entry `intentionally-changed` and replaces its record. The shape was found by the CRW-711 reduced state campaign (dev 7839042f6, seed 711), where the issue counts 1,253 differences of this one kind.

Decision D2 (CRW-1065, 2026-10-09): the port keeps the refusal. A non-JSON state file that holds an unpaired surrogate escape is not overwritten by the default state. The CXC rewrite is not required by any contract the port keeps: the oracle's writers answer a stored file that the reader cannot use by publishing over it, and the port's other data-preserving decisions on unreadable session files (CRW-435, CRW-1005 D1) refuse the same kind of write. The recovery for such a file is the CLI reset, which removes `sessions/*.json` (`internal/pabcd/reset`, the state scope), so a refused session is not stuck.

- A non-JSON state file holding a lone surrogate escape (for example `not json \ud800`): the oracle's `readStateStrict` reads it as an unreadable default, and its `writeState` publishes that default over the stored bytes (the oracle's `written` text); the port's `WriteState` refuses the rewrite before any temp file is staged, returns `writeError` naming the file, and leaves the file byte for byte as it was. The read still answers `unreadable: true`. port: intentionally-changed (D2: refusal instead of the default rewrite; pinned as `unreadable-file-holding-a-lone-surrogate-escape`).
- The byte-preservation test for the exact non-JSON input is `TestWriteStateRefusalLeavesANonJSONFileByteForByte` in `internal/pabcd/state/surrogate_rewrite_test.go`, over three shapes (plain text with the escape, a truncated object, an object with trailing characters). It is green on the port's refusal and red when the refusal is moved after the write: with the check evaluated after the rename, the file reads back as the default state in all three shapes (red output in `/state/crw/crw-1065/evidence/red-2/red-refusal-after-write.log`). The check was not moved in the change; the mutation was applied to a scratch edit and reverted.
- Supersedes CRW-711.md, item beginning "A state file that is not valid JSON and whose text holds an unpaired surrogate escape" (the non-JSON shape of the state campaign's 1,253 differences; pinned there as `open`, `port: pending`): now port: intentionally-changed (D2, the first item above). CRW-711.md is not edited here, because a later issue never edits another issue's file (known-defects/README.md).
- Open for the coordinator: a state file that holds a lone surrogate escape now fails every `WriteState` caller until the file is reset or the escape removed. That is the CRW-1005 open item, and the hook writers that used to publish the default over a non-JSON file now receive `writeError`. Whether each hook surfaces that error usefully was not checked in this change.
