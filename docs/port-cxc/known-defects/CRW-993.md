# CRW-993 — the restore identity and the case-only alias after CRW-899

Source: CRW-899 pre-merge evaluation pr841-e36c7ac5 (defects d1, d2 and d3). The defects are the port's own. CXC v0.2.40 (commit 3c1459ac) has no sidecar lock and no identity comparison of the config path (source deactivate.ts:117,122,132,155). The Go files are internal/runtime/install/configguard/deactivate.go (Deactivate, configLockPathsSameTargetReason, configLockPathsProbeFold, configLockPathsProbedEntry, configLockPathsPublishGuard), activate.go (configLockPathsPublishChecked) and internal/pabcd/crwdir/atomic.go (PublishChecked).

- The restore compared the manifest's file and parent with the pinned file and directory, but never the live parent of the pinned pathname. A directory moved away after the pin, and replaced under the old name with hard links to the config file and its sidecar, was accepted: the restore published into the replacement and reported the key restored while the file the manifest names kept it (CRW-899 evaluation d1); port: fixed (the live parent of the pinned pathname must still be the captured directory, checked before the comparison and again immediately before the rename by crwdir.PublishChecked, so a refusal publishes nothing. Pinned by TestConfigLockRestoreIdentityRefusesAHardLinkedReplacementDirectory, with the controls TestConfigLockRestoreIdentityRestoresAnOrdinaryFile and TestConfigLockRestoreIdentityRestoresAMovedDirectoryWithIntactIdentity).
- A case-only alias of the locked entry under a directory without read permission was refused, although the entry can be proven (CRW-899 evaluation d2); port: fixed. A folding directory is answered by a probe through the held descriptor: the ASCII case-swapped name of the sidecar, looked up without following a link, must resolve to the sidecar's device and inode. The manifest's spelling is then the locked entry when its by-name lookup gives the pinned file's identity, and no directory listing is read. A case-sensitive directory refuses, a hard link under a case variant included, as E2 requires. A readable parent keeps the enumeration it used. Pinned by TestConfigLockCaseAliasFoldingDirectoryIsRestored, TestConfigLockCaseAliasFoldingDirectoryRefusesADifferentEntry, TestConfigLockCaseAliasLookupFailureNamesTheReason, TestConfigLockCaseAliasUnknownFoldNamesTheReason, TestConfigLockCaseAliasCaseSensitiveRefusesAHardLinkUnreadable, TestConfigLockCaseAliasRealProbeAnswersCaseSensitiveHere, and TestConfigLockPathsDeactivateAcceptsACaseVariantUnderAnUnreadableParent (the last runs only on a folding filesystem).
- Residual of the d2 fix: a process that can create entries in the directory can also create a case-variant hard link of the sidecar, and so fake a folding answer. That needs write access in the directory and belongs to the same-uid name-operation residual CRW-899 keeps. The probe answers for the directory the pin holds, so a directory with its own case setting (ext4 casefold) is answered for itself.
- The one exception to the same-file restore promise (CRW-899 c1): when the directory's case behaviour cannot be probed (an unknown answer) or the by-name lookup fails, a case-only alias is refused, and the refusal names the reason. Nothing else the promise accepts is refused.
- CRW-899.md described the refusal of a valid case alias under an unreadable parent as fixed, and kept the enumeration-only refusal text for it (evaluation d3); port: fixed (CRW-899.md was edited in place: the unreadable-parent items state the CRW-993 answer, and the refusal text no longer held is removed. TestConfigLockCaseAliasRecordMatchesTheProbe reads the record).
- Between the last parent check and the rename, a process that can rename the directory can still redirect the publish. The guard is path-based and the rename is crwdir.Rename, so the two are separate calls. This is the same external replacement window the record keeps for ApplyManagedKey and for Deactivate content path; port: kept (closing it needs the temp file created and renamed through the held descriptor, which the publish layer does not expose).
