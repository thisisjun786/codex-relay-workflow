# CRW-993 — the restore identity and the case-only alias after CRW-899

Source: CRW-899 pre-merge evaluation pr841-e36c7ac5 (defects d1, d2 and d3) and the pre-merge evaluation of this branch, crw993-9a1faa7f (generation 1 head 9a1faa7f2; generation 2 fixes the findings below). The defects are the port's own. CXC v0.2.40 (commit 3c1459ac) has no sidecar lock and no identity comparison of the config path (source deactivate.ts:117,122,132,155). The Go files are internal/runtime/install/configguard/deactivate.go (Deactivate, configLockPathsSameTargetReason, configLockPathsProbeFold, configLockPathsProbedEntry, configLockPathsPublishGuard), activate.go (configLockPathsPublishChecked), internal/pabcd/crwdir/atomic.go (PublishChecked) and internal/pabcd/crwdir/swap.go (ConfigLock.HeldInfo).

- The restore compared the manifest's file and parent with the pinned file and directory, but never the live parent of the pinned pathname. A directory moved away after the pin, and replaced under the old name with hard links to the config file and its sidecar, was accepted: the restore published into the replacement and reported the key restored while the file the manifest names kept it (CRW-899 evaluation d1); port: fixed (the live parent of the pinned pathname must still be the captured directory, checked before the comparison and again immediately before the rename by crwdir.PublishChecked, so a refusal publishes nothing. Pinned by TestConfigLockRestoreIdentityRefusesAHardLinkedReplacementDirectory, with the controls TestConfigLockRestoreIdentityRestoresAnOrdinaryFile and TestConfigLockRestoreIdentityRestoresAMovedDirectoryWithIntactIdentity).
- A case-only alias of the locked entry under a directory without read permission was refused, although the entry can be proven (CRW-899 evaluation d2); port: fixed (a folding directory is answered by a probe through the held descriptor: the ASCII case-swapped name of the sidecar is looked up without following a link, and the lock's held sidecar must have a link count of one and be the entry that name reaches. The manifest's spelling is then the locked entry when its by-name lookup gives the pinned file's identity, and no directory listing is read. A case-sensitive directory refuses, a hard link under a case variant included, as E2 requires. An unknown answer refuses with its reason: the case-swapped lookup failed, the sidecar has another name, the identity differs, or the name has no ASCII letter. Pinned by TestConfigLockCaseAliasFoldingDirectoryIsRestored, TestConfigLockCaseAliasFoldingDirectoryRefusesADifferentEntry, TestConfigLockCaseAliasLookupFailureNamesTheReason, TestConfigLockCaseAliasUnknownFoldNamesTheReason, TestConfigLockCaseAliasCaseSensitiveRefusesAHardLinkUnreadable, TestConfigLockCaseAliasRealProbeAnswersCaseSensitiveHere, TestConfigLockPathsCaseAliasSidecarWithAnotherNameIsRefused, and TestConfigLockPathsDeactivateAcceptsACaseVariantUnderAnUnreadableParent (the last runs only on a folding filesystem).
- Residual of the d2 fix: a same-uid writer that links and unlinks the sidecar between the swapped-name lookup and the fstat can still fake a folding answer. That needs write access to the directory and belongs to the same-uid name-operation residual CRW-899 keeps; port: kept (the window is that lookup-to-fstat interval; closing it needs the lock file's own name pinned, which the lock does not expose).
- The one exception to the same-file restore promise (CRW-899 c1): a case-only alias is refused, with its reason, when the case behaviour of its directory is unknown (the case-swapped lookup failed, the sidecar has another name, the identity differs, or the name has no ASCII letter) or when the by-name lookup fails. Nothing else the promise accepts is refused; port: kept (the refusal is the fail-closed direction and it names its reason).
- CRW-899.md described the refusal of a valid case alias under an unreadable parent as fixed, and kept the enumeration-only refusal text for it (evaluation d3); port: fixed (CRW-899.md was edited in place: the unreadable-parent items state the CRW-993 answer, the refusal text no longer held is removed, and the pointer to fourteenth- and fifteenth-generation items that do not exist is replaced. TestConfigLockCaseAliasRecordMatchesTheProbe parses this file).
- The readable-parent enumeration (configLockPathsOneFoldedEntry, os.ReadDir) is the predecessor's own path at CRW-899 head e36c7ac5, and it is kept: port: kept (generation 1 decision, relay event 329b363efe76de234b075fe9b730e8cd item 4, a readable parent keeps the enumeration it uses; the no-listing proof of c1b is the unreadable-parent probe, not this branch).
- Platforms other than Linux and macOS have no search-only open flag here, so a directory without read permission has no descriptor and the case-only alias is refused with its reason; port: kept (refusing is the fail-closed direction).
- macOS: the search-only open flag 0x40000000 (O_EXEC | O_DIRECTORY, which is O_SEARCH) is used in config_lock_paths_dirfd_darwin.go, with TestConfigLockPathsDirFlagsOpenASearchOnlyDirectory (darwin only). It is compiled and vetted on Linux with GOOS=darwin; it is not executed on macOS here; port: fixed (the flag and its source comment match internal/pabcd/cli planDirectoryFlags on origin/dev).
- The FIFO handover of the alias and restore tests was unbounded: a regression could hang the package. The writers open through configLockPathsOpenFifoWriter with a 20 second bound and Deactivate in the alias tests is bounded by configLockPathsDeactivateBounded; port: fixed (TestConfigLockPathsFifoWriterIsBounded pins the writer bound).
