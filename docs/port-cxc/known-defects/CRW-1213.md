# CRW-1213 — the agent acceptance and integration rows in the zone, the agent path of dag-accept and dag-integrate, and the agent landing

Source: the 0.5.0-alpha design issue R05 (CRW-1213). This is the port's own addition: CXC v0.2.40 (commit 3c1459ac) has no agent execution kind, no flow journal and no acceptance of an agent's result, so there is no oracle line for it. The Go files are internal/relay/store/dag_zone.go (the appended statements) and dag_agent_integration_stages.go, internal/relay/dagsched/accept_agent.go (the agent path of dag-accept), agent_union.go (acceptanceOf, agentIntegratedAt, agentLandedSHA), accept.go (the route and the slot returner), candidates.go (the candidate and MarkFrozen), integration_batch.go (the stage rows, the actor, the pending marks), integration.go (the observation), commit_targets.go (commitAccepted, integrationRefsOf), manifest.go (landedOf) and accept_premerge.go (the held candidates).

- The Linear body of CRW-1213 names `internal/relay/dagsched/feature_coverage.go`, which dev does not have: the packet identity and feature coverage of PR 816 (the cancelled CRW-839) were never merged (see CRW-1212, which makes the same finding). Nothing is edited there; port: kept. `internal/relay/dagsched/manifest.go` is edited for `landedOf` only (below); `accept_premerge.go`, which is not in the body's edit regions, is edited so `premergeLeftOut` reports a held agent candidate as it reports a relationship one; port: kept.
- The UNIQUE key of dag_agent_acceptances, `(execution_id, head, criteria_set_digest)`, is decided here because the shipped zone sentence cannot be edited (dag_zone.go, the header of the ledger): a re-review under new criteria of the same execution and head (R07) is another criteria digest, so another row, and the same key again is the same acceptance. Beyond that key the rows of a node form a chain like its executions (a row names the one it supersedes; one row per node has none; a row is followed by at most one), enforced by the same partial unique indexes and guards, and the value triggers `dag_agent_acceptances_execution_check`, `dag_agent_acceptances_chain_check` and `dag_agent_integration_stages_acceptance_check` keep a row on the plan, node, manifest, execution and head it names (a foreign key only checks that the row exists); port: kept. Pinned by TestAgentAcceptanceAppendOnlyGuards, TestAgentAcceptanceNullAndNoReplaceGuards and TestAgentAcceptanceZoneUpgradeFromOldZone (store, and TestAgentAcceptanceZoneUpgradeFromOldZone in the swap gate).
- The reasons of the agent path (`reviewer_missing`, `reviewer_not_verified`, `independence_refused`, `independence_unproven`, `agent_worktree_unrecorded`, `agent_not_orchestrator`, `cross_kind_acceptance`) are closed reasons in the detail of a `disposition_conflict` or a `scope_role_mismatch`, not new refusal reasons of contract/schema/relay-exit-codes.json (D-02: this build registers no new reason); the checks that exist keep their own reasons (`premerge_*`, `head_not_receipt_head`, `merge_base_mismatch`, `criteria_set_changed`); port: kept.
- What the reviewer verdict and the author pairs are read from is defined by this issue, because the store-backed flow journal (F06) has no writer in this build yet: a reviewer call is the terminal `completed` row of a `reviewer` or `reviewer-final` call that carries the plan, node and execution, with the head under review in `commit_sha`, the verdict document in `result_bytes` and the `criteria_digest` its input carried in `detail_json` (never the digest the verdict document names: a reviewer's own claim about its input is not a record of it); the pair of a call is the configured pair the host read back, the `thread_started` row's `detail_json` (`model`, `effort`), and for a continued call (`resume`), which opens no thread, the `prepared` row's `resume_of` with `configured_model` and `configured_effort`; an author pair is the pair of a completed `executor`, `executor-t1` or `architect` call of the node and the pair of its execution rows; the call is recorded by the run the execution names. The family of a model is `execution.ModelFamily`. A batched reviewer call (one verdict block for several nodes, F15) is not read: its rows carry no single node. port: pending (F06 writes these rows; the keys above are the contract it writes to). Pinned by TestAgentAcceptRequiresDistinctFamilyReview, TestAgentAcceptCriteriaDigestMatch, TestAgentAcceptCriteriaDigestIsTheRecordedInput and TestAgentAcceptReadsContinuedCalls.
- The head of an agent acceptance is the commit git reads in the execution's worktree, never the commit the call names (P-AV-2); a call that names another commit is `head_not_receipt_head`, and an execution that records no worktree cannot be accepted. The relationship commit path takes the head from the ruling the generation fixed (`dag_verified_heads`), which an agent node has no row of; port: kept. Pinned by TestAgentAcceptHeadFromGit.
- A `parent_handover` row continues the execution it follows: the same work under the same manifest, held by another orchestrator. An acceptance or a frozen candidate of the execution before it keeps standing (`agentExecutionStands`), the actor of `dag-integrate`, `MarkFrozen` and the observation is the orchestrator of the current execution (`executionOf`; the observation reads the last row of the chain, closed or not), and a tier step or a correction starts new work, so an acceptance of an earlier execution is not a candidate; port: kept. The batch proves the orchestrator again inside the fenced transaction that moves the branch (an acceptance survives a handover, so the frozen candidate alone does not show the owner changed during the verification). Pinned by TestAgentIntegrateActorIsOrchestrator, TestAgentIntegrateRechecksOrchestratorBeforeTheMove and TestAgentMarkFrozenWritesAgentMark.
- The `merged_json` entry of a batch row names `"execution_kind":"agent"` for an agent candidate and is left as it was for a relationship candidate (`omitempty`), so the bytes of every existing batch row and the output of `dag-integrate` do not change; port: kept. Pinned by TestAgentIntegrateActorIsOrchestrator and TestRelationshipPathUnchanged.
- A node that holds a current acceptance on both sides is held out of candidate selection and of `premergeLeftOut` instead of failing the listing of the whole plan, and the explicit request for it is refused `cross_kind_acceptance`; `acceptanceOf` returns neither record. port: kept. Pinned by TestAcceptanceOfAtMostOneCurrentAcrossKinds.
- `landed_sha` of an agent landing is the merge commit the batch recorded for the acceptance (`dag_integration_batches.merged_json`), read through `landedOf` for an observation of an agent acceptance, and not the accepted head and not the tip the observation read (the cancelled CRW-1003, d3: the landed commit was attributed to the wrong commit). The relationship kind still reports the tip (or the landed merge turn); port: kept. The merge commit is selected by the observation's target (repository and ref against the batch's checkout and integration ref), so an acceptance integrated into two refs answers each observation with its own merge commit; and it is bound to the landing the observation proved: the agent `intent` row records the acceptance's highest observation sequence number on the batch's target when the batch froze it, and a batch frozen at or after an observation's sequence number is never its landing, so a reintegration of the same target after it lost the merge leaves the earlier observation on the first merge commit. Pinned by TestAgentLandedShaIsRecordedMergeCommit, TestAgentLandedShaIsThatOfTheObservedTarget and TestAgentLandedShaOfAnObservationOutlivesAReintegration.
- The slot of an agent node goes back with the reason `dag_accepted` (a node without a head) or `dag_integrated` (every target satisfied by `agentIntegratedAt`) in the transaction of the acceptance or the observation; `slotReturner` also reads an agent node's chain, so a slot held for the previous orchestrator goes back as its recorded holder after a handover; port: kept. Pinned by TestAgentNonImplementationAcceptReleasesSlot and TestAgentIntegratedReleasesSlot.
- The serialization of integrations into one target is the compare-and-swap of the ref move the batch already makes (`git update-ref ref new old`, then a record of the move that `VerifiedMoveOnto` reads), so the code of `VerifiedMoveOnto` and `PushIntegration` did not change and POLICY.md and AGENTS.md state the rule in the present tense; the loser of two projects' race moves nothing, cannot push a tip it did not verify, and merges and verifies again on the new tip before it lands. Pinned by TestAgentVerifiedMoveOnto and TestTwoPlansSameTargetCASLoserReverifies; port: kept.
- What stays for R06: the conflict sweep a receipt or a landing owes is not run for an agent node (it measures the live heads of relationships' executions), `staleOf` and `consumedStanding` read the frozen acceptance, so they judge no agent acceptance stale (the candidate predicate adds the criteria equality and the execution check itself), and an edge out of an agent node is satisfied by no landing (`integratedEdge` reads `loadActiveAcceptance`); docs/relay/agent-execution-readers.md lists the readers. port: pending (R06).
- The PR-route landing of an agent node and the pull-request acceptance of an agent node do not exist: a call that names `--repository` and `--pull-request` for a node with a current agent execution is `malformed_receipt`, and CRW-1226 owns the landing; there is no 'local CI only' route. port: kept.
