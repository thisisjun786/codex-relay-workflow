# CRW-1165 — one form proves a cd: `cd <literal path> || exit <digits>` at the top of the text

Source: follow-up of CRW-1099 (Claude cross-check of lane-guard-worktree-ingress 6e7dc565c, P2, outside its promised scope); CXC v0.2.40 `pabcd-state/src/worktree-guard.ts:280-287` (the oracle skips a segment that starts with `cd` and does not model a failed cd). The Go side is `internal/pabcd/shellir/cdexit.go` (the form and the text it needs), `shellir.go` (`cdOrExit`, `Context.top`) and `env.go` (`analyze`); the readers that ask for proven directories are `AnalyzeEnvProvenDirectory` and `AnalyzeScriptProvenDirectory` (the worktree deletion guard in `internal/pabcd/hook/worktreedel_judge.go`, the memory write gate and the shell write reader).

- Supersedes known-defects/CRW-1099.md, bullet beginning "Post-evaluation safety corrections" (the sentence that only a simple, non-negated `cd` reached through success on `&&` establishes the directory for the next command): it now has one more case. port: fixed as a narrowing (over-refusal of ordinary cleanup; the refusal was the safe direction, so this is no security repair). A statement at the top of the text (not in a block, a branch, a loop, a function, a subshell, a substitution or a carried text such as `bash -c` or `eval`) that is exactly `cd <literal path> || exit <digits>` proves the cd for every later statement of the same list: a cd that fails ends the shell, so `cd /outside || exit 1; rm -rf out` removes `out` in `/outside` and is allowed like `cd /outside && rm -rf out`. The path is literal text (no expansion, pattern, brace, tilde, option or quote left in it), the cd and the exit carry no redirection, assignment, negation or background, the status is one to three digits, and the proof holds only if the text around it leaves `exit` and `cd` alone: no function, coprocess, `declare`/`typeset`/`local`, and none of trap, enable, source, `.`, eval, alias, unalias, shopt, builtin, command, unset, set, exec, hash, setopt, unsetopt, emulate, autoload, fc, history, bind anywhere in the text (also quoted or backslashed, `'local'`, `\eval`), and no command name the reader cannot spell (`$CMD`). Where the reader is given the environment, a BASH_ENV, ENV, SHELLOPTS, BASHOPTS, CDPATH or exported function named exit or cd withdraws the proof (the worktree guard reads with no environment, as for `&&`).
- Everything else stays unproven and refused: `cd X; rm`, `cd X || true`, a bare `exit`, `exit $?` or any status that is not digits, `exit 1 2` (bash does not exit on it), `|| return`, `|| { ...; exit 1; }`, `set -e`, `if cd X`, `cd -P`, a cd with a redirection or an expansion, and the same form inside a group, a subshell, a function, a branch, a loop, `bash -c`, `eval`, `trap` or `find -exec sh -c`. The 13 ways found by the verification of the first attempt (lane worktree-cd-proof, final ce5e66ca7, a P0 per round: a failure branch that removes the directory, a `return` before a group, `exit` redefined in a group, `exit $(echo 1 2)`, a failing redirection under `set -e`, `set -Qe`, an unreachable `set -e` after `return`, a function's state after `return`, a DEBUG trap, `enable` or `source` before `set -e`, an expansion error, `exit` redefined by the left command, a quoted `'local'`) are refusal tests first (`TestCRW1165EveryOtherFormKeepsTheDirectoryUnproven` and `TestCRW1165CdOrExitProvesOnlyTheOneForm`); the first attempt's wider forms (`set -e`, `|| return`, `if cd`) are not taken. The `find ... -exec sh -c 'cd build; rm -f {}' \;` case (worktreedel_crw895_test.go) and the `cd /tmp; echo "$(rm -rf ../repo)"` corpus row keep their expectations: the `;` form is not this form.
- The refusal tests of that first attempt are kept as they were (`TestCRW1165FirstAttemptRound0Refusals` to `Round4Refusals` and `TestCRW1165FirstAttemptMemoryGateRefusals` in `internal/pabcd/hook/worktreedel_crw1165_first_attempt_test.go`, taken from the lane branch codex/crw-lane-worktree-cd-proof): each command is run as written and again with its bare `exit` given the status `1`, the one spelling the narrow form accepts, so each is refused by the text around the form and not by how the exit is spelled; the memory write gate reads the same texts. A script file is a text of its own: `cd <literal> || exit 1` at its top proves the cd for the rest of the script (`bash script.sh` is allowed), a bare exit or a group does not.
- The proof is checked against real shells: `TestCRW1165ProofHoldsInRealBash` runs bash (and zsh where installed) on every combination of 24 forms, 26 prefixes that could change exit or cd, and 10 wrappers, with a cd target that does not exist, and requires that no command the reader places in the target runs. Not claimed: a function, alias or trap that the shell itself defines before the text runs (the guard shares this assumption with every command it reads, `rm` and `cd` included), and the logical path of a cd target that is a link (the guard compares paths as it does for `&&`).
- Verification: the Sol xhigh pass the issue asks for (security guard; any P0 keeps the change out of integration and the issue in Backlog) is the coordinator's step; this lane ran its own differential and adversarial review only.
- Verification round 1 (two P0, both fixed before integration). (1) zsh `disable exit` (and `unhash`, `unfunction`, `zmodload`, `zcompile`, `sched`) removes or replaces a builtin without any of the names the first list held, so `disable exit; cd /missing || exit 1; rm -rf .` went on after the failed cd (real `zsh -f`: `command not found: exit`); those names are in the list of `exitProofBanned` now, and `export -f` / `readonly -f` (any declaration option holding `f`) withdraws the proof as well. (2) A function named exit that the parent shell exports (`exit() { :; }; export -f exit; bash cleanup.sh`, or `env 'BASH_FUNC_exit%%=() { :; }' bash cleanup.sh`) is inherited by the bash that runs the script, whose body the guard read on its own and found plain. Three changes close the boundary: the reader refuses a function named exit like every other modelled program (`modelledName`); `BASH_FUNC_*`, `SHELLOPTS` and `BASHOPTS` are code environment names (an assignment before a program is refused, as BASH_ENV is); and a record of a script file now says whether the text that runs it left exit and cd alone (`Exec.ExitTainted`), which the reader of the body takes over (`AnalyzeScriptProven`, `ScriptOptions`): a body run by a text that is not plain (trap, set, eval, a function, disable ...) does not get the proof, so `trap : DEBUG; bash cleanup.sh` refuses where `bash cleanup.sh` is allowed. The worktree guard also answers the shell startup variables (BASH_ENV, ENV, SHELLOPTS, BASHOPTS, BASH_FUNC_exit%%, BASH_FUNC_cd%%, CDPATH) from the hook's own environment, which the command inherits; every other variable stays unknown for it, as before, and the memory gate passes the environment it has to the script bodies it reads. Tests: `TestCRW1165FixRound1*` (shellir and hook; the hook ones are the verifier's two probes plus a table run against real bash and zsh: an allowed text must not leave the stand-in `touch` after the failed cd), and the prefixes `disable exit; ...`, `unhash`, `unfunction` and the exported function in the real-shell differential. The review of that round found one more way in the same family: zsh defines a function or an alias by assigning to a table (`functions[exit]=:`, or `aliases[exit]=true` on a line before the form; real `zsh -f` ran the command after the failed cd), with no command that declares it. A text that spells `functions`, `aliases`, `galiases`, `saliases`, `options`, `BASH_ALIASES` or a `dis_*` table anywhere (a command, a string or a comment) gets no proof, and a text that assigns variables by a name it does not spell (`read "$N"`, `printf -v "$N"`, `export "$N"=...`) is read again without the proof when the first reading used it. Not claimed: a function or option the shell defines before the text for reasons outside the hook's environment (a login shell snapshot of the user's functions), as before.
