# CRW-1005 — the state rewrite and a lone UTF-16 surrogate: slug, supersededBy and receiptClaimed

Source: the CXC v0.2.40 oracle (commit 3c1459ac) `pabcd-state/dist/state.js` `readStateStrict` (:494) and `writeState` (:620), which keep a lone surrogate escape (such as `\ud800`) in a stored string when the file is rewritten; and the port's `internal/pabcd/state` (`write.go` `writeState`, `rewrite.go` `RewriteKeepsUnverified` and `rewriteLosslessUnpaired`, `restore.go` `ReconstructUnverified`). The pinned cases are `lone-surrogate-slug` and `truncated-receipt-claimed` in `internal/dev/cxcfuzz/testdata/state/cases.json`, found by the CRW-708 state campaign (seed 708, head 49e3cd18c).

Decision D1 (coordinator, 2026-10-09): a state file that holds an unpaired surrogate escape is refused by a rewrite, not preserved in place. The issue's preserve criterion is replaced by refusal. The port reads the escape as U+FFFD in memory and a Go string cannot carry a lone surrogate to disk faithfully, so preserving it would also make the next rewrite of that file refused.

- The oracle's `writeState` keeps a lone surrogate escape in `slug`, `supersededBy` or `receiptClaimed` as written (state.js:620), where the port's `WriteState` wrote U+FFFD over it; pinned as `lone-surrogate-slug`. Before this change the guard `RewriteKeepsStored` refused only the callers that consulted it, so a `WriteState` caller that did not consult it wrote U+FFFD. `writeState` now checks the file on disk with `rewriteLosslessUnpaired` and returns an error naming the file, which leaves the file byte for byte as it was. Red: `TestWriteStateRefusesToRewriteAFileHoldingALoneSurrogate` (red output in `/state/crw/crw-1005/evidence/red-1-write-refuses.log`); a whole surrogate pair still writes (`TestWriteStateStillWritesAFileWhoseSurrogatePairIsWhole`). The check fails closed: a file that exists but cannot be read (permissions, I/O) cannot be shown clean, so `writeState` returns before staging a temp file; only a missing file is a new write, and a directory at the path falls through to the rename failure it always had (red: `TestWriteStateRefusesWhenTheExistingFileCannotBeRead`, `/state/crw/crw-1005/evidence/fix1/red-unreadable.log`; `TestWriteStateCreatesAFileThatDoesNotExist` keeps the new-file path). port: intentionally-changed (D1: refusal instead of preservation; the in-memory read still shows U+FFFD, nothing is written).
- The 256-unit cut of `receiptClaimed` (`restore.go` `ReconstructUnverified`, the astral-cut path) leaves a lone high surrogate, which the oracle keeps and the port writes as U+FFFD; pinned as `truncated-receipt-claimed`. Checked against the original: both cut the receipt at the same 256-unit boundary and both lose the low half of the pair, so the cut is not a new loss; only the replacement of the cut half differs. The port keeps its valid U+FFFD, because a lone surrogate written to disk would make the next rewrite refused (D1). port: intentionally-changed (the cut's replacement character, D1 rationale).
- A lone surrogate already in a file is still read as U+FFFD by `ReadStateStrict`; only the write is refused. No read path changed. port: kept (the read answers as before).
- Open for the coordinator: a file that holds a lone surrogate now fails every `WriteState` caller until the escape is removed, including hook writers that previously wrote it over. The refusal is D1, but the recovery path (who clears such a file, and whether the CLI reset should) is not decided here.
