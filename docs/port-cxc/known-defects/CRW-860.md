# CRW-860 — pyjson boundary inputs: lone surrogate keys, Normalize spellings, hook budgets of one and two, circular values

Source: package audit p65-m75-audit-r1 (grader gpt-6-astra xhigh, head 80d26ad1; parent triage /state/crw/p-crw-65-m1-run1/audit-r1-triage.md, items J1 to J5). The oracle for internal/pyjson is Python's json.loads and json.dumps (the relay's stored and hashed formats), not a CXC file. The Go files are internal/pyjson/scan.go (object, closed, HookedError), dumps.go (number, value, containerIdentity, Encode, Dumps) and loads_test.go. The red tests are TestCRW860_* in internal/pyjson/boundary_audit_test.go; the red output is /state/crw/crw-lane-m75-audit-fixes/evidence/red-CRW-860-pyjson-j1-j3.log (J1 to J3) and red-CRW-860-pyjson-j4.log (J4, a stack overflow). Reachability, per item: J1 is reached by a current caller (the execution policy file is scanned by HookedError in internal/bridge/execution/decode.go and, through nestedTooDeep, in internal/relay/registry/rolepolicy.go before any schema check, so a policy with distinct lone-surrogate keys such as {"\ud800":1,"\ud801":2} meets the changed key reading); J2 is not reached by a current caller (the Normalize callers, internal/bridge/ledger/canonical.go and internal/relay/store/receipt_intake.go, encode values from encoding/json with UseNumber or from Loads, whose numbers are valid JSON spellings); J3 is not reached in production (the only hook budget in use is execution.PolicyDepth, 9998; budgets of one and two are package API); J4 is not reached by a current caller (callers pass JSON-shaped values read from Loads or encoding/json, which hold no cycle); J5 is a test only.

- HookedError decoded object keys with encoding/json, which turns each lone surrogate into U+FFFD, so two distinct lone-surrogate keys were reported as a duplicate (J1, scan.go). The refusal side only: port: fixed (the key is read as loads reads a str with Surrogates, so distinct lone surrogates are distinct keys and the same surrogate twice is still a duplicate. Pinned by TestCRW860_HookedErrorKeepsDistinctLoneSurrogateKeysDistinct).
- Encode with Normalize read an integer spelling with big.Int.SetString and a fraction or exponent with ParseFloat before any JSON-number check, so +1 and 01 were written as 1 with no error, while Encode without Normalize refused them (J2, dumps.go). port: fixed (the spelling is checked as a JSON number before it is normalized, as without Normalize; a lenient Dumps still writes the spelling as it is. Pinned by TestCRW860_NormalizeRefusesAnInvalidNumberSpelling).
- The hook's recursion check was on only for a hook budget above zero, so a limit of one or two (hookDepth of minus one or zero) never refused an object that closes deeper than the budget (J3, scan.go). port: fixed (an explicit hooked flag gates the check, so a budget of one or two is enforced as the documented limit-2 rule states. Pinned by TestCRW860_HookRecursionBudgetOfOneAndTwoIsEnforced; the unbounded budget of zero and the budget of three are controls in the same test).
- writer.value had no cycle state and no depth cap, so a map, slice or Object that holds itself recursed until the goroutine stack was exhausted, a fatal error and not an error value (J4, dumps.go). port: fixed (the writer tracks the containers it is inside of by data pointer and length. Encode refuses a cycle with "circular reference detected"; a lenient Dumps writes the back reference as null. The depth is not capped: a finite value is bounded by its own size, and only a cycle recurses without end. Pinned by TestCRW860_EncodeRefusesACircularValue, which also checks that a shared acyclic value is written in full).
- The SortKeys round trip in TestDumps_writes_what_Loads_reads_back skipped the value comparison (J5, loads_test.go, a test-adequacy gap and not a defect of the writer). port: fixed (the round trip compares each value against the same value with its Object fields in key order, through sortedFields; the strengthened comparison passes on the current writer, so no defect was found by it).
