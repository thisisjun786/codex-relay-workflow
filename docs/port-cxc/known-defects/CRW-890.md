# CRW-890 — an OCX that refuses the live-catalog command is its own catalog state

Source: `plugins/codexclaw/components/subagent-config/src/live-catalog.ts` (the `catch` at :108-113) at CXC v0.2.40,
commit 3c1459ac; the Go port at `internal/role/livecatalog.go` (`ErrCatalogUnsupported` :31, `unsupportedMessage` :34, the
failure answer :184-208, `RunOcxModels` :511 with the classification at :533-535, `rejectedCommandLine` :541-560) and
`internal/role/catalog.go` (`CatalogUnsupported` :29). Recorded by CRW-1078 from the oracle review of 2026-10-10 (finding
U11-001); the change itself is CRW-890 (`318ee6a5d`), whose issue required it. The GUI and the MCP server read the catalog
through the same reader.

- The oracle treats every rejection of the OCX models command as an ordinary discovery failure: with no cache the answer is
  state `unavailable`, status `unavailable` and the message "OCX model discovery failed. Check OCX and refresh."; with a cache it
  keeps the cache's own state, sets status `stale` and appends " Showing the last successful list." to the same message
  (`live-catalog.ts:108-113`); port: fixed (CRW-890 decided that an OCX that has no live-catalog command is not a catalog that
  could not be read, and the answer must say so. A non-zero exit with empty stdout and a stderr line starting `Usage: ocx models`
  is the OCX refusing the command line itself, and only that signal is classified as `ErrCatalogUnsupported`; any other failure
  stays an ordinary discovery failure, so the oracle's answer for it is unchanged. The result differs from the oracle only for that
  rejection, and both cases change:

  | | oracle | port |
  | -- | -- | -- |
  | no cache: `state` | `unavailable` | `unsupported-ocx-catalog` |
  | no cache: `status`, entries | `unavailable`, none | `unavailable`, none (same) |
  | no cache: `message` | "OCX model discovery failed. Check OCX and refresh." | "This OCX does not support reading the live model catalog (ocx models live --json)." |
  | cache: `state` | the cache's state (for example `ocx-active`), replaced nowhere | `unsupported-ocx-catalog`, set in the struct and in the cached raw object that is merged into the wire answer |
  | cache: `status`, entries | `stale`, the cached list | `stale`, the cached list (same) |
  | cache: `message` | "OCX model discovery failed. Check OCX and refresh. Showing the last successful list." | "This OCX does not support reading the live model catalog (ocx models live --json). Showing the last successful list." |

  Pinned by `TestLiveCatalogTellsUnsupportedFromAFailure` (unsupported with and without a cache, wire state included; a read
  failure, with and without a cache, stays `unavailable` and `stale` and is never unsupported) and
  `TestRunOcxModelsClassifiesTheCommandRejection` (the usage block is unsupported; a runtime failure is not) in
  `internal/role/unsupported_test.go`.)
