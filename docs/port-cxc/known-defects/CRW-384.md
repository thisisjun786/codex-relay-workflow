# CRW-384 — orchestrate transition core

Source: CXC v0.2.40 (`3c1459ac`) `plugins/codexclaw/components/pabcd-state/src/orchestrate-cli.ts`, the transition half
:549-1131 and the helpers :96-103 and :431-465 it uses, ported to Go as `internal/pabcd/cli/orchestrate_transition.go`
with the `orchestrate-cli.test.ts` cases of that range as `internal/pabcd/cli/orchestrate_transition_test.go`. The
recorded corpus has no fixture this issue can claim: the orchestrate fixtures need the CLI verb row, which CRW-758
owns, so they stay pending and nothing here is tagged identical or intentionally-changed.

- The command's own contract says it never throws ("Execute a parsed orchestrate CLI command. Does its own state IO.
  Never throws."), yet three paths of the ported range let an exception escape to the caller: the source resolution of
  every phase verb (`orchestrate-cli.ts:572`, whose own catch handles only the refusal it raises itself), the B entry
  source capture (`:1070`) and the epoch nonce's `randomBytes` (`:97`) (source `orchestrate-cli.ts:423`, `:572`, `:97`
  and `:1070`); port: kept (the Go port has no throw, so it returns those as an error to the caller, which is the same
  answer at a different carrier; no refusal path of the range uses it).
- Two arms of the ordinary edge write can never run: the plan binding's "entering A another way" arm
  (`result.state.phase === "A" ? state.planUnit : null`, `orchestrate-cli.ts:1073-1074`) and the check epoch's
  "staying in C" arm (`state.phase === "C" ? state.checkEpoch : ...`, `:1077`). No legal edge is a self-edge, and P>A is
  the only edge into A, where the minted binding always wins the first arm, so both read as live rules that nothing
  reaches (source `orchestrate-cli.ts:1073-1077` against `fsm.ts`'s `VALID_TRANSITIONS`); port: kept (both arms are
  ported as they are, in `orchestrateTransitionPlanBindingOf` and `orchestrateTransitionCheckEpoch`, so the port's shape
  matches the oracle's; a later change may drop them).
- Supersedes known-defects.md, section "Found by the CRW-609 lossless rewrite guard", item beginning "A writer of the
  session file that does not ask the guard still replaces a lone surrogate": now port: fixed for this writer (the
  orchestrate transition is the writer that item named as a future one; each of its three session writes asks
  `cliVerdictsIntact`, which is `state.RewriteKeepsUnverified` plus the count the caller read, and refuses with
  "refusing to overwrite it" and no write at all, leaving state, both ledgers and the goalplan untouched; the general
  item stays for any writer that does not ask the guard).
