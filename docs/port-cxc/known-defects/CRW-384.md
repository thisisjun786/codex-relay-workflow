# CRW-384 — orchestrate transition core

Source: CXC v0.2.40 (`3c1459ac`) `plugins/codexclaw/components/pabcd-state/src/orchestrate-cli.ts`, the transition half :549-1131 and the helpers :96-103 and :431-465 it uses, ported to Go as `internal/pabcd/cli/orchestrate_transition.go` with the `orchestrate-cli.test.ts` cases of that range as `internal/pabcd/cli/orchestrate_transition_test.go`. The recorded corpus has no fixture this issue can claim: the orchestrate fixtures need the CLI verb row, which a sibling issue owns, so they stay pending and nothing here is tagged identical or intentionally-changed.

- The command's contract says it never throws, yet three paths of the ported range let an exception escape: the source resolution of every phase verb (`:572`), the B entry source capture (`:1070`) and the epoch nonce's `randomBytes` (`:97`) (source `:423`); port: kept (the Go port has no throw, so it returns those as an error to the caller; no refusal path uses it).
- Two arms of the ordinary edge write can never run: the plan binding's "entering A another way" arm (`:1073-1074`) and the check epoch's "staying in C" arm (`:1077`), because no legal edge is a self-edge and P>A is the only edge into A; port: kept (both are ported as they are, in `orchestrateTransitionPlanBindingOf` and `orchestrateTransitionCheckEpoch`).
- The transition publishes the state it read when the command started, with no lock, so a hook that writes the same session in between - a memory grant, an idle-edit counter, a verdict - is overwritten by the stale copy and its update is lost (source `:163`, `:653` and `:1070-1131`; found by the Devin review of this port's pull request, `kind: bug`); port: fixed (a data-loss defect, the class the parity rule revision of 2026-10-03 fixes during the port: `RunOrchestrateTransition` holds `state.WithSessionLock` across the whole read, gate and write, and a lock that cannot be taken is reported as an error; `TestOrchestrateTransitionHoldsTheSessionLock`).
- The ordinary edge publishes the session state before its transition-ledger row (source `:1119` then `:1123`), so a row write that fails leaves an advanced FSM whose row nothing can replay and a retry the table refuses; port: fixed (the row goes first, so a failed append changes nothing and the same verb can be retried; found by the Codex review; `TestOrchestrateTransitionRowBeforeState`).
- The P>A housekeeping takes the epoch of only the FIRST open plan_audit round whose epoch differs from the new one and hands just that epoch to `supersedeStaleRounds`, so a plan holding open rounds of two or more old epochs keeps the later ones open (source `:1088-1096`; found by the Devin review, `kind: bug`); port: kept.
- The housekeeping runs before the state write and is fail-open (source `:1085-1119`), so a P>A whose state write then fails has already closed the old rounds and cleared their cursor while the session stays at P, and the retry mints a different epoch (found by the Devin review, `kind: bug`); port: kept.
- The A>B review binding (source `:49-92`, `:688-691`) and the B>C source gate (source `:701-717`) are not ported by this issue: `orchestrateTransitionReviewBinding` and `orchestrateTransitionSourceGate` are pass-throughs that the sibling issue which owns them fills, that issue also owns the `crw pabcd orchestrate` verb row, and nothing in the tree calls `RunOrchestrateTransition` but its own tests. Two review findings of `kind: security` name the gap (the Devin review); port: pending (the sibling issue that ports the two gates closes it).
- The rewrite guard this file asks (`cliVerdictsIntact`) covers the unverified-record half only; the interview half - a stored tracker past `interview.MaxTrackerArray`, or ontology entries reconstruction drops - lives unexported in the hook package (`sessionHookInterviewKeepsStored`), which this issue's edit regions exclude (found by the Codex review); port: pending.
- The goalplan read that gates the work-phase binding is not held under the goalplan write lock across the session publication (source `:613` against `:1119`), so a plan a steering or lifecycle writer changes in that window is not revalidated (found by the Codex review); port: pending.
- Supersedes known-defects.md, section "Found by the CRW-609 lossless rewrite guard", item beginning "A writer of the session file that does not ask the guard still replaces a lone surrogate": now port: fixed for this writer (each of its three session writes asks `cliVerdictsIntact`, which is `state.RewriteKeepsUnverified` plus the count the caller read, and refuses with "refusing to overwrite it" and no write at all; the general item stays for any writer that does not ask the guard).
