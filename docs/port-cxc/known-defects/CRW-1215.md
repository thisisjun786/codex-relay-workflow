# CRW-1215 — the life of an agent node: handover, a correction attempt of a stale result, the restart report, and the slot of a node that is given up

Source: the 0.5.0-alpha design issue R07 (CRW-1215). This is the port's own addition: CXC v0.2.40 (commit 3c1459ac) has no agent execution kind, so there is no oracle line for it. The Go files are internal/relay/dagsched/agent_lifecycle.go (AgentClose, AgentCorrect, adoptAgent, resumeOfAgent), epoch.go (Adopt, AdoptWith, the restart report and its printed object), revalidation.go (routeOf, routeAgentNode, ActionAgentCorrection) and the tests in agent_lifecycle_test.go. The functions are library functions of dagsched; their one writer is the run process (R10), which has no command for them yet.

- Supersedes CRW-1214.md, the item beginning "Not done here, and not a defect of the readers": now port: fixed (`routeOf` reads the node's current acceptance of either side; an accepted agent node is routed by `routeAgentNode` to `agent_correction`, to `revalidate` when only its criteria changed and everything it consumed is current, or to `hold`, and never to `redefine`; `AgentCorrect` is the correction). Pinned by TestStaleAgentNodeReleasesCorrectionAttempt, TestCriteriaOnlyChangeRereviewsSameHead, TestAgentCorrectRefusals.
- The `SAME child` rule of revalidation.go (a result that must be reworked goes back to the same child, as the next generation of the same relationship) is the rule of a relationship node. An agent node has no child, and its place is the next attempt of the same node: a row of `dag_agent_executions` of kind `correction` that supersedes the current one. A change of the criteria alone writes no execution row: the same head is judged again by a new reviewer call, and the acceptance row of the same execution, head and the new criteria digest follows the old one (R05's `UNIQUE (execution_id, head, criteria_set_digest)`). port: kept. Pinned by TestCriteriaOnlyChangeRereviewsSameHead.
- `Adopt` of an agent node appends a `parent_handover` row (same manifest, role, tier, pair, thread, worktree and base; the next attempt; it supersedes the current row; the actor is the registered parent of the project and holds the epoch). An acceptance made before it stands (`agentExecutionStands` follows handover rows), `executionOf` names the new orchestrator for the integration, no operator is needed because an agent node has no merge turn, and the slot stays held under the task that reserved it: `slotReturner` finds that task in the node's agent chain and returns the slot as it, with no reservation a ceiling could refuse. The run id of the new row is the one of the row it follows unless the caller names its own (`AdoptWith`, `AdoptOptions.RunID`); `dag-adopt` has no `--run-id` flag (`specs.json` is outside the edit regions of this issue), so a handover through the command keeps the previous run id. port: kept (pending R10 for the flag). Pinned by TestAgentNodeHandoverIntegrates, TestHandoverAgentSlotReturnedAsHolder, TestHandoverAgentSlotReturnedAsHolderByAClose.
- A recovery hold writes nothing. The zone has no state for it (`dag_agent_closures` knows cancelled, escalated, superseded and revoked), and the body says it keeps the slot, so `AgentClose` with `dispatch_unknown` or `host_failure` answers `Held` after it has checked the actor and the execution, and `dag-restart` derives a held node from the journal: a call of the work the current execution holds (its own and the executions of the `parent_handover` rows before it) is unresolved: the newest event of that call (greatest `event_seq`) ends `held` or `outcome_unknown`, or is an intent (`turn_requested`...) that never ended. Calls are judged one by one; the first version read only the newest row of the whole work, so a completed independent call hid an unresolved one (evaluation 08a9d2b1, d3). A held node needs `crw flow recover`, a released one `run resume`. The body does not say how held is read; a call that ended `held` for an engine pause is reported as held as well. port: kept. Pinned by TestHoldKeepsAgentSlot, TestRestartReportsAgentNodes.
- `AgentClose` of a node that has a standing acceptance that has not landed closes the acceptance too (state `revoked`, no slot of its own) in the same transaction, which the body does not say: an execution closed under a standing acceptance would leave the node reading accepted and satisfying the edges built on it. A node whose head landed is refused (`disposition_conflict`, `landed`): its value is in the target. So is a node whose head may have landed (`agentLandingRefusal`, `agentLandingOpen`): IntegrateBatch moves the target and records the move before ObserveIntegration reads it, and the observation needs the acceptance to stay current, so a close or a correction in that interval would revoke or supersede an acceptance whose head is in the target. A batch of the acceptance that moved the ref, marked the head contained or planned the move counts until an observation of the target made after the batch froze the acceptance says the target lacks the head; the observation (dag-observe) settles it either way (evaluation 08a9d2b1, d1). The guard errs to refuse: a batch that planned a move it never made keeps the node until the target is observed once. port: kept. Pinned by TestCancelReleasesAgentSlot, TestAgentCloseRefusesALandedNode, TestAgentCloseAndCorrectKeepAMovedUnobservedLanding, TestAgentCloseAfterALostLandingIsAllowed.
- A node whose execution a closure ended reads as a node nobody owns (`planned`/ready), as R04 defined it, so `dag-ready` offers it again; keeping a cancelled or escalated node from being released again is the run's decision (R10), which holds the plan. port: pending (R10).
- `AgentCorrect` keeps the slot a node holds (an accepted head that has not landed holds it, and the holder may be the previous orchestrator) and reserves one from the frozen manifest only when the slot went back with the acceptance (a node without a head); a reservation the capacity refuses rolls the whole correction back. Its judgement is judgeNodeRelease's without the readiness reading (`judgeCorrection`, `rejudgeCorrection`): the node is held by its own accepted execution, so the reading would never call it ready, and what the reading checks (the plan lets the node run, nothing above it is stale, every input is there) is what the route `agent_correction` already requires. The half of the judgement after the reading is repeated in agent_lifecycle.go because release.go is not among the edit regions of this issue; the two copies are to be one function when a later issue edits release.go. The correction is admitted as a release is (`correctionAdmission`, agent_lifecycle_guard.go): the host memory bound, the merge window and registered-parent check of `resourceHold`, and the edit-region overlap of the release rule under the plan's release policy are judged with the node's own execution left out; the host is read once before the transaction, the rest again inside it (evaluation 08a9d2b1, d2; capacity is the reservation's). Pinned by TestAgentCorrectKeepsTheReleaseAdmission. The attempt starts at the role and tier the caller names (`AgentReleaseOptions`; the run passes the first tier of the executor policy). port: kept (pending the merge of the two judgements). Pinned by TestStaleAgentNodeReleasesCorrectionAttempt, TestStaleNonImplementationAgentNodeReservesItsSlotAgain.
- `dag-restart` prints an `agent` object for an agent node (`execution_id`, `execution_kind`, `attempt`, `state`, `actor_task_id`, `run_id`, `action`) and adds no key to the nodes of a relationship. A node another orchestrator holds is `adopt_needed` with the action `dag-adopt`; a node this actor holds is `adopt` (released: `run resume`; accepted: `dag-integrate`, or the correction or the new review a stale route names), `reconcile` (held: `crw flow recover`) or `none` (integrated, or accepted with no head to land). port: kept. Pinned by TestRestartReportsAgentNodes, TestRestartReportsStaleAgentNodes.
