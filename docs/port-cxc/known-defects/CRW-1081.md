# CRW-1081 — relay job run passes the caller's descriptors to the job

Source: Linear CRW-1081, left out of CRW-1057 as the same class of defect on the job CLI path. The oracle is CXC v0.2.40 (commit 3c1459ac), which is not in this clone, so its spawn lines are not cited. The Go files are internal/relay/job/spawn.go (runBackground, which calls markInherited before the shell is started), the shared sweep internal/relay/fdsweep/sweep.go (MarkInherited, moved out of internal/relay/service by this issue so that the job package can use it: service imports job, so job cannot import service), and the tests internal/relay/job/spawn_inherit_linux_test.go (TestRunBackgroundDoesNotInheritCallerDescriptors, TestRunBackgroundKeepsExtraFiles, TestRunBackgroundRefusedWhenTheSweepFails). The red and green runs are /state/crw/crw-lane-job-fds/evidence/red-1-before-fix.log and green-1-after-fix.log.

- `relay job run` (internal/relay/dispatch/job.go -> internal/relay/job/verbs.go RunBackground -> spawn.go, exec.Command with Setsid and no ExtraFiles) gave the detached shell every descriptor above 2 that the job CLI process held without close-on-exec, and the job outlives its caller: a shell's `exec 9>lock` (the installer's integration lock) stayed held by the job. The red test holds such a descriptor at 20 and lists `/proc/self/fd` from inside the job: the caller's file was there. port: fixed (runBackground marks every descriptor above 2 close-on-exec through fdsweep.MarkInherited, after the removals and the NUL check and right before the start, so a refused argument still starts nothing).
- The sweep is the one of CRW-1057 (close_range with CLOSE_RANGE_CLOEXEC, then /proc/self/fd, then /dev/fd), not a copy: it moved to internal/relay/fdsweep, service/inherit.go keeps its error text and calls it, and the service behaviour is unchanged (its sweep tests moved with the code; the launch refusal test stays in service and replaces closeOnExecInherited instead of the sweep tables).
- A start that cannot show that every caller descriptor is kept out of the job is refused: runBackground returns the error and writes no record and no ledger row, as for any start failure that Node throws from spawn itself. port: deviation, fixed (the same reasoning as CRW-1057: a descriptor that cannot be marked, or no way to reach every descriptor, is the in-promise defect).
- Descriptors passed on purpose are not touched: the fork sets ExtraFiles up at 3 and up and clears close-on-exec on those copies, so a file a start function adds to cmd.ExtraFiles is still in the job (TestRunBackgroundKeepsExtraFiles). RunBackground itself passes none.
- The tests hold their descriptor at 20, inside the soft descriptor limit, and do not depend on a raised RLIMIT_NOFILE.
