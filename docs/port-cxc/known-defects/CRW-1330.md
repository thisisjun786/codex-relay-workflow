# CRW-1330 — a flow run's role pairs had two sources, and the policy loader refused a file for a section nothing ran on

Source: CRW's own design (CRW-1316 design section 8, Jun's decision in the CRW-1316 issue that the helper role store decides the subagent models), not the CXC oracle: the flow engine has no counterpart in CXC v0.2.40 (commit 3c1459ac). The CXC side is the helper role store (subagent-config/src/store.ts, ported as `internal/role/store.go`), whose role list `Roles()` (explorer, reviewer, executor, architect) the GUI bundle, the settings API, the MCP tools and the spawn hooks read and which this issue does not change. The Go side is `internal/role/flowroles.go` (the flow-only keys and `ReadFlowSnapshot`), `internal/role/helper_cli.go` and `store.go` (get, set and reset of the flow-only keys), `internal/flow/engine/policy.go` (`PolicyFromRoleHelper`), `internal/flow/engine/cli.go` (`LoadPolicy`), `internal/flow/engine/roles.go` (`crw flow roles`), `internal/flow/engine/engine.go` (the started row), `internal/flow/cli/start.go` (the start plan), `internal/bridge/execution/agentroles.go` and `policy.go` (the loader), `internal/bridge/capabilities.go` (`get_capabilities`) and `internal/runtime/doctor/flow_roles.go` (`crw doctor flow-roles`).

- The six pairs of a flow run came from the execution policy's `agent-roles` section while the helper role store (`CRW_HOME/subagents.json`) decided the four helper roles' models, so one role had two sources that could disagree, and `executor-t1` and `reviewer-final` had no place in the store at all; port: fixed (every production `crw flow` command builds its table from one read of the store, `role.ReadFlowSnapshot`: the four helper roles and the flow-only keys `executor-t1` and `reviewer-final` from the same `roles` object, with the code's alias table and model aliases and nothing read from the policy file. A flow-only key with no usable entry runs its compiled default, `anthropic/claude-sonnet-5-5` at `xhigh` and `gpt-6.1-sol` at `xhigh` (the agent-roles values of 10-14, never the executor's or the reviewer's pair), and a role in mode default, with no entry, or with an entry that cannot be used is undecided (the empty pair, so a call of it names no model and no effort); each is a warning, and a store that cannot be read leaves the roles without a compiled default undecided with the reason, never a refusal. The table's Source is the store's path and its Digest the canonical digest of the six (model, effort) pairs (SHA-256 of the compact JSON array of `[role, model, effort]`), which the run pins in its started row, and a resume that reads another digest writes `policy_repinned` as before; a prompt override, a fallback or another member of the store does not change it. The run's started row carries `policy_warnings` when the table warned. The lane's `RuleVersion` and `VerifierRule` stamps, the start plan, `crw flow roles`, `crw doctor flow-roles` and `get_capabilities` (`executionPolicy.agentRoles`) show the same snapshot. `crw role helper get|set|reset` take the two flow-only keys by name and answer the role as the flow reads it (`source`: `store` or `compiled_default`); a set over the key's own unusable entry is refused like a set over a helper role's. Pinned by `TestCRW1330_FlowSnapshotReadsTheSixRolesFromOneRolesObject`, `TestCRW1330_MissingFlowKeysUseTheCompiledDefaultsAndWarn`, `TestCRW1330_ModeDefaultRoleIsUndecided`, `TestCRW1330_UnusableFlowKeyStopsOnlyItself`, `TestCRW1330_DigestCoversTheSixPairsOnly`, `TestCRW1330_HelperSetGetResetTheFlowKeys`, `TestCRW1330_LoadPolicyBuildsTheTableFromTheRoleHelper`, `TestCRW1330_ResumeRepinsWhenAPairOfTheSnapshotChanges`, `TestCRW1330_FlowRolesShowsTheStoreTheDigestThePairsAndTheWarnings`, `TestCRW1330_BuildLaneStampsTheSnapshotPairs`, `TestCRW1330_StartPlanCarriesTheSnapshotAndItsWarnings` and `TestCRW1330_CapabilitiesAgentRolesComeFromTheRoleHelperSnapshot`).
- The execution policy loader refused the whole file (the relay's and the bridge's policy too) when an `agent-roles` pair was not in the file's `allowed` list or a reviewer ran an author's model family, for a section no flow run reads any more; port: fixed (both cross-checks are warnings the loader keeps, `Policy.Warnings`, shown by `crw flow roles` and `crw doctor flow-roles`; a file that still declares `agent-roles` adds the warning that the flow no longer reads it to every flow command's table. A structurally malformed `agent-roles` or `agent-aliases` section still refuses the file. A run whose snapshot puts `reviewer` or `reviewer-final` on the family of `architect`, `executor` or `executor-t1` starts and records the warning; the runtime independence gate (`independence_refused`, `independence_unproven`) is unchanged. Pinned by `TestAgentRolesPairsMustBeAllowed`, `TestReviewerFamilyDiffersFromExecutor`, `TestCRW1330_ReviewerFamilyOverlapIsWarnedAndRecordedAtRunStart` and `TestCRW1330_DoctorFlowRolesWarnsAboutAnUnreadAgentRolesSection`).
- Deviation: the helper's list (`crw role helper` with no verb), its help text, the unknown-role message, the settings API, the MCP tools and the GUI keep the four helper roles of the CXC answer and do not show the flow-only keys; port: kept (the CXC corpus pins those answers, and the GUI bundle is not rebuilt in this issue; `crw role helper get executor-t1` and `crw flow roles` show them).
- Deviation: the fake backend's placeholder table is the table of a test only, a process under `internal/testsupport`'s isolation (`CRW_TEST_ISOLATION_ROOT`) whose store has no file; a test that writes a store reads it as production does. A production `crw flow` command with no store runs four undecided roles and the two compiled defaults, each warned, where it ran the placeholder table before; port: kept (the placeholders named fake models no host runs).
- Deviation: `get_capabilities` describes `executionPolicy.agentRoles` when the store has a file or the policy file declares `agent-roles`, and from the snapshot (`source`, `digest`, each role's `state`, `warnings`); a host with neither describes none, as the contract fixture of an unconfigured host pins. `Policy.Summary`, the worker policy receipt the relay publishes and compares, still describes the file's section unchanged; port: kept (the receipt is the relay's record of the file it runs on).
