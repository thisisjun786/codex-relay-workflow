# CRW-692 — the pump's DAG, capacity and audit alert sources

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no management pump). The predecessor is the management tools' `mgmt_pump.py` (`dag_events`, `capacity_events`, `eval_events`), which this issue replaces in Go. The Go files are `internal/manage/pump_signals.go` (the three sources), `internal/manage/pump.go` (the registry, the two settings, the dry flag and the commit step) and `internal/manage/capacity.go` (`capacityEvaluate`, `capacityEvaluation.Commit`, the alert epoch).

Settings (the `pump` object inside the `manage` object of the selected CRW configuration file: `--config`, else `CRW_CONFIG`, else `${XDG_CONFIG_HOME:-$HOME/.config}/crw/config.json`, i.e. `{"manage": {"pump": {"dag_review_seconds": 600, "capacity_seconds": 1800}}}`; a standalone `manage.json` is not read, and a top-level `pump` is ignored. Both are optional, a missing or non-positive value keeps the default): `dag_review_seconds` (default 600) is the interval between DAG reviews; `capacity_seconds` (default 1800) is the interval between capacity judgements. The audit queue `<state_dir>/audit/alerts.jsonl` is read every round, from the byte offset kept in the pump state (`offsets.signal_audit`).

- The predecessor kept the last DAG text and the last capacity text and sent again whenever the wording changed, and a failed or unmeasured review read as "no anomalies" (the `info` event); port: fixed. The standing anomalies are kept as the sorted set of tuples kind, plan, node, issue and, for a parent's duplicated tool results, the call id, with a change counter under `cursors.signal.dag.*`, so a reworded anomaly is not sent again, an error round or a review with an unmeasured check never clears, a review with an unmeasured check can add an anomaly but drops none, and A, clear, A is three events `signal_dag#1..3`. A parent's relay refusal is not a standing anomaly but an occurrence: the host reader gives every refusal of a parent the same kind and issue and an empty plan and node, so a set could hold one refusal for good and hide every later one. The review therefore keeps its rollout offsets and reported call ids in the pump's own state (`cursors.signal.dag.refusal_offsets`, handed to `DagReview` through a context offset store instead of its `dag-review-state.json`), saved in the same write as the pending events, and each round's new refusals are one urgent event `signal_dag_refusals#<n>` (the counter is `cursors.signal.dag.refusals`) that is never part of the set; a rollout seen for the first time reports none of its history, a review that fails after it moved the offsets gives them back, and the pump takes no state-directory lock or offset file of the review's own. The first-sight boundary (the size at which a rollout's history ends) is not the size at each reading that finds no offsets: it is written once to `<state_dir>/pump-dag-pins.json` (atomic, fsynced, never through a symlink, never in a dry run) before the first reading classifies any refusal against it, and dropped once the saved pump state holds the rollout's offsets; a kept boundary past the end of the rollout (a replaced or shortened file) is taken again at the size the file has, so a boundary is never past what a first-sight reading's own size would be and writing it before the pending events can only make a reading report more. A pump that ends, or whose state save fails, before its offsets reach disk therefore reads again against the same boundary, so a refusal appended during or after the first reading is reported by the next round instead of being taken for history. A boundary that cannot be written (or a boundary file that cannot be read) leaves that rollout's refusal reading unmeasured and records no offsets for it. The limit that remains is the definition of history itself: a refusal whose answer was complete at the size the first durably written boundary records is history. Pinned by the `TestPumpSignalDag*` tests, among them `LaterRefusalOfTheSameParentIsReported`, `IdenticalRefusalsAreEachReported`, `LaterDuplicateOutputIsReported`, `FailedReviewKeepsTheRefusalOffsets`, `FirstSightRefusalSurvivesALostPendingWrite`, `RefusalAfterAFailedFirstSaveIsReported`, `HistoryStaysOutAcrossALostState`, `UnwritablePinTakesNoRefusalReading`, `DryRunWritesNoPin`, `PinIsDroppedOnceTheOffsetsAreSaved`, `RefusalOfAFailedRoundIsSavedUnderTheSameId` and `BoundaryPastTheEndIsTakenAgain`.
- The predecessor's capacity state moved before its alert was recorded, so an alert could be lost to a pump that ended between the two; port: fixed (decision of the coordinator after the CRW-692 judge: `Capacity` is split into `capacityEvaluate`, which reads and writes nothing, and `Commit`, which saves the alerted state; the pump order is evaluate, save the pending events, commit; an event id is `signal_capacity#<plan>@<alert epoch>:<waiting digest>`, the epoch counts a plan's alerts from the last committed state, so an evaluation whose commit was lost is judged again under the same epoch and the same id and the pending/sent dedupe absorbs it, while a `realert_hours` re-alert is the next epoch; a failed commit is logged and isolated and the next read repeats it; pinned by the `TestPumpSignalCapacity*` tests, among them the crash between the pending write and the commit, each save failing, the periodic re-alert and the dry run). The waiting-set digest in the id is an addition to "plan and epoch": a waiting set that changed before a lost commit was repaired is a new alert rather than one the sent set swallows. Two guards were added after the verification of the first head. The capacity state file carries a `version` and a `revision` (a random token drawn for every write), and a commit is made under a lock and only against the generation its evaluation read (absent file, version and revision, or the digest of an undecodable file; a file that cannot be read matches nothing): a commit that arrives after the command line (or another evaluation) saved a newer state, or after the file was lost and written again from nothing to the same version, is refused with `errCapacityStateMoved`, logged, and the next read judges the newer state, so a late commit can never roll an epoch back (`Capacity` itself judges again, at most three times). The lock is taken without blocking and retried for at most 200 ms; a lock another writer holds longer fails that commit with `errCapacityStateBusy`, which the pump logs as the source's commit failure while the round goes on to the other sources, the delivery and the parent queue, and the next read converges on the same id (pinned by `TestCapacityCommitIsRefusedAcrossAStateFileGeneration`, `TestCapacityCommitOverAnUnreadableState` and `TestPumpSignalBusyCapacityLockDoesNotHoldUpTheRound`). The epoch in an event id comes from the pump's own record per plan (`cursors.signal.capacity.epoch.<plan>`: the state epoch and the state file generation the alert was judged on, the epoch used, the waiting digest, whether the alert is settled), saved with the pending events: only a retry of the same judgement (an unsettled record, the same state file generation, so no commit of any kind came between, the same base epoch and waiting set) reuses its epoch, a plan the report no longer judges has its record settled, and any other alert takes an epoch above the record's, so a plan removed from the settings and registered again, or a lost `capacity-state.json`, alerts under a new id instead of the id already sent, also when the first alert's commit had failed (pinned by `TestPumpSignalCapacityRemovedAndReaddedPlanAlertsAgain`, `UncommittedAlertIsNotReusedByALaterGeneration`, `LostStateFileAlertsUnderANewId`, `StaleCommitKeepsTheNewerState` and `DelayedCommitDoesNotRollBackTheCommandLine`).
- The audit alert queue is read by byte offset like the predecessor's `eval_off`, from the start of the file the first time (the queue is consumed, so the backlog is not history), and an event is one low event per complete line with the id `signal_audit#<start offset of the line>`; port: kept in shape, fixed in the edges (a half-written last line is skipped and the offset stays at its start, two identical lines are two events, a blank or malformed complete line is passed over, and a file that shrank, or whose identity (device and inode of the open file, kept as `cursors.signal.audit.file`) changed whatever its size, restarts at its start under a new epoch so its ids cannot collide with the old file's; the supported rotation is a rename or truncate of the queue file, a state that predates the identity adopts the file it finds, and an in-place rewrite that keeps both the inode and a size at least the read offset is not detected; an alert names at most three defects, each cut at 200 characters, as the predecessor did).
- The capacity read runs before the round saves its pending events, so it is bounded: each `gh` call is cut off after 30 seconds (`capacityExecTimeout`, also for `crw manage capacity`; the lane count is then unknown, as for any gh failure) and its output pipes are released two seconds after it was killed (`WaitDelay`, so a gh that left a child holding them cannot hold the call), and the pump gives the whole read 90 seconds (`pumpSignalCapacityBudget`); a read past the budget is unmeasured, moves nothing, is logged and made again on the next round (also a read that returns a report only after the budget ran out or the round was cancelled: the evaluation absorbs a failed signal read as an unknown signal, so such a report is not a judgement, and it records no event, read time, alert record or commit), while the round saves and delivers the other sources' events. Pinned by `TestPumpSignalStuckCapacityReadDoesNotHoldUpTheRound`, `TestPumpSignalTimedOutCapacityEvaluationIsUnmeasured`, `TestPumpSignalTimedOutCapacityReadWithoutPlansIsUnmeasured`, `TestCapacityMergeCountIsBoundedByItsOwnDeadline` and `TestCapacityExecKillsAStuckChildAndItsOutputPipe`.
- One source failing is logged in `pump.log` and its read is made again on the next round; it blocks no other source (`Sources[name]` stays the read status alone; pinned by `TestPumpSignalOneSourceFailingDoesNotBlockTheOthers` and `TestPumpSignalCapacityFailingDoesNotBlockDagAndAudit`).
- The issue's end condition "PR CI all green" is replaced by the integration gate: the integrator's `crw-dev ci local` on the merged tree (`verification-record/1` PASS) is the end condition, together with `go test -count=1 ./internal/manage`, vet, gofmt and `crw-dev ci validate`; internal work opens no pull request.
