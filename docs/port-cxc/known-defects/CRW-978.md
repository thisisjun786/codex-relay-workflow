# CRW-978 — the differential-fuzz targets: shared comparison, worker isolation and failure records

Source: the dev-only harness in `internal/dev/cxcfuzz` (`target_goalplan.go`, `target_state.go`, `worker.go`, `workerenv.go`, `cxcfuzz.go`, `names.go`, `stamps.go`, `failures.go` and the shims under `testdata/`), compared with the CXC v0.2.40 readers and writers it drives (`pabcd-state/dist/goalplan.js`, `pabcd-state/dist/state.js`, `subagent-config/dist/spawn-attach-hook.js`) and the rename table `contract/schema/cxc/name-substitution.json`. Every defect below is in the harness, not in the port or the oracle, and each is fixed in this change unless it says otherwise.

- The goalplan diagnostic named the oracle's `.codexclaw` directory where the port reads `.crw`, so two empty reads differed by that name alone and counted as differs; the comparison now applies the rename table's directory rule to every diagnostic path before it compares and reduces (`normaliseDiagnosticPaths`). The naming difference itself stays class d, wording, port: kept. port: fixed (harness).
- A string the oracle kept, in which only some unpaired surrogates had become U+FFFD, was a plain difference instead of a data loss in the state and goalplan targets; `lossyString` now accepts any mix of kept surrogates and replacements, at any depth. port: fixed (harness).
- The shape mask hid a stamp the write had kept from the file, because it masked any millisecond ISO stamp under `updatedAt`; a write's own stamp is now masked only inside the clock window the write ran in, on the Go side and in both shims, so each side is judged against its own clock. port: fixed (harness).
- A worker started under the caller's `HOME`, `CODEX_HOME`, `CRW_HOME`, `CODEXCLAW_HOME`, `TMPDIR` and `XDG_*` variables, including its start-up handshake, so an oracle import could reach the caller's homes; every worker now starts under a start-up root the harness owns, and the caller's values are dropped. port: fixed (harness isolation; CRW-971 item 1).
- An error reply was decoded into Go strings, so a lone surrogate in an error message became U+FFFD before the comparison; the name and message now pass through as the worker wrote them. port: fixed (harness; CRW-971 item 2).
- An explicit `--seed 0` was indistinguishable from an omitted seed and was replaced by the clock; the seed flag is now recognized as given. port: fixed (harness; CRW-972 item 3).
- A timed-out case was counted and forgotten; a decode failure and a failed temporary root were counted as timeouts. A case the harness could not answer now writes its input, case number and cause (timeout, dead worker, no answer, decode, temporary root, error) once per input under `failures/`, and the summary names the record. port: fixed (harness; CRW-972 item 4).
- The spawn shim appended its load root to whatever path `CXCFUZZ_LOAD_ROOTS` named in the inherited environment, so a file outside the case's scratch root, or a link to one, could be written; the shim now records the root only in the scratch the harness gave it, opened without following a link. port: fixed (harness; a write outside the scratch root, CRW-997 item 1).
- The worker requirement check returned an explicit path without a stat, so a missing or non-executable path was accepted; it now must name an executable regular file. port: fixed (harness).
- The pin replay discarded `RemoveAll` errors; a case root that could not be removed is now reported with its pin. port: fixed (harness).
- The state and goalplan comparisons did not share one definition of a data loss; the goalplan and state targets now use the same `lossyString` and the same stamp window. port: fixed (harness).
