# CRW-656 — stopped close reads the newest turn through thread/turns/list

Source: no CXC v0.2.40 (commit 3c1459ac) behaviour is recorded here. The oracle's dispatch path is
`plugins/codexclaw/components/subagent-config/src/fallback-dispatch-cli.ts`, which has no stopped
close of its own and never read a child's turn; the port's stopped close is a CRW addition
(`internal/role/created_check.go`, `createdCheckStop`). The defect below was introduced by the port
and is fixed by the port, so it is a Go-side defect rather than an oracle one.

- The port's stopped close decided on the shape of the thread/read answer: `createdCheckRead` set
  `createdCheckIdentity.Turns` only when that answer carried a JSON `turns` array, and
  `createdCheckStop` called `thread/turns/list` only then. A host that omits the field, or sends
  `null`, closed the record with `runtime not confirmed` and freed the attempt's agent id while the
  child's newest turn was still running — the case the check exists to block (`internal/role/created_check.go`,
  lines 122-130 and 243-245 at this issue's base commit); port: fixed by CRW-656
  (the `Turns` field and the reply's `turns` field are removed, and a confirmed own child with a
  non-nil host always reads `thread/turns/list` with `limit 1`).
