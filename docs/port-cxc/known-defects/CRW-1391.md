# CRW-1391 — a flow run did not declare its nodes' edit regions, so the second node crw.dag admitted was held back

Source: CRW's own design (the decided default of CRW-1391, (a): `crw.release` declares a node's admission regions before the relay's release; CRW-1316 S5), not the CXC oracle: CXC v0.2.40 (commit 3c1459ac) has no flow run. The Go side is `internal/flow/ops/lane_design.go` (`AdmissionRegions`, `admittedOthers`, `WarnRegionsNotDeclared`, the release row's `regions`, `regions_declared` and `warnings`, `ReleaseOutcome.Warnings`), `internal/flow/ops/seams.go` (`ReleaseRequest.Regions`, `Admitted`; `ReleaseResult.RegionsDeclared`, `RegionsWarning`), `internal/flow/cli/schedrelay.go` (`Release`, `declareRegions`) and `internal/relay/dagsched/regions.go` (`NodeRegions`, a read); the references are `docs/flow/script.md` ("The lane of a node"), `plugins/crw/skills/crw-run/SKILL.md` (Start) and `plugins/crw/skills/crw-run/references/region-grades.md` ("Declare the regions").

- A flow run released a node without declaring its edit regions to the relay, whose release judgment reads only `dag_node_regions`, so a node with no declaration overlapped every other and the second of two nodes `crw.dag` admitted together was held back `defer:edit_overlap`; the lane ended unreleased and the milestone `incomplete` until a resume asked again. The cap-2 session milestone e2e ran two nodes at once only because its owner declared the regions before the run; port: fixed (`crw.release` passes the node's admission regions - the plan's regions and then the DESIGN's `edit_regions`, as `crw:lib/lane` `admissionRegions` makes them, none when either side names none - and `SchedRelay.Release` declares them through `DeclareRegions` after the epoch claim and before `ReleaseAgent`, when the node has no declaration in force. A plan region is declared as the handoff states it; an `edit_regions` entry is a file, a tree when it ends in `/`, a symbol after `#`. The relay's store form is unchanged: rows are written to `dag_node_regions` and its side tables as `dag-region-declare` writes them. `TestSessionProjectMilestoneEndToEndOnTheFakeHost` no longer declares anything and both nodes still run at once and land; red first: on dev 97d5ca46 without the owner's declaration A-2's release is `defer:edit_overlap` and the test times out. Pinned also by `TestReleaseDeclaresTheAdmissionRegions` (disjoint nodes both released with their regions; really overlapping ones still have the second held back `defer:edit_overlap`) and `TestReleaseAsksForTheAdmissionRegions`; red first).
- The relay's judgment counts every ready node ranked before the released one as a holder of its declaration, so declaring only the released node left a race: when the lane of the later-ranked node released first, the earlier node was still undeclared and held it back (seen once in five runs of the e2e with only the node's own declaration); port: fixed (the release also declares the admission regions of the milestone's other designed nodes that have none in force, `ReleaseRequest.Admitted`; a failure of one of those is left to that node's own release. `TestReleaseDeclaresTheMilestonesOtherNodes` releases A-2 before A-1 and `TestReleaseAsksForTheOtherNodesAdmissionRegions`; red first, the first one deterministic).
- A declaration the relay refuses (a path outside the repository, a node that already holds undeclared regions, a store error) is a warning, never a refusal: the release row records `regions`, `regions_declared` `failed` and `regions_not_declared` with the relay's reason, the answer carries it in `warnings`, and the node is released as an undeclared one, as before; port: fixed (`TestReleaseGoesOnWhenTheDeclarationFails`, `TestReleaseWarnsOfRegionsTheRelayDidNotDeclare`; red first).
- A node with a declaration in force keeps it (`regions_declared` `kept`): the parent's graded declaration made before the run (crw-run, "Release by region grade") is not overwritten by ungraded regions, and a resume or a later release of the node does not try to widen what it holds. A declaration the run made for a node that a later DESIGN revision (a re-plan) gives other `edit_regions` is kept too: the lane's own admission (`crw.dag`) reads the new regions, so the run never runs two nodes at once whose new regions overlap, and the relay's judgment may only hold a node back that the lane would have run; port: kept (`TestReleaseKeepsADeclarationInForce`).
- Named limit: only the nodes of the run's milestone that the DESIGN plans are declared. A ready node of another milestone of the plan, which has no DESIGN yet, stays undeclared, and when it ranks before a node of the run it still holds that node back `defer:edit_overlap` (the plan's regions alone are not the admission regions the lane uses); the child's node released as an issue child (`crw.releaseChild`) and a land release (`land-head`, no DESIGN) declare nothing; port: kept (declare such nodes with `dag-region-declare`, or a follow-up).
