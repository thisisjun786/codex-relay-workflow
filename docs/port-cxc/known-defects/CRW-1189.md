# CRW-1189 — refusal and continuation wording that left the next action to a guess

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/hook.ts` `STOP_NEXT_COMMAND` (:1523-1537), `buildStopBlock` (:1577-1631), and `memory-write-gate.ts` (the oracle has no command reader and no managed dispatch records for the last three items). The Go side is `internal/pabcd/hook/stop.go`, `internal/pabcd/state/lock.go`, `internal/pabcd/shellir/modules.go`, `internal/role/spawn/node_error.go` and `hook_managed.go`. Found by the isolated trial r3 (R3-S2-F1 to F4, S5-R3-F1) and confirmed by real-environment trial r1.

- The Stop block's example command for P, A, B and C carried `"workPhaseId":"<bound goalplan only>"` (and at C `"testReceiptPath":"<bound goalplan only: ...>"`) for every session, so a session without a bound goalplan was handed keys it cannot fill, and a bound one a marker in place of the id and the path (hook.ts:1523-1537); port: fixed. A session without a bound goalplan gets the command without those keys; a bound session gets its goalplan's active work phase id and, at C, the path `crw pabcd receipt test` writes (`.crw/evidence/<session>/test-receipt.json`) with a line that names the receipt command to run first. A bound plan with no runnable work phase has no id to give, so the key is left out. `planUnit` stays at P (the P to A gate asks for it of every session; the agent names the unit `crw pabcd plan init <slug>` creates). The rest of the text is the oracle's.
