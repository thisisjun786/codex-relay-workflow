# CRW-1001 — policy write answers that disagreed with the state the write left

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no execution policy write route). The Go files are `internal/policystore/policy_write.go` (`Write`, `swapPolicy`, `registrationEnvelopeOf`) and `internal/gui/policy_api.go` (`policyWriteHandler`). The defects were found by the pre-merge evaluation of CRW-867c (`pr882-4986b830`, d1 and d2, criterion C3 PARTIAL) and by its independent review (three non-blocking findings). The policy file, the wiring record and the backups were never damaged; the answers' classification and path strings were wrong.

- The moved-file branch answered recovery_needed (HTTP 500, repair advice, "neither is applied") when the file and the wiring record named the same document: an editor saved another valid document T, `crw install register-mcp --re-register-policy` registered T, the exchange found T and undid itself (CRW-867c evaluation d1); port: fixed (the answer is `not_applied`, HTTP 409, with `currentDigest`, `fileDigest` and `registeredDigest` all naming the document on disk, the policy file's backup and no recovery advice; a file and a record that differ, a record that names another file or cannot be read, and bytes kept from a raced exchange stay recovery_needed. Pinned by TestAMovedFileThatTheRecordAlreadyNamesIsNotARecovery, TestAMovedFileTheRecordDoesNotNameStaysARecovery, the existing TestAKeptExchangeReportsTheRecordAsItStands, and TestPolicyWriteAnswersNotAppliedWhenTheFileMovedToWhatTheRecordNames; the screen renders it as its own notice).
- `registrationEnvelopeOf` read the installer's envelope with `encoding/json`, which turns a lone surrogate escape into U+FFFD, so `recordBackup` named a file that does not exist when the installer's directory name is not UTF-8 (CRW-867c evaluation d2); port: fixed (the envelope is read with pyjson with surrogates kept, the spelling every other path of the answer has, and the response writes it back as the escape. Pinned by TestTheEnvelopeKeepsALoneSurrogateInTheBackupPath and, against the real installer with a working directory whose name holds byte 0x80 and a relative CODEX_HOME, TestTheRecordBackupNamesTheFileTheInstallerMadeWhenTheDirectoryIsNotUTF8).
- The success path called `syncDirectory` directly, so a test that fails `writeSync` never reached it (review finding 1); port: fixed (it goes through `writeSync`; TestASuccessfulPublicationSyncsItsDirectoryThroughTheSeam pins the stored answer with its warning).
- A failed exchange was classified cancelled whenever `ctx.Err()` was set (review finding 2); port: fixed (only an error that is the context's own, or its cancellation cause, is cancelled; TestAnExchangeFailureWhileTheContextEndsIsNotCancelled).
- A cancelled answer carried no digest of the file it left alone and no cause (review finding 3); port: fixed (every cancellation after the file was read carries `fileDigest`, and the cancelled body carries `reason` with the context error and its cause. Pinned by TestACancelledAnswerNamesItsCauseAndTheFile and TestPolicyWriteCancelledAnswerCarriesItsCauseAndTheFileDigest). The digest first reported was the one read under the lock; the pre-merge evaluation of `711ab36e` (d1) showed it can be stale, because the policy lock serializes writers and not editors: an editor that saves another document between the backup and the publication leaves a file the answer does not describe. The digest is now read from the file when the write ends (`fileAsItIs`), "" when it cannot be read, and the screen words it as "the policy file had digest ... when the write ended". Pinned by TestACancelledAnswerNamesTheFileAsItIsWhenTheWriteEnds (red on `711ab36e`: evidence/round-eval/red-go-cancel-digest.log).
- A moved file whose undo could not be synced but whose file and record agree is `not_applied` with a warning that a power loss may bring the candidate back; port: kept (the file and the record agree now, and the next write is refused on the digest disagreement if the candidate returns).
- The screen dropped the warnings of a refusal body: `noticeForWrite` copied `warnings` only from a 200, so the unsynced-undo warning of a `not_applied` answer never reached the user; port: fixed (`noticeForWrite` keeps `warnings` of every error body and the notice renders them; pinned by TestANotAppliedAnswerCarriesTheUnsyncedUndoWarning and the two web tests "a not_applied answer keeps the server's warnings for the screen" and "the screen shows the warning a not_applied answer carries").
- A moved file that lacked the requested change was a final refusal for the screen before the wiring record was consulted, so a competing writer's provisional publication stopped the automatic reconciliation and the page stayed "Not saved" after the queued request published (pre-merge evaluation d2); port: fixed in `judgeLostWrite` (web/src/policy-state.ts): it is a refusal only when the record names that file; under a record that names another digest the result stays unknown and the screen keeps reading (see CRW-994).
