# CRW-1146 — SessionStart static text re-issued on every resume

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/cxc-ops/src/map-affordance.ts` (`runMapAffordanceSessionStart`, called from `cli.ts:119-121`) and `plugins/codexclaw/components/subagent-config/src/fallback-dispatch-cli.ts:11-35`. The Go files are `internal/affordance/hook.go` (`RunMapAffordanceSessionStart`) and `internal/role/fallback_notice.go` (`RunFallbackNoticeHook`). Found by the isolated real-use trial r1 (S4-F4): the s1 rollout held the session-binding rule 15 times and the static pointers as often, because Codex appends every SessionStart output as a new developer item and dedups nothing.

- The oracle ignores the SessionStart payload's `source` and prints the whole list (binding, map pointer, skill search, Korean writing, loop, stacked PR, background terminal, questions, PATH banner) and the subagent dispatch card on startup, resume, compact and clear alike (`map-affordance.ts` runMapAffordanceSessionStart; `fallback-dispatch-cli.ts` sessionStart branch); port: fixed (a resume repeats only guidance the session was not given, found by what the session was given and not by the word resume. Each of the two legs keeps, per session, the SHA-256 of the guidance text it last gave under `<CODEX_HOME>/crw/session-guidance/<sha256 of the session id>/<leg>` (`internal/guidancerecord`; no text, no payload), written after the answer, never by a cancelled leg. With `source` exactly `"resume"` and a record equal to the text this run would give, the map-affordance leg re-issues only the session binding and the `crw`-not-on-PATH banner, which can change between runs, and the subagent fallback leg answers nothing. Without a record (the leg was silent at the session's start because the hook switch was off or a different build ran, or the session id cannot be keyed), or with a record of other text (the role store, `CRW_SPAWN_V1` or the model catalog changed while the session was closed, a first fallback was configured, the command the pointers name changed, the map pointer appeared), the resume gives the whole output and records it, so the next resume of it is short. The file count inside the map pointer is not part of what is compared. Startup, compact (the context was emptied), clear and a missing, non-string or unknown `source` give the whole output and record it. The recall leg and the self-heal flag warning are unchanged: the warning's repetition rule is the self-heal report issue's (N51 of the 10-10 review), not yet in dev.
