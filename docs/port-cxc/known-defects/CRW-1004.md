# CRW-1004 — state backup: the first listing's log identity, the space preflight, and a real damaged-page test

Source: the pre-merge evaluation of the state backup of CRW-862 (pr787-1bfd207d, defects d1 and d3) and the review of its fourth generation (head 79d748d51), both of the Go installer; CXC v0.2.40 (commit 3c1459ac) has no state-directory backup, so no oracle file applies. The Go files are internal/runtime/install/zone.go (backupState, listingDiff, scratchNeed, sqliteIntegrityCheck) and backup_cmd.go (BackupState, backupStateUsage).

- A store log that is a link, whose copy failed with ENOENT because its target went between the first listing and the copy, was left out of the entries handed to the listing comparison, so a link target or resolved source that moved in the same window went unseen and the backup succeeded (zone.go, backupState; pr787-1bfd207d d1); port: fixed (the comparison takes the first listing as it was read, `entries`, and the copy loop's `copied` keeps serving the digest comparison, so the first listing's identity and the source the copy read are two separate checks. A log that is an ordinary file keeps the churn rules: its identity is the same in both readings, or it is absent from one. Cases: TestTheBackupRefusesALogLinkRetargetedWhenItsFirstTargetWentBeforeTheCopy, red on the tree before the change with the output kept with the handoff, and TestTheBackupStillAcceptsAnOrdinaryLogThatWentAndCameBackBetweenTheListings as its control).
- No test damaged a page of a store: the 'a corrupted copy' case replaces the whole check with a fake answer, so nothing showed that `sqliteIntegrityCheck` finds damage (zone_sidecar_test.go; pr787-1bfd207d d3); port: fixed (a store with real rows and an index has whole pages overwritten, and the gate, with no substituted answer, reports a failure for it and an `ok` for the same store undamaged, without changing the copy; the end-to-end case damages the copy after its verification and before the gate and expects the refusal, the kept copy and a manifest with restoreCandidate false. Cases: TestTheIntegrityGateFindsARealDamagedPage and TestTheBackupRefusesACopyWhoseStorePagesAreReallyDamaged; this is a test that was missing, so it passes on the tree before the change, and the mutation that makes the gate answer `ok` fails both, with the output kept with the handoff).
- The free-space preflight charged every entry whose path starts with `relay.sqlite3`, although the gate duplicates only `relay.sqlite3` and its log, so a leftover journal, a store-like directory's contents or a copy of the store under another name could make it refuse a backup that fits (zone.go, scratchNeed; review of 79d748d51, P2 1); port: fixed (the two exact paths are charged; case TestTheSpacePreflightChargesOnlyTheStoreAndItsLog, red before the change).
- The comments of `crw install backup-state` said it takes the same artifact as the install route and that restoreCandidate is true when the check passed, although the install route reads the store's schema first and this command opens nothing before it, so a store left with an unmerged log is copied with its frames in the log and not in the copied `relay.sqlite3` (backup_cmd.go, BackupState; review of 79d748d51, P2 2); port: fixed (the artifact was complete and only the words overstated it: the header, the usage text, BackupState's comment and docs/runtime-install.md now say that the log is copied as it lies and that restoreCandidate judges the store with the log replayed in the scratch duplicate. Case TestTheOperatorCommandCopiesAnUnmergedLogAsItLiesAndJudgesItReplayed pins the behaviour the words describe).
- The documentation comment of `sqliteIntegrityCheck` was split by the `scratchNeed` block (zone.go; review of 79d748d51, P2 3); port: fixed (the comment is joined to its function).
- Evaluation of 901ee68a (P2): the positive control for an ordinary log recreated between the listings removed and recreated the log in the same hook, before the copy, so its copy succeeded and the case it was meant to pin was not reached; port: fixed (TestTheBackupAcceptsAnOrdinaryLogThatWentBeforeItsCopyAndCameBackAfterIt removes the log after the first listing and writes a header-only log back at the copied step: the backup is accepted, holds no log, and the manifest says `gone before its copy`; the behaviour was already so, the test now pins it).
