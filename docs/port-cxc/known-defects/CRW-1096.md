# CRW-1096 — skill search merges ClawHub's row-count score with the other sources' keyword scores

Source: `plugins/codexclaw/components/skill-search/src/cli.ts:72-74,193` and `scoring.ts:20-49` at v0.2.40 (commit 3c1459ac); the Go side is `internal/skill/search/merge.go` (`mergeSources`), `run.go` (`runCLI`) and `cli.go` (`clawhubSearch`). Found by the 10-10 CXC improvement review (A8-08, P2).

- A multi-source search sorted every row by its own source's score, so ClawHub's `rows returned - position` (and gh's, the same) competed with jaw's and hermes's additive keyword weights: the number of rows ClawHub happened to answer decided the order, and an exact id or name match of weight 10 or 14 lost to an unrelated first row when ClawHub answered 20 rows (`--source all --limit 1` chose `other0`) (source `cli.ts:72-74,193`, `scoring.ts:20-49`); port: fixed (each source keeps its native order and the merge is a weighted reciprocal-rank fusion, `weight / (60 + nativeRank)` with jaw and hermes 1, ClawHub 0.8, gh 0.6, plus a boost larger than any fusion sum for an exact match of the whole query on a row's id (1.0) or name (0.5); ties go to the order the sources were named in, then to the native order. The size of a source's answer no longer decides relevance, and an exact match comes first from whichever source has it. The policy is written at the top of `merge.go`. Pinned by `TestExactMatchOutranksAnotherSourcesRankOneWhateverItsRowCount`, `TestExactNameOutranksNativeRankInAnotherRow`, `TestMergeKeepsEachSourcesNativeOrderAndInterleavesByRank`, `TestSameIDInDifferentSourcesStaysDistinctAndDeterministic`, `TestMergeWithAFailedSourceKeepsTheOthersInOrder`).
- `score` kept its meaning and its spelling: it is the score the row's own source gave it, comparable only with rows of that source; ClawHub's and gh's carry no relevance, only the position in the source's answer. The merged order is the policy above, not a sort on `score`, so the printed scores of a multi-source list are not monotonic. A row keeps its `source`, so the same id from two sources stays two rows.
- Each source's limit was applied before the merge (so `--limit 1` kept only each source's first row and the merge could not see a better match at its second); port: fixed (a source offers all its matching rows and the limit applies to the merged list; a search of one named source is not merged at all: its rows keep the source's native order, with neither the fusion nor the exact-match boost, so it returns the same rows in the same order as before, pinned by `TestSingleSourceSearchKeepsTheNativeOrder` (a later exact id in ClawHub's answer and a superseded exact id in jaw do not take the native rank-1 row's place); `--source all` is merged even when only one of its sources answers). The one recorded case that changed is `TestCLISourceBranches` (`search tdd --source all`): jaw, hermes and ClawHub all match the id exactly, so the order is the named order of the sources (jaw, hermes) and no longer hermes first by its larger keyword score.
