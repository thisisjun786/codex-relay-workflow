# CRW-1362 — no test ran a session run of a project to the end of its milestone

Source: CRW's own design (CRW-1316 design sections 15 (lane S5), 16 and 18.6), not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no flow run and no session call. The Go side is `internal/flow/cli` (`session_lane_e2e_test.go` new; `lanelab_test.go`: `newLaneLabFor`, the lab's owner and target branch).

- The session call path was tested piece by piece (the engine's session calls over fakes, CRW-1331; the host adapter, CRW-1332; the owner's commands over three explorer calls, CRW-1348), and no test ran the project lane of a plan on the session backend through the owner's commands, so the end conditions of CRW-1316 (section 16) had no test; port: fixed (`TestSessionProjectMilestoneEndToEndOnTheFakeHost`: the lane lab's plan of two issues of one milestone, a temporary relay store and git repository with the target branch `dev`, the fake App Server and the helper role store; `crw flow start project-lane` on the session backend, the test as the owner thread taking every step with `crw flow next`, spawning each subagent through the spawn hook and reporting it with `crw flow dispatched`. It checks that the only top-level thread besides the subagents is the owner's and every role call ran on a subagent of it; that the two nodes (cap 2, disjoint regions) had their executors in flight at once; that every reviewer read the node's head in a directory of its own, not the owner's cwd; that every `thread_started` row names the subagent the owner spawned for that attempt, with the role's pair under the decided-parts rule (the architect's undecided effort bound `effort_unchecked` at the effort the host applied), one row per attempt and one completed row per call; that a run killed after the architect's completed row is resumed by the next `crw flow next`, and one killed after the design audit's subagent was spawned and before it was reported binds that subagent from its `step_published` row; that the App Server restart loses the executor that still runs (`session_attempt_lost`, its subagent closed, a second attempt in the same allocation) and the late report of the lost attempt is answered `close`; that the fix round of the other node runs after the restart and lands; that the milestone closes over `dev` with both nodes accepted, merged and observed once, and the report sent up; and that each acceptance's reviewer thread, model and effort are those of the reviewer call's newest `thread_started` row. Mutation-red: the test fails when a late report of an ended attempt is answered bound, when `thread_started` records the host's cwd as the call's, when a lost attempt writes no `session_attempt_lost` row, and when `crw.dag` runs one node at a time).
- A flow run releases a node without declaring its edit regions to the relay: the relay's release reads only the declarations of `dag_node_regions` (`dag-region-declare`, `dagsched.Scheduler.DeclareRegions`), and a node with none overlaps every other (`defer:edit_overlap`), so the second of two nodes the flow admitted together (its own admission reads the plan's regions and the DESIGN's `edit_regions`) is held back unreleased and the milestone ends `incomplete` until a resume asks again; port: pending (the procedure says the parent declares the regions before the release, `plugins/crw/skills/crw-run/references/region-grades.md`, and the test's owner does; the run declaring the regions it admits by is a change of the release path and of what the relay records, not made in this lane).
- Deviation: a run process the test kills still flushes its journal's open batch when its world closes (`World.Close`), so the cli scenario's deaths are those of a process that ends; a death that loses the batch is the engine's session crash tests over the SQLite journal (CRW-1367); port: kept.
