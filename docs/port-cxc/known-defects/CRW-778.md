# CRW-778 — published state writes in the tombstone, budget and memory gate callers

Source: the state writer is `plugins/codexclaw/components/pabcd-state/src/state.ts` `writeState` at CXC v0.2.40 (commit
3c1459ac): it writes a temp file, publishes it with a rename, and returns whatever the publication threw. The callers are
`plugins/codexclaw/components/pabcd-state/src/subagent-evidence.ts` `recordTombstone` (:272) and `resolveTombstone` (:434),
and `plugins/codexclaw/components/pabcd-state/src/memory-write-gate.ts` `consumeAuthorization` (:262), which
`handleMemoryWriteGate` reaches. The Go port is `internal/pabcd/evidence/tombstone.go` (`recordTombstone`),
`internal/pabcd/evidence/budget.go` (`resolveTombstone`) and `internal/pabcd/hook/memorygate.go` (`memoryGateConsume`). The
oracle never syncs the published file or its directory (`known-defects.md`, "Found by CRW-479 state publication
durability"), so it cannot fail after the rename; CRW-479 added the directory fsync to the Go port, which is what makes a
post-rename failure reachable and these callers observable. The oracle's own callers skip the same reconciling step, so the
shape is faithful; the divergence these lines close is that a published state used to be reported as a plain failure. The
three cases below are a loss of state — a healthy session marked corrupt, a removal reported as not made, and a spent
authorization denied — so under the parity rule revision of 2026-10-03 they are fixed during the port rather than kept.

- A published-but-failed commit write is read as a failed commit, so the sentinel tier writes the state again and stamps
  `unverifiedCorrupt` on a healthy session whose tombstone was already published, and the goal-complete gate then refuses
  that session as unreadable or overflowed (oracle `subagent-evidence.ts` `recordTombstone` :272, which cannot fail after
  the rename; Go `internal/pabcd/evidence/tombstone.go` `recordTombstone`); port: fixed by CRW-778 (a loss of state, fixed by
  decision under the parity rule revision of 2026-10-03: a commit whose write reports `state.Published` returns true, so the
  sentinel tier never runs; no recorded corpus fixture drives this, so none is tagged intentionally-changed).
- A published-but-failed write leaves `removed` false though the tombstone removal reached the final path (oracle
  `subagent-evidence.ts` `resolveTombstone` :434; Go `internal/pabcd/evidence/budget.go` `resolveTombstone`); port: fixed by
  CRW-778 (a loss of state, fixed by decision under the parity rule revision of 2026-10-03: a write that reports
  `state.Published` counts as removed, so a late valid receipt does not leave the parent blocked on a tombstone that is
  already gone).
- A published-but-failed write that spends a memory write grant denies the write it authorized, so the user loses the grant
  and must ask again although the authorization is gone from the visible state; the direction is fail-closed, but the deny
  note is wrong (oracle `memory-write-gate.ts` `consumeAuthorization` :262, whose `catch` already allows the call, so the
  oracle has no such divergence; Go `internal/pabcd/hook/memorygate.go` `memoryGateConsume`); port: fixed by CRW-778 (a loss
  of state, fixed by decision under the parity rule revision of 2026-10-03: a write that reports `state.Published` leaves
  the call allowed, because the grant it spent is already visible to every reader).
- Other `state.WriteState` callers that skip a reconciling step when the write reports a post-rename failure
  (`state.Published(err)` true). CRW-778 fixes the three above only; these two would each need the same published/read split,
  and they are outside this issue's scope (oracle `pabcd-state/src/state.ts` `writeState`; Go callers named below); port:
  pending.
  - `internal/pabcd/cli/memory.go` (`RunMemoryCLI`): reports "could not record the grant" though the grant was published.
  - `internal/pabcd/cli/scan_record.go` (scan record): reports "scan record failed" though the round was published.
- Supersedes known-defects/CRW-744.md, item beginning "Other `state.WriteState` callers that skip a reconciling step": its
  sub-items for `internal/pabcd/evidence/tombstone.go` (`RecordTombstone`), `internal/pabcd/evidence/budget.go`
  (`ResolveTombstone`) and `internal/pabcd/hook/memorygate.go` (`memoryGateConsume`) are now port: fixed by CRW-778 (each is
  a loss of state, fixed by decision under the parity rule revision of 2026-10-03); its sub-items for
  `internal/pabcd/cli/memory.go` and `internal/pabcd/cli/scan_record.go` stay port: pending.
