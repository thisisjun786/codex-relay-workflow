# CRW-564 — the SubagentStop review observer

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/review-observer.ts:57-164` (`handleReviewObserver`) and the `subagent-stop-review` dispatch of `cli.ts:454-461`, with the oracle cases `test/review-binding.test.ts` and `test/review-deadlock.test.ts` and the fixtures `hook__subagent-stop-observing-review__baseline_empty_workspace` and `hook__subagent-stop-observing-review__non_reviewer_ignored`. The Go files are `internal/pabcd/hook/reviewobserver.go` (`HandleReviewObserver`) and the `subagent-stop-observing-review` row of `internal/harness/legs.go`. The installed hooks stay CXC's; the row only answers when `crw hook subagent-stop --leg subagent-stop-observing-review` is run.

- The observer reads the goalplan, and the write it makes after a recorded verdict goes through the same `writeGoalplan` that drops a stored review round `revival` cannot read, so a verdict written over such a plan deletes the round from the file with no trace (`review-observer.ts:157`, `goalplan.ts` revival); port: fixed (a record data-loss defect, the class the parity rule fixes during the port: the observer runs inside `goalplan.WithGoalplanWriteLock`, which hands no plan to a writer whose revival would drop or change stored data, so the observer leaves the file as it is and records nothing, as it does for a held lock; pinned by `TestReviewObserverLeavesAPlanWithAnUnreadableRoundAlone`).
- The oracle compares an absent stored binding with `!==` against the session, the epoch and the active work-phase, so a round without `ownerSessionId`, `planEpoch` or `workPhaseId` (a round opened before REVIEW-BINDING-01) is ignored with a ledger line, and `workPhaseId` absent never equals a null active work-phase either (`review-observer.ts:134-146`); port: kept (an empty stored value is an absent one after revival, so the Go comparison treats it the same; the ledger line reads "none" for the absent side).
- The oracle's `agent_type` is optional (a v1 spawn has none, `review-deadlock.test.ts:111-122`), where the harness's shared SubagentStop parser requires it; port: kept (the leg hands the raw payload to `HandleReviewObserver`, which reads `agent_type` as `""` when it is missing, so a v1 reviewer is still recorded).
- A payload field of another JSON type than text (`cwd`, `session_id`, `agent_id`, `agent_type`, `last_assistant_message`) is read as absent; the oracle would carry the value on (a number as `reviewerSession`) or throw on it and exit silently (`review-observer.ts:59-71`); port: kept for every field but `agent_id` (the host sends text for these fields; a missing `cwd`, `session_id` or `last_assistant_message` ends in the same silent exit, a missing `agent_type` is a v1 spawn); an absent `agent_id` is the next entry.
- The oracle reads `agent_id ?? ""` and records the sign-off of a child it cannot name: the round turns terminal with an empty `reviewerSession`, the real reviewer's later answer is refused as a second signer, and the A>B check, which reads the verdict only, spends the PASS as an honest approval (`review-observer.ts:117-118,133`); port: fixed (a missing, empty or non-text `agent_id` records nothing and writes one `review_signoff_ignored` line, "the child named no agent id", leaving the round open for the real reviewer; pinned by `TestReviewObserverIgnoresASignoffFromAChildItCannotName`).
- The oracle reads the session state and writes the verdict under the goalplan lock only, while `orchestrate B` checks the latest round and publishes the state under the session lock, so a reviewer's FAIL can be written between the transition's review check and its publication and the session still enters B on a stale attest (`review-observer.ts:57-164`, no session lock; `orchestrate-cli.ts` validateReviewBinding then publish); port: fixed (the observer takes the session lock first and the goalplan lock second, the order of every writer in this tree, and judges the state it reads under the session lock, so a verdict is either recorded before the transition's check or ignored as "the session left A"; a held session lock is a missed recording after about 250 ms, as a held goalplan lock is; a workspace with no session state is left untouched without taking the lock; pinned by `TestReviewObserverWaitsForTheSessionLockAndJudgesTheStateItLeaves`).
- The ledger row of a child that exited without a parseable sign-off (`review_signoff_unparsed`, `review-observer.ts:103`) has no constant in `goalplan.GoalplanLedgerEvent`; port: kept (the event is written only by this observer, and `reviewObserverUnparsed` names it beside the code that writes it).
