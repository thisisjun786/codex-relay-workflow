# CRW-1331 — every agent call opened an App Server thread; the engine had no path for a role subagent of the owner thread

Source: CRW's own design (CRW-1316 §3, §3.4, §4, §5, §6), not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no flow engine, and its role calls are subagents of the session that runs them. The Go side is `internal/flow/engine` (`sessionhost.go`: `SessionHost`, `SessionConfig`, `HeadKeeper`, `StrayRef`, `RecordedBackend`; `stepbus.go`: `Step`, `DispatchReport`, `DispatchReply`, `FileStepBus`; `session.go`: the session call path; `call.go`, `engine.go`, `hold.go`, `resume.go`, `recon.go`, `checkpoint.go`, `journal.go`), `internal/flow/callstate`, `internal/flow/journal` (the intent rows), `internal/flow/ops` (`gitsnap.go` `Commit`, `lane_build.go` crw.commit, `proofs.go` `Prover.Node`), `internal/flow/backend/agent` (`Allocator.HeadOf`, `Allocator.KeepRef`), `internal/flow/shadow`, `internal/flow/cli/runs.go`, `internal/relay/dagsched/accept_agent.go`, `internal/flow/roles/*.md` and `internal/flow/workflows/lib/packets.js`.

- The engine ran every agent call as an App Server thread it started itself (`Backend.StartThread`, `RunTurn`), so a flow run opened a top-level thread per role call and nothing let the project orchestrator run the call on a subagent of its own (CRW-1316); port: fixed (with `engine.Config.Session` a run's calls are session calls: the `prepared` row and its allocation give every role a directory P, the `step_published` intent row is committed before the step file and a self-contained packet are written on the run's step bus, a dispatch report is bound only to the owner thread's subagent that carries the marker `crw-flow-op: <call>/t<k>-a<n>` and the role's pair, `thread_started` (host-read pair, `cwd` P, `host_cwd`, `attempt`, `via: session`) and `turn_started` are written in one batch, and the harvest feeds the existing validation, repair and terminal rows; pinned by `TestSessionCallEveryRole`, `TestSessionRepairThroughSendInput`, `TestSessionRowsInTheStore`).
- No row recorded which backend a run used, so a resume always built the App Server backend whatever the run had been started on; port: fixed (the `started` row records `backend`, a resume on the other backend is refused with the reason before any row is written, and the shadow report names the recorded backend; `TestSessionMixedResumeIsRefused`, `TestAppServerRunRecordsItsBackend`, `TestShadowReportNamesTheRecordedBackend`). The App Server resume environment (`journal.ResumeEnv`) still builds the App Server backend only: a session run's resume is refused there by the engine until the session environment is wired (CRW-1316 S3).
- A subagent answer has no output schema of its own and may carry prose before its JSON, and a failed or interrupted subagent turn had no mapping to the engine's host failures; port: fixed (the `final_answer` message, else the phase-null fallback of the App Server backend; the trailing JSON object is taken out of prose with `raw_text` and `extracted` beside the canonical `result`; a failed turn is `TurnOutcome.Failed` with its `codexErrorInfo`, so quota pause, `context_window_exceeded` and host holds behave as for a thread; a pause interrupts the bound subagent and waits until it is inactive; tokens come from the rollout's `token_count`, and an unmeasured session turn records `tokens_unmeasured` with `pauses: false`; `TestSessionHarvestSelectsTheAnswer`, `TestSessionFailedTurnIsAHostFailure`, `TestSessionPauseInterruptsTheSubagent`, `TestSessionTokens`).
- A restart of a run that owned subagents would have gone through the App Server reconcile, live resend and worktree retirement, giving a call a new allocation per attempt and losing a subagent spawned before it was reported; port: fixed (an open session call goes on in place from its last row: `prepared` and `step_published` publish again after a marker search, `thread_started`/`turn_started` harvest the bound subagent, `session_attempt_lost` spawns the next attempt; an attempt is lost only when its thread is `notLoaded`, `systemError` or unknown with its marker turn interrupted, failed without an error or unchanged for `LostAfter`; a stale or early report (an ended attempt, a step the run did not publish) is answered `close`, and a turn that ended interrupted or failed without an error on a gone thread is lost only when a second read still shows the thread gone (`TestSessionLostNeedsASecondRead`); a continuation runs on a new subagent with its own `thread_started` row and takes the checkpoint branch inside a suffix; `TestSessionLostAttemptGoesOnInTheSameAllocation`, `TestSessionRunDeathAtEachRow`, `TestSessionStaleAndEarlyReports`, `TestSessionPairMismatchIsNotBound`, `TestSessionContinuationAfterRestart`, `TestSessionHeldCallGoesOnInPlace`).
- A subagent inherits its parent's cwd and sandbox, so an executor's pending tree could have been taken of the owner's checkout, and an executor that committed would have broken `crw.commit` (HEAD is not the parent) and the effect proof (a foreign commit); port: fixed (P is the call's cwd for `pending_tree`, `p_held` and `qa_source`; at harvest an executor's HEAD is compared with its start, a moved HEAD is kept on `refs/crw/flow/<run>/stray/<node>/a<n>` and recorded `executor_head_moved`; `crw.commit` commits the pending tree on the recorded start with the observed HEAD as the compare-and-swap's old value; `Prover.Node` takes a recorded stray HEAD whose tree is the pending tree as the call's state; the trace digests write `read_role_wrote`, `executor_wrote_outside` and `shared_state_changed` as warnings; `TestSessionExecutorThatCommitted`, `TestSessionTraceDigestsWarn`, `TestCommitOverAStrayHeadKeepsTheRecordedParent`, `TestStrayHeadWithThePendingTreeIsProven`, `TestCrwCommitOverAStrayHead`, `TestAllocatorKeepsAStrayHead`).
- Relay acceptance judged an author call by the pair of its newest thread only, so the earlier attempt of a session executor whose edits stay in the head, bound with another pair, would not have been an author pair; port: fixed (the newest `thread_started` row of a session call names the earlier attempts' pairs in `prior_pairs`, and `authorPairs` reads them; `TestAgentAcceptOnSessionRows`).
- Deviation: the role overlays and `workflows/lib/packets.js` now say "work only under the absolute path P" instead of naming the thread's cwd, which is still true on the App Server; the prompt digest of the calls whose packet text changed differs from a run journaled before, so such a call of a run in progress runs live on its resume (installed when no run is in progress, CRW-1316 §13); port: kept (the overlays must not state a cwd a session subagent does not have).
- Deviation: write isolation of a subagent is recorded, never enforced, because the host gives every subagent its parent's sandbox (CRW-1316 §2, §6); port: kept (warn and record, Jun's rule for a reversible action).
