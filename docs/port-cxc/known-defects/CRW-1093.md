# CRW-1093 — memory authorization from affirmative user requests

Source: CXC v0.2.40 `pabcd-state/src/memory-write-gate.ts:78-105`, ported in `internal/pabcd/hook/detect.go`.

- The whole-prompt detector armed a one-write marker from negated or quoted examples; port: fixed. Only affirmative user sentences authorize memory. Quoted spans, backticks, Markdown fences, blockquotes and embedded task packets are excluded. Memory-specific English and Korean negatives override affirmative idioms in the same sentence. Lists, don't-forget / 잊지 마 and requests referring to following quoted content remain affirmative. Other prompt detectors and `prompt_submit.go` are unchanged.
- `TestCRW1093PromptToProtectedWrite` runs prompt submission followed by a protected Write with PABCD on and off, checks the marker, and denies a second write. `TestCRW1093ConcurrentAndNextTurn` permits exactly one of eight concurrent writes and denies a later turn. The CLI grant and cwd/session/turn binding are unchanged. Recorded detector expectations for negation, quotes and Korean sentence endings intentionally differ from the oracle.

- The final boundary pass also excludes variable-width inline backticks, unfinished quotes and curly single quotes, recognizes negatives with intervening adverbs, and excludes plain Task packet headings. The actual harness UserPromptSubmit → memory-write ingress is tested separately, with PABCD on/off and a second-write refusal. Additional quote/adverb/packet cases were red before the correction and green afterwards.

- Post-evaluation correction: quote/code spans are removed across physical lines before matching whole sentences, and a negative on a continuation line can veto its sentence. Affirmative idioms may themselves wrap across lines. English prohibitions on unrelated file writes no longer veto a request to remember a preference. Question punctuation is preserved: the Korean recall question 기억해? does not authorize a protected write; port: fixed. Actual prompt-submit and protected-write ingress verifies these cases with PABCD on/off and one-time consumption.
- Negation refinement retains refusals that refer to memory as it/this/that or say write to memory, while unrelated prohibitions such as do not write tests remain valid remembered preferences. These forms also cross physical lines; actual prompt/memory ingress is red before this refinement and green after it.
- The narrowed English dictionary also retains the negative form of keep this/that/it in mind. Wrapped negative idioms deny, while unrelated write prohibitions in remembered preferences still allow; red/green actual-ingress evidence is retained.
- Fix-round (final head): the memory negative dictionary also covers `Let's not`, `must not / should not / will not` and their contractions, optionally followed by `ask/want/need/expect/have you to` (`Let's not remember this`, `I won't ask you to remember this`, `You must not remember this`); port: fixed. Actual prompt/memory ingress cases are in `TestCRW1093CorrectionActualIngress`, with the unrelated-write preference control (`you must not write tests ...`) still affirmative.
- Recorded oracle difference: a trailing line break after an affirmative request (`기억해\n`, `기억해\r\n`) now arms the marker, where the oracle's end-of-input match did not (a Go/oracle quirk); the affirmative reading is within the issue's promise. The two corpus expectations in `detect_test.go` changed from false to true accordingly; port: fixed.
