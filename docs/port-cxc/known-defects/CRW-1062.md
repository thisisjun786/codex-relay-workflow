# CRW-1062 — moves of the managed checkout and xargs-fed removals in the worktree guard

Source: Linear CRW-1062 (created 2026-10-09, from the independent verification of the CRW-895 branch: GPT sol, reported as
item A11 and section 5-1 of /state/crw/mgmt/activation-readiness-shell-reader-20261009.md). The Go files are
internal/pabcd/hook/worktreedel_judge.go (worktreeDelJudgeMv, worktreeDelMayReach, mvSources, worktreeDelJudgeGit) and the
reader rows in internal/pabcd/hook/testdata/shellir/rows/45-crw-1062.txt. The reader itself (internal/pabcd/shellir) is unchanged.

- A move of the managed checkout, its slot root or an ancestor of the working directory was allowed: the guard judged no mv at
  all, so `mv ../repo /tmp/gone` took the checkout away, which is the removal rm -r is refused for. port: fixed (a source
  that is the checkout, the slot root or an ancestor of the working directory is refused; -t, --target-directory and -- are read
  as mv reads them). Pinned by TestMoveOfCheckoutOrAncestorIsRefused and rows CRW-1062-01; moves inside the worktree stay
  allowed in the same test.
- A move whose operand the reader cannot read was judged by no rule. port: fixed (refused as unreadable when the operand could
  name the checkout, that is when the directory the command runs in is unknown or is the checkout, inside it or above it). A
  variable operand run from outside the checkout, such as the loop variable of `for f in ...; do mv $f $f.bak; done` in a
  state directory, stays allowed as on dev: refusing it lost 2 allowed commands of the benign corpus. Pinned by
  TestMoveWithUnknownOperandIsRefused and TestShellWriteBenignAccounting, which matches the dev report line for line.
- A removal whose target arrives through xargs was allowed, since the guard found no literal target: a printf-format feed
  (CRW-1062-02), a file-operand filter in front of xargs (CRW-1062-03), a custom delimiter (CRW-1062-04) and a plain echo feed,
  the CRW-895 shape (CRW-1062-05). port: fixed (git worktree remove behind a run-time carrier, which is xargs, find, parallel or
  entr, is refused as unreadable whatever its input is, because the reader does not prove the bytes the carrier reads). Pinned by
  TestXargsFedRemovalIsRefused and rows CRW-1062-02 to 05.
- A move behind a run-time carrier (xargs, find, parallel or entr) is refused by the same rule, so an in-worktree move fed by a
  pipeline is refused too. port: kept (a fail-closed over-block; no allowed command of the benign corpus is affected).
- An unrelated xargs stays allowed: `echo x | xargs wc -l` (CRW-1062-06) and `echo x | xargs git status` (TestXargsFedRemovalIsRefused).
- A non-recursive rm behind xargs is not changed here; it belongs to the CRW-895 line. port: pending (CRW-895).
