# CRW-1062 — moves of the managed checkout and xargs-fed removals in the worktree guard

Source: Linear CRW-1062 (created 2026-10-09, from the independent verification of the CRW-895 branch: GPT sol, reported as
item A11 and section 5-1 of /state/crw/mgmt/activation-readiness-shell-reader-20261009.md). The Go files are
internal/pabcd/hook/worktreedel_judge.go (worktreeDelJudgeMv, mvSources, worktreeDelJudgeGit) and the reader rows in
internal/pabcd/hook/testdata/shellir/rows/45-crw-1062.txt. The reader package internal/pabcd/shellir changes only by the
Feed field of its command context, which names the run-time carrier (xargs, find, parallel, entr) that feeds a text through
the shells it runs.

- A move of the managed checkout, its slot root or an ancestor of the working directory was allowed: the guard judged no mv at
  all, so `mv ../repo /tmp/gone` took the checkout away, which is the removal rm -r is refused for. port: fixed (a source
  that is the checkout, the slot root or an ancestor of the working directory is refused; -t, --target-directory and -- are read
  as mv reads them). Pinned by TestMoveOfCheckoutOrAncestorIsRefused and rows CRW-1062-01; moves inside the worktree stay
  allowed in the same test.
- A move whose source the reader cannot read is refused from any directory. The source may name the checkout through a variable
  whose value the guard cannot see, so `cd /tmp && mv "$SRC" /tmp/gone` (CRW-1062-09) is refused although /tmp is unrelated to the
  checkout. port: fixed. Cost: the loop `for f in ...; do mv $f $f.loadfail; done` in a state directory was allowed on dev and is
  refused now; two commands of the benign corpus (report lines 1546 and 1547 of TestShellWriteBenignAccounting) change for this
  reason. The reader does not bind a loop variable to its word list, so a loop-variable model is the way to allow them again;
  it is a separate follow-up, not part of this change. An unknown destination alone stays allowed (CRW-1062-13).
- A move is judged under both option readings: getopt permutes the arguments, so an option after the first operand is an option,
  and with POSIXLY_CORRECT it is an operand (`POSIXLY_CORRECT=1 mv build.log -S ../repo /tmp/gone`, CRW-1062-10). port: fixed.
- A move that find -exec runs in a shell (`find ../repo -exec sh -c 'mv {} /tmp/gone' \;`, CRW-1062-08) is refused, because
  the placeholder names the checkout at run time. port: fixed through the Feed field. The same Feed reaches a git worktree
  remove in such a shell, which is refused too.
- A removal of the worktree through git with a global option before the subcommand (`git -P worktree remove`,
  `git --no-pager worktree remove`, CRW-1062-11) was allowed. port: fixed (the judge skips the global flags the reader accepts
  before the subcommand, and the value-taking ones with their value).
- A removal whose target arrives through xargs was allowed, since the guard found no literal target: a printf-format feed
  (CRW-1062-02), a file-operand filter in front of xargs (CRW-1062-03), a custom delimiter (CRW-1062-04) and a plain echo feed,
  the CRW-895 shape (CRW-1062-05). port: fixed (git worktree remove behind a run-time carrier, which is xargs, find, parallel or
  entr, is refused as unreadable whatever its input is, because the reader does not prove the bytes the carrier reads). Pinned by
  TestXargsFedRemovalIsRefused and rows CRW-1062-02 to 05, and by the git global option rows CRW-1062-12.
- A move behind a run-time carrier (xargs, find, parallel or entr) is refused by the same rule, so an in-worktree move fed by a
  pipeline is refused too. port: kept (a fail-closed over-block; the benign corpus has no such command allowed on dev).
- An unrelated xargs stays allowed: `echo x | xargs wc -l` (CRW-1062-06) and `echo x | xargs git status` (TestXargsFedRemovalIsRefused).
  A nested shell under find that names no checkout stays allowed (CRW-1062-14).
- Not covered and not changed here: a recursive rm, or an rmdir, run by a shell that find or xargs starts
  (`find ../repo -maxdepth 0 -exec sh -c 'rm -r {}' \;`). The rm rule judges a nested shell as dev did. port: pending (a
  follow-up, separate from the move and git rules).
- A non-recursive rm behind xargs is not changed here; it belongs to the CRW-895 line. port: pending (CRW-895).
