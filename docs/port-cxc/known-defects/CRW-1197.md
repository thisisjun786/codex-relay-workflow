# CRW-1197 — the App Server backend of the flow engine: what the decided design left to the code

Source: CRW's own design (0.5.0-alpha, issue F04), not the CXC oracle: the flow engine has no counterpart in CXC v0.2.40 (commit 3c1459ac). The Go side is `internal/flow/backend/agent/` (the backend, the allocator), the thread model of `internal/bridge/appserver/fakehost/threads.go`, the schema copies and fixtures under `internal/bridge/appserver/testdata/`, and the hooks the engine gives a backend in `internal/flow/engine/backend.go`, `call.go` and `journal.go`.

- The body names three edit regions (`internal/flow/backend/agent/`, `fakehost/`, `testdata/`), but the call lifecycle it describes is written by the engine: the `prepared` row that must precede the worktree, the `fork_requested` and `fork_started` rows, the re-check before the first `turn_requested`, `P_held` on a held row and the interrupt intent are all rows of `callRun.execute`. A backend alone cannot order them; port: deviation, kept visible (`internal/flow/engine` gains optional interfaces a backend may implement - `Placer`, `Forker`, `Reconciled` - and the call reads them; a backend that implements none, the fake, runs the lifecycle F01 shipped, and the whole engine test suite passes unchanged. `Placement.Map` is the shape of the `allocation` member of `prepared`).
- F01 ended a call whose request got no answer (a lost connection, a phase timeout) with a written `outcome_unknown` row, while the body says such a call is not held and its `turn_requested` stays its last row for the reconcile pass (F05). Both are kept: the App Server backend declares `engine.Reconciled` and the call then writes no terminal row (`TestTurnStartTransportLossIsNotHeld`), and the fake backend keeps writing `outcome_unknown` (`TestHostFailureMap` and the CallResult golden of F01); port: deviation, kept visible (the script sees `unknown` with `dispatch_unknown` either way).
- The 0.154 refusals of an ephemeral thread's history are fixtures, but no App Server was started to record them (this lane starts no host process): the message texts are the ones the 0.154.0 binary carries, and the code -32600 is the invalid-request code of the other refusals in the repository's fixtures. Whether the real frame carries more members than `code` and `message` is not known from here; port: kept (`testdata/fixtures/ephemeral-refusals.PROVENANCE.txt` says so, and `TestEphemeralHistoryRefusedFixture` pins the fake to the files). The fake also refuses `thread/read` with `includeTurns: true` on a persistent thread, with the deprecation text of the same binary, so a backend that falls back on hydration fails its tests; what 0.154 answers there is not recorded.
- `crw.commit` (F08) and the suffix restore (F07) do not exist yet. The allocator reads the rows they will write by name: the result commit of a completed `crw.commit` call row is `Data["commit"]` of the row with `Op: crw.commit` and `Data["node"]`, and a restored worktree is the flow row `worktree_restored` with `node`, `lineage`, `attempt`, `path`, `C`, `P` and `snapshot_digest` (`agent.OpCommit`, `agent.EvWorktreeRestored`). Those two shapes are this issue's interface for F07 and F08; port: deviation, kept visible (the tests write the rows themselves, as those issues will, and a differing shape there is a change to `journaled` and `lastCommit` in `internal/flow/backend/agent/worktree.go`).
- The body says a restore is verified against its "snapshot digest" and a held executor carries "the working snapshot" without fixing what that is (engine.resume.workingSnapshot belongs to F06). `Allocator.Snapshot` defines it for this build: the tree object id of every file a worktree holds that git does not ignore, computed in a throwaway index; port: deviation, kept visible (F06 and F07 take their digests from this function or replace it together with the rows above).
- The relay client unsubscribes the connection from a thread it started when the first turn there ends (it retains only a never-run thread), and a host sends a thread's notifications only to subscribed connections, so the notification bus carried the first turn of a flow thread and none after it: a repair or fix turn was heard only by the pull fallback, one poll interval late; port: fixed (the backend holds each thread's subscription with `Client.HoldThread` before every turn and releases it in `Backend.Close`; `TestThreadStaysSubscribedAcrossTurns` runs a call's repair turn and two continuations with the pull an hour away).
- A reviewer, architect or explorer call without a `head` runs in a detached worktree at the node's base; the body names the head only for the reviewer; port: kept (the base is what `AllocatorConfig.Base` reads, else the repository's HEAD).
- A run cancelled while a `turn/start` is still waiting for its answer cannot interrupt the turn it may have started: the turn id comes in the answer, so the backend has none to send `turn/interrupt` for, and the call ends `superseded` (`cancelled`) while the host's turn runs on; port: kept (a turn already named by `turn_started` is interrupted - `TestCancelledRunInterruptsTheTurn` cancels at that row - and the unnamed one is found by its `<call_id>/t<k>` marker by the reconcile pass of F05).
