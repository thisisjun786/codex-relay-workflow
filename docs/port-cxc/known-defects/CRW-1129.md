# CRW-1129 — a policy stop keeps a way to record its child's cleanup

Source: `plugins/codexclaw/components/subagent-config/src/fallback-dispatch.ts` at v0.2.40 (commit 3c1459ac), `report`
(:184, the stop decision before any execution-state or reconciliation check), `taskFailed` (:220) and the non-active
short-circuit of `runDispatch` (:150-158); the Go port's `dispatchProviderDecision` and the non-active return of
`dispatchPinnedRunHeld` in `internal/role/dispatch_ledger.go`, and `createdCheckStop`, `dispatchPolicyStopCleanup`,
`dispatchCleanupRecord` and `createdCheckHeld` in `internal/role/created_check.go`.

- A provider failure the policy refuses to fall back from (a denial, a cancellation) sets the dispatch to stopped before the
  execution state or the child is looked at, and leaves the attempt running with its recorded child; every later report
  returns early on the stopped dispatch, the Go stopped close included, so the child's termination, the inspected partial
  work, or the correction of a wrongly attributed id can never be recorded, and the id stays held for good (source
  `fallback-dispatch.ts:184` and `:220`; recorded with the oracle: stopped, running and the child kept, a later complete
  ignored); port: fixed (the decision, the stopped status and the original code stay. At the checked boundary the stop marks
  the attempt's `cleanup` as `pending` when it names a child that is not accounted for. The stopped report on such a dispatch
  is a cleanup-only amendment: it needs `executionState: "stopped"`, the recorded `agentId` and `reconciliation`, reads the
  child through the same termination observation as the handoff (CRW-1126), refuses an active child or a turn in progress,
  records the evidence as `unconfirmed` with the id still held when the child's end cannot be seen, and, when it is seen,
  fails the attempt with the reconciliation, keeps the code and task failure, records `confirmed` cleanup and frees the id.
  The dispatch stays stopped and the answer is always `stop`: no candidate rotation, no new attempt, no spawn and no
  main-direct. A created refusal that meets such an id names the cleanup report. Pinned by
  `TestDispatchCleanupAfterAPolicyStop`, `TestDispatchCleanupWithoutAChild` and `TestDispatchCleanupHoldsTheIdUntilConfirmed`).
- The cleanup keeps the members it does not own, and each state replaces the previous cleanup over those members (see
  CRW-1127; pinned by `TestDispatchTerminationAndCleanupKeepMembersTheyDoNotOwn`).
