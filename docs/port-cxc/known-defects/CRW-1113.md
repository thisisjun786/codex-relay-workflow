# CRW-1113 — a sign-off that met a held lock is kept and drained, not dropped

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/review-observer.ts:57-164`, the SubagentStop observer that owns plan-audit approval. The Go side is `internal/pabcd/hook/reviewobserver.go` (the observer), `internal/pabcd/hook/reviewobserver_inbox.go` (the inbox and its drain) and the A>B transition in `internal/pabcd/cli/orchestrate_transition.go`. Found by the 10-10 CXC improvement review (A3-06, P2 confirmed).

- The oracle drops a reviewer's sign-off when the session lock or the goalplan lock is held for the observer's whole wait (`review-observer.ts:160-162`), and when the plan write fails: the parsed sign-off lives in a local variable only, the hook always releases the child with an empty answer, and nothing persists it to be tried again. A PASS vanished after about 259 ms against a live session lock (about 94 ms against the goalplan lock), and the audit round stayed `in_flight` after the lock was gone; the same sign-off without a lock was approved. The Go port did the same (`reviewobserver.go` before this issue discarded the session lock error, the goalplan lock result and the `WriteGoalplan` error); port: fixed (the observer keeps the parsed sign-off first, as one small file `.crw/review-inbox/<session>/<hash>.json` holding the session, plan slug, plan epoch, work-phase, launch, agent id and verdict, never the message text; the file is complete before it is visible, and one child's sign-off for one launch is one file however often it is delivered. It then publishes under the session lock then the goalplan lock, the order every writer of this tree follows. An entry that was not published stays and is drained at the next legitimate moment: the next SubagentStop of the same session, and the A>B transition, which drains under the session lock it already holds before it judges the review binding (`hook.DrainReviewObserverInbox`) and drains once more inside the goalplan lock of its own A>B publication (`hook.DrainReviewObserverInboxInLock`), on the plan it then judges, so a kept FAIL that met a busy lock at the first drain is still honoured and a valid verdict whose plan write failed refuses the edge instead of being deleted after the session moved to B. Nothing blocks the child, and nothing polls. Pinned by `TestReviewObserverKeepsASignoffThatMetAHeldLockAndApprovesItAfterwards` (session lock and goalplan lock; the round is approved with no new reviewer round after the lock is released), `TestOrchestrateReviewBindingDrainsAKeptSignoffBeforeTheCheck` (a kept FAIL is honoured by the A>B check, a kept PASS is recorded as the reviewer's approval and its entry removed, with the lock released before the transition and held through its first drain) and `TestReviewObserverInboxDrainIsIdempotent`).
- A kept sign-off is judged again at drain against the binding as it is then, through the code a live sign-off uses: the session must be in A and bound to the same plan, the plan epoch it arrived under must be the current one and the round's, the work-phase it arrived for must be the active one and the round's, the child must be the round's reviewer, and the round must still be `in_flight` (a round that already holds a terminal verdict is never overwritten). Every other outcome is ignored with a `review_signoff_ignored` ledger row and the entry is removed, so a stale entry cannot approve an old plan later. Worker and executor exits and exits with no parseable sign-off or no agent id are never kept; port: fixed (new behaviour of this issue; pinned by `TestReviewObserverInboxEntryIsRevalidatedAtDrain` for superseded epoch, session that left A, another active work-phase, an earlier terminal verdict and another signing child, and by `TestReviewObserverKeepsNothingForWorkersExecutorsOrUnparsedExits`).
- An inbox that cannot keep a sign-off (full at 64 entries, unwritable) is not an approval: the sign-off is still judged once in memory when the locks are free, as before, and one bounded `review_signoff_inbox_failed` row (200 characters of detail) records the failure at once, whether or not a session or goalplan lock is free (the row is a ledger append, which takes no lock). A valid verdict whose plan write failed stays in the inbox with one bounded `review_signoff_write_failed` row. An entry file that is not one of ours is removed with one row. A sign-off kept while the plan could not be read (the unlocked first look failed) carries no work-phase, and the drain binds it to the round's own, which must be the active one; it is no longer refused as a work-phase mismatch. Pinned by `TestReviewObserverInboxFailureIsADiagnosticNotAnApproval` (both locks held), `TestReviewObserverTransientlyUnreadablePlanDoesNotDestroyASignoff`, `TestReviewObserverUnknownWorkPhaseEntryStillFollowsTheRound` and `TestReviewObserverInboxDropsAnUnreadableEntryAndDrainsTheRest`; port: fixed.
- The inbox is opened one component at a time from the workspace, `.crw`, `review-inbox` and the session directory each without following a link, and every create, list, read and remove then runs relative to that directory descriptor; a link or a non-directory in any of those places is an inbox failure (the bounded `review_signoff_inbox_failed` row and the in-memory judgement above), so nothing outside the workspace's own inbox is created, read or removed. Only names of the observer's own shape (32 hex digits and `.json`) are listed, read or removed; any other file in the directory is left alone and not reported. Entries are ordered by a nanosecond receipt time. Pinned by `TestReviewObserverInboxNeverFollowsALinkOutOfTheWorkspace` (session directory and inbox directory linked to a foreign directory) and `TestReviewObserverInboxRemovesOnlyItsOwnFileNames`; port: fixed (new behaviour of this issue).
- A plan write that fails after the rename has published the plan (`state.PublishedError`: the directory fsync or its open) recorded the verdict: the drain goes on from the recorded plan, removes the entry and writes one bounded `review_signoff_write_unsynced` row, so a later child's sign-off in the same drain is refused against the terminal verdict instead of overwriting it, and the A>B in-lock drain judges the published plan with nothing left unapplied. A write that fails before publication recorded nothing: that entry and every entry after it stay unjudged for the next drain (one `review_signoff_write_failed` row), so no later child's sign-off is recorded ahead of an earlier one. Pinned by `TestReviewObserverDrainKeepsAVerdictPublishedBeforeItsWriteFailed`, `TestReviewObserverInLockDrainAnswersThePublishedPlan` and `TestReviewObserverDrainKeepsAnUnpublishedVerdictAheadOfLaterSignoffs` (reviewer-1 FAIL then reviewer-2 PASS for one launch); port: fixed (new behaviour of this issue).
- Not changed here: the sign-off parser (`internal/pabcd/review/signoff.go`) is untouched, and the drain points are limited to the observer's own hook and the A>B transition; `review-round` and the Stop hook do not drain.
