# CRW-924 — a ".." after a link folded by Join, Dir, Glob and WalkDir below a configured root, and the installer boundary of runtime-upgrade

Source: CRW-924 (the `internal/manage` half of the class named in known-defects/CRW-937.md, item beginning "The same class (a `Join` or `Clean` removing a `..` after a link)") and the pre-merge evaluation of this branch, crw924-7bd9d0ef (defect d1, criterion c3, defect d2). The defects are the port's own: Go's `filepath.Join`, `Dir`, `Clean`, `Abs`, `Glob` and `WalkDir` clean their result, which removes a `..` that follows a symbolic link before the filesystem sees it, so a root spelled `<link>/../state` named a different directory than the kernel resolves it to. The Go files are internal/manage (config.go, audit*.go, checkpoint.go, capacity.go, deliver*.go, sendparent.go, pump*.go, improve_*.go, memlog.go, dagreview_host.go, upgrade.go, upgrade_steps.go, rootpath.go) and internal/crwconfig/paths.go (JoinRoot).

- Every path built below a configured or environment root (manage state, state_dir, the relay store and socket, HOME, XDG_STATE_HOME, CODEX_HOME, the release directory) was built with `filepath.Join`/`filepath.Dir` and so named the cleaned directory for a root that mixes a link and `..` (CRW-924 item 1); port: fixed (`crwconfig.JoinRoot` joins as raw text, `rootDir` takes the directory from the text, `coreHomeDir` joins raw; TestJoinRoot* in config_root_join_test.go plant a decoy at the cleaned spelling and require every command to leave it alone).
- The searches `filepath.Glob` (the pump's rollout below CODEX_HOME, the release archive) and `filepath.WalkDir` (the audit reference sources) join each name they find with `filepath.Join`, so they went on in the cleaned directory after their first level; port: fixed (`rootGlob` and `rootWalk` in rootpath.go join found names as raw text; a literal pattern component is looked up with `Lstat` as `filepath.Glob` does, so a CODEX_HOME that may be searched but not listed still yields its rollout; the symlink refusals of the copy are kept).
- `TestJoinRootNoCleaningPathCallsInManage` fails when `filepath.Join`, `Dir`, `Clean`, `Abs`, `Split`, `Glob`, `Walk` or `WalkDir` is called in a non-test file of internal/manage outside the allowlisted functions (paths already resolved by `EvalSymlinks`, the cleaned fallback identity of an unresolvable audit bundle, the tar entry name check, the resolved directory of the improve output); port: kept (a lexical check on text that is not a root is correct, and each allowlisted function names why).
- The job bundle key of the audit (CRW-924 item 2) is already resolved on dev by `auditBundleResolvedPath`/`auditBundleIdentity` (component-wise `EvalSymlinks`); its cleaned absolute spelling is only the documented fallback for a bundle the kernel cannot resolve; port: kept.
- `crw install update`, run by runtime-upgrade, cleans `--from` and `--backup-state-to` (`filepath.Abs` in internal/runtime/install archive.go and cli.go) and takes the `SHA256SUMS` from the cleaned archive's directory. Once management kept the run directory raw, a state directory spelled through a link and `..` made the installer read the archive and checksums of the cleaned directory (another archive, or none after the service was stopped) and write the backup there (pre-merge evaluation d1); port: fixed (`resolveRunDir` makes the run directory physical with `EvalSymlinks` after the archive is pinned and before anything is stopped, and the update names the pinned archive and the backup through it, so the installer's cleaning is the identity. A run directory that cannot be resolved is refused as `sums_failed`. Pinned by TestUpgradeUpdateArgumentsNameThePhysicalRunDirectory, with and without another archive and checksums at the cleaned spelling).
- The installer still cleans the paths it is given; port: kept (its callers pass spelled paths on purpose and the installer is not part of this issue; the other arguments of the update, `--state` and `--socket`, are passed as configured and were not changed by this issue).
- Supersedes known-defects/CRW-937.md, item beginning "The same class (a `Join` or `Clean` removing a `..` after a link)": now port: fixed for internal/manage (CRW-924; CRW-923 keeps its own files).
