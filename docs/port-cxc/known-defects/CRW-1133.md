# CRW-1133 — the create_goal guard no longer refuses a token_budget the user named

Source: CXC v0.2.40 (commit 3c1459ac) plugins/codexclaw/components/pabcd-state/src/goal-gate.ts, lines 25-29
(CREATE_GOAL_WARNING), 105-125 (hasInvalidCreateGoalInput, applyGoalBudgetGuard) and 166-205 (the dispatcher that
runs it before every other guard, also with PABCD off), with freeze.ts GOAL_ACTIVATION_DIRECTIVE (step 2). Go port:
internal/pabcd/hook/goalgate.go (the guard is removed; the registration in internal/harness/legs.go stays),
internal/pabcd/interview/freeze.go (GoalActivationDirective), plugins/crw/skills/crw-loop/references/durable-goalplan.md
and plugins/crw/skills/crw-run/references/goal-mode.md. Found by the combined review of 2026-10-10 (finding B4-03).

- A create_goal whose tool_input carries any key but objective is denied, and the deny text and the freeze handoff
  tell the agent to omit token_budget so the goal stays unlimited; the denial runs also when PABCD is off, so a limit
  the user named could not reach the host and the agent was led to delete it, against the Run goal-mode rule that a
  user-supplied limit is kept (goal-gate.ts:105-125, :25-29, :166-205; recorded as
  `hook__pre-tool-use-guarding-goal-budget__token_budget_denied`); port: fixed (a deviation from the oracle, recorded
  by decision of CRW-1133: the guard is removed and a create_goal is passed to the host whatever its tool_input
  holds, so the fields and their values are validated by the host's own tool contract and a limit the user named
  reaches it as given. The registration stays and answers nothing, so its declaration and trust hash do not move.
  The freeze handoff, the durable-goalplan reference and the Run goal-mode rule now say one thing: pass token_budget
  only when the user named a token limit, with exactly that value, never one the agent chose; with no limit named the
  goal is unlimited; a host whose create_goal does not accept token_budget is a reported capability conflict, not a
  reason to create the goal without the limit. CRW still never writes the host's goal database. The interview and
  goal-complete guards are unchanged. The recorded case is tagged intentionally-changed in
  contract/notes/cxc/CRW-1133.json: the answer is now silence).

  Pinned by `TestInstalledCreateGoalLegPassesTheUsersBudgetToTheHost` in `cmd/crw/goal_budget_test.go` (the installed
  leg behind a crw switch: objective only, a positive budget, a value the host rejects, an unknown field),
  `TestGoalGateLetsCreateGoalReachTheHost` in `internal/pabcd/hook/goalgate_test.go`,
  `TestSyntheticHostGoalLifecycleKeepsTheUsersBudget` in `internal/pabcd/hook/goalgate_budget_test.go` (create, spend,
  budget_limited, resume, raise: the hooks read the goal and the limit stays the user's), and
  `TestFreezeGoalHandoffDoesNotTellTheAgentToDropTheBudget`, `TestSkillsDoNotTellTheAgentToDropTheBudget` and
  `TestFreezeGoalActivationDirectiveIsTheRecordedConstant` (the oracle's text but for step 2) in `internal/pabcd/interview`.
