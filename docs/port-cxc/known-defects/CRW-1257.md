# CRW-1257 — SessionStart first-fallback notice read as a ban on an explicit native spawn

Source: CXC v0.2.40 (commit 3c1459ac), `fallback-dispatch-cli.ts:9` (the guidance text, "Roles with a first fallback use the main-owned dispatch protocol before native spawn") and `fallback-dispatch-cli.ts:11-21` (the SessionStart notice that carries it); the port's `internal/role/fallback_notice.go` (`DispatchGuidance`, `ExplicitNativeSpawnNote`, `fallbackSessionNotice`), `internal/role/spawn/hook_route.go` (the unmanaged notice of a direct spawn) and `plugins/crw/skills/crw-pabcd/references/delegation.md` ("Configured first fallback"). Evidence: the real-environment trial r1, scenario S5-s6.

- The oracle's SessionStart text says a role with a first fallback uses the dispatch protocol before native spawn, and says nothing of the spawn hook allowing a direct spawn that carries no dispatch marker (and marking it as not managed by first-fallback tracking); a parent model given the user request "spawn an explorer natively, without `crw role helper dispatch`" refused it as forbidden by its session instructions, so the request, a one-time recursion grant test, never started (real-environment trial r1, S5-s6-grant), although the hook allows exactly that spawn (`hook_route.go`, control S5-C-plain); port: fixed (the notice is the oracle's text byte for byte, `DispatchGuidance` unchanged and still pinned by `guidance.golden`, followed by one CRW-owned sentence, `ExplicitNativeSpawnNote`: dispatch is the default procedure and not a prohibition; when the user's current request explicitly asks for a direct native spawn, spawn it as asked for any role (explorer, executor, reviewer or architect), the spawn hook allows it and marks it unmanaged, and an unmanaged spawn creates no managed receipt. It is said only where the notice announces a configured fallback, and the whole notice stays within the 4096 UTF-16 units budget for all four roles with the dispatch card. `delegation.md` "Configured first fallback" says the same in a paragraph. Pinned by `TestFallbackNoticeSaysAnExplicitNativeSpawnIsNotRefused`, `TestFallbackNoticeOracleAndRepeatedStartup` (notices.json), `TestDispatchSurfaces_ConfiguredFallbackIsTheDefaultNotAProhibition` and, for the hook side, `TestSpawnHookAllowsAnExplicitNativeSpawnAsUnmanagedForEveryRole`).
- The sentence takes no capability away and adds no refusal rule: the hook's decision on a direct spawn, the unmanaged notice it appends (which still carries `DispatchGuidance` only) and the managed spawn's markers and receipts are unchanged; port: kept.
- The notice text of a session with a configured fallback is longer, so the guidance digest the session-guidance record keeps (CRW-1146) changes with it: a resumed session that was given the earlier notice is given this one once; port: kept (the CRW-1180 claim of the replay fixture `hook__session-start-announcing-subagent-fallback__fallback_configured_protocol_precedes_card` states the new stdout and digest).
