# CRW-941 — sed script writes and sort -o read as destinations, options read as getopt_long reads them

Source: Linear CRW-941 (CRW-765 final-diff review P2, an existing defect of dev), the management re-check of 2026-10-09 on dev
09e5c5bcc (probe sources under /state/crw/mgmt/recheck-20261009/, group g6) and the independent verifier's addition (sed
--expression with the script as a separate argument). The oracle is the CXC v0.2.40 memory write gate (3c1459ac,
shell-write-destinations.ts), which reads the operands of sed -i, the -o of sort in its short forms and the full --output, and no
sed w, W or s///w file. The Go files are internal/pabcd/shellir/gnuopts.go (the shared option reader), internal/pabcd/shellir/carriers.go
(sedInline), internal/pabcd/hook/shellwrite_sed.go (the script reader) and internal/pabcd/hook/shellwrite_ir.go (the sort and sed
destinations). The reproductions are rows CRW-941-01 to 16 (the issue) and CRW-941-S01 to C26 (this change) in
internal/pabcd/hook/testdata/shellir/rows/03-crw-851-941-998-951.txt and 18-crw-941.txt, indexed in reproductions.tsv; the red
output on dev is evidence/red-1-before-fix-dev-09e5c5bcc.log.

- sort --o=FILE, --o FILE, --ou=FILE and --ou FILE (the abbreviations of --output shorter than --out) wrote the file and the
  memory gate answered none; GNU getopt_long accepts any unambiguous prefix of a long option, and no other long option of sort begins
  with o. The reader required five letters. port: fixed (security). The reader now resolves every long option name of sort and sed the way getopt_long
  does (shellir.MatchLongOption: an exact name, else a prefix of one option or of several that mean the same; a prefix of options
  that differ is ambiguous). Pinned by rows CRW-941-S01 to S27 and TestMemoryGateReadsSortOutputAndSedScriptWrites (every prefix of
  --output, with = and with a separate value, through HandleMemoryWriteGate with and without a grant).
- sort read the value of -k, -S, -t, -T and -y only when attached, and the value of every long option never: a value that looks
  like -o (sort --key -o FILE, where -o is the key and FILE an input) was read as the output option. The value of every sort option
  that takes one is now skipped, as getopt does. port: fixed (an over-refusal removed; row CRW-941-S34).
- sort and sed options after an operand (sort x --o=FILE) are read; getopt permutes and so does the reader. The words after -- are
  operands. POSIXLY_CORRECT, which stops the permutation, is not modelled: a reading that sees an option there only refuses more.
- A sort option that is no option of sort, or an ambiguous prefix (--s: --sort or --stable; --c: --check or --compress-program), makes sort stop
  before it writes, so no destination is named (rows CRW-941-S32, S33). port: fixed.
- sed --expression with the script as a separate argument, and every abbreviation of --expression (--expr, --exp, --e, ...), in the
  separate and the = form: read as a script (rows CRW-941-E01 to E12). The sed option reader (shellir.ParseSedArgs, used by
  the shared reader's sedInline and by the destination readers of the hook, so there is one reading of the command line) knows
  the long option table of GNU sed and refuses what it cannot prove: an unknown option, an ambiguous prefix (--s, --f), --help and
  --version, an option that needs a value and has none, a value given to an option that takes none, and an option word the reader
  cannot evaluate before the first operand. port: fixed (security). Before this change --expr=SCRIPT and the like were refused as
  unmodelled (attempt/deny/deny), and so were --line-length N, --line N and the abbreviations --regexp and --z; they are read now
  (rows E03 to E08, E25, E27, E32, E34, E35).
- sed -i in any spelling (-i, -ni, -i.bak, --in-place, --in-place=SUF, and the abbreviations --in, --i=SUF) names its operands;
  an abbreviation was refused as unmodelled before. -I, -b and --follow-symlinks are read as sed reads them. port: fixed
  (rows CRW-941-I01 to I11).
- A sed script file (-f, --file, --fi=, --fil, -nf, -fFILE, --file=- with the script in a here-document) stays unreadable: the file's
  text is not in the command, so the three gates refuse it (attempt/deny/deny); a script file the same text writes and then runs
  is refused for the same reason. port: kept (the CRW-941 text asks for it; rows CRW-941-10, F01 to F14).
- The sed script reader ended a command too early in four places, so a write the script performs was not named. GNU sed opens every
  w file when it reads the script, so a w after q, a branch or a label is a write whether or not it runs. port: fixed (security):
  q, Q, l and L take an optional number and the next command follows (sed 'q;w FILE'); a label of b, t, T or : ends at a blank, a
  semicolon or a brace (sed 'b end;w FILE', sed ':a;w FILE;ba'); and a block opened after an address ({ after /re/ or 1,3!) is a
  block, where it was read as an unknown command and made the whole script unreadable (sed -n '/a/{p;q}' x.txt was a write
  attempt, and is now an ordinary command). Rows CRW-941-E38 to E42, E45, C18; TestShellSedScriptWrites. The text of a, i and c and the
  file of r and R are read to the end of the line, as before; a continuation line of that text is read as a command, which can only
  refuse more.
- The file name of w, W and the w flag of s runs to the end of the line (GNU sed), so sed 'b end;w FILE;:end' names the file
  "FILE;:end"; the name is under the same directory as FILE and the gate judges it as it judges FILE. port: kept.
- /dev/stdout and /dev/stderr are no write destination, sort -o and sed w under the work tree or the trusted temporary root are
  allowed, and sed -n p, sed 's/a/b/', sed 's/w/x/', sed 'y/w/x/', sort x.txt and the common sed loops (:a;N;$!ba;s/\n/ /g) are
  allowed: the controls are rows CRW-941-11 to 16 and CRW-941-S28 to S36, E-controls C01 to C26.
- Benign accounting over the parent-filtered corpus (8020 commands) is unchanged by this change, command for command: memory allowed
  4518, named 458, asked a grant for 973, refused 2071; GitHub allowed 5177, denied 772, refused 2071; worktree allowed 5071,
  denied 878, refused 2071 (TestShellWriteBenignAccounting; the per-command report before and after is identical).
- Not read: a sed or sort written through a run-time program word (xargs sed, find -exec sort) names the unknown destination, as before;
  the oracle does not read these either.
