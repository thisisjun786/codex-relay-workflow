# CRW-1265 — a sandboxed Codex runs only in a dedicated root: never the account home, a directory above it, or a directory above a project root

Source: not an oracle behaviour. CXC v0.2.40 (commit 3c1459ac) starts no sandboxed Codex of its own and has no counterpart of the rule; the defect is the port's own product paths, found on 2026-10-11 when `/home/jun/.git` appeared and vanished 63 times in 140 seconds and an account-wide backup failed. The Codex linux sandbox (bubblewrap) makes and removes an empty `.git` mount target in a working root that has none (openai/codex PR #17734, issues #26463 and #37318). The Go files are `internal/sandboxroot` (the rule, `testdata/cases.json` the table the coordinator's Python guard runs too), `internal/crwconfig` (`paths.go` `sandbox_root`, `config.go` `sandbox.project_roots`), `internal/bridge` (`create.go`, `worktree.go`, `mutations.go`, `sandboxroot.go`), `internal/relay/adapter/transport.go` (`guardedSend`), `internal/manage` (`childresume.go`, `relay.go`), `internal/role/managed_spawn.go`, `internal/relay/service/launch.go`, `internal/runtime/install/unit.go` and `internal/dev/laneparity/realhost.go`.

- `create_thread` checked only that `cwd` was an absolute, existing directory, and no other product path judged where a sandboxed thread ran: a `workspace-write` or `read-only` thread could be created, resumed (bridge send, child-resume, relay delivery) or spawned (managed spawn) with the account home, a directory above it or a directory above other projects as its working root or writable root. Every such path now asks `sandboxroot.Check` (working root), `CheckWritable` (writable roots: the App Server `runtimeWorkspaceRoots`, the sandbox policy's `writableRoots`, `sandbox_workspace_write.writable_roots`) or `CheckDestination` (a worktree that does not exist yet) before the App Server or Codex is called; a refusal sends nothing and leaves no success record. port: fixed.
- A sandbox that is off (`danger-full-access`, `dangerFullAccess`, the bypass flag) is outside the rule and runs as before; a sandbox that cannot be determined counts as on, and `externalSandbox`, which creates no bubblewrap mount but is not named by the decision, counts as on too. port: kept (decision C names only the modes that create no sandbox).
- `CheckDestination` takes the sandbox as well as the destination (`CheckDestination(destination, sandbox)`; the issue text has one argument), because a worktree thread started with `danger-full-access` is outside the rule and its destination must not be refused. port: deviation from the issue's signature, same behaviour for a sandboxed run.
- A resume whose cwd cannot be determined (the host reported none and the request named none) has no working root to judge; its writable roots are still judged, and `thread/resume` reports the cwd it runs at. A real host always reports one. port: kept.
- A relay delivery, a bridge send and child-resume judge the cwd the resume will run at (the request's, else the one `thread/read` reports) under the sandbox the request states, else the host reported, else the recorded settings; a thread made in the account home before the rule existed is therefore not run again there (`sandbox_root_refused`, nothing sent, retry-safe in a relay delivery). The subscription-only resume (`HoldThread`: `threadId` and `excludeTurns` only) starts nothing and is not judged; `TestSubscriptionResumeSendsNoCwdSandboxOrTurn` pins its fields. port: fixed.
- A managed spawn's child works in the parent's cwd and the host sets its sandbox, which the dispatch record does not carry, so it counts as on: a parent session opened in the account home, above it, above a project root or outside every dedicated root cannot spawn a managed child, and the denial names the rule. port: fixed.
- The relay supervisor and worker (`Service.launch`), every relay command `crw manage` runs with an existing `--state` directory, and the systemd user unit that `register-service` writes (`WorkingDirectory=<state directory>`, which `register-service` makes) run in the relay's state directory instead of the directory they were started from; before, a relay started from a login shell or a user unit had the account home as its cwd. A unit written before this line existed is still recognised as the installer's own for `--remove`, but `register-service` on it answers `unit_differs` (it never overwrites a unit it did not just render): remove it and register again. port: fixed.
- `crw-dev parity realhost` runs `codex exec` with `sandbox_mode = "read-only"` in every cell; its scratch directory (default: the temporary directory) and each cell's work directory are now checked before Codex is started, so a scratch outside the sandbox base (`paths.sandbox_root`, default `/scratch/crw`) is refused and the run names `--scratch`. port: fixed (a behaviour change for a default `TMPDIR` of `/tmp`).
- Test fixtures that named a thread's cwd or roots by a path that does not exist (`/w`, `/parent`, `/workspace/example/...`) now name real directories of the test tree; the goldens keep their recorded names through substitutions (`internal/relay/adapter`). Each test package whose product code reaches the rule installs `sandboxroottest` in `TestMain`, with a fake account home, a fake Codex home and a fake crw configuration, so no test reads the real home, the real `~/.codex` or the real configuration. port: kept (test-only).
