# CRW-811 — orchestrate commit order and the goalplan-locked work-phase gate

Source: CXC v0.2.40 (`3c1459ac`) `plugins/codexclaw/components/pabcd-state/src/orchestrate-cli.ts`:
the three write paths of the transition half (:562-563 reset, :653-655 the I>P override, :1119 then
:1123 the ordinary edge), the work-phase binding gate (:612-622) and the D-close goalplan lock
(:754, :1038). Ported to Go as `internal/pabcd/cli/orchestrate_transition.go`, with
`internal/pabcd/cli/orchestrate_transition_commit_test.go` for this issue's cases.

- The transition-ledger row is appended after the session state is published, so a row write that fails
  leaves an advanced FSM whose transition nothing can replay, and no retry can back-fill it
  (source `:1119` then `:1123`; CRW-384 had moved the row first to close the opposite defect);
  port: kept (the issue's answer restores the oracle's order and answers the row failure with a
  warning on a success; the remaining gap is that a ledger row can be missing while the FSM advanced).
- The work-phase gate reads the goalplan without holding its write lock (source `:613` against
  `:1119`); port: fixed (the binding the state write lands under is revalidated inside
  `goalplan.WithGoalplanWriteLock`, and the state is published in the same lock; `orchestrateCommitPublish`
  and `TestOrchestrateCommitRevalidatesTheBinding`). The unlocked read stays in front of it for the
  oracle's refusal precedence and for the C>D arm the unported D close owns.
- The oracle publishes the state and then appends the row with no lock at all, so a concurrent writer's
  update is overwritten; port: fixed already by CRW-384 (`RunOrchestrateTransition` holds
  `state.WithSessionLock`), unchanged here.
- Supersedes `CRW-384.md`, item beginning "The ordinary edge publishes the session state before its
  transition-ledger row": now port: kept (CRW-384's row-first fix is reverted to the oracle's
  state-first order, per this issue's answer; the pre-publication failure is the case that now writes
  no row).
