# CRW-1361 — a rebound store seat stayed superseded, any management seat declared the store's capacity, another seat's lead registration was refused, and a restated report kept its first text

Source: CRW's own design (CRW-1314 design sections 1 and 2, the CRW-1333 follow-ups from its pre-merge verification), not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no management seat, no management edge and no report-up. The Go side is `internal/relay/registry` (`linkage.go` `applyBindingPlan`, `linkage_write.go` `managementEdgePlan`), `internal/relay/capacity/capacity.go` (`checkDeclarer`, `recordDeclarerWarning`), `internal/relay/cli/reportup.go` and `internal/relay/argparse/specs.json` (`linkage-bind --creator`).

- A thread that laid its store seat down for its management seat, handed the management seat over and bound the store seat again got its old row back as `active` with `superseded_by` still naming the management binding: the bind answered active, every reader of a live seat skipped the row, and `StoreScopeSupervisor` answered nobody, so the manager that took the seat over lost the store seat's authority too (a rare order, closed on the refusing side, recovered by binding again) (registry/linkage.go `applyBindingPlan` `reactivate`); port: fixed (a reactivated binding is live, so `superseded_by` is cleared with the status; `scope_rebound` is still written, and `StoreScopeSupervisor` answers the rebound store seat. Pinned by `TestStoreSeatRebindAfterTheManagementSeatsHandoverIsLive`).
- Any live management seat holder passed the store-scope declarer check, while `StoreScopeSupervisor` names one holder (the live store seat, or the management seat that took a laid-down store seat over), so N sessions could each state the store's ceiling (widening, fail-open, never a gate) (capacity/capacity.go `checkDeclarer`); port: fixed (the store scope has one declarer, the holder `StoreScopeSupervisor` answers; any other live management seat holder's `limit-declare` or `usage-observe` at the store scope is still written, because a declaration is reversible, and the answer warns under `declarerWarning` and a `store_scope_declarer_warned` journal row records it; a task with no live store or management seat is still refused `scope_role_mismatch`. Pinned by `TestStoreDeclarerIsTheStoreScopeSupervisorHolderAndOthersAreWarned`, with `TestManagementSeatLimitDeclareSucceeds` now binding the store seat its comment describes).
- A lead registration (or, since CRW-1314 D1c, a project owner binding) whose `--creator` holds a management seat other than the one whose edge already stands above the initiative or project was refused `link_conflict`, although the registration is reversible (registry/linkage_write.go `managementEdgePlan`); port: fixed (Sion's answer 10-14 to Jun's rule, reversible registration: warn and record. The binding is written or stands and the command exits 0, no second edge is written, the standing edge stays and the seat's handover is still the way to move it; the answer carries `managementLinkSkipped` and the journal one `management_link_skipped` row, the pattern D1c added for the legacy initiative edge. `duplicate_scope_owner` stays where it is the store's own invariant: a second owner at the same scope and role (`scope_bindings_one_live_owner`). `linkage-bind --creator` help says so. Pinned by `TestLeadRegistrationSecondManagementTakesOnlyByHandover` and `TestProjectOwnerBindingSecondManagementTakesOnlyByHandover`, both rewritten to the new outcome).
- `report-up` again with the same report id and a changed text left the `lead_report` row with the first text while the unsent message was rewritten with the new one (cli/reportup.go `record`); port: fixed (the row follows the message: while the message was never sent both say the new text and a `lead_report_restated` row records the change; once the message may have gone neither is changed and the answer warns that the sent text stands. Pinned by `TestReportUpRestatedUnderTheSameIDUpdatesTheRowAndTheUnsentMessage`).
- The six `flow_*` direct kinds still label their envelope `orchestrator_to_lead` with layer `lead`, while the two-layer design sends them to the management session (the parent in the new names) (supervisor/direct.go); port: kept (decided for this lane: the names are CRW-1352's, which applies Jun's section 18 names, top session, repository session as parent and project session as child, with the relay role ids unchanged).
- Supersedes CRW-1333.md, item beginning "Nothing recorded which management session a lead belongs to": the second session's registration is now warned and recorded rather than refused `link_conflict` (port: fixed, the item above).
- Supersedes CRW-1314.md, item beginning "Binding a project owner recorded nothing": the second session's binding is now warned and recorded rather than refused `link_conflict` (port: fixed, the item above).
