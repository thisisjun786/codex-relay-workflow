# CRW-1307 — PreToolUse guards warn and record; only irreversible actions stay blocked

Source: Jun's 10-13 rule, relayed by Sion with the confirmed guard table (Jun-delegated): no hard gate for a reversible action. The CXC oracle (v0.2.40, commit 3c1459ac) denies at every one of these refusals (goal-gate.ts, automation-ownership-gate.ts, worktree-guard.ts, memory-write-gate.ts, comment-lint, spawn-attach-hook.ts:1136-1150, cli.ts:76 for an input over the limit); the GitHub post and child push guards are CRW's own. The Go side is `internal/harness/guardmode.go` (the mode table `guardBlocks`, `SettleGuard`, `ReleaseGuard`, `RecordDecision`), `internal/harness/hook.go` (dispatch settles every pre-tool-use leg's answer; `InputRecord` replaces `InputDeny`), `cmd/crw/component_hooks.go` (the GitHub post, child push and attaching-skills rows settle their answers), and the rules the three split guards name: `internal/pabcd/hook/childpush.go` (`childPushDestroys`, `ChildPushDecision`), `githubpost.go` and `githubpost_judge.go` (`githubPostInlineSecret`, `GitHubPostDecision`), `worktreedel.go` and `worktreedel_judge.go` (`GuardVerdict.Rule`, `WorktreeGuardPreToolDecision`).

- The oracle denies every refusal of its PreToolUse guards (the goal gates, the interview in goal mode, automation ownership, the managed worktree deletion guard, the memory write gate, the apply_patch lint, the spawn attach hook's recursion, final gate, flow-bound and managed dispatch refusals); port: changed. A refusal passes with the refusal text as a warning in `hookSpecificOutput.additionalContext`, prefixed `[crw warning] Not blocked (recorded): ` (`[crw warning] Not blocked (no record written): ` when the record below was not written: a hook outside a plugin, an unwritable home), without a `permissionDecision` (the Codex host reports `permissionDecision:allow` without `updatedInput` as unsupported, so the answer carries context only and leaves the host's approval rules as they are), and a decision line is appended to `<CODEX_HOME>/crw/hook-decisions/<sha256 of the session id's JSON>.jsonl`: leg, rule, decision (`warn`, `block`, `release`), time, session and subagent, never the command text or a secret value. The rule a record names is the leg's (`interview-in-goal` for the goal-mode interview refusal), else the tag, code or cause at the head of the refusal (`final-gate`, `managed-dispatch` among them), else `refusal`. Pinned by `TestSettleGuardWarnsAndRecordsARefusalTheTableDoesNotKeep`, `TestGuardWarningSaysWhetherTheDecisionWasRecorded`, `TestRuleOfNamesTheRuleNeverTheCommand`, `TestCRW1307HarnessLegsWarnAndRecord` and the flipped leg tests listed in the handoff.
- The oracle denies a hook input it cannot read whole (`[crw] hook input could not be read; refusing to bypass policy enforcement`, the 4 MiB overflow, CRW-1101's `InputDeny`), the spawn attach hook denies an input over 4 MiB (now released, `TestSpawnLegReleasesAnOversizedInputWithARecord`), and CRW's GitHub post and child push guards deny an input over 1 MiB, a read error or a leg cancelled before it read its input; port: changed (fail-open with a record in every PreToolUse guard: the call passes with the warning that the guard did not check it and a `release` line, rule `unreadable-input`). `TestGuardInputFailuresDenyBeforeEffects`, `TestInputFailurePolicyMatchesLegSemantics`, `TestGitHubProtectionIngressFailuresDeny` and `TestChildPushGuardLegAnswersUnreadInput` keep their cases and assert the release.
- A command the shared reader (shellir) cannot read was refused by every guard that reads commands (CRW-1283's fail-closed rule); port: changed (it warns, also in the three split guards: an unreadable push of `dev`, an unreadable gh post, an unplaced worktree deletion pass with a warning and a record). Named limit: a force push of `dev` the reader cannot read, a secret in a body the guard cannot read, and a deletion of the checkout through a target the reader cannot place are not blocked.
- Kept at block (the table's three irreversible rules): a relay child's force (`-f`, `--force`, `--force-with-lease`, a `+` refspec), delete (`-d`, `--delete`, an empty source) or `--mirror` push onto `dev` or `main` (rule `shared-branch-history`, `TestCRW1307ChildForceDeleteMirrorOntoSharedBranchIsTheBlockRule`, `TestChildPushGuardLegReadsTheRelayStore`); a secret in GitHub post text (rule `secret-in-github-text`, `TestCRW1307SecretInAnInlineGitHubBodyIsTheBlockRule`); a deletion by `rm -r`, `git worktree remove`, `find -delete` or `-exec rm`, or `xargs rm` whose target resolves to the managed checkout, slot or an ancestor (rule `resolved-deletion`, `TestCRW1307ResolvedWorktreeDeletionIsTheBlockRule`, `TestCRW1307HarnessLegsWarnAndRecord`). The block answer is the deny it was, and a `block` line is recorded.
- An inline GitHub body, a body on standard input and a command of several posts were refused whole and never scanned for a secret; port: fixed (they warn now, so when the guard refuses a text with a rule that warns, it scans every gh execution of that text for the text it posts (`githubpost_carried.go`): the values of `--body`, `-b`, `--title`, `-t`, `--notes`, `-n`, `--subject`, `--comment` and, for `gh api`, `-f`, `--raw-field`, `-F`, `--field` values that are not `@file`; the files of `--body-file`, `-F`, `--notes-file`, `gh api --input` and `-F`/`--field name=@file`; a body on standard input that the command shows (a here-string, a here-document, a `<` file, the arguments and here-documents of the stages before it in its pipeline); and a body file the same text writes first by a redirection or `tee` from text it shows. A secret found there is the block rule. `TestCRW1307SecretCarriedAfterARefusalThatWarnsIsTheBlockRule`.) Named limit: a body file outside TMPDIR, /tmp and /var/tmp or one the guard cannot read, a body piped in from a program whose output the command does not show (`cat f |`, `curl |`), and a secret inside a script file run after a refusal that warns in the outer text (found only when that script is reached) are not scanned.
- The worktree deletion guard answered the first refusal of a text; port: changed (the text is judged to the end and a resolved deletion is the answer over an earlier rmdir, mv, inline program or unreadable refusal). It still does not look at whether the worktree holds unmerged work, so a clean worktree's deletion is blocked too (named limit of the table).
- The guard does not tell a new memory note from an overwrite or a deletion of an existing one; port: kept (all memory writes warn; the table puts the ambiguous case at warn). Deleting another task's heartbeat warns for the same reason.
- The spawn attach hook's refusal ledger entries (flow-bound `refused` decisions, a recursion grant kept for the retry) are written as before although the spawn now passes; port: kept (the decision record says it passed with a warning).
- The goal-budget leg refuses nothing it reads (CRW-1133); only its unreadable-input deny changes, to the release.
