# CRW-917 — GitHub post guard: the --input body is read as JSON; shell words, argv and named pipes

Source: Linear CRW-917 (the CRW-783 evaluation of PR #739 after its merge, score 3; the parent's reproduction in
/state/crw/p-crw-130/probe-739eval.log), and the pre-merge evaluation of head 3a4a172b (score 5; record
/state/crw/mgmt/pre-eval/crw917-3a4a172b.json). The guard is CRW's own protection (CRW-783), so there is no CXC oracle. The Go files are
internal/pabcd/hook/githubpost.go (the form checks and the --input body), internal/pabcd/hook/githubpost_judge.go (the judge over
the shared reader), internal/pabcd/hook/githubpost_scan.go (the secret patterns), cmd/crw/component_hooks.go (the cancelled answer)
and the shared command reader internal/pabcd/shellir. The reproductions are rows CRW-917-01 to 11 (internal/pabcd/hook/testdata/
shellir/rows/04-crw-875-917-984.txt), CRW-917-41-01 to 12 (rows/41-crw-917.txt) and CRW-917-42-01 to 09 (rows/42-crw-917-round2.txt),
indexed in reproductions.tsv. The tests are TestCRW917InputIsJSONOrRefused, TestCRW917ShellWordsAreNormalised,
TestCRW917ArgvWordsAreNotSplitAgain and TestCRW917FIFOBodyIsRefusedWithoutBlocking (githubpost_crw917_test.go), and
TestCRW917DuplicateJSONKeysAreAllScanned, TestCRW917BodyFilesAreScannedAsText and TestCRW917InterpreterProgramIsCanonical
(githubpost_words_test.go). The red output on the base 7839042f6 is /state/crw/crw-917/evidence/red-1-before-fix-base-7839042f6.log
and red-2-rows-on-base-7839042f6.log; the red output of round 2 on 3a4a172b is /state/crw/crw-917/evidence/round2/red-1-round2-on-3a4a172b.log,
and the NAME=value red output is /state/crw/crw-917/evidence/round2/red-2-round2-nameval-on-8ddf344b.log.

- A gh api --input body that is not one JSON document (plain text, an unclosed object, or text after the document) was scanned
  as raw text and allowed when clean, so a body the guard could not read was posted unchecked. The body is the request JSON, so
  the guard now refuses such a body as unreadable (unreadable-github-post, at the file). --body-file and -F body=@file still read
  the file as text. Rows CRW-917-41-01 to 03; the two expectations in githubpost_test.go that allowed a non-JSON --input now
  expect the refusal. port: fixed (security).
- Quoted options ('--body', '--body-file' with a value), a quoted program name (g""h), a redirect glued to the subcommand
  (gh pr</dev/null comment), an expansion in a body file name, a secret in a quoted title, and a secret spelled with a unicode
  escape in a JSON key were judged wrongly at the PR #739 merge; the base commit reads them the way the shell does, after the
  command reader redesign (CRW-1028). Pinned by rows CRW-917-01 to 11 and 41-04 and 41-08 to 11, and TestCRW917ShellWordsAreNormalised.
  port: fixed (CRW-1028 on dev; this change pins them).
- A whitespace-split reader refused git checkout -b topic (the substring -b) and split an argv word such as "Plain title" again.
  The guard reads no text by splitting on whitespace now, and an argv array is one word per element. Rows CRW-917-06 (of 04-crw-875-917-984.txt)
  and 41-12; TestCRW917ArgvWordsAreNotSplitAgain. port: fixed (CRW-1028 on dev; pinned here).
- A body file given as a named pipe made the hook block until a writer opened it, and a cancelled hook wrote no answer. The file is
  opened without blocking and its descriptor is checked before it is read, and a cancelled guard answers deny
  (GitHubPostCancelledAnswer). Row CRW-917-41-07; TestCRW917FIFOBodyIsRefusedWithoutBlocking. port: fixed (in dev before this change).
- The header of githubpost.go described a second, whitespace-based reading of the text that no longer exists; the header now
  describes the one reader. port: fixed (comment only).
- A gh api --input body with a key that repeats kept only the last value for the secret scan, so an earlier value holding a secret
  was allowed although the request carries every value. The scan reads every key and every value, repeated keys included. Rows
  CRW-917-42-01 and 42-02; TestCRW917DuplicateJSONKeysAreAllScanned. port: fixed (CRW-917 round 2).
- --body-file and -F body=@file decoded a JSON-looking file before the secret scan, so clean text whose escape sequence spelled a
  secret was refused, although gh posts the raw bytes. The raw bytes are scanned now, with the secret patterns and the NAME=value
  rule; for a JSON document the strings are also split out of the raw text, so a NAME=value inside a string is caught as the decoded
  scan caught it. Rows CRW-917-42-03 to 05, 42-08 and 42-09; TestCRW917BodyFilesAreScannedAsText. port: fixed (CRW-917 round 2).
- An interpreter's program text (python3 -c and the like) was checked for a gh post by its raw text, so a name built from empty quote
  pieces inside the program (g""h pr comment) passed. The program is judged with quotes and backslashes removed, as the shell reads
  its words. Rows CRW-917-42-06 and 42-07; TestCRW917InterpreterProgramIsCanonical. port: fixed (CRW-917 round 2).
- A cancelled GitHub post guard answered the deny "cancelled at the hook" and exited 130. It answers the deny of an unreadable
  command (unreadable-github-post at command) and exits 0, as an ordinary deny does; TestGitHubPostGuardLegAnswersDenyWhenCancelled
  and TestGitHubPostCancelledAnswerDenies check both. port: fixed (CRW-917 round 2).
- Supersedes CRW-1028.md, the item beginning "When the GitHub post guard is cancelled": now port: fixed (CRW-917 S7 asks the deny
  of an unreadable command and an exit of 0, as an ordinary deny does; the interrupted status of CRW-1028 evaluation defect d17 is replaced).
