# CRW-1377 — follow-ups of CRW-1359 and CRW-1360: one CODEX_HOME rule for the hook, the launcher, register-mcp and doctor, the quoted digest override, the flow show policy phrases

Source: CRW's own wiring; the CXC oracle (v0.2.40, commit 3c1459ac) trims `CODEX_HOME` in `resolveCodexHome`, which `internal/runtime/install/features.go` ports. The Go files are `internal/pluginwiring/codexhome.go` (`CodexHomeNamed`, new), `internal/pluginwiring/launch.go` (`codexHome`), `internal/affordance/policy_warning.go` (`codexHomeOf`, the `CODEX_THREAD_BRIDGE_EXECUTION_POLICY_DIGEST` warning), `internal/runtime/install/cli.go` (`options`, which register-mcp and the other install commands take), `internal/runtime/install/features.go` (`resolveFeatureHome`) and `internal/runtime/doctor/doctor.go` (`CodexHomeOf`); the docs are `docs/runtime-install.md` and `docs/role-execution-policy.md`. No record shape, relay schema or host setting changes.

- The `SessionStart` policy warning trimmed `CODEX_HOME` with its own copy of the rule (`affordance.codexHomeOf`), while the bridge launcher (`pluginwiring.codexHome`), `crw install register-mcp` (`options`, which read a padded value as a relative path under the working directory) and `doctor.CodexHomeOf` used it as given, so a padded `CODEX_HOME` made the hook and the launcher read different record directories (CRW-1359 evaluation d1 and carried c6; CRW-1360.md, the d3 bullet); port: fixed (one helper, `pluginwiring.CodexHomeNamed`: the value trimmed of the whitespace around it with `text.Trim`, the set the hook and the installer's features command already used; a blank value names no home and each caller keeps its own default. The hook, the launcher, `options` (register-mcp and every install command that takes it), `resolveFeatureHome` and `doctor.CodexHomeOf` call it. Pinned by `TestCRW1377TheLauncherTrimsCodexHome`, `TestCRW1377TheHookTrimsCodexHomeAsTheLauncherDoes`, `TestCRW1377RegisterMCPTrimsCodexHome` and `TestCRW1377DoctorTrimsCodexHome`, each with the same padded value ` \t/crw1377/codex-home \n` and the same expected directory `/crw1377/codex-home`, and the blank case where they have one).
- The issue names "the mirror in `crw_bridge_mcp.py`" of the launcher's rule. That Python launcher is no longer in the repository (the package has shipped `plugins/crw/wiring/crw-bridge.sh`, which runs the Go bridge with `--plugin-launch`, since todo 43); `pluginwiring.codexHome` is the port of its `codex_home()` and is the one place the launcher reads `CODEX_HOME`, so there is no second copy to change or to test; port: kept (nothing to change).
- The `SessionStart` warning printed the value of a `CODEX_THREAD_BRIDGE_EXECUTION_POLICY_DIGEST` override unquoted (`policy_warning.go`, the digest branch; CRW-1359 evaluation d2), where the path override is quoted; port: fixed (the value goes through `quote.Shell`. Pinned by `TestCRW1377TheDigestOverrideIsShellQuoted`).
- `docs/role-execution-policy.md` ("One role snapshot per run") named only `policy none` and not the phrases `crw flow show` prints for a run whose start predates the journaled policy file, nor that a later start clears `repinned from` (CRW-1359 evaluation d3); port: fixed (the section names `policy file not recorded  digest <digest>`, `policy not recorded`, and that a later start clears `repinned from`, as `internal/flow/cli/read_cmds.go` and `recordedPolicy` do; documentation only, pinned by the unchanged `TestShowClearsRepinnedFromOnALaterUnchangedStart`).
- Named limit. Other readers of `CODEX_HOME` outside these four (the relay hook settings, the recall paths, the sandbox root, the policy store, the hook switch, the worktree and automation gates) keep their own reading; the issue names these four, and none of the others writes or reads the bridge record or the hook's policy warning; port: kept.
