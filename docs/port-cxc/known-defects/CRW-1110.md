# CRW-1110 — the 65th unresolved verdict of a session

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/subagent-evidence.ts:254-296` (recordTombstone) and `:284`, with `reconstructUnverified` in `plugins/codexclaw/components/pabcd-state/src/state.ts:72`. The Go side is `internal/pabcd/evidence/overflow.go` (the overflow records, `RecoverOverflow`, `publishable`), `tombstone.go` (`recordTombstone`, `HasTombstone`), `budget.go` (`resolveTombstone`), `internal/pabcd/cli/evidence.go` (resolve) and `internal/pabcd/hook/goalgate_complete.go` (the completion gate). Found by the 10-10 CXC improvement review A3-05.

- Supersedes known-defects.md, section "Found by the subagent evidence attempts port", item beginning "`recordTombstone` appends without checking the 64-entry cap": now port: fixed (the main list never grows past the cap the reader keeps, and a list is published only after it is shown to read back whole. A verdict that does not fit is recorded beside it, in `.crw/evidence-overflow/<session>-<digest>/<tuple digest>.json`, one record per exact agent and turn repeating its session; `HasTombstone`, the child's late receipt, `crw pabcd evidence resolve` and the goal-complete gate all find it there by the exact session, agent and turn, and an overflow directory that cannot be read denies completion like an unreadable list. A late receipt of the 65th child resolves that verdict only and the other 64 keep denying completion. A file written before the fix with more than 64 records is recovered under the session lock by the next tombstone, resolve or `crw pabcd evidence resolve`: every stored record is checked first (`state.RewriteKeepsStored` over the whole list), then the records past the cap are written beside the main list and the main list is rewritten with the first 64; the corruption flag the file stores is kept and only the overflow's own flag goes; a file with a record the reader would change is left byte for byte and still denied. Pinned by `TestSubagentStopOverflowVerdictIsKeptBesideTheCap`, `TestSubagentStopOverflowRecoversA65File` (with two verdicts arriving at once during the recovery), `TestRewriteGuardKeepsThe65thVerdictWhenThe66thArrives`, `TestRewriteGuardRecoversA65RecordFile`, the `record_65th_when_64_exist` override of `TestTombstone`, the 66-record overrides of `TestResolveTombstone` and the `evidence/overflow` case of `TestCLIDataLossPreservesVerdictBytes`).
- `crw pabcd memory allow-write` still refuses a session file whose list is past the cap instead of recovering it (`cliVerdictsIntact`); port: kept. It writes no verdict, and the next tombstone or resolve recovers the file.
- `crw pabcd evidence resolve` without `--turn` counts the agent's resolvable verdicts across the main list and the ones recorded beside it, under the session lock, and resolves only when there is exactly one; port: fixed (the oracle's list has no second place). Two verdicts of one agent in different turns, one in each place, are ambiguous and resolve neither. The request the caller made is kept apart from the turn whose lock it holds: a request without `--turn` reads its one match without a lock only to know which tuple lock to take, and under the locks it counts every turn's verdicts again, so a verdict of another turn recorded while it waited for the lock makes it ambiguous rather than resolving the turn of the first read; one match whose turn is not the locked one (a writer raced the unlocked read) only names the turn and runs again with that tuple's lock held. Pinned by `TestEvidenceCLIAmbiguityAcrossMainAndOverflow` and `TestEvidenceCLIImplicitTurnRechecksAmbiguityUnderTheLock`.
- The records that move beside the main list are durable before the main list shrinks; port: fixed. A record is written through a temp file whose data is fsynced, renamed, and its directory fsynced, and the directories on the way to it (the session's overflow directory, `.crw/evidence-overflow`, `.crw` and the workspace) are fsynced too; a failure of any of these steps is returned, and `RecoverOverflow` then leaves the main list as it is, because the overflow copies are the only copies of the verdicts past the cap once it is rewritten. Pinned by `TestRecoverOverflowSyncsTheOverflowBeforeTheMainListShrinks`, `TestRecoverOverflowKeepsTheMainListWhenTheOverflowCannotBeSynced` and `TestRecordTombstoneBesideTheCapIsSynced`.
- `crw pabcd evidence resolve` without `--turn` resolves nothing when the records beside the list cannot be read completely (a directory it cannot list, an entry that is not one of its records): the request is a request for the agent's one verdict, and that cannot be shown when the other place is unreadable; port: fixed. Naming the turn needs no uniqueness and still resolves. The main list is read as before. Pinned by `TestEvidenceCLIImplicitResolveRefusesWhenTheOverflowCannotBeRead`.
