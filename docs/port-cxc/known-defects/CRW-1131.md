# CRW-1131 — recall memory requeue, CLI and recall hook wording residue

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/recall/src/`: `memory-requeue.ts`, `cli.ts`, `hook.ts` and `cwd-context.ts`. The Go side is `internal/recall/memoryrequeue.go`, `sqlite.go` (`openDbReadWriteExisting`), `cli.go`, `hook.go` and `hookcontext.go`. The items are the 10-10 CXC improvement review's fix-now list for the requeue, CLI and hook lines of known-defects.md (A8 kept); each was reproduced before it was changed (the red output is in the lane's evidence directory, `red-1131.txt`). The recorded CLI and hook cases whose answer the port changed are listed in the port-fixed files beside the grids, and the recorded fixtures of `contract/fixtures/cxc` that print the changed text are claimed in `contract/notes/cxc/CRW-1131.json`.

- Supersedes known-defects.md, section "CRW-352 memory requeue", item beginning "A positive retry allowance below one": now port: fixed (a positive `retries` below one is refused (`--retries 0.5 must be a whole number of at least 1`, state unavailable) and nothing is written, so the backoff is no longer cleared without eligibility. A value that is not positive keeps the default of three, as recorded. `RequeueExhaustedMemoryJobs`; pinned by `TestSweep1131FractionalRetriesAreRefused`).
- Supersedes known-defects.md, section "CRW-352 memory requeue", item beginning "The schema guard omits `retry_at`": now port: fixed (the guard names every column the write matches or sets, `retry_at` included, for the dry run as for the apply: the store is unsupported with `jobs table is missing column(s): retry_at` and is not written. `readMemoryRequeue`; pinned by `TestSweep1131SchemaGuardNamesEveryColumnTheWriteNeeds`).
- Supersedes known-defects.md, section "CRW-352 memory requeue", item beginning "NULL, numeric and BLOB kind/key values": now port: fixed (a row whose kind or key is not stored as text is not selected and not coerced; it is counted as left alone under `untyped-key` and the report says it cannot be addressed. `typeof` is read with the row; pinned by `TestSweep1131UntypedKeysAreNotCoerced`).
- Supersedes known-defects.md, section "CRW-352 memory requeue", item beginning "With no kind filter, exhausted consolidation jobs": now port: fixed (without `--kind`, a job whose kind is a consolidation kind is left alone, counted under `consolidation`, and the report says `--kind` must name it; naming the kind selects it as before. `requeueIsConsolidation`; pinned by `TestSweep1131ConsolidationNeedsAnExplicitKind`).
- Supersedes known-defects.md, section "CRW-352 memory requeue", item beginning "A failed BEGIN reports": now port: fixed (a BEGIN that did not succeed is reported as `requeue did not start and nothing was changed`; only a failure after BEGIN is rolled back and says so, and a rollback that itself failed is named. `writeMemoryRequeue` returns whether the transaction began; pinned by `TestSweep1131FailedBeginIsNotARollback` and the lock test of `TestMemoryRequeueLockedTransaction`).
- Supersedes known-defects.md, section "CRW-352 memory requeue", item beginning "Reopening for apply": now port: fixed (the write opens the store without CREATE and selects the rows again on the connection it writes through: `BEGIN IMMEDIATE` takes the write lock and the rows to give retries to are selected inside that transaction, so what is written was read from the file the writing connection has open, whatever the store name pointed to at the dry run's read-only selection (a symlink retargeted to another store and back included). A removed store is reported and not created again; a store put in its place is the store the name now has and is written only for its own rows. No file identity is compared, so nothing can pass such a comparison while the connection is on another file. `openDbReadWriteExisting`, `applyMemoryRequeue`; pinned by `TestSweep1131ApplyNeverCreatesOrSwitchesTheStore` and `TestSweep1131RetargetedStoreNameNeverMixesSelectionAndWrite`).
- Supersedes known-defects.md, section "CRW-352 memory requeue", item beginning "Duplicate kind/key rows": now port: fixed (the selection carries each row's rowid, read as text and bound back as a 64-bit integer so that a rowid past 2^53 stays exact end to end, and under the first of the names `rowid`, `_rowid_` and `oid` that no column of the table shadows (a declared column of that name hides the rowid and need not be unique), and the write updates that row by the same name, so rows that share a kind and key are written one by one and `changed` is the number of rows the database changed; with a fraction refused as above, the same rows are not counted again. A table without rowids, or one whose every rowid name is a column, is written by its primary key columns (read as text with its type and bound back as text or as a 64-bit integer, so an integer key past 2^53 is read and written exactly; a key value that is not text or an integer is left alone as an untyped key), so a limit of one changes one of two rows that share a kind and key; a table with neither a rowid it does not shadow nor a primary key, which has nothing to name a row by, is not written and the apply says so; no row is ever written by its kind and key alone. `readMemoryRequeue`, `writeMemoryRequeue`, `applyMemoryRequeue`. Pinned by `TestSweep1131DuplicateRowsAreWrittenByIdentity` (a limit of one on a rowid table) `TestSweep1131WithoutRowidTableIsWrittenByItsPrimaryKey` and `TestSweep1131ShadowedRowidIsNotTheRowIdentity`; the exactness of a rowid and of an integer key past 2^53 by `TestSweep1131LargeIntegerRowIdentitiesAreExact`).
- Supersedes known-defects.md, section "Found by the CRW-391 recall CLI port", item beginning "Unknown recall verbs print usage and exit 0": now port: fixed for the unknown verb (a command the CLI does not have prints `unknown recall command: ...` on stderr and exits 1; the empty command, `help`, `/?` and `--help` still print the usage and exit 0. The empty search query keeps its recorded usage on stdout and exit 1. `Run`; pinned by `TestSweep1131UnknownVerbIsAnError`).
- Supersedes known-defects.md, section "Found by the CRW-391 recall CLI port", item beginning "Memory status and requeue ignore unknown flags": now port: fixed (the two verbs read their flags with a parser of their own: only the flags the verb has, a value for every flag that takes one (a missing value, or a dash-leading word where a value belongs, is the strict parser's `argument missing` or `ambiguous` message), no value on a boolean, no bare word and nothing after `--`. `recallCLIParseStrict`; pinned by `TestSweep1131ManagementVerbsReadFlagsStrictly`).
- Supersedes known-defects.md, section "Found by the CRW-391 recall CLI port", item beginning "`chat index --status --rebuild` writes": now port: fixed (the two flags together are refused with `--status and --rebuild conflict`, before the index is opened; `--status` alone and `--rebuild` alone are as before. `recallCLIChatIndex`; pinned by `TestSweep1131StatusWithRebuildWritesNothing`).
- Supersedes known-defects.md, section "Found by the CRW-391 recall CLI port", item beginning "Requeue accepts a decimal integer prefix": now port: fixed (`--limit` and `--retries` are read whole: digits only, at least one, no fraction, exponent, hex or trailing word; `2tail`, `1.5`, `0x10` and `0` are refused with a message that names the flag and the value. `recallCLIPositiveInt`; pinned by `TestSweep1131CountFlagsAreWholePositiveIntegers`).
- Supersedes known-defects.md, section "CRW-388 — recall hooks", item beginning "The recovery pointer is sliced at 160 UTF-16 units": now port: fixed (the line is chosen from complete candidates, the fullest that fits the 160 units: with the description, with a shorter separator, as the two commands alone, and as the memory search command alone, which is given whole even when it alone is over the budget; a command is never cut inside a path. `recallHookRecoveryLine`; pinned by `TestSweep1131RecoveryPointerKeepsItsCommands`).
- Supersedes known-defects.md, section "CRW-388 — recall hooks", item beginning "Version target extraction matches date and IP address fragments": now port: fixed (a dotted number is a version target only when its context names a version: a version word (`version`, `v`, `release`, `tag`, `버전`, `릴리스`) or `@` right before it, which wins over everything below; a version word right after it (`2026.10 릴리스`); the three-part form of a version (`2.49.0`); or a package name right before it (`Python 3.12`, `node 20.11`), a word of ASCII letters that is not one of a few prose words (`is`, `and`, `then`, `date`, ...). A date (`2026.10.04`, `04.10.2026`) and a piece of a longer dotted number (the `1.2.3` of `1.2.3.4`, an address) are never one without a version word before them, and a bare decimal or an abbreviated date (`원주율 3.14`, `날짜 2026.10`) is not one. `recallHookIsVersion`; pinned by `TestSweep1131DatesAndAddressesAreNoVersions` and the `extract` cases 138 to 140 of `testdata/hook/port-fixed.json` (`2.1 2.2 2.3 2.4 2.5 2.6` gives no target); the upstream fixture's cap check uses three-part versions).
- Supersedes known-defects.md, section "CRW-388 — recall hooks", item beginning "The unavailable-project diagnostic hardcodes the bare command": now port: fixed (the diagnostic names the invocation the hook resolved, `Run \`<invocation> recall chat index --status\``; the bare name only when none was resolved. `HandleSessionStart`; pinned by `TestSweep1131UnavailableAdviceUsesTheResolvedInvocation` and `TestRecallHookUnavailableAdviceParity`).
- Supersedes known-defects.md, section "CRW-388 — recall hooks", item beginning "The cwd basename is interpolated into the header": now port: fixed (the header reads `[crw-recall] Recent work in this project:` and the directory name stands inside the untrusted block as `Project: "<name>"`: line breaks and control characters become spaces, runs of spaces one, at most 80 characters, JSON-quoted, so a directory name cannot make a line of the prompt. `renderCwdBlock`, `hookContextLabel`; pinned by `TestSweep1131DirectoryNameIsQuotedDataInsideTheBlock`).
