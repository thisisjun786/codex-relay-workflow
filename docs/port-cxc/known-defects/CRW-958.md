# CRW-958 — per-use storage roots, tool environment and the storage check

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, names no storage roots; the pointer is the port). The Go side is `internal/crwconfig` (`paths.go` the roots, `toolenv.go` the tool environment, `check.go` and `fs_*.go` the check behind `crw config check`), with the consumers `internal/dev/ci/local.go`, `internal/dev/ci/validate.go`, `internal/skill/merge_build_check_go.go`, `internal/manage/config.go`, `internal/manage/pump.go` and `internal/manage/audit_package.go`. These are the places the issue's text and the coordinator's triage differ from what this change does.

- The triage proposed `manage_state` as the durable-state bundle root that owns the relay store, its WAL and its sidecars. The current canon and code keep the management tool's state and the relay's state apart (`internal/manage/config.go` `StateDir`, `internal/relay/store/state.go` `DiscoverStateDir`), so `manage_state` is unchanged and a new root, `relay_state`, is the relay's durable state: the parent of the per-scope store directories, each one bundle; port: kept (a deviation from the triage, decided by the verifier's correction). Its precedence is `--state`, `CODEX_SESSION_RELAY_STATE`, `manage.relay.state`, the scope directory below a configured `relay_state`, then the relay's discovery; the management tool derives the scope directory from the socket with `store.SocketScope`. A relay started outside the management tool keeps its own discovery, and a store already recorded for the socket under another scope directory is not adopted when `relay_state` is configured; `crw config check` reports that placement as drift.
- The store, its WAL and its sidecars are one bundle: a `paths.relay_store`, `relay_db`, `relay_wal`, `relay_sidecar` or `relay_sidecars` key is refused (`state_split`), and so is a store whose WAL or sidecar is a link into another directory. The relay's own `daemon.log` and `control.sock` stay in the store directory with the rest of the bundle, so `log_root` moves the management tool's pump log (`internal/manage/pump.go`), not the relay's daemon log; port: kept (moving `daemon.log` apart would split the bundle the issue says is handled only together).
- The triage's evidence that `merge_build_check_go.go` makes `GOCACHE`, `GOMODCACHE` and `GOPATH` owned directories was wrong: the owned parts are the temporary directory and telemetry, and the caches are the caller's. The helper keeps the `HOME`, `GOENV`, `GOWORK`, telemetry and owned `TMPDIR`/`GOTMPDIR` isolation, names a configured `build_cache` and `module_cache` after everything else, and under a configured `build_work` makes its owned directory a `merge-build-go-*` subdirectory that it removes itself; port: kept.
- The sealed local CI run (`internal/dev/ci/local.go`) takes `build_cache` and `build_work` from the configuration and does not take `module_cache`: a module tree is trusted from a cache without the go.sum check, so the module cache is not part of what a sealed run may read (`TestLocal_a_step_never_sees_the_callers_module_cache`); port: kept.
- The socket path check counts the bytes of the whole path, suffix included (`<root>/<16 hex scope>/control.sock`), not the root's length. It is an error only for `relay_state`, whose suffix is known; `temp_root` and `scratch_root` hold the sockets of tests whose names are not known here, so a root with no room for the store-socket suffix is a warning there; port: kept.
- v2 flow nodes (F04) keep their per-call working directory under the durable flow state, which F05 uses as a persistent thread's identity; this change does not move it to a disposable temporary root and adds no sentence that does. The tree this change is made on carries no flow engine, so there is no call site to wire; port: pending (the flow engine's lane takes `crwconfig.ToolRoots` and `temp_root` for its tool starts and states the durable call directory's lifetime and recovery).
- The packet text of `plugins/crw/skills/crw-run/references/task-packet.md` already names `temp_root` and `scratch_root` and a short whole socket path; the `/var/tmp/crw-<n>` example in the triage is not in the current text. `internal/dev/cxcfuzz` built a host path (`/scratch/crw/fuzz`) into its default output root; port: fixed (it is `fuzz` below the resolved `scratch_root`, and `TestNoHostPathOrDeviceNameInProduct` fails on any such path in product code, skills and packet templates). The recorded-oracle checkout `/var/tmp/cxc-v0.2.40/...` in `internal/dev/cxcfuzz/echo.go` is the one remaining host-bound default and is left to the CXC port's own record; port: pending.
