# CRW-1387 — the lineage fallback's first-line read is bounded, and an unreadable lineage is recorded once per session

Source: CRW's own guard, no CXC oracle (the fallback is [CRW-1370](CRW-1370.md), the warn-and-record modes [CRW-1307](CRW-1307.md)); Go files `internal/relay/hook/childlineage.go` (`rolloutParent`), `internal/harness/guardmode.go` (`SettleGuardOnce`, beside `SettleGuard` and `RecordDecision`), `cmd/crw/component_hooks.go` (the declared leg `pre-tool-use-guarding-child-push`). No relay schema, decision record shape, delivery state, host setting or trust key changes; no leg is added.

- `rolloutParent` read the first line of a rollout with `bufio.Reader.ReadBytes('\n')` and compared it with `lineageMetaLimit` (8 MiB) only after reading it whole, so a `transcript_path` whose first line has no newline was read into memory entire (`childlineage.go`, `rolloutParent`); port: fixed (the line is read through `io.LimitReader(f, lineageMetaLimit+1)`: a first line over the limit stops one byte past it and is an unreadable lineage, `the first line of the rollout is too long`, which the guard warns about and records, fail-open). This is also item 4 of CRW-1395.
- Supersedes CRW-1370.md, item beginning "Named limits.", its point (3) ("A sub-agent of a non-child parent whose transcript cannot be read now leaves a `warn` record on each push ..."): now port: fixed (the warn record of an unreadable lineage is left once per session id: the first such push claims the marker `<sha256 of the session's JSON>.pre-tool-use-guarding-child-push.unreadable-lineage.once` in `<CODEX_HOME>/crw/hook-decisions`, created with `O_EXCL`, and records the decision as before; a later push of the same session id passes with the same warning, which says the first one was recorded and this one leaves no record. A marker that cannot be made records as before. A relay record that cannot be read, the CRW-1303 case, still warns and records on every push. The only refusal of the guard stays the force, delete or `--mirror` push onto `dev` or `main` by a session the store knows as a child, `shared-branch-history`.)
- Named limits. (1) The marker is per session id and per warning kind, not per sub-agent: a second sub-agent of the same session with an unreadable lineage leaves no second record. (2) The marker is never removed, as the session's decision records are not; a session whose lineage becomes readable is judged again from its next push, and a later unreadable push of it leaves no record. (3) A session's warning still appears on every such push; only the record is once.

Pinned by `TestRolloutParentReadsAtMostTheLimitOfAFirstLineWithoutANewline` (`internal/relay/hook`: a file whose first line is over the limit with no newline is an unreadable lineage, and of a first line three times the limit at most `lineageMetaLimit+1` bytes are read) and `TestCRW1387AnUnreadableLineageLeavesOneWarnRecordPerSession` (`cmd/crw`: three pushes of one session leave one record, every push warns and passes, a second session id leaves its own one record). `TestCRW1370AnUnreadableLineageFailsOpenWithARecord` now wants one record for a session's two pushes; `TestCRW1303UnjudgeableLineageFailsOpenWithARecord` (four records for four pushes while the relay record is unreadable) is unchanged and passes.
