# CRW-1059 — sequential executions inside bash -c and a command substitution see later scripts' writes

Source: the independent check of CRW-1028 (10-09), which recorded the over-block as the follow-up of its item "Sequential executions inside a carried text and a command substitution see the writes of later scripts" (docs/port-cxc/known-defects/CRW-1028.md). The defect is the port's own: a rule for the order of writes that the top-level text already follows was not applied to a text that a shell runs with -c, nor to a command substitution. The Go files are internal/pabcd/hook/githubpost_judge.go (githubPostInOrder, githubPostWritesOf, which the GitHub post guard and the worktree deletion guard both use), internal/pabcd/shellir/shellir.go (Context.Repeat, set in carried and wrapped) and internal/pabcd/shellir/policy.go (isOnceCarrier).

- Inside bash -c '...' and inside a command substitution, every script body's writes reached every script there, so a script that ran before a rewriting script was judged as already rewritten. bash -c 'bash lint.sh; bash refresh.sh' and x=$(bash lint.sh; bash refresh.sh) were refused, though the rewrite happens only after lint.sh ran; port: fixed (a shell's -c string and a command substitution run once where the text puts them, so their executions follow the top-level order. A carrier that may run its text again or alongside the rest (xargs, find, parallel, entr, watch, trap, eval, a shell reading stdin, script -c, flock -c), a loop, a pipe, a background job, a process substitution and a function body keep the unordered rule, so the rewrite still reaches every execution there). Cases: rows CRW-1059-01 to -04 (the allowed sequential forms) and CRW-1059-05 to -10 (the refused forms: the rewrite before the rewritten script, a loop, a pipe, a background job, a function body, and a rerun of the rewritten script); the same over-block in CRW-1028 ev-overblock-02 and -03 now allows, and its deviation marks are removed.
- Supersedes known-defects/CRW-1028.md, the item beginning "Sequential executions inside a carried text and a command substitution see the writes of later scripts": now port: fixed (the bash -c and command substitution cases above; the carriers listed as kept below stay as they were).
- Residual: eval, script -c, flock -c and the other carriers that run their text once still use the unordered rule, so a sequential command inside them can still be refused; port: kept (the issue scopes the fix to bash -c and command substitutions; these carriers keep refusing, which fails closed).
- After the pre-merge evaluation of 0ef1b43d (findings d1 to d3): a simple command with two or more command substitutions, in its assignments, words or redirections, leaves them unordered, because bash expands the argument substitutions before the assignment ones; watch repeats its text with or without -x, so it is a repeating carrier in both forms; the substitutions of an arithmetic for header run again with the loop, so they are walked as a loop body. Rows CRW-1059-11 to -20 (rows/45-crw-1059-evaluation-0ef1b43d.txt) cover them. port: fixed (the three cases above). Residual: a simple command with two or more substitutions is still refused where bash would run them in order, for example printf "$(bash lint.sh)" "$(bash refresh.sh)"; port: kept (it fails closed, the same as before this change, and the reader does not model the expansion order of each word kind).
