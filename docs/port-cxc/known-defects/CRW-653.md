# CRW-653 — the dispatch CLI's read-only App Server host

Source: no CXC v0.2.40 (commit 3c1459ac) behaviour is recorded here. The oracle's dispatch path is
`plugins/codexclaw/components/subagent-config/src/fallback-dispatch-cli.ts`, which has no App Server
host and never read a child's turn; the host is a CRW addition
(`internal/role/created_check.go`, `createdCheckRead` and `createdCheckStop`, and the new
`internal/role/dispatch_host.go`). Everything below was introduced by the port.

- The dispatch CLI passes one host to `CheckedDispatch`, and `createdCheckRead` consults a host
  before the native thread database, so connecting the host also moves the created report from the
  native database to the App Server. When the App Server is reachable but answers `thread/read` for
  the child with an error or an unusable answer, a created report the native database would have
  accepted is refused with "host could not verify created agent"; the reverse (a native row that the
  App Server would not confirm) changes the same way. This issue's criteria cover the stopped close
  only, and the parent's answer passes one host to the whole command, so the created path is left as
  it is (`internal/role/dispatch_cmd.go`, the `dispatchHostOpen` call; `internal/role/created_check.go`,
  `createdCheckRead`); port: pending (a later issue decides whether the created report keeps reading
  the native database, or the host is scoped to the stopped close).
