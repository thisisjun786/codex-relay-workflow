# CRW-653 — the dispatch CLI's read-only App Server host

Source: no CXC v0.2.40 (commit 3c1459ac) behaviour is recorded here. The oracle's dispatch path is
`plugins/codexclaw/components/subagent-config/src/fallback-dispatch-cli.ts`, which has no App Server
host and never read a child's turn; the host is a CRW addition
(`internal/role/created_check.go`, `createdCheckRead` and `createdCheckStop`, and the new
`internal/role/dispatch_host.go` with `internal/role/dispatchhost`). Everything below was introduced
by the port.

- Passing one host to `CheckedDispatch` for every action moved the created report off the native
  thread database, because `createdCheckRead` consults a host before it. A created report the native
  database would accept was then refused with "host could not verify created agent" whenever the App
  Server could not answer `thread/read` for that child (`internal/role/dispatch_cmd.go`;
  `internal/role/created_check.go`, `createdCheckRead`); port: fixed by CRW-653 (the CLI asks for the
  host only for a report whose outcome is stopped, so the created report and every other input run
  exactly as on dev with a nil host and never dial; the parent decided this on 2026-10-06,
  del-c0330769d135-a1, and Devin reported the same behaviour as a red finding on the pull request).
- Making a file of package `role` dial the App Server put `net/http` and `github.com/coder/websocket`
  into `internal/relay/faults`' non-test dependency graph through
  `faults -> relay/dispatch -> relay/job -> harness -> pabcd/hook -> role`, failing
  `TestFaultsDependencyInventoryContainsNoNetworkClient` and the `go-product (test-3)` job
  (`internal/role/dispatch_host.go` at the first attempt's head, commit fa5de3104); port: fixed by
  CRW-653 (the dialing moved to `internal/role/dispatchhost`, which `cmd/crw` installs into the
  nil-default `role.OpenDispatchHost`; package `role` names no network client again).
