# CRW-871 — non-canonical session ids at the mutating entries, and the first SIGINT

Source: CXC v0.2.40 (`3c1459ac`) `plugins/codexclaw/components/pabcd-state/src/orchestrate-cli.ts`
`runOrchestrateCli` :466-1131 (the state read, the lockless transition, the terminal branch of
`src/cli.ts` :143-152), `scan-cli.ts` `parseScanCliArgs` :79-207, and
`review-round-cli.ts` `runReviewRoundCli` :210-306. Ported to Go as
`internal/pabcd/cli/orchestrate_status.go` (`RunOrchestrateRead`),
`internal/pabcd/cli/orchestrate_transition.go` (`orchestrateCommitRun`,
`RunOrchestrateTransitionContext`, `orchestrateTransitionApply`),
`internal/pabcd/cli/scan_args.go` (`ParseScanCliArgs`),
`internal/pabcd/cli/review_round_run.go` (`RunReviewRoundCli`),
`internal/pabcd/state/lock.go` (`WithSessionLockContext`) and the `orchestrate` row of
`internal/harness/pabcd.go` / `internal/harness/pabcd_cli.go`.

- The oracle sanitises the session id into the state file name (`state.ts` `sanitizeKey`) and
  checks existence against the raw id (`orchestrate-cli.ts` :328-330), so an id such as `raw id`
  makes `crw pabcd orchestrate reset --session 'raw id'` judge one file and rewrite
  `raw-id.json`, a DIFFERENT session's state, and the same class reaches `scan record` (which
  rewrites the sanitised session's `sessionId`) and `review-round open`/`abort` (which judge the
  sanitised session's plan). Each mutating entry now refuses an id for which
  `state.IsCanonicalSessionID` is false before it reads, locks or writes, so the existence check,
  the read, the lock and the write all use one key; the state library keeps sanitising, as its
  recorded oracle rows pin (data-loss class, the parity rule revision of 2026-10-03); port: fixed.
- The oracle's terminal branch is a short-lived process with no signal path: a SIGINT during the
  mutation ends the process, and the port's `crw pabcd orchestrate` row was registered with `Run`
  (`internal/harness/pabcd.go`), so the invocation context `cmd/crw serve` cancels on the first
  SIGINT never reached `RunOrchestrateTransition`, and a mutation past its lock wait still
  published its state and ledger rows. The row now takes `RunContext`,
  `RunOrchestrateTransitionContext` carries the context, `state.WithSessionLockContext` ends the
  lock wait with it, and the transition reads it once more immediately before each branch's first
  durable effect; a mutation cancelled before its first write answers `Interrupted` (130) with
  nothing written, and one already past its first write finishes and answers as before; port: fixed.
- Supersedes known-defects/CRW-758.md, item beginning "The row is registered with `Run`": now
  port: fixed (the row is a `RunContext` row, the context reaches `RunOrchestrateTransitionContext`,
  and the lock wait and the pre-write check both end with it).
- Supersedes known-defects/CRW-758.md, item beginning "The oracle's terminal branch has no signal
  path at all": now port: fixed (the row takes the invocation context and the transition ends on it
  before the first write, a deliberate deviation from the oracle's no-signal process).
