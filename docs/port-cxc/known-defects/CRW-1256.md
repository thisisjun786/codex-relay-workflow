# CRW-1256 — the `crw install switch` help describes `cxc` as a return to CXC

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no `crw install switch`). The Go side is `internal/runtime/install/switch_cmd.go` (`switchUsage` and `renderSwitch`). The decision it must match is CRW-201 and CRW-1228: `cxc` means only the ported hooks off (emergency stop) and is not a way to bring CXC back, because the full CXC removal (cutover S9.3b) left no CXC-owned role files. The restore itself is unchanged and is byte for byte: on a home that still holds a `codexclaw@codexclaw` table that was `enabled = true` before `switch crw`, `switch cxc` puts that line back, so the plugin is on again (`switch_cmd_test.go` TestInstallSwitchRoundTripThroughTheCommand), and a recorded `enabled = false` is put back as well, which turns a CXC plugin turned on by hand since off again (`configguard/switch.go` RunSwitch, `RestoreTableKeyExact`); the wording says so and never claims the opposite. The finding is from the real-environment trial r1, S4-E (`/state/crw/mgmt/real-trial-r1/S4-results.json`).

- The installed help said `switch cxc` is "return to CXC: restore what the switch changed", that the switch replaces "CXC-owned" role files unconditionally, and the human status text never said what `active=cxc` or a conflict with `switch cxc` means; port: fixed (wording only: `switchUsage` now calls `cxc` the emergency stop of the ported hooks that puts back only what the switch recorded as changed, never installs CXC, and says a remaining CXC plugin entry recorded as enabled comes back on with the role files the switch replaced, and says `switch crw` puts the CRW role file in place only where one is missing or is an older CXC file, leaving a CRW file or a file of another owner as it is; the human `status` / switch text explains `active=cxc` as hooks off, says whether the CXC plugin is enabled in config.toml, and adds an emergency-stop line to a conflict that says what `switch cxc` does to the CXC plugin from the record: with no recorded CXC plugin line the plugin stays on, with a recorded line that leaves it on (`enabled = true`) it stays on, and with a recorded `enabled = false` (the plugin was turned on by hand since `switch crw`) the restore turns it off; the help says the same. `RunSwitch`, the manifest, the `.bak` copies, the rollback, the role-file ownership decisions and every JSON document, `notes` included, are unchanged; pinned by `TestInstallSwitchHelpDescribesCXCAsTheEmergencyStop`, `TestInstallSwitchStatusConflictKeepsJSONNoteAndExplainsEmergencyStopInText` and `TestInstallSwitchStatusActiveCXCExplainsHooksOffInText` `TestInstallSwitchLegacyRoundTripTextSaysTheCXCPluginIsOnAgain` and `TestInstallSwitchConflictNoteFollowsTheRecordedCXCLine` (recorded true, recorded false and no record, each checked against the real `switch cxc` afterwards) in `internal/runtime/install/switch_help_test.go`). `docs/runtime-install.md` still carries the old paragraph; CRW-1228 owns that file.
