# CRW-1256 — the `crw install switch` help describes `cxc` as a return to CXC

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no `crw install switch`). The Go side is `internal/runtime/install/switch_cmd.go` (`switchUsage`, and the conflict note of `ReadSwitchStatus`). The decision it must match is CRW-201 and CRW-1228: `cxc` means only the ported hooks off (emergency stop) and never a re-activation of CXC, because the full CXC removal (cutover S9.3b) left no CXC-owned role files. The finding is from the real-environment trial r1, S4-E (`/state/crw/mgmt/real-trial-r1/S4-results.json`).

- The installed help said `switch cxc` is "return to CXC: restore what the switch changed", that the switch replaces "CXC-owned" role files, and the conflict note only named `switch cxc` as a way out; port: fixed (wording only: `switchUsage` and the conflict note now call `cxc` the emergency stop of the ported hooks, with the recorded values restored, and say it does not re-activate CXC; `RunSwitch`, the manifest, the `.bak` copies, the rollback and the JSON output are unchanged; pinned by `TestInstallSwitchHelpDescribesCXCAsTheEmergencyStop` and `TestInstallSwitchStatusConflictNoteNamesCXCAsEmergencyStop` in `internal/runtime/install/switch_help_test.go`). `docs/runtime-install.md` still carries the old paragraph; CRW-1228 owns that file.
