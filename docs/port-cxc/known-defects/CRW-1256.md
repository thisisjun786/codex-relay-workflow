# CRW-1256 — the `crw install switch` help describes `cxc` as a return to CXC

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no `crw install switch`). The Go side is `internal/runtime/install/switch_cmd.go` (`switchUsage` and `renderSwitch`). The decision it must match is CRW-201 and CRW-1228: `cxc` means only the ported hooks off (emergency stop) and never a re-activation of CXC, because the full CXC removal (cutover S9.3b) left no CXC-owned role files. The finding is from the real-environment trial r1, S4-E (`/state/crw/mgmt/real-trial-r1/S4-results.json`).

- The installed help said `switch cxc` is "return to CXC: restore what the switch changed", that the switch replaces "CXC-owned" role files unconditionally, and the human status text never said what `active=cxc` or a conflict with `switch cxc` means; port: fixed (wording only: `switchUsage` now calls `cxc` the emergency stop of the ported hooks that puts back only what the switch recorded as changed and does not re-activate CXC, and says `switch crw` puts the CRW role file in place only where one is missing or is an older CXC file, leaving a CRW file or a file of another owner as it is; the human `status` / switch text explains `active=cxc` as hooks off and adds an emergency-stop line to a conflict. `RunSwitch`, the manifest, the `.bak` copies, the rollback, the role-file ownership decisions and every JSON document, `notes` included, are unchanged; pinned by `TestInstallSwitchHelpDescribesCXCAsTheEmergencyStop`, `TestInstallSwitchStatusConflictKeepsJSONNoteAndExplainsEmergencyStopInText` and `TestInstallSwitchStatusActiveCXCExplainsHooksOffInText` in `internal/runtime/install/switch_help_test.go`). `docs/runtime-install.md` still carries the old paragraph; CRW-1228 owns that file.
