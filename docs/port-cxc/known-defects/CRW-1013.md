# CRW-1013 — the receipt directory lock needs read permission

Source: the #598 (CRW-636) post-merge evaluation, P0 (alerts.jsonl pr 598), reproduced by the parent on dev a850a3fcc. The defect is the port's own: CXC v0.2.40 (commit 3c1459ac) takes no receipt directory lock (the receipt test is receipt-cli.ts:75-185, and its publication has no lock to take). The Go files are internal/pabcd/cli/receipt.go (RunReceiptCLI, receiptLockFile, receiptLockWait, withdrawReceipt), internal/pabcd/cli/receipt_dir_mode_test.go and internal/pabcd/cli/receipt_withdraw_race_test.go. The readers of the session evidence directory that were checked are the gate's named-path reads (internal/pabcd/evidence/evidence.go HasValidReceipt, internal/pabcd/gate/manifest.go, internal/pabcd/gate/receipt.go), the QA walk of internal/pabcd/hook/renderobs.go (qa/ only), the reset of .crw (internal/pabcd/reset/reset.go) and port/cxc/skills/crw-qa/scripts/validate-evidence.mjs (qa/ only, and its own qa-receipt.json).

- A successful receipt test failed in a session evidence directory without read permission (mode 0300, owned by a non-root user): the publication opened the directory for reading to take its flock, so the run answered "open .../.crw/evidence/s1: permission denied" and published nothing, although the command passed (#598 CRW-636 evaluation P0); port: fixed (the lock is now the receipt's lock file, test-receipt.json.lock, in the same directory, which needs the write and search permission a publication already needs. The directory is no longer opened. Pinned by TestReceiptPublishInAWriteOnlyEvidenceDirectory; its red run is kept under /state/crw/crw-1013/evidence/red/c1-red-write-only-dir.log).
- Publish and withdrawal share one exclusive lock, so a withdrawal never removes a receipt another run published after the comparison (CRW-636); port: kept (the same lock, now on the lock file; TestReceiptWithdrawalKeepsAnotherRunsReceipt and TestReceiptDirectoryIsLockedFromPublishThroughWithdrawal pin it, and TestReceiptLockWaitEndsWithTheContext pins the wait).
- A receipt test in a directory without write permission is refused with the publication's own error, the temporary file of the publication that cannot be created there (open <dir>/.test-receipt.json.<random>.tmp: permission denied); port: kept (the message is unchanged. The lock file cannot be created there either, so the run continues without the lock, only in that case, and the publication refuses. Pinned by TestReceiptPublishInAReadOnlyEvidenceDirectoryKeepsItsRefusal, which passed before the change as well).
- A lock file, test-receipt.json.lock, now stays in each session evidence directory after a receipt run, where the directory held only the receipt before (and the lock itself was not a file). port: intentionally-changed (the lock must be a file for the directory to need no read permission. Its name ends in .lock, the sidecar-lock convention of the state files, so the listings that take only .json names skip it, and the checked readers of the directory address named paths or the qa/ subdirectory. Nothing deletes it: removing a lock file another run is waiting on would let two runs lock different inodes of one name).
- The CRW-636 publish path can run unlocked when the lock file cannot be created and the directory is not writable (the refusal above), so a concurrent change of the directory mode between the lock open and the publication could leave the publication unlocked for its one refusal; port: kept (the publication refuses in that directory, since it cannot create its temporary file there, so nothing is published without the lock).
