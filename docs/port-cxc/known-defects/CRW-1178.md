# CRW-1178 — a pycache locked out repeated test runs, and unreadable refusals read as policy refusals

Source: the CRW memory and GitHub post guards, and CXC v0.2.40 `memory-write-gate.ts` (the oracle has no command reader and never refused these commands). Go files of the port: `internal/pabcd/shellir/modules.go`, `internal/pabcd/hook/memorygate.go`, `memorygate_analysis.go`, `githubpost.go`, `githubpost_judge.go`. Found by the isolated trial r2 (S2R2-F1, S2R2-F2, S2R2-F5, S3-R2-F1).

- The module inventory of `python3 -m unittest` and `-m pytest` refused every `.pyc` under the working directory, so a run that left a `__pycache__` locked out every later run (`-B`, `PYTHONDONTWRITEBYTECODE=1` and `env PYTHONDONTWRITEBYTECODE=1` forms included) in both guards; port: fixed in part, a deviation from the issue's plan. Python loads a cache entry instead of its source whenever the entry's header agrees with the source (a timestamp entry with the source's modification time and size, or a checked-hash entry with the source's hash), and the header is no proof that the code was compiled from that source: a crafted entry beside a harmless `test_calc.py` runs code the reader never read (it wrote below the memories root in the verification). So a `.pyc` is skipped only when it is a stale timestamp entry (`__pycache__/<module>.<tag>[.opt-N].pyc`, or pytest's assertion-rewrite entry `__pycache__/<module>.<tag>-pytest-<version>.pyc` such as `test_calc.cpython-312-pytest-8.3.2.pyc`, the tag letters then digits such as `cpython-312`, flags 0, recorded time or size different from the regular `<module>.py` in the directory above), which the interpreter or pytest discards and recompiles from the source the inventory reads. Both compare `int(st_mtime)`, a double that rounds a time just below a whole second up to it (`1700000000.999999999` reads `1700000001.0`), so the recorded time agrees with the source when it is the whole second below the source's time or, for a time with a fraction, the next one. Still refused: a `.pyc` in `__pycache__` whose name is not that shape (`calc.pyc` imports as the sourceless module `__pycache__.calc`, which the interpreter never compares with a source), an entry that agrees with its source, any hash-based entry, a `.pyc` outside a `__pycache__` (the sourceless import path), an entry with no readable source, a short or unreadable header, a link, and `.pyd` and `.so` files; the reason names the file and the route (`cache runs instead of <module>.py; remove __pycache__, use python -B`, after which repeated `-B` runs leave no cache and stay allowed). A command that runs `touch` on a module source, or copies or moves a path naming `__pycache__`, before the run is refused as a rewrite of module imports, and when a stale entry was skipped, only commands known to change no file may run before the module run in the same text, or beside it (the rest of its pipeline, anything after its coprocess): `cd`, `pushd`, `popd`, `pwd`, `echo`, `printf`, `true`, `false`, `:`, `test`, `[`, `set`, `unset`, `export`, `ls`, `cat`, `head`, `tail`, `wc`, `grep`, `sleep`, `which`, `type`, `basename`, `dirname`, `realpath`, `readlink`, `stat` and the wrappers `env`, `command`, `nice`, `timeout` (each spelled as a bare name), with no redirection that writes to anything but `/dev/null` or a descriptor. Anything else (`touch`, `truncate`, `cp -p`, `install -p`, `rsync -t`, an archive, a write redirection, an interpreter, a shell, a script, a function or program the reader cannot judge) is refused (`module cache entry is stale only until the command runs cp; remove __pycache__, use python -B`), because a time and size change through another name of a source (a hard link) could make the entry agree with its source after it was judged (verification found `cp -p` with a same-content donor doing this). With no cache entry skipped these commands are unchanged, as is any command after the run. Other files below `__pycache__` are inventoried like any file. The decision for every refused shape is unchanged.
- The inventory replaced the walk error with a fixed text and dropped the cause; port: fixed. The reader's own reason now reaches the answer, with the file below the working directory (`module imports compiled code that is not read (foo.pyc: compiled module without a source)`).
- An unreadable program was denied as `[crw MEMORY-WRITE-GATE] ... a protected write has not been established`, and the GitHub guard added `unreadable-github-post; GitHub posting has not been established` for the same non-GitHub command, so one test command drew two policy refusals without a cause; port: fixed. A text that does name a post keeps the GitHub wording and gains the reason. Rule IDs `unreadable-program` and `unreadable-github-post`, the decisions, the one-write grant spending and the leaf routing are unchanged; `MEMORY-WRITE-GATE` stays on every refusal of an observed or unverifiable protected write.
