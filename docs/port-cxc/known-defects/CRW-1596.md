# CRW-1596 — clean-host Git and Python behavior exposed implicit assumptions

Source: GitHub-hosted CRW CI on ubuntu-24.04, run 38965009633. These are port-owned checks and fixtures, not CXC oracle behavior.

- Flow assignment reuse accepted an ancestry yes/no answer without first checking that both named commits could be read. Git on the hosted runner could give that answer for the corrupt-object fixtures while the development host returned an error. `treeMatch` now checks the current HEAD and recorded commit first, preserves missing commits as mismatches and unreadable objects as errors, then asks ancestry using the resolved HEAD. The original corruption tests remain, and `TestFlowAssignmentChecksReadabilityBeforeAncestry` pins both conclusive ancestry answers without depending on a Git version; port: fixed (product).
- The CRW-1187 interpreter fixture assumed `keyword` had not been imported before the working directory joined the module search path. Site startup could cache the standard-library module and prevent the shadow from running. The fixture now deliberately preloads it in an isolated user site and runs its execution premise with `-S`, with and without `-I`. Both original commands and the `-S` commands retain their guard assertions, and the real shadow must still write its marker only without `-I`; port: fixed (test isolation). No guard rule or interpreter-version skip was added.
