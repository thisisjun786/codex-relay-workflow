No defect of the oracle was found while porting it; the gate, its store subset and their answers
replay byte for byte through the corpus. One deliberate deviation from the oracle's store guard is
recorded here, because it is the only place the port is not equal-or-stricter:

- The oracle compares the store file's `ctimeMs` between the fstat before the read and the one after it, so a metadata-only change during the read (a chmod or a chown) makes ownership unavailable (`automation-store.ts:124`); port: kept — the port's file must build for every target `make dist` publishes, and darwin's `syscall.Stat_t` names that field differently from linux's, so `os.SameFile` (dev and ino) plus `ModTime` and `Size` stand in for dev/ino/mtime/ctime. A content change on a regular file always moves `ModTime`, so the bytes read stay a consistent snapshot and no mutation the oracle denies is allowed here; only a metadata-only change during the read goes unnoticed.
