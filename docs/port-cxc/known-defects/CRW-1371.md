# CRW-1371 — a decision reserved for Jun could be answered only from the single store seat, whatever management session ran the project

Source: CRW's own design (CRW-1314 §5, lane D3; two session layers, management and project owner, Jun 10-14), not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle's user-grade and delegated-management-grade `decision-answer` is recorded only by the task the store-scope supervisor binding holds, and it has no management seat. The Go side is `internal/relay/cli/decisions.go` (`runDecisionRaise`, `decisionManagementAuthority`, `decisionAnswerProvenance`) and `internal/relay/registry/linkage_read.go` (`ManagementSeatsAbove`, `ManagementSeat`). Found by the CRW-1314 design review: with a management seat per thread (CRW-1333) and the management -> project edge (CRW-1314 D1c), the answer still went through `registry.StoreScopeSupervisor`, so of two management sessions only the one that had laid the store seat down could answer, and the other could not answer its own project's decisions.

- A user-grade or delegated-management-grade question raised from a project recorded nothing about the management session above it; port: fixed (`decision-raise` writes into `authority.ref` the key of the management seat whose live execution edge stands directly above `--origin-project`, read as a project key and, when no edge stands above that key, as a flow plan's id through its header's project, which is how `crw manage batch decide` raises; no edge leaves the authority as given; a parent-class ref stays the raiser's). Pinned by `TestDecisionRaiseRecordsTheManagementSeatAboveTheProject`, `TestDecisionRaiseOfANightBatchNamesTheSeatAboveThePlansProject`.
- The answer to such a question was accepted only from the store seat's holder; port: fixed (`decisionAnswerProvenance` reads a record whose ref names a management seat through that seat's current owner: the owner answers, every other task, the store seat's holder included, is refused `authority_unverified`, a seat with no live owner refuses every answerer, and a handover moves the right with the seat; an answer that cites the class without a ref takes the record's, so `crw manage batch decide`'s answer line is unchanged). Pinned by `TestDecisionAnswerTwoManagementSeatsEachAnswerTheirOwnProject`, `TestDecisionAnswerFollowsTheManagementSeatHandover`, `TestDecisionAnswerAManagementSeatWithoutAnOwnerIsRefused`, and end to end over the scripted App Server by `TestManagementProjectE2EDecisionIsAnsweredByTheManagementAbove` (the management session binds the project owner, the project raises the decision and sends its request, the idle management thread gets the turn and answers, the other session is refused, the project reads the answer and its next report reaches the same thread).
- Deviation: a record with no management ref (a project with no management edge, or a row raised before the edge stood) keeps the store seat's rule, and the grade and via rules are unchanged (`TestDecisionAnswerWithoutAManagementRefKeepsTheStoreSeatRule` and the existing CRW-737, CRW-903 and CRW-1333 decision tests); what the raise cannot settle is warned and recorded, never refused: a ref the raiser named that is not the seat above the project is replaced by the seat (`ref_replaced`), and a seat that cannot be read (`seat_unreadable`) or two live management edges above one project (`seat_contested`) leave the authority as given, each answered under `authorityWarning` and journaled once as `decision_authority_warning` (`TestDecisionRaiseWarnsAndKeepsGoing`); a repeated raise that folds into an older record keeps that record's authority, as a fold always did; the only refusal is the existing `authority_unverified` identity check; the relay store's schema is unchanged (the seat is a value of the record's existing `authority` JSON, plus a new `journal.kind` value, no CHECK; `relay_schema_shipped.json` and its compat test untouched); the dag scheduler's `dag-decision-record --authority-kind K --authority-ref R` is not one of these grades (its authority text is opaque, D-09, and recording is not authority) and is unchanged; where `decision-answer --option --text` stores narrative (CRW-1325 item 25) is not this issue; port: kept (reversible code and row values only, Jun 10-13: warn and record, fail open).
