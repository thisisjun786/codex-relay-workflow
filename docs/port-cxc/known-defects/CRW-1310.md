# CRW-1310 — a parent can pull a receipt inside its active turn

Source: CRW's relay delivery, not the CXC oracle. The owners are internal/relay/delivery/receipt_pull.go, ack.go and the relay command adapter and argument specification.

- A parent waiting within its own active turn could not acknowledge a completion the daemon kept deferred_busy; port: fixed by an explicit receipt-pull command. The caller's CODEX_THREAD_ID, task and recorded recipient must agree, and the host must observe that recipient's live turn with a start time. The transaction rechecks recipient identity, final stage, generation, revision supersession, relationship, holds and ordering. It returns the receipt without a send or a new turn and records inbox_only and receipt_pulled with the exact message and pulling turn.
- A repeated pull can return newly rendered bytes, and an acknowledgement could use the timing of an earlier failed send; port: fixed. A replay reads the stored message and revalidates currency; acknowledgement is bound to the pulling turn and verifies that host turn. Older failed-send timestamps do not describe this pull.
- TestReceiptPullDeliversABusyCompletionIntoTheCallersTurn, TestPulledCompletionIsAckedFromThePulledTurn, TestReceiptPullRefusesARecipientThatMovedDuringTheHostRead and TestReceiptPullAndTheDaemonClaimExcludeEachOther cover synthetic store/host behavior. TestReceiptPullRejectsASupersededRevisionInTheSameGeneration covers first pull and replay after a newer revision. TestPulledCompletionAckVerifiesAfterAFailedAttemptNewerThanTheTurn covers the earlier failed-send case.
- Limits: this is an explicit pull, not unsolicited turn injection. The caller's process identity is the same local CODEX_THREAD_ID trust boundary the tool host provides. Real host delivery latency and an installed service were not measured. The receive command still means claim, acknowledge and verdict; reading a receipt is not verification.
- Reconciliation of an earlier busy send could overwrite inbox_only after a pull and make it sendable again; port: fixed. Both the snapshot judgment and the guarded delivery UPDATE preserve receipt_pull. TestReceiptPullSurvivesReconciliationOfAnEarlierBusyAttempt checks the ordinary read and a forced stale snapshot against the write guard.
- Final review P1: a held, withheld, old-generation or superseded predecessor blocked a current receipt even though the predecessor could not be pulled; port: fixed. The order checks only current, unheld completions and the daemon's supersession judgment. TestReceiptPullSkipsUnpullablePredecessors covers each case; the original older-current-receipt ordering test stays.
- Final review P2: existing snapshot and assignment readers describe inbox_only as channel_closed, including a successful receipt_pull, and can suggest changing approval settings; port: pending under the requested one-review P0/P1-only scope. The receipt and same-turn acknowledgement are valid, but that display is not evidence of a transport or settings failure.
