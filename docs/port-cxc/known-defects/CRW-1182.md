# CRW-1182 — the account-home content snapshot follows links below the root and records a dangling root link

Source: the CRW-1176 follow-ups d2 and d3 (`lane-account-home-snapshot` 1ab6cd6e3); there is no CXC oracle for this helper, which is a test-support snapshot of the account homes. The Go file is `internal/testsupport/homes.go` (`Contents`, `walkHomeDir`, `snapshotWalk`, the budget constants); the cases are in `internal/testsupport/homes_links_test.go`, and the existing `AccountHomes` tests (`homes_test.go`) keep their expectations. Test-only helper: no production code reads it.

- A directory link below a watched directory was recorded as a link and not walked, so an in-place edit of a fixture behind it was not seen (CRW-1176 d2); port: fixed (a link is followed: a directory is walked under the link's label, a link to a regular file is read through it, a link to a FIFO, device or socket is recorded with the target's mode `(target <mode>, not read)` and never opened, and a link that leaves the watched root is walked too, since the watch exists to see the fixture a link reaches. The link keeps its own line with its target, and a followed target's mode is on that line as `(target <mode>)`, so a chmod of a fixture a link reaches outside every watched directory is seen. Pinned by TestContentsSeesAModeChangeOfALinkedTarget, TestContentsFollowsALinkToADirectoryUnderTheRoot, TestContentsReadsALinkedFileThroughTheLink and TestContentsWalksALinkThatLeavesTheRoot).
- A dangling root link was read as absent, so a change of its target was not seen (CRW-1176 d3); port: fixed (the root is judged with its link metadata first: a dangling link is recorded as `<label> <mode> -> <target> (dangling)` and a change of the target is a change of the snapshot. Pinned by TestContentsRecordsADanglingRootLinkWithItsTarget).
- A cycle ends the walk at its link and is marked `(cycle)`; a second path to a directory already walked, a link or the plain directory itself, is marked `(alias of <first path>)` and is not walked again (whichever of the two names sorts first is walked), so a fixture reached twice is read and counted against the byte budget once. Cycles are judged by the real directories above the link (ancestry), not by a global visited set, so a plain alias is not mistaken for a cycle. Every key of both tests is an absolute physical path: a watched directory spelled relative to the working directory is made absolute (prefixed, not cleaned, so a `..` after a link still resolves physically) before it is resolved, so a link with an absolute target back to it is a cycle and a plain-and-link alias under it is read once. Pinned by TestContentsMarksAnAbsoluteLinkToARelativeRootAsACycle and TestContentsCountsAnAbsoluteLinkAliasOnceUnderARelativeRoot. Pinned by TestContentsMarksACycleAndTerminates, TestContentsWalksACommonDirectoryOnceAndMarksTheAlias, TestContentsReadsADirectoryOnceWhetherTheLinkComesBeforeOrAfterIt and TestContentsCountsAnAliasedFixtureOnceAgainstTheByteBudget; the FIFO and device case by TestContentsRecordsALinkToAFIFOWithoutOpeningIt.
- The walk limits are 32 nested directories (a linked directory counts as one level, like a plain one), 4096 entries and 64 MiB of regular-file content. The read of a directory is bounded by the same budget: `readDirBounded` reads the entries that remain in the budget and one more as the overflow sentinel, never the whole listing, and the walk stops at the overflow (the CRW-1182 evaluation, d1; pinned by TestContentsReadsOnlyTheRemainingBudgetOfALinkedDirectory, which counts the names one read returned, and TestContentsEntryBudgetEdgeOfALinkedDirectory, children that fit exactly succeed and one more errors). A walk past one is an error that Verify reports, so an incomplete snapshot is never taken as a pass; an unreadable entry keeps its line and its error as before. Pinned by TestContentsErrorsPastTheDepthLimit, TestContentsDepthLimitIsThirtyTwoDirectoriesForPlainLinkedAndMixedChains, TestContentsErrorsPastTheEntryBudget and TestContentsErrorsPastTheByteBudget; the byte read is capped at the remaining budget.
- Kept: HOME contributes its top-level names only, and a link at HOME's top level is a name, not walked. The retrust fixture rewrites HOME/codex on purpose, and a recursion into HOME would read that rewrite as a stray write (port: kept, the exception the existing retrust tests rely on). Pinned by TestContentsKeepsHomeToItsTopLevelNames.
