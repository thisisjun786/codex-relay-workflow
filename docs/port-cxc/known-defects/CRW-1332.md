# CRW-1332 — the fake host had no subagent threads and the session host facts were unrecorded

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no flow run and no session call, so
nothing of it is ported here. The Go side is `internal/flow/sessionhost` (new: `sessionhost.go`, `answer.go`, `find.go`,
`tokens.go`), `internal/bridge/appserver/fakehost` (`subagents.go` new, `threads.go`), `internal/flow/bound/ledger.go`
(`Decision.Op`), and the shared decoding in `internal/flow/backend/agent/turn.go` and `internal/flow/ops/native.go`. Found while
building lane S2b of the CRW-1316 design (`/state/crw/mgmt/design-1316/design.md` sections 2, 3.3 and 5) and by the read-only
probe of the live host on 2026-10-14 (docs/flow/session-host.md, "Host facts").

- The fake App Server had no subagent thread. It could not show a thread with `parentThreadId`, `threadSource: subagent`, the
  `thread_spawn` source and `agentRole`, a finished thread reading `notLoaded`, the owner's `collabAgentToolCall` item, or a
  running thread lost on an App Server restart. So no test could exercise how a run reads the role subagents of a session call
  (fakehost `threads.go`); port: fixed. `Threads.Spawn` and `Threads.Restart` model them as the live 0.154.0 host shows them,
  `Server.DropConnections` drops the connections a restart ends, and the run loop takes the lock before it reads a turn a restart
  may cut. Pinned by `TestSubagent_readsAsASubagentThreadAndIsNotLoadedAfterItsTurn`, `TestSubagent_turnsListNewestFirst`,
  `TestSubagent_runningSubagentIsLostOnRestart`, and in `internal/flow/sessionhost` by `TestReadAgent`, `TestTurns`,
  `TestTurnsOfLostAndNotLoadedSubagents`, `TestInterrupt` and `TestFindByMarker`.
- The fake answers a `thread/turns/list` summary request with no items and `itemsView: notLoaded`. The live host gives the
  turn's first `userMessage` and last `agentMessage` with `itemsView: summary` (fakehost `threads.go` `handleTurnsList`);
  port: fixed for subagent threads, and kept for the other threads (the App Server backend's tests were written against the
  fake's summary, and changing it for every thread is outside this lane; reversible).
- The fake's `thread/list` without `sourceKinds` lists every thread. The live host lists the interactive sources only
  (`ThreadListParams.sourceKinds`) (fakehost `threads.go` `handleList`); port: fixed for subagent threads, which such a listing
  leaves out, and kept for the other sources, as above.
- The design names the agent argument of `send_input` and `close_agent` `agent_id` (CRW-1316 design 3.2). The live
  declarations name it `target`, and `wait_agent` takes `targets` and `timeout_ms` (docs/flow/session-host.md, "Host facts");
  port: pending (lanes S3 and S4 write the step output and the skill text that tell the orchestrator how to call them).
- The design takes the installed codex for 0.155.0-alpha.9.2 and asks for a re-check on 0.155 (CRW-1316 design 2). The App
  Server and every `codex` binary on the host are codex-cli 0.154.0, so the probe re-checked 0.154.0, the schema copy's
  version; port: kept (no 0.155 host is installed; the facts are recorded against the version that runs).
- The spawn hook's ledger records no `op`, so the ledger alone cannot tie a spawn to a step (`internal/flow/bound` `Decision`);
  port: pending (the reader is fixed: `Decision.Op` exists, `FindByMarker` uses it and falls back to the spawn message's first
  line, the item's `prompt`, with no warning when the ledger line exists and with `no_ledger_line` when it does not; lane S3
  makes the hook write the op).
- What a 0.154 host reports for a turn an App Server restart cut was not probed, nor the error text for a thread id it does
  not know (fakehost `subagents.go`, sessionhost `notFound`); port: pending (the fake reads such a turn `interrupted` unless
  `LostTurnStatus` names another status, and the reader takes `not found` or `no rollout` in an error answer for an absent thread;
  a later read-only probe of a cut subagent settles both).
