# CRW-1406 — a notice whose send was held uncertain was staged again on every reconcile, and the empty-seat fold warning had no test

Source: CRW's own design (CRW-1314 §3, the D4 follow-ups of CRW-1390, Argon V5 P3s of 2741763e), not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no flow run, no management seat and no direct message on the supervisor channel. The Go side is `internal/flow/report` (`relay.go` `RelaySender.stage`) and `internal/relay/cli` (`decisions.go` `decisionSeatsText`, tests only).

- A run's escalation or completion notice staged through the supervisor channel by a run process that died before it wrote the `escalation_notice` or `completion_notice` row, whose send the daemon then moved to `held_uncertain`, was answered no class by every later reconcile (the `held_uncertain` case of `stage` had no `relayReportKind` guard, unlike the `read` case), so no notice row was written and every reconcile staged the notice again until a readback settled the message (Argon V5 P3 of 2741763e) (flow/report/relay.go `RelaySender.stage`); port: fixed (a notice found `held_uncertain` is answered as staged, `queued`, as one found read is, so the run writes its notice row once and stages it no more; a report found `held_uncertain` still stages nothing and answers no class, so no `queued` row is written over the daemon's `unknown`). Pinned by `TestAnEscalationNoticeWhoseSendIsHeldUncertainIsRecordedOnceAndNotStagedAgain` and `TestACompletionNoticeWhoseSendIsHeldUncertainIsRecordedOnceAndNotStagedAgain`, with `TestAnUncertainSendBeforeTheQueuedRowReadsUnknown` (the report case) unchanged.
