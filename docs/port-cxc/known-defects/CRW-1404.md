# CRW-1404 — the follow-ups of the e2b lane (CRW-1391, CRW-1397): region spellings in the release's declaration, the run state on a land's replay

Source: CRW's own design (the decided defaults of CRW-1404, from the Argon V5 review of the e2b lane, head 189283fe: one P2 and one P3, confirmed), not the CXC oracle: CXC v0.2.40 (commit 3c1459ac) has no flow run. The Go side is `internal/flow/ops/lane_design.go` (`AdmissionRegions`, `RegionForm`, `RegionOf`), `internal/flow/cli/schedrelay.go` (`declareRegions`, `Release`), `internal/flow/ops/lane_land_head.go` (`landRelease`) and `internal/flow/ops/seams.go` (`ReleaseResult.HeldRunState`); the reference is `docs/flow/script.md` ("The lane of a node").

- Item 1: `declareRegions` looked a region up among the plan's by its text as written, before trimming or cleaning it, and `AdmissionRegions` dropped a DESIGN `edit_regions` entry only when it was the same string as one already admitted. A DESIGN that repeated a planned region whose change is not the default (`rename`, `delete`) or that is `exclusive`, with blanks around it or in another spelling (`./path`), was declared twice - once as the plan states it and once as a plain edit - and `DeclareRegions`, which cleans every path, refused the node's whole declaration as one region declared twice with different changes; the release went on (`regions_not_declared`), with the node undeclared; port: fixed (both compare a region by its normal form, `RegionOf`: trimmed, a tree when it ends in `/`, a symbol after `#`, the path cleaned with `path.Clean` as `DeclareRegions` cleans it. `AdmissionRegions` admits a region once, in its first spelling; `declareRegions` declares each normal form once, and a region that is one of the plan's, in any spelling, carries the plan's change and exclusive flag. The relay's store form is unchanged. `TestReleaseDeclaresAPlannedRegionInAnotherSpelling` (blanks, `./path`, several overlapping spellings at once beside a region of the DESIGN's own), `TestAdmissionRegionsDropsAnotherSpellingOfARegion`; red first).
- Item 2: when the relay answered a land's release with the replay of an execution another run holds (released, `Run` another run: the fallback after the first answer `land_node_held`), `landRelease` held the land with no run state, because `SchedRelay.Release` did not read it on a replay; a land held by a run that had ended was told `crw flow resume` of that run, and the row recorded no `held_run_state` and no `land_node_held_by_ended_run`; port: fixed (`SchedRelay.Release` reads the state of the run whose execution a replay answers when that is another run, `ReleaseResult.HeldRunState`, and the fallback passes it as the first answer does, so an ended holder is told `crw flow cancel <run>` and the row records `held_run_state` and the warning. `TestReleaseOfAnotherRunsReplayNamesItsState`, `TestLandHeadOfANodeAnEndedRunHoldsOnTheReplay`; red first, the first one's red log ran with a holder run whose journal was not recorded and is backed by a revert-red log).
- Item 3 (the named limit of this lane): the lane's own admission in the workflow script (`crw:lib/lane` `admissionRegions`, `regionsOverlap`) compared regions as written, so a node whose region is spelled with blanks or as `./path`, a symbol of a file another node edits whole, or a symbol of a file whose other symbol the plan deletes was not seen by `crw.dag` to overlap the other node; the relay, whose declarations are the normal forms with the plan's change and hold, held the second node back `defer:edit_overlap` and its lane ended unreleased; port: fixed by CRW-1461 (`crw.dag` admits by the Go ops `crw.admissionRegions` and `crw.regionsOverlap`, the relay's rule with the plan's change and hold, which the milestone node carries as `planned_regions`, judged once per pair of region lists and read through a table kept by their content; the script-side functions are gone. A changed project lane does not resume a run recorded under the old one: the entry script's digest gate refuses a direct run, and the child workflow's digest gate refuses a night batch that opened it. `TestDagAdmitsByTheRelayRule`: the three spellings beside a disjoint node with two slots, the disjoint node runs beside the first, the second is asked for only after the first landed, and no release is held back; red first).
