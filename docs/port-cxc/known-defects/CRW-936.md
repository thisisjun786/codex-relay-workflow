# CRW-936 — retrust publication follow-up: durability, the overlap report and every refusal

Source: CXC v0.2.40 (commit 3c1459acadeb1906d97c00a598e1457327ae372d)
`plugins/codexclaw/components/cxc-ops/src/hook-trust.ts:345-477` (`retrustHooks` and its
`writeAtomic`), through the port's swap-then-verify publication in
`internal/pabcd/crwdir/swap.go` (`PublishSwap`/`crwdirSwapPublish`) and
`internal/runtime/doctor/hooktrust_retrust.go` (`hookTrustRetrustWith`, `hookTrustRetrustReport`).

The oracle writes the rewritten document in place with `writeFileSync`, so it has no post-exchange
step to sync and no displaced file to read back; the port's publication replaced that write (CRW-844,
PR #767) and the defects below are in the port's own addition, found by the CRW-844 pair evaluation
on dev 9a7fcae2 (score 5, three P1 of four; the fourth, the activation writing feature settings
before the config lock, was closed by CRW-877 and is not this issue's).

- `PublishSwap` synced the target's directory only on its success path; the no-replace move failing
  and the backup read-back failing returned a `*PublishedError` without syncing anything, and a
  backup in another directory was never synced even on success. Retrust counts such a failure as a
  warning and exits 0, so it reported success without the published rename being durable
  (`internal/pabcd/crwdir/swap.go:200-216` at the baseline); port: fixed (CRW-936: every
  post-exchange return syncs the directories that hold the target and the backup, each once, and a
  sync failure is joined into the `PublishedError` with `errors.Join` — `crwdirSwapSyncDirs`,
  `crwdirSwapPublish`).
- The conflict branch returned as soon as the displaced bytes differed from the bytes retrust read, so
  the target was never read again and the report claimed config.toml held retrust's content even when
  a second save had landed right after the publication
  (`internal/runtime/doctor/hooktrust_retrust.go:408-411` and the report at :713 at the baseline);
  port: fixed (CRW-936: the branch re-reads the target, sets `LateWrite` with `Conflict` when it
  holds a newer save, and sets `RecheckFailed` and asserts nothing about the target when the re-read
  itself fails — `hookTrustRetrustWith`, `hookTrustRetrustReport`).
- A refusal before the plan existed printed nothing at all, and a refusal that had a plan never named
  the backup it did not create, so an operator saw a failure with no items, no path and no file state
  (`internal/runtime/doctor/hooktrust_retrust.go:306-308` and the report at :698-714 at the
  baseline); port: fixed (CRW-936: the result carries the config path from the moment it is known and
  the CLI fills the refusal's reason, so every refusal prints the config path, the reason, the file
  state and, with a plan, the backup path marked not created — `HookTrustRetrustCLI`,
  `hookTrustRetrustReport`).
- The port's own comment on `hookTrustRetrustWith` described the conflict as "the target holds
  retrust's content" in every case, which the two-save overlap makes false; the comment and the
  conflict error text now follow the re-read result; port: fixed (CRW-936).
- The ordinary path (nothing raced the exchange) returned the post-publication read error without
  recording it, so `hookTrustRetrustReport` fell through to its success wording and told the operator
  config.toml held the rewritten config even when the file could not be read at all
  (`internal/runtime/doctor/hooktrust_retrust.go:446-448` and the report at :716-717 at the baseline);
  port: fixed (CRW-936 generation 2: the read failure sets `RecheckFailed` and `RecheckError`, the
  report says the target could not be read again and claims nothing about it, and the exit status stays
  the failure it was — `hookTrustRetrustWith`, `hookTrustRetrustReport`). This is the same report
  function and the same concept as the conflict-path defect above (the 2nd-generation answer's d2).
- When the content the exchange displaced could not be read back, the branch returned at once: the
  target was never read again and the report fell through to its success wording, asserting that
  config.toml held the rewritten config although nothing had looked at it. Whether another writer raced
  the exchange is undecidable without those bytes, but what the target holds is not
  (`internal/runtime/doctor/hooktrust_retrust.go:427-432` at the generation-2 head); port: fixed
  (CRW-936 generation 2: the read failure sets `DisplacedUnreadable` and `DisplacedError`, the branch
  skips the conflict comparison and still reads the target, and the report names the unreadable
  displaced path with its reason instead of claiming what it holds — `hookTrustRetrustWith`,
  `hookTrustRetrustReport`, `displacedClause`).
- A refusal before the plan with an empty but *set* `CODEX_HOME` printed `config.toml: (unknown)`: the
  report treated the empty string as "no Codex home was known" although the command line had one, whose
  target is `./config.toml`. The refusal therefore hid the path B3 promises for exactly the
  configuration the option parser accepts (`internal/runtime/doctor/hooktrust_retrust.go:552-553` and
  the report path at :767-771 at the generation-2 head); port: fixed (CRW-936 generation 2: the parsed
  options carry whether a Codex home was resolved, so the report names the target the set value implies
  and reserves `(unknown)` for a run that never learned one — `hookTrustRetrustOptionSet`,
  `hookTrustRetrustReportPath`).
