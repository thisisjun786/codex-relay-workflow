# CRW-1341 — the tracking backend is a setting of the configuration file

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle names no work-tracking backend and its configuration has no `tracking` section. The Go side is `internal/crwconfig/tracking.go` (the section, its spelling rule, `CheckTracking` and the `gh` probe), the `Report.Tracking` field and `Preflight` in `internal/crwconfig/check.go`, and the `check` verb in `internal/crwconfig/config.go`; the reference is `docs/runtime-install.md` ("Where work tracking lives"). The GitHub transition (the Linear project "CRW 1.0 GitHub 전환") is not finished: the record of the work stays on Linear until Jun says the switch is done, and `thisisjun786/crw-work` is the test target.

- The oracle's configuration cannot say where work is tracked, so the code repository and the tracking repository could only be one; port: fixed (`tracking: {kind, repo}` is its own section apart from `manage.repository`; kind `github` is the 1.0 path and `linear` a read-only archive setting. Pinned by `TestTrackingRoundTrip`, `TestTrackingDefaults`, `TestTrackingRepoSpelling`, `TestTrackingInvalidSections`).
- A section that is missing or malformed must never make the shared load refuse for the other readers (the lesson of CRW-1319's final verification); port: fixed (`File.Tracking` judges the section lazily and `load` never reads it, so the relay state selection, the tool roots, `crw config paths` and `show` read as before; the warning is `tracking_missing` or `tracking_invalid`. Pinned by `TestMalformedTrackingNeverStopsAnotherReader`, `TestMissingTrackingWarnsInConfigCheckOnly`, `TestDoctorStorageWarnsOnAMalformedTrackingSection`).
- `crw config check` did not say whether the tracking repository could be used; port: fixed (a `gh auth status` and a GET `gh api repos/OWNER/NAME` through an injectable probe read authentication, `permissions`, `has_issues` and `archived`; each way issues cannot be read and written is an error that says what to do. The check writes nothing. Pinned by `TestCheckTrackingThroughTheProbe`, `TestRunCheckTracking`, `TestGHProbeReadsOnly`, `TestGHProbeFailures`).
- Named limit: a clean host with no `tracking` section now has one warning in `crw config check` and `crw doctor storage` (`tracking_missing`, exit 0), which the earlier clean report did not have (`TestRunCheck` expects it); the plain `crw doctor` report and `crw install` stay silent about a missing section. Port: kept (the warning tells a host what to set before the switch from Linear is made).
- Named limit: the check reads access as the signed-in `gh` login only. `kind: linear` is accepted but not probed or used by any command. Port: kept (the 1.0 path is GitHub; the archive reader is a later issue).
