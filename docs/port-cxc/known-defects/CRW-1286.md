# CRW-1286 — a read-only child cannot report that its work is blocked

Source: CRW's relay reporting and bridge creation paths, found during r2 S8 F0-2 on
2026-10-12. The child tried to emit `blocked_needs_input`, but CLI ownership preflight
opened a writable store in the child's sandbox and was refused by the read-only filesystem.
No event reached the parent. The decided CRW behavior is daemon-only child reporting and
an explicit refusal of read-only child creation, not an inherited or silently widened sandbox.

- `emit`, `intent-claim` and `intent-disposition` go through the selected state's control
  socket. The daemon borrows its already-open store for each command; closing a command's
  handle does not close the daemon's pool or release its gate. The daemon alone decides
  where the report is recorded: the caller's state selection only finds the socket and the
  daemon runs the command on its own state; a caller-relative path is refused. Missing daemons fail explicitly with no local writer or
  bridge fallback; port: fixed in source, a deliberate deviation from direct CLI writes.
- Delegated emits refuse caller-selected artifact freeze destinations before opening services
  or writing files; the seccomp regression preserves an unrelated manifest even on refusal.
- `create_thread` refuses the child role with a read-only sandbox or explicit `readOnly`
  policy, with guidance to recreate it writable. Other roles retain their sandbox behavior;
  port: fixed in source.
- `TestReadOnlyChildCanEmitBlockedNeedsInput` and
  `TestReadOnlyChildBlockedReachesTheParent` run the built CLI with Linux seccomp refusing
  writable opens, against a temporary daemon owner and fake host. The former also checks
  the explicit absent-daemon error; the latter proves the parent delivery is dispatched.
  `TestReadOnlyChildClaimsAndDeclaresThroughTheDaemon` covers both marker commands with
  the default marker selection. `TestCreateThreadRefusesAnUnworkableChildSandbox` covers
  the sandbox mode and explicit policy independently, before any thread or turn start.
  These source tests do not establish installation, independent review or live r2 acceptance.
- `TestChildReportStateLocationIsTheDaemons`, `TestAChildStateSelectionCannotRedirectTheDaemonsRecord`
  and `TestTheDaemonRefusesACallerRelativePath` pin that location rule.
- Completion remains blocked: the existing fixtures that report without a daemon
  (delivery and cli CLI goldens, dagsched, the executable contract corpus) still need
  moving to a daemon-owned store, so the full suites are not green.
