# CRW-1194 — journal-tail and receive: a waitable journal feed and a claim, ack and verdict command

Source: CXC v0.2.40 (commit 3c1459ac) has no counterpart of either command: `journal-tail` and `receive` are relay commands added by
the 0.5.0-alpha design (R01 = R9 and R4). The Go files are `internal/relay/cli/journal_tail.go`, `internal/relay/delivery/receive.go` and
`cmdVerdict` in `internal/relay/delivery/cli.go`, which `receive` shares. This record notes the deviations from the three commands that
`receive` composes, and what the new commands do not claim.

- `claim`, `ack` and `verdict` were three commands a delivery turn ran one after another, each its own process, so a turn that held a
  reviewed verdict spent three round trips and could stop between them (source `cli.py` `cmd_claim`, `cmd_ack`, `cmd_verdict`); port:
  fixed (`crw relay receive` runs the three over the same library functions in one process, each in its own store transaction, with the
  refusals and records of the commands; the existing three commands are unchanged and their handlers' answers are pinned by
  `TestExistingCommandsGoldenUnchanged`).
- `cmd_verdict` read its line, the `--criteria` file and the `--restoration` marker in the handler, so the reading could not be run
  without opening the store; port: kept (the handler is split into `PrepareVerdict`, which reads the line, and `PreparedVerdict.Record`,
  which rules it on an open store, in the order the handler used: the reading first, then the store, then `--verified-head`'s shape; the
  words and exit codes are the handler's). `receive` calls the reading before the claim, so a verdict line the verdict command would
  refuse before it opens the store (a restoration naming no finding, an unreadable `--criteria`, a malformed head) writes no claim and no
  acknowledgement, where the three commands run by hand would have written both before the verdict refused.
  The reading runs as the command's own validation, before dispatch admits the store, so such a line also creates no store and binds
  none to its `--socket`.
- `receive` runs the verdict whatever the claim answered: `already_claimed` is reported and not a stop, because `verdict` never consulted
  the claim; port: kept (the three commands run by hand behave so).
- `receive` without `--socket` records a first acknowledgement as the parent's intent (unverified), and the verdict then refuses
  `not_acknowledged`, as `ack` and `verdict` do without a host; an acknowledgement already verified and a verdict already on record
  are returned as they are (`ack` and `verdict` answer a settled event before they consult the turn or the host), so a repeated
  `receive` of a finished event succeeds offline; port: kept.
- The verdict file is `receive`'s own input (the three commands take options): a JSON object of the verdict command's options, with no
  verdict turn, because the verdict is ruled from `--ack-turn`; a file the command cannot read is a usage error (exit 4), where
  `verdict --criteria` reports an unreadable file as the host's failure (exit 3); a key an object gives twice and data after the document are usage errors too (the shared `loads` the older commands use keeps the last
  of a repeated key and lets a closing bracket trail; `receive`'s file does not use it); port: kept (a new input, read strictly).
- `journal-tail` reads through the read-only opener, so on a store this runtime could write it does not take the write gate that
  the generic read-only command path takes; the absent and the partial store are judged on the resolved database as the other read-only commands judge them
  (`store.CheckReadable`: a link naming no file is `store_absent`, a write gate or ownership mirror beside no database is the partial-store
  refusal) and nothing is created; port: kept.
- `journal-tail --kinds` returns the cursor of the last entry returned, not of the last row scanned, so a filtered reader that finds
  nothing re-reads the same span on its next call; port: kept (the spans are index range reads, and the cursor stays one definition).
- `doctor`'s `offlineCommands` and `hostRequiredCommands` do not list the two commands: the lists are the contract's and the cut ref's;
  port: kept (pinned by `TestDoctorCommandListsUnchanged`).
