# CRW-1056 — the recorded-date oracle tests depend on the host time zone

Source: the CRW-1056 observation (10-09, Claude Code, security P1 verification): internal/recall TestIndexRankRecordedOracle/dates/date/0 and internal/role TestLiveCatalogOracleDates fail under TZ=Asia/Seoul and pass under TZ=UTC, at dev 7d23cd46f (per the issue) and reproduced at the CRW-1056 base 2eb3066c1. The recorded values were made under UTC (internal/recall/testdata/indexsearch/oracle.json, the `dates` corpus; internal/role/livecatalog_test.go, the comment above TestLiveCatalogOracleDates). The Go files are internal/recall/format.go (the zone-less timestamp read, `loc := time.Local`, lines 314-338) and internal/role/livecatalog.go (catalogDate, `location := time.Local`, line 381). The zone-less reading itself is the kept port deviation in known-defects.md (the Date.parse entries for startedAt/endedAt and recall format.ts timestamps).

- The two tests read zone-less legacy stamps ("2026/09/09", "2026/1/2", "1/2/2026", the numeric dates "0", "1", "32", "49", "50", "1.5") through the host's local zone, so their expected values held only under a UTC host; under TZ=Asia/Seoul the recency score of the dated hit and each numeric date moved by the zone offset; port: fixed (test only: both tests pin time.Local to time.UTC for their duration, the same pattern as format_test.go and rollout_test.go; the local zone is read from TZ once, when first used, so the pin is on time.Local itself rather than on the environment). Verified green under TZ=Asia/Seoul, TZ=America/Los_Angeles and TZ=UTC.
- Product code is unchanged: a zone-less legacy stamp is still read in local time, as V8's Date.parse does for the original CXC; port: kept (the local reading is the decision recorded in known-defects.md; whether the port should instead read zone-less stamps as UTC is not decided by CRW-1056 and stays open for the owner).
