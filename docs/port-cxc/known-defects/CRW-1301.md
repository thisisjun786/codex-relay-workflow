# CRW-1301 — an integration target that moved outside the integration path

Source: CRW's own design, not the CXC oracle. CXC v0.2.40 (commit 3c1459ac) has no integration branch, no `dag-integrate-push` and no fault class for a moved target, so there is no oracle pointer. The Go side is `internal/relay/dagsched/integration_target.go` (the comparison and the fault), `integration_push.go` (where the push asks for the comparison), `internal/relay/integrate/cli.go` (the printed document), `internal/relay/faults/ledger.go` and `contract/schema/fault-kinds.json` (the class declaration). The defect was found in the second real trial (r2 F0-1): a relay child ran `git push origin HEAD:dev` and moved the integration branch on the remote, and the relay neither saw it nor told anyone. CRW-1284 guards the child's push. This issue is part (b), decided as A + D(i) (Sion 10-13, Jun-delegated).

- The relay never compared the remote integration target with what it had recorded, so a move made outside the integration path went unnoticed (r2 F0-1); port: fixed for the push (`dag-integrate-push` compares the remote head it already reads with the heads recorded for the integration ref, which are every intent's base and every `ref_moved` head, and with the same heads of the store's other integration refs, whose push to the same remote branch is the integration path too. A head outside every recorded set records a broken `integration_target_moved` fault in the existing fault ledger, which raises the supervisor's blocking notice, and names it to the calling parent in `target_moved`, or at the end of the refusal's detail when the push is refused. The outcome, the refusal reason, the exit code and the remote are the ones the push gives without the comparison, and nothing is reverted. Pinned by `TestIntegrationTargetMovedOutsidePathRaisesFault`, `TestIntegrationTargetOnPathRecordsNoFault`, `TestIntegrationTargetAnotherRefOnPathRecordsNoFault`, `TestIntegrationTargetUnreadableRemoteRecordsNoFault` and `TestPushDocumentNamesTheMovedTarget`).
- The comparison runs only when a push runs; port: kept (decision A). Nothing reads the remote on a schedule, and nothing records which remote and remote ref are the integration target, so a moved target is seen at the next `dag-integrate-push` and not before. Recording the target and a periodic remote check are CRW-1304. The fault sweep stays free of git reads and network calls, as `docs/relay/faults.md` requires.
- The receive and acknowledgement steps compare no ref; port: kept (CRW-1302).
- A remote that cannot be read, or a remote branch that does not exist yet, is compared with nothing; port: kept (the push defers or refuses it as before, and no fault is recorded without a head to compare).
- The parent is told through the push's own output, and the supervisor through the ledger's blocking notice. There is no separate notice addressed to the parent; port: kept (decision D(i): the two together are the parent notice).
- The recorded heads are matched by the integration ref's name, as the verified-move check matches them, so a branch of the same name in another checkout of the store counts as recorded; port: kept (the same rule as `VerifiedMoveOnto`).
- Because nothing records which remote branch an integration ref is pushed to, a head the relay recorded for any integration ref of the store counts as on the path, also when a commit of another ref was pushed to this remote branch by hand; port: kept until CRW-1304 records the target.
- Every other mover of the remote branch is named, including a pull request merged into it, a merge train landing or a person's push, because none of them is the integration path. The supervisor accepts such a move through the fix and reverification loop; the next batch whose base is that head records it, and later pushes over it raise nothing; port: kept (decision A).
- A further move while the fault is open adds an occurrence to the same fault but no second blocking notice, because the ledger raises that notice when the fault opens; port: kept (the ledger's rule for every class).
- The batch's `old_head` (the local integration branch before the batch) is not part of the recorded set, since it is the ref's earlier `ref_moved` head or a branch the relay did not create; port: kept.
- The class is not swept and no push clears it, because a clear would withdraw a blocking notice the daemon had not yet carried. It clears through the fix and reverification loop, and it is registered by the process that records it rather than at start, so `fault-policy` in another process does not list it; port: kept.
