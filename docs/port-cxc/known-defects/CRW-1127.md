# CRW-1127 — a created report is tied to the attempt's issued spawn

(:169-176, the created outcome), `readState` (:95, :100, :121, the stored status checks) and `issueManagedSpawn` (:250-267);
the Go port's `dispatchReport`, `dispatchStatus` and `dispatchPinnedDecode` in `internal/role/dispatch_ledger.go`,

- Supersedes known-defects.md, section "CRW-529 dispatch ledger library", item beginning "A created report is accepted before spawn issuance": now port: fixed (at the checked boundary a created report needs the attempt's recorded issuance; without it the report is refused and nothing is written, unless the caller takes the explicit reconciliation path below. The parity ledger `RunDispatch` keeps the oracle answer. Pinned by `TestDispatchReceiptCreatedRequiresIssuance`).
- Supersedes known-defects.md, section "CRW-529 dispatch ledger library", item beginning "Stored status validation coerces values to strings": now port: fixed (a stored dispatch or attempt status must be a literal enum string; a singleton array or an object is "invalid dispatch status" or "invalid attempt status" and the record is not rewritten. The recorded corpus cases `coerced dispatch status` and `coerced attempt status` of `internal/role/testdata/dispatch/oracle.json` are replayed as intentionally changed by `TestDispatchLedgerOracle`, and the `status coercion error` case of `TestDispatchLedgerStoredValidation` now expects the invalid status. Pinned by `TestDispatchReceiptStatusIsALiteralString`).
- Supersedes known-defects.md, section "Found by the CRW-574 created-check fix for archived children", item beginning "The created check proves a real child of this session": now port: fixed (the created check compares the host's first user message of the child, the native database's `first_user_message`, with the attempt: the message the issued native call delivered starts a line with this attempt's `[CRW-DISPATCH:<dispatch>:<attempt>]` marker, so a child spawned for another attempt or outside any dispatch is refused once the host shows its first message. When the host shows none, the child is recorded `unverified` and cannot complete an independent review until a later created report correlates it. The marker alone does not tie the child to the issued call, because the caller writes it into the call's message and a child made before the issuance (hook off, an older call) can carry it: the spawn hook records the time it issued the attempt (`issuedAtMs`), and the child counts as the call's result (`attempt-marker`) only when the native database's creation time of the child (`created_at_ms`, else `created_at`) is not before that time and no other child of the session carries the marker from the issuance on. A child created before the issuance is refused; a host with no creation time, an attempt issued before the time was recorded, an unreadable marker query or a second marked child leave the child `unverified`. The host's spawn result in the parent's rollout names the child by `task_name` only, not by its thread id, so it is not used as the tie. Pinned by `TestDispatchReceiptCorrelatesTheIssuedChild`, `TestDispatchReceiptMarkerAloneDoesNotProveTheIssuedCall` and `TestDispatchReceiptUnverifiedChildCannotCompleteAReview`).
- A created report names nothing of the native call, so a report could carry an arbitrary agent for an issued attempt whose recorded `toolUseId` belongs to another call (source `fallback-dispatch.ts:171-176`, which reads no tool id); port: fixed (a created report that names `toolUseId` must name the one the spawn hook recorded, else it is refused; a replay of the same report is idempotent and writes the same bytes, and a receipt already `attempt-marker` for that child is kept as recorded when the host later shows less (the first message or settings no longer visible), so the replay never weakens it. Pinned by `TestDispatchReceiptCorrelatesTheIssuedChild` and `TestDispatchReceiptReplayKeepsAConfirmedReceipt`).
- The ledger keeps the requested candidate, the issuance flag and the caller's `observedModel` as unrelated fields, so the record cannot tell what was requested, what was issued, which child the host witnessed and what the host shows from what the caller claims (source `fallback-dispatch.ts:171-176`); port: fixed (an accepted created report writes one `receipt` on the attempt: the candidate pair, the issuance with its tool id, the child with its parent and the witnessing host surface, the correlation (`attempt-marker`, `unverified` or `unissued`), the caller's `observedModel` kept as a claim, and the model and effort the native thread row shows, or `unobservable`. Issuance is never read as provider or model proof).
- A child spawned while the spawn hook was off has no issuance and could only be adopted silently or left unrecorded (source `fallback-dispatch.ts:171-176`); port: fixed (a created report of an unissued attempt that carries `reconciliation` evidence records the real child of this session with receipt correlation `unissued`; nothing is deleted or spawned again, and such a child cannot complete an independent review (`createdCheckComplete` refuses a reviewer's complete whose receipt is not `attempt-marker`). Pinned by `TestDispatchReceiptUnissuedChildIsReconciled`).
- The recorded fixture `cli__subagents__dispatch_created_complete` claimed by CRW-530 moves to this issue's notes file: its created step is now the issuance refusal, which precedes the host read.
