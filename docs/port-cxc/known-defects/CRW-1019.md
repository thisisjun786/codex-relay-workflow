# CRW-1019 — the producer-temporary classifier and an empty final name

Source: the CRW-672 evaluation of PR #648 (P1, found by reading the code; not reproduced by execution). The defect is the port's own: the state-copy classifier of the Go port (internal/runtime/install/migrate/classify.go, classifyProducerTemp, and inventory_intermediate_test.go). The CXC writers always put a non-empty final name before the pid (source subagent-evidence.ts:221, state.ts:387,625, both of which write <final>.<pid>.<uuid|ms>.tmp), so an empty final name is ordinary data in the user evidence tree. The oracle files named here are the writers, not the classifier. The Go lines were at classify.go:588-603 and :166-168 when the issue was filed; they are classify.go:652-675 and :179 at the fix commit.

- classifyProducerTemp accepted <head>.<uuid>.tmp for any non-empty head, so .123.<uuid>.tmp (an empty final name before pid 123) was skipped as an intermediate in evidence/** while the millisecond shape .123.<ms>.tmp was copied as ordinary data; a user file under the same name was therefore dropped from the state-copy plan depending on its UUID shape; port: fixed (the UUID branch now requires the same non-empty final name before a pid as the millisecond branch does; pinned by TestInventoryProducerTempFinalName with the pid-then-uuid and millisecond pairs, and by TestInventoryUserTmpIsCopied and TestInventoryProducerTmpInEvidenceIsSkipped in inventory_intermediate_test.go).
- The millisecond shape .123.<ms>.tmp with an empty final name is ordinary data and is copied; port: kept (it was already correct on dev; the same tests pin it).
- A producer temporary with a non-empty final name, such as evidence/x/a.json.123.<uuid>.tmp, is still skipped as an intermediate; port: kept (the same tests pin it, and the UUID and millisecond shapes now agree on it).
- The inventory rows that match <final>.<uuid>.tmp outside evidence (sources/, subagents.json, model-catalog.json) read a name such as .123.<uuid>.tmp as the final name .123 with no pid; they are not changed by this issue (no CXC writer writes a dotfile final name there); port: kept (not covered by a test in this record).
