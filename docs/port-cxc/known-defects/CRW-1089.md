# CRW-1089 — recall repeat penalty counted what the hook did not show

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/recall/src/hook.ts:325-327,382,433,518-534,563-586` and `index-db.ts:182-205`; the Go side is `internal/recall/hookcontext.go`, `internal/recall/hook.go` and `internal/recall/hitcount.go`. Found by the 10-10 CXC improvement review, A8-10.

- The oracle raised the history of every selected entry as soon as it was selected, before the character budget cut entries from the block and before the summary index was read, so an entry the model never saw was penalized in the next session (source `hook.ts:433,518-534`; recorded tiny-budget and summary-error builders); port: fixed (selection, rendering and counting are three steps. `hookContextDemote` only reads the history and closes the store before it returns; `renderCwdBlock` reports how many leading entries the block carries, and `CwdContextResult.Refs` names exactly those; `recallHookRun` writes the answer and only after the write succeeded counts `Refs`, in `recallHookCountHits`. Of five selected entries, the two the budget admits are counted; a summary failure or an empty block counts nothing. Pinned by `TestHookContextCountsOnlyTheRenderedEntries`, `TestHookContextSummaryFailureAndEmptyBudgetCountNothing`, `TestSessionStartCountsTheEntriesItWrote`, `TestSessionStartCountsNothingWhenTheAnswerWasNotWritten`, and the recorded builders 92, 97, 104 and 106 of `TestHookContextOracle`, whose results are in `testdata/hookcontext/port-fixed.json`).
- A character budget that fit no entry still reported `hits` with empty text (source `hook.ts:382,534,586`; recorded tiny-budget builder); port: fixed (the result is `empty`, so the session-start answer carries no cwd block and nothing is counted; recorded builder 86).
- A bump failure returned the neutral selection even after earlier refs were written, and a later ref's failure left the earlier counts committed (source `hook.ts:433-438`, `index-db.ts:182-205`; recorded bump-error selection); port: fixed (`bumpHitCounts` runs in one `BEGIN IMMEDIATE` transaction, so a failure part way counts none of its refs; a history that cannot be written is ignored after the answer is out, so it never hides a valid block. Pinned by `TestHitCountsWriteErrorKeepsNoPartialCommit` and `TestSessionStartHistoryFailureKeepsTheContextAndCountsNone`; the recorded bump-error builders 96 and 105 now show the block selected by the counts that were read).
- A retry of counting could count twice; port: fixed (each hook invocation counts under one random event identity: `recordHitEvent` writes the event and the counts in the same transaction and does nothing for an event it already holds, and `recallHookCountHits` retries a failed attempt up to three times under that identity. The event row stays after counting, so a repeated `Bump` of the sidecar store with the same event changes nothing while the row is kept; rows are removed by an age bound of 24 hours and a bound of 1,000 rows (`recall_hit_events`, created inside the first counting transaction). Pinned by `TestHitEventCountsOnce`, `TestSidecarStoreBumpCountsAnEventOnce` and `TestHitEventsAreBounded`). Writing to stdout is not taken as proof that the model read the block; the repeat penalty of the next session start stays as it was.
- A present empty thread id was one deduplication key while its history ref fell back to the file (source `hook.ts:563,572`; recorded empty-id fallback hits); port: fixed (an entry is keyed by `hitCountRef`, `thread:<id>` or `file:<path>`, the ref the history uses, and an empty id is no id: two files with empty ids are two entries, and one file seen with and without an id is one. `TestHookContextEmptyThreadIDIsAbsent`).
- Dates were compared as strings and the fallback timestamp was sliced to ten UTF-16 units without checking that it was a date, so a text such as `2026-13-45` or `z` could be the newest date and the "as of" label (source `hook.ts:529,579,582`; recorded non-ISO date label); port: fixed (`hookContextDate` accepts ten characters that name an existing calendar date, entries are labelled with that normalized date or `[undated]`, and the label names the newest date among the entries shown, compared as dates; with no date to name among the entries shown (even when an entry the budget left out has one) the staleness notice stays and says `an unknown date`, and the block is rendered again so that the longer notice fits the budget and the refs stay the entries shown. `TestHookContextDatesAreParsedBeforeTheyAreCompared`, `TestHookContextNoticeNamesOnlyShownDates`; recorded builders 107 and 108).
- Clipping below three units used a negative slice end and kept most of the input, and a negative count sliced from the end (source `hook.ts:325-327`; recorded negative and tiny clip budgets); port: fixed (`hookContextClip` clamps the bound before it slices, reserves three units for the ellipsis when it cuts, and below three units returns that many dots; `RecallBudget.valid` clamps negative counts to zero, so a negative entry count or character budget asks for nothing. `TestHookContextClipAndCountsAreBounded`; recorded clip rows 19-22, 28-31, 37-40 and 46-48, and builders 86 and 87).
