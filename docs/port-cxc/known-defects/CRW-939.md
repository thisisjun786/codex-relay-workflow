# CRW-939 — skill-scripts-node changed-path check and the Node-run exception

Source: these are not oracle behaviours. They are defects of this repository's own CI, found while
evaluating the job CRW-353 added against CXC v0.2.40 (commit `3c1459ac`), whose own gate the job
follows. The port's files are `.github/workflows/ci.yml` (the `skill-scripts-node` job: its
checkout and its "Decide from the changed files whether the staged skills changed" step) and
`internal/dev/ci/workflow_test.go` (`pythonInWorkflow` and the tests that hold the job).

## Defects

- The job's changed-path check compared a pull request's base tip with its head directly
  (`git diff --name-only "${base}" "${head}" -- "${SKILLS_ROOT}"`), so a staged-skill change that
  only the base branch carried read as this pull request's, and a branch that carried the same
  staged-skill change as its base read as no change at all, ending the job before it installed Node
  and ran the tests (source: the two-tip comparison, not the oracle's shape; `.github/workflows/ci.yml`
  before this issue); port: fixed (a pull request is compared from its merge base with the three-dot
  range `"${PR_BASE_SHA}...${PR_HEAD_SHA}"`, a push still compares the commit it replaced with the
  one it added, a manual dispatch still runs the tests, and the job's checkout already fetched full
  history; pinned by `TestWorkflow_the_skill_paths_compare_a_pull_request_from_its_merge_base` and
  `TestWorkflow_the_skill_paths_keep_the_push_range_and_run_on_a_dispatch`).
- The workflow detector admitted a path below a skills root, and a skills-root value, in any
  workflow whose job happened to be named `skill-scripts-node`, because it tracked the job name
  alone and never the file, so a second workflow could run a skill script by copying the job's name
  (source: the name-only exception, not the oracle's shape; `internal/dev/ci/workflow_test.go`,
  `pythonInWorkflow` before this issue); port: fixed (the exception is keyed by file and job
  together — `.github/workflows/ci.yml`'s `skill-scripts-node` — pinned by
  `TestWorkflow_the_skill_scripts_exception_is_one_file_and_one_job`,
  `TestWorkflow_a_copied_skill_scripts_node_job_in_another_workflow_is_a_finding` and the
  `TestWorkflow_python_detector` rows).
