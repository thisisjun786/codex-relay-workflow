# CRW-1149 — unset restores only a key crw still owns

Source: CXC v0.2.40, commit 3c1459ac — `plugins/codexclaw/components/config-guard/src/config-set.ts` (the unset branch at :90-119 checks only that a record exists, then restores its prior value) and `cli.ts` (:107-111). The Go port is `internal/runtime/install/configguard/configset.go` (`ApplyManagedKey`, `configUnsetRefusal`, `ReleaseManagedKey`), `deactivate.go` (`DecideKeyRestore`) and `internal/runtime/install/config_cmd.go`. The finding is the 10-10 CXC improvement review A7-04; CRW-866 had fixed only the lock.

- Unset restored the recorded prior value whenever a record existed, without checking that crw set the key or that the live value was still the one crw applied, so a user's later `false`, or a string such as `'user-choice'`, was overwritten with the old value and the command exited 0 (source `config-set.ts:90`); port: fixed (unset decides with the deactivation's table, `DecideKeyRestore`: crw set the key, the live value read semantically is the applied value, and an originally absent key's absence is proven when config.toml changed since; otherwise it writes nothing, keeps the record, exits 1 and names the reason (not set by crw, missing, changed or unverifiable) and the manual next step. `crw install config unset <key> --release` drops the record and leaves config.toml as it is. Pinned by `TestConfigUnsetRefusesAKeyCrwNoLongerOwns`, `TestConfigUnsetRefusesAnUnprovenOriginalAbsence`, the control `TestConfigUnsetRestoresAKeyCrwStillOwns`, and `TestConfigUnsetRefusalAndReleaseThroughTheCLI`).
- The live value and the applied value were compared as text; port: fixed (`DecideKeyRestore` also accepts the same TOML value written another way, through `tomledit.SameValue`; text that is equal stays equal, so the recorded decision table replays unchanged).
- Supersedes known-defects.md, section "CRW-348 — managed config command port", item beginning "Unset restores the recorded prior value without checking": now port: fixed (see the first item; the no-op suffix of an unset now says the record was cleared instead of `already set; recorded`).
- An unset after an interrupted set adopted a key the user wrote as crw's, because the recovery took a matching value as proof (found by the pre-merge evaluation of c3081dc3); port: fixed (see CRW-1153.md, the recovery proves the write with a done record; pinned by `TestKilledBeforeTheKeyIsWrittenIsNotAdoptedWhenTheUserSetsIt`).
- The first listing of a disable that had no row for an owned flag released the install (see CRW-1145.md; pinned by `TestOwnedFlagMissingFromTheFirstListingKeepsTheInstallLive`).
