# CRW-1183 — a refused word in the temporary path turns allow rows of the shell guards into denies

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no shell write reader). The Go side is
`internal/pabcd/hook/worktreedel_program.go` (`worktreeDelRemovesToken`, `worktreeDelStartsToken`, `worktreeDelRunTimeToken`) and the
tests `shellwrite_repro_test.go`, `shellwrite_crw941_test.go` and `githubpost_test.go`.

- The worktree deletion guard refuses a python3, node or ruby program that holds a word naming a removal, a program start or a
  run-time call, wherever the word stands, also inside a string (CRW-1028 accepted that cost). A path is such a string: a
  command that names a fixture under `/home/jun/code-worktrees/...` carries the word "code", and one under a temporary directory
  named after a test carries "exec" or "delete" (`python3 -c 'open("/home/jun/code-worktrees/x","w")'` is a deny). Run with
  TMPDIR below such a directory, `TestReproductionRows` (272 rows) and `TestCRW941ShapesThroughTheThreeEntryPoints` (the sed
  `--expression`, `--expr`, `--e` and POSIXLY_CORRECT rows) failed with worktree deny where the rows expect allow; the lanes' managed
  worktrees live under `code-worktrees`. The earlier cause given for the failure, that ruby is not installed, was wrong: no row starts an
  interpreter, the three gates read the command text only, so the perl and ruby rows (CRW-765-33) need none. port: kept (the
  production rule is unchanged: freeing a path from the word rule widens what the guard allows and needs its own security review;
  the cost is that a managed worktree's own path in a program string is refused, which is the safe direction. The tests
  fix the environment instead: `neutralTempBase` leaves TMPDIR when neither it nor its symlink-resolved path holds a refused word,
  and otherwise sets it to `/tmp` or `/var/tmp`; with neither clean and writable the test is skipped with the reason, or fails when
  `CRW_TEST_REQUIRE_CLEAN_TMPBASE` is set. `cleanTempDir` makes the fixtures without the test name in them, `requireCleanFixture` checks
  the final fixture paths as written and as resolved. `TestGuardRowsRunWhereTMPDIRHoldsARefusedWord` runs the three tests in a child
  process with TMPDIR under a directory named `code-worktrees-*` and fails on any skip, so the rows are shown to run; the helper's word
  list and symlink handling are pinned by `TestRejectedPathTokenNamesTheWordsTheGuardRefuses` and `TestNeutralTempBase*`).
- `TestGitHubPostGuardRefusesABodyFileOutsideTheRoots` assumed that the checkout's `go.mod` lies outside `/tmp` and `/var/tmp`; the GitHub post
  guard always trusts those two roots, so a checkout under either reads the file and the expected refusal never came. This is a
  second cause, not the word rule. port: fixed (the test takes the file from `/etc/hosts` when the checkout, as written or resolved,
  lies under a trusted root, and skips with the reason only when that file is not a regular file outside the roots too).
- The same TMPDIR also fails `internal/manage` (`TestChildCheck*`, `TestHostRead*`: the unix socket path under a long TMPDIR exceeds the
  address limit, `dial unix ...: invalid argument`), while `internal/harness` and `internal/gui` pass with it. That is another cause
  (socket path length, which `heavy_slot.sh` already guards by keeping the lane TMPDIR short) and is outside this issue. port: pending.
- The pre-merge evaluation of 9201b469 found two P0 and two P1 (reported on this record too) in the CRW-1165 and CRW-1187 changes of the same lane; they are fixed there (known-defects/CRW-1165.md and CRW-1187.md, "Pre-merge evaluation of 9201b469"). The one that touches this issue's own tests: the end-to-end probe of the PEP 701 form needs Python 3.12 or later, and is skipped with the reason on an older interpreter, the static refusal staying asserted. The temporary-base fix of this issue is unchanged.
