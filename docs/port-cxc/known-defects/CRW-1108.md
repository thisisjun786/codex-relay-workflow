# CRW-1108 — an explicit --session mutation is bound to the native session, and the state boundaries take canonical ids only

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/orchestrate-cli.ts:489` (native identity checked for implicit status only), `plugins/codexclaw/components/pabcd-state/src/state.ts:380` against `:624` and `:672` (ensureState refuses a non-canonical id, writeState and withSessionLock sanitise it), and `:780-787` (readInterviewEvents). The Go side is `internal/pabcd/cli/orchestrate_status.go` (`NativeSessionRefusal`, and `nativeSessionMismatch`, called by `RunOrchestrateRead`), `internal/harness/pabcd_cli.go` (the terminal rows that supply the native environment, `nativeSessionRefused`), `internal/pabcd/state/write.go` (`writeState`), `internal/pabcd/state/lock.go` (the session lock) and `internal/pabcd/state/ledger.go` (`AppendInterviewEvent`, `ReadInterviewEvents`). Found by the 10-10 review B2-01 (notes/B2.md): with native CODEX_THREAD_ID 0190cafe-0279-7000-8000-000000000279, `crw pabcd orchestrate P --session 0190cafe-0279-7000-8000-000000000280 --cwd repo-B` changed the foreign session IDLE->P with exit 0.

- `runOrchestrateCli` corroborates the native session only for an implicit `status`; an explicit `--session` of a mutation is checked for its shape and for its file, so a command run inside one native Codex session changes a parent's, a sibling's or an earlier session's FSM with exit 0, against SESSION-IDENTITY-01 (`orchestrate-cli.ts:489`; Go `internal/pabcd/cli/orchestrate_status.go`); port: fixed (when CODEX_THREAD_ID is set and nonempty, a mutating verb whose `--session` is not that id, the terminal key `cli` included, is refused with exit 1 and "Nothing was written." before the attestation-error branch, the lock, the state file and the ledger; the absorbed resolver `host.ResolveNativeSession` confirms the subject where it can and the refusal says so, but a lookup that fails is not a refusal, so the id comparison is the whole alias guard and a terminal that cannot reach the native database is not broken. The same guard (`cli.NativeSessionRefusal`, called by the terminal rows of `internal/harness/pabcd_cli.go` after their parse and before the library takes a lock or writes) binds every other terminal command that changes a session: `memory allow-write`, `scan record`, `review-round open` and `abort`, `receipt test`, `evidence resolve`, `metric record`, `ingest` and a `kind` that names a kind, `divergence mode on|off` and `candidate add`, and `loop init --session` with the loop verbs that change a bound plan; each answers the refusal with exit 1 on the stream of its other refusals. A terminal without CODEX_THREAD_ID keeps its explicit id and the reserved key, `status` and the other reading verbs (`metric show`, `divergence candidate list`, `review-round show`) stay reads of any id, `reset` (the approved maintenance command) is not guarded, and hooks never receive the native environment, because a subagent's CODEX_THREAD_ID is not the root session id of its hook payload. Pinned by `TestOrchestrateMutationRefusesAnotherNativeSession`, `TestOrchestrateMutationKeepsTheOwnNativeAndTheStandaloneTerminal`, the row reproduction `TestPabcdOrchestrateRowRefusesAForeignSessionUnderANativeOne` and `TestPabcdTerminalMutationsRefuseAForeignSessionUnderANativeOne`, which checks for each command that the tree, the lock and the foreign session's grant are unchanged).
