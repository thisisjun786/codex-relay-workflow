# CRW-1108 — an explicit --session mutation is bound to the native session, and the state boundaries take canonical ids only

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/orchestrate-cli.ts:489` (native identity checked for implicit status only), `plugins/codexclaw/components/pabcd-state/src/state.ts:380` against `:624` and `:672` (ensureState refuses a non-canonical id, writeState and withSessionLock sanitise it), and `:780-787` (readInterviewEvents). The Go side is `internal/pabcd/cli/orchestrate_status.go` (`nativeSessionMismatch`, called by `RunOrchestrateRead`), `internal/harness/pabcd_cli.go` (the terminal row that supplies the native environment), `internal/pabcd/state/write.go` (`writeState`), `internal/pabcd/state/lock.go` (the session lock) and `internal/pabcd/state/ledger.go` (`AppendInterviewEvent`, `ReadInterviewEvents`). Found by the 10-10 review B2-01 (notes/B2.md): with native CODEX_THREAD_ID 0190cafe-0279-7000-8000-000000000279, `crw pabcd orchestrate P --session 0190cafe-0279-7000-8000-000000000280 --cwd repo-B` changed the foreign session IDLE->P with exit 0.

- `runOrchestrateCli` corroborates the native session only for an implicit `status`; an explicit `--session` of a mutation is checked for its shape and for its file, so a command run inside one native Codex session changes a parent's, a sibling's or an earlier session's FSM with exit 0, against SESSION-IDENTITY-01 (`orchestrate-cli.ts:489`; Go `internal/pabcd/cli/orchestrate_status.go`); port: fixed (when CODEX_THREAD_ID is set and nonempty, a mutating verb whose `--session` is not that id, the terminal key `cli` included, is refused with exit 1 and "Nothing was written." before the attestation-error branch, the lock, the state file and the ledger; the absorbed resolver `host.ResolveNativeSession` confirms the subject where it can and the refusal says so, but a lookup that fails is not a refusal, so the id comparison is the whole alias guard and a terminal that cannot reach the native database is not broken. A terminal without CODEX_THREAD_ID keeps its explicit id and the reserved key, `status` stays a read of any id, and hooks never receive the native environment, because a subagent's CODEX_THREAD_ID is not the root session id of its hook payload. Pinned by `TestOrchestrateMutationRefusesAnotherNativeSession`, `TestOrchestrateMutationKeepsTheOwnNativeAndTheStandaloneTerminal` and the row reproduction `TestPabcdOrchestrateRowRefusesAForeignSessionUnderANativeOne`).
- Supersedes known-defects.md, section "Found by the session state writes port", item beginning "`ensureState` refuses an id that `sanitizeKey` would rewrite": now port: fixed (`WriteState` and the session lock refuse an id that sanitising would rewrite, and the empty id, with `ErrNonCanonicalSessionID` before anything is created, as `EnsureState` already did, so `a/b` no longer replaces `a-b`'s file or waits on its lock and `""` no longer writes `missing.json`; the recorded cases `write_alias_ids`, `write_noncanonical_id` and `lock_key_is_sanitised` are replayed with the refusal in `internal/pabcd/state/oracle_writes_test.go`; the read side refuses it as well: `ReadStateFile` answers `ErrNonCanonicalSessionID` before opening anything, so `ReadStateStrict` marks `a/b` and the empty id unreadable instead of returning `a-b`'s or `missing`'s phase and grants; pinned by `TestStateBoundariesRefuseNonCanonicalSessionIDs` and `TestStateReadsRefuseNonCanonicalSessionIDs`).
- Supersedes known-defects.md, section "Found by the session ledger port", item beginning "`readInterviewEvents` accepts a row on its `event`, `roundId` and `contradictionCount` alone": now port: fixed (`ReadInterviewEvents` counts a row only when it names the session asked for and carries `ts` and a numeric `highContradictionCount` besides the oracle's three fields, and a non-canonical or empty id reads no rows; `AppendInterviewEvent` refuses such an id, so two ids no longer share one scan ledger.
