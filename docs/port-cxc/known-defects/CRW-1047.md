# CRW-1047 — wrapper options that take a value outside the table hide a Node test (CRW-983 residue)

Source: the port's own skill-scripts-node reader, not an oracle behaviour. The defect is the fail-open of the
CRW-983 wrapper reader found by the CRW-983 evaluation (head 08bbd1b11), in `internal/dev/ci/workflow_test.go`:
`wrapperRunsNodeTest`, `wrapperWalk`, `envSplitCluster`, `shellWrapperArgs` and `commandRunsNodeTest`. The
tests that hold it are `TestWorkflow_a_wrapper_option_with_an_unlisted_value_hides_no_node_test` and the
CRW-983 tests beside it. The read-only CRW-983 record stays as it is.

- `sudo --user root node --test`: `--user` is not in the table of value-taking options, so `root` was read as the
  program and the Node test was not seen; port: fixed (an option the table does not list is judged under both
  readings, the option alone and the option with the next word, and a node test under either reading is a finding).
- `env --unset HOME node --test`: the same reason, with `HOME` read as the program; port: fixed (the same two-reading
  rule for an unlisted env option).
- `env -S 'node --test'`: the value of `-S` was skipped, so the command line it holds was never read; port: fixed (the
  value of `-S`, `-Svalue`, `--split-string=value`, its GNU abbreviations (`--split`, `--s`, with a separate value or
  `=value`) and the `-iS` cluster is split into words by env's own rules (`envSplitString`), the words replace the option
  in env's argument list with the words after the value following them, and env's walk reads that one argv; a value the
  splitter cannot read whole is a finding).
- Unknown dash-option judged under both readings (the general rule of the first three items): the option alone, and the
  option with the next word, each read as a command; port: fixed (the same walk; a `--` ends the wrapper's options; an
  `=` in the option's word does not change the two readings).
- `env -S 'echo' node --test`: the old reader skipped the `-S` value and read `node --test` as the program, so it was a
  finding; env runs `echo node --test`, which runs no Node test, so the new reader accepts it; port: intentionally-changed
  (the finding was a reading mistake, not a guard: the words after the `-S` value are the arguments of its command, and
  the test pins the echoed form as no finding).
- Controls kept as non-findings: `env FOO=1 echo node --test` and a log line that only names `node --test`, behind a
  wrapper's unlisted option or in an `-S` value, as `echo`'s or `printf`'s argument; port: kept (the reader still reads
  the printed text as a word, never as a command, and `TestWorkflow_a_wrapper_option_with_an_unlisted_value_hides_no_node_test`
  holds these rows).
- A wrapper's `--` before its program, `sudo -- echo node --test`: the old reader read `echo` as the program and the
  new reader ends the options at `--` and reads `echo`; port: kept (no finding, as before).
- `env -iSnode --test`, a `-S` value attached to a cluster after env's flags: the whole word was skipped as one flag, so
  the Node test after it was not read; port: fixed (the cluster is read by `envSplitCluster`).
- Known limit, kept: the table lists only the options it listed at CRW-983, and a listed option takes exactly the next
  word. An attached short value such as `sudo -uroot` is an unlisted word and is read both ways, so it is a finding when
  the next word is a Node test. port: kept (both readings cover the attached form; no table entry was added for it).

## Fix round 1 (the independent verification of 93235dfa5)

- `env -S 'node\_--test'` and `env -S 'node --test\c ignored'`: the first value was read as a Bash script and missed; env
  splits its value itself (`\_` separates words outside quotes, `\c` ends the value), and both run `node --test`, checked
  with GNU env 9.7 and a fake `node` that prints its arguments; port: fixed (`envSplitString` implements the splitter:
  blanks, `'...'`, `"..."`, `#` comment, the escapes `\_ \c \f \n \r \t \v \\ \# \$ \" \'`).
- `env -S 'echo hello; node --test'`: the old reader took `;` as a command separator and reported a second command; env
  runs `echo` with the arguments `hello;`, `node` and `--test`, which prints the text and runs no Node test; port:
  intentionally-changed (no finding; the value is one argv, not a script, and `env -S 'echo; node --test'` is no finding
  for the same reason).
- Unsupported syntax in an `-S` value fails closed: an unterminated quote, a trailing backslash, an escape env rejects
  (`\x`), `\c` in double quotes, and a `$` outside single quotes (a `${NAME}` expansion needs env's environment); port:
  fixed (each is a finding).
- `sudo --foo=value root node --test`: the `=` shortcut read the word as a complete option and never judged the second
  reading, so `root` as the option's value hid the test; the coordinator's criterion (c2) has no `=` exception; port:
  fixed (an unknown option is judged under both readings whatever its word looks like). Known limit, kept: because the
  second reading skips a word after `--foo=value`, `sudo --foo=value echo node --test` is a finding (the skipped word
  is `echo`); this is the price of the fail-closed reading.
- `env --split 'node --test'`, `env --s 'node --test'`, `env --sp='node --test'`: GNU env accepts any non-empty prefix of
  `--split-string` (no other env long option starts with `s`), and the old reader recognised only the full spelling;
  port: fixed (`envSplitLong`, with a separate value and with `=value`).
- The tests that hold these: `TestWorkflow_env_split_string_is_read_as_env_splits_it`,
  `TestWorkflow_an_unknown_option_with_an_equals_is_read_both_ways`, `TestEnvSplitString` (the splitter's table, the
  expected words taken from GNU env 9.7) and the amended rows of
  `TestWorkflow_a_wrapper_option_with_an_unlisted_value_hides_no_node_test`.

## Fix round 2 (the independent verification of 0649b25b5)

- `env -S '\_node --test'`, `env -S 'FOO=1\_\_node --test'` and `env -S '\c' node --test`: the splitter marked a word
  as started at every backslash, so a `\_` or `\c` where no word had started added an empty word, env's walk read that
  empty word as the program and the Node test was not seen; GNU env 9.7 runs the fake `node` with `--test` for all
  three; port: fixed (a word starts only at a character, a character escape or a quote, so only an empty pair of quotes
  is an empty word; `env -S "'' node --test"` stays no finding, since env runs the empty program).
- `timeout -- 10 node --test`: the round-1 `--` rule judged the words after `--` as the command, so the duration `10`
  was read as the program; a regression from the base 7d23cd46f, where the walk skipped the duration; port: fixed
  (timeout's first word that starts no option is its duration, after `--` as well, and the command follows it;
  `timeout -- 10 echo node --test` is no finding).
- `timeout inf node --test`, `timeout .5 node --test`: the duration was recognised only by a leading digit, so a
  duration spelled otherwise was read as the program; both run the fake `node` with `--test`; port: fixed (the first
  non-option word is the duration whatever its spelling, and only that one word: `timeout 10 20 node --test` reads `20`
  as the program).
- The tests that hold these: `TestWorkflow_a_separator_escape_and_a_timeout_duration_hide_no_node_test` and the
  added rows of `TestEnvSplitString`.

## Fix round 3 (the pre-merge evaluation of a7cfde55)

- `env -S '-i -S -i -S ... -i'` (40 repetitions): every split re-entered `wrapperRunsNodeTest` with a fresh visited set
  and no depth check, and each unknown `-i` is read both ways, so the walk branched 2^n times and no depth guard was
  reachable; the removed dev-side reader was linear on this input; port: fixed (the splits of one reading share one
  walk: the visited argument lists are walked once, and each split is one more level of depth against
  `shellMaxDepth`, past which the run is a finding). The 40-repetition line ends at once with a finding.
- `env -S "9=1 node --test"`, `env --unset HOME '9=1' node --test`, `env 9=1 node --test`, `env -- 9=1 node --test`: env
  takes any `NAME=VALUE` word with a non-empty NAME as an assignment, and the reader used the shell's identifier rule, so
  `9=1` was read as the program and the Node test behind it was not seen; the same gap was in the removed dev-side
  reader; port: fixed (`envAssignment`: a non-empty name without `=`; before the program a word that starts with `-` is
  an option, after `--` every such word is an assignment). `env 9=1 echo node --test` and `env FOO=1 echo node --test`
  stay no finding.
- The tests that hold these: `TestWorkflow_an_env_assignment_need_not_be_a_shell_identifier` and
  `TestWorkflow_repeated_env_split_options_are_read_in_bounded_work`.

## Fix round 4 (the verifier of c96ff3c6)

- `env` (or `sudo`, `timeout`) followed by thousands of unknown options: the state key of the wrapper walk joined the
  whole remaining argument list at every option, so the walk copied O(n) words per option and allocated O(n^2) (about
  347MB for 4000 options, against 0.4MB before round 3; 1.5s for 8000 options); the removed dev-side reader was
  linear; port: fixed (the argument list is a chain of interned nodes, so a walk state is the wrapper name, the
  duration flag and a node number, a constant to name however long the list is, and an env split chains its words in
  front of the shared rest without copying it). The visited set and the depth bound across splits are unchanged.
  `TestWorkflow_a_long_wrapper_option_list_is_walked_in_linear_work` holds it (4000 unknown options stay under 16MB for
  env, sudo and timeout).
