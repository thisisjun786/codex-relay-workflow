# CRW-1047 — wrapper options that take a value outside the table hide a Node test (CRW-983 residue)

Source: the port's own skill-scripts-node reader, not an oracle behaviour. The defect is the fail-open of the
CRW-983 wrapper reader found by the CRW-983 evaluation (head 08bbd1b11), in `internal/dev/ci/workflow_test.go`:
`wrapperRunsNodeTest`, `envSplitRuns`, `envSplitCluster`, `shellWrapperArgs` and `commandRunsNodeTest`. The
tests that hold it are `TestWorkflow_a_wrapper_option_with_an_unlisted_value_hides_no_node_test` and the
CRW-983 tests beside it. The read-only CRW-983 record stays as it is.

- `sudo --user root node --test`: `--user` is not in the table of value-taking options, so `root` was read as the
  program and the Node test was not seen; port: fixed (an option the table does not list is judged under both
  readings, the option alone and the option with the next word, and a node test under either reading is a finding).
- `env --unset HOME node --test`: the same reason, with `HOME` read as the program; port: fixed (the same two-reading
  rule for an unlisted env option).
- `env -S 'node --test'`: the value of `-S` was skipped, so the command line it holds was never read; port: fixed (the
  value of `-S`, `-Svalue`, `--split-string=value` and the `-iS` cluster is read as a command line that env runs, with
  env in front of each of its commands, and the words after the value appended to the last one; a value the reader
  cannot read whole is a finding).
- Unknown dash-option judged under both readings (the general rule of the first three items): the option alone, and the
  option with the next word, each read as a command; port: fixed (the same walk; a `--` ends the wrapper's options, and
  an option with an `=` in its word takes no next word).
- `env -S 'echo' node --test`: the old reader skipped the `-S` value and read `node --test` as the program, so it was a
  finding; env runs `echo node --test`, which runs no Node test, so the new reader accepts it; port: intentionally-changed
  (the finding was a reading mistake, not a guard: the words after the `-S` value are the arguments of its command, and
  the test pins the echoed form as no finding).
- Controls kept as non-findings: `env FOO=1 echo node --test` and a log line that only names `node --test`, behind a
  wrapper's unlisted option or in an `-S` value, as `echo`'s or `printf`'s argument; port: kept (the reader still reads
  the printed text as a word, never as a command, and `TestWorkflow_a_wrapper_option_with_an_unlisted_value_hides_no_node_test`
  holds these rows).
- A wrapper's `--` before its program, `sudo -- echo node --test`: the old reader read `echo` as the program and the
  new reader ends the options at `--` and reads `echo`; port: kept (no finding, as before).
- `env -iSnode --test`, a `-S` value attached to a cluster after env's flags: the whole word was skipped as one flag, so
  the Node test after it was not read; port: fixed (the cluster is read by `envSplitCluster`).
- Known limit, kept: the table lists only the options it listed at CRW-983, and a listed option takes exactly the next
  word. An attached short value such as `sudo -uroot` is an unlisted word and is read both ways, so it is a finding when
  the next word is a Node test. port: kept (both readings cover the attached form; no table entry was added for it).
