# CRW-1304 — the integration target remote ref is recorded, compared and read between pushes (with CRW-1302)

Source: CRW's own design, not the CXC oracle. CXC v0.2.40 (commit 3c1459ac) has no integration branch, no `dag-integrate-push` and no fault class for a moved target, so there is no oracle pointer. The Go side is `internal/relay/store/dag_integration_targets.go` (the append-only zone table and its typed writers), `internal/relay/dagsched/integration_target_record.go` (the record), `integration_target_check.go` (the one-shot check), `integration_target_receive.go` (the acknowledgement comparison of CRW-1302), `integration_target.go` (the push's comparison, restated for a recorded target), `internal/relay/delivery/ack_target.go` (the hook the acknowledgement calls), `internal/relay/integrate/target_cli.go` and `cli.go` (the commands and the documents) and `internal/relay/argparse/specs.json`. CRW-1301 chose A + D(i) and left the record of the target and the periodic read to this issue (B), and left the receive and acknowledgement comparison to CRW-1302. The fault class `integration_target_moved` of CRW-1301 is reused; its evidence gains `source` (`push`, `check` or `receive`). Jun's standing rule decides the open choices: a reversible condition warns, records and fails open, and only an input error is refused.

- The relay recorded only the local integration ref, so which remote branch it is pushed to was nowhere in the store (CRW-1301); port: fixed (the append-only table `dag_integration_targets` holds a `target` row per record and an `observed` row per head read; `dag-integration-target-record`, the `--remote` and `--remote-ref` flags of `dag-integrate` and `dag-integrate-push` write the target, a repeat of the newest record writes nothing and a changed remote or remote ref appends a row. The table is a new table appended to the zone ledger, not a new stage of `dag_integration_stages`, whose CHECK on the stage cannot be widened on a store that already exists. Pinned by `TestIntegrationTargetZoneGuards`, `TestIntegrationTargetZoneNullAndNoReplaceGuards`, `TestIntegrationTargetZoneUpgradeFromOldZone`, `TestRecordIntegrationTargetAppendsOnlyChanges`, `TestRecordTargetAppendsOnceAndRefusesBadInput`, `TestPushRecordsTargetAndObservation` and `TestTargetRecordCommand`).
- The record names a plan only as the plan that recorded the newest head of the integration ref (or `--plan`), and a repeat that names another plan or another actor writes nothing; port: kept (the identity of a target is its checkout, integration ref, remote and remote ref).
- `dag-integrate-push` compares first and records after, so the comparison of a ref's first push is the CRW-1301 comparison; port: kept (a ref with no record behaves as before, and the existing `integration_target_*_test.go` pass unchanged).
- With a recorded target the push and the check compare with the heads recorded for the integration ref alone, so another ref's head on the target's remote branch is outside the path; port: fixed (pinned by `TestRecordedTargetComparesWithOwnHeadsOnly` and `TestCheckTargetsOfTwoRefsOnOneRemoteBranch`). The heads are still matched by the ref's name, as the verified-move check matches them, so a ref of the same name in another checkout of the store counts; port: kept.
- Nothing read the remote between pushes, so a move made while no `dag-integrate-push` ran was seen at the next push and not before; port: fixed (`dag-integration-target-check` is a one-shot command that cron, the coordinator or the integrator runs. It reads each recorded remote with `remoteURLForPush` and `lsRemoteHead`, records the broken `integration_target_moved` fault for a head outside the recorded heads (one occurrence per remote head, no second blocking notice) and stores every head it read. Pinned by `TestCheckTargetOnPathRecordsNoFaultAndStoresTheHead`, `TestCheckTargetMovedRecordsOneFaultPerHead` and `TestPushRecordsTargetAndCheckerReadsIt`).
- The daemon does not run the check and the fault sweep still makes no network call; port: kept (faults.md's rule stands, and `TestCheckTargetIsNotADaemonStep` pins that no daemon source names the check; `internal/relay/daemon` is untouched).
- A remote that cannot be reached or does not answer within a minute, a remote without the branch, a checkout git cannot read, and a ref with no recorded head are deferred: nothing is faulted and the reading says why; port: kept (the same rule as the push; pinned by `TestCheckTargetDefersWhatItCannotRead`).
- The check never reverts, pushes or blocks; port: kept (pinned by the same tests: the remote keeps the head it holds). A fault or an observation the check cannot write is named in its reading, and only a flag beginning with a dash and a filter that names no recorded target are refused (`TestCheckTargetRefusesOnlyInputErrors`).
- The check reads each remote in turn, so a slow remote delays the targets after it by at most its minute; port: kept (one-shot, run from cron).
- The receive and acknowledgement steps compared no ref (CRW-1302); port: fixed (`ack` and the ack step of `receive` read, without a network or git call, the newest observation of the target recorded for the child's plan and compare it with the `baselineRevision` of the child's intent. Pinned by `TestReceiveComparesObservationWithBaseline`, `TestReceiveComparesNothingWithoutBothSides`, `TestReceiveComparisonMakesNoGitCall` and `TestAckCarriesTheTargetNoticeAndProceeds`).
- Deviation from a literal "mismatch": an observed head that differs from the baseline and is a head the relay recorded for the integration ref is the target advancing along the integration path (another node was integrated), so it records nothing; only a head that differs from the baseline and is none of the recorded heads is a move outside the path and records the fault. A literal mismatch would raise a blocking fault for every child whose base predates a later integration; port: kept (the same meaning as CRW-1301's, `source: receive`).
- The comparison compares nothing when the event's generation has no managed-start request and intent file, when the intent cannot be read, when `baselineRevision` is not a full commit id (the baseline of a node with no base is the opaque string `dag-input-manifest:<digest>`, and the example of `docs/relay/README.md` is `observed-revision`), when no observation of a recorded target exists, when more than one current target of the child's plans has an observation, and when a store row cannot be read; port: kept (fail open; pinned by `TestReceiveComparesNothingWithoutBothSides`).
- `intent.json` and the intent fields carry no target ref name, because they mirror the CXC oracle; the target is the store's record; port: kept.
- The step the comparison runs in proceeds whatever it finds; the notice is `targetMoved` in the acknowledgement's output, and the supervisor's blocking notice is the ledger's; port: kept (warn and record).
- The comparison reads the newest stored observation, which is as old as the last push or check. A target that moved after the last read is not seen at acknowledgement; port: kept (the periodic check bounds the age; nothing in receive reads the remote).
