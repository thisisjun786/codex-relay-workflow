# CRW-1401 — TestReceiptIntakeWritesNoLineageRowUnderAnotherKey failed once in integration: a parallel test freed an inode the store-file identity table still held

Source: CRW's own relay store tests, no CXC oracle (CXC v0.2.40, commit 3c1459ac, has no store-file identity table). The failure is the one of integration `cc-q10142229` (`/state/crw/integration/runs/cc-q10142229.verify.log`, passed on the package rerun, `.flake-rerun.log`). The Go files are `internal/relay/store/state_test.go` (`TestLocate_returns_empty_physical_fields_when_missing`), and, read only, `internal/relay/store/storefile.go` (the identity table, `holdsLiveStoreIdentityLocked`, `liveStoreRef.release`), `store.go` (`Store.Close`) and `scope.go` (`HashArtifact`). No relay store schema, store code, receipt status, refusal code or fault class is added or changed.

- `TestReceiptIntakeWritesNoLineageRowUnderAnotherKey` failed at its receipt (`receipt_lineage_key_test.go:73`, `scope_escape: '.../002/work/out.txt' is a relay store file this process holds or opened`), not at either lineage assertion. The parallel `TestLocate_returns_empty_physical_fields_when_missing` removed an open store's database and closed the store at return. `Store.Close` gives back the store's reference in the identity table only after it has closed the connection (CRW-967), so the database's inode was freed while its key was still in the table; ext4 gives the next new file the freed inode at once, and a parallel test whose artifact took it in that window had the artifact refused as a store file. Reproduced by running the two real test functions side by side (200 pairs, five spinners, `-count=5`: 214 of 1000 receipt runs refused, the same message; the receipts alone pass 1000 of 1000); port: fixed (test only). The test now gives the database a second name before it removes the path, so the inode stays allocated until the TempDir cleanup, which runs after the deferred `Close`; `Locate` still sees a missing path. With the change the same reproduction passes 1000 of 1000, and the named test passes at `-count=20` with five spinners, alone and in the full package. No other test of the package frees an inode the table still holds: a temporary probe that watched the table during two full package runs (a key no descriptor of the process names and no entry of its store's directory names) found only this test on the unchanged code and nothing with the change.
- Named limit: the window itself is in the store. A store whose database file is unlinked while it is open frees the inode when `Close` closes the connection, and until the reference is given back a new file that took that inode is refused by the artifact reader, the authorized opener and the independent-review reader as a relay store file (a refusal, nothing read or written). The order is the one CRW-967 chose so that a reader is never told a store's file is ordinary while the connection still holds locks on it; giving the reference back before the close would reopen that, and holding the registry lock across `DB.Close` would make every artifact read wait on a close (and on any query the close waits for). It needs a database removed under a live process and an artifact created and read in the same moment; port: kept.
