# CRW-1157 — bounded, cause-specific refusal diagnostics

Source: the CRW memory and GitHub post guards, and CXC v0.2.40 `memory-write-gate.ts`. The prior memory template described every unreadable program as an observed protected write and suggested user authorization even to a leaf.

- Unknown destinations and unreadable programs are now explicit bounded cause codes; port: fixed. Diagnostics say what cannot be verified and give a readable-script alternative (the `crw pabcd receipt test -- ...` suggestion named in the issue was dropped, see the post-evaluation correction below: it needs `--session` and a phase-C check binding). Confirmed protected writes retain MEMORY-WRITE-GATE-01, the target and the one-write grant route. Failure to consume authorization is reported as authorization-state, preserving the grant on an unpublished state write. No parser error values enter the answer.
- Leaf payloads with agent_id or agent_type receive parent-report guidance instead of a user-confirmation or grant instruction; port: fixed. Decisions, one-time consumption and binding remain unchanged.
- CRW's GitHub guard retains unreadable-github-post and its deny decision, but commands without a post mention receive a reader diagnostic. An out-of-root body file identifies the TMPDIR, /tmp and /var/tmp restriction; port: fixed. This replaces the repeated body-file suggestion. Rule IDs remain stable and labels are bounded.
- Tests: TestCRW1157DenialCauses and TestCRW1157GithubRecovery cover confirmed/unknown/unreadable/state causes, leaf routing, value-free errors and the 700-byte reason cap. Existing command decisions stay covered by the reproduction corpus. Actual agent S2/S5 reports require the coordinator's isolated trial; this implementation session cannot contact other agents.

- Compatibility tests now pin the unchanged internal rule/place independently of rendered prose. The final 700-byte bound keeps UTF-8 labels valid and retains both ends of long targets, including the basename. Publication and state-preservation negatives remain unchanged; long-target and existing refusal tests verify the new presentation.

- A relative body-file with no usable cwd has an unknown location, so its diagnostic no longer claims it is outside a temp root. Known out-of-root paths keep the explicit temp-root explanation. Cwd labels use the remaining message budget so short notes retain a hostile-but-valid root without exceeding 700 bytes.
- Five diagnostic-only CXC fixture claims move from CRW-518 to contract/notes/cxc/CRW-1157.json, with explicit expected output substitutions. The frozen oracle fixtures are unchanged; every exit, decision and state entry remains checked. The cxcfuzz memorygate seed cases retain their oracle bytes and prior disposition records and explicitly pin the new Go diagnostics. Expectations were authored from frozen targets and the specified cause/template, not recorded from the Go implementation.

- Post-evaluation correction: the judge carries whether the failing execution was a post and its bounded body-location refusal cause. Rendering no longer re-resolves a body operand against the original payload cwd or loses a post reached through a shell file. Body containment and the diagnostic use the same location helper; port: fixed. FIFO/read failures inside a temp root are distinguished from a known outside-root refusal, including after cd.
- Parent unreadable-program/unknown-destination recovery now offers one readable-script alternative. The unconditional receipt command was invalid without --session and a phase-C check binding, so it is no longer suggested; port: fixed. Leaf reporting and confirmed protected-write grants remain unchanged. The diagnostic-only cxcfuzz expected messages change accordingly; frozen oracle outputs remain intact.
- Fix-round (final head): an unknown destination of an edit tool call (Write/Edit/patch with a relative path and no usable cwd) is an actual write request whose destination cannot be resolved, so a parent keeps the one-write grant route (`allow-write`, per cwd) beside the unknown-destination cause and an absolute-path hint, as the issue's decided answer requires; port: fixed. A general shell command with an unknown destination still receives no grant route, and a leaf is sent to its parent. `TestCRW1157UnknownDestinationEditKeepsGrantRoute` covers the three cases.
