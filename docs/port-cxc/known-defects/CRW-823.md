# CRW-823 — the cli memory allow-write, scan record and review-round callers of a published write

Source: the state writer is `plugins/codexclaw/components/pabcd-state/src/state.ts` `writeState` at CXC v0.2.40 (commit
3c1459ac): it writes a temp file, publishes it with a rename, and returns whatever the publication threw. The goalplan
writer is `plugins/codexclaw/components/pabcd-state/src/goalplan.ts` `writeGoalplan`, reached by
`plugins/codexclaw/components/pabcd-state/src/review-round-cli.ts` (:230-267 and :278-283). The Go port is
`internal/pabcd/state/write.go` (`writeState`) and `internal/pabcd/goalplan/write.go` (`writePublishAt`), with the
callers `internal/pabcd/cli/memory.go` (`RunMemoryCLI`), `internal/pabcd/cli/scan_record.go` (`scanRecordRun`) and
`internal/pabcd/cli/review_round_run.go` (`reviewRoundRunOpen`, `reviewRoundRunAbort`). The oracle never syncs the
published file or its directory (`known-defects.md`, "Found by CRW-479 state publication durability"), so it cannot fail
after the rename; CRW-479 added the directory fsync to the Go port, which is what makes a post-rename failure reachable
and these callers observable. The oracle's own callers skip the same reconciling step, so the shape is faithful; the
divergence these lines close is that a published state used to be reported as a plain failure.

The `CRW-778.md` and `CRW-793.md` files this record supersedes live on their own branches; at this issue's baseline the
same pending items are the "Other `state.WriteState` callers" item of `CRW-744.md` and, for the goalplan writer, the
`port: kept` line of `known-defects.md`. The four callers below are therefore also recorded directly, so the record is
correct whichever order the merge lane lands 778, 793 and this issue in.

- `internal/pabcd/cli/memory.go` `RunMemoryCLI` reports "could not record the grant" though the grant was published,
  so a retry records the same grant twice (oracle `memory-cli.ts`, which cannot fail after the rename; Go
  `internal/pabcd/cli/memory.go` `cliPublishedMemoryAllowWrite`); port: fixed (the write counts as done when
  `state.Published(err)` is true: the command answers its existing success and appends the line "session state was
  published but its directory could not be synced: <err>", a failure before publication is unchanged and nothing is
  rolled back; no recorded corpus fixture drives a directory sync failure, so none is retagged, and the cases are in
  `internal/pabcd/cli/published_callers_test.go`).
- `internal/pabcd/cli/scan_record.go` scan record reports "scan record failed" though the round was published, so a
  retry appends the same scan round again and the interview ledger holds a duplicate (oracle `scan-cli.ts` :211-417,
  which cannot fail after the rename; Go `internal/pabcd/cli/scan_record.go` `cliPublishedScanRecordRun`); port: fixed
  (the write counts as done when `state.Published(err)` is true: the command answers its existing success, appends the
  same warning line and needs no retry, leaving exactly one round and one ledger row; a failure before publication is
  unchanged).
- `internal/pabcd/cli/review_round_run.go` `open` (:201) reports a failed write though the plan holds the in-flight
  round, so the launch id, which only the packet prints, is never shown although the round is open (oracle
  `review-round-cli.ts` :230-267; Go `internal/pabcd/cli/review_round_run.go` `reviewRoundRunOpen`); port: fixed (the
  write counts as done when `state.Published(err)` is true: the packet is rendered and the answer carries the line
  "goalplan '<slug>' was published but its directory could not be synced: <err>"; a failure before the rename is still
  an error and the packet error still returns the zero result).
- `internal/pabcd/cli/review_round_run.go` `abort` (:223) reports a failed write though the plan holds the closed
  round, so the abort looks like it did not happen (oracle `review-round-cli.ts` :278-283; Go
  `internal/pabcd/cli/review_round_run.go` `reviewRoundRunAbort`); port: fixed (the same published split, with the
  existing success line and the same warning appended).
- Supersedes known-defects/CRW-778.md, item beginning "Other `state.WriteState` callers that skip a reconciling
  step": its sub-items for `internal/pabcd/cli/memory.go` (`RunMemoryCLI`) and `internal/pabcd/cli/scan_record.go`
  (scan record) are now port: fixed by CRW-823 (the write counts as done when `state.Published(err)` is true, so the
  success answer stands and the durability failure is carried as a warning).
- Supersedes known-defects/CRW-793.md, item beginning "The other `WriteGoalplan` callers have no reconciling step":
  its sub-items for `internal/pabcd/cli/review_round_run.go:201` (open packet) and
  `internal/pabcd/cli/review_round_run.go:223` (abort) are now port: fixed by CRW-823 (the same published split, with
  the goalplan warning line the goalplan package already uses).
- The goalplan writer itself does not yet report publication: `internal/pabcd/goalplan/write.go` `writePublishAt`
  returns the post-rename directory-open error (:313) and the directory `Sync` error (:316) as plain errors at this
  issue's baseline, so `state.Published(err)` is false for a real goalplan directory-sync failure and the review-round
  half of this change is dormant until the writer reports publication. The writer-side wrapping is the goalplan-writer
  issue's change (branch `codex/crw-793-goalplan-published-steering`, pull request #718, commit 6231bae1c, which returns
  `&state.PublishedError{Err: err}` from both sites) and `internal/pabcd/goalplan/` is outside this issue's edit
  regions; port: kept (recorded so a reader of this record knows the caller-side split is dormant until the writer
  reports publication, and that the caller needs no further change when it does; no rollback and no behaviour change
  either way, because the production path dispatches the real writer and a plain error still fails closed).
