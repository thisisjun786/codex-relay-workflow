# CRW-927 — reset link judgement: the search question at every dot component, no open during the judgement, in-root failures are absent

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/cxc-ops/src/reset.ts:16,35-42`
(`existsSync` and `rmIfExists`; the judgement reproduces the kernel's answer for the link rather than
calling it). Go port: `internal/pabcd/reset/reset.go` (`resetPin`, `resetLinkTargetExistsWith`,
`resetLinkWalkTarget`, `resetLinkWalkSearchable`).

- Supersedes CRW-822.md, item beginning "A multi-component dot-ending target such as": now port:
  fixed (the judgement opens no file and no directory — the descriptor is taken once by `resetPin`
  and every judgement step is an `fstatat(AT_SYMLINK_NOFOLLOW)` or `readlinkat` relative to it — so
  the intermediate directories of a target such as `keep/sub/..` are resolved by the kernel, which
  needs no read permission and issues no `openat`; a search-only (0111) directory now answers as
  the kernel does; pinned by `TestResetLinkPermJudgesLikeStatInSearchOnlyDirectories`).
- The oracle resolves `keep/../.` with the kernel's own walk, so with `.crw/keep` at mode 000 it
  answers EACCES and `rmIfExists` keeps the link (`reset.ts:16,35-42`); the port asked the search
  question only at the last component of the target and removed the link. The walk now asks it at
  every `.` and `..` component it passes, through the pinned descriptor; port: fixed (pinned by
  `TestResetLinkPermKeepsASearchDeniedMiddleDot`).
- The oracle answers ELOOP for a link loop and a chain past the kernel's 40 traversals, and EACCES
  for a directory it cannot search, so `rmIfExists` keeps the link (`reset.ts:16,35-42`); the port
  handed those in-root failures to the root-path judgement, which refuses with "reset directory
  changed while judging a link" once the pinned directory has been renamed and stops the reset
  before the remaining candidates. Such a target is now decided by the walk and is absent, and only
  a target that really leaves the root keeps the descriptor stat and the root-path judgement; port:
  fixed (pinned by `TestResetLinkPermInRootFailuresAreAbsentInARenamedPin` and
  `TestResetLinkPermTenLinkChainIsRemovedWithAndWithoutARename`).
- Residual race, recorded because the issue names it: a component the walk has seen to be a
  directory can be swapped for a link between that observation and the `fstatat` that resolves the
  concatenated path, so the stat answer can describe a different file than the walk saw. Only the
  verdict is affected; the removal still acts on the leaf through the pinned descriptor
  (`os.Root.Remove` refuses a name that escapes the root), so no path outside the workspace is
  removed; port: kept.
- Supersedes the expectation of `internal/pabcd/reset/reset_linkdot_test.go`'s
  `TestResetLinkDotTargetSkipsTheRootStat` row `plain_keep_keeps_the_descriptor_path`: now the walk
  alone decides every in-root target, dot-ending or not, so the row is renamed
  `plain_keep_is_decided_by_the_walk` and expects no descriptor-path stat; port: fixed (the
  expectation changed with the answer, not a defect of the oracle).
