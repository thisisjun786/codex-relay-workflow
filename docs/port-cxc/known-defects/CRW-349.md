# CRW-349 — SessionStart self-heal hook, report only

Source: CXC v0.2.40 (3c1459ac) plugins/codexclaw/components/config-guard/src/cli.ts:167-196 (the
hook branch, with makeRealRunner at :140-149), self-heal.ts:151-262 (selfHealDeclaredFeatures,
renderSelfHealContext, makeRealSelfHealDeps at :290-323, parseSelfHealMarker at :120-149) and
features.ts:15-34,58-96. Go port: internal/runtime/install/configguard/selfheal_report.go, its test,
and the session-start-healing-declared-features row of cmd/crw/component_hooks.go.

- The oracle heals from SessionStart: it runs `codex features enable <soft key>`, rewrites
  $CODEX_HOME/config.toml through that CLI, writes the self-heal marker
  ($CODEX_HOME/codexclaw-self-heal.json) and rewrites the install manifest so `disable` can revert
  the flag (self-heal.ts:151-262); port: report-only by the J4 decision (the port diagnoses the
  declared state and warns when a soft flag is off, and it never enables a flag, writes config.toml,
  the marker or the manifest, and makes no backup; the warning names `crw install features enable`,
  which the user runs. An automatic path that edits the user's Codex configuration is the conflict
  the J4 decision settles).
- A heal is recorded as consent without being verified: `healedKeys` gains the key as soon as
  `codex features enable` exits 0 (self-heal.ts:193-199,254), without confirming the flag reads on,
  so a write that did not take effect (another writer reverts config.toml) leaves consent for a
  flag that stays off and every later session takes the `declined` branch and stays silent
  (self-heal.ts:183-191) — the permanent silence `healedKeys` exists to prevent, reached through
  its own record; port: kept (the decline branch is ported as the oracle has it, and the port never
  enables, so it only reads a consent record an earlier CXC session wrote).
