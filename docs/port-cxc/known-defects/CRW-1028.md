# CRW-1028 — command reader shared by the command gates

Source: the CXC v0.2.40 worktree deletion guard (pabcd-state/src/worktree-guard.ts) and the CRW-783 GitHub post
rules, as ported in internal/pabcd/hook (worktreedel.go, githubpost.go) before this change; the shell reading
they used was a hand-written lexer, replaced here by internal/pabcd/shellir over mvdan.cc/sh/v3 (Bash variant).
Every change below is an intentionally-changed verdict recorded as a security class; the rows are in
internal/pabcd/hook/worktreedel_changes_test.go and worktreedel_corpus_test.go.

- A GitHub post the text hides behind an ANSI-C escape, an unknown program word, a non-literal carrier or a shell
  that reads its program from a pipe or a here-document is refused; the lexer allowed several of these; port: fixed (security).
- A GitHub post inside a script file that a shell runs is read and judged, and a post inside an interpreter program
  that names one is refused; the lexer did not read script files; port: fixed (security).
- A recursive removal whose operands arrive at run time (xargs, find -exec and -execdir, parallel) is refused; the fallback allowed it
  when no target resolved; port: fixed (security).
- The worktree guard's text fallback for unresolved targets is gone: a non-recursive rm, the Windows verbs
  (rd, Remove-Item, REMOVE-ITEM) and a comment or echo naming the slot are judged on what the reader shows;
  port: fixed (the Windows verbs are not POSIX removals and are no longer denied; the rest is bash-correct).
- A command the reader cannot read (unknown program word, unclosed substitution, zsh-only syntax, a parse error) is
  refused; the lexer allowed some of these; port: fixed (security).
- A shell option after -c does not make the next word the program: bash -c -e 'rm' runs rm, and the reader reads it
  so; the lexer and the new reader agree on bash -c 'echo $1' -c 'rm' (rm is an argument there); port: fixed (security).
- A backslash-newline in a text that also holds a # is refused, because bash ends a comment at a newline while the
  parser reads a continuation; port: fixed (security).
- A command over 64 KiB is refused; the lexer read any length; port: fixed (intentional limit, reported).
- Shell nesting is read to 32 levels; the lexer denied a benign nest beyond 8 levels; port: fixed (the innermost
  command decides, as bash does).
- A function body is read where it is defined, so a post defined but called later is judged; port: fixed (security).
- The memory write gate refuses a shell command the reader cannot read, in place of the lexer's unreadable-program
  check; port: fixed (the memory gate reads its shell writes from the reader; the gate's own shell lexers are deleted).
- The memory write gate's shell lexer named the destinations of tee, cp, mv, install, dd of=, sort -o, sed -i, perl and ruby -i
  with string scanning; the reader gives the same destinations from the parsed words, and a destination it cannot evaluate
  (a variable, a substitution, a glob, a brace) is the unknown destination, which the gate asks a grant for; port: fixed (security).
- A lone carriage return outside every word and comment is refused: the parser ends a word there and bash keeps the byte,
  so one destination could read as two; a carriage return inside quotes or a here-document reads the same and is allowed;
  port: fixed (security).
- A bracketed program word (a pathname pattern to the shell, such as [IO.File]::WriteAllText) is unknown, where the lexer named
  no destination; the write is asked for a grant; port: fixed (security).
- An inline awk program has no reader in this port, so its writes (print > file) are unknown rather than unnamed; port: fixed (security).
- The PowerShell and .NET write detection is not ported: a PowerShell command word is an ordinary command and names no
  destination, as the POSIX-only port has always done; port: kept (PowerShell is outside the POSIX gate; the unknown mark
  stands wherever the reader cannot evaluate the word).
- The Python and JavaScript literal readers name a destination only when the literal decodes exactly; a triple-quoted or
  escaped path they cannot decode is unknown, where the old reader named it; port: fixed (security, the destination is asked for).
- The memory gate names each destination once; the lexer kept duplicates; port: kept (set semantics, same verdict).

- The memory gate read no write of a sed w, W or s///w command given with -e or as the script, only the operands of sed -i; the
  reader now names each w, W and s///w file in every form; port: fixed (security).
- A Python write whose destination is not a literal (open(name, "w"), shutil.copy(src, dst), os.rename(src, name)) named nothing;
  it is now the unknown destination, which the gate asks a grant for, as the CRW-951 rule states; port: fixed (security). A
  copy or rename that gives its destination as a literal keeps its name.
- A Python write whose mode is computed (Path.open("w".strip()), open(p, mode)) or whose mode is given to a receiver
  (receiver.open("w")) named nothing; a computed mode now writes, and a receiver's open names the unknown destination (its file
  is the receiver); port: fixed (security).
- functools.partial(open, path, mode="w") named nothing; it is read as the open call it wraps; port: fixed (security).
- A rename or replace on a receiver the walk cannot name (p.replace(target), os.rename with a receiver of any shape) names its
  target argument, or the unknown destination when the target is not a literal; a link method on such a receiver is unknown;
  port: fixed (security).
- builtins .exec(...) with a blank before the dot was not read as exec; the blank is allowed as Python allows it; port: fixed (security).
- A Python program passed to exec, eval or compile whose argument is not a literal was not reported by the memory gate's
  shell path; the gate now reads the exact program bytes the shell gives and refuses such a program; port: fixed (security).
- A python -m module, a sed -f script file, and a stdin pipe whose producer is printf with a format directive or a /dev/null
  stdin redirect are refused as unreadable; the reader does not model those forms and refuses rather than reads them; port: kept
  (over-refusal, fail closed; the benign accounting counts them).
- The GitHub post guard denies every command the reader cannot read, so the rows the memory gate refuses are denied too; port: kept
  (fail closed; the guard is a deny-only gate).
- A destination that a shell writes into /dev/null (>/dev/null) is named as a write; port: kept (the name is true; no protected
  directory is /dev/null).

- A word with an unquoted, unescaped brace expansion is not known, and the decision is taken on the whole word: a quoted part or an
  expansion inside the braces does not hide the group, so {rm,"-rf"}, {"a",b}, {$x,b}, {a,b}$x, x{"a",b}y, {a,'b'} and {1.."3"} are
  unknown (bash expands the ones with a plain comma). In a program position the word is unreadable; as an operand it is an unknown word.
  Quoted, escaped, lone-brace and parameter-expansion words stay known. The rule is a lexical rule over the parts of one word; a brace
  group that a shell builds only at run time from a variable is not a brace expansion for bash either and is not judged. Tests:
  TestBraceExpansionIsUnknown, TestBraceControlsStayKnown, TestBraceWordsAcrossQuotesRefusedInAllGates,
  TestBraceControlsAllowedInAllGates, TestBraceParameterExpansionIsNoGroup; port: fixed (security).
- A managed-worktree inline program of python, node, perl or ruby is refused when it can remove a file, when it starts another program, or
  when it reaches a name only at run time. The removal rule is lexical over the whole text, strings and comments included: a token that
  starts with rm (rm, rmdir, rm_r, rm_rf, rmtree, rmsync) or contains remove, unlink, delete, trash, truncate, erase, wipe, shred, purge or
  destroy. The starting rule refuses exec, spawn, system, popen, subprocess, child_process, fork, binding and qx, and a backtick or %x in
  Ruby and Perl. The run-time rule refuses getattr, __import__, eval, exec, compile, runpy, pickle, marshal, ctypes, code, imp and the
  rest of the common set in every language; vm, module, worker_threads, WebAssembly and Function in node; instance_eval, class_eval,
  module_eval, send, public_send, load and binding in ruby; require or do with a variable in perl; and a subscript whose key is not a
  number or a plain literal. Ordinary programs stay allowed (print, json, re, math, open for reading, json.load). Accepted price, port:
  kept: python3 -c 'l=[1]; l.remove(1)' and a string that contains the word remove are refused in a managed worktree. Recorded residuals:
  an encoded payload that the token scan cannot read (a base64 pickle is refused by the name pickle, not by its bytes), and a name that is
  built outside the program text and reaches the program only as data. Tests: TestWorktreeDelInlineProgramRows,
  TestWorktreeDelProgramRefusalWords; port: fixed (security).
- The program-running wrappers watch, flock, chroot, script, strace, ltrace, entr, at and batch are modelled with their option grammar, and
  an option the grammar does not list makes the program unproven: watch joins its command into a shell string unless -x, which runs the argv;
  flock reads -c as a shell string and the lock operand, with options read again after the lock file; chroot reads its long options and the
  new root and refuses a program-less chroot; script reads -c as a shell string with the file last and refuses a script without -c; strace and
  ltrace read their -o file as a write of their own; entr runs its utility with the names from stdin (a run-time carrier, as xargs is) and reads
  -s as a shell string; at and batch read their program from standard input or a file and are unreadable. Generation 4 models script's
  files: the file operand, else typescript in the directory the program runs in (script writes its transcript there when none is given),
  and the -I, -O, -B and -T files, each as a write of its own; the -c value is shell code and never a file. strace and ltrace name their
  -o file the same way. The option grammar is util-linux's; a host whose script or strace has another grammar is not verified by this
  port, and an option outside the modelled grammar makes the program unproven. Tests: shellwrite_runner_test.go, shellwrite_script_files_test.go
  (default transcript, file operand, -a, the four log files, a relative and an absolute -c string with no phantom destination, a /dev/null
  control, a cd before the default transcript), shell_env_test.go. port: fixed (security) for the shapes these tests name. The default
  transcript is exact for util-linux 2.41.3, the host's script: typescript is written when no file operand is given and none of -I, -O or -B
  names an output log (-T and -a alone keep it); a file operand together with -I, -O or -B is an error of script and is still named.
- A Python, Node, Perl or Ruby interpreter whose script operand is a file-descriptor alias (/dev/stdin, /dev/fd/N, /proc/.../fd/N) is
  unreadable: the program is the text of that descriptor, which the reader does not follow. An ordinary script file operand is still not
  judged, as c1e states. Tests: reproduction rows CRW-989-03 and CRW-989-04; port: fixed (security).
- hash with options only (hash -r, hash -l) is no longer refused as a zsh invalidator; a word that is not an option, or one the reader cannot
  read, is an operand and is refused. Test: the audit row Z-hash-control; port: fixed (narrowing of a refusal: hash -r only clears the table).
