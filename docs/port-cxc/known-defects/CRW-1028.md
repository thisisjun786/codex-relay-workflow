# CRW-1028 — command reader shared by the command gates

Source: the CXC v0.2.40 worktree deletion guard (pabcd-state/src/worktree-guard.ts) and the CRW-783 GitHub post
rules, as ported in internal/pabcd/hook (worktreedel.go, githubpost.go) before this change; the shell reading
they used was a hand-written lexer, replaced here by internal/pabcd/shellir over mvdan.cc/sh/v3 (Bash variant).
Every change below is an intentionally-changed verdict recorded as a security class; the rows are in
internal/pabcd/hook/worktreedel_changes_test.go and worktreedel_corpus_test.go.

- A GitHub post the text hides behind an ANSI-C escape, an unknown program word, a non-literal carrier or a shell
  that reads its program from a pipe or a here-document is refused; the lexer allowed several of these; port: fixed (security).
- A GitHub post inside a script file that a shell runs is read and judged, and a post inside an interpreter program
  that names one is refused; the lexer did not read script files; port: fixed (security).
- A recursive removal whose operands arrive at run time (xargs, find -exec) is refused; the fallback allowed it
  when no target resolved; port: fixed (security).
- The worktree guard's text fallback for unresolved targets is gone: a non-recursive rm, the Windows verbs
  (rd, Remove-Item, REMOVE-ITEM) and a comment or echo naming the slot are judged on what the reader shows;
  port: fixed (the Windows verbs are not POSIX removals and are no longer denied; the rest is bash-correct).
- A command the reader cannot read (unknown program word, unclosed substitution, zsh-only syntax, a parse error) is
  refused; the lexer allowed some of these; port: fixed (security).
- A shell option after -c does not make the next word the program: bash -c -e 'rm' runs rm, and the reader reads it
  so; the lexer and the new reader agree on bash -c 'echo $1' -c 'rm' (rm is an argument there); port: fixed (security).
- A backslash-newline in a text that also holds a # is refused, because bash ends a comment at a newline while the
  parser reads a continuation; port: fixed (security).
- A command over 64 KiB is refused; the lexer read any length; port: fixed (intentional limit, reported).
- Shell nesting is read to 32 levels; the lexer denied a benign nest beyond 8 levels; port: fixed (the innermost
  command decides, as bash does).
- A function body is read where it is defined, so a post defined but called later is judged; port: fixed (security).
- The memory write gate refuses a shell command the reader cannot read, in place of the lexer's unreadable-program
  check; port: fixed (the memory gate reads its shell writes from the reader; the gate's own shell lexers are deleted).
- The memory write gate's shell lexer named the destinations of tee, cp, mv, install, dd of=, sort -o, sed -i, perl and ruby -i
  with string scanning; the reader gives the same destinations from the parsed words, and a destination it cannot evaluate
  (a variable, a substitution, a glob, a brace) is the unknown destination, which the gate asks a grant for; port: fixed (security).
- A lone carriage return outside every word and comment is refused: the parser ends a word there and bash keeps the byte,
  so one destination could read as two; a carriage return inside quotes or a here-document reads the same and is allowed;
  port: fixed (security).
- A bracketed program word (a pathname pattern to the shell, such as [IO.File]::WriteAllText) is unknown, where the lexer named
  no destination; the write is asked for a grant; port: fixed (security).
- An inline awk program has no reader in this port, so its writes (print > file) are unknown rather than unnamed; port: fixed (security).
- The PowerShell and .NET write detection is not ported: a PowerShell command word is an ordinary command and names no
  destination, as the POSIX-only port has always done; port: kept (PowerShell is outside the POSIX gate; the unknown mark
  stands wherever the reader cannot evaluate the word).
- The Python and JavaScript literal readers name a destination only when the literal decodes exactly; a triple-quoted or
  escaped path they cannot decode is unknown, where the old reader named it; port: fixed (security, the destination is asked for).
- The memory gate names each destination once; the lexer kept duplicates; port: kept (set semantics, same verdict).
