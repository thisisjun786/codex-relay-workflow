# CRW-1028 — command reader shared by the command gates

Source: the CXC v0.2.40 worktree deletion guard (pabcd-state/src/worktree-guard.ts) and the CRW-783 GitHub post
rules, as ported in internal/pabcd/hook (worktreedel.go, githubpost.go) before this change; the shell reading
they used was a hand-written lexer, replaced here by internal/pabcd/shellir over mvdan.cc/sh/v3 (Bash variant).
Every change below is an intentionally-changed verdict recorded as a security class; the rows are in
internal/pabcd/hook/worktreedel_changes_test.go and worktreedel_corpus_test.go.

- A GitHub post the text hides behind an ANSI-C escape, an unknown program word, a non-literal carrier or a shell
  that reads its program from a pipe or a here-document is refused; the lexer allowed several of these; port: fixed (security).
- A GitHub post inside a script file that a shell runs is read and judged, and a post inside an interpreter program
  that names one is refused; the lexer did not read script files; port: fixed (security).
- A recursive removal whose operands arrive at run time (xargs, find -exec and -execdir, parallel) is refused; the fallback allowed it
  when no target resolved; port: fixed (security).
- The worktree guard's text fallback for unresolved targets is gone: a non-recursive rm, the Windows verbs
  (rd, Remove-Item, REMOVE-ITEM) and a comment or echo naming the slot are judged on what the reader shows;
  port: fixed (the Windows verbs are not POSIX removals and are no longer denied; the rest is bash-correct).
- A command the reader cannot read (unknown program word, unclosed substitution, zsh-only syntax, a parse error) is
  refused; the lexer allowed some of these; port: fixed (security).
- A shell option after -c does not make the next word the program: bash -c -e 'rm' runs rm, and the reader reads it
  so; the lexer and the new reader agree on bash -c 'echo $1' -c 'rm' (rm is an argument there); port: fixed (security).
- A backslash-newline in a text that also holds a # is refused, because bash ends a comment at a newline while the
  parser reads a continuation; port: fixed (security).
- A command over 64 KiB is refused; the lexer read any length; port: fixed (intentional limit, reported).
- Shell nesting is read to 32 levels; the lexer denied a benign nest beyond 8 levels; port: fixed (the innermost
  command decides, as bash does).
- A function body is read where it is defined, so a post defined but called later is judged; port: fixed (security).
- The memory write gate refuses a shell command the reader cannot read, in place of the lexer's unreadable-program
  check; port: fixed (the memory gate reads its shell writes from the reader; the gate's own shell lexers are deleted).
- The memory write gate's shell lexer named the destinations of tee, cp, mv, install, dd of=, sort -o, sed -i, perl and ruby -i
  with string scanning; the reader gives the same destinations from the parsed words, and a destination it cannot evaluate
  (a variable, a substitution, a glob, a brace) is the unknown destination, which the gate asks a grant for; port: fixed (security).
- A lone carriage return outside every word and comment is refused: the parser ends a word there and bash keeps the byte,
  so one destination could read as two; a carriage return inside quotes or a here-document reads the same and is allowed;
  port: fixed (security).
- A bracketed program word (a pathname pattern to the shell, such as [IO.File]::WriteAllText) is unknown, where the lexer named
  no destination; the write is asked for a grant; port: fixed (security).
- An inline awk program has no reader in this port, so its writes (print > file) are unknown rather than unnamed; port: fixed (security).
- The PowerShell and .NET write detection is not ported: a PowerShell command word is an ordinary command and names no
  destination, as the POSIX-only port has always done; port: kept (PowerShell is outside the POSIX gate; the unknown mark
  stands wherever the reader cannot evaluate the word).
- The Python and JavaScript literal readers name a destination only when the literal decodes exactly; a triple-quoted or
  escaped path they cannot decode is unknown, where the old reader named it; port: fixed (security, the destination is asked for).
- The memory gate names each destination once; the lexer kept duplicates; port: kept (set semantics, same verdict).

- The memory gate read no write of a sed w, W or s///w command given with -e or as the script, only the operands of sed -i; the
  reader now names each w, W and s///w file in every form; port: fixed (security).
- A Python write whose destination is not a literal (open(name, "w"), shutil.copy(src, dst), os.rename(src, name)) named nothing;
  it is now the unknown destination, which the gate asks a grant for, as the CRW-951 rule states; port: fixed (security). A
  copy or rename that gives its destination as a literal keeps its name.
- A Python write whose mode is computed (Path.open("w".strip()), open(p, mode)) or whose mode is given to a receiver
  (receiver.open("w")) named nothing; a computed mode now writes, and a receiver's open names the unknown destination (its file
  is the receiver); port: fixed (security).
- functools.partial(open, path, mode="w") named nothing; it is read as the open call it wraps; port: fixed (security).
- A rename or replace on a receiver the walk cannot name (p.replace(target), os.rename with a receiver of any shape) names its
  target argument, or the unknown destination when the target is not a literal; a link method on such a receiver is unknown;
  port: fixed (security).
- builtins .exec(...) with a blank before the dot was not read as exec; the blank is allowed as Python allows it; port: fixed (security).
- A Python program passed to exec, eval or compile whose argument is not a literal was not reported by the memory gate's
  shell path; the gate now reads the exact program bytes the shell gives and refuses such a program; port: fixed (security).
- A python -m module, a sed -f script file, and a stdin pipe whose producer is printf with a format directive or a /dev/null
  stdin redirect are refused as unreadable; the reader does not model those forms and refuses rather than reads them; port: kept
  (over-refusal, fail closed; the benign accounting counts them).
- The GitHub post guard denies every command the reader cannot read, so the rows the memory gate refuses are denied too; port: kept
  (fail closed; the guard is a deny-only gate).
- A destination that a shell writes into /dev/null (>/dev/null) is named as a write; port: kept (the name is true; no protected
  directory is /dev/null).
- Benign accounting over the parent-filtered corpus (8020 commands), at the final code of this generation: the memory gate allowed
  4518, named 468, asked a grant for 972 and refused 2062 as unreadable; the GitHub guard allowed 5234, denied 724 and refused 2062
  as unreadable; the worktree guard allowed 5081, denied 877 and refused the same 2062 as unreadable (the same reader). The refusals
  are dominated by $RELAY and other variable program words, unclosed here-documents whose bodies the corpus does not carry, pathname
  patterns as program words, PATH assignments and git subcommands outside the closed list; the brace-word and file-API rules of this
  generation moved some rows from allowed to need-grant or denied. The scrubbed fixture of 300 commands stays allowed. Test
  TestShellWriteBenignAccounting prints these counts. port: kept (the reader refuses each of these by rule).
- A write to /dev/null (2>/dev/null, >/dev/null) is no destination of the gate, as the v0.2.40 oracle has it for 2>/dev/null; port:
  fixed (narrowing of named destinations; no protected file is /dev/null).
- A command with no program word, only a redirection (>file), was refused as an unknown program; it is read as an empty program
  that writes its redirection's file; port: fixed (narrowing of refusals, the write is named).
- A script operand of sed -i and of perl or ruby -i is named as a file (the port's reading of the operands, kept from the lexer
  era); the v0.2.40 oracle named the file only for the common forms; port: kept (over-report, fail closed; the seven changed
  cases below are tagged intentionally-changed in the cxcfuzz seed cases).
- The seed cases of internal/dev/cxcfuzz whose pinned answers the new rules change are tagged intentionally-changed with a record
  naming this file: shellwrite sed-in-place, campaign-perl-in-place, crw857-subshell-write, crw857-command-substitution-write;
  memorygate crw857-memorygate-substitution-write, crw857-memorygate-codex-home-expansion, campaign-link-follow-differ (the last was
  open, now intentionally-changed).
- The differential fuzz runs of 300 seconds each (seed 1028) found no crash and no timeout: shellwrite 16623 cases (same 3824,
  differ 5701, miss 261, extra 6837), memorygate 3325 (same 2124, differ 145, miss 4, extra 1052), worktreedel 19714 (same 17072,
  differ 296, miss 91, extra 2255). Read against the v0.2.40 oracle: most differ and extra rows are refusals (the reader names the
  unknown destination where the oracle named a path it read by lexing); every miss row sampled from the three runs begins with a
  # comment, which bash does not read and the oracle lexed; the worktreedel runs also show a relative hook cwd that the oracle
  refuses as unresolvable and the port allows (a follow-up candidate in the handoff). The summaries are under the evidence root,
  not checked in; port: kept (differences from the lexer oracle are the intended readings of this issue).
- The Python and JavaScript literal readers name a destination only when the literal decodes exactly, so the triple-quoted and
  escape forms they cannot decode are the unknown destination; the existing triple-quote and escape tests now accept it;
  port: fixed (security).

- A redirection on a compound command ({ :; } > file, ( : ) > file) was computed and dropped, so the file it writes was not
  named; it is now read as an empty program with that redirection; port: fixed (security).
- A cd, a variable or a function change made in a loop body was kept after the loop; the directory and the variables are unknown
  after a loop; port: fixed (security).
- An unquoted expansion whose value holds a blank, a tab, a newline or a glob character splits into several words; it is one
  unknown word, not one known program; port: fixed (security).
- A shell builtin that changes the shell (cd, export, set, unset, alias, and the like) named behind an external program (env cd,
  nice cd) is unreadable, and an external program's inner command runs on a copy of the state; port: fixed (security).
- parallel runs the programs its ::: operands name at run time, so it is unreadable; port: fixed (security).
- The memory gate joins a relative destination to the directory a preceding cd made; a program in the payload directory keeps the
  destination as written, so the gate's link resolution is unchanged; port: fixed (security).
- find -delete removes its start points: the worktree guard judges them. An inline Python, Node, Perl or Ruby program in a managed
  worktree is refused when it can remove a file (any spelling that contains remove, unlink, rmdir, rmtree, delete, rm_rf, rmsync,
  trash or truncate, or the token rm), when it starts another program (exec, spawn, system, popen, subprocess, child_process, fork,
  binding, qx, a backtick or %x in Perl and Ruby), and when it reaches a name only at run time (getattr, __import__, eval, importlib,
  globals and the like, or a subscript whose key is not a number or a plain string literal). The rule is a token scan in
  worktreedel_program.go, not a list of removal names, so the spellings the reviewer reproduced are refused; an ordinary program is
  allowed. port: fixed (security); the scan over-refuses where a removal word appears in a string.
- A removal target under a directory the reader does not know is protected: the guard fails closed; port: fixed (security).
- gh api --input and -F body=@file read a JSON body by its string values, keys and escapes decoded, and scan those; a body that
  is not JSON is scanned as text. The place the deny names counts the scanned strings, not the file's lines; port: fixed (security).
- A body file named - (standard input) is refused; a body path is resolved through its symbolic links before the trusted-root
  check, and a regular file is checked on the descriptor it reads: the path is opened without blocking and without following a
  final link, and the descriptor is required to be a regular file before any byte is read, so a named pipe swapped in after the
  check is refused without a hang (test TestGitHubPostRegularFileSwappedForPipe); port: fixed (security).
- A coding declaration in the first two lines is read for every coding name on the line, not the first one; port: fixed (security).
- A Node writer whose first argument is no string literal, and a Python open bound to a name (f = open), name the unknown
  destination; port: fixed (security).
- An inline perl or ruby program has no reader in this port, so its writes are the unknown destination; port: fixed (security).
- sed's e command and the e flag of s run a shell command the text names: the destination is unknown; port: fixed (security).
- sort -o names its file in every form: -o FILE, -oFILE, -ro FILE, --output FILE, --output=FILE and an unambiguous abbreviation;
  port: fixed (security).
- git -c keys that run a program by driver name (diff.<driver>.command, merge.<driver>.driver, filter, textconv and the like) are
  refused; port: fixed (security).
- A plain Python string whose text begins with f' is no f-string: print("f'}'") no longer asks for a grant; port: fixed (false
  refusal of CRW-1012).
- When the GitHub post guard is cancelled it answers deny before it stops; port: fixed (security).
- A Python f-string or replacement field nested 33 levels or deeper is unreadable; 32 levels are read (the walk counted from 0
  and allowed 33). Test TestShellWriteFStringNestingExact covers f-string and spec-field nesting; port: fixed (security).

- A word with an unquoted, unescaped brace expansion (a comma list or a .. sequence, nested or not) is not known: in a program position
  it is unreadable, and as an operand it is an unknown word. The parser keeps the braces as literal text, so before this change
  rm -rf <checkout>{,.bak} and {rm,echo} -rf ../repo were allowed by the worktree gate and {cp,install} /tmp/x <memory file> by the
  memory gate. Quoted, escaped and lone-brace words stay known. Tests TestBraceExpansionIsUnknown, TestBraceWordsInTheWorktreeGate and
  TestBraceWordsInTheMemoryGate; port: fixed (security).
- rm -rf .{cache,local} and its line-continued form are denied, because the brace expansion makes the target unknown; the two corpus
  rows and the recorded change rows held the old allowed reading. Intentionally changed (security); port: fixed (security).
- The memory gate ignored the carrier of a program that xargs, find -exec, find -execdir, find -ok or parallel runs: its destination
  arrives at run time, so it is now the unknown destination and the gate asks for a grant. parallel is a marked carrier now. Test
  TestMemoryGateRunTimeCarrierDestinations; port: fixed (security).
- A Node or Python program that holds a file API (fs, promises, pathlib, shutil, os, io, open, Path) and writes through a name the
  reader cannot attribute has an unknown destination: a write function destructured, aliased or imported bare, a write name that is
  not a dot call, getattr and the other run-time names, and a computed subscript. A dot call with a literal destination keeps its
  exact destination. Tests TestMemoryGateUnattributableWriteSpellings and TestMemoryGateLiteralWriteKeepsDestination; port: fixed (security).
- A payload cwd that is empty, relative or not an existing directory makes the directory unknown in the three gates (shellirPayloadCwd).
  Tests in shellir_cwd_test.go; port: fixed (security).
- A body file or script file is opened without blocking and without following a final link, and the opened descriptor is checked
  before it is read (test TestGitHubPostRegularFileSwappedForPipe, with a seam between the check and the open); port: fixed (security).
- The sed s and y commands held the delimiter check twice in one || expression (a lint finding, SA4000); both reads are now explicit
  and the verdict is the same; port: kept (no verdict change).
- Four unused helpers and one unused type were deleted (literalHeredoc, shellVerbCpMvWrites, worktreeDelChangeFor, delErrorf), and
  the removal-name regexp, which held a literal backspace byte, was replaced by the token rule; port: fixed (lint).

  rm -rf ./build-7627 names an unrelated child directory of the working directory, not the worktree, and is no longer denied (the old
  fallback matched the slot id as a raw substring). A loosening; recorded in contract/notes/cxc/CRW-1028.json; port: fixed (security).
- intentionally-changed (security), contract fixture hook__pre-tool-use-guarding-managed-worktree-deletion__unresolvable_target_fallback_denies:

  rd and Remove-Item are PowerShell verbs with no meaning on this POSIX host, so the three steps that name them are silent. A loosening;
