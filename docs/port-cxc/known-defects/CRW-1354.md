# CRW-1354 — a head the child made outside a project-lane run had no way to land through the gates

Source: CRW's own design (Jun's decision of 10-14 04:3x: the child chooses how the work is made, CRW enforces the order, the gates and the record; CRW-1316 design §18.3), not the CXC oracle: CXC v0.2.40 (commit 3c1459ac) has no flow engine and no agent acceptance. The Go and script side is `internal/flow/workflows/land-head.js` (the gate-only workflow), `internal/flow/ops/lane_land_head.go` (`crw.release` with `land`: `LandOpts`, `LandHead`, `ThreadConfigs`, `landAuthorModels`), `internal/flow/ops/lane_design.go` (`ReleaseOpts.Land`, `ReleaseOutcome.Land`), `internal/flow/ops/seams.go` (`ReleaseRequest.AuthorModel`, `AuthorEffort`), `internal/flow/ops/lane.go` (`Deps.LandRoot`), `internal/flow/ops/journalq.go` (`worktreeOf`, `authorModels`), `internal/flow/ops/lane_build.go` (`expectedCriteria`), `internal/flow/ops/lane_land.go` (the issue of the premerge record), `internal/flow/cli/schedrelay.go` (`Release`, `worktreeOf`), `internal/flow/cli/laneops.go` and `world.go` (`LandRoot`, `hostThreads.ThreadConfig`) and `internal/relay/dagsched/release.go` (`AgentReleaseOptions.AuthorModel`, `AuthorEffort`); the references are `docs/flow/script.md` ("Landing a head made outside a run") and `plugins/crw/skills/crw-canon/references/flow.md`.

- A head the child made with its own subagents outside a run could not land: relay acceptance on the agent path requires a current agent execution of the node, held by the orchestrator, a completed reviewer call of the run that holds it, and at least one observed author pair, and only a project-lane run released a node and recorded those; port: fixed (the gate-only workflow `land-head` - args `plan`, `milestone`, `issue`, `head` and `authors`, the subagent threads that wrote the head - releases the node to its run with `crw.release(..., {pinned: true, land})`: the head is resolved in the run's repository, each author thread is read back from the host (`thread/read`, the configured pair), the plan the relay holds is compared with the plan of the run's `crw.milestone` row and the node's slice is carried as for every release, and the agent release records on the node's execution row the pair the authors ran on (`author_model`, `author_effort`, columns the row had and no writer filled; `AgentReleaseOptions`, the stored form unchanged). The head is checked out, detached, in a worktree of the run's, which the release row names and the execution's handle points at. The gates are the ones a project-lane head passes, writing the same rows: `crw.verify` (verification-record/1 of the exact tree), `crw.review` (a fresh reviewer whose model family differs from every author the release observed), `crw.land` (`crw.accept` - the relay's agent acceptance, which judges the reviewer against the recorded author pair through the unchanged `authorPairs` - then `crw.integrate`). No executor, architect or design-audit call is made or recorded. Pinned over the fake App Server by `TestLandHeadLandsAHeadMadeOutsideARun` and `TestLandHeadKeepsTheIndependenceGate` (a reviewer of the author's family stays `independence_refused`, an author never read back is `independence_unproven`, and nothing is accepted), and at the relay by `TestAgentReleaseRecordsTheAuthorPairTheAcceptanceJudges`; red first).
- The decided default holds without weakening the acceptance and without inventing rows: the acceptance's code is unchanged and reads the execution row's author pair as it always did; the pair is the one the host reads back for the threads the child names, recorded in the land's release row with each thread, and no `flow_calls` row of an executor is written. Named limit: the run observes the pairs of the threads the child names, not that those threads wrote the head - the provenance of a head made outside a run is the child's naming, where a project-lane head's is the run's own executor calls; the reviewer, the verification and the acceptance judge the head itself. Port: kept (follow-up when the hook ledger's `unrecorded_author` lines of the child's spawns, CRW-1348, can be joined with the head's commits).
- Named limit: one execution row holds one author pair, so a land whose authors ran on more than one model family is refused as an input error (`land_author_families_mixed`, nothing written at the relay): the relay could not judge the reviewer against every family. Authors of one family on several pairs land, the execution recording the first observed pair (the relay compares families). Port: kept (such a head is landed one family's work at a time, or made in a project-lane run).
- The refusals of the path are input errors (no head, a head git does not resolve, authors of several families, an issue that is not a node of the milestone), the plan comparison every release makes (`plan_changed`) and the gates (a verification that fails, a review that is not verified or not independent, an acceptance or integration the relay refuses), each ending the run escalated for the child or unreleased with the reason; everything else is a warning of the release row: an author thread whose pair is not read back (`land_author_unobserved`), no author named (`land_authors_unnamed`) and paths outside the node's regions (`land_out_of_scope`). The path fixes nothing: a head that needs changes is the child's to change and land again. A lost epoch ends the run `stopped` with `epoch_lost`.
- `TestEveryWorkflowReleasePassesPinned` (`internal/flow/scenario/invariants_test.go`) split a release's arguments at every comma, so an options literal that carries more than `{pinned: true}` failed it; port: fixed (the arguments are split at the top level and an options literal whose first member is `pinned: true` passes; every release still has to pass it).
- Named limit: the execution of a land records the role and tier `executor`, the agent surface's default, since no other role runs the node, and the reviewer packet of a land carries the node's criteria and regions from the plan and its done condition from the issue's end condition (no DESIGN exists); port: kept.
