# CRW-854 — cxcfuzz: a worker's start-up was charged to a case's per-case deadline

Source: the differential-fuzz harness itself, `internal/dev/cxcfuzz`, which has no oracle
counterpart at CXC v0.2.40 (commit `3c1459ac`) and is specified by the CRW-701/CRW-743/CRW-854 issue
bodies rather than ported from a source file. The defect is in the harness's worker pool:
`Pool.exchange` (`internal/dev/cxcfuzz/worker.go:137-174`) gave one deadline (`p.timeout`, the
per-case `DefaultTimeout` of five seconds, `internal/dev/cxcfuzz/cxcfuzz.go:31`) to the write-and-read
pair, and a freshly started worker's first exchange also covered its fork/exec, interpreter boot and
shim top-level imports. Nothing at CXC is ported differently by this fix: no oracle file changes, no
shim changes and no protocol change.

## Defects

- The worker pool charged a freshly started worker's start-up (fork/exec, the shim interpreter's boot
  and its top-level imports) to the first case's per-case deadline, so on a busy runner the boot alone
  exceeded the five-second deadline and the agreement campaign `TestCampaignEchoAgreesWithTheShim`
  counted an agreeing case as a timeout and failed (measured here: a first exchange of 3.0 s at a 1%
  CPU quota against a warm exchange of about 100 us, and 2 of 30 cases counted as timeouts at a 0.4%
  quota); a replacement worker started after a timeout carried the same charge to the next case
  (`worker.go:124-135` handed a just-started worker straight to `exchange`); port: fixed (a real
  behaviour defect of the harness, fixed by the issue's own instruction: `Pool.acquire` now waits for
  a freshly started worker to answer one handshake request under a separate start-up deadline
  (`DefaultStartupTimeout`, one minute, `Config.StartupTimeout`) before the worker takes a case, so the
  per-case deadline covers only that case's own exchange with a ready worker; a worker that does not
  answer the handshake in time is killed, replaced, and the case counted as a timeout exactly like a
  stalled request, so a real divergence is never masked -- `Pool.ready`, `Pool.roundTrip`,
  `TestStartupDelayIsNotChargedToTheCaseDeadline`, `TestPoolStartupWaitsForAReadyWorker`,
  `TestPoolStartupTimeoutIsReportedAndTheSlotReturns`).
- The echo shim's `CXCFUZZ_STALL=1` left the first request unanswered, which the harness documented as
  a per-case timeout; after the fix the first request a worker receives is the start-up handshake, so a
  stalled worker now expires its start-up deadline instead of a case's per-case deadline
  (`internal/dev/cxcfuzz/testdata/echo/shim.mjs:10,21,57`); port: kept (no oracle behaviour is
  involved -- this is the harness's own test knob, no test drives `CXCFUZZ_STALL`, and the knob's
  comment was updated to say what it now stalls; the campaign's timeout count is unchanged).

## Notes

This file records one fixed harness defect and one kept documentation consequence. Neither is an
oracle parity difference: `docs/port-cxc/differential-fuzz.md` now states the start-up contract, and no
corpus fixture, shim or recorded oracle answer changed.
