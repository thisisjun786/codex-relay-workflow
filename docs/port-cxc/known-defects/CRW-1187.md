# CRW-1187 — a module run executed code the inventory did not read: shadows of any standard-library name, writers beside the run, and sources that move the imports

Source: the CRW memory and GitHub post guards, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no command reader and never read a module run). The Go files of the port are `internal/pabcd/shellir/modules.go`, `modules_names.go`, `modules_source.go`, `env.go` and `shellir.go`; both guards (`internal/pabcd/hook/memorygate.go`, `githubpost.go`) take the reading from there. Found by the independent verification of CRW-1178 (round 8, three P2 findings that were already at the base); the issue is CRW-1187.

- `python3 -m json.tool` and `-m py_compile` read no inventory and refused only a fixed list of local shadow names, so the modules Python 3.14 imports after it sets `sys.path[0]` (keyword, reprlib, fnmatch, dis, weakref, `_colorize`, annotationlib, compression, textwrap and more) ran from the working directory as `keyword.py` or `keyword.pyc` (end to end with the real interpreter: `keyword.py` writes the memory note under `python3 -B -m json.tool` and `-m py_compile`); port: fixed (security). For these two modules a file, a compiled file, an extension or a package of the working directory with the name of any standard-library module is refused (`stdlibModuleNames` in `modules_names.go`: the names of `sys.stdlib_module_names` and `sys.builtin_module_names` of Python 3.14.4, the modules of 3.8 and 3.9 that later versions removed, the site-startup names; and any name that starts with an underscore, which covers the private modules a version adds), unless the run leaves the directory out of `sys.path`. The reason names the file and the route (`run python -I -m json.tool ...` or move the file). `-I` is that exception; `-P` is it only when PYTHONPATH is proven unset (the text neither spells the name nor may build a variable name at run time, and the hook's environment does not set it), because `-P` alone keeps PYTHONPATH (checked with the real interpreter: `PYTHONPATH=. python3 -P -m json.tool` imports the shadow). Version handling: a public module a future version adds is not covered until the list is refreshed; `TestCRW1187StdlibListCoversTheHostInterpreter` fails when the interpreter on the host has a module name the reader would not refuse as a shadow. unittest and pytest keep the narrower list for the names their own imports use (their sources, packages and compiled files are walked and read by the inventory).
- The check for a writer to an import location (a carried program, an archive extraction, a redirection or a copy-like command to a code path or an unknown destination) looked only at the records before the module run. A record that runs at the same time can create the module a test imports later; port: fixed (security). The records of a text are now also judged when they run beside a module run: another stage of the pipeline it is in (`python3 -m unittest | tee late.py`), a background job or a coprocess on either side, and a process substitution. A command that runs after the module has ended (`;`, `&&`, a later statement) is not judged, so `python3 -B -m unittest; printf x > late.py`, `python3 -B -m unittest | tee out.log` and `sleep 1 & python3 -B -m unittest` stay allowed. Not modelled: a background job a text starts that outlives its own statement and is awaited elsewhere is judged by the same rule (refused when it can write a module file, on either side).
- A test module (or a conftest, a helper, a package initializer) read by the inventory could itself move the imports: `sys.path.insert`, `sys.pycache_prefix` (which `python -E -B` does not stop), importlib loaders by path, a `.pyc` copied and imported; the run then loaded code outside the inventory, and `-I` does not prevent it (the interpreter still lets the source change `sys.path`; end to end with the real interpreter: under `python3 -I -B -m unittest` the module's own `sys.path.insert` loaded a directory that wrote the memory note); port: fixed (security). The reader now scans the text of every source of a unittest or pytest run at token level and refuses, as unreadable with the file and the construct in the reason: any use of `sys.path`, `sys.pycache_prefix`, `sys.meta_path`, `sys.path_hooks`, `sys.path_importer_cache` or `sys.__dict__` (also through `import sys as s`, `from sys import path [as p]`, `from sys import *`, `getattr`/`setattr`/`vars` on the module, and `"sys"` fetched by name); any `importlib` attribute but `import_module`, `reload`, `invalidate_caches`, `resources` and `metadata` (also through `import importlib as il`), `importlib.machinery` and `importlib.util` and the loader and finder names (SourcelessFileLoader, SourceFileLoader, spec_from_file_location, ...); `__import__` and `import_module` (and a name given to them with `as`) called with anything but one plain module name, or mentioned other than in an import statement; `getattr`, `setattr`, `vars` on `sys`, `importlib` or `builtins`; `__path__` and `submodule_search_locations`; `imp`, `runpy.run_path`, `zipimport`, `marshal`, `compileall`, `py_compile`, `site.addsitedir`; PYTHONPATH, PYTHONPYCACHEPREFIX and PYTHONHOME in the text; and a name that ends in `.py`, `.pyc`, `.pyd`, `.so`, `.pth` or holds `__pycache__` together with a call that writes, copies, moves or links a file (`open` in a write mode, `write_text`, `shutil.copy`, `os.replace`, ...). The reason does not offer `python -I` as a route for these (it does not stop them): remove the construct from the test sources, or keep the code to run in the project files. py_compile only compiles its operands and imports nothing from them, so their text is not scanned. What stays allowed: an ordinary import, `importlib.import_module` and `importlib.reload`, `sys.argv`, `sys.exit`, `sys.modules`, `sys.executable`, `sys.stdout`, `mock.patch('sys.stdout')`, writes to files that are not module files, `copy.deepcopy`, `str.replace` next to a `.py` name. The reader's general limit stays: Python the text builds or reads at run time and runs with `exec` is not claimed. Measured with the real interpreter (`TestCRW1187EveryWorkingImportMechanismIsRefusedByBothGuards`, 37 mechanisms that load code from outside the project, among them `sys.path` in six forms, `getattr`/`vars`/`__import__`/`import_module` with a name built from pieces, a finder, `spec_from_file_location`, a sourceless loader, a copy, link, rename or write of the module into the project, `runpy.run_path`, a package's `__path__`, `site.addsitedir`, a subprocess with PYTHONPATH): every one is refused by both guards, except `exec(compile(open(outside).read(), ...))` and `exec` of a string built from pieces, which the memory gate refuses and the GitHub post guard does not (it does not refuse `exec` in any program, with or without a module run); port: kept (outside this issue).
- The friction of that scan, measured on the test-named Python files of the host (`/usr/lib/python3`, 1021 files of numpy, pytest, twisted, systemd and more; `/usr/lib/python3.14`, 69 test files): 91 of 1021 and 12 of 69 are refused, nearly all test infrastructure that sets `sys.path` or builds extension modules (34 `sys.path`, 30 file writes at an import location, 11 `sys` by name, 7 importlib.util or machinery, 3 PYTHONPATH). An application's own tests that import its package from the working directory are not touched. A project whose tests need `sys.path.insert` is refused and has to run those tests another way (a separate command that the guards judge, or a layout that needs no path change).
- Tests: `TestCRW1187*` in `internal/pabcd/shellir` (the shadows as source, compiled file, extension and package for json.tool and py_compile; `-I` and `-P` and the PYTHONPATH cases; the list against the host interpreter; every writer beside the run on either side and the sequential and harmless companions that stay allowed; the table of source constructs, each under unittest, `-I`, `-E -B` and pytest, with conftest, helper, package and ancestor sources; the ordinary sources that stay allowed; the kept runs: no cache, `-B` after a separate removal, `-E -B`) and in `internal/pabcd/hook` (both guards, with the real interpreter in a temporary home: the shadow and the module's own `sys.path` and `sys.pycache_prefix` ran before the change, are refused now, and the `-I` and plain runs the reasons lead to are allowed).
