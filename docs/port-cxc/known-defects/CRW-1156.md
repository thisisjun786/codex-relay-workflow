# CRW-1156 — skill search remote reads without a deadline or a size bound

Source: `plugins/codexclaw/components/skill-search/src/cli.ts:45-49,164-220` at v0.2.40 (commit 3c1459ac); the Go side is `internal/skill/search/run.go` (`fetchHTTP`, `RunContext`, `searchAll`), `cache.go` and `cli.go` (`runGH`). Found by the 10-10 CXC improvement review (A8-07, P1).

- The oracle's `fetch` has no request deadline, no body deadline and no size bound: a server that never answers, or never stops answering, holds the command for ever (or fills memory), and `Response.text()` is read whole before any size test (source `cli.ts:45-49`); port: fixed (the context of the command reaches the HTTP request, so the connect, the headers and the body all end at the deadline: one source, or one `show` read, within 20 s and the whole command within 60 s. The body is streamed through `io.LimitReader(limit+1)` before it is decoded; a body over the limit, declared by `Content-Length` or counted while reading, is refused with `response exceeds N bytes` and is never cut. A catalog (and so a cache file) is limited to `MaxBodyBytes` (4 MiB) as before, now before the allocation; a skill body that `show` prints has its own documented limit, `MaxShowBodyBytes` (1 MiB). Pinned by `TestHTTPFetchDeadlinesAndBounds`, `TestShowBodyHasItsOwnLimit`).
- The sources of one search ran one after another, so one stopped endpoint kept every later source and the stale-cache fallback from being reached (source `cli.ts:164-220`); port: fixed (`searchAll` reads the sources of a search at the same time, at most four at once, each under its own 20 s deadline; the results are merged in the order the sources were named, whichever answered first, so the output does not depend on timing. A timed-out read leaves the cache file as it was and serves the usable stale entry with the usual warning. Pinned by `TestSearchBoundsEachSourceAndKeepsTheOthers`, `TestSearchRunsIndependentSourcesConcurrently`, `TestSearchTimeoutKeepsTheUsableCache`).
- A search whose every selected source failed printed `no matching skills` (or `[]`) and exited 0, so a caller could not tell a failed lookup from an empty one (source `cli.ts:101-135,170-194`; this completes the CRW-496 item "Search source, gh launch/auth and malformed-gh-JSON failures can produce empty results with exit 0"); port: fixed (when every selected source is unavailable the command writes nothing to stdout, names each failure on stderr (with `all`, a last line `skill-search: all selected sources unavailable (...)`) and exits 3; one source answering, even with no rows, is exit 0 and the JSON array keeps its shape. A source counts as unavailable when its read failed or timed out, or `gh` could not be launched, exited non-zero, or printed text that is not JSON; a source served from a stale cache is available. A caller that treated exit 0 as "looked" must now handle exit 3. Pinned by `TestSearchExitStatusByAvailability` and the replay claims for `cli__skill__search_offline_without_cache`, `cli__skill__search_gh_absent`, `cli__skill__search_gh_auth_failure` and `cli-help__skill__search_dashdash_help` in `contract/notes/cxc/CRW-496.json`).
- A cancelled caller left the command running to its end; port: fixed (`RunContext` ends the command with exit 130 and `skill-search: interrupted` when its context is cancelled; `crw skill` passes the process context. Pinned by `TestRunContextCancellationReturnsPromptly`). `gh` runs under the same deadline and its pipes are closed one second after it ends or is stopped, so a child it leaves holding them cannot hold the search.
- Supersedes known-defects.md, section "CRW-496 — skill-search CLI", item beginning "Search source, gh launch/auth and malformed-gh-JSON failures": now port: fixed (a search whose every selected source failed exits 3 and writes no rows; a failed source among others is named on stderr and the others answer, exit 0; see the third item above).
- Supersedes known-defects.md, section "CRW-496 — skill-search CLI", item beginning "Show suppresses catalog errors": now port: partly fixed (a skill body that `show` fetches is limited to `MaxShowBodyBytes` and read under the deadline; a catalog that cannot be read is still skipped silently and a matching row's body failure still ends the command with exit 1 and the cause).
- Supersedes known-defects.md, section "Found by the skill-search library port (CRW-278)", item beginning "Remote bodies, entry paths and skill identifiers": now port: fixed for the transport (the 4 MiB catalog bound is enforced while reading, before the body is held, and no longer depends on an injected fetcher).
- The default transport still reports a connection failure as `fetch failed` and drops its cause (known-defects.md, "CRW-496 — skill-search CLI", item beginning "The default fetch transport reports only"); port: kept. A deadline is reported as `fetch timed out`, a cancelled command as `fetch canceled`, and an over-limit body as `response exceeds N bytes`.
