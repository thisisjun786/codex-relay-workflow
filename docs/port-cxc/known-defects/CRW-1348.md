# CRW-1348 — a session run could not be started, stepped, resumed or woken outside the tests

Source: CRW's own design (CRW-1316 design sections 3.2, 5, 9, 10, 11 and 15, lane S3), not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no flow run, no step exchange and no orchestrator binding. The Go side is `internal/flow/cli` (`next.go` new: `crw flow next`, `crw flow dispatched`; `session.go` new: the backend of a start, the subagent slots, the binding, the session facts; `start.go`, `process.go`, `world.go`, `spec.go`, `deps.go`, `cli.go`), `internal/flow/engine` (`sessionwake.go` new; `session.go`, `sessionhost.go`, `engine.go`, `resumecli.go`), `internal/flow/backend/agent` (`session.go` new: `SessionBackend`, `SessionHost`; `bound.go`), `internal/flow/journal` (`sessionenv.go` new: `SessionEnv`, `StageWake`; `resumeenv.go`), `internal/flow/bound` (`orchestrator.go` new; `bound.go`, `ledger.go`) and `internal/role/spawn/flow_bound.go`.

- `engine.Config.Session` was filled only by tests: `crw flow start` built the App Server backend, `crw flow resume` could only refuse a session run, and nothing took the steps a run published; port: fixed (`crw flow start` defaults to `--backend session`: the run process builds `Config.Session` from the session host adapter of `internal/flow/sessionhost`, the `FileStepBus` of `<state>/flow/<run>` and the owner thread, over `agent.SessionBackend`, which embeds the Allocator and so is the Placer, Restorer, HeadKeeper and DirRemover and proves and reads sources as the App Server backend does; the pool is `min(pool, agents.max_threads - 1)`; a resume, the run process's and the foreground `crw flow resume RUN SCRIPT` over `journal.ResumeEnv`, takes the backend of the started row with `engine.StartedBackend` and builds the session environment again, and a spec that names another backend is refused as an input error; the foreground resume of a session run holds it as the run process does (`engine.ResumeHold`): the pool at `agents.max_threads - 1`, the owner's orchestrator line written again while it runs and closed when the run ends; `crw flow next` hands out the steps with the run's state, the slots and a hint, removes a close step's file once handed out, resumes a run no process holds that is not paused or over and writes a missing binding again; `crw flow dispatched` writes the inbox atomically and prints the run's reply, and a report without a run waits in the inbox. Pinned by `TestNextHandsOutTheStepsOfTheBus`, `TestNextResumesARunWithNoProcess`, `TestDispatchedWritesTheInboxAndPrintsTheReply`, `TestStartDefaultsToASessionRunAndBindsItsOwner`, `TestResumeTakesTheRecordedBackend` and, on the fake App Server, `TestSessionRunEndToEndOnTheFakeHost`, `TestForegroundResumeOfASessionRunBindsTheOwnerAndCapsThePool` and `TestForegroundResumeRefusesAMixedResume`).
- The orchestrator line carried the explorer and reviewer pairs only, `BindOrchestrator` lived in the App Server backend and was never called, and nothing ended or replaced the line of a run that was gone; port: fixed (`bound.BindOrchestrator` writes the line with the pairs of the six roles and `Line.Validate` takes no orchestrator line without them (an undecided role of the helper role store, CRW-1330, has the empty pair, and its spawns keep the host's default with the ledger warning `role_undecided`); the start writes it, the run process writes it again on a start or resume and closes it when the run ends; a run is live while its process holds the run lock, the open line of a run without the lock is closed first, and a second start while the first run lives warns and does not bind; the App Server backend's methods call the bound package. Pinned by `TestOrchestratorLineCarriesTheSixRolePairs`, `TestBindOrchestratorOneLiveRunPerThread`, `TestStartDefaultsToASessionRunAndBindsItsOwner`, and `TestOrchestratorBindingOpensAndCloses` unchanged).
- The spawn hook let an orchestrator spawn explorer helpers only, refused every other agent type, architect and a ciphertext task without a role name, and refused every spawn of a thread whose binding could not be read or whose ledger could not be written (`flow_bound_unavailable`); the ledger recorded neither the role nor the op, so the run's marker search could not tie a spawn to its step by the ledger alone; port: fixed (the decision table of design section 9: a spawn by a subagent and a full-history fork are refused, every other spawn is allowed with the pair of its role, the role a flow-bound `CRW-ROLE:` parser reads (exactly the six values; the oracle parser is unchanged) or the agent_type's; the ledger records `role`, `op` and `warning` (`role_agent_type_mismatch`, `unrecorded_spawn`, `unrecorded_author`); a ledger that cannot be written allows with a stderr warning, and a binding that cannot be read is no binding, with a stderr warning. Pinned by `TestSessionOrchestratorDecisionTable`, `TestSessionOrchestratorLedgerUnwritableAllows`, `TestSessionOrchestratorHookFailureAllows`, `TestFlowBoundRoleHeaderTakesTheSixRoles`, `TestDecisionRecordsRoleAndOp`, `TestMarkerOpIsTheFirstLine`, and the revised `TestOrchestratorHelperTypeMapping`, `TestOrchestratorCiphertextRoleFromTaskName` and `TestFlowBoundLookupUnavailableIsAnOrdinaryThreadWithAWarning`).
- A run that published a step had no way to reach an owner thread between its turns; port: fixed (with `SessionConfig.Wake` the run stages a `session_step_waiting` message through `run:<id>` when it publishes a step and the owner is not busy, notifies again after 15 minutes without a dispatch with intervals that double up to an hour, writes a `session_unresponsive` escalation after two hours and goes on; the wake id is `(run, batch)`; each wake is a `session_wake` row; the relay's busy wake (CRW-1334) delivers to a busy owner after its turn. Pinned by `TestSessionWakesTheOwnerAndEscalatesWithoutStopping`, `TestSessionDoesNotWakeABusyOwnerFirst`, `TestSessionRenotifyScheduleGrowsToTheMax` and the staged message of `TestSessionRunEndToEndOnTheFakeHost`).
- A session run started with no reading of what its protocol needs; port: fixed (the warn facts `owner_bound`, `role_models`, `owner_state_writable`, `subagent_slots` and `multi_agent_v1` are judged at the start of a session run, after them the `verifier_prerequisites` of CRW-1319 that every run has, and none stops it (CRW-1318). Pinned by `TestSessionFactsWarnAndNeverBlockTheStart`).
- The session wiring treated a role pair as whole where CRW-1331 compares only its decided parts: `Line.Validate` took no orchestrator line whose role names a model and leaves its effort undecided (so the owner was not bound on such a table), the hook would have put an empty `reasoning_effort` in that role's spawn, `role_models` named such a role as having no pair, and the world of a session run's process and the foreground resume's environment built the App Server backend with the explorer pair binding of a run on the App Server, so a session run whose explorer or reviewer is undecided was refused before it started; port: fixed (an orchestrator line carries the decided parts of each role, an effort without a model is refused; the hook puts in the decided parts only and the ledger's applied pair is what it put in; `role_models` says `no pair for` and `no effort for`; a session run's App Server backend, which starts no thread and no turn, has no flow binding, and a run on the App Server keeps it unchanged. Pinned by `TestOrchestratorLineCarriesTheSixRolePairs`, `TestSessionOrchestratorUndecidedEffortAppliesTheModelOnly`, `TestBindOwnerCarriesTheDecidedPartsOfEachRole`, `TestRoleModelsFactNamesTheUndecidedPart`, `TestASessionRunIsBuiltOnUndecidedHelperPairs`).
- Deviation: the shared trace digest leaves out the run's own refs under `refs/crw/flow/<run>/` and the hook's ledger and claims of the flow-bound directory, which the run and the owner's own spawns move while a subagent works; port: kept (warn and record; a digest of them would warn on every session call).
- Deviation: the subagent slots and `multi_agent_v1` are read from `<CODEX_HOME>/config.toml` (`agents.max_threads`, default 6; `features.multi_agent_v2`); port: kept (the start, the run process and the foreground `crw flow resume RUN SCRIPT` apply the slot bound from it).
