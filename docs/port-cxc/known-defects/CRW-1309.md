# CRW-1309 — managed-start accepted a marker root the daemon does not judge Stops under

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle's `managed-start` (managed.py) writes the `--marker-root` it is given into the routing record and the assignment directory and never asks whether it is the root `control.sock` evaluates Stops under (control.py `owner_paths`). The Go side is `internal/relay/managed` (`marker_root.go`, called from `begin` in `run_steps.go`), `internal/relay/hook/adapter.go` (`OwnerMarkerRoot`, `MarkerRootRefusal`, shared with `ownerPaths`), `internal/relay/hook/control_marker_root.go` (the `marker-root` control.sock method and `AskOwnerMarkerRoot`) and `internal/relay/adapter/managed_cli.go` (the daemon is asked there). Found by the 10-13 r2 F0-1 run (20261013T050105Z): the parent started with `--marker-root .../f01-k1-a1/markers`, the relay accepted it, and the child's `intent-claim` was refused "control.sock evaluates Stops only under this owner's marker root ..." and later ended `claim_uncorrelated` / `no_store_recorded`, so the completion record was silently lost.

- `managed-start` took any `--marker-root` and recorded it in the routing record and the assignment directory, so a child whose Stops the daemon would not evaluate was started and its completion record was lost without a word (F0-1-1, F0-1-3); port: fixed (a new start whose resolved `--marker-root` is not the marker root the daemon judges Stops under (the root the daemon answers to the `marker-root` question over control.sock, `hook.OwnerMarkerRoot` evaluated in the daemon's own environment, the selection `ownerPaths` applies) is refused at the start as `marker_root_mismatch`, exit 2, before the reservation, the creation and the dispatch, with the reason `control.sock evaluates Stops only under this owner's marker root <daemon's>; the request named <given>` and the resolved root beside it. The daemon, not the caller's environment, names the root: a parent whose `CODEX_SESSION_RELAY_MARKER_ROOT` differs from the daemon's or is unset is judged against the daemon's root, and the correct root starts. When the daemon cannot be asked (no daemon on the socket, or an older one that rejects the method), the root is the one managed-start's own environment resolves and the refusal says that, with the reason the daemon was not asked. A relative `--marker-root` is refused earlier by the request identity's rule that a path must be absolute. The roots are compared as the daemon compares them (normalized absolute path, or the same existing directory) and on the request's symlink-resolved root. A replay of a request id already reserved skips the check and stays judged by the reservation comparison, so a started request keeps working. Pinned by `TestCRW1309_MarkerRootOtherThanTheDaemonsIsRefusedAtStart`, `TestCRW1309_MarkerRootNamingTheDaemonsRootStarts`, `TestCRW1309_ReplayOfAStartedRequestIsNotRefusedByTheRootCheck` and, over the built CLI, `TestManagedStartRefusesAMarkerRootTheDaemonDoesNotJudgeUnder`, and for the daemon's own answer `TestManagedStartAdmitsTheDaemonsRootWhenTheCallersEnvironmentDiffers`, `TestManagedStartRefusesARootTheDaemonDoesNotJudgeEvenWhenTheCallersEnvironmentNamesIt`, `TestManagedStartRefusalNamesTheDaemonsRootAndThatRootStarts`, `TestManagedStartWithoutADaemonFallsBackToItsOwnEnvironmentAndSaysSo`, `TestManagedStartWithADaemonThatRejectsTheQuestionFallsBackAndSaysSo`, `TestManagedStartRefusesARelativeMarkerRootWithItsReason` and the hook-side `TestControlAnswersTheOwnersMarkerRoot`).
- Deviation: callers that ran `managed-start` with a `--marker-root` unlike the relay daemon's now need the daemon's own root; they read it from the refusal, which names it (managed-start asks the daemon, so exporting `CODEX_SESSION_RELAY_MARKER_ROOT` in the parent is neither needed nor enough); the relay-side tests that started over the built CLI without a daemon give managed-start's environment the root they pass; port: kept (a reversible input error refused with its reason is preferred to a silently broken record, Jun 10-13).
