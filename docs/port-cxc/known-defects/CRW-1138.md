# CRW-1138 — the generated runtime pointer is one literal shell word

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/cxc-ops/src/cxc-resolve.ts:83` and `:86` (`cxcInvocation`); the Go side is `internal/pabcd/host/invocation.go` (`Invocation`, `ShellWord`), whose command the resolvers of `internal/pabcd/hook/directives.go` and `internal/affordance/render.go` and the other emit sites put in a Markdown code span. Found by the 10-10 CXC improvement review (A1-06), which saw `/home/$A1_TEST_SEGMENT/...` reach a harmless argv printer as `/home/expanded/...`.

- `cxcInvocation` put the generated path in double quotes without escaping, so a home holding a dollar sign or a backtick was expanded by the shell that ran the command, and a double quote or backtick broke the command or its code span; port: fixed (the runtime pointer path is one single-quoted POSIX shell word, a single quote closed, escaped and reopened, and a backtick written as `"$(printf '\140')"` outside the quotes, so the word holds no backtick and stays inside its code span. `CRW_BIN` is still a trimmed multi-word command prefix used as written, and the resolvers keep their rules: only backtick-anchored `crw` commands are resolved, with the CLI table's words. crw is released for Linux and macOS only, so there is no win32 spelling. Pinned by `TestInvocationIsOneLiteralArgumentInEveryShell` (sh, dash, bash and zsh print one argument equal to the path for a space, single quote, dollar sign, double quote, backtick and backslash), `TestResolvedCommandsStayInsideTheirCodeSpans`, `TestCRWBinStaysACommandPrefix` and `TestInvocation`).
- Supersedes known-defects.md, section "Found by the host-state reads port", item beginning "`cxcInvocation` puts the dispatcher path in double quotes": now port: fixed (CRW-1138, see above).
