# CRW-1300 — the relay child push guard's wiring: the binding read and the leg declaration

Source: CRW's own guard, no CXC oracle (the defect, r2 S8 F0-1, and the judgment are in [CRW-1284](CRW-1284.md)); Go files `internal/relay/hook/childbinding.go` and `cmd/crw/component_hooks.go`, the declaration `plugins/crw/wiring/hooks/pre-tool-use-guarding-child-push.json`. CRW-1300 carries the wiring of CRW-1284, split off by Sion (10-13, Jun-delegated, option (1)); the two keys are gated and integrated together.

- The binding read. `hook.ChildBinding` asks the relay store that the completion hook's settings select (`CODEX_HOME/crw-completion-hook.json`: their `dbPath`, else `relay.sqlite3` in the relay's state selection) whether the session is the `child_task_id` of a relationship, and returns that relationship's `parent_cwd`. The store is opened read-only in place (no sidecar, 2 s) and never written. A home without those settings, or a selected store that does not exist, has no relay child; settings or a store that cannot be read are an error. The judgment then refuses, in any session, a push and a command the reader cannot read that spells `push` (fail-closed: the session may be a child); a command the reader cannot read that spells no push passes, so a damaged store does not stop the unreadable but harmless commands of parent and integrator sessions. The binding names the session whose `session_id` the hook payload carries. A thread the child spawns (a sub-agent) carries the child's `session_id` and its own thread id as `agent_id`, so the binding resolves it to the child and the leg judges its pushes as the child's ([CRW-1303](CRW-1303.md)); a thread whose `session_id` is not a `child_task_id` of the store, its own thread id among them, has no binding and is not judged.
- The leg. `pre-tool-use-guarding-child-push` is a `PreToolUse` hook on `^(Bash|shell|exec_command|local_shell)$`, 10 s, `(crw) Guarding relay child pushes`, whose command starts `crw hook pre-tool-use --leg pre-tool-use-guarding-child-push` of the installed runtime. Its row in `cmd/crw` reads the hook input as the GitHub post guard reads it (an input that cannot be read whole, or a leg cancelled before it is, is refused, and input arriving after the cancellation is neither recorded nor judged), records the invocation, and hands the CRW-1284 judgment the binding: an error as unreadable, a session that is not a child as no binding, a child with its own branch (`ChildPushOwnBranch` of the hook's cwd against `dev`, `main`, origin's HEAD, the `refs/`, `heads/`, `tags/` and `remotes/` prefixes and `parent_cwd`, which may be NULL). The binding is read only for a command that pushes or cannot be read.
- The declaration. The file is appended last to the manifest's `hooks` in `plugins/crw/.codex-plugin/plugin.json`, after the flow status line; the shipped list (`cxccorpus.OwnHooks`) and the lane parity table (`laneparity.ExpectedLegs`) name it as CRW's fourth own registration. Declared legs are 35 (34 before), the manifest's hook files 36 (35 before); the plugin version follows the package digest. `docs/plugin-packaging.md`, `docs/port-cxc/parity-harness.md` and the canon's `delivery.md` name the leg.
- The trust identity. The new declaration adds one trust key, `crw@local:wiring/hooks/pre-tool-use-guarding-child-push.json:pre_tool_use:0:0`; the 35 existing declaration files are byte-identical, so their trusted hashes stand. The retrust plan that `crw doctor retrust` prints appends that one key at the end (recorded in `contract/notes/cxc/CRW-392.json`).
- The retrust plan. The real installation's trust for the new key is granted by Jun at the next install; until then only RX isolated homes are retrusted. The leg guards a session only when its key is trusted and the runtime is built from this change: an older runtime releases the unknown leg without a decision (exit 0, `internal/harness/hook.go`).
