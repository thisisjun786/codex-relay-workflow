# CRW-1112 — the receipt marker is the last marker line, and a name with two leading dots is inside the root

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/subagent-evidence.ts:130-133` (extractReceiptPath) and `:137-139` (isPathInsideDirectory). The Go side is `internal/pabcd/evidence/evidence.go` (`ExtractReceiptPath`, `insideDirectory`) and `internal/pabcd/evidence/assignment.go` (`lastMarkerValue`). Found by the 10-10 CXC improvement review A3-07 and the isolated real-use trial r1, finding S5-F2.

- Supersedes known-defects.md, section "Found by the subagent evidence attempts port", item beginning "`extractReceiptPath` takes the first `EVIDENCE_RECORDED:` that is followed by something": now port: fixed (the marker is the last line of the reply that starts, after white space, with `EVIDENCE_RECORDED:` and has a path after it; a line ends at `\n`, `\r`, U+2028 or U+2029 and nothing is read past it, so an empty marker never takes the next line, an earlier valid marker line counts when the last one is empty, and a marker inside a sentence (the directive the child quotes) or after other text on its line is not a marker line. The path checks are unchanged. In the trial's session s4 an executor quoted the directive and then ended with a correct marker for a real receipt; the quoted `<path>`` was judged and the child spent its budget. Pinned by `TestSubagentStopS4QuotedDirectiveReceiptIsAccepted`, which replays that child's own final answer, `TestExtractReceiptPathLastStandaloneLine` and the overrides of `TestExtractReceiptPath` (`newline_after_colon`, `ws_u2028`, `empty_first_then_valid`, `first_marker_wins`, `prefixed_marker`, `inline_in_prose`)).
- Supersedes known-defects.md, section "Found by the subagent evidence attempts port", item beginning "`isPathInsideDirectory` refuses every relative path that starts with `..`": now port: fixed (only a relative path that is `..` or starts with `..` and a separator leaves the root; `..notes.txt` and `..d/result.txt` inside it are accepted. A path outside the root, the root itself, an absolute path elsewhere, an empty file, a directory and a receipt that is a link are still refused, and the physical-root check is unchanged. Pinned by `TestHasValidReceiptDotDotNames`, `TestSubagentStopDotDotNamedReceipt` and the `receipt_name_starts_with_dotdot` and `dotdot_directory_name` overrides of `TestHasValidReceipt`).
- The overflow records (CRW-1110) are read and unlinked only through a chain of real directories, `.crw/evidence-overflow/<session>-<digest>`, each step checked as `writeOverflow` checks it; port: fixed. A link at any step (`.crw`, `.crw/evidence-overflow` or the session directory) makes the records unreadable, so the completion gate denies, `HasTombstone` finds none, and neither `crw pabcd evidence resolve` nor a child's late receipt unlinks a record of another directory that the link leads to. Pinned by `TestOverflowChainLinksAreRefused` and `TestOverflowLinkedAncestorIsNeverUnlinked`.
