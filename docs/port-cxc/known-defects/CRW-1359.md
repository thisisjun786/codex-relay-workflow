# CRW-1359 — the tracking check reads the sign-in and the repository on one host, says what a missing permissions answer means, and WithTracking writes the file as a person keeps it

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no `tracking` section. These are the follow-ups the pre-merge evaluation of CRW-1341 recorded (`/state/crw/mgmt/pre-eval/crw1341-7555cf52.json`, d4, d1, d3, d2); the first design is in `CRW-1341.md`. The Go side is `internal/crwconfig/tracking.go` (`ghProbe`, `CheckTracking`, `WithTracking`) and the plain `crw doctor` storage entry that `Report.Ordered` in `internal/crwconfig/check.go` builds; the reference is `docs/runtime-install.md` ("Where work tracking lives"). Everything here is a warning or a record except the errors that already existed; nothing blocks a start.

- d4 (P2): nothing pinned that a valid `tracking` section gives the storage entry of the plain `crw doctor` report a `tracking` key; port: fixed (test only, the behaviour was there). The key carries `set`, `kind` and `repo` in that order before `findings`, a section without `kind` reads as github, a file without the section has no key. Pinned by `TestDoctorStorageCarriesTheTrackingKeyForAValidSection`. There is no red run on the unchanged code, because the behaviour already held; the recorded red is a mutation (`report.Tracking` not set), see the handoff.
- d1 (P3): `ghProbe` read the sign-in with `gh auth status --hostname github.com` while `gh api repos/OWNER/NAME` goes to gh's default host (`GH_HOST`), so a broken github.com login made `tracking_auth` wrong on a host that works through another one; port: fixed. Both calls now carry `--hostname HOST`, `HOST` being `GH_HOST` (trimmed) else github.com (the same rule `internal/relay/dagsched` uses for the forge host). A broken second login of the same host makes `gh auth status` exit non-zero although the active login works, so a failed `auth status` now decides only when the repository read proves nothing: an answer with `permissions` is a signed-in login, an answer without them or a failed read is `tracking_auth`, and the error names the host. Pinned by `TestGHProbeAsksAuthAndAPIOnTheSameHost`, `TestGHProbeBrokenSecondLoginDoesNotHideTheActiveOne` and the unchanged `TestGHProbeReadsOnly` (now with the `--hostname` argument) and `TestGHProbeFailures`.
- d3 (P3): a repository answer with no `permissions` (a fine-grained token, an app token, a token without the scope) read as "no permission to read issues", an error that blamed the login; port: fixed. The probe now records `permissions_unreported`, and `CheckTracking` answers `tracking_permissions`, a warning that names those three causes and says what to check; both issue verdicts stay false in the recorded access (not proven), `crw config check` exits 0, and an archived repository is still the `tracking_issues` error. Permissions that are present and all false are still the old error. Pinned by `TestMissingPermissionsAreAWarningThatNamesTheCauses`.
- d2 (P3): `WithTracking` sorted the keys of the user's file and escaped `<`, `>` and `&`; port: fixed before any caller exists (none is added here). The document is read as an ordered object: every section keeps its value and its place, a replaced `tracking` stays where it stood, a new one goes last, a repeated key keeps its first place and last value, and the output is indented with the characters as written. A document that is not one object (`null`, an array, a scalar, a truncated or trailing-garbage document) is refused and nothing is written; an empty document is a new one. Pinned by `TestWithTrackingKeepsKeyOrderAndDoesNotEscapeHTML`, `TestWithTrackingRefusesADocumentThatIsNotAnObject` and `TestTrackingRoundTrip`.
- Named limit: a failed `gh auth status` with a repository answer that carries permissions is treated as signed in, so a host whose `gh` is broken for the active login but whose token is accepted from the environment (`GH_TOKEN`) reads as signed in; that is the login `gh api` uses, which is what the check is about. Port: kept.
- Named limit: `WithTracking` still has no caller; a command that writes the section is a later issue. The comment of a hand-edited file is not kept (JSON has none).
