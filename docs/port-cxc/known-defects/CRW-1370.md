# CRW-1370 — a sub-agent below depth 1 reaches the child push guard through its lineage

Source: CRW's own guard, no CXC oracle (the premise is [CRW-1303](CRW-1303.md), the judgment [CRW-1284](CRW-1284.md), the warn-and-record modes [CRW-1307](CRW-1307.md)); Go files `internal/relay/hook/childlineage.go` (`ChildBindingByLineage`), `internal/relay/hook/childbinding.go` (`ChildBinding`, unchanged), `cmd/crw/component_hooks.go` (the declared leg `pre-tool-use-guarding-child-push`). No relay schema, delivery state, supervisor state, host setting or trust key changes; no leg is added (35 declared legs).

- The observation, read only on 2026-10-14 (codex-cli 0.154.0; nothing under `<CODEX_HOME>` written): `<CODEX_HOME>/crw/hook-decisions` holds 273 records in 7 files, 13 distinct `sessionId`s, and 62 records that carry an `agentId`, in 9 (`sessionId`, `agentId`) pairs. The rollout of each of the 9 sub-agent threads has `source.subagent.thread_spawn.depth` 1, `session_meta.payload.session_id` and `parent_thread_id` equal to the record's `sessionId`, and its own `id` equal to the `agentId`. All 13 `sessionId`s are root sessions (`source` `vscode`); none is a sub-agent thread's id. So no hook input from a thread at depth 2 or deeper is in the records: 0 of 273. The host's rollouts hold 497 threads at depth 2 or 3 (492 and 5; 10983 rollouts in all), and every one has a `session_id` (the root) different from its `parent_thread_id` (the immediate parent) and from its own `id`. Which of those the host stamps as the hook input's `session_id` for such a thread is therefore not observed: the root's (the case CRW-1303 relies on), the immediate parent's, or the thread's own.
- Supersedes CRW-1303.md, item beginning "Named limits.", its point (1) ("Sub-agents deeper than one level ..."): now port: fixed (the premise stays unobserved, so the fallback is built: when a sub-agent's input carries a `session_id` the store does not hold as a `child_task_id`, the guard follows the lineage; the root session's `session_id` is bound as before without it).
- The lineage fallback (`ChildBindingByLineage`): only when `session_id` has no binding, the input names an `agent_id` and a `transcript_path`, and only for a command that pushes (the guard asks for a binding no earlier). It reads the first line (`session_meta`) of the sub-agent's own rollout, takes `source.subagent.thread_spawn.parent_thread_id`, asks `ChildBinding` about it, and goes on to that parent's rollout, found under the same Codex home's `sessions` (`sessions/*/*/*/rollout-*-<id>.jsonl`) or `archived_sessions`; at most 4 parents up. A thread of the lineage that the store knows as a child binds the sub-agent to it (the child's parent working directory, so the rules are the child's: a push to `dev` warns, the child's own branch passes). A lineage that ends at a root with no child above it, which is a parent's or an integrator's sub-agent, binds nothing and leaves no record. It reads rollouts only and writes nothing; a payload without `agent_id` or without `transcript_path` never reads one.
- Fail-open. A transcript or a parent's rollout that cannot be found or read, a first line that is not a `session_meta` record, a relay record that cannot be read and a lineage deeper than 4 parents give no binding and pass the push with the `[crw warning]` text and a `warn` decision record (leg, rule `child-push-guard`, `sessionId`, `agentId`; never the command text), as an unreadable relay record does (CRW-1303.md). The only block of the guard stays the force, delete or `--mirror` push onto `dev` or `main` by a session the store knows as a child (rule `shared-branch-history`), a sub-agent found through its lineage included. A fallback that cannot find a child never blocks.
- Named limits. (1) The fallback follows `parent_thread_id` only; a rollout whose `session_meta` names none (the host's other shapes) ends the lineage as a root. (2) A parent's rollout is looked for by its thread id under the sub-agent's own Codex home (`sessions`, found from `transcript_path`), so a lineage that crosses homes is unreadable and warns. (3) A sub-agent of a non-child parent whose transcript cannot be read now leaves a `warn` record on each push, where before it left none. (4) The evidence is the host's records and rollouts and temporary-home tests, not a live hook run of this change.
