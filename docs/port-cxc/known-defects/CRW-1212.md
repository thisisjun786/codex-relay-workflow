# CRW-1212 — the agent execution kind and the flow journal in the zone, and the cases of the cancelled CRW-1003

Source: the 0.5.0-alpha design issue R04 (CRW-1212). This is the port's own addition: CXC v0.2.40 (commit 3c1459ac) has no flow journal and no agent execution kind, so there is no oracle line for it. The Go files are internal/relay/store/dag_zone.go (the appended statements), internal/relay/dagsched/agent_union.go (executionOf, releaseOf), internal/relay/dagsched/release.go (ReleaseAgent, judgeNodeRelease) and internal/relay/dagsched/regions.go (agentRegionOwners).

- The Linear body of CRW-1212 takes three cases of the cancelled CRW-1003 (d1 duplicate_scope_owner, d2 managed_start_one_pending_issue, d4 the owner check by pair, and the three P3: the whole-repository key without a kind suffix, the reservation's packet read from the live node, the README's refusal name) and names the lines of the branch codex/crw-839-feature-packet-identity (PR 816, never merged: dev has no packet identity, no `packet_id`, no `registry/linkage.go` packet guard and no feature coverage); port: kept (the cases are implemented against what dev has: a "packet" is a node of an issue, the second packet is a second agent node of the same issue_key, d1 and d2 hold because the agent surface writes no relationship, scope binding or managed start, d4 and the whole-repository key are the owner rule of agentRegionOwners over the declarations of the nodes of one issue (a place is judged by every declaration of the issue, so a directory's owner covers the files under it, and the key of a place carries the kind of place as a suffix), the reservation reads the frozen manifest (reserveFrozen) and the README names the plan-write refusals; the packet identity of PR 816 stays where it is. Pinned by TestAgentSecondPacketNoScopeOwnerRefusal, TestAgentSecondPacketNoPendingManagedStartLimit, TestAgentRegionOwnerBroadTreeKeyCoversPairFileKeys, TestAgentRegionKeyWholeRepoCarriesKindSuffix, TestAgentReservationUsesFrozenReleaseManifest and TestContractReadmeNamesPlanWriteRefusal).
- The relationship `dag-release` and the relationship surface keep the tests and goldens they had; `--marker-root` is no longer required by the option parser and is required by the command on the relationship surface (the usage error moves from the parser to runRelease and keeps exit 4); port: kept (the agent surface starts nothing and has no marker root).
- `live_relationship_execution`, `live_agent_execution`, `cross_kind_execution`, `agent_region_owner_missing` and `agent_region_owner_ambiguous` are closed reasons in the detail of a disposition_conflict and not refusal reasons of contract/schema/relay-exit-codes.json (D-02: this build registers no new reason); port: kept.
- The relationship side of "current" is read from the rows the relationship kind already has: an open release intent (latestRelease whose managed request no dag_node_executions row is bound to yet), or else the newest execution of the relationship the node stands on (a correction is read under its own generation and manifest) while that relationship is not replaced (superseded_by: a replaced relationship has ended whatever was accepted of it) and is active or paused, or, with an active acceptance of that relationship's own result, anything but cancelled; a release a child was bound to is history and ends with its relationship (dag-release-close never ends it, so the intent alone cannot decide). releaseOf of a manifest on this side is the open intent or the newest initial/correction row of that relationship. A relationship the store does not hold counts as current, so an unreadable record never lets a node go to the other kind. R06 moves the node-scoped readers to executionOf and releaseOf; until then the readers of the frozen tables other than stateOf (below) do not see an agent execution (docs/relay/agent-execution-readers.md lists them); port: pending (R06).
- A chain of dag_agent_executions stays on one node of one plan and runs forward: the foreign key of supersedes_execution_id only checks that the execution exists, so the trigger dag_agent_executions_chain_check (appended to the zone ledger, not a key guard) refuses a row whose predecessor is of another plan or node or is not an earlier attempt; without it a row of another node could name A's last row as its predecessor and A would have no last row, so no current execution; port: kept. Pinned by TestAgentExecutionChainStaysOnOneNode.
- The reader set is computed to a fixed point over the type-checked calls (a function that calls a reader reads), not one level; a statement that creates, drops or alters a table is not a read, so the callers of the store's open are not readers. progress_replay.go and the other 18 indirect readers are classified in docs/relay/agent-execution-readers.md; port: kept. Pinned by TestReaderSetFollowsWrappersToAFixedPoint and TestReaderSetOfTheTreeHoldsIndirectReaders.
- The agent release judges the node without the issue-level ownership of a managed start: resourceHold's two issue queries (an open relationship of the issue, a managed start of it reserved or create_armed) moved to issueOwned, and a reading with ReadyOptions.AgentNode skips them for that node only, in the judgement and in the rejudgement under the lock; the parent count, the merge window, the edges, the inputs and the capacity still apply, and the node-level exclusion (live_relationship_execution) keeps a node to one kind. internal/relay/dagsched/ready.go is outside the edit regions of the Linear body because the issue-level checks live there; port: kept. Pinned by TestAgentReleaseBesideManagedRecordsOfTheIssue.
- The agent release reserves the slot before it writes the input manifest (reserveFrozen reads the row stored under the digest, or the body the release is about to store under it) and reads the stored row back before the execution row, so a refused reservation (capacity_exhausted, a slot subject another parent holds) leaves no manifest, slot or execution row, only the conflict row the refusal records; port: kept. Pinned by TestAgentReleaseRefusedReservationWritesNoRelease.
- A current agent execution holds its node and its edit regions in the reading (stateOf: running, skip:already_owned, holds), the one reading both release surfaces, dag-ready and DeclareRegions are judged on: without it a paused node of another issue that overlaps an exclusive place an agent holds became a candidate again and was released beside it (the agent's own issue was protected by agentRegionOwners only). Only stateOf moves to the union early; the other node-scoped readers stay R06. releaseOf refuses a store holding both kinds as current under any manifest, as executionOf does (it used to compare the manifest first and return the requested side); port: kept. Pinned by TestAgentExecutionHoldsItsExclusiveRegionsInTheReading and TestReleaseOfRefusesBothKindsCurrentUnderAnyManifest.
