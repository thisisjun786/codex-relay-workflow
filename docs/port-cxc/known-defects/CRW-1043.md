# CRW-1043 — the receipt wait's store path and its read-only sidecars

Source: the pre-merge evaluation of CRW-833, crw833-a2299397, defects d1 and d2 (the evaluation's c3 and c4 were judged out of scope by the parent). The defects are the port's own: no CXC v0.2.40 counterpart (commit 3c1459ac) has a receipt-wait reading. The Go files are internal/manage/capacity_signals.go (capacityReceiptWaitFor), internal/manage/relayread.go (relayReadStorePath, relayReadOpenStore) and internal/relay/store/hold.go (OpenInPlace, InPlaceRead).

- The receipt wait named the store with a cleaned path, so a state spelling that mixes a symbolic link and ".." could read another store than the relay's (d2); port: fixed on dev before this issue (CRW-865: relayReadStorePath joins raw through crwconfig.JoinRoot and relayReadOpenStore resolves the path the way SQLite does, and capacityReceiptWaitFor reads through it). Pinned by TestCapacityReceiptWaitResolvesTheStateSpellingThroughALink, which fails when the state directory is cleaned before the join (log in the CRW-1043 evidence directory).
- The read-only receipt query could create -wal and -shm beside a WAL store with no log frame (d1, part); port: fixed on dev before this issue (store.InPlaceRead reads a store whose log holds no frame immutable=1, which creates no sidecar, opens mode=ro only beside an existing index, and refuses a log that holds frames beside no index with ErrWALWithoutIndex). Pinned by TestCapacityReceiptWaitCreatesNoSidecarBesideACleanStore and TestCapacityReceiptWaitRefusesWithoutCreatingASidecar.
