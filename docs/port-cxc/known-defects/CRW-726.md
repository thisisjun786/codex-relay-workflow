# CRW-726 — unreadable program positions, expansion-built command names and the memory gate's twin

Source: `plugins/codexclaw/components/pabcd-state/src/worktree-guard.ts` at v0.2.40 (commit 3c1459ac) —
`evaluateCommand` :347-447, `splitSegments`/`tokenize` :191-248 and `DESTRUCTIVE_HINT` :448-451 — and
`plugins/codexclaw/components/pabcd-state/src/memory-write-gate.ts` — `classifyMemoryWrite` :88-140 with
`shellWriteDestinations` :25-264; the port in `internal/pabcd/hook/worktreedel.go` (`worktreeDelUnreadableProgram`,
`worktreeDelUnreadableCuts`, `worktreeDelUnreadableWords`, `worktreeDelNamedByExpansion`, the here-document readers)
and `internal/pabcd/hook/memorygate.go` (the shell branch of `memoryGateClassify`).

- A program position is read only as written, so a program the outer shell builds at run time is allowed and deletes the
  protected worktree: `bash -c "$(printf 'rm -rf ../repo')"`, `bash -c "$x"`, `eval "$(printf ...)"`, `eval $X`,
  `source <(printf 'rm -rf ../repo')`, `. <(cat f)`, `source "$F"`, `printf 'rm -rf ../repo' | bash`,
  `bash <<< "$(printf 'rm -rf ../repo')"`, and a here-document a listed shell reads whose body the outer shell expands
  (`bash <<EOF` with a body holding `$(...)`, a backtick substitution or `$X`) all run the removal; the memory gate
  returns no attempt for `bash -c "$(printf 'echo x > <memories>/a')"`, `printf 'echo x > <memories>/a' | bash` and
  `eval "$X"` (source `worktree-guard.ts:347-447` and `memory-write-gate.ts:88-140`; the oracle's own answers were
  re-checked by the parent with the guard's own test rig); port: fixed by CRW-726 (a security fix, by decision under the
  parity rule revision of 2026-10-03: `worktreeDelUnreadableProgram` names the position — a `-c` program of sh, bash,
  dash, ash, zsh, ksh or su with `--command=` and `su -cPROGRAM`, an `eval` operand, a `source`/`.` operand, a shell
  reading a pipe or a here-string, or a here-document a listed shell reads — and the guard refuses the command at every
  reading depth with `a program the guard cannot read before it runs: <what>`; the memory gate's shell branch fails
  closed on the same answer, beside CRW-741's f-string check; no recorded corpus fixture drives any of these forms, so
  none is tagged intentionally-changed).
- A simple command whose name word the outer shell builds is not recognised, so `$(printf 'rm -rf ../repo')`,
  `X=rm; $X -rf ../repo` and `"$X" -rf ../repo` delete the protected worktree (source `worktree-guard.ts:347-447`, the
  verb is read from the literal first word); port: fixed by CRW-726 (a name word that is wholly one command substitution
  or one backtick pair is refused as `a command line built by a command substitution` whatever its operands, and a name
  word that carries a parameter expansion is judged as `rm -r` with the command's literal operands and refused as
  `a command named by an expansion` only when one of them reaches the protected worktree).
- Accepted over-denial of the new rule: in a managed worktree the guard now also refuses `bash -c "$(cat script.sh)"`,
  `eval "$(ssh-agent -s)"`, `source <(kubectl completion bash)`, `curl ... | bash` and `$(which go) test ./...`, none of
  which deletes anything (source: the oracle allows all five, `worktree-guard.ts:347-447`); port: fixed as an accepted
  false positive of the security fix (the guard reads text and cannot run a substitution, so it refuses rather than
  allow; the issue body names the first four as accepted and the fifth is the same shape).
- A script file stays out of scope: `bash script.sh`, `source ./env.sh` and `bash < file` are read as today, because
  the file's contents are not in the text the guard reads (source `worktree-guard.ts:347-447`); port: kept.
- A here-document that feeds a command which is no listed shell is data, so no program position is read in it:
  `cat <<EOF` with a body holding `bash -c "$X"` is allowed, and so is the same with a quoted delimiter. A body a
  listed shell reads from standard input stays a program of its own and is judged (source `worktree-guard.ts:347-447`,
  which reads a here-document body as flat text); port: fixed by CRW-726 (the first form was an over-denial this change
  introduced, found by the PR's review; `worktreeDelUnreadableDataMask` blanks the data bodies before the segment scan,
  keeping the newlines so the line structure of the rest is unchanged).
- A subshell keeps the pipe that fed it, a descriptor before a here-document operator belongs to that redirection, and
  a program that runs `$0` as well as `$@` builds its command line from both: `printf 'rm -rf ../repo' | (bash)`,
  `bash 0<<EOF` with an expanding body, and `bash -c '"$0" "$@"' rm -rf ../repo` each ran the removal while the
  reading let it through (source `worktree-guard.ts:347-447`, which reads none of them); port: fixed by CRW-726 (found
  by the PR's Codex review: the subshell cut keeps the pipe, `worktreeDelUnreadableHereArgs` drops the descriptor with
  its operator, and `worktreeDelShellOperandsJoin` is joined by the same operands with `$0`).
- A here-document belongs to the command that holds its operator, and a redirection replaces a pipe on a shell's
  standard input: `cat <<EOF; bash </dev/null` with a body holding `$X`, and `printf 'rm -rf ../repo' | bash </dev/null`,
  are read as today (source `worktree-guard.ts:347-447`); port: fixed by CRW-726 (over-denials this change introduced,
  found by the PR's Codex review: `worktreeDelUnreadableLineShellAt` names the owning command, and
  `worktreeDelUnreadableStdinRedirected` sees the `<` that replaces the pipe).
- Only descriptor 0 replaces a shell's standard input: `printf 'rm -rf ../repo' | bash 2</dev/null` still runs the pipe
  as bash's program, so the pipe is refused. A descriptor other than 0 was read as a stdin override while this change
  was being fixed and let the pipe through (source `worktree-guard.ts:347-447`); port: fixed by CRW-726
  (`worktreeDelUnreadableStdinRedirected` accepts only `0</file`, `<file` and `<<`, and
  `TestWorktreeDelStdinDescriptor` pins both directions).
- A regression of generation 1 (71cf063d, P0, security): `worktreeDelUnreadableStdinRedirected` treated every word
  starting with `<` as a standard-input replacement, so the pipe suppression cancelled the pipe refusal for a descriptor
  duplication and `printf 'rm -rf ../repo' | bash <&0` and `| bash 0<&0` were allowed while bash ran the piped program
  (`| bash <&2` was allowed too, though it is no bypass today). The parent found it in its independent review of the
  head (source `worktree-guard.ts:347-447`, which reads none of these); port: fixed by CRW-726 generation 2
  (`worktreeDelUnreadableStdinFile` accepts only a word that opens a FILE on descriptor 0 — `<file`, `< file`, `0<file`,
  `0< file` — while a duplication, a close and a descriptor other than 0 keep the refusal, fail closed;
  `TestWorktreeDelPipeStdinDescriptor`).
- A gap of generation 1's own pipe rule (P0): the subshell strip handled only a subshell with no inner separator and no
  brace group, so `printf 'rm -rf ../repo' | (true; bash)`, `| (cd sub; bash)`, `| ( exec 2>/dev/null; bash )`,
  `| (cd sub && bash)`, `| { bash; }` and `| { cd sub; bash; }` were allowed while bash read the pipe (source
  `worktree-guard.ts:347-447`); port: fixed by CRW-726 generation 2 (`worktreeDelUnreadablePipes` reads the right side of
  each single `|` whole to the next separator at its own depth, and every simple command inside a subshell or a brace
  group is judged; `TestWorktreeDelPipeCompound`).
- A gap of generation 1's own pipe rule (P0): `worktreeDelUnreadableCommandWord` and `worktreeDelUnreadableLineShellAt`
  skipped only sudo, command, builtin and env, so `printf 'rm -rf ../repo' | nohup bash`, `| timeout 5 bash`,
  `| setsid bash`, `| nice bash`, `| stdbuf -o0 bash`, `| exec bash` and `| time bash` were allowed while the walk's
  own program reader skips the whole wrapper table (source `worktree-guard.ts:347-447`); port: fixed by CRW-726
  generation 2 (`worktreeDelCommandPrefix` and `worktreeDelCommandPrefixEnv` walk the one `worktreeDelQuoteWrappers`
  table, shared by every reader; `TestWorktreeDelPipeWrapper`).
- The same wrapper gap in `stripPrefixes`, which names a segment's command and stripped only sudo, command, builtin and
  env, as the oracle does (source `worktree-guard.ts:262-267`): `nohup rm -rf ../repo`, `timeout 5 rm -rf ../repo`,
  `nice rm -rf ../repo`, `setsid rm -rf ../repo` and `stdbuf -o0 rm -rf ../repo` from the checkout were allowed on dev
  and on this head; port: fixed by CRW-726 generation 2 (`stripPrefixes` now skips the same wrapper set through the
  shared prefix walk, which can only add denies; `TestWorktreeDelRemovalWrapper`).
- The memory gate reads the same check: `printf 'echo x > <memories>/a' | nohup bash` and
  `printf 'echo x > <memories>/a' | (cd x; bash)` are write attempts of their own and are denied without a grant, with
  `(a program the gate cannot read: ` in the reason (`TestMemoryGatePipeWrapper`).
- A compound command on the right of a pipe keeps the pipe through a trailing redirection, through nesting and through a
  shell compound's keywords: `printf 'rm -rf ../repo' | (bash) 2>/dev/null`, `| ( ( bash ) )`, `| { (bash); }`,
  `| if true; then bash; fi`, `| while true; do bash; done`, `| for i in 1; do bash; done` and `| case x in x) bash;; esac`
  were allowed while bash read the pipe (source `worktree-guard.ts:347-447`); port: fixed by CRW-726 generation 2 (the
  region is cut at its separators and its delimiters and every piece is judged; `TestWorktreeDelPipeReviewFindings`).
- A wrapper option that takes a separate argument hid the shell: `| sudo -u root bash`, `| env -u FOO bash`,
  `| sudo -p prompt bash` and `| timeout -s TERM 5 bash` were allowed (source `worktree-guard.ts:347-447`); port:
  fixed by CRW-726 generation 2 (`worktreeDelWrapperOptionArg` is the one table of per-wrapper option arity;
  `TestWorktreeDelPipeReviewFindings`).
- An unbalanced delimiter word swallowed the rest of the pipe scan: `printf 'rm -rf ../repo' | tee { | bash` and
  `| echo { | bash` were allowed although bash runs the piped program (source `worktree-guard.ts:347-447`); port: fixed
  by CRW-726 generation 2 (the scan reads forward from each operator and a depth that never returns to zero still ends
  the region at the next separator; `TestWorktreeDelPipeReviewFindings`).
- The pipe scan ran before the here-document data mask, so here-document data was judged: `cat <<'EOF'` with a body
  `echo hi | bash` and `cat > run.sh <<'EOF'` with a body `curl x | bash` were denied although the body is data
  (source `worktree-guard.ts:347-447`); port: fixed by CRW-726 generation 2 (the mask is applied first;
  `TestWorktreeDelPipeReviewFindings`).
- The pipe scan was quadratic: 32 KB took 0.79 s, 128 KB 12.5 s and 1 MB hung past 20 s, where the same command
  answered in 15 ms before this change (source: the guard's own hook timeout, `worktreeDelWalkBudget`); port: fixed by
  CRW-726 generation 2 (one forward pass; `TestWorktreeDelPipeScanIsLinear`).
- Widening `stripPrefixes` for generation 2's c15(d) broke the oracle's own first walk, which the file header promises is
  byte for byte: `nohup rm -rf ../repo`, `timeout 5 rm`, `nice rm`, `setsid rm`, `stdbuf -o0 rm` and `nohup git
  worktree remove ../repo` were denied by the first walk on the generation-2 head and allowed by the oracle (source
  `worktree-guard.ts:262-267`); port: fixed by CRW-726 generation 2 (`stripPrefixes` keeps the oracle's prefix set and
  the wider set is `stripPrefixesExtended`, which only the extended walk uses; `TestWorktreeDelPipeReviewFindings` pins
  the first walk's answer for every one of them).
- A compound body on the right of a pipe that the region reader did not reach: `| (case x in x) echo esac ; bash;; esac)`,
  `| (while true; do echo done ; bash; break; done)`, `| (for i in x; do bash; break; done)` and
  `| { while true; do bash; break; done; }` were allowed while bash read the pipe (source `worktree-guard.ts:347-447`);
  port: fixed by CRW-726 generation 2 (the region a pipe feeds runs to the end of the text when it opens a compound,
  because a compound's own separators and its case patterns make its end hard to find and reading past it can only
  deny too much; `TestWorktreeDelPipeCompoundBodies`).
- A gap of generation 2's own pipe rule (P0, security): the scan looked for a bare `|` byte, so the `|&` operator and
  a pipeline that continues on the next line (whitespace, a blank line or a comment after the operator) were no pipe
  and the shell on the next line was allowed while bash ran the piped program (source `worktree-guard.ts:347-447`,
  which reads neither form): `printf 'rm -rf ../repo' |& bash`, `|& (true; bash)`, `|& nohup bash`, `|&\nbash`,
  `|\nbash` and `| # c\nbash`; port: fixed by CRW-726 generation 2 (`worktreeDelUnreadablePipes` walks the text with
  the quoting reader and a carried depth, and `worktreeDelUnreadablePipeStart` skips the `&` of `|&` and the
  whitespace and comment a continued pipeline may hold before its command; `TestWorktreeDelPipeOperatorForms`).
- A regression of generation 2's own pipe rule (over-denial): the same bare-byte scan read a `|` inside a quote as an
  operator, so `echo "a | bash"`, `echo 'x | bash'` and `printf x | grep -e 'a|bash'` were denied although no shell
  reads a pipe there (source `worktree-guard.ts:347-447`, which reads neither); port: fixed by CRW-726 generation 2
  (the scan steps the quoting reader before it reads the byte, so a quoted `|` is data;
  `TestWorktreeDelPipeQuoteAndChain`).
- The generation-2 pipe scan replayed the quoting reader over the whole prefix before every operator, so a command of
  many pipes cost time quadratic in its length: 256 KB took 22.4 s where the same text answered in 109 ms after the
  fix (source: the guard's own hook timeout, `worktreeDelWalkBudget`); port: fixed by CRW-726 generation 2 (the
  reader and the depth are carried through the one forward pass; `TestWorktreeDelPipeScanIsLinear`).
