# CRW-1262 — the internal/manage tests wait for the disk's fsync: the package took 591 s when I/O stalled

Source: CRW's own tests, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no `crw manage` package. The Go side is `internal/manage/core_testhelp_test.go` (`TestMain`, `coreMain`), `internal/manage/core_tmpfs_test.go` (the choice of the root) and `internal/manage/core_tmpfs_cases_test.go` (its tests); the production store and its durability code are unchanged. Follow-up of CRW-1259, whose `/dev/shm` root was dropped after two regressions.

- A run of the package makes about 21,900 `fsync` calls (21,857 in the strace of the test binary; the issue counted 15,500 to 16,600), and on a loaded host each waits behind the other writers of the disk: one run took 591 s of the integration's 600 s, 229 s of it in one test; port: fixed (route chosen: the test-only tmpfs root; `TestMain` runs the package in `/dev/shm/crw-manage-tmp-<pid>` when that is fit, and in the caller's `TMPDIR` when it is not. Measured with `go test -count=1 ./internal/manage/` through `heavy_slot.sh`: 87.8 s on the disk at load5 24.7 to 21.8, and 61.9 s on the tmpfs at load5 18.6 to 16.8; the 21,857 `fsync` calls are the same both ways, 7.00 s spent in them on the disk against 0.68 s on the tmpfs. The disk was not stalled in either run, so a stalled-disk run of the package was not reproduced; what the route removes is the dependence on the disk, and the 300 s target under a stall rests on that, not on a run).
- Why this route and not a store option: the tmpfs route changes no production code, so the store's `fsync` stays the one every other caller and test of it exercises and no test-only switch can leak into the product; a test-only option on the store would have needed its own proof that the production constructor still syncs and would still leave the tests that write through other paths (the pump ledgers, the premerge repositories, the state directories) on the disk. The fallback (a test-only store option) was not needed: the tmpfs route held structurally.
- The first regression of CRW-1259: a test binary started again by a test (the supervisor child, any helper that goes through `TestMain`) made a `/dev/shm` root of its own and left it when it ended through `os.Exit`; port: fixed (the process that makes the root names it in `CRW_MANAGE_TEST_TMPFS_ROOT` as `<pid>:<root>`, every process a test starts inherits it, and a helper that finds a live owner and a directory named `crw-manage-tmp-<that pid>` of ours there uses it and makes and removes none; the owner removes the root after `m.Run`, so the isolation tree a helper leaves in it goes with it. Red first: the CRW-1259 behaviour behind the new seams left 241 `/dev/shm` roots in one run of the package and `TestTmpfsRootLeavesNothingAfterHelpersReexec` failed on it. Pinned by `TestTmpfsRootLeavesNothingAfterHelpersReexec` (a parent and a helper started from the test binary, the helper leaving through `os.Exit`: the helper has the parent's `TMPDIR`, and neither the `/dev/shm` stand-in nor the disk `TMPDIR` holds anything after) and `TestTmpfsRootDeclinedParentLeavesNothingAfterHelpersReexec` / `TestTmpfsRootFollowsAnAliveParentsDeclining` (a parent that chose no tmpfs, a same-name root or too little room, marks `<pid>:-`, and a helper it starts again chooses none, so it leaves no root through `os.Exit` in the fallback branch either; red first: evidence/round2/red-before-fix-720932a2.log) and `TestTmpfsRootHelperReusesTheParentsRoot` (a dead parent, a missing root, another pid's root, a foreign or relative directory and a marker without a pid are no marker)).
- The second regression: one small exec probe did not reject a small or full tmpfs, and every fixture write then failed; port: fixed (a root is made only if the base has at least 2 GiB and 20,000 inodes free to an unprivileged user (`statfs`), and a script written in it then runs; otherwise the tests keep the caller's `TMPDIR` and nothing is left in the base. Red first: the one-probe stand-in chose a root for each of a tmpfs one byte under the floor, one with 64 MiB, one with no bytes, one with no inodes and one an inode under the floor. Pinned by `TestTmpfsRootRejectsASmallOrFullTmpfs`, `TestTmpfsRootIsChosenAtTheFloorAndIsTheCallersToRemove` and `TestTmpfsRealHostReadsSpaceAndRunsAScript`).
- A run killed by a `go test` timeout or a signal cannot remove its root, and the root is memory; port: fixed (the next run removes the `crw-manage-tmp-<pid>` roots of the base whose pid is gone and leaves a root of a live pid, a name without a pid and any other directory. Pinned by `TestTmpfsRootSweepsTheRootsOfDeadProcessesOnly`). Named limit: a pid that is reused by another process keeps a dead run's root until that process ends; port: kept (a root is a few megabytes of memory and the sweep never removes the root of a live pid).
- Named limit: the root's name is only the prefix and the pid, so the tests' unix sockets under `TMPDIR` (the app-server control socket of the host fakes, `TMPDIR` plus 67 bytes) stay under the 107 bytes of a socket path; a first form with a random suffix made eight child-check and host-read tests fail with `connect: invalid argument`. A root of that name that is already there is not replaced and the tests stay on `TMPDIR`; port: kept (`TestTmpfsRootIsChosenAtTheFloorAndIsTheCallersToRemove` pins the name and the length, `TestTmpfsRootRejectsASmallOrFullTmpfs/a_root_of_the_same_name_is_there` the refusal).
