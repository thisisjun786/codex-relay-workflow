# CRW-1398 — follow-ups of the h bundle (CRW-1311, 1377, 1387, 1393, 1395; Argon V5): child-resume without child_check.disabled_servers, the newest batch plan on a moved-target fault, the lineage once marker, pairCheck on a failed receipt, the OS socket limit

Source: CRW's own bridge, manage tool and relay, no CXC oracle (CXC v0.2.40, commit 3c1459ac, has no `crw manage child-resume`, no execution policy with several pairs per role and no integration branch). The Go files are `internal/manage/childresume.go` (`resumeDisabledList`), `internal/crwconfig/childcheck.go` and `verifier.go` (`withChildCheckDefault`, `writeSection`), `internal/relay/dagsched/integration_target_check.go`, `cmd/crw/component_hooks.go`, `internal/bridge/mutations.go` and `internal/relay/hook/control.go`; the text is `docs/runtime-install.md` ("The servers `crw manage child-resume` switches off"). No relay store schema, receipt status, refusal code, fault class or skill is added or changed.

- `crw manage child-resume` (dry run included) refused with `disabled_servers_unset` when the configuration file did not name `manage.child_check.disabled_servers`, which no installer wrote and no document named (CRW-1311.md, the `crw manage child-resume --dry-run` bullet); port: fixed (a missing key reads as the default list, `crwconfig.DefaultChildCheckDisabledServers`, the empty list, with a warning on standard error and a record in the report, `disabledServers` with `source` `default`, `servers`, `warning`; a key the file names, an empty list included, is `source` `config` and is not warned about; a key that is not a list of names is still `disabled_servers_unset`; `crw config verifier`, the installation's one writer of the file, writes `manage.child_check.disabled_servers: []` where the file does not name it and keeps a list it has; `docs/runtime-install.md` names the key. Pinned by `TestResumeReadsAMissingDisabledServersKeyAsTheDefaultWithAWarningAndARecord`, `TestResumeDryRunReadsAMissingDisabledServersKeyAsTheDefaultToo`, `TestResumeKeepsAPresentDisabledServersListWithoutAWarning`, `TestResumeStillRefusesADisabledServersKeyThatIsNoList`, `TestResumeCommandRunsFromAConfigFileWithoutChildCheck`, `TestConfigVerifierWritesTheChildCheckDefault`, `TestConfigVerifierKeepsTheChildCheckListAFileNames`, `TestDefaultChildCheckDisabledServersIsAnEmptyListEveryTime`; `TestResumeCommandLineAndRefusals` now expects the host read where it expected the refusal, and `TestConfigVerifierRepairsAMalformedSection` reads only the verifier section of the file it checks).
- `crw manage child-check` keeps `disabled_servers_unset` for a comparison with no `--disabled` and no non-empty list: it compares servers, so with none it has nothing to compare and never reports `ok`; the installation's empty default is therefore a reason to name `--disabled`, not a list it can use; port: kept.
- A dry run of a `notLoaded` thread ends `settings_unverified` and stays so after the CRW-1311 bridge route. That route resumes a multi-pair role's thread without the pair because the bridge does not know which of the role's pairs the thread runs, and compares what the host reports; a dry run sends nothing, so it cannot resume to learn it. `child-resume` already resumes with the recorded model and effort (the record is the child's one authorized pair, there is no pair to withhold) and starts the turn only when the host's answer equals the record, which is the same compare-after-resume without the transmitted-or-not distinction. Pinned by `TestResumeDryRunReportsUnverifiedSettings` and `TestResumeOfANotLoadedThreadSendsTheRecordedPairAndComparesTheAnswer`; port: kept (no change to the route).
- Supersedes CRW-1311.md, item beginning "`crw manage child-resume --dry-run` ended with `disabled_servers_unset`": now port: fixed (the missing key is read as the default, the installation writes it and the configuration reference names it; the dry run on a `notLoaded` thread ending `settings_unverified` is kept, for the reason in the bullet above).
