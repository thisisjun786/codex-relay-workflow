Source: CRW's own design, not the CXC oracle. Found by the real-environment trial r2 S6 (evidence `ev/S6/20261012T050218Z`). The contract it corrects is CRW-692's (`CRW-692.md`, the DAG source), whose present-tense text now carries the rule and its reason. The Go files are `internal/manage/dagreview.go` (`dagReviewCheckIsStandingGap`), `internal/manage/pump_signals.go` (`pumpSignalDagSource.Collect`) and `internal/manage/dagreview_host.go` (`dagHostRelaySubcommand`).

The other answer the issue offers (only the unmeasured checks that concern an anomaly kind in the set block the clear) was not taken, for the reason written in CRW-692.md. Pinned by `TestPumpSignalDagClearsWithARealPlanPresent` (a real `DagReview` over a store with a plan) and `TestPumpSignalDagTransientUnmeasuredStillBlocksClear`.
- A parent that ran the relay through a wrapper script (`/tmp/s6r dag-accept ...`) got no refusal reported; port: kept, documented. The recognized forms are written in CRW-692.md and pinned by `TestDagHostRelayCommandFormsAreTheDocumentedOnes`; reading refusal envelopes whatever the program word is was not chosen, because it would report the refusals of commands that are not the relay's.
