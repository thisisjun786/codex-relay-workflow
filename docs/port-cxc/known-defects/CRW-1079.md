# CRW-1079 — reset --state removes the path the UTF-8 decoded session name names

Source: `plugins/codexclaw/components/cxc-ops/src/reset.ts` (:62-63) at CXC v0.2.40, commit 3c1459ac; the Go port at
`internal/pabcd/reset/reset.go` (:461-466). Found by the oracle review of 2026-10-10 (finding U12-01).

- The oracle lists `sessions/` with `readdirSync`, which decodes every name as UTF-8 (an invalid sequence becomes U+FFFD), and
  removes the path built from that string. A file named with bytes that are not UTF-8 (`ff 2e 6a 73 6f 6e`) is therefore never
  the file it removes: the path with U+FFFD is `absent` and the raw file stays, and when a real `U+FFFD.json` exists beside
  it only that one is removed. The port removed the raw `entry.Name()`; port: fixed (the oracle's behaviour, so no deviation
  remains: the name goes through the Node-compatible UTF-8 decoder before the candidate is judged, and the directory handle
  and its boundary protection are unchanged. Leaving a raw-byte file behind is the oracle's answer; the file can only appear
  through a filesystem that holds non-UTF-8 names, since the session writer sanitises keys, and the removal stays inside
  `sessions/*.json`).

  Pinned by `TestResetStateDecodesSessionNamesLikeNode` in `internal/pabcd/reset/reset_filename_test.go` (raw alone, raw beside
  `U+FFFD.json`, a valid name beside a raw one, two raw names; the lists are the oracle's `runReset`).
