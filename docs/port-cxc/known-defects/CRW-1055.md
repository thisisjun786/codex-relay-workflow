# CRW-1055 — improve propose after the sighting-based counts: multi-origin migration, migration loss, posted drafts, rerun cap

Source: Linear CRW-1055 (the remainder of CRW-988). The improve commands are a Go-only feature of the port, not part of CXC v0.2.40
(commit 3c1459ac), so there is no oracle file; the decisions below are the recorded answers to the issue's six questions. The Go
files are internal/manage/improve_propose.go (`improveProposeLegacySeenIndex`, the stored counts), internal/manage/improve_run.go
(the roadmap document) and the tests in internal/manage/improve_residual1055_test.go. The red output of the quoting fix is
/state/crw/crw-lane-improve/evidence/round2/red-d1-before-fix-02f7dc15.log.

- A first migration of a draft written without the improve item, for a record that now names several origins, counts what a draft
  written fresh over the same bundle counts: the first origin takes over the one stored sighting and every further origin is a new
  sighting, so the count grows by origins minus one once and a rerun changes nothing
  (TestImproveResidual1055MultiOriginMigrationCountsWhatAFreshDraftCounts). port: kept (the answer is the intended one; pinned by a test).
- The count of a draft without the improve item is its stored sightings, never a number read back from its body, so a merged count
  that ran past its sightings loses the surplus at the first migration (TestImproveResidual1055MigrationDropsTheSurplusOfAMergedCount).
  CRW-988 refused any body parser, and improve drafts are not yet used in operation, so the loss is the accepted hand-over cost.
  port: kept (a deviation from the earlier draft's number, accepted).
- A posted draft keeps its counts, project, title and body as the issue was opened with them, and only its seen list grows
  (TestImproveResidual1055PostedDraftKeepsItsCountsWhileItsSeenGrows). port: kept (intended preservation: the draft records an issue
  already opened).
- A repeated `improve run` of one boundary and ref drafts nothing new (CRW-920 C5), so a candidate the cap cut stays out of the drafts
  on that ref. It is not lost: the roadmap lists it, and when a candidate was left it names `crw manage improve propose --bundle
  <bundle>`, which drafts it with the configured cap (TestImproveResidual1055CutCandidateIsDraftedByProposingTheRoadmapBundle,
  TestImproveResidual1055RoadmapNamesNoCommandWhenNothingWasLeft). The bundle path in that line is written as one shell word
  (internal/quote.Shell), because a ref or a state directory may hold a space or a shell metacharacter and the line is meant to be
  pasted into a shell (TestImproveResidual1055RoadmapCommandSurvivesTheShell; before the fix the path split at the space, red).
  port: fixed.
- CRW-739 suppression applies only when the fingerprint or the title matches. That is the answer the CRW-739 issue set, so nothing
  changed. port: kept.
- The three comparison helpers (`improveProposeSeenEqual`, `improveProposeProjectsEqual`, `improveProposeStringsEqual`) compare
  element by element and join no separator, so values that are not valid UTF-8 stay equal to themselves and apart from each other
  (TestImproveResidual1055ComparisonsKeepInvalidValuesApart, TestImproveResidual1055BundleWithInvalidValuesProposesOnceAndStaysStable).
  port: kept (pinned by tests).
