# CRW-1159 — an advisory answer is decided again inside the lock that records it

Source: `plugins/codexclaw/components/pabcd-state/src/hook.ts` `handleUserPromptSubmit` (the same-turn guard :691, the loop-arm write :739-743, the trigger branch :755-780 and the passive modes :803-847) at CXC v0.2.40 (commit 3c1459ac). The Go side is `promptSubmitClaim` in `internal/pabcd/hook/prompt_submit.go`, called from the loop-arm branch there and from every recording write of `internal/pabcd/hook/prompt_trigger.go`. Found by the 10-10 CXC improvement review (A1-03).

- Supersedes known-defects.md, section "Found by the UserPromptSubmit hook port (CRW-644)", item beginning "The same-turn guard is read before any lock": now port: fixed (the lock that records an answer reads the state again, and an answer goes out only when that read does not record the turn yet: of two invocations of one turn that both passed the unlocked guard, the second to take the lock answers nothing. The recording writes no longer report success for a turn another invocation recorded. `TestCRW1159OneTurnIsAnsweredOnce` covers the loop-arm mandate, the trigger advice, the agbrowse directive of an un-armed session and the passive modes 2 and 3; `TestPromptSubmitLoopArmStoresTheTurnOnce` now expects the second answer to be empty).
- The passive branches choose the directive and the cursor on the same unlocked read (`hook.ts:803-847`), so a transition, a new binding, a PostCompact cursor reset or a moved active work phase that lands between that read and the write answers the previous phase's directive and writes the previous phase as `lastInjectedPhase` over the new phase; the trigger branch's advice names the work phase of the same stale read (source `hook.ts:755-780`, `:809-843`); port: fixed (the recording lock compares the phase, the orchestration flag and the binding, the cursor for the passive modes, and the bound goalplan's active work phase for an answer that names it; a moved input drops the decision, which neither answers nor writes, and the next prompt decides on the new state. `TestCRW1159AStaleDecisionIsDropped`). The cursor is not the only witness of the context generation: PostCompact leaves a cursor that is already nil as it is, so a compaction that lands after the decision cannot be told from the cursor alone. The handler marks the transcript (`host.MarkTranscript`, a stat of the regular file) before it reads the state, and a passive answer, which writes the cursor, is dropped when the recording lock finds a compaction record (`compacted`, the ContextCompaction item or the older `context_compacted` event) appended after the mark, a compacted record larger than the read buffer included, or the file replaced by a shorter one (`TestCRW1159ACompactionAfterTheDecisionDropsTheAnswer`, `TestTranscriptMarkSeesACompactionAppendedAfterIt`). The mark stands at the start of a record still being written when it is taken (a transcript that does not end in a newline), so a compacted record whose type was on disk at the mark and whose remainder lands before the lock still drops the answer, with the cursor already nil and the ContextCompaction item not yet written; a record whose start lies more than 1 MiB back is of an unknown kind, and any growth after the mark then reads as changed (`TestTranscriptMarkTakenInsideARecord`, `TestCRW1159ACompactionCompletedAcrossTheMarkDropsTheAnswer`). A transcript that cannot be read gives no mark and changes nothing (fail open). A turnless payload still records nothing (the oracle writes nothing for it), but its answer is decided again before it goes out (`promptSubmitVerify`: the state read inside the session lock, once the session has a sessions directory, and the transcript mark), so a phase move, a binding or work-phase move or a compaction that landed after the read drops the turnless directive too; a session with no sessions directory is read without the lock and is left without a file, and a lock that cannot be taken answers nothing, as for an answer that records (`TestCRW1159ATurnlessAnswerIsDecidedAgain`, `TestPromptTriggerTurnlessHintsPreserveThePhase`).
- Kept as they were: the memory-write marker is still written before every early return, a repeated turn's included (`TestCRW1159ARepeatedTurnStillRecordsTheRememberRequest`); the chat `orchestrate` commands keep their own owner and lock (no lock is nested); a lock or write failure still answers nothing; a write the rewrite guard skips (an unreadable state, or one the reader would not keep whole) and a write that published and then failed a later step still answer.
