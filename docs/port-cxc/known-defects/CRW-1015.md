# CRW-1015 — harness drift: the MCP file read bound to the plugin root, and a killed ast-grep probe is not a missing interpreter

Source: the pre-merge evaluation of CRW-617 (pull request 590, defects d1 and d2). CXC v0.2.40 (commit 3c1459ac) reads the file `mcpServers` names with `fs.readFileSync(path)` after `existsSync`, and its `runAstGrepCheck` tells a spawn that never started (`error.code` ENOENT, status 127/9009) from a probe the timeout killed (status null, signal SIGTERM, `error.code` ETIMEDOUT) (`plugins/codexclaw/components/cxc-ops/src/doctor.ts:556-578`, `:620-645`). The Go files are internal/runtime/doctor/harness_drift.go (harnessDriftMCPCheck, HarnessAstGrepCheck, harnessDriftRunKilled), manifest_targets.go (targetReadRooted, ValidateManifestTargets), rooted_read.go (doctorRootedRead) and harness_report.go (HarnessRun).

- The MCP file's containment was judged on a name (`targetEscapesRoot`) and the file was then statted and read again by that name, so a link inside the plugin root swapped for a link to a file outside it after the check led the read outside, and `drift:mcp` passed with the outside file's server count (harness_drift.go, harnessDriftMCPCheck; the same check-then-read in ValidateManifestTargets for the manifest's hook files and its `mcpServers` file; CRW-617 evaluation d1); port: fixed (the file is read through `doctorRootedRead`: the plugin root is opened once with `os.OpenRoot` on its real path, as `hookTrustEntriesReadContained` does, and the file is statted and opened through that root, so a link that leaves the root is refused at the open and the bytes come from that handle. The existence check and the read are one rooted open: a name the root cannot reach is the "missing" finding, an escape found at the open is the "resolves outside the plugin root" or "escapes plugin root" finding, and a directory is the read's own EISDIR. Pinned by TestHarnessDriftMCPReadCannotLeaveTheRootWhenALinkIsSwapped, TestManifestTargetsMCPReadCannotLeaveTheRootWhenALinkIsSwapped and TestManifestTargetsHookFileReadCannotLeaveTheRootWhenALinkIsSwapped, which swap the link between the verdict and the open through `doctorRootedReadSeam`, with the controls TestHarnessDriftMCPReadFollowsAnInsideLink and TestDoctorRootedReadClassifiesMissingAndDirectory; the red output of the first three before the fix is kept with the handoff).
- The Root refuses an absolute link even when it points back inside the plugin root, a link that leaves the root and returns, and a chain of more than 8 links; the stat-then-read it replaces followed all three; port: fixed (an intentional change from the stat-then-read it replaces: the refusal is the fail-closed direction and matches `hookTrustEntriesReadContained`; the answer is the escape finding. Pinned by TestHarnessDriftMCPReadRefusesAnAbsoluteLinkBackInsideTheRoot).
- A link that leaves the root toward a file that does not exist keeps the "missing" finding the paired walk of `targetEscapesRoot` gives it (CRW-652): `doctorRootedClassify` stats the name only to choose between the two findings, reads nothing, and a swap around that stat changes the finding, never what is read; port: kept (TestManifestTargetsKernelOrderMissingComponentKeepsPairedFallback and TestManifestTargetsRealpathOracleAgreementVerdict).
- The manifest `.codex-plugin/plugin.json` itself is still read by name in both `HarnessDriftChecks` and `ValidateManifestTargets`: the oracle reads it with no containment check, the file is the root of the plugin's own description and a deployment may link it from elsewhere, and no verdict about it precedes the read, so there is no check-then-read; port: kept (binding the manifest to the root would refuse such a deployment and is a separate decision).
- `HarnessAstGrepCheck` read every run with no exit status as the missing interpreter. The shared runner contract answered a probe the timeout killed with the same no-status shape as a spawn failure, so a probe over 8 seconds was reported as `python3 not found - install Python 3.9+ ...` where the oracle answers `sg not resolved — run ast_grep_helper.py install to provision`; the replay hid it by converting the recorded timeout to the status -1 and a port-only test pinned the wrong answer for a no-status run whose stderr was `signal: killed` (harness_drift.go; harness_report.go:84-98; CRW-617 evaluation d2); port: fixed (`HarnessRun.Killed` marks a run the timeout or a signal ended and is false for a process that never started; `harnessDriftRunKilled` reads that marker, the status -1 of a signalled `os.ProcessState` and the `signal: ...` text os/exec leaves on stderr of a no-status run as a killed run, and it is judged before the missing-interpreter case. The real runner `harnessRunExec` sets the marker for a timeout kill and for a signal death and leaves it false for a spawn failure. The replay passes the recorded ETIMEDOUT through as a run with no status and the marker, and the old port-only test is replaced by TestHarnessAstGrepCheckKilledWithNoStatus, TestHarnessAstGrepCheckSpawnFailureStaysMissingInterpreter and TestHarnessAstGrepCheckKilledMarkers; the red output before the fix is kept with the handoff).
- Supersedes known-defects.md, section "Found by the drift and ast-grep check port (CRW-617)", item beginning "A probe the runner could not start and one it killed at the timeout collapse": now port: fixed (a killed run is told from a spawn failure by `HarnessRun.Killed`, the status -1 or the `signal: ...` text; no runner choice is left open).
