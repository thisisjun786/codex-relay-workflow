# CRW-743 — divergence record loses the answers of the input it holds

Source: the differential-fuzz harness this issue carries from CRW-701 commit ea1ea0c2 —
`internal/dev/cxcfuzz/cxcfuzz.go`, the campaign's divergence write (`Campaign`, the
`Shrink` call and the `writeDivergence` call around it) and `internal/dev/cxcfuzz/cases.go`
(`Adopt`, `CheckCase`). The harness has no CXC v0.2.40 oracle counterpart: it is new dev-only
code, so the issue body is the specification here.

- A divergence file is written with the shrunk input but with the two answers of the input as it
  was generated: the campaign shrinks `input` and writes `canonical(shrunk)` as `Input`, while
  `Go` and `Oracle` still hold the values of the pre-shrink evaluation, because the shrinker's
  keep test used only the verdict and threw the candidate's answers away. `--adopt` copies the
  three fields verbatim into `testdata/<target>/cases.json`, and `CheckCase` then compares a
  freshly computed Go output against that stale `Go`, so an adopted case can never replay:
  measured on this head, `crw-dev fuzz echo --cases 40 --seed 5 --workers 1` under
  `CXCFUZZ_MUTATE=1` followed by `crw-dev fuzz echo --adopt <divergence> --tag open` wrote the
  case `{"mutate": true, "text": ""}` with `go` = `{"flag": true, "mutate": true, "n": 6,
  "text": ""}` (the pre-shrink run) and `TestCases` failed with `go {"mutate": true, "text":
  ""}, pinned {"flag": true, "mutate": true, "n": 6, "text": ""}`;
  port: fixed by CRW-743 (a record file losing the answers that belong to the input it records,
  fixed under the parity rule revision of 2026-10-03: the keep test now carries the last kept
  candidate's two answers into the divergence file, so `Input`, `Go` and `Oracle` describe one
  run and an adopted case replays. No recorded corpus fixture drives the harness, so no fixture
  is tagged intentionally-changed).
