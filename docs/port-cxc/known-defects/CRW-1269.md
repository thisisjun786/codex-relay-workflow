# CRW-1269 — dag-restart names the command that takes each unresolved call (R07 × F05)

Source: CRW's own design (0.5.0-alpha; found at the last verification of CRW-1215, head 0ac62aa7), not the CXC oracle. The Go side is `internal/flow/callstate`, `internal/relay/dagsched/agent_lifecycle.go` (`agentCallStates`, `resumeOfAgent`), `internal/flow/engine/{recon,resumecli,hold,resume}.go`, `internal/flow/journal/resumeenv.go`, `internal/flow/backend/agent/bound.go` and `cmd/crw/main.go`; the tests are `internal/relay/dagsched/agent_lifecycle_test.go`, `internal/flow/callstate/callstate_test.go`, `internal/flow/engine/recon_fix_test.go`, `internal/flow/backend/agent/held_turn_test.go` and `internal/flow/journal/resume_cli_test.go`.

- `agentCallHeld` judged a call unresolved when its newest event was not completed, null_model, refused or superseded, and named `crw flow recover` for all of them. Since CRW-1198 `crw flow recover` accepts only a call whose last terminal row is an unknown outcome with reason `dispatch_unknown` that nobody has cleared (`callState.held()`), so dag-restart named a command that refuses an unanswered dispatch intent, a call whose hold was cleared, and a call that ended held for an engine pause or a host failure. dag-restart now reads the call's rows with `callstate.Classify`, which `callState.held()` of the engine uses too, so the two cannot disagree: a call in recovery hold gets `crw flow recover`, every other unresolved call gets `crw flow resume`, and the report's detail names the arguments (`CALL (--adopt THREAD|TURN | --absent)`, `RUN SCRIPT`). A node with a call in recovery hold and another unresolved call is told to recover first. Pinned by `TestRestartNamesTheCommandOfEachCallState` (an unanswered intent, a started turn, a cleared hold, a held call, an unknown outcome of another reason, a hold) and `TestClassify`; port: fixed.
- The resume command did not exist: the action for a released node was the text `run resume`. `crw flow resume [--state DIR] [--socket PATH] [--repo DIR] [--args JSON | --args-file FILE] RUN SCRIPT` is defined by CRW-1200 (the resume walk): it opens the stored journal and the App Server (`engine.ResumeEnv`, installed by the binary like `RecoverEnv`), checks that the script and the arguments are the run's, and runs the walk. dag-restart's action for a released node is now `crw flow resume` too. Pinned by `TestGuidedCommandsAcceptEachCallState`: the built binary takes a call at an unanswered intent with `crw flow resume`, takes a call in recovery hold with `crw flow recover`, refuses it with `crw flow recover` once it was cleared (exit 1, not in recovery_hold) and takes it with `crw flow resume`, and exits 2 for a script, arguments or run that are not the run's; port: fixed.
- The dag-restart report calls every unresolved call `held` (state) and `reconcile` (resume value), as before; the state of a node whose call only waits for the run's resume stays `held`. port: kept.
- An edited script is not a resume of the run (`crw flow run W --resume-from RUN` of the design is not here); `crw flow resume` refuses a script or arguments whose digest is not the one on the run's `started` row. port: pending.
- Supersedes CRW-1215.md, item beginning "A recovery hold writes nothing": now port: fixed (the sentence "A held node needs `crw flow recover`, a released one `run resume`" is replaced: a node whose call is in recovery hold needs `crw flow recover`, a node with any other unresolved call or none needs `crw flow resume`; held is still derived from the journal, per call, by `callstate.Classify`).
- Supersedes CRW-1215.md, item beginning "`dag-restart` prints an `agent` object": now port: fixed (the released action is `crw flow resume`, and the `reconcile` action is `crw flow recover` for a call in recovery hold and `crw flow resume` for any other unresolved call).

- End condition of the third state: the decided answer said a call that ended held for another reason gets "that reason's resolution command". There is no such command per reason, and none is needed: `crw flow resume RUN SCRIPT` is the resolution for every reason a call ends held, so dag-restart names the same command for all of them. A held row asks no operator input (`--adopt THREAD|TURN`, `--absent`): what a hold needs is the condition outside the run gone (the budget, the host's availability, the engine pause, which does not outlive its process, the flow-bound directory) and a process that goes on with the call. The resume walk (`heldInPlace`) does that for every reason, but only on the host's proof of what the hold left open, and the proof can change the call's state: a running turn of the call is interrupted and confirmed ended first, and the call stays held while it runs (next item); a refused request is proven to have made nothing by the listing of the call's cwd or the marker of its operation, and when that proof fails (an incomplete listing, a thread with turns at the cwd, a turn carrying the marker) the call ends `outcome_unknown` (`dispatch_unknown`) with an escalation - it is then in recovery hold and dag-restart names `crw flow recover` for it. When the proof holds the call keeps its attempt, a `hold_cleared` row is written, and the reason decides only what the process sends: the original packet for a call held before its thread existed (`budget_exhausted`, a refused `thread/start`), the fixed continuation instruction for a delivered turn (`host_infra_*`, `engine_paused`); where the walk cannot go on in place (`worktree_failed`, a worktree whose files are not the hold snapshot, a thread that is not idle again for `host_infra_activeTurnNotSteerable`, an attempt held `recovery_hold` before it made anything) the call runs again as a new attempt. A resume while the condition outside the run still holds ends the call held again with a new row, never a refusal of the command. Pinned end to end by `TestGuidedCommandsAcceptEachCallState` (`internal/flow/journal/resume_cli_test.go`): the first process is the engine on the fake host, and a call held for `budget_exhausted`, for a refused `thread/start` (`host_infra_usageLimitExceeded`) and for a failed turn (`host_infra_serverOverloaded`) is read as unsettled by `callstate.Classify` (the reading dag-restart and `crw flow recover` share, so dag-restart names `crw flow resume`), refused by the built binary's `crw flow recover` (exit 1, not in recovery_hold) and taken by its `crw flow resume` once the host fault is gone (exit 0, `hold_cleared`, the same attempt ends completed); the failed proof by `TestHeldCallWhoseHostProofFailsBecomesARecoveryHold` (a thread with a turn stands at the cwd of the refused `thread/start`: the resume makes nothing, the call ends `outcome_unknown` `dispatch_unknown`, `callstate.Classify` reads recovery hold, so dag-restart names `crw flow recover`, and the built binary's `crw flow recover` no longer refuses it); the dag-restart side by `TestRestartNamesTheCommandOfEachCallState` (held and other unknown outcome -> `crw flow resume`); port: kept (a deviation from the wording of the issue: one resolution command for all held reasons, with this reason).
- A held row did not prove that the call's host turn had stopped: an engine pause whose `turn/interrupt` the host ignored (or whose end did not come within the interrupt wait) ends the call held `engine_paused` while the turn still runs. The resume sent the continuation on that thread without reading it, and once the host refused it (`activeTurnNotSteerable`) a later resume started a new attempt - `endOpenCalls` skipped terminal rows, so the old turn was neither interrupted nor confirmed ended before the node's worktree was kept and restored and replacement work began. Now `heldTurnsEnded` (`internal/flow/engine/hold.go`) reads every thread a held attempt of the call sent a turn on (also an attempt a resume's suffix ended superseded after its held row, `last_event` held): an idle thread runs nothing, a running turn of the call is interrupted and confirmed ended with `thread/read`, and a thread that cannot be read, runs a turn that is not the call's or stays active is an error. `heldInPlace` runs it before the call goes on: on an error the call stays held as it is (its held result is replayed, nothing is sent, its node stops). `endOpenCalls` runs it for every held call of the node (and the call's own) that the resumed script did not take over, before a new attempt, so the restore of the boundary and `supersedePrior` hold the new attempt `recovery_hold` while the old turn runs. An attempt held `recovery_hold` before it made anything starts again as a new attempt once the old turn is shown ended (it has no thread, and perhaps no allocation, to go on with in place). Pinned by `TestHeldPauseIsNotContinuedOrReplacedBesideItsRunningTurn` (the evaluator's trigger: parallel executors, a quota failure, the other turn ignores the interrupt; two resumes send nothing on its thread, make no thread and add, keep or restore no worktree of its node), `TestHeldPauseInASuffixKeepsItsRunningTurnInView`, `TestHeldPauseInterruptsItsRunningTurnBeforeTheContinuation` and `TestHeldAttemptThatWaitedForAnOldTurnStartsAgain` (`internal/flow/backend/agent/held_turn_test.go`); port: fixed.
- `crw flow resume` built its App Server backend without the flow binding (`agent.Config.Bound` nil), so `bindTurn` wrote nothing: a call held `host_config_flow_binding` sent its turn on resume with the binding still missing, and with no binding file the native spawn hook took the engine thread for a standalone one (no engine helper allowance, no pinned helper pair, CRW-1207). `journal.ResumeEnv` now gives the backend an `agent.BoundConfig` with the run id and the role table `engine.LoadPolicy` reads (the source `crw flow resume` pins the run's policy from), so every engine turn of the resumed process writes its binding line before `turn/start`, and a line that cannot be written holds the call `host_config_flow_binding` with nothing sent. No `crw flow run` over the App Server exists in this build (CRW-1207.md), so no run setting records whether the first process bound its turns; the resume binds them always, which only puts the run's own threads on the hook's engine path. The table is read by `ResumeEnv` and again by the command itself (two reads of the same policy source, an edit of the file between them would give the lines another digest than the run's). Pinned by `TestResumeWritesTheFlowBindingOrKeepsTheCallHeld` (the built binary: over a flow-bound directory that is not private the held call stays held and no turn is sent; after the repair the call's engine line is in its thread's binding file and the call completes); port: fixed.
