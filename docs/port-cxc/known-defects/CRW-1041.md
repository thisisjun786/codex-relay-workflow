# CRW-1041 — risk tier: the classifier and its decision record, and the original request left open

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no risk tier or batch gate; the pointer is the port). The Go side is `internal/risktier` (`Classify`, `ClassifyRegion`, `Decide`, `Decode`); the record is `contract/schema/policy-decision.schema.json`; the policy is written in [docs/relay/risk-tier.md](../../relay/risk-tier.md).

- CRW-1041 asked for lower gating of low-risk issues: no per-issue evaluation or independent review, one combined verification per batch, one fix per failing batch. Part a builds only the classifier and a decision record; no gate reads the tier, so nothing is skipped and `skipped_gates` stays empty; port: pending (the batch gate becomes F15 of the 0.5.0-alpha design, where every member still gets its own `premerge-record/1` and `dag-accept` and a failing member its own fix; that differs from the written request, so the Linear issue is not complete until the difference is accepted in the issue).
- The decided answer lists "sweeps and small edits outside high paths" as low. A path cannot say that a change is a sweep or small, and "a small fix is low" must not outrank an unknown path, so the allowlist holds only documentation prose under `docs/` and the plain data files of the listed testdata trees; port: kept (a sweep is high until its tree is added to the allowlist; the same decided answer says only a known allowlist is low).
- The decided answer lists "skill reference markdown that is not executable instruction text" as low. A path cannot tell a table of names from a page that changes a command procedure or an authority rule, and the verifier correction says such a page is not low because it is Markdown; port: kept (everything under `plugins/` is high by path. A management exception can set the execution tier of a page that only restates names to low, with its name and reason; the classification stays high).
- `tier = max(author declaration, derived)` and the management exception both exist; port: fixed in the record (`tier` is the classification and never changed by an exception; `execution_tier` is the tier whose gates run and differs from `tier` only through the recorded `exception`, which requires a name, a reason and a time).
- Verification round 1 found and fixed three defects: a `testdata` file or directory under a high tree (`internal/relay`, `internal/runtime`, `internal/hookswitch`, `internal/policystore`) was lowered by the testdata allowlist because the tree check ran only after the low rules; a directory-scoped `AGENTS.md` or `CLAUDE.md` under `docs/` or `testdata` was low because only the root files were protected; `Decode` read a schema-forbidden JSON null as a zero value. port: fixed (the high trees and the agent instruction names are a floor before the allowlist; `Decode` refuses a null outside `declared_tier` and `region_tier`); pinned by `TestHighTreesBeatTheLowAllowlist`, `TestNestedInstructionFilesAreHigh` and `TestDecodeRefusesNullsTheSchemaForbids`.
- Verification round 2 found and fixed two defects: the security corpus (`internal/dev/cxcfuzz/testdata/worktreedel/cases.json`, `memorygate/cases.json` and the other recorded cxcfuzz answers, and `internal/pabcd/gate/testdata/cases.json`) was low because its file names carry no reserved word; `Decode` accepted members the schema refuses, because `encoding/json` matches names without regard to case (`TIER`, `PATH`) and `omitempty` erased an empty `old_path` or `key`. port: fixed (the corpus trees are named in the high floor with the rule `security_corpus`; `Decode` requires the document to equal the record written back, member for member); pinned by `TestSecurityCorpusIsHigh` and `TestDecodeRefusesWhatTheSchemaRefuses`.
- Correction round 3 (after the pre-merge evaluation of c5ada9d6) found and fixed two defects of the same kind, which the two earlier name-based rounds could not close: `internal/role/testdata/dispatch/safety.json` and `internal/pabcd/cli/testdata/boundary.json` (the expected answers of the dispatch ledger's symlink and containment refusals and of the receipt guards) and `internal/pabcd/source/session/testdata/scenarios.json` (strings that `TestOracleParity` runs with `sh -ec`) were low as testdata data, because their names carry no reserved word and the extension is a data extension. A file name cannot say what a test does with the file, and the repository has dozens of other testdata trees whose files are oracle replays, goldens or commands. port: fixed (testdata is low only inside a tree listed in `lowTestdata`, now `internal/skill/search/testdata`; every other testdata file and tree region is high with the rule `testdata_not_listed`); pinned by `TestProtectedTestdataIsHighAtEveryLevel`, `TestEveryTestdataFileIsHighUnlessListedLow` (every testdata file of the repository against a hand-written low list), `TestUnlistedTestdataTreeIsHigh` and `TestLowTestdataTreesAreOnlyFedToPureTests`. This narrows the decided answer's "testdata-only" low rule to listed trees; the same answer says only a known allowlist is low.
- Pinned by the tests in `internal/risktier/risktier_test.go`: `TestClassifyPathSets`, `TestClassifyNamesTheRuleThatDecides`, `TestAuthorCanOnlyRaise`, `TestDiffThatLeavesDeclaredRegionsIsReclassified`, `TestExceptionChangesTheExecutionTierAndNotTheTier`, `TestSkippedGatesAreRecordedOnlyWhereTheyRan`, `TestDecodeRefusesATamperedRecord` and the two schema tests.
