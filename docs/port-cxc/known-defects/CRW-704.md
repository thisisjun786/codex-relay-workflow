# CRW-704 — the deletion guard's second walk, and the spawn classifiers' oracle surface

Source: the CXC v0.2.40 oracles the two targets compare against — `pabcd-state/dist/worktree-guard.js`
(`handleWorktreeGuardPreTool` at 568, `evaluateCommand` at 453, `evaluateSegment` at 347) and
`subagent-config/dist/spawn-attach-hook.js` (`inferRole` 493, `isFullHistoryFork` 520,
`isV2SpawnInput` 534, `isSpawnToolName` 586, `isCollaborationToolName` 591, `mentionedFolders` 832,
with `stripControlMarkers` 409, `denyEnvelope` 450 and `isFernetTokenShape` 550 internal) — against
the port's `internal/pabcd/hook/worktreedel.go`, `internal/pabcd/hook/worktree.go` and
`internal/role/spawn/{classify,inline}.go`, driven by the targets `worktreedel` and `spawn` in
`internal/dev/cxcfuzz`. The campaigns that found them are the 10-minute run per target recorded in
CRW-704's pull request.

- The oracle's deletion guard answers only the classes of difference its own comparison names, and the
  port's second walk deliberately denies shapes the oracle allows: a removal behind a shell wrapper
  (`sh -c 'rm -rf .'`, `bash -c "rm -rf ../repo"`, `eval 'rm -rf .'`, `su -c 'rm -rf .'`), a program
  nested past the reading depth, a removal cut out of a continuation or a comment, and a removal whose
  target arrives through a command substitution in a data argument (`printf '%s' "$(rm -rf .)"`).
  The campaign measured this on the delivered head: 49,204 cases, 44,719 agreeing, 4,485 Go-only
  denies, 0 oracle-deny the Go side allows, 0 differing reasons (source `worktree-guard.ts:191-218`,
  `:448-483`; Go `worktreedel.go`, the extended walk in `walk` and `judgeReadings`); port: fixed by
  the CRW-498 port (security class: each shape deletes a protected worktree and the oracle allows it;
  the port's second walk runs only when the oracle's walk allows and only adds denies). Four of the
  nine pinned cases in `internal/dev/cxcfuzz/testdata/worktreedel/cases.json` carry this as
  `intentionally-changed` (CRW-611, CRW-639, CRW-657 and CRW-670), each with the record naming that
  section; the CRW-585 case and the four plain allow/deny cases are `identical`.
- `mentionedFolders` answers a bare mention's capture without the `cxc-` prefix
  (`out.add(m[1].toLowerCase())`) and a link's folder as written, where the port answers
  `"crw-"+capture` for the bare branch and the folder as written for the link branch
  (`spawn-attach-hook.js:832-843`; `internal/role/spawn/inline.go`); port: kept, and pinned as the
  `identical` cases of the `spawn` target: the shim renames the bare capture on the way into the
  oracle (the table's note is that the folder X becomes crw-X, so the direction in is X for crw-X), so
  the two sides answer the same name.
- `stripControlMarkers` (409), `denyEnvelope` (450) and `isFernetTokenShape` (550) are internal to
  the oracle module, so the issue's rule leaves the port's `StripControlMarkers`, `DenyEnvelope` and
  `IsFernetTokenShape` out of the `spawn` target rather than reproducing an internal expression in
  the shim; port: kept (the six exported classifiers are the target's surface, and the exclusion is
  recorded in the target's own comment, in this file and in the pull request).
