# CRW-1136 — the native session and goals databases are read under one resolved root

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/session-binding.ts:60-68` (the newest-database lookup) and `plugins/codexclaw/components/pabcd-state/src/goal-active.ts:35-36` (`resolveGoalsDbPath`); the Go side is `internal/pabcd/host/root.go` (`CodexSQLiteRoot`, `HostHome`, `Root.Join`, which is `crwconfig.JoinRoot`), `internal/pabcd/host/session.go` (`newestStateDB`) and `internal/pabcd/host/goal.go` (`GoalsDBPath`). Found by the 10-10 combined review (B2-04), whose reproduction read a live row from the lexically cleaned directory while the directory the kernel selected held the same session archived.

- The newest-database lookup listed the root as the kernel resolves it and opened the lexically cleaned path, so a `CODEX_SQLITE_HOME` or `CODEX_HOME` ending in `<symlink>/..` listed one directory and read another's `state_<N>.sqlite`: `crw relay session current` accepted a session the selected database marks archived; port: fixed (the root is resolved once and every database path is `Root.Join`, raw text without cleaning, so the directory listed and the file opened are one; `DBPath` reports that spelling. A symlinked directory on the way is followed; only the database file itself must not be a link, as before. The live WAL read is unchanged. Pinned by `TestNativeSessionReadsTheDatabaseOfThePhysicalRoot`).
- `resolveGoalsDbPath` cleaned the same `..` with `path.join`, so the goals database was read under another root than the native one; port: fixed (`GoalsDBPath` joins under the same `CodexSQLiteRoot`; pinned by `TestGoalsDatabaseIsUnderTheSameRootAsTheNativeDatabase` and `TestGoalsDBPathHonorsSQLiteHomeOverCodexHome`).
- The database root was decoded from UTF-8 with U+FFFD before it was listed, so a root whose name holds bytes that are not UTF-8 was looked up under its replacement spelling, a directory that does not exist or holds another profile's databases; port: fixed (the root keeps its bytes for listing and opening; working directories keep the decode the oracle applies; pinned by `TestNativeDatabaseIsListedAndOpenedUnderOneSpelling`, which also covers quotes, a dollar sign, a backtick, a backslash and a space, and the raw-bytes case of `TestResolveNativeSessionSeesPathsAsNodeDoes`).
- An empty `HOME` with neither database variable set made the databases' directory `.codex` below the working directory, and a relative `CODEX_HOME` or `CODEX_SQLITE_HOME` resolved against it, so the identity depended on where the command ran; port: fixed (`HostHome` takes an empty or unset `HOME` as the account's passwd home, as the Codex host does, and a relative variable or home is refused with a message naming the variables; `Root.Note` records that an empty `HOME` was replaced and the relay CLI's `session current|bind|source` prints it on the stderr writer `Execute` was given (`Services.Stderr`), on a refusal too (the JSON answer on stdout is unchanged; hooks and `orchestrate status` do not print it), and nothing reads or moves a `.codex` below the working directory. `CODEX_SQLITE_HOME` stays a database-only override; pinned by `TestResolveNativeSessionResolvesRelativePathsAgainstTheWorkingDirectory` `TestCodexSQLiteRootSourcesAndNotes`, `TestResolveNativeSessionCarriesTheRootNote` and `TestSessionRootNoteReachesTheSuppliedStderr`).
