# CRW-1374 — follow-ups of CRW-1304: the next plan's child is compared at acknowledgement, the target check has its place in the integrator procedure, the daemon sweep's silence is a behaviour

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no integration branch). The Go files are `internal/relay/dagsched/integration_target_receive.go` (`observedTargetOf`, `integrationRefsOfChild`), `integration_target.go` (`targetStageRows`, shared with `recordedTargetHeads`), `internal/relay/adapter/daemon_sweep_no_network_test.go`, and, for the procedure, `plugins/crw/skills/crw-run/references/merge-readiness.md` and `docs/relay/dag-scheduler.md`. The relay schema, the delivery state and the supervisor state are unchanged; the target table is not written by this change.

- `observedTargetOf` found the target only by the `plan_id` its first record named, and a record of the same remote and remote ref is a no-op, so a child of a later plan on the same integration ref and remote branch was compared with nothing at acknowledgement (CRW-1304.md, the bullet on the receive and acknowledgement steps); port: fixed (the target is looked up by the child's integration ref, with no schema change and no new row: the child's integration refs are the refs a batch of one of the plans carrying the child's issue key was recorded for (`dag_integration_stages`, the intent rows) and the refs whose recorded heads, the bases and the `ref_moved` heads of their batches, include the child's `baselineRevision`; the plans' own recorded targets stay candidates. Of those targets exactly one with an observation compares, as before, and an issue no live node of a plan carries compares nothing. Pinned by `TestReceiveComparesAChildOfALaterPlanOnTheSameIntegrationRef` (both ways to the ref), `TestReceiveDoesNotGuessTheTargetOfAChildNothingTiesToTheRef` and the unchanged `TestReceiveComparesObservationWithBaseline`, `TestReceiveComparesNothingWithoutBothSides` and `TestReceiveComparisonMakesNoGitCall`).
- The reading is evidence-based and still no guess: a child whose plan has no batch on the ref and whose baseline is none of the ref's recorded heads (a child started from a head outside the integration path, in a plan that has not integrated yet) is not found, so a move that predates its start is not compared; port: kept (the periodic check below bounds how long such a target stays unseen).
- The periodic `dag-integration-target-check` had no place; port: fixed (it is the last step of every integrator pass in the existing integrator procedure of the crw-run skill, `references/merge-readiness.md`, section "Integrate a node by its commit"; a pass that integrates nothing still runs it. No skill is added; the plugin payload is re-recorded).
- `TestCheckTargetIsNotADaemonStep` proved the daemon's silence by searching source text; port: fixed (`TestTheDaemonSweepMakesNoGitOrRemoteCall` runs the sweep the daemon builds (`daemonFactory`) and records its faults over a store that holds a recorded target with an observed head, with a git stand-in first on `PATH` that records and fails every call, and requires the stand-in was never called; the same stand-in is then reached by `CheckRecordedTargets`, so the silence is the sweep's. The source-text test stays as a second, weaker guard).
- A push deferred after the remote was read records nothing, and one integration ref pushed to two remote branches in turn confirms only the newest target (CRW-1374 d3); port: kept (P3; not asked for here; to be seen again when a real use alternates).
