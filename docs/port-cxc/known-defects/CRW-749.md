# CRW-749 — spawn hook depth bound at Node's measured edge, and the divergence mode write failure in Node's words

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/subagent-config/src/spawn-attach-hook.ts:854,1089-1109`
(`JSON.stringify` of the answer, whose RangeError the hook's outer catch turns into no output) and
`plugins/codexclaw/components/pabcd-state/src/divergence-cli.ts:115,153` (the mode write outside any try; the entry point's
`unhandledRejection` handler prints `err.message`). Go port: `internal/role/spawn/hook_route.go` (`spawnHookRouteMaxDepth`),
`internal/role/spawn/testdata/hook/record-hook.mjs` and `oracle.json`, `internal/pabcd/cli/divergence.go`,
`internal/pabcd/cli/node_error.go` (`nodeSpelled`). The folded CRW-750 (Duplicate of this issue) is the divergence item.

- Supersedes known-defects.md, section "Found by the CRW-614 spawn hook routing port", item beginning "`JSON.parse` reads any depth, but
  `JSON.stringify` throws a RangeError near 4,458 levels": the writer bound is now measured, not estimated. With the spawn recorder
  (`record-hook.mjs`, Node v24.20.0, default stack, the oracle's `runSpawnAttachHook` called through the recorder's own `recordRoute`
  chain, bisected on the oracle itself) a `tool_input` holding 4,462 levels of junk is answered with the allow envelope and one
  holding 4,463 prints nothing. `spawnHookRouteMaxDepth` is 4,463 (`tool_input` is level 1, so its junk may nest to 4,462), where
  it was 4,400; the two edge cases are recorded by the recorder in `oracle.json` ("route: deep nesting", the last two steps) and the
  replay tests (`TestSpawnHookRouteOracleReplay`, `TestSpawnLegReplaysTheRecordedRouteSteps`) were red on the allow case before the
  change. The recorder's string walk became an explicit-stack walk, because a recursive walk overflows before the oracle's own answer
  does at this depth; every earlier recorded case is byte for byte unchanged (the recorder reproduces the checked-in `oracle.json`
  exactly apart from the two new steps); port: fixed for Node 24's default stack.
- The edge is a property of the Node stack, not of the payload: it moves with `--stack-size`, the platform, the Node version and the
  depth of the calling chain (the same oracle bisected from a bare script call prints 4,467 levels and not 4,468; through the recorder
  4,462 and 4,463; the old record says 9,103 with a 2 MB stack). A different edge gives the other answer for a payload nested between
  the two; the port fixes one, the recorded one, and a payload past it still prints nothing, which is the safe direction; port: kept.
- Supersedes known-defects.md, section "CRW-594 — a failed divergence candidate save (port-introduced defect, fixed)", item beginning
  "The divergence CLI's other error path keeps Go's spelling": the mode write's failure is now reported in the oracle's words
  (parity restored, not a fix of an oracle defect), for the create of the temp file (`*os.PathError`, "open '<path>'") and for the rename onto the mode file (`*os.LinkError`, "rename '<old>' -> '<new>'", a permission failure there reads `EACCES: permission denied, rename '<mode file>.<pid>.<ms>.tmp' -> '<mode file>'`; pinned by `TestNodeSpelledRenameFailure` and `TestNodeSpelledRenameRefusedByTheDirectory`, red before the round-1 fix). `RunDivergenceCli` returns the error spelled by `nodeErrorMessage`, wrapped so that
  `errors.Is`/`errors.As` still reach the cause (a cancelled context keeps the harness's Interrupted answer), and its caller prints
  `crw cli failed: EACCES: permission denied, open '<mode file>.<pid>.<ms>.tmp'` for a read-only divergence directory, where it
  printed `crw cli failed: open <path>: permission denied`; the name substitution `codexclaw` to `crw` is the only difference from
  the oracle's line. Pinned by `TestDivergenceCliModeWriteFailureIsSpelledAsNodeSpellsIt` (red before the change) and
  `TestDivergenceCliModeWriteKeepsTheContextError`; port: fixed.
- The recorder's explicit-stack walk keeps every JSON key as an own data property (`deep.mjs`): the first version assigned into a plain
