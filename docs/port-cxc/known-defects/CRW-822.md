# CRW-822 — reset link judgement through the pinned root, and the attest CLI surrogate

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/cxc-ops/src/reset.ts:16,35-42`
(`existsSync` and `rmIfExists`) and `plugins/codexclaw/components/pabcd-state/src/attest.ts:103`
(`rec.auditVerdict.trim().toLowerCase()`), with `JSON.parse` as the attest CLI decoder. Go port:
`internal/pabcd/reset/reset.go` and `internal/pabcd/cli/orchestrate_args.go`.

- Supersedes CRW-745.md, item beginning "A link whose immediate target is another link that ends in a dot component": now port: fixed (the judgement walks the target's components through the pinned root with `Lstat` and `Readlink` only, so a chain such as `interviews -> alias`, `alias -> keep/.` is decided without `root.Stat` and the target directory is never opened; pinned by `internal/pabcd/reset/reset_linkwalk_test.go`).
- Supersedes CRW-745.md, item beginning "A dot-ending link inside a pinned directory that is renamed before the removal is refused": now port: fixed (the walk never uses the root's path name, so the renamed pinned directory no longer changes the verdict and the link is removed as it was before CRW-745; `TestResetLinkDotTargetFailsClosedWhenThePinnedPathMoved` carries the removal, and `reset_linkwalk_test.go` pins that reset continues with the remaining candidates).
- Supersedes CRW-745.md, item beginning "`decodeCliAttest` decodes the attestation with `encoding/json`": now port: fixed (the syntax check stays `encoding/json`'s and the value is read with `pyjson.Loads` in `Surrogates` mode, so a lone surrogate escape reaches `lowerJS` as the three WTF-8 bytes it keeps; pinned by `internal/pabcd/cli/orchestrate_args_surrogate_test.go`).
- The `attest` package comment (`internal/pabcd/attest/attest.go:16-17`) still says a lone surrogate is not carried ("a Go string holds U+FFFD instead"), which this issue's CLI decode change makes stale: the CLI path now keeps it. The file is outside this issue's edit regions (sibling issues CRW-755, CRW-786 and CRW-811 work in `internal/pabcd/cli` and its neighbours), so the sentence is left for a later issue; port: pending.
- The walk's hop ceiling is 40 (the issue's answer), where `os.Root` itself follows at most 8
  (`os/root.go` `rootMaxSymlinks`). The count starts at one because the caller already read the
  candidate link's target, and the kernel counts that link among the 40 traversals it allows for
  the whole resolution: a chain of 40 links inside the target makes 41 and the OS reports a loop,
  so the walk must not call it present either. `reset_linkwalk_test.go`'s `chain_past_40` and
  `TestResetLinkWalkCountsTheCandidateLinkInTheCeiling` pin the boundary against `os.Stat` on the
  same chains; port: fixed (the first revision of this pull request counted only the links inside
  the target and accepted one extra, found in the Devin and Codex reviews).
- A deeper `..` target such as `keep/sub/..` has its intermediate directories opened by the walk:
  `os.Root.Lstat("keep/sub")` traverses `keep` with O_DIRECTORY. Measured with strace on a small
  program, the judgement this replaced opened nothing for that target (a single `os.Stat` on the
  root's path), so this is a real extra open, and the directory it opens is the one the trailing
  `..` names — the target. No verdict changes: `os.Stat` on the same link resolves it too. The
  issue's answer names `Lstat` and `Readlink` as the calls to use, and the walk uses only those,
  but a multi-component target cannot be resolved without traversing its intermediates. Removing
  it needs a component-wise walk over raw `lstatat`/`readlinkat` on the root descriptor, which the
  `os.Root` API does not expose; port: kept (recorded as a residual, found in the Devin review).
- A link that is not a directory link and ends in `..` (`alias -> keep/inner.txt`, with `a.json ->
  `alias/..`) refuses: `os.Root` reports ENOTDIR for the `..` step, and today's OS path reports
  ENOTDIR as well, so the verdict is unchanged and the link stays absent. Recorded because the same
  target resolves when the link is a directory link; port: kept.
- `decodeCliAttest` now keeps a lone surrogate in every attestation field, `planUnit` and
  `planPaths` included. Node converts a lone surrogate to U+FFFD when it hands a path to a
  filesystem call, so a `planUnit` spelling a lone surrogate names the U+FFFD file for the oracle
  and the WTF-8 name for the port: the two can accept different plan units (verified with Node v24
  on a directory holding only the WTF-8-named file, where `fs.existsSync` reports false). The
  issue's answer scopes the lossless read to the whole attestation, so normalizing the path-valued
  fields is left for a later issue; port: pending.
