# CRW-1077 — a goals database whose status column is not named `status` is unreadable

Source: `plugins/codexclaw/components/pabcd-state/src/goal-active.ts` (:70-74, `row.status`) at CXC v0.2.40, commit
3c1459ac; the Go port at `internal/pabcd/host/goal.go` (the column-name check :56-68), read by
`internal/pabcd/hook/session_hooks.go` and the goal firewall of `prompt_submit.go`. Found by the oracle review of 2026-10-10
(finding U10-001).

- SQLite keeps the column name a table declares, so for a `thread_goals` table declared with `STATUS` or `Status` the oracle's
  `row.status` is `undefined` and the answer is `unreadable` (which suppresses the interview) whatever the row holds, an
  `active` row included. The port scanned the first column without looking at its name and answered `inactive` for `paused` and
  `active` for `active`; port: fixed (the oracle's behaviour, so no deviation remains: the answer is `GoalUnreadable` unless
  the result's one column is named exactly `status` and holds text, the way `host/session.go` already checks the threads
  columns).

  Pinned by `TestGoalActiveStatusColumnNameCaseIsUnreadable` (`STATUS` and `Status`, paused and active; the lowercase schema
  unchanged) in `internal/pabcd/host/goal_test.go` and, for the hook, the `STATUS` row of
  `TestSessionHookPostToolUseCapturesAndReinjects` in `internal/pabcd/hook/session_hooks_test.go`.
