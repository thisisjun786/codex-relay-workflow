# CRW-1143 — an exit 0 is not proof that a flag changed

Source: CXC v0.2.40, commit 3c1459ac — `plugins/codexclaw/components/config-guard/src/multi-agent-v2.ts` (:100-118 report `changed: true` after any exit 0), `activate.ts` (the flag owned on exit 0 at :225-231), `deactivate.ts` (:184-185) and `features.ts` (`parseFeaturesList`, :61-76). The Go port is `internal/runtime/install/configguard/features.go` (`FeatureState`, `ParseFeatureStates`, `ReadFeatureStates`, `ReadDeclaredState`), `activate.go`, `deactivate.go`, `multiagentv2.go` (`SetMultiAgentV2State`), `intent.go` and `internal/runtime/install/features.go` (status). The finding is the 10-10 CXC improvement review A7-08.

- The activation took a flag as crw's, and the deactivation took it as disabled, on the CLI's exit 0 alone, so a CLI that changed nothing made the install report success and record ownership of a flag that was never on (source `activate.ts:225-231`, `deactivate.ts:184-185`); port: fixed (after the enables, and after the disables, the flags are read back with `codex features list` from the same config: only a flag observed enabled is crw's, a hard flag that stays off fails the activation with the flags observed on recorded, a soft one is a soft failure, and a disable that is not observed is reported as a failure that keeps the ownership. A list that cannot be read back proves nothing: the activation keeps its intent for the next explicit command (CRW-1153) instead of committing, and the deactivation reports the flags as unconfirmed. Pinned by `TestActivateOwnsOnlyAFlagItObservedTurnOn`, `TestActivateSoftFlagThatStaysOffIsASoftFailure`, `TestActivateSoftFlagUnsupportedUpstreamStaysSoft`, `TestDeactivateExitZeroIsNotAVerifiedDisable`, `TestDeactivateFlagPathsAndOrdering` and `TestFeaturesDisableBranches`).
- Supersedes known-defects.md, section "CRW-531 — multi_agent_v2 settings library", item beginning "A successful runner call reports `changed: true`": now port: fixed (`SetMultiAgentV2State` reads the state back from the same config after the runner and the repair; a runner that changed nothing, removed the file or wrote the other value is an error, and Changed is computed from the observed state before and after. Pinned by `TestMultiAgentV2ExitZeroIsNotAVerifiedChange` and `TestMultiAgentV2RunnerOutcomes`).
- Supersedes known-defects.md, section "Found by the CRW-442 config-guard features and managed keys port", item beginning "A malformed duplicate row is ignored without clearing a prior valid value": now port: fixed on every command path (`ParseFeatureStates` refuses a declared row that is cut short or does not end in true or false, and two rows of one flag that disagree, instead of reading them as disabled; `ParseFeaturesList` keeps the oracle's recorded answers for the replay. Pinned by `TestParseFeatureStates` and `TestParseFeaturesListRecordedEdges`).
- Supersedes known-defects.md, section "Found by the CRW-442 config-guard features and managed keys port", item beginning "The feature-list parser validates only the first and last fields": now port: fixed for the comment tail (a declared row ending in a comment is refused, not dropped); the free middle columns are the stage words and stay accepted, and a bare CR or U+2028 still separates fields, port: kept.
- A declared flag the CLI lists no row for was read as disabled; it is now unsupported, and `crw install features status` prints `unsupported` for it. The activation still tries it, so a soft flag missing upstream stays a soft failure; port: fixed (new state, `TestActivateSoftFlagUnsupportedUpstreamStaysSoft`).
- The two recorded disable cases `cli__disable__reverts_live_flags_and_key` and `cli__disable__features_list_unavailable_reverts_from_manifest` move from contract/notes/cxc/CRW-866.json to CRW-1143.json with the read-back: their scripted list reports every flag on, or fails, so both disables are reported as unconfirmed failures and the command exits 1; port: fixed (intentionally changed in the replay; the fixtures are unchanged).
- A flag whose enable exited nonzero after the CLI wrote it was left unowned and its intent closed, so the deactivation never turned it off; port: fixed (the exit status and the observation are separate: every flag the activation attempted and finds enabled is crw's, and a nonzero exit is still recorded as the flag's failure and fails the activation. Pinned by `TestNonzeroRunnerThatAppliedTheFlagKeepsOwnership`).
- The multi-agent switch measured its result with the read-only reader, which answers v1 for a file that is gone, unreadable or not TOML, so a runner that removed or truncated config.toml was reported as a verified disable; port: fixed (after the runner the file is read and decoded: a missing file on the disable direction, an unreadable one and an invalid one are errors in both directions, and Changed is computed from the measured state. Pinned by `TestMultiAgentV2RunnerThatLeavesNoReadableConfigIsNotAChange`).
