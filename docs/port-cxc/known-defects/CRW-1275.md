# CRW-1275 — steer-only management needs no turn-start settings, stranded closes spend no refusal budget, and parent queue ordinals avoid delivery retries

Source: CRW's own design, not the CXC oracle (CXC v0.2.40 has no management pump). Follow-up to [CRW-1273](CRW-1273.md); that entry describes the current management contract. The Go files are `internal/manage/config.go`, `internal/manage/pump.go`, `internal/manage/pump_queue.go` and the shared delivery core in `internal/manage/deliver.go` and `internal/manage/deliver_send.go`.

- An empty `settings.management` was rejected regardless of send mode; port: fixed. Explicit `manage.pump.steer_only: true` bypasses the turn-start settings judgement and sends management batches only through `steer_thread`, without `expected_settings`. Idle and unmeasured threads wait. The shared delivery core also enforces the selected mode, including an idle race after the pump's probe; locally unsent attempts wait durably without consuming retries or refusals. Default delivery still requires both management settings, and parent/supervisor queues keep their own delivery rules. Pinned by `TestManageConfigAcceptsSteerOnlyWithoutManagementSettings` and `TestPumpSteerOnlyNeverStartsAnIdleTurnAfterTheProbe`, including repeated idle rounds and active recovery under the same request id.
- A stranded close advanced the count that parks a batch after three bridge refusals; port: fixed. `mgmt_refused.ordinal` advances for both closes and proven refusals, while `count` advances only for proven refusals. One close followed by two refusals remains pending; the third actual refusal parks, with a log line that accurately names three refusals. A state lacking the new ordinal uses its existing count as the floor, preserving already spent ids; historical closes in that count cannot be identified retroactively. Pinned by `TestPumpStrandedCloseDoesNotCountAsARefusal` and the existing stranded-close tests.
- Parent queue refusal ordinals collided with `Deliver` retry request ids; port: fixed. The fingerprint-ledger regression reproduces an outage spending `B`, `B-r1` and `B-r2`; after the parent reasoning settings are corrected, the next parent batch formerly reused `B-r1` with a different fingerprint and remained frozen despite bridge recovery. New refusal batches use `B-m1`, then `B-m2`, through the same ordinal helper as management. Existing frozen pins retain their exact logical ids and are reconciled before any fresh batch is formed. Pinned by `TestPumpQueueRefusalOrdinalNeverCollidesWithDeliverRetryIDs`, which verifies recovery and exactly-once archival, and the existing parent queue pin/reconciliation tests.

These are source and temporary fake-bridge checks, not installation or live delivery evidence.

Correction: the idle-race guard initially missed the tool-selection default branch. A later `active_without_in_progress_turn` observation converted a definitely unsent waiting record to unknown; `get_operation` then found no request and spent `-r1` and `-r2`, creating a synthetic refusal that could eventually park the event without any delivery call. Steer-only non-steerable observations now preserve durable waiting, the frozen body and the same request id without reconciliation, retries or refusal increments. Default delivery is unchanged, and an uncertain reply from an actual `steer_thread` dispatch still stays unknown and is reconciled. `TestDeliverSteerOnlyUnmeasuredRaceKeepsWaitingWithoutRetries` covers idle-to-unmeasured waits, both real status/turn disagreements, unloaded/error/unknown observations and an active observation without a turn id. `TestPumpSteerOnlyObservationWaitNeverParksAndRecovers` covers eighteen observation-only rounds with no delivery calls, retry/refusal/ordinal consumption or parking, continued collection and recovery through one steer under the original id and frozen body. `TestPumpSteerOnlyKeepsUnknownAttemptFrozen` retains the separate uncertain-dispatch contract.
