# CRW-1137 — skill search cache and CLI sweep

Source: `plugins/codexclaw/components/skill-search/src/cache.ts:40-60` and `cli.ts:32-43,63-67,204-229` at v0.2.40 (commit 3c1459ac); the Go side is `internal/skill/search/cache.go`, `cli.go` (`ParseFlags`, `CacheKey`, `Help`) and `run.go`. Found by the 10-10 CXC improvement review (A8 kept items re-read as fix-now). Each item was reproduced by a failing test before it was changed.

- Supersedes known-defects.md, section "Found by the skill-search library port (CRW-278)", item beginning "The cache catches write failures as well as fetch failures": now port: fixed (a body that arrived and could not be stored is reported as `cache write failed for <key>; the fetched catalog was not stored, serving stale cache (<cause>)`, a fetch that failed or was refused for its size as `network fetch failed for <key>; serving stale cache (<cause>)`, so a full or read-only disk is no longer reported as a network outage. The stale entry is still what is served in both cases, as in the oracle. Pinned by `TestCacheWriteFailureIsNotReportedAsANetworkFailure` and the existing `TestCacheStaleAndMiss`).
- Supersedes known-defects.md, section "Found by the skill-search library port (CRW-278)", item beginning "A future cache mtime is fresh": now port: fixed (a file is fresh when its age is from minus one minute (clock skew between the writer and the reader) up to the TTL; a stamp further ahead is not fresh and the catalog is read again, so a wrong clock or a copied cache cannot pin a catalog for years. Pinned by `TestCacheFutureModTimeIsNotFresh` and the `future` case of `TestCacheThresholdRefreshAndZero`). The replay of the recorded cache fixtures stamped their files in 2099 to keep them fresh; they now read the catalog again, fail on the closed network and serve the stale entry with its warning, which `contract/notes/cxc/CRW-496.json` records on `cli__skill__search_all_sources_cached_and_offline`, `cli__skill__search_json_from_fresh_cache`, `cli__skill__search_plain_with_footer`, `cli__skill__search_stale_cache_served_offline`, `cli__skill__show_known_id_needs_network` and `cli__skill__show_unknown_id_exits_1`.
- Supersedes known-defects.md, section "CRW-496 — skill-search CLI", item beginning "Unknown options (including `--help`)": now port: fixed (`--help` and `-h` print the command's help (usage, options, limits, merge and score meaning, exit statuses) on stdout and exit 0 without reading anything; `--` ends the options and every word after it is a query word or id, `--help` and `--json` included; an unknown option (`--wat`, `-z`, `--limit=3`) or an option without its value (`--source`, `--limit ""`, or followed by another option or `--`: `--limit --refresh`, `--source --json`, `--limit -- --help`; a negative number is still a `--limit` value) is named on stderr with the usage and exits 2 before any read. A lone `-` is still a word. Pinned by `TestHelpAndUnknownOptionsAnswerWithoutTheNetwork`, `TestDoubleDashMakesTheRestLiteralQueryWords`, `TestOptionValueIsNeverAnotherOptionOrTheDoubleDash`, `TestCLIFlags`; the replay claims for `cli-help__skill__search_dashdash_help` and `cli-help__skill__show_dashdash_help` in `contract/notes/cxc/CRW-496.json`).
- Supersedes known-defects.md, section "CRW-496 — skill-search CLI", item beginning "Catalog cache keys retain only the first 24": now port: fixed (the cache file is `<source>-<sha256 of source, NUL and the whole URL>.cache` (`CacheKey`), so two URLs that begin alike, which every raw.githubusercontent.com address does, and the same URL under two sources never share a file. The files an earlier build wrote under the old names are not read again and age out; one catalog read follows an upgrade. Pinned by `TestCacheKeyHashesTheWholeURLAndSource`).
- Supersedes known-defects.md, section "CRW-496 — skill-search CLI", item beginning "`show --source gh` searches jaw, hermes and clawhub": now port: fixed (`show --source gh` is refused before any read with `show does not support source "gh" (use jaw, hermes, clawhub or all)` and exit 1, because gh searches code and has no catalog to look an id up in. Other unknown sources keep the oracle's answer, `no skill "<id>" in source(s) <source>`. Pinned by `TestShowRefusesASourceItCannotQuery` and the changed recorded case `show x --source gh` in `recordedOracleChanges`).
