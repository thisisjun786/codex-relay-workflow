# CRW-945 — store halt: corruption met in a sub-pass or an observation reaches the daemon's halt

Source: the pre-merge evaluation of CRW-848 (pull request 811, five P1 findings; the original text is the pr 811 line of the management pair-eval alerts). The halt is the Go relay's own safety rule (docs/relay/invariants.md I-564, CRW-848); the Python oracle (CXC v0.2.40, commit 3c1459ac) has no store halt, so no oracle file applies. The Go files are internal/relay/delivery/reconcile_pass.go and scheduler.go, internal/relay/supervisor/omission_observer.go, internal/relay/faults/managed_readings.go and sweep.go, internal/relay/daemon/daemon.go and observe.go, and internal/relay/store/halt.go (SiteError, DetectedCorruption).

- The reconciliation pass stored an attempt's failure as its retry reason and went on, and the delivery scheduler turned a delivery's failure into a note and went on to the next delivery and the cursor writes, so a failure of the corrupting class never reached the daemon's halt branch (reconcile_pass.go, ReconcilePass; scheduler.go, attempt and Deliver; CRW-848 evaluation P1 1); port: fixed (a failure the classifier calls corrupting is returned and ends the pass; any other failure stays the note or the retry reason it was. Cases: TestReconcilePassHalt_* and TestSchedulerHalt_*, red on the tree before the change with the output kept with the handoff, damaging one table of a temporary store so the rest of it still answers).
- The unclaimed-turn reading dropped the corruption result of its store read and handed back the reading it started with, so the halt helper never saw it (omission_observer.go, unclaimedOmission; P1 2); port: fixed (the reading carries the `store_unreadable: ` reason the delivery reader uses, which the helper classifies; a failure that is not of the class keeps the original reading. Cases: TestUnclaimedOmissionHalt_*).
- The halt helper dropped the failure of the marker's publication, and the fault sweep turned any observer error into a gap, so a marker that could not be written left the sweep recording on and the daemon without its in-memory halt (omission_observer.go, haltOnUnreadableStore; faults/managed_readings.go; P1 3); port: fixed (the helper returns a `store.DetectedCorruption` the classifier sees through, ManagedReadings returns an observer error of the class instead of a gap, and the daemon, which publishes through `halted` and keeps its halt whatever became of the marker, halts on it. A marker the observer did publish is not an error: the daemon takes it over between the sweep's reading and its recording, so the recording is not attempted. Cases: TestHaltOnUnreadableStore_*, TestManagedReadingsHalt_* and TestHaltCoverage_aMarkerThe*).
- A settlement that halted the store did not end the observation loop or the deferred settlements, and the tick went on to its later steps (observe.go, observe and settleDeferred; daemon.go, Tick; P1 4); port: fixed (the loop, the deferred settlements and the tick end where the halt stands. The settlement's own receipt lookups, which only noted a failure, now halt on one of the class. Case: TestHaltCoverage_aSettlementThatHaltsEndsTheObservationPass).
- The requeue's enqueue and the sweep's ledger writes were marked at the observation site because the caller passed the sweep's site for the whole sub-pass (daemon.go, Tick; faults/sweep.go, RecordAll; P1 5); port: fixed (the failing step names its site with `store.AtSite` and the daemon takes it with `store.SiteOf`: the requeue's enqueue and intent writes and the ledger's records and cursor writes are `write`, the scans and readings stay `observation`. Cases: TestHaltCoverage_aRequeueWriteIsMarkedAtTheWriteSite, TestHaltCoverage_aRequeueScanIsMarkedAtTheObservationSite and TestHaltCoverage_aSweepRecordingWriteIsMarkedAtTheWriteSite).
- Verification round 1 (four P1 findings on the first fix): the sweep read the next settled turn after the observer had published the marker, a marker followed by a failure that is not corruption was not taken over, a halt in the delivery or reconciliation pass dropped the counts and notes of the attempts made before it, and the read failures of those two passes were marked as write sites; port: fixed (ManagedReadings ends its page at the first reading after which the marker stands and the sweep returns the halt refusal without collecting or recording; the daemon takes the marker over whatever the sweep returned; Tick merges the delivery and reconciliation counts before it halts or returns the error; the scheduler's and the reconciliation pass's listing, cursor and gate reads are `observation` and their cursor and gate writes `write` through `store.AtSite`, an inner site standing. Cases: TestHaltFollowup_* in the daemon and supervisor packages and TestReconcilePassHalt_a*Site, TestSchedulerHalt_aListingRead*; the reconciliation counts kept by a halt are merged by the same code as the delivery counts and are not pinned by a Tick-level test).
- Verification round 2 (three P1 findings and one P2 on the second fix): a corrupt read of the observation loop was returned to Tick, which halted on it only after the loop's deferred settlements had run on the damaged store; a read inside the delivery attempt or the reconciliation attempt (past the listings) still reached the marker as `write`; an observer that published the marker and then returned a failure that is not corruption, or no reading, was taken for a gap and the next settled turn was read; and a delivery pass followed by a failed read of the waiting heads that was not corruption lost the pass's counts; port: fixed (observe halts on its own returned failure at the observation site before the deferred settlements, which then do not run; the store's querier marks a failure of the class at the statement that met it - a query `observation`, an exec, BEGIN or COMMIT `write` - and the single-row readers, `Store.All` and delivery's row helpers do the same, an inner mark standing (`store.MarkSite`); ManagedReadings checks the marker before each turn and after each observation whatever it answered; Tick merges the delivery pass's counts and notes as soon as the pass returns. Cases: TestHaltRound2_* in the daemon package, TestSchedulerHalt_a*InsideTheAttempt* and TestReconcilePassHalt_a*InsideTheAttempt*, each red on b61607772 with the output kept with the handoff).
- Not covered by this issue and left as found: the acknowledgement verification and the turn checks of the same tick still turn a failure into a note (daemon.go, Tick, `VerifyPendingAcks` is halted on its error but `ConfirmKeptAcks` and `TurnChecks.Pass` return none); port: kept (neither returns an error to halt on, and the evaluation did not name them).
