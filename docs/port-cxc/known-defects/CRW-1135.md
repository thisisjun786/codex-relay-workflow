# CRW-1135 — the session source binding probes Git under the bridge's policy, and an unknown native repository refuses

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/session-source.ts:41-45` (`gitProbeEnv`) and `:62-73` (`nativeGitIdentity`), against `source-identity.ts:61-66`; the Go side is `internal/gitprobe` (the policy `internal/bridge/worktrees` introduced, now shared), `internal/pabcd/source/git.go` (`Probe`, `NotARepository`), `internal/pabcd/source/session/session.go` (`git`, `nativeGitIdentity`), `internal/bridge/worktrees/worktrees.go` and `internal/manage/premerge.go` (`premergeGitEnv`). Found by the 10-10 combined review (B2-05), whose reproduction failed `crw relay session source` on a valid linked worktree with an inherited `GIT_OBJECT_DIRECTORY`.

- The session source probes removed four routing variables and the source capture six, so an inherited `GIT_OBJECT_DIRECTORY` naming a missing directory failed every binding probe of a valid worktree, and `GIT_CEILING_DIRECTORIES`, `GIT_NAMESPACE` or configuration injected through the environment reached the probes; port: fixed (the binding probes and the capture run under `gitprobe`'s read-only probe policy, which the bridge's worktree commands already used: every inherited `GIT_*` variable removed, no prompt, no lazy fetch, hooks at the null device, no file system monitor, no submodule recursion, no optional locks, no replacement objects, a time bound. The source probes take that policy through the environment (`GIT_OPTIONAL_LOCKS`, `GIT_NO_REPLACE_OBJECTS`, `GIT_CONFIG_COUNT`), so the argument lists stay the oracle's and the CXC replay's recorded git calls still match; the bridge passes the same options as arguments too. The capture keeps its output limit and its status, clean filters included; the receipt command keeps `source.GitEnv`. Pinned by `TestLinkedWorktreeSourceIgnoresInheritedGitRouting`, which compares the binding, resolution, capture and gate under `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_DIR`, `GIT_CEILING_DIRECTORIES` and `GIT_NAMESPACE` with a clean environment, and by `TestCaptureRunsNoRepositoryProgramAndIgnoresInheritedRouting`, where an inherited `GIT_CONFIG_PARAMETERS` and the repository's `core.fsmonitor` no longer run a program during the capture, and by the scenario `env_object_dir_breaks_probes`, whose recorded answers are replaced in `portFixed` of `oracle_test.go`).
- `nativeGitIdentity` took any failure of `git rev-parse --git-dir` (git missing, a time-out, a directory it may not enter) for "not in a repository", and binding then skipped the same-repository check, so an unrelated repository could be bound; port: fixed (only git's own discovery answer, exit status 128 with "not a git repository (or any of the parent directories)" or "not a git repository (or any parent up to mount point ...)" in the C locale, is outside a repository; "not a git repository: <gitdir>", which git prints for a linked worktree whose Git directory it cannot read, is a repository git could not read and refuses like any other failure; any other failure refuses with the binding unchanged, in `Bind` and in `Resolve`. git's discovery answer alone is not enough either: git skips a `.git` it may not stat, or a Git directory whose `HEAD` it may not read or whose `objects` or `refs` it may not enter, and then prints the same discovery message, so an ordinary repository whose `.git` is unreadable looked like no repository. `unreadableGitMarker` walks git's search path (the physical cwd and each parent on the same file system) and refuses as unknown when it passes such a marker; a marker git can read and rejects, such as the empty `.git` a sandbox leaves in `/tmp`, leaves git's answer standing. A native directory git answers is outside every repository still binds a repository root. Pinned by `TestNativeProbeFailureIsUnknownNotOutsideARepository`, `TestNativeUnreadableGitdirIsUnknownNotOutsideARepository` (real git, unreadable Git directory of a linked worktree), `TestNativeUnreadableOrdinaryGitdirIsUnknownNotOutsideARepository` (real git, an ordinary repository's `.git`, `HEAD`, `objects` or `refs` unreadable, from its root and a subdirectory), `TestNativeBelowReadableNonRepositoryGitMarkerStillBinds` and `TestRunOutputLimit`).
- The probes had no time bound, so a git that hung (a network-backed directory, a lazy fetch) held the command for ever; port: fixed (a binding probe is bound by `gitprobe.Timeout`, 30 seconds as the bridge's, and the capture's status by five minutes; past it the child is killed, as at the output limit, and the probe fails).
- The pre-merge evaluation removed its own list of six routing variables; port: fixed (`premergeGitEnv` is `gitprobe.Sanitize`, the common base without every routing variable, including the alternate object directories, the discovery boundary and injected configuration, with the evaluation's own index and identity applied once after it; the transport variables a fetch needs stay. Pinned by `TestPremergeGitEnvAppliesItsOverridesAfterTheCommonBase`).
