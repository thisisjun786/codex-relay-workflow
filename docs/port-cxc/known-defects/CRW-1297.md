# CRW-1297 — a relay child that cannot reach the daemon reports through the bridge

Source: CRW's own design, not the CXC oracle (the CXC bridge has twelve tools and no child report). A relay child
reports (`emit`, `intent-claim`, `intent-disposition`) only through the relay daemon's `control.sock`
(CRW-1286.md), and Codex refuses that connect in a sandbox without network access (CRW-1296.md). The Go files are
`internal/bridge/mcp/report.go` (`reportChild`, `WithChildReports`, `RegisterChildReports`), `schema.go`, `server.go` and
`main.go` there, `internal/relay/adapter/cli.go` (`Register` wires `hook.ForwardChild` and `store.ResolveStateDir` in at
executable composition, so `internal/bridge/mcp` imports no relay package but the leaf `argparse`: `internal/relay/store`'s tests
import it), `contract/schema/bridge-mcp-tools.json` with `descriptions_generated.go`, and, unchanged,
`internal/relay/hook/control_child.go` (`ForwardChild`, `handleChildCommand`) and `internal/relay/dispatch`
(`OwnedChildState`, `ExecuteOwnedChild`).

- The bridge has a thirteenth tool, `report_child` (`command`: `emit`, `intent-claim` or `intent-disposition`;
  `arguments`: that command's own options). The bridge runs outside the child's sandbox, so it connects to
  `control.sock` where a readOnly child, or a workspace-write one without network access, cannot. It sends
  `crw <command> <arguments>` through `hook.ForwardChild`, and the daemon runs it on its own store through
  `handleChildCommand`: the same checks and record as a direct report. Exit 0 answers `exitCode`, `stdout`, `stderr`
  and, for a JSON object, `report`; a nonzero exit is an error result carrying the daemon's answer. An addition to
  the CXC bridge; port: fixed in source, a deliberate deviation. The frozen listing grew by that tool:
  `contract/schema/bridge-mcp-tools.json`, `descriptions_generated.go` and the golden of
  `Test_tools_list_is_the_frozen_listing` were regenerated (`CRW_GOLDEN=update`), and the tool counts in
  `internal/bridge/mcp/main_test.go` and `internal/runtime/integration/isolated_home_test.go` are thirteen.
  `get_capabilities` lists no tools and is unchanged.
- The daemon alone decides where the record goes (CRW-1299.md, held on this route). The bridge finds the daemon from its own
  configuration: the App Server socket it was started with (`""` for the default), resolved the way `relay` resolves a
  state (`store.ResolveStateDir`: `CODEX_SESSION_RELAY_STATE` in the bridge's own environment, else the configured relay
  state or the directory discovery scopes by that socket). It reads nothing of the call: the arguments are read against
  the command's own options (`argparse.Parse`, as the daemon reads a child's command line), and a `--state`,
  `--socket`, `--kind-module`, `--json` or `--help`, which are no options of a child command, an option the command lacks
  and a missing required one are refused by the bridge in words naming the argument, asking the daemon nothing; a path
  relative to the child passes that reading and is refused by the daemon naming its option (the CRW-1299 check, held on
  this route); the child's argv, environment and working directory never reach the bridge. A bridge whose state has no
  daemon, or whose operator configured another state than the daemon's, answers
  `relay daemon unavailable; child report was not submitted`, writes
  nothing and opens no store: there is no local fallback; port: fixed in source. Pinned by
  `TestABridgeToolCarriesANetworklessChildsReceiptAndBlockedReportToTheDaemon`,
  `TestABridgeReportCannotRedirectTheDaemonsRecord`,
  `TestABridgeReportWithoutADaemonIsAnExplicitErrorWithNoLocalStore`, `TestReportChildForwardsToTheDaemonOnTheBridgesOwnState`,
  `TestReportChildNeverTakesTheStateFromTheCall`, `TestReportChildAcceptsOnlyTheChildCommands` and
  `TestReportChildSaysWhyTheDaemonRefused`.
- The operator's side: the bridge and the daemon must be configured for the same state. A bridge started with
  `CODEX_SESSION_RELAY_STATE` (or a relay state root) other than the daemon's finds no daemon and every report ends with
  the explicit error above; nothing is written to the wrong place. The child's MCP profile has to leave this bridge enabled.
- The create-time refusal (`internal/bridge/create.go`, CRW-1296.md) and `register --child-settings`'s refusal
  (CRW-1298.md) are unchanged: a relay child still writes its work, so a relay child is created under a sandbox that
  reaches the daemon. The tool is the safety net for a child created outside them (a thread without the `child` role, or
  one created outside the bridge), the decision of CRW-1286 and CRW-1296; port: kept.
