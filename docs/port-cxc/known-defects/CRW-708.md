# CRW-708 — JSON documents: pyjson, PABCD session state and goalplan

Source: the differential-fuzz harness `internal/dev/cxcfuzz` (this issue) drives three targets, each
against the CXC v0.2.40 oracle (commit 3c1459ac) imported under `ORACLE_ROOT`: `pyjson` against the
Python standard library JSON module through `python3 -m json.tool`
(`internal/dev/cxcfuzz/testdata/pyjson/shim.mjs`), `state` against
`plugins/codexclaw/components/pabcd-state/dist/state.js` `readStateStrict`/`writeState` (:494, :620)
through `testdata/state/shim.mjs`, and `goalplan` against the same component's `goalplan.js`
`readGoalplanDetailed`/`writeGoalplan` (:698, :921) through `testdata/goalplan/shim.mjs`. The Go sides
are `internal/pyjson` (`Loads`, `Dumps`), `internal/pabcd/state` (`ReadStateStrict`, `WriteState`) and
`internal/pabcd/goalplan` (`ReadGoalplanDetailed`, `WithGoalplanWriteLock`, `WriteGoalplan`).

## Defects

- The oracle cannot re-dump a lone surrogate with `ensure_ascii=False`: `json.tool --no-ensure-ascii`
  exits 1 with `'utf-8' codec can't encode character '\ud800'` and a partial stdout, where the port's
  `pyjson.Dumps` writes the `\ud800` escape. A real behaviour difference (exit code, stdout, stderr);
  pinned in `testdata/pyjson/cases.json` as `open-lone-surrogate-no-ensure-ascii`; port: pending.
- The oracle's `readStateStrict` keeps a lone surrogate escape in a stored string as the surrogate
  character (`JSON.parse` holds it), where the port's reader yields U+FFFD, so a state file whose slug
  or `supersededBy` carries `\ud800` is read back differently. This is the CRW-556 regression the issue
  names (a comparison that cannot tell the stored surrogate from the replacement character); a real
  behaviour difference and a data-loss class, not fixed in this PR; pinned in `testdata/state/cases.json`
  as `lone-surrogate-slug`; port: pending.
- The oracle reads a goalplan whose objective holds a lone surrogate escape, where the port's reader refuses it as `unreadable` ("unpaired JSON surrogate ... would lose stored text") so the surrogate is never silently replaced by U+FFFD. The same CRW-556 class as the state case above; a deliberate guard the port keeps; pinned as `intentionally-changed` in `testdata/goalplan/cases.json` as `lone-surrogate-objective`; port: kept (the port refuses rather than lose stored text).
- The oracle's `writeGoalplan` rewrites a plan and silently drops what its reviver does not keep (a
  repeated key, an unknown top-level key, `reviewRounds` its reviver discards), where the port's
  `WithGoalplanWriteLock` refuses the rewrite as `unreadable` with a "refusing to rewrite it" reason so
  no stored data is lost. A deliberate difference (the port guards data loss the oracle does not), so
  the cases are tagged `intentionally-changed`: `duplicate-work-phase-id`, `unknown-top-level-key` and
  `review-rounds-dropped` in `testdata/goalplan/cases.json`; port: kept (the port's write lock refuses a
  rewrite that would drop a key, by design; the oracle publishes the loss).
- The same lossy-rewrite class has two more shapes the generation-3 campaigns produce, and the port
  refuses both the same way: a work-phase task whose title is not a string, which the oracle's reviver
  skips (`goalplan.js:597-600`), so the port's write lock refuses the rewrite naming
  `workPhases[0].tasks[0]`; and a review round whose `planFiles` the oracle's reviver drops
  (`goalplan.js:404-407`), refused naming `reviewRounds[0].planFiles`. Pinned as
  `intentionally-changed` in `testdata/goalplan/cases.json`: `title-less-task` and
  `review-round-plan-files-dropped`; port: kept (the same by-design guard as the three above).
- The harness's own timestamp mask hid the difference it exists to catch. Both sides rewrote every
  millisecond ISO-8601 substring of an answer to `@TS@`, so a persisted timestamp the port rewrote to
  another instant compared `Same` (the parent's probe: two state answers differing only in a persisted
  `recordedAt` compared equal, and the real goalplan run masked the persisted
  `reviewRounds[].openedAt`). A defect of this harness, not of the oracle or the port; port: fixed (the
  mask is now by key, at the document's top level, over the one `updatedAt` a write restamps from the
  wall clock, and the read form's only when the reader defaulted it; every other timestamp-shaped value
  is compared as stored, and `TestStateCompareSeesAPersistedTimestampChange`,
  `TestGoalplanCompareSeesAPersistedRoundTimestampChange` and
  `TestMaskTopLevelTimestampLeavesANestedUpdatedAt` pin it).
- Two pinned cases pinned nothing. The `lone-surrogate-slug` (state) and `lone-surrogate-objective`
  (goalplan) inputs held a literal backslash rather than a surrogate escape, so both sides read the same
  text and both cases evaluated `Same` while the record still pointed at them for the class the seed-708
  campaigns produce 2,000 times over. A defect of this harness's own fixtures; port: fixed (both inputs
  are replaced with the campaign's own divergence, keeping each tag and record, and
  `TestPinnedDivergencesAreRealDivergences` plus `TestPinnedOracleAnswersMatchTheOracle` pin the
  invariant).
- The harness's own tests started a shim the host could not run. `TestPinnedOracleAnswersMatchTheOracle`
  and `TestShimsAnswerTheStartupHandshakeInertly` start the state and goalplan shims, which import
  `pabcd-state/dist/state.js` and `pabcd-state/dist/goalplan.js` under `DefaultOracleRoot` at their top
  level; on a runner that has node but no extracted oracle tree (every hosted CI runner) node exits with
  `ERR_MODULE_NOT_FOUND` before the shim reads a request, so both tests failed with "the oracle did not
  answer: EOF" and "the shim did not answer the handshake: EOF" instead of reporting the input the host
  lacks. A defect of this harness's own tests, not of the oracle or the port; port: fixed (one
  `requireOracleModule` helper beside `requireNode` skips a target whose shim imports a module that is
  absent under `DefaultOracleRoot`, naming the file, and both tests run it per target, so the pyjson
  parts still run wherever python3 is).

## Generation 5: the pre-merge evaluation's six defects

The pre-merge evaluation of head 34de8075 found six defects inside this issue's promise, all introduced
by this pull request. Each is fixed here rather than carried to a follow-up (the management rule of
2026-10-07 15:0x: a defect inside the promise is fixed in this pull request whatever its grade).

- The comparators flagged data loss only for a missing top-level key. `stateLostKeys` and
  `goalplanLostKeys` compared the top-level keys of the two published documents, so a key or array
  element lost at any depth, and a string whose code units the Go side replaced (the pinned
  `lone-surrogate-slug` writes the oracle's surrogate as U+FFFD), came back as a plain `differ`
  instead of the data loss the issue asks to name first. A defect of this harness; port: fixed (one
  shared `writtenLosses` walk compares every path of the oracle's published document, and
  `TestStateCompareSeesANestedLoss`, `TestStateCompareSeesAReplacedStringAsLoss`,
  `TestGoalplanCompareSeesANestedLoss` and `TestGoalplanCompareSeesADroppedArrayElement` pin it,
  with `TestStateCompareKeepsAPlainDifferencePlain` and `TestGoalplanCompareKeepsTheRefusalAndTheSame`
  holding the controls).
- The generators did not reach the boundaries the issue body names. pyjson nested only one to three
  levels; goalplan built one ordinary file with two phases, no repeated ids and no linked slug
  directory; the state `receiptClaimed` shapes put a whole surrogate pair after 254 characters, so the
  reader's 256-unit cut never split a pair. A defect of this harness; port: fixed (pyjson draws
  documents around Python's 1000-container recursion limit with the size computed before the build;
  goalplan draws repeated work-phase, task and criterion ids, a deep `dependsOn` chain and a plan read
  through a symlinked slug directory whose target stays inside the case root; state draws
  `receiptClaimed` of 255, 256 and 257 UTF-16 units ending in an emoji, so the 257-unit value is cut
  inside the pair. `TestPyjsonGenerateReachesTheRecursionBoundary`,
  `TestGoalplanGenerateReachesTheNamedBoundaries` and
  `TestStateGenerateReachesTheReceiptClaimBoundary` pin each shape).
- `TestPinnedOracleAnswersMatchTheOracle/pyjson` failed instead of skipping on a host that has node but
  no python3: the subtest passed `requireNode` and then met the pool's `NoCommand` for python3 as a
  `t.Fatal`. A defect of this harness's own tests; port: fixed (`requireOracleCommands` beside
  `requireNode` and `requireOracleModule` skips a target whose worker needs a command the host lacks,
  naming it).
- A package-level `var timestampText = regexp.MustCompile(...)` did work at program start, which c4
  forbids for a package `crw-dev` imports on every dev command. A defect of this harness; port: fixed
  (`isTimestampText` is a hand-written matcher over the time layout, so the package does no work at
  program start).
- `lookPathIn` fell back to this process's PATH when the environment held an explicit empty `PATH=`,
  so the dependency check and the worker's own environment disagreed: the check accepted a command the
  worker could not reach and the campaign recorded the worker's start-up failure as a fuzzing
  difference. A defect of this harness; port: fixed (only an environment with no `PATH` entry at all
  falls back, and an explicit empty one finds nothing; `TestLookPathInTreatsAnEmptyPathEntryAsEmpty`
  and `TestCampaignRefusesAMissingRequirementUnderAnEmptyPath` pin it).
- The state seed cases the issue body names were missing: no pinned input carried `unverifiedSubagents`,
  so neither the truncated `receiptClaimed` rewrite nor the 65th verdict was replayed without Node. A
  defect of this harness; port: fixed (`truncated-receipt-claimed` is pinned as `open` — the oracle
  keeps the lone high surrogate its cut leaves and the port writes U+FFFD, the CRW-556 class — and
  `sixty-fifth-verdict` is pinned as `identical`; `TestStateSeedCasesCoverTheNamedRegressions` pins
  their presence, and `TestCases` replays both with no Node).
