# CRW-1342 — the work tracking adapter reads and writes GitHub issues; what it leaves to its callers

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle names Linear in its relay and skills and has no tracking interface. The Go side is the new package `internal/tracking` (`tracking.go` the `Tracker` interface and its types, `github.go` the GitHub REST implementation, `blockedby.go` the `Blocked by:` reader, `token.go` the token sources, `errors.go` the typed errors); the tests are `internal/tracking/*_test.go` against an httptest fake GitHub and `live_test.go` (build tag `live`, read-only, not run by CI). No caller is wired: CRW-1343..1345 move the callers over, and work tracking stays on Linear until Jun says the switch is done.

- The adapter does not decide who may write: `Comment`, `Close` and `AddLabel` write for any caller that holds a token, while the transition design lets only the owning session write and an executor not (CRW-1342, "쓰기는 담당 세션만 한다"); port: kept (the caller owns that rule, as it owns the choice of the `[layer · session]` header; the adapter only refuses a header that is not one line of that form).
- `Blocked by:` is read from the body text, one issue per `#N` or `<owner>/<name>#N` reference on a line that starts with `Blocked by:`; GitHub's own issue dependency relations are not read, and a reference inside a code fence or in the middle of a sentence is not a block; port: kept (the transition design puts the block in the body so a Linear import keeps it).
- `Tracker.Milestone` leaves `Issue.SubIssues` empty, since the sub-issue list is one request per issue; `Tracker.Issue` fills it; port: kept (a caller that needs the sub-issues of a milestone reads each issue).
- A rate limit is a typed error (`*RateLimitError`, with `Reset` and `RetryAfter`) and is not retried; a write is not retried either; port: kept (the caller decides when to ask again, so a retry cannot post a comment twice).
- A comment is not idempotent: the same `Comment` call twice writes two comments; `AddLabel` is idempotent on GitHub's side; `Close` on a closed issue sets the state reason again; port: kept.
- A moved or renamed repository answers 301 and the adapter follows no redirect (a followed POST would turn into a GET), so the caller gets an `*APIError` of status 301 and fixes the repository setting; port: kept.
- A list read stops after 200 pages of 100 (20000 items) with an error, and refuses a `Link` next page on another host than the API root so the token goes nowhere else; port: kept.
- A milestone is read by number only, not by title; port: kept (the identifier is `<repo>#N`).
- The live read test needs a token (`GH_TOKEN`, `GITHUB_TOKEN` or `gh auth token`) and the network, so it is behind `-tags live` and CI does not run it; its transport refuses any method but GET; port: kept.
