# CRW-1397 — the follow-ups of the gate-only land (CRW-1354, CRW-1381, CRW-1382)

Source: CRW's own design (the decided defaults of CRW-1397 and its comment, items 1 to 9, from the grading, the verifications and the Argon V5 review of the f lane, head 86c1bc8d and 991df299), not the CXC oracle: CXC v0.2.40 (commit 3c1459ac) has no flow engine. The Go side is `internal/flow/ops/lane_halt.go` (`crw.escalate` with `end_land`, `closeRetryWaits`), `internal/flow/ops/seams.go` (`ErrCloseConflict`, `ReleaseResult.HeldRunState`), `internal/flow/ops/lane_land_head.go` (`readAuthors`, `landRelease`, `WarnLandHeldByEndedRun`, `WarnLandPairUnrecorded`), `internal/flow/ops/lane_decisions.go` (`endConditionsNotRun`, `WarnEndConditionNotRun`), `internal/flow/cli/schedrelay.go` (`Close`, `Release`, `runState`), `internal/flow/cli/settle.go` (`SchedulerSettle`, `relayRunNodes`), `internal/flow/cli/answer.go` (`crw flow cancel` of an ended run), `internal/flow/cli/start.go` (`FactPlanLiveRun`) and `internal/flow/cli/answer_rules.go` (`Judge`); the references are `docs/flow/script.md` ("Landing a head made outside a run", the design stage), `plugins/crw/skills/crw-canon/references/flow.md` and `plugins/crw/skills/crw-run/SKILL.md`.

- Item 1: `crw.escalate` with `end_land` recorded every Close error that was not a lost epoch as `close_refused`, so a transient relay error left the land's execution current under a run that had ended; the next land answered `land_node_held` and advised `crw flow resume` of a run that was over, with no settle step; port: fixed (only the relay's `disposition_conflict` refusal of the close - an accepted head that landed or may be in the target, wrapped by `SchedRelay.Close` as `ops.ErrCloseConflict` - is `close_refused`; any other error is asked again in place, twice, and one that keeps failing is the op's error, the escalation row written once. A land of a node whose holding run has ended answers `land_node_held` as before, with `held_run_state` and the warning `land_node_held_by_ended_run`, naming `crw flow cancel <run>`; nothing is refused that was not. `crw flow cancel` of a run that ended otherwise than cancelled gives up the executions it still holds and says so (a run that ended with none is refused as over, as before), and every cancel also gives up the executions the relay records under the run's id that its rows do not name. `TestAnEndedLandAsksAgainAfterATransientClose`, `TestLandHeadOfANodeAnEndedRunHolds`; red first. `TestAnEndedLandGivesItsReleaseBack` keeps its cases; its refused close is now the relay-kept kind, `ErrCloseConflict`, as `SchedRelay.Close` answers it).
- Supersedes CRW-1354.md, item beginning "Named limit: a run killed between the relay's release and the release row": now port: fixed for its first half (the cancel of that run gives up the execution the relay records under its run id, `relayRunNodes`); the second half (an execution of a session another run superseded, `stale_coordinator_epoch`) stays kept.
- Item 2: a land-head run's release claims the plan's coordinator epoch, so a run of the same plan that is still going (another node or milestone) stops `epoch_lost` at its next fenced write; nothing at the start said so; port: fixed (warn and record: `crw flow start land-head` adds the preflight fact `plan_live_run` naming every run of the plan that has not ended, printed and kept in the run's spec, and the start goes on; one run per plan stays the rule, and crw-run says not to use land-head while a run of the plan is going. `TestLandHeadStartWarnsOfALiveRunOfThePlan`; red first).
- Item 3, named limit: authors of more than one model family are refused `land_author_families_mixed` before any gate, even where a reviewer of a third family would be independent of all of them, because the node's execution row holds one author pair; lifting it changes the relay's stored form; port: kept (named in `docs/flow/script.md`).
- Item 4: crw-run's `SKILL.md` named `crw flow start land-head` without pointing at the command table; port: fixed (one line points at `crw-canon/references/flow.md`, the command table).
- Item 5: the end condition commands ran only when the first DESIGN's first audit round spawned an explorer, and a round that spawned none left no record; port: fixed (warn only: that round's `crw.exploreRecord` row carries one warning `end_condition_not_run` naming each command and its issue, and `end_conditions_not_run`; the op reads the commands from the run's `crw.milestone` row, so its arguments and input digest are those of the base binary and a run recorded before replays it. `TestADesignWithNoExplorerRecordsTheEndConditionNotRun`; red first).
- Item 6: no test pinned the refusal of the acceptance of a node whose current execution another run holds; port: fixed (test only, green before this issue's change, evidence red-1397-cli.log: `TestAcceptOfANodeAnotherRunHolds` - the run that asks for it is refused `reviewer_missing`, the review having to be a call of the run that holds the execution, no acceptance is written and the execution stays the other run's).
- Item 7: a land one of whose named authors was not read back recorded the first observed author's pair on the node's execution, although the set is unproven (`landAuthorModels` gives the review no authors and it is `independence_unproven`); port: fixed (the execution's author pair stays empty and the release row warns `land_author_pair_unrecorded` with the observed pair. `TestLandHeadLeavesTheAuthorPairOfAnUnprovenSetEmpty`; red first).
- Item 8: `crw flow answer` took the same decision applied again as a replay by its id alone, so a decision applied whole and applied again with `--answer-for` parts (or the reverse, or other parts) answered the old row as if applied; port: fixed (the input refusal `already_applied`, naming the parts the row holds and the parts given; the same parts again replay, nothing is appended. `TestAnswerAgainWithOtherPartsIsAlreadyApplied`; red first).
- Item 9: `readAuthors` kept the host's model and effort as read, so blanks around them made the relay's release refuse a malformed receipt, an unhandled release error; port: fixed (both are trimmed, and a model of blanks only is no model, `null_model`. `TestReadAuthorsTrimsThePair`; red first).
