# CRW-475 — the .crw tree refuses symbolic links: one rule for its writers and the evidence-root readers

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/codexclaw-dir.ts:7-26` (ensureCodexclawDir), `interview-ledger.ts:219-224` (appendEvent), `state.ts:216-242` and `:696-795` (appendLedger, appendInterviewEvent, ensureState, writeState), `metrics.ts` and `divergence.ts` (the metric ledger, the objective kind, the divergence mode and archive), `subagent-evidence.ts:155-170` (hasValidReceipt, the attempt counters), `source-receipt.ts:103` and `:124-126` (parseArtifactManifest) and `receipt-cli.ts:69-71` (the receipt path). The Go files are `internal/pabcd/crwdir/crwdir.go` (EnsureDir and the shared checks RequireDir, EnsureSubdir, CheckTree, NotLink and OpenFile), `internal/pabcd/state/ledger.go`, `write.go` and `outbox.go`, `internal/pabcd/interview/ledger/ledger.go`, `internal/pabcd/metric/metrics.go` and `divergence.go`, `internal/pabcd/evidence/evidence.go`, `attempts.go`, `lock.go` and `unrecordable.go`, `internal/pabcd/gate/manifest.go` and `internal/pabcd/cli/receipt.go`. The rule: a symbolic link, dangling or not, where a directory or a file of the project's `.crw` tree belongs is an input error. The writer refuses it with an error that names the path and says `symbolic link` (wrapping `crwdir.ErrLink`), writes nothing through it and leaves the link as it is; a CLI exits 1 with that message; a hook fails open: SessionStart creates nothing and its answer names the link, a chat orchestrate command is answered as not applied naming it, and the other hook writes (the remembered-prompt marker and the Stop budget among them) are dropped as a failed write always was, so no hook blocks on it (pinned by `TestHooksFailOpenWithAWarningOnALinkedStateTree`, `internal/pabcd/hook`). The red runs are `/state/crw/crw-lane-symlink-refuse-475/evidence/red/red-1.log` and `red-2.log`.

- The remaining race: every check here is made on the path and the writer then opens, creates or renames by path again, so a directory swapped for a link between `RequireDir` (or `EnsureSubdir`) and the later open, mkdir or rename is followed; `O_NOFOLLOW` guards the last component only. Only `.crw/.gitignore` is created through a descriptor. A party that can plant links in the workspace must win that window against a running write; port: kept (closing it means descriptor-relative walks, `openat` or `os.Root`, through every writer, which is beyond this issue's size; the window is the same one `makeMarkerDir` documented before).
- Writers of the `.crw` tree this issue leaves as they are. The hooks that reach the tree through `os.Root` or descriptor walks (`internal/pabcd/hook` worktree marker, render observations, review inbox, compaction recovery; CRW-198, CRW-488) keep their own confinement: below `.crw` a link that stays inside the workspace is followed, and so is one at `.crw` itself for the worktree marker, which makes `.crw` through its root rather than through `crwdir.EnsureDir`; the affordance recovery marker (`internal/affordance`) already refuses a link at `.crw` and at its directory and fails open; the dispatch ledger (`internal/role`, CRW-559) and the source binding (`internal/pabcd/source/session`) already check every directory, before and after making it. goalplan (CRW-340, CRW-357) and the freeze manifest (CRW-437) keep their own limits, and the config.toml swap publish and `crwdir.Publish` (which follows a link at the final path for the files outside the tree that use it) are untouched; port: kept.
