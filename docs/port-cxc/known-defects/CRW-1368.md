# CRW-1368 — the promotion-lock tests no longer rest on the host's load

Source: CRW's own test suite, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle's promotion lock is `runtime_install.py`'s `fcntl.flock`, which the Go port keeps (`internal/runtime/record/locks.go`, `Promote`). The tests are `TestAHeldPromotionLockRefusesAndReleasesTheCandidate` (`internal/runtime/install/decisions_test.go`), `TestAnInterruptedWaitRemovesNothing` (`sweep_test.go`), `TestAnInterruptedRollbackMovesNothing` (`interrupt_test.go`) and `TestDoctorReportsAHeldPromotionLockAndPromotionRefuses` (`internal/runtime/doctor/doctor_test.go`); the shared helper process is `golden.Helper` and `golden.Spawn` (`internal/runtime/golden/golden.go`).

- The helper process that held the flock for these tests could lose it: `golden.Helper` took the lock on a file it never used again, so a garbage collection in the helper ran the file's cleanup, closed the descriptor and dropped the lock, and `record.Promote` then succeeded while the test said another run held it (base `golden.go:62-71`; seen as `doctor_test.go:612: a promotion ran while another held the lock: <nil>` in 2 of 20 runs under five `nice -n 19` spinners); port: fixed (`Helper` keeps the file reachable to the end; pinned by `TestAHelpersLockSurvivesItsGarbageCollection`, which asks the helper to collect and then probes the lock).
- Three install tests ended a lock wait by a time window: a context of 300 ms and a `time.Sleep(time.Second)` before the holder let go (base `interrupt_test.go:22,27`, `sweep_test.go:105,110`), so a host slow enough to take the lock after 1 s let the command go on and take it; and `TestAHeldPromotionLockRefusesAndReleasesTheCandidate` shortened the process-wide `record.PromotionTimeout` to 200 ms (base `decisions_test.go:108-118`); port: fixed (the tests pass `record.WithSeam`, whose `Waiting` signal cancels the context at the first pause for the promotion lock, or moves a test clock past `record.PromotionTimeout`; the holder lets go only after the command has returned. The shared helper `interruptedWhileHeld` carries `TestInterruptedRegistrationsWriteNothing` the same way).
- The doctor test gave `record.Promote` a real 100 ms timeout (base `doctor_test.go:611`); port: fixed (a test clock, as above).
- Named seam: `record.Seam` (`Now`, `Waiting`) rides on the context through `record.WithSeam`; no product caller sets one, a context without it reads `time.Now()` and says nothing, and a wait that finds its context done returns the context's error before pausing, as it did on its next select. Product refusal, release and interrupted-wait behaviour is unchanged (pinned by `TestASeamSteersALockWait` and the existing `TestLockWaitsEndWithTheContext`). Port: kept.
