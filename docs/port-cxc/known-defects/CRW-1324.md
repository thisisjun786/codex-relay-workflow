# CRW-1324 — install, doctor and config say the policy and model premises before they break (policy digest, role helper models, policy path, config source)

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no execution policy, no flow engine and no `crw manage`. The Go side is `internal/pluginwiring/drift.go` (the policy file against the bridge record), `internal/affordance/hook.go` and `policy_warning.go` (the `SessionStart` hook), `internal/runtime/doctor/role_models.go` and `internal/role/livecatalog.go` (`ReadCatalogReadOnly`), `internal/flow/cli/runs.go` and `read_cmds.go` (`crw flow show`), and `internal/manage/config.go` with `internal/crwconfig/config.go` (`crw manage config`). Found by the 10-13 field trial (CRW-1315 items 5, 9, 20 and 30(b)). Everything here is a warning or a record; nothing blocks a start, a spawn or a run.

- Editing `execution-policy.json` left the bridge record naming the old digest, so the packaged launcher refused to start `codex-thread-bridge` in every new session and the screen showed only a failed handshake (item 5); port: fixed. `SessionStart` reads the Codex home's bridge record (a plugin-owned version-2 record that names a policy) and, when the policy file is missing, is not a regular file, or hashes to another digest than the record, adds a warning to the session context at every start and resume (like the PATH banner, since it can change between starts). The warning names the policy path, both digests (shortened) and the repair `crw install register-mcp --re-register-policy --execution-policy <path>`, and points to the policy editor, whose write (`policystore.Write`) edits the file and re-registers it through the same installer step in one operation. A host with no record, a record of another shape, a policy that cannot be read for another reason, or a matching policy gets no warning. No new command edits the policy: the one command that re-registers after a hand edit is `--re-register-policy`, and the one operation that edits and re-registers is the policy editor's write; both already existed and are now connected by the warning. Pinned by `TestSessionStartWarnsWhenThePolicyDigestDiffersFromTheBridgeRecord`, `TestSessionStartWithoutABridgeRecordHasNoPolicyWarning`, `TestSessionStartResumeRepeatsThePolicyWarning` and, against the real installer in a temporary home, `TestPolicyEditAndReRegisterClearTheSessionStartWarning`.
- `crw role helper` could point a role at a model the provider does not list (`inferhub/kimi-k3`, item 9) and nothing checked it; port: fixed. `crw doctor` has a `roleModels` entry: for each helper role in model mode (and each `fallback.model`) it checks the model against the live catalogue the role helper and the GUI list from (OCX's `ocx models live`, else the native Codex catalogue), names the catalogue it read (`state`, `source`, model count), and warns once per model no catalogue lists. The catalogue is read through `Options.ModelCatalog`, a seam tests fill, so no OCX process or network call runs in a test; the default read is `role.ReadCatalogReadOnly`, which keeps no cache file because the doctor writes nothing. No catalogue is read while no role names a model, and a catalogue that could not be read condemns nothing (`listed` is null and its state is recorded). The execution policy's allowed list is not a catalogue here: whether a role's model is in `allowed` and whether `agent-roles` exists are item 6, which the running lane of CRW-1330 (CRW-1316 S1) covers together with its doctor warnings. Pinned by `TestDoctorWarnsOfARoleHelperModelNoCatalogueLists`, `TestDoctorReadsNoModelCatalogueWhenNoRoleNamesAModel` and `TestDoctorRecordsAnUnreadableModelCatalogueWithoutWarningOfModels`.
- `crw manage config` reported `config.source` as `default` for a file it had read at the default location, and a management session recorded "there is no config file" (item 20); port: fixed. `config.source` still says where the path came from (`config`, `env`, `default`); the report now carries `config.loaded` beside it: true when a file was read at `config.path`, false when the location holds none and the defaults stand (`crwconfig.File.Loaded`). Pinned by `TestConfigLoadedReportsWhetherAFileWasRead`.
- `crw flow show` did not say which policy file the run holds (item 30(b)); port: fixed. The run records `policy_source` and `policy_digest` in its `started` row and a resume that reads another digest writes `policy_repinned`; `show` prints a `policy <path>  digest <digest>` line (with `repinned from <digest>` after a repin, `policy none (placeholder table, no execution policy file)` for a run on the placeholder table) and `--json` carries `policy_path`, `policy_digest` and `policy_repinned_from`. Pinned by `TestShowNamesTheRecordedPolicyPathAndDigest` and `TestShowSaysARunHasNoPolicyFile`. The `crw flow roles` half of item 30(b) (the store path, the digest, the six pairs, and the fake table only for tests) belongs to CRW-1330, not to this issue.
- Named limit: `crw flow show` prints what the run recorded, not the policy file as it stands now; the file can have been edited since (the run keeps its snapshot), and the digest of the file today is what `crw doctor` and the `SessionStart` warning compare with the bridge record. A run whose `started` row predates the `policy_source` field prints `policy none`.
- Named limit: the `SessionStart` warning reads the bridge record and the policy file at the start, so it says nothing about a drift that begins mid-session; the next start or resume says it. It reads only the Codex home's record; a bridge started from a record elsewhere is not judged.
