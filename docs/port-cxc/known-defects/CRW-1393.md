# CRW-1393 — the relay/hook socket tests follow TMPDIR past the sun_path limit, and the Stop adapter's row for a too-long control socket path

Source: CRW's own tests and the Stop adapter, no CXC oracle (the Python Stop adapter `stopadapter.py`, retired, left the same bare `[Errno 22] Invalid argument` row, which `Test33ReviewD5` pinned). Go files: `internal/relay/hook/socketdir_test.go` (`socketDir`, new), the fixtures `hookHome` (`adapter_test.go`), `Test33D1SurrogateBinaryPython` and `Test33D3DialErrnosPython` (`defect_fixes_test.go`), `Test33AdapterBinaryPython` (`adapter_parity_test.go`), `ownedState` (`control_marker_root_test.go`), and `internal/relay/hook/adapter.go` with `control.go` (`controlPathNote`). No relay schema, settings, journal row shape or decision record changes.

- The relay/hook tests made the directories their `control.sock` lives in under `TMPDIR` (`os.MkdirTemp("", ...)` in `hookHome` and the D1 and D3 fixtures, `t.TempDir()` in `Test33AdapterBinaryPython` and `ownedState`), so a lane `TMPDIR` over about 60 bytes pushed the socket path past the 104 (darwin) or 108 (Linux) byte `sockaddr_un` limit and a bind or connect failed with `invalid argument` (CRW-1362's merge, `TestControlRejectsAMarkerRootQuestionWithParameters`; CRW-389 recorded the same weakness); port: fixed (`socketDir(t, prefix)` makes the directory under `/tmp` whatever `TMPDIR` names and removes it at the end of the test; every test of the package that binds or dials a socket by path reaches it through `hookHome`, `socketDir` or `canonicalRoot` (the fixed `/tmp/crw-oracle`), and the tests that use `ControlAddress` get a short path too. With a 112-byte `TMPDIR` the package failed 46 tests on the base and passes on the head: `evidence/red-CRW-1393-long-tmpdir.log`, `evidence/green-CRW-1393-long-tmpdir.log` in the lane state).
- The product's control socket path can exceed the limit: it is `<relay state>/control.sock`, and the relay state is the directory of the configured `dbPath`, `CODEX_SESSION_RELAY_STATE` or the discovered state root, any of which a user can name. The owner's listener, the child's report, the marker-root question and the child-owner probe reach a long path through `ControlAddress` (`/proc/self/fd/<dirfd>/control.sock` on Linux). The Stop adapter dials the path itself, and its `guard_unreachable` row said only `[Errno 22] Invalid argument: '<path>'`; port: fixed (the row's `detail` adds, after the system's text, `(the control socket path is longer than a unix socket address holds: at most 103 bytes on darwin and 107 on Linux; give the relay state a shorter directory)` when the dial failed with EINVAL on a path of 104 bytes or more. The Stop is released as for any unreachable guard and nothing is refused; the record is the adapter's journal row. Pinned by `TestAControlSocketPathOverTheLimitIsAReadableUnreachableRow`; the `Test33ReviewD5` golden (`testdata/golden/Test33ReviewD5.json.gz`, the EINVAL case of `dialErrors`) now holds the note, its only changed line. Beside it, `crw config check` (and the `storage` entry of `crw doctor`) reports `socket_path_too_long` for a configured `relay_state` root whose store socket would reach the limit and warns for a `temp_root` that leaves no room (docs/runtime-install.md, docs/CI.md); a state directory named otherwise is not checked there.)
- Named limits. (1) The Stop adapter still dials the plain path, so on Linux a state directory whose `control.sock` is 108 bytes or more is unreachable to it although the owner can bind it through `/proc/self/fd`: reaching it the same way would also move the peer check, which reads the socket path from the connection (`authenticatePeer`), and is not asked for here; port: kept (warns and records, as above). (2) On darwin, which has no `/proc/self/fd`, `ControlAddress` still names that path for a socket of 104 bytes or more (docs/port/refactor-backlog.md, the [todo36][PR185 4128791771] entry); port: kept.
