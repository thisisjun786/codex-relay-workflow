# CRW-677 — the M2b classifier's destination registrations, handles and fallback

Source: no CXC v0.2.40 (commit 3c1459ac) behaviour is recorded here. The M2b state-copy classifier is a CRW
design (docs/port-cxc/state-migration.md), and its port lives in
`internal/runtime/install/migrate/classify.go`. The four defects below are port-introduced and are fixed by the
port, so they are Go-side defects rather than oracle ones. No recorded corpus answer changes, so no case is tagged
intentionally-changed.

- A scope's mapped destination root was registered for the destination temporary scan only through its children, so
  an abandoned older-run `.migrate-<26>-<n>.tmp` at a destination root was never reported when the source root held
  no mapped child (`internal/runtime/install/migrate/classify.go`, `classifyProject` and `classifyUser` at this
  issue's base commit); port: fixed by CRW-677 (both roots register their own destination directory with
  `noteDest`, and `noteDest` already returns early when the destination root is absent).
- Every directory reached the destination registration, including one the inventory only skips, so a container that
  holds only skip rows registered a destination directory nothing is written into: a link or a regular file there
  refused the whole preflight (`classify.go`, `emitDir` at this issue's base commit); port: fixed by CRW-677
  (`noteDest` is called only for a copy or transform disposition, so a skipped container and a skipped subtree are
  not registered).
- `classifyDestTemps` returned on the error branch and on the absent-directory branch without closing the parent
  handles `classifyOpenDest` had opened, so repeated scans of a destination path whose last directory is absent
  leaked one descriptor each (`classify.go`, `classifyDestTemps` at this issue's base commit); port: fixed by
  CRW-677 (every opened handle is closed on all three branches; the red-first case reads /proc/self/fd on Linux).
- A selected user pair whose source root is absent skipped `classifyUser` entirely, so the literal `~/.codexclaw`
  fallback enumeration never ran and the messenger service files `serve.out.log`, `serve.err.log` and `serve.cmd`
  (the service ignores the override) were not reported as excluded (`classify.go`, `classify` at this issue's base
  commit); port: fixed by CRW-677 (an absent source runs only `classifyUserFallback`, which reports the literal
  home and copies nothing from the absent source).
