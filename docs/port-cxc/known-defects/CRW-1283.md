# CRW-1283 — program wrappers, readable script files and assigned PATH

The CRW command guards (GitHub post, memory write, managed-worktree removal) read the commands of a Codex session through the shared shell reader. The reader read every `"$@"` as an unknown option, the GitHub guard refused a command it could not read while saying that the command names no GitHub post, and the guards' refusals recommended a readable script file that another guard then refused; port: fixed as decided by Sion (plan C and split (1), 10-13).

- Program wrappers. `ionice`, `nice`, `env`, `timeout` and the other program wrappers are read by their option grammar, and the command after them is judged: `ionice -c3 nice go version` passes every guard, `ionice -c3 nice gh pr comment ...` is a GitHub post, and a memory write or a removal of the managed checkout behind them is refused.
- Script wrappers that forward `"$@"` (named limit). The reader does not follow the arguments a script forwards, so it fails closed: a script whose body forwards `"$@"` (the shape of `.omo/mgmt/tools/heavy_slot.sh`) is refused by every guard, run by a shell (`bash f.sh ...`, `zsh f.sh ...`, `. f.sh`) or by its path; the memory and worktree guards read such a script run by its path for this. The reason names the path the user can follow, which no guard blocks: run the forwarded command directly, with `ionice` and `nice` in front of it if wanted. The real `heavy_slot.sh` is refused; a registry of trusted wrappers (path and sha256, granted and recorded) is the follow-up CRW-1290. Only `"$@"` (and `${@}`) marks a forwarder: a script run by its path that forwards through `$*` or `"$1"` is not read by the memory and worktree guards (the CRW-1287 limit below); run as `bash f.sh` it is read and its unknown arguments refuse a destination they would name.
- Readable script files. The memory gate reads a readable script file run as `bash f.sh` or `sh f.sh` and judges its writes; a script whose destination it cannot place is refused with the advice to use a direct command with a literal program and absolute write paths, which the GitHub and worktree guards allow for a command without their targets. `git push` inside a script file is refused by the GitHub guard.
- PATH assignments (named limit). Every assignment to PATH is refused (`unreadable-program: assignment to PATH changes which program runs`), whatever the value and the program: a prefix (`PATH=/d cmd`), a statement, `export PATH=...` and `env PATH=... cmd`, as at c007bd50; and, stricter than c007bd50, which read them as other declarations, a declaration word that spells PATH in quoted or unquoted parts (`export 'PATH=/d'`, `export "PATH=$D"`, `export "P"ATH=$D`, `export "PATH"=$D`), a spelled start of PATH completed at run time (`export P$X=/d`), zsh's `path` in a declaration word (`export 'path=/d'`) and a declaration builtin reached as a command (`X=1 export PATH=/d`). A `gh`, a `git push` or a script behind an assigned PATH stays refused with it. Reading a literal PATH (the program it selects is judged; a value with an expansion is refused only where it may select a target program) is the follow-up CRW-1292.
- Refusal wording. The GitHub guard's reader refusal says `The reader cannot tell whether the command posts to GitHub.` instead of `It names no GitHub post.` (Sion decision 1), and the refusals of both guards name a direct command with a literal program and absolute paths instead of a readable script file; the CRW-1178 wording tests and the two memorygate fuzz seeds `crw650-open-triple-quote` and `crw857-memorygate-codex-home-expansion` pin the revised texts, their decisions unchanged.

The four named regressions are `TestGithubPostGuardAllowsAWrapperThatNamesNoPost`, `TestMemoryWriteGateReadsAReadableScriptFile`, `TestCommandReaderPathAssignmentResolvesTheProgram` (it asserts the PATH refusal; the allowing side is CRW-1292's) and `TestGuardRefusalNamesAPathAnotherGuardAllows`. The forms the security reviews and the Opus verifications found are refusal tests (`crw1283_review_test.go`, `crw1283_probe_test.go`, `crw1283_identity_test.go`, `crw1283_loop_test.go`, `crw1283_zshparam_test.go`, `crw1283_planc_test.go`) and the three-guard rows of `internal/pabcd/hook/testdata/shellir/rows/49-crw-1283.txt`; the PATH rows there record their CRW-1292 case and the refusal every gate gives now. `TestCRW1283GuardFuzz` composes the wrapper, PATH, script, program-file and out-of-order PATH forms around each guard's target and asserts that every form carrying a target is refused; its doc comment gives the differential against c007bd50. Existing security rows and their recorded deviations are unchanged.

Limits that predate this issue and are not widened by it: the memory and worktree guards do not read a script run by its path unless its body forwards `"$@"` (pinned by the fuzz as class ownlimit; follow-up CRW-1287); a `#!` interpreter named by an absolute path is read by its basename; a copied or linked binary run by its absolute path, or by a bare name, is read by its name; a PATH a builtin assigns by name (`read PATH`, `printf -v PATH`, a name reference) or a declaration whose name is built wholly at run time (`export "$N=/d"`, `export "$N"`, or an unquoted `export FOO$X` that splits into a PATH word) is not read as an assignment to PATH (follow-up CRW-1292, which reads PATH). These are source-reader guarantees, not evidence that a host script or a live hook has run.
