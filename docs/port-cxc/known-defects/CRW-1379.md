# CRW-1379 — follow-ups of the plan input (CRW-1343): the key warning through a pipe, sub-bullets of an end condition, the edge id suffix of a re-plan

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no flow compile and no tracking milestone). The Go files are `internal/flow/planinput/` (`planinput.go` `Build`, `body.go` `bullets`, `enc.go` `ReplanEdgeSuffix`, `cli.go`) and `internal/flow/compile/` (`input.go` `Project.Warnings` and `InputWarning`, `compile.go` `Options.Binding`, `keybinding.go` `KeyWarning` and `ReadScopes`, `cli.go` `Deps`, `RunWith` and the flags `--thread`, `--state`, `--socket`). The wording of the skills (`crw-plan`, `crw-canon` `flow.md`) is not part of this change. No relay store schema, dag rule, refusal code, receipt status or skill is added or changed, and the plan revision a compile prints is the same bytes with or without a carried warning.

- The key-mismatch warning of `crw flow plan-input` (`project_key_bound`, `project_key_unchecked`) stood on stderr and in the opt-in `--envelope`, so `crw flow plan-input | crw flow compile --dry-run -`, the pipe the documents recommend, kept no record of it, and `crw flow compile` did not compare a key at all (CRW-1343.md, the warnings bullet; CRW-1379 d2); port: fixed (the key warning is also the `warnings` member of the project in the compile input, so the bare input carries it; compile carries a project's `warnings` into the plan's `warnings` (the issue a warning is about is its `path`), in the dry run and in the real compile, where the printed plan result holds the warnings beside the revision document `dag-plan-put` takes (the revision itself has no place for them); the handoff `crw flow start --handoff` pins is the same input, warnings included. Compile compares each project key with the live parent bindings of the owner thread (`--thread`, default `CODEX_THREAD_ID`, read-only from `--state` and `--socket`, the reading `crw flow start` makes) and warns `project_key_bound` or `project_key_unchecked` as plan-input does, unless the handoff already carries a warning of that rule for the project. Nothing refuses and the revision is unchanged. Pinned by `TestBuildCarriesTheKeyWarningsInTheCompileInput`, `TestPipedPlanInputKeepsTheKeyWarningInTheCompiledPlan`, `TestHandoffWarningsAreCarriedIntoThePlanWarnings`, `TestCompileComparesTheProjectKeyWithTheBinding` and `TestCLIComparesTheKeyWithTheNamedThread`).
- Only the key warnings are put into the input; the other warnings of the mapping (`criteria_missing`, `region_invalid`, `size_value`, the blocker warnings, `target_missing`, `milestone_closed`, `no_open_issue`) stay on stderr and in the envelope, as before; port: kept (the issue asks for the key warning; a caller that wants the others in the record uses `--envelope`).
- With no thread named (no `--thread` and no `CODEX_THREAD_ID`) `crw flow compile` reads no relay store and says nothing about the key; plan-input records `project_key_unchecked` for that case in the handoff it writes, and compile carries it. A handoff written by hand, compiled outside an owner session, therefore gets no new warning; port: kept (a warning on every compile of a handoff that no thread owns would change the output of every existing caller).
- An indented bullet under an end condition was read as an end condition of its own, so a sub-bullet that states how its parent is shown made a second criterion, and no test checked it (CRW-1379 d3); port: fixed (a bullet indented deeper than the criterion above it, at any depth, after a blank line, with any marker or checkbox, joins the text of that criterion; a bullet at the parent's indent or less is a new criterion; a sub-bullet of a `Blocked by:` item is dropped with it. The lists of edit regions are read as before, each bullet an item. Pinned by `TestIndentedSubBulletBelongsToItsParentCondition`).
- The check of the order edge id counted `e:FROM:TO` only, so an edge of 127 or 128 characters was built into an input that compiled and was refused by compile the first time the plan was revised after the edge was retired, when the edge is named `e:FROM:TO.2` (compile never reuses a retired id; CRW-1379 P3); port: fixed (plan-input counts the `.2` of the first re-plan, `ReplanEdgeSuffix`: an edge of 127 or more characters is an input error naming both issues, its length, the suffix and the limit, so the two keys of an order fit in 123 characters together; a later re-plan's `.10` and on are not counted, as the number of re-plans is not known. Pinned by `TestEdgeIDLengthEdges`, which re-plans the order through compile and dag to show the `.2` edge and the refusal of the 127 character edge).
- Supersedes CRW-1343.md, the first bullet (beginning "Before this change the project key of a plan came from the Linear project by hand"): the bullet opens with a change history; its content stands, restated here: the project key of a plan was taken from the Linear project by hand, and a wrong key ran 41 minutes before the first claim refused it (CRW-1317); now port: fixed (`crw flow plan-input --milestone OWNER/NAME#N` prints the handoff with the milestone ref as the project key, spelled `OWNER:NAME:N`, and one issue line per open issue, keyed by its ref, with `after` from the `Blocked by:` lines inside the milestone; the output decodes strictly and compiles with `crw flow compile --dry-run`).
- Supersedes CRW-1343.md, the bullet beginning "The warnings are printed on stderr and, with `--envelope`, kept in the `warnings` array", its words "the bare input has no place for them because `crw flow compile` reads its input strictly and the compile package is not changed": the project of the bare input has the `warnings` member and the compile package carries it; now port: fixed (the key warnings are in the bare input, and `--envelope` still keeps all the warnings).
- Supersedes CRW-1343.md, the bullet beginning "The relay dag reads a plan's project key, node ids and edge ids as identifiers", its words "and an order edge `e:FROM:TO` over 128 characters (both keys together over 125)": the limit of an order edge is the 128 characters of its id with the `.2` of a re-plan, both keys together over 123; now port: fixed (see the edge id bullet above).
