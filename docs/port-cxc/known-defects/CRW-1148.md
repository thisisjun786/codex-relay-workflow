# CRW-1148 — config help in any position, arity, and the resolved key id

Source: `plugins/codexclaw/components/config-guard/src/cli.ts:48-113` at v0.2.40 (commit 3c1459ac); the Go side is `internal/runtime/install/config_cmd.go` (`runConfig`). Found by the 10-10 CXC improvement review (A7-07) and handed to this issue.

- Config help is recognized only as the first action, and a set ignores every token after its value, so `config set memories.dedicated_tools true --help` exits 0 and changes the setting, with a backup and a manifest write; `list --help` lists the keys, `get --help` treats help as an id, and any further argument is ignored (`cli.ts:52-58,60-96`); port: fixed (every action prints the usage and exits 0 when `--help`, `-h` or `help` appears at any argument position, before the home is resolved and before anything is read or written, as `crw install features` already does; a token past the action's arity (`list` none, `get` and `unset` the id, `set` the id and the value) is a usage error, exit 2, before any read or write. The command spellings, the output channels and the success exit codes are unchanged. Pinned by `TestConfigCommandHelpAndExtraArgumentsWriteNothing`, `TestConfigCommandHelpLeavesManifestAndBackupsUntouched` and the help cases of `TestConfigCommandArgumentsAndReads`).
- `get` resolves a padded id with the trim but then searches the live state with the original untrimmed id, so a set key printed `(unset)` and the line carried the padding (`cli.ts:71-79`); port: fixed (get, set and unset all use the resolved `ManagedKeyID`, so a padded id gives the same line as the canonical one. Pinned by `TestConfigCommandPaddedIDUsesResolvedKey`).
- `unset` printed the set line `<id>: <prior> -> <applied>`, which reads as a no-op change (`false -> false`); port: fixed (`<id>: restored to <prior>`, with `(unset)` when the key was absent before crw set it; the backup line is unchanged).
