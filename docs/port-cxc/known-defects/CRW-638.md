# CRW-638 — the pinned-root overlap check missed a destination behind a bind mount

Source: no CXC v0.2.40 (commit 3c1459ac) behaviour is recorded here. The oracle has no state-migration
command, so the pinned-root overlap check is a CRW addition of the migration foundations
(`internal/runtime/install/migrate/roots.go`); the defect below is Go-side and the same file fixes it.

- The check compared a root's chain against the other roots' own identities only
  (`overlapByIdentity`, `roots.go` at this issue's base commit), so a destination whose existing ancestor
  was a bind mount of a directory inside the source tree carried that subdirectory's identity, matched
  neither root, and `Open` accepted it: `EnsureDest` then created the destination inside the source tree.
  A bind mount is one directory reached by a second name, so its (dev, ino) is unchanged
  (`roots.go:266-291`, `:211-231` at this issue's base commit); port: fixed by CRW-638 (`Open` now also
  collects, for every selected tree that exists, the identities of its root and of every directory below
  it, walking from the pinned handle through `Dir.Child` only, and refuses a tree or Codex home whose chain
  holds one of them, with `ReasonOverlap` and the detail "reaches <other path> through another spelling (a
  bind mount)"; a tree the walk cannot read, or one of more than 200,000 directories, refuses the same way).
