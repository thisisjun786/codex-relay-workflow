# CRW-830 — the CXC GUI build reaches outside `gui/`

Source: CXC v0.2.40 (`3c1459ac`) `plugins/codexclaw/gui`: `vite.config.ts:3` imports
`./src/server/middleware.ts`, whose own imports at `src/server/middleware.ts:17-21,31` and
`src/server/handlers.ts:12-14,20` reach five sibling component packages under
`plugins/codexclaw/components/` — `subagent-config`, `provider-bridge`, `config-guard`,
`cxc-ops` and `messenger-bridge` — and the tests `test/handlers.test.ts:19-20`,
`test/middleware.test.ts:8`, `test/subagent-scope-api.test.ts:9` and `test/crlf-where.test.ts:17`
reach the same packages. Ported as the screen sources under `web/`; the API those files
served is Go (`internal/gui`) and is not part of this port.

- The GUI package is not self-contained: its build, its dev server and its own tests read
  five packages outside `gui/`, so the directory cannot be built, developed or tested on
  its own (source `vite.config.ts:3`, `src/server/middleware.ts:17-21,31`,
  `src/server/handlers.ts:12-14,20`); port: kept for the upstream project, and not inherited
  here — `web/` ports the shell and the shared parts and drops `src/server/` and the dev-server
  middleware with it, so nothing under `web/` reads outside its own directory. The Vite
  config keeps the react plugin and the build output directory only.
- `src/server/text-lines.ts` is a shared helper copied verbatim into every consuming
  component package rather than imported across the boundary, because the components are
  dependency-free of each other and a `../../` specifier would not resolve at build time
  (source `src/server/text-lines.ts:9-13`); port: kept — the file is not moved into `web/`,
  which has no consumer for it. It arrives with the issue that needs it.
