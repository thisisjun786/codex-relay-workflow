# CRW-1488 — a subagent call had no go: the verifier's go_root reached crw.verify only

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no flow engine. The Go files are `internal/crwconfig/verifier.go` (`VerifierTools.GoEnv`), `internal/flow/cli/repository_tools.go` (`repositoryTools`), `internal/flow/cli/process.go` (the run's `engine.Config.Tools`), `internal/flow/engine/tools.go` (`RepositoryTools`), `internal/flow/engine/session.go` (`sessionPacket`), `internal/flow/engine/call.go` (`ThreadSpec.Tools`, `ForkSpec.Tools`) and `internal/flow/backend/agent/thread.go` (`threadParams`). Found by the 1209 field trial (10-15, findings 12): the M2 architect wrote that Go was not on the subagent's `PATH` and still planned every check as bare `go`, and the design audit raised it as a P1; `verifier.go_root` was read only by `crw.verify` and the integration verifier (`laneops.go` `laneVerifierTools`).

- The go the verifier runs was given to no agent call of a run; port: fixed (with `verifier.go_root` set and the section usable, every call the run starts is given exactly the entries the verifier's command gets, `PATH=<go_root>/bin:<the run process's PATH>`, `GOROOT=<go_root>`, `GOTOOLCHAIN=local`, and nothing else: no `go_root`, an ignored section or an unreadable file give nothing, as before (`TestRepositoryToolsFromVerifierGoRoot`). An App Server call's thread/start and thread/fork carry them as `config.shell_environment_policy.set`, a nested table the host merges over its own policy, so its inherit, exclude, include_only and other set entries stay, and the role prompt ends with a `Repository tools` section (`TestRepositoryToolsReachThreadShell`, `TestThreadSpecCarriesRepositoryTools`)).
- A session call's subagent could not be given an environment; port: kept (spawn_agent takes no environment and the subagent's shell is the owner session's, so the run cannot set it; the task packet of every session call, of every role, has a `Repository tools` section that names the go, the setting and its file, and the prefix `PATH=<go_root>/bin:"$PATH" GOROOT=<go_root> GOTOOLCHAIN=local` to put in front of every command that runs go and to write into every such command of a plan (`TestSessionPacketNamesRepositoryTools`); a run with no tools writes the packet of before (`TestSessionPacketWithoutRepositoryTools`). The packet's digest is journaled and never compared on a resume, so no journaled call runs again for it).
