# CRW-145 — the goal-idle block leads with the arming command, and offers it where it cannot run

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/hook.ts` `buildGoalIdleBlock` (:1694-1738; the oracle's `startNext` line, the "or close the goal honestly" line and the no-slug `loop init` branch). The Go side is `internal/pabcd/hook/stop.go` (`stopGoalIdleBlock`) and the predicate it reads is `internal/pabcd/source/session/gate.go` (`CheckBound`), the one `orchestrate P` applies to a goalplan-bound session (`internal/pabcd/cli/orchestrate_transition.go`, #133). Found by CRW-29 (the completion boundary of a project parent): the block instructed `orchestrate P` in a workspace where it is refused.

- The block opens with "Either start the next work-phase now: `orchestrate P`" and names the honest exits (`update_goal` complete or blocked) second, and it offers the command in a workspace with no resolvable source identity, where `orchestrate P` of a goalplan-bound session is refused ("this workspace has no resolvable git source identity ...") (hook.ts:1694-1738); port: fixed (the honest exits come first: "Close the goal honestly: `update_goal` status "complete" (...) or status "blocked" for an external blocker.", then "Or start the next work-phase now: `crw pabcd orchestrate P --session <id>`" where the command can run. When `session.CheckBound(cwd, sessionId)` fails the command line is replaced by the reason, worded by the kind of refusal (`GateResult.Cause`): a session without a source binding whose working directory has no git source identity (`CauseUnavailable`, the one refusal binding a git source tree clears) reads "The next work-phase cannot be armed from this workspace: it has no resolvable git source identity, and a goalplan-bound cycle cannot be closed without one (C -> D needs a test receipt bound to a commit), so entering P is refused. Binding a git source tree does not clear this (binding runs the same git); make git work for this workspace first.", because the bind command runs the same git and would be refused the same way; any other refusal (a binding or source-root error such as a corrupt, foreign or moved binding or a missing binding for a pinned worktree, `CauseBindingError`, or a bound worktree without an identity, `CauseBoundUnavailable`) names CheckBound's reason and does not offer the bind command, which a session's immutable binding would refuse the same way: "The next work-phase cannot be armed from this workspace: the session's source identity cannot be resolved (<CheckBound's reason, e.g. Source binding is unreadable or corrupt; existing bytes were preserved.>), and a goalplan-bound cycle cannot be closed without one (C -> D needs a test receipt bound to a commit), so entering P is refused. Binding a different source tree does not clear this (a session's source binding is immutable); resolve what the reason names first." The LOOP-UNIT-CHAIN-01 line ends its parenthesis at "append it to the goalplan" instead of "then orchestrate P". The predicate is the source identity and not the absence of `.git`, as `CheckBound` documents: a non-git working directory whose session is bound to a git source worktree can run the command and keeps the option. The block is still a block: the decision, the counter (counted at IDLE, three consecutive per phase, 24 per user turn), the work-phase lines, the empty-plan line and every other branch are the oracle's. The identity is investigated (git status, the hashing of the dirty files) before the session lock is taken, never under it, so a slow investigation does not make another writer of the session give up its lock; it is read only for a Stop that reaches the block: after the role release, and only when the counter, judged on the state read before the lock with the bound goalplan and the metric rows, leaves a block, so a per-phase cap release (the first and the latched ones after it) and a total cap release investigate nothing. The lock then re-judges the binding, the goal, the turn and the counter as before, and the block uses the answer already in hand; a block the lock finds that the judgment before it did not foresee (another writer changed the state in between) has no investigated answer and offers the oracle's arming command, as a timed-out investigation does. The investigation has a 5 s budget inside the 15 s Stop wiring limit, and the budget is the investigation's own deadline and not only the time the Stop waits for it: `session.CheckBoundContext` runs the git of the binding and of the capture in a process group of its own (`source.ProbeContext`) and stops the hashing of the dirty files at the next file or chunk, so at the deadline the group, with any clean or process filter git started, is killed and reaped, and the Stop waits up to 2 s for that before it answers, leaving no git running behind the hook process. An investigation that does not finish in the budget is no evidence that arming is impossible, so the oracle's arming command is offered; a verdict that arrives as the deadline passes is not a verdict (a cancelled probe reports its cancellation as a refusal) and is treated the same way. The command-line verbs keep `CheckBound` and the unowned probes (their git stays in the terminal's foreground group), whose `OK` and `Reason` are unchanged.
