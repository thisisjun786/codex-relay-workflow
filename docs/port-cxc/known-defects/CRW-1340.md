# CRW-1340 — the synchronous Interview is retired and crw-define registers a milestone and its issues

Source: Jun's 10-14 decision, relayed by Sion, with Jun's 04:3x correction: the synchronous Interview that came over from CXC conflicts with the 1.0 goal of reaching dev integration without a person in the loop, so `crw-interview` and the PABCD I phase leave the automatic path; `crw-define` is not removed (proposing its removal was Sion's mistake) and is retargeted. The CXC oracle (v0.2.40, commit 3c1459ac) ships the `interview` skill, promotes a plan request to the Interview under its default `new-unit` policy (interview-policy.ts), composes the I directive with the Interview owner and the Mind dispatch (hook.ts:324-437, minds.ts:66-81) and reinjects a Mind rescan round after each captured answer (hook.ts:1929-1937). The Go side is `internal/pabcd/projectcfg/policy.go` (`DefaultPolicy`), `internal/pabcd/hook/directives.go` (`phaseIDirective`, `InterviewDirective`), `internal/pabcd/hook/session_hooks.go` (`sessionHookRescanReinjectDirective`), `internal/affordance/render.go` (`questionsText`) and `internal/harness/pabcd_cli.go` (`configInterviewUsage`).

- A plan request (`Use crw-pabcd`, `Use crw-pabcd to start Plan phase`) in a project without a `crw.json` got the Interview directive, because the oracle's default interview-entry policy is `new-unit`; port: changed (the default is `off`, so a plan request gets the P directive and the default flow never opens the Interview; a project `crw.json` that names `new-unit` or `always` still promotes it, and `crw pabcd config interview` prints `(default)` on `off` and `current: off` without a file). Pinned by `TestCRWDefaultFlowNeverEntersInterview` (the session start, the default policy, a plan request, the default transitions and the loop recipe never lead into I), `TestReadPolicy` and `TestPabcdCLIConfigScanVerbs`.
- The I directive loaded `$crw:crw-interview` for dimensions, questions, readiness and its tracker commands, and the composed directive carried the Mind dispatch text pointing at `crw-interview`'s `references/mind-dispatch.md`; port: changed (the directive keeps the oracle's first two lines and says that CRW holds no synchronous interview: settle what the repository and the issue answer, write the rest as OPEN ASSUMPTIONS, lift a question that changes scope or design as a decision request to the session above the project session with `crw flow report-up`, and leave I as crw-pabcd phase control states; the Mind dispatch is no longer appended). `TestRecordedPhaseAssembly` and `TestRecordedDirectiveResolution` keep the oracle's recording and derive the CRW text from it (`crw1340Interview`).
- After a captured `request_user_input` answer in an I phase, the post-answer leg reinjected a rescan directive that routed to `$crw:crw-interview` and drove a Mind rescan round with user questions; port: changed (the first line is the oracle's; the rest folds the answer into the plan's OPEN ASSUMPTIONS and sends a remaining scope or design question up as a decision request). `TestSessionHookRescanDirectiveMatchesTheK5Extraction` checks the oracle's first line and its Interview route.
- The SessionStart and compaction card told a session that the Interview uses `request_user_input` and named `$crw:crw-interview`; port: changed (the questions paragraph says that no session opens an interview or waits for a user answer, that ambiguity during a run is a decision request to the session above the project session, the parent (repository session), lifted with `crw flow report-up`, that a milestone or issue unclear before it runs goes back to its registration, and that outside a run a main agent may leave an async question without waiting). Pinned by `TestSessionStartQuestionsRouteAmbiguityUp` and the affordance goldens.
- Kept, unreachable from the CRW default flow: the I phase in the state machine and its `orchestrate I` entry, the I->P readiness gate and its attested override, the interview tracker and `crw pabcd scan`, the PostToolUse answer capture and the goal-mode interview guard, the `interview` hint of the prompt detector, the `new-unit` and `always` policies, and `internal/pabcd/interview` with `MindDispatchDirective` and the Mind lens prompts. The CXC fixtures that pin them (`cli__orchestrate__interview_entry_and_ungated_i_to_p_refused`, `cli__orchestrate__abort_to_interview_is_ungated`, `cli__scan__derive_from_captured_answers`, the `hook__post-tool-use-capturing-interview-answers__*`, `hook__pre-tool-use-guarding-interview-in-goal__*`, `hook__stop-checking-pabcd-continuation__interview_phase_never_driven` and `hook__user-prompt-submit-checking-pabcd-trigger__interview_*` fixtures) and the oracle records (`internal/pabcd/hook/testdata/oracle-directives.json`, `internal/pabcd/interview/testdata/minds/`, `contract/schema/cxc/injected-text.json`) stay as recorded. Nothing on the default path enters I: the session start bootstraps IDLE, `NextPhase` never chooses I, the Stop continuation never names `orchestrate I`, the loop recipe enters at P, and a natural-language hint never changes the phase.
- Skills: `crw-interview` is removed with its routes (crw-pabcd's mandatory owner row, Agent judgment and Catalog Discovery routing, `references/catalog-discovery.yaml`, which only the Interview read, crw-dev's C5 row and async-questions reference, crw-loop's durable goalplan, crw-canon skill-family, the inventory map rows and descriptions entry). `crw-define` stays and is the step that registers a milestone and its issues, used by the top session (today Sion) and the parent (repository session): it organizes purpose, desired change, success evidence, scope and open decisions, asks one question at a time only when one is really needed, runs no ritual interview, and a needed question is the top session's conversation with Jun; its Linear parts are unchanged (the GitHub switch is CRW-1344). The skill count is 32 (`TestSkillDirectoryCountAtMost32`). `crw-dev-uiux-design` keeps its intent-discovery ladder as an optional path of that skill; crw-run, crw-pabcd and crw-dev do not call it (`TestDefaultFlowRaisesDecisionRequests`).
