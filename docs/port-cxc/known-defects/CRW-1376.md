# CRW-1376 — the interrupted-wait tests catch a command that ignores its context, and the helper's collection is acknowledged

Source: CRW's own test suite, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the promotion lock and the `.crw-lock` sidecar are `runtime_install.py`'s, kept by the Go port (`internal/runtime/record/locks.go`, `Promote`, `Lock`, `wait`). The tests are `TestAnInterruptedRollbackMovesNothing` and `TestInterruptedRegistrationsWriteNothing` (`internal/runtime/install/interrupt_test.go`, through the shared `interruptedWhileHeld`), `TestAnInterruptedWaitRemovesNothing` (`sweep_test.go`, the same helper) and `TestAHelpersLockSurvivesItsGarbageCollection` (`internal/runtime/golden/golden_test.go`, with `golden.Helper`). No product file changes. The evidence is under `/state/crw/crw-lane-safety-followups-1375/evidence/` (`1376-*`).

- Supersedes known-defects/CRW-1368.md, item beginning "Three install tests ended a lock wait by a time window", for what the rewritten helper could no longer see: `interruptedWhileHeld` let the holder go only after the command had returned, so a command that ignored its context waited out the lock's timeout and still passed (with `record.wait` made to ignore its context the three tests passed after 20 s, 65 s and 125 s, `1376-d1-before-mutation-oldtest.log`); port: fixed (the helper counts the command's pauses for the held lock through `record.Seam.Waiting`: the first cancels the context, a second one means the command kept waiting, so the test fails and the holder lets go there, and whatever the command then does under the freed lock is what the test's own checks see. The same mutation now fails all three within 3 s, `1376-d1-mutation-red-newtest.log`; a mutation red, not a red first, since the change is to the tests).
- Supersedes known-defects/CRW-1368.md, item beginning "The helper process that held the flock for these tests could lose it", for its pin: `TestAHelpersLockSurvivesItsGarbageCollection` relied on a fixed 50 ms sleep in the helper after `runtime.GC` for the file's finalizer to run (base `golden.go:79-83`), so a slow finalizer goroutine let it pass without the keep-alive; port: fixed (the helper answers `collected` only once the finalizers of the collection have run: it queues a marker finalizer, waits until it ran, then a second one, and the runtime's single finalizer goroutine runs the second only after the batch that held the file's; `golden.collect`. With the keep-alive removed the test fails in every run, `1376-d2-mutation-red-*.log`).
