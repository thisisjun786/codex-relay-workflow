# CRW-1482 — the stop hook looked for a flow executor's receipt under the owner's native cwd

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/subagent-evidence.ts:449` and `:489` (the receipt is judged under the payload cwd's evidence directory only), the root the CRW-1115 assignments extended ([CRW-1115](CRW-1115.md)); the flow engine that dispatches the executor is CRW's own design (CRW-1316), with no CXC oracle. Found by the 1209 field trial of 10-15 (installed build a5c1b772), findings item 17, coordinator label C9: `/state/crw/crw-1209/trial-20261015/findings.md`. The Go side is `internal/pabcd/evidence/flow_assignment.go` and `assignment.go` (the flow contract, its fixed receipt, the op binding and the recorded digest), `internal/pabcd/evidence/directives.go` (`VerifierDirectiveFor`), `internal/pabcd/hook/subagentstop.go` (`subagentStopDecide`), `internal/flow/engine/session_evidence.go` and `session.go` (the record at publication, the spawn message and packet, `evidence_receipt`, the cleanup), `internal/flow/journal/sessionenv.go` (`EvidenceCwd`) and `internal/flow/backend/agent/session.go` (`Trace`).

- An executor of a session flow run is spawned by the owner thread and works in the call worktree P the run made (`flow/<run>/wt/...`). Its SubagentStop payload carries the owner's session id and cwd, its rollout's own first UserMessage is the engine's spawn message, and its final message is the RECEIPT JSON alone, as the packet's output contract asks. The engine recorded no assignment (the spawn message had no `CRW-WORKTREE:` line), so the child had no contract and the hook looked for a receipt in `<owner cwd>/.crw/evidence`, which the child never writes and which did not exist; the contract's one-JSON final message also left no room for the `EVIDENCE_RECORDED:` last line the hook wanted. Every executor path of the trial met it: three blocks spent the budget and a tombstone released the child (M2 `run-f9257152d719`, M1 `run-7b534f998cfc`, escalated as `blocked_scope`); the QA capture call (an `executor` call with `qa: true`) meets it the same way; port: fixed. The engine is the trusted writer of the contract, as the spawn hook is in CRW-1115. With `SessionConfig.EvidenceCwd` set (`journal.SessionEnv`: the directory the run was started in), every spawn step of a gated agent type gets a flow record (`Origin: "flow"`, `Op` = the step's `crw-flow-op` marker, `Root` = P with its device, inode and HEAD) under `<EvidenceCwd>/.crw/evidence-assignments/`, written before the step's `step_published` row, which records `evidence_assignment` and `evidence_ignored`; P's `.crw/evidence` is made as real directories. The id is derived from the owner, the run, the call and the marker, so a republished, recovered or adopted step reuses its open or claimed record, and a record that cannot be written holds the call (`evidence_assignment_failed`) before anything is dispatched. The spawn message keeps its text and appends `[CRW-EVIDENCE-ASSIGNMENT:<id>]` with the absolute receipt file `<P>/.crw/evidence/<id>.md`; the packet gets an Evidence section. The hook judges a flow contract without a marker line: only that file, inside the registered tree, not older than the dispatch, and only for the child whose own first UserMessage starts with `crw-flow-op: <Op>` (a block copied into another step's message is no contract). A receipt in the owner's native `.crw/evidence`, in another call's or another run's worktree, or an explicit `EVIDENCE_RECORDED:` naming any other file is refused, and the block reason (`VerifierDirectiveFor`) names the absolute file; the budget rule (three blocks, then a tombstone) is unchanged. The claim records the stop's turn and the receipt's sha256 (records with flow fields are version 2), and the completed row records `evidence_receipt`: `accepted` with the path, the digest, the claiming agent and turn, `turn_match`, `ignored` and a copy on the step bus that outlives P, else `missing` (never claimed, a tombstone release included) or `unverified` (claimed by another agent, or bytes changed since). The bind writes the same record under a differing host cwd and records `evidence_cwd`; an unclaimed record is removed where its attempt ends without its subagent (a lost attempt, a terminal end other than held); the owner trace leaves the owner cwd's `.crw/` out, so the hook's own writes raise no `executor_wrote_outside`. Without `EvidenceCwd` the engine's messages, packets and rows stay byte for byte. Pinned by `TestFlowAssignment` (`internal/pabcd/evidence/flow_assignment_test.go`), `TestSubagentStopFlowExecutor` (`internal/pabcd/hook/subagentstop_flow_test.go`), `TestFlowBoundSpawnKeepsEvidenceBlock` (`internal/role/spawn/flow_bound_session_test.go`), `TestSessionEvidence` (`internal/flow/engine/session_evidence_test.go`), `TestSessionTraceIgnoresOwnerCrwState` (`internal/flow/backend/agent/session_test.go`) and, end to end on the fake App Server through the hook's registered leg, `TestC9` (`internal/flow/cli/session_c9_e2e_test.go`): `ReceiptAccepted` (a receipt at the file the message names, a final message with no marker line: released, the completed row's `evidence_receipt` accepted with `turn_match`, the bus copy and `evidence.AcceptedReceipt` hold the same bytes) and `Refused` (no receipt, a receipt forged in the owner's native `.crw/evidence` that the native root alone would take, and a receipt of the same name in another run's checkout are each blocked with the reason naming the file; after the budget the tombstone releases the child and the completed row says `missing` with no bus copy).
- Extends CRW-1115.md, item beginning "A subagent's SubagentStop payload carries its parent's native cwd": the tree assignment there is recorded by the spawn hook from a packet's `CRW-WORKTREE:` line, and "without the packet lines nothing is recorded and the native cwd stays the only root"; a flow run's executor step now gets its assignment from the engine instead (the item above), and every other rule of that item stands. That record is not edited (one file per issue).
- Limits, recorded and not fixed here. (1) `evidence_receipt` only records: the hold on a `missing` or `unverified` receipt belongs to the acceptance path's unit check (R2, CRW-1436), and carrying the receipt into the land review and cross-check packets is C12 (findings item 18, R2 CRW-1436 and R3 CRW-1442), which read the completed row's `evidence_receipt` and its bus copy. (2) A target repository that does not ignore `.crw/` gets the receipt into P's pending tree; the engine records `evidence_ignored: false` and `ignored: false`, dispatches the step anyway and never writes `info/exclude`, leaving the decision to R2 and land review (CRW's own repository ignores `.crw/`). (3) A reader older than this change refuses a version 2 record and blocks, as before the fix; the hook and the engine ship in one binary, so only a mixed installation meets it. (4) `turn_match` compares the SubagentStop payload's `turn_id` with the engine's bound turn; the fake host gives both the same id, and the trial journals are the check for the real host.
