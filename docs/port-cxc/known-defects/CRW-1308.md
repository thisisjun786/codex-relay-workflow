# CRW-1308 — the sandbox work-root rule warns and records; no caller refuses

Source: not an oracle behaviour. CXC v0.2.40 (commit 3c1459ac) starts no sandboxed Codex of its own and has no counterpart of the rule. Jun decided on 2026-10-13 that CRW removes every sandbox work-root restriction CRW-1265 added: the weak side is a tool that refuses to work when any directory above it holds a `.git` (AAS fixes its own check, AAS-89), not the sandbox. The Go files are `internal/sandboxroot` (`warn.go`: `Warn`, `Record`, `RecordPath`, `ReadRecords`, `SetWarningOutput`; `sandboxroottest`: `Warnings`, `Warned`, `ClearWarnings`), `internal/bridge` (`create.go`, `worktree.go`, `mutations.go`, `sandboxroot.go`), `internal/relay/adapter/transport.go` (`warnResumeRoot`), `internal/manage/childresume.go`, `internal/role/managed_spawn.go`, `internal/role/spawn/hook_managed.go` and `internal/dev/laneparity/realhost.go`.

- Supersedes CRW-1265.md, item beginning "`create_thread` checked only that `cwd`": now port: fixed (CRW-1308: every such path still asks `sandboxroot.Check`, `CheckWritable` or `CheckDestination`, and hands the verdict to `sandboxroot.Warn`, which writes one line `[crw warning] sandbox root not refused (CRW-1308): <caller>: <verdict>` to standard error and appends one JSON line to `<CODEX_HOME>/crw/sandbox-root-warnings.jsonl` (`schemaVersion`, `caller`, `decision` "warn", `rule`, `path`, `resolved`, `project`, `decidedAt`; no message, prompt or other setting); the App Server or Codex is then called as for an allowed root. A sandboxed `create_thread` whose cwd is the account home, a plain folder under it or a parent of a project root goes out with its warning recorded: `TestCreateThreadOutsideDedicatedRootsProceedsWithRecordedWarning`).
- Supersedes CRW-1265.md, item beginning "A relay delivery, a bridge send and child-resume": now port: fixed (CRW-1308: the cwd and the writable roots are judged from the same sources, and the verdict is a warning: the resume and the turn go out, `sandbox_root_refused` is never a receipt's `rpcError` or a `crw manage child-resume` failure reason, and child-resume's exit 2 for it is gone. The callers are `bridge/create_thread`, `bridge/create_thread:thread/start`, `bridge/create_worktree_thread:preflight`, `bridge/create_worktree_thread:check`, `bridge/send_message_to_thread`, `bridge/send_message_to_thread:thread/resume`, `relay/send_message_to_thread`, `manage/child-resume`, `manage/child-resume:thread/read` and `manage/child-resume:thread/resume`. The tests that pinned the refusals keep their names and now pin a pass with a warning: `TestCreateThreadRefusesHomeCwdBeforeHostCall`, `TestCreateThreadRefusesProjectAncestorCwd`, `TestCreateWorktreeThreadRefusesHomeDestination`, `TestSendMessageRefusesRecordedHomeCwdBeforeResume`, `TestSendMessageRefusesReportedHomeWritableRoots`, `TestSendMessageRefusesHomeRootsOnlyTheResumeAnswerReports`, `TestCreateThreadsWithholdPromptWhenHostAnswersWithHomeWritableRoot`, `TestGuardedSendRefusesSandboxedHomeResume`, `TestGuardedSendRefusesInheritedHomeWritableRoots`, `TestChildResumeRefusesRecordedHomeCwd`, `TestChildResumeRefusesLiveHomeSettings`).
- Supersedes CRW-1265.md, item beginning "A managed spawn's child works in the parent's cwd": now port: fixed (CRW-1308: the marked and the V2 `task_name` spawn are selected and issued wherever the parent's cwd is, with a `role/managed_spawn` warning; the spawn hook's denial of a root-refused V2 call and `role.IsManagedSpawnRootRefusal` are gone: `TestManagedSpawnRefusesHomeParentCwd`, `TestSpawnHookV2TaskNameRefusesAParentOutsideTheSandboxRoots`).
- Supersedes CRW-1265.md, item beginning "`crw-dev parity realhost` runs `codex exec`": now port: fixed (CRW-1308: a cell runs Codex whatever the scratch is, with a `laneparity/realhost` warning for the run directory and the work directory: `TestRealhostRefusesScratchAtHomeBeforeCodex`).
- The relay supervisor and worker, the manage relay commands and the systemd unit keep running in the relay's state directory (CRW-1265.md, item beginning "The relay supervisor and worker"): that is tidiness, not a restriction. port: kept.
- `crwconfig` still reads `paths.sandbox_root` and `sandbox.project_roots` without error, so an installed configuration keeps working; they now decide only which roots are warned about. A sandbox base that is unusable (`sandbox_root_unusable`) is a warning too. port: kept.
- The record lies in the crw directory of the Codex home beside CRW-1307's hook decision records (`<CODEX_HOME>/crw/hook-decisions/`), in a file of its own: CRW-1307's records are one file per hook session and name a session, a leg and a rule slug, while a verdict here comes from a caller outside any hook (bridge, relay, child-resume, managed spawn, real-host run) and names the caller and paths. A record that cannot be written leaves the line with "(no record written)" and never stops the caller; the file is appended to and never rotated. port: deviation (two record files in one directory).
- The coordinator's `/state/crw/mgmt/bin/codex-guarded`, which runs the same rule in Python over `testdata/cases.json`, is outside the repository and is changed by the coordinator at installation; the table stays the rule's own (`TestCaseTableMatchesCheck`). port: kept.
