# CRW-1207 — the native helpers of a thread a flow run bound follow the role pair (F14): a deviation from the CXC spawn hook, and what the decided design left to the code

Source: CRW's own design (0.5.0-alpha, issue F14), not the CXC oracle: the oracle's `runSpawnAttachHook` (subagent-config/src/spawn-attach-hook.ts, CXC v0.2.40, commit 3c1459ac) knows no flow run. The Go side is `internal/role/spawn/{flow_bound,hook_route}.go` (the hook), `internal/flow/bound/` (the file contract the run and the hook share), `internal/flow/backend/agent/{bound,agent,turn}.go` (the run writes the binding), `internal/flow/ops/native.go` (the run imports the hook's decisions), `internal/role/{dispatch_card,fallback_notice}.go` (the card) and `internal/flow/engine/backend.go` (the held reason); the tests are `internal/role/spawn/flow_bound_test.go`, `internal/role/dispatch_card_flowbound_test.go`, `internal/flow/bound/bound_test.go`, `internal/flow/backend/agent/bound_test.go` and `internal/flow/ops/native_test.go`.

- Port deviation (the decided design's own): on a thread a flow run bound, the oracle's rule that a native helper takes the parent's model and effort (`role.go:149-156`) or the caller's explicit values (`spawnHookRouteSettings`, `hook_route.go:479-498`) no longer holds. An engine call may spawn at most one native helper (`nativeAllowance`, 1 for executor, executor-t1, architect, reviewer and reviewer-final calls, 0 for explorer calls and the SP-QA-1 call), its agent_type must be `explorer`, and it gets the explorer pair of the run's pinned policy whatever the caller sent or inherited; the thread that orchestrates an open run may spawn `explorer` helpers only, with the reviewer pair when the message's producer header (the lines before the first line-start `TASK:`) has a `CRW-ROLE: reviewer` line and the explorer pair otherwise (review keywords never choose), and a `CRW-ROLE: architect` header is refused. Everything else (no flow-bound directory, a session id that is not a thread id, a thread no run registered, a closed last line) is the ordinary path, byte for byte (`TestStandaloneHookUnchanged`, `TestFlowBoundUnregisteredThreadStandalone`); port: fixed.
- A directory under `~/.local/state/crw/flow-bound` that is not the current user's, not mode 0700 or a symlink, and a binding file that is not a regular file of the current user with mode 0600, cannot be read whole, ends in a cut line or whose last line is not a valid binding line, refuse every spawn of a thread-shaped session (`flow_bound_unavailable`, detail `unsafe_dir`, `unsafe_file`, `unreadable`, `truncated` or `unparseable`); the hook never falls back to the ordinary path for them (`TestFlowBoundLookupUnavailableDenies`). A binding file that was removed is not told from an unregistered thread by the hook; the run's import catches the spawn as `unbound_spawn`. The location is computed from `os.UserHomeDir` and not from `XDG_STATE_HOME`, by one function (`bound.Dir`) that the run and the hook share; port: fixed.
- The recursion token `CRW-SUBSPAWN-ALLOWED` mints no grant on a bound thread, engine or orchestrator, and the guard, skill, evidence-assignment, prompt-override and managed-dispatch legs of the ordinary hook do not run there: the helper gets the pair and nothing else (the body says "the explorer pair is put in"; the settings store and the policy file are not read, because the hook never opens either). A hook payload of a subagent (`agent_id` or `agent_type` set) on a bound session is denied as any leaf (`LEAF-TOPOLOGY-01`); port: fixed.
- A full-history fork (`fork_context` true, or a v2 spawn whose `fork_turns` is empty or `all`) keeps the parent's model and effort, so its pair cannot be set: it is refused, with the guidance to spawn a new explorer with a question packet, on engine and orchestrator threads alike, and it does not use the call's allowance. The body names no code for this refusal; the code is `full_history_fork_refused`. A `tool_input` that is no object, or has no string `agent_type`, is `native_type_refused`; one nested deeper than the hook can record is `flow_bound_unavailable`; port: fixed.
- The per-call limit is the claim `claims/<thread_id>/<call_id>` under the flow-bound directory, made whole by `link(2)` from a synced temporary file, with the answer stored beside it as `<call_id>.answer` by a rename before the hook prints it. The answer is a function of the claim's original input and the binding line only, so a claim with no answer (the hook stopped after the claim) and two deliveries at once give the bytes an uninterrupted run gives (`TestFlowBoundClaimWithoutAnswerRecovers`, `TestFlowBoundSameEventConcurrentDelivery`). The orchestrator thread has no claim (no count limit beyond the host's), so a redelivery there needs none and is stable by construction; port: fixed.
- "The dispatch ledger" of the body is `flow-bound/decisions/<thread_id>.jsonl` (`bound.AppendDecision`), the hook's own append-only record, one line per decision with the run, thread, call, tool use id, decision, reason, the pair the caller sent (empty is inherited), the pair applied and the helper role. The role package's managed dispatch ledger is a record of fallback attempts and has no place for a refusal or for a pair the hook applied. An allowed spawn whose line cannot be written is refused (`flow_bound_unavailable`), because the run checks every native spawn of a bound thread against the ledger; a decision of the same tool use that says the same is written once; port: fixed.
- The run's import (`ops.ImportNativeSpawns`) writes two kinds of rows to `flow_spawn_decisions`: `native_spawn` (the hook's decision, with the requested and applied pair in their columns) and `native_observation` (`observed`, `unobserved` with the reason `no_receiver`, `read_failed`, `null_model` or `null_effort`, `pair_mismatch`, or `unbound_spawn`, the configured pair of each receiver in `evidence_json`). The three pairs stay apart: requested is what the caller sent (the item's own request is kept in the evidence), applied is what the hook set, configured is what `thread/read` of the receiver says. A present field that differs from the applied pair is `pair_mismatch` even when the other field is null; only a pair that is fully read and equal is `observed`. `pair_mismatch` and `unbound_spawn` are escalated once each as configuration faults (`ops.EscalateNative`, a `escalation` row of class `configuration_fault`). The row ids are hashes of the facts, so an import repeated for the same turn writes nothing more (`ops.StoreSpawnRows`); port: fixed.
- The run writes the engine line before every `turn/start` (including the repair turn and a turn sent again after a restart) in `Backend.RunTurn`, and a line that cannot be written, or a thread whose id is not the form of a thread id (the fake host's `thr-fake-NNN` is not), holds the call with `host_config_flow_binding` and sends nothing. The held reason is the new `engine.CodexErrorFlowBinding` in `ClassifyHostFailure` (`internal/flow/engine/backend.go`, outside the body's edit regions; the `host_config_<kind>` family of `docs/flow/script.md` is extended there). `agent.Config.Bound` is optional so that a backend without it keeps today's behaviour; the process that starts runs on the App Server sets it (`Bound.NativeAllowance` is where F13 marks the SP-QA-1 call, which has allowance 0). The orchestrator's opening and closed lines are `Backend.BindOrchestrator` and `Backend.CloseOrchestrator`; port: fixed.
- Edits outside the body's edit regions, each small and needed: `internal/role/fallback_notice.go` (the SessionStart hook gives a bound session the flow card), `internal/flow/engine/backend.go` (the held reason), `internal/flow/backend/agent/{agent,turn}.go` (the config and the call before `turn/start`), `internal/bridge/appserver/fakehost/{threads,seed}.go` (`ThreadIDs`, so the fake host can name threads with ids of a real host's form, and `TurnPlan.Items`, so a turn can hold a CollabAgentToolCall; both additive, the defaults are unchanged), `internal/flow/backend/agent/{env_test,reconcile_fix_test}.go` (the test env builds the backend with the binding on request) and `docs/flow/script.md` (the held reason).
- Not done here, because the pieces they need belong to other issues or to the installation: `crw doctor` does not yet show the flow-bound directory check (`bound.CheckDir` is the one function it should call; `Diagnose` is a recorded report whose shape this issue does not change); `crw flow run` over the App Server (the run that calls `BindOrchestrator` at its start and `CloseOrchestrator` when it ends or is cancelled, builds `agent.BoundConfig` and calls `ImportNativeSpawns`/`StoreSpawnRows`/`EscalateNative` after each engine turn) is not in this build; the proof on a real flow thread waits for G-V2. The SessionStart card is chosen from the binding as it is when that hook runs: a session that starts before the run's first line for it is written gets the ordinary card, and the spawn hook still decides by the binding; port: pending.
