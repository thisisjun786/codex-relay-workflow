# CRW-1066 — differential-fuzz throughput: one case at a time, one python3 per request, and the per-case root cost

Source: the dev-only harness in `internal/dev/cxcfuzz` (`cxcfuzz.go`, `worker.go`, `canon.go`, `canon_fast.go`, `root.go`, `scenario.go` and `testdata/pyjson/shim.mjs`), driving the Python standard library's `json.tool` (the pyjson oracle) and the CXC v0.2.40 (commit 3c1459ac) `pabcd-state/dist/state.js` (the state oracle). Every defect below is in the harness, not in the port or the oracle, and each is fixed in this change. Found by measuring the CRW-711 campaigns (pyjson 6.6 and state 5 cases per second at four workers) and profiling the state target (docs/port-cxc/differential-fuzz.md, "Throughput").

- The campaign loop evaluated one case at a time, so `--workers` only sized the pool of oracle processes and three of four workers always waited; a campaign of "four workers" used one. Cases are now judged up to `--workers` at a time, the inputs still drawn in order from the seed and the results applied in case order, so a seed gives the same counts and files at any worker count. port: fixed (harness; `TestCampaignEvaluatesUpToTheWorkerCountCasesAtOnce`, `TestCampaignGivesTheSameResultAtOneWorkerAndFour`).
- The pyjson shim started one `python3 -m json.tool` per request (2.3 process starts per case at seed 711, shrink candidates included, of about 50 to 70 ms each, against the 150 ms a case took). It now answers from a bounded memory of earlier answers, from a reused json.tool process closed by a sentinel document, or from a fresh process for every refusal, host-parser rejection, deep nesting and oversized answer, so the exit status, stdout and stderr are those of a fresh process (`TestPyjsonShimMatchesAFreshJsonToolForEveryRequest`). port: fixed (harness).
- A worker killed for a timeout left the processes it had started running, a stopped reused `python3` included; the pool now ends the worker's whole process group. A reused json.tool process that dies is a dead-worker case and one that stops answering is a timeout case, replaced with the case recorded, and the campaign fails on either (`TestCampaignCountsAReusedProcessThatDiesMidCampaign`). port: fixed (harness).
- `canonical` wrote a two-megabyte oracle traceback character by character (the recursion-limit answer of pyjson), about 20 ms each and four times per case; a long ASCII string is now written in one pass, about 7 times faster (`TestCanonicalWritesWhatThePyjsonWriterWrites`, `TestCanonicalWritesALongStringFasterThanThePyjsonWriter`). port: fixed (harness).
- `PrepareRoot` had the home guard resolve every path of a case root again for each of six directories, and `RemoveCaseRoot` walked the tree before it removed it, a third of the CPU of a state case; the root is judged once and removed first by `RemoveAll` (`TestStateCasesAnswerTheSameInARootPreparedEitherWay`, `TestRemoveCaseRootRemovesAnUnlistableDirectoryAndLeavesALinksTarget`). port: fixed (harness).
- A campaign could not be stopped between cases: a host load gate had to kill it and lose the run, and a two-hour campaign on a busy host never finished. A signal now ends the draw, the drawn cases finish, `summary.json` says `stopped`, and `--skip` carries the same seed on from the case after the last one judged (`TestCampaignSegmentsGiveTheWholeRun`, `TestCampaignStopLetsTheDrawnCasesFinishAndAResumeFinishesTheRun`, `TestRunPassesSkipToTheCampaign`). port: fixed (harness).
- A campaign that lost cases to a timeout, a dead worker or a missing answer only counted them; one line on stderr now names the counts and the records (`TestFailureWarningNamesTheUnansweredCasesAndTheirRecords`). port: fixed (harness).
- The state target on a disk is bounded by the sync of the atomic write on both sides, 47 % of a case; a campaign therefore sets `TMPDIR` to a tmpfs directory of its own. port: kept (the port syncs the file as the oracle does; the harness only moves the case roots).
- The default tools root holds no extracted CXC v0.2.40 tree on this host, so a campaign names one with `CRW_CXC_ORACLE_ROOT`; the campaigns of this issue used `git archive v0.2.40 plugins/codexclaw/components` of the CXC repository. port: kept (harness input).
- The pyjson end condition of 1,000,000 cases is not reached in two hours at four workers (about 72 cases per second); the proposed basis is in docs/port-cxc/differential-fuzz.md, "The end condition", and waits for Jun. port: pending.
