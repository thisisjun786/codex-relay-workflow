# CRW-1066 — differential-fuzz throughput: one case at a time, one python3 per request, and the per-case root cost

Source: the dev-only harness in `internal/dev/cxcfuzz` (`cxcfuzz.go`, `worker.go`, `canon.go`, `canon_fast.go`, `root.go`, `scenario.go` and `testdata/pyjson/shim.mjs`), driving the Python standard library's `json.tool` (the pyjson oracle) and the CXC v0.2.40 (commit 3c1459ac) `pabcd-state/dist/state.js` (the state oracle). Every defect below is in the harness, not in the port or the oracle, and each is fixed in this change. Found by measuring the CRW-711 campaigns (pyjson 6.6 and state 5 cases per second at four workers) and profiling the state target (docs/port-cxc/differential-fuzz.md, "Throughput").

- The campaign loop evaluated one case at a time, so `--workers` only sized the pool of oracle processes and three of four workers always waited; a campaign of "four workers" used one. Cases are now judged up to `--workers` at a time, the inputs still drawn in order from the seed and the results applied in case order, so a seed gives the same counts and files at any worker count. port: fixed (harness; `TestCampaignEvaluatesUpToTheWorkerCountCasesAtOnce`, `TestCampaignGivesTheSameResultAtOneWorkerAndFour`).
- The pyjson shim started one `python3 -m json.tool` per request (2.3 process starts per case at seed 711, shrink candidates included, of about 50 to 70 ms each, against the 150 ms a case took). It now answers from a bounded memory of earlier answers, from a reused json.tool process closed by a sentinel document, or from a fresh process for every refusal, host-parser rejection, deep nesting and oversized answer, so the exit status, stdout and stderr are those of a fresh process (`TestPyjsonShimMatchesAFreshJsonToolForEveryRequest`). port: fixed (harness).
- A worker killed for a timeout left the processes it had started running, a stopped reused `python3` included; the pool now ends the worker's whole process group. A reused json.tool process that dies is a dead-worker case and one that stops answering is a timeout case, replaced with the case recorded, and the campaign fails on either (`TestCampaignCountsAReusedProcessThatDiesMidCampaign`). port: fixed (harness).
- `canonical` wrote a two-megabyte oracle traceback character by character (the recursion-limit answer of pyjson), about 20 ms each and four times per case; a long ASCII string is now written in one pass, about 7 times faster (`TestCanonicalWritesWhatThePyjsonWriterWrites`, `TestCanonicalWritesALongStringFasterThanThePyjsonWriter`). port: fixed (harness).
- `PrepareRoot` had the home guard resolve every path of a case root again for each of six directories, and `RemoveCaseRoot` walked the tree before it removed it, a third of the CPU of a state case; the root is judged once and removed first by `RemoveAll` (`TestStateCasesAnswerTheSameInARootPreparedEitherWay`, `TestRemoveCaseRootRemovesAnUnlistableDirectoryAndLeavesALinksTarget`). port: fixed (harness).
- A campaign could not be stopped between cases: a host load gate had to kill it and lose the run, and a two-hour campaign on a busy host never finished. A signal now ends the draw, the drawn cases finish, `summary.json` says `stopped`, and `--skip` carries the same seed on from the case after the last one judged (`TestCampaignSegmentsGiveTheWholeRun`, `TestCampaignStopLetsTheDrawnCasesFinishAndAResumeFinishesTheRun`, `TestRunPassesSkipToTheCampaign`). port: fixed (harness).
- A campaign that lost cases to a timeout, a dead worker or a missing answer only counted them; one line on stderr now names the counts and the records (`TestFailureWarningNamesTheUnansweredCasesAndTheirRecords`). port: fixed (harness).
- The state target on a disk is bounded by the sync of the atomic write on both sides, 47 % of a case; a campaign therefore sets `TMPDIR` to a tmpfs directory of its own. port: kept (the port syncs the file as the oracle does; the harness only moves the case roots).
- The default tools root holds no extracted CXC v0.2.40 tree on this host, so a campaign names one with `CRW_CXC_ORACLE_ROOT`; the campaigns of this issue used `git archive v0.2.40 plugins/codexclaw` of the CXC repository (commit 3c1459ac). port: kept (harness input).
- The pyjson end condition of 1,000,000 cases takes two and a half hours at four workers (112 cases per second), half an hour more than the two-hour campaign; the proposed basis is in docs/port-cxc/differential-fuzz.md, "The end condition", and waits for Jun. port: pending.

Found by the two-hour campaigns of this issue (seed 711, four workers, the dev tip 79e4214e1, the CXC v0.2.40 oracle tree; the campaign records are in `/state/crw/crw-1066/fuzz/`). A class is pinned with `--adopt` as an `open` case recorded CRW-1066; where the port's answer is the safe or the more exact one it says so, and whether such a case becomes `intentionally-changed` is the follow-up's decision.

- The managed-worktree deletion guard (worktreedel): the oracle denies `cd deep && rm -rf .` with its working directory in the slot's checkout, because it does not follow the `cd`; the port follows it and allows, as the removed `.` is the subdirectory `deep` and not the checkout or one of its ancestors (case `crw-1066-miss-5720a99f75f1`, which answers the same wherever the case root is). The oracle also denies `rm -rf ../../<slot id>` when the path resolves to another directory that only carries the slot's name, which is the raw substring match of the earlier `slot_substring_denies_unrelated_target` defect; the port resolves the path and allows (case `crw-1066-miss-185182b7af62`). port: pending (pinned open; the port's answer is the exact one in both).
- The oracle allows `mv . /`, `mv ../repo /`, `find . -delete` and `rm -rf $` with the working directory in the slot, where each moves or deletes the slot; the port denies them as the deletion of the worktree (cases `crw-1066-extra-040e4d74744f`, `crw-1066-extra-d1c921302221`, `crw-1066-extra-238fd0d8e5d9`, `crw-1066-extra-0a1930027f0a`). port: pending (pinned open; the port is the stricter side).
- `rm -rf ~/.codex/worktrees/<slot>` and `rm -rf $HOME/.codex/worktrees/<slot>` are denied by both sides with different reasons: the oracle names the worktree, the port says it cannot analyse the command (cases `crw-1066-differ-0a76b5cc462f`, `crw-1066-differ-1e0e7239bf26`). port: pending (pinned open; wording).
- The shell-write destination reader (shellwrite): the campaign judged 1,912,676 cases and found 795,263 distinct shrunk differences, 1,369,562 differing cases in all (664,934 differ, 673,076 extra, 31,552 miss). They fall into 37 classes (kind by the first construct the shrunk command holds, in the order comment, heredoc, python inline, xargs, in-place edit, tee, move or copy, special redirect, substitution, line break, wrapper, quote, plain redirect), each pinned with its shortest member as case `crw-1066-shellwrite-<kind>-<construct>`. The commands the shared reader could not read (535,914) were all refused by the Go side (`unreadableNotRefused` 0). The representatives of the 11 miss classes, where the oracle names a destination the port does not, are oracle over-reports: the oracle reads the text after a `#` as live, names the words after the first destination of `tee` and `sed -i` on a new line (`b`, `nohup`, `sed`), names `rel)` and `hi>/m/a` for a closing parenthesis or a redirect that is no destination, and names the operands of a command it cannot tell apart; the other classes (extra, differ) are the port's reader naming destinations the oracle does not or spelling them otherwise. Only the representatives were read; the other members of the classes are not triaged one by one. port: pending (pinned open, follow-up to decide per class between `intentionally-changed` with a record and a fix).
- The memory write gate (memorygate): 125,932 cases, 24,728 distinct shrunk differences in 9 classes (the port's deny against the oracle's allow with the gate's reason 9,773 and with the command reader's `Cannot analyze this command` 9,156 and with `Cannot verify the program's write destination` 268; both deny with different reasons 3,243, 1,313, 844, 4 and 4; and 123 misses), pinned as `crw-1066-memorygate-<kind>-<hash>`. The 123 misses, where the oracle denies and the port allows, are 120 commands with a `#` that opens a comment (the oracle reads the commented words as live) and 3 whose quoting makes the oracle's word split read a memories path as a redirect target that the shell reads as part of another word; none is a write to the memories directory the port let pass in the representatives read. port: pending (pinned open, follow-up as above).
