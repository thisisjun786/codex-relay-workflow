# CRW-1153 — config.toml, the flags and the ownership record are one recoverable transaction

Source: CXC v0.2.40, commit 3c1459ac — `plugins/codexclaw/components/config-guard/src/config-set.ts` (config.toml published at :102, the manifest after it from :136), `activate.ts` (the hard failure at :233-246 returns before the manifest at :299; `readPriorManifest` at :154-162 reads a malformed manifest as absent). The Go port is `internal/runtime/install/configguard/intent.go` (the intent, `txPrecheck`, `txPublish`, `commitManifest`, `recoverIntent`, `readOwnedManifest`), `activate.go` (`Activate`), `configset.go` (`ApplyManagedKey`, `ReleaseManagedKey`), `deactivate.go` (the recovery before a deactivation) and `internal/runtime/install/features.go`, `config_cmd.go`. The finding is the 10-10 CXC improvement review A7-03 and the combined review B7-02 (partial failure recovery).

- config set published config.toml before the manifest, so a manifest that could be read but not written failed the command after config.toml had changed from false to true, with no record to undo it (source `config-set.ts:102,136`); port: fixed (every file the transaction publishes is checked under the config lock before anything changes: an existing file must open for writing and its directory must accept a new entry. Pinned by `TestConfigSetWithAnUnwritableManifestChangesNothing`).
- A command that stopped between its publications (a failed backup, intent, config or manifest publication, or a kill) could leave a change no record owned (source `config-set.ts:102-156`, `activate.ts:217-299`); port: fixed (an intent beside the manifest names the records the change starts from, the config file and each planned effect, marked attempted before it runs; the manifest is committed from what was done and the intent removed. A stop leaves the intent, and the next explicit command (enable, disable, config set, unset or release) records, under the config lock and before anything else, the ownership of every attempted effect that is in place now. It reverts nothing, so a user's edit made since is neither undone nor adopted, and the SessionStart self-heal never recovers. Pinned by `TestActivationTransactionSurvivesAFailureOrAKillAtEveryStep` and `TestConfigSetTransactionSurvivesAFailureOrAKillAtEveryStep`, which fail or kill every step of a clean run in turn, rerun, check the exact record and revert to the original, and the control `TestRecoveryNeverAdoptsOrRevertsAConcurrentExternalEdit`).
- A publication whose directory sync failed after the rename was counted as done (CRW-802's `activationPublished`), so the command reported a durable success; port: fixed for the activation and config set/unset/release (the change is in place, so the transaction continues and the ownership is recorded, and the command reports a `*crwdir.PublishedError` that says the changes may not survive a power failure and exits 1. Pinned by `TestTransactionReportsAnUnsyncedDirectoryWithTheRecordInPlace`). The deactivation and the multi-agent switch report it too: the manifest's release, the recovery of an interrupted change, the config.toml restore and the tuning repair of `SetMultiAgentV2State` keep their publication in place, and the command returns the result with a `*crwdir.PublishedError` and exits 1. Pinned by `TestDeactivateReportsAnUnsyncedReleaseAndRecovery` and `TestMultiAgentV2RepairWithAnUnsyncedDirectoryIsReported`.
- Supersedes known-defects.md, section "Found by the config-guard activation and manifest port (CRW-333)", item beginning "A hard feature-enable failure leaves earlier enabled flags": now port: fixed (the activation commits a manifest that records the flags enabled before the hard failure as crw's, and the deactivation reverts them. Pinned by `TestActivateHardFailureRecordsTheFlagsItEnabled`, `TestActivateFailurePaths/hard` and `TestFeaturesSoftAndHardFailures/goals`).
- A manifest that exists but is not one crw can read was taken as absent and replaced by the next activation, losing its records (source `activate.ts:154-162`); port: fixed (the activation and config set/unset/release refuse it and leave it as it is. Pinned by `TestActivateRefusesAMalformedManifest` and `TestActivateMalformedReadableManifestIsRefused`).
- Supersedes known-defects.md, section "CRW-348 — managed config command port", item beginning "Per-file writes are atomic but the config and ownership manifest are not one transaction": now port: fixed (see the second item).
- A flag the CLI enabled before a later managed-key write failed was left unowned (`TestActivateFailedConfigPublicationPreservesBytes`); port: fixed (it is recorded; the key that was never written is not).
- An intent whose directory sync failed was counted as published and the effects after it ran, so a power failure before the manifest could lose the intent and leave a change no record owned; port: fixed (the intent is the one publication that stops the transaction on a sync failure: the first intent is taken back and nothing changes, and the intent that marks an effect attempted leaves that effect unrun while the effects already in place are committed to the manifest. Config set writes config.toml only on a durable intent. Pinned by `TestIntentThatMayNotBeDurableStopsBeforeEveryEffect`, which fails each of the six intent publications of a clean activation in turn, and `TestConfigSetIntentThatMayNotBeDurableChangesNothing`).
- A repeated enable whose baseline held only the records it was about to rewrite lost the ownership of a managed key it had not reached when a hard flag failure or a refused key publication stopped it; port: fixed (the baseline of a carried activation holds every flag and key record the install already has, and a record leaves the manifest only through its own effect. Pinned by `TestStopBeforeAnEffectKeepsTheOwnershipItStartedFrom`).
