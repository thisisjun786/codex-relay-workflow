# CRW-1048 — the branch reading counted a closed release as owned

Source: the pre-merge evaluation of CRW-995, crw995-d24d860c, defect d4 (P1, minor_separable, outside the CRW-995 promise and not made by its change). This is the port's own defect: CXC v0.2.40 (commit 3c1459ac) has no branch-candidate reading. The Go files are internal/manage/capacity_branches.go (branchReadReleased) and internal/relay/dagsched/release_recovery.go (OpenReleaseNodes, beside latestRelease).

- The branch reading owned every node with a dag_releases row, so a release that dag-release-close closed (its closed row in dag_release_recoveries, the intent abandoned before it created a child) kept its bundle out of the candidates, while Scheduler.Ready reads the node as unowned and releasable again; port: fixed (branchReadReleased takes the open releases from dagsched.OpenReleaseNodes, which applies latestRelease, the scheduler's own judgement, node by node; a bound execution still owns its node. Pinned by TestBranchCandidatesCountAClosedReleaseAsNotOwned, which fails on the previous code (the C+D bundle is missing; log in the CRW-1048 evidence directory), with the control TestBranchCandidatesKeepABundleWhoseReleaseIsOpen).
- internal/relay/dagsched/bundles.go (bundleReleased, the dag-bundles reading) still owns every dag_releases row, so the same closed release is still counted there; port: pending (the canon's own reading is outside CRW-1048, which changes only the branch reading in internal/manage; it needs its own issue and a test of its own).
