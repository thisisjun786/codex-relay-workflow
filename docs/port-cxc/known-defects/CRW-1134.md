# CRW-1134 — the remaining defects of the bg store, registry, spawn and hooks

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/bg-wake/src/store.ts`, `registry.ts`, `spawn.ts`, `hook.ts` and `cli.ts` at the lines each item of known-defects.md names. The Go files are `internal/relay/job/store.go` (EnsureDir, atomicWrite, writeTemp, appendLedger, readText), `internal/relay/job/registry.go` (checkRecord, readRecord, BrokenRecords, readExitCode, reconcile, settle, ReadDisabledState), `internal/relay/job/spawn.go` (runBackground), `internal/relay/job/hook.go` (runHook) and `internal/relay/job/verbs.go` (list, get, cancel, status, on). One test per item is in `internal/relay/job/sweep_test.go`; the red run of all eleven against the code before this lane is `/state/crw/crw-lane-bg-job/evidence/red-1134/red.log` (the reservation's red is in `evidence/red-1155/red.log`). Every item reproduced before it was changed. The replay differences are claimed in `contract/notes/cxc/CRW-1134.json`, which takes over ten claims from CRW-345 and CRW-490 with their reasons.

- Supersedes known-defects.md, section "Found by the bg store port", item beginning "`atomicWrite` leaves its temporary file": now port: fixed (a write or a rename that fails removes the temporary file this call created exclusively, and nothing else; `TestAtomicWriteRemovesItsOwnTemporaryFileWhenTheRenameFails`).
- Supersedes known-defects.md, section "Found by the bg registry port", item beginning "`readExitCode` takes the integer prefix": now port: fixed (the trimmed body must be one whole integer with an optional sign, finite as a number; `1x`, `12.5`, `0x10` and `3 4` are a write in progress, which the grace window and the pid then judge; `TestReadExitCodeWantsOneWholeInteger`).
- Supersedes known-defects.md, section "Found by the bg registry port", item beginning "A running record with no pid and no exit file whose `startedAt` does not parse": now port: fixed (such a record is settled failed with no exit code and the ledger detail `startedAt unreadable`; no pid is named, so nothing is signalled, and cancel of a record without a pid signals nothing either; `TestReconcileSettlesAJobWhoseStartCannotBeRead`).
- Supersedes known-defects.md, section "Found by the bg registry port", item beginning "`isRecord` tests four keys": now port: fixed (`checkRecord` requires the thirteen keys with their types, an integer pid, a number exit code and a known status, before any lifecycle step; a file that fails it, does not read, is not a JSON object or holds another id is a broken record: no reconcile, wake, adoption, stamp or cancel touches it, its bytes stay, and `list` (plain), `get`, `cancel` and `status` report it with the reason; `list --json` stays a list of records. A key this port does not name is still kept and written back. `TestBrokenRecordsAreKeptAndReportedNotWorkedOn`, `TestReadRecordWantsTheWholeRecordAndKeepsTheKeysItDoesNotName`).
- Supersedes known-defects.md, section "Found by the bg registry port", item beginning "`disabledState` takes an unreadable `disabled` file": now port: fixed (only a missing switch file is on; one that is there and does not read keeps the wake off, `status` shows `off (읽을 수 없음: ...)`, and `on` fails when it cannot remove the switch; `TestAnUnreadableOffSwitchKeepsTheWakeOff`).
- Supersedes known-defects.md, section "Found by the bg spawn port", item beginning "`runBackground` with an empty command": now port: fixed (`RunBackground` refuses it with `ErrEmptyCommand` before anything is created; `TestRunBackgroundRefusesAnEmptyCommand`).
- Supersedes known-defects.md, section "Found by the bg spawn port", item beginning "A shell that cannot start because of ENOENT": now port: fixed (the record already settled failed is what `RunBackground` returns, and `run` prints `<id> failed` and exits 1; the thrown/settled split is the oracle's; `TestRunBackgroundReturnsTheFailedRecordOfAShellThatCouldNotStart`, `TestRunBackgroundSpawnFailureSettlesFailed`).
- Supersedes known-defects.md, section "Found by the bg spawn port", item beginning "The paths of `<id>.out` and `<id>.exit` are cleared before the start": the id is reserved exclusively before any file of the job is touched (see CRW-1155.md); the link half stays with CRW-475; port: fixed for the reservation, kept for the links.
- Supersedes known-defects.md, section "Found by the bg spawn port", item beginning "The record and the ledger keep the command as given": now port: fixed as far as the issue decides (the command is still kept whole for diagnosis, which the package comment of store.go documents, but the store is private: a bg directory the port creates is 0700, and the records, the switch files and the ledger are created 0600 from their first write; a directory that exists already is not changed and nothing is chmodded afterwards; the job's `.out` and `.exit`, which its shell creates under the caller's umask, sit inside that directory. `TestTheBgStoreIsPrivateFromItsFirstWrite`).
- Supersedes known-defects/CRW-878.md, item beginning "Not this issue's defect, recorded so the same privacy argument is not mistaken for an oversight", for the bg store only: `.crw` itself is still created by `crwdir.EnsureDir` as that item says (outside this issue), but its bg directory is now 0700 when the port creates it, and what is written into it is 0600; port: fixed for bg.
- Supersedes known-defects.md, section "Found by the bg spawn port", item beginning "`reconcile` reads the exit file and only then asks": now port: fixed (before a record is settled failed with no code it is settled under the store lock, and the exit file is read again there: a code published in between wins; `TestReconcileReadsTheExitFileAgainBeforeItCallsAJobVanished`).
- Supersedes known-defects.md, section "Found by the CRW-490 bg hooks port", item beginning "A read error or input over the 1Mi UTF-16-unit limit becomes an empty payload": now port: fixed (the hook still records its invocation, with empty input, and then does nothing: no wake, no adoption, no stamp, no output; empty input that read cleanly keeps the oracle's fallbacks. `TestBgRunHookDoesNothingWithUnreadableOrOversizedInput`; the rows of `TestBgRunHookThresholdFallbackAndErrors` that woke now stay quiet).
- Supersedes known-defects.md, section "Found by the CRW-345 job verb port", item beginning "`get` counts the final empty line": now port: fixed (the final newline ends the last line and is not a line, and the lines are shown as they are, trailing spaces and blank lines included; `TestCLIGetCountsLinesNotTheirTerminator`; the replayed `cli__bg__get_tail_and_missing_id` now shows twenty lines by default and three for `--tail 3`).
