# CRW-1085 — readable diagnostic commands and bounded Python test discovery

Source: CRW's shared shell reader (`internal/pabcd/shellir`), destination reader and the isolated command trials. CXC v0.2.40 has no equivalent reader. This supersedes the blanket module refusal recorded in CRW-894 and the opaque carried-shell-file memory classification in CRW-1028.

- Version/help options with no program operand and shell noexec syntax checks were refused as programs; port: fixed. `[` is read like `test`. Shell noexec can be disabled again with +n or +o noexec; that form still reads the executed program.
- Python -m refused ordinary test and JSON commands; port: fixed. The fixed list is unittest, pytest, py_compile and json.tool. Explicit Python file operands are bounded regular files; discovery walks cwd for test*.py and *_test.py (pytest also includes conftest.py), with at most 128 files and 1 MiB total. Unknown directories, unreadable files, FIFO, local import shadows, rewritten import/source files and unordered module execution refuse. The no-directory reading delegates directory-dependent checks to the two directory-aware readings. Unsupported modules/options remain unreadable. json.tool input operands are data, not Python programs.
- Every carried shell file required a memory grant, including an existing harmless sh/bash script; port: fixed. The destination leg reuses the GitHub guard's bounded nonblocking regular-file reader, stale-file tracking and four-level script depth. Outer writes follow into nested scripts. Unreadable or rewritten files retain an unknown destination. Existing corpus rows for readable scripts now record their actual modeled destinations; GitHub/worktree verdicts stay unchanged except the explicitly allowed clean json.tool controls.
- Read-only awk was unknown; port: fixed. A program without >, pipe, system() or getline is read-only. Programs with any such operation remain unknown. This intentionally conservative rule can still refuse strings/comments containing those tokens.
- Tests: TestCRW1085ReadableCommandsAtIngress exercises memory and GitHub ingress; TestCRW1085ModuleBoundsAndSpecialFiles pins discovery limits and FIFO refusal; TestCRW1085NoExecDoesNotHideExecution pins disabled syntax-only mode. The full existing reproduction and shell-family rows cover rewritten/shadowed files. Trial agent launches remain the coordinator's operation; this lane does not contact agents.
- CRW-951's Python computed-destination work is not duplicated. Its workspace Path(variable).write_bytes case needs the predecessor's integrated implementation; it is tracked separately in the private handoff.

- Final boundary checks preserve read-only, unredirected getline while redirected getline remains unknown. Explicit py_compile bytecode output is a named __pycache__ destination (including with -B), so compiling a source below the protected memories root is refused. Shell FIFO operands refuse without a blocking read. Discovery refuses linked directories whose nested test set cannot be bounded by this walk.

- A module operand containing a link followed by .. was joined/cleaned before opening, so the reader inspected its lexical sibling instead of the program Python opens; port: fixed. Relative operands now retain every component after the physical cwd, discovery starts at the physical cwd, and py_compile cache paths retain the operand's parent components. TestCRW1085ModulePathFollowsLinkBeforeDotDot pins the protected program and compile cases; the standalone old-head ingress reproduction was allowed before the correction.

- Post-evaluation correction: interactive shells ignore noexec; the reader now keeps interactive bodies visible and refuses unknown named option values. Additional awk program files are refused rather than trusting only the first file. All three guards share these execution records; port: fixed.
- Test selection is not an import boundary. unittest/pytest now inspect the bounded local Python source inventory, including helpers and package initializers; pytest includes collection hooks and refuses configuration that may load uninspected plugins. Linked/compiled imports and sources outside that inventory refuse. This conservative inventory may refuse unrelated local Python code or a configured pytest run; port: fixed. It does not execute Python or inspect arbitrary installed dependencies.
- Directory-aware module records now reach the Python readability check. Import bytecode writes are modeled unless disabled; explicit py_compile writes remain modeled even with -B. PYTHONPYCACHEPREFIX is a conservative destination root, including command assignments and inherited environment; port: fixed.
- A readable shell file with an uninspected interpreter file operand retains an unknown destination. Direct child shell programs outside installed bin roots use the same bounded reader and stale/depth checks; opaque children remain unknown, and a proven missing child executes no body. The outer shell file alone no longer proves its child harmless; port: fixed.

- Cache correction includes imports of the fixed runner itself when no local sources are selected (including json.tool). Python -E/-I ignore cache-related environment variables, while -B still suppresses implicit imports and does not suppress explicit compilation. Direct child shell reading preserves the existing benign corpus decisions; port: fixed.
