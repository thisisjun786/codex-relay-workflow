# CRW-1082 — parity harness: the hook switch in every step's home, the shipped declarations, the real-host cells

Source: the CRW-203 harness (`internal/dev/laneparity`, `internal/dev/cxccorpus/engine.go`, `internal/contracttest/cxc_hookfire.go`) and the CRW-392 switch (`internal/hookswitch/hookswitch.go`, `plugins/crw/wiring/hooks/*.json`); the oracle files are the hook entry points of CXC v0.2.40 (commit 3c1459ac) that the corpus fixtures replay. The host measurements were made on codex-cli 0.154.0 (`docs/plugin-packaging.md`, "How hooks and MCP servers load"). The harness is described in `docs/port-cxc/parity-harness.md`.

- The harness (CRW-392's first step, 1666f2f4f) wrote `<CODEX_HOME>/crw/switch.json` into the case's `CODEX_HOME` only, so a fixture step that sets `CODEX_HOME` to a home of its own, or unsets it (the hook then reads `$HOME/.codex`), ran its ported leg against no switch and got silence; a full `parity all` on 7c2462a69 showed 3 of 229 fixtures differing (`hook__permission-request-allowing-agent-thread__home_cwd_default_config` and `__codex_config_must_be_full_access`, `hook__session-start-detecting-managed-worktree__unmanaged_and_root_are_silent`), which a run of the fixtures' slice in the unit tests never reached; port: fixed (the engine's `Seed` runs before every process step with that step's environment, the harness puts the switch in the Codex home the step names, made with the modes the hooks give what they make, and takes it out before the tree is observed; nothing is written outside the case root and the account's home is never resolved. Cases: TestFire_theSwitchIsInTheCodexHomeOfEveryStep, TestSeed_putsTheSwitchInTheCodexHomeOfTheStep, TestRunScenario_seedsEveryStepWithTheEnvironmentItRunsIn; red: `crw-dev parity fire --only` on those three at 7c2462a69, exit 1, kept under the issue's evidence).
- `crw-dev parity all` fired a root generated from K1, never the declarations that ship: pointed at `plugins/crw` every command starts `"$HOME/.local/share/crw-runtime/current/bin/crw"`, which the receipts could not identify, so all 456 receipts failed ("names no crw build") and 229 fixtures differed; port: fixed (the harness links that path to the build under test in the `HOME` of every step it fires and removes the link and the directories it made, a receipt names the build the link leads to, and `all` fires `plugins/crw` unless `--generated`. Case: TestFire_theShippedPluginFiresThroughItsOwnDeclarations; red: `parity fire --plugin plugins/crw` at 7c2462a69).
- The report held no evidence that the switch gates the ported legs outside a unit test of the harness; port: fixed (the `switchSilence` cell fires one fixture per ported leg with the switch off and at `cxc`: every firing must exit 0 in silence, record nothing, and every leg must have fired. Cases: TestJudgeSilence, TestSilence_thePortedLegsAreSilentWithTheSwitchOffAndAtCxc, TestFire_atCxcThePortedLegsAreSilent).
- The corpus replays the hooks through `crw hook` in a temporary root; it never showed the real host starting them. The real-host cells (`parity realhost`, `all --realhost`) run codex-cli 0.154.0 through whole turns in isolated homes against a stub Responses-API provider on the loopback interface, with the plugin as it ships in the home's plugin cache and trusted by `crw doctor retrust` (never by a bypass flag), and compare the hooks the host started with the declared ones: at `crw` the host started exactly 21 hooks for a turn of one shell command and one image view (SessionStart 9, UserPromptSubmit 5, PreToolUse 3, PostToolUse 1, Stop 3), each given the host's thread, one turn id and, for tool events, a tool call id, and 4 answers reached the model; with the switch off or at `cxc` the host started the same 21 and none of the ported legs answered or recorded; with no trust recorded it started none; port: kept (no defect found in the hook surface; the host behaviour is recorded here and in the parity harness document. Cases: TestRealHost_theCellsRunOnTheRealCodex and TestRealHost_aHookThatDoesNothingOrIsNotHeardFails behind the `realhost` build tag, the judgement and recorder tests without it).
- The host passes a hook the tool name `Bash` for its `exec_command` tool and `spawn_agent` (without the `multi_agent_v1` namespace) for a spawn, so the matchers of `pre-tool-use-guarding-managed-worktree-deletion` (`^Bash$`) and `pre-tool-use-attaching-skills` match what the host names, not what the model called; the host starts the UserPromptSubmit hooks again for the prompt of an agent a turn spawns (5 more starts, under the agent's turn id) and the SubagentStop hooks once when it ends, the one matched by `.*` and, for role `worker`, the one matched by `^(executor|worker)$`; port: kept (host behaviour, measured by the `turn/crw` and `spawn/crw` cells).
- After a compaction the host starts the SessionStart hooks again (`source: "compact"`) besides the three PostCompact hooks, and the recall context (`[crw-recall] Context was just compacted ...`) reaches the model from that SessionStart, not from a PostCompact hook (the three PostCompact hooks answer nothing); port: kept (host behaviour, measured by the `compaction/crw` cell).
- The PermissionRequest leg cannot be started by a `codex exec` turn: `exec` runs with approval policy Never, and an escalated command is refused (`approval policy is Never; reject command`) before any permission request, so the leg's host path is not verified, only its payload handling by the corpus; port: kept (the `permission/crw` cell reports itself not verified with that measurement, and passes as verified if a host that asks is ever driven; PostCompact, SubagentStop and the others of the issue's list are verified).
- Run in a home of its own without a proxy, the host starts a git clone of its plugin catalogue at the beginning of a turn (it leaves `.tmp/plugins-clone-*` directories with an empty `.git` in the home); port: kept (host behaviour; the real-host cells give the host a proxy that refuses every connection but the loopback provider and an empty git configuration, so a cell never reaches the network).
- A plugin package that holds a link to a directory (or a `--plugin` root that is one) made the real-host copy into the plugin cache recurse into itself without end, and a link that leads back into the package would have done so too; the unverified list lost the real-host cells although the cells had not run (a filter that matched nothing, or only some cells), and the seeding of the switch and of the runtime link checked the home by name only, so a link in the case root (the scenario's `given.symlinks`) could take a file out of it; port: fixed (the copy resolves links, copies the directory they name and reports a cycle as an error; a cell leaves the list only when the real-host cells that cover it ran and passed, and a filter that matched no cell claims no turn in the scope; the seed and its undo resolve every link before they create or remove anything and refuse one that leaves the case root. Cases: TestCopyPlugin_followsLinksAndRefusesACycle, TestNotVerifiedWithRealHost_onlyWhatRanAndPassedIsCovered, TestRealHostCommand_aFilterThatMatchesNoCellClaimsNothing, TestSeed_refusesALinkOutOfTheCaseRoot; red outputs under the issue's evidence, fix1).
- The undo of the seed removed the directories it had made without checking the way to them again, so a Codex home (or the HOME of the runtime link) replaced by a link out of the case root after the seed lost an empty directory of the same name behind the link; and a real-host cell whose turn the host never ran against the stub provider (an exec that ends at once on an API the stub serves and the host does not speak) failed instead of being reported not verified, and the scope named it among the cells that ran whole turns; port: fixed (the undo resolves the way to each made directory and leaves one behind a link out, or one that is a link now; a cell whose turn sent no model request, or whose retrust failed, is compared with a control run in a home of the stub provider alone, and is not verified with both measurements when the control fails the same way and failed when the control succeeds, and the scope names only cells whose turn reached the provider. Cases: TestSeed_refusesALinkOutOfTheCaseRoot, TestRealHost_aHostTheStubCannotDriveIsNotVerified, TestRealHost_aTurnTheControlRunsButTheCellDoesNotFails, TestRealHost_aFailedRetrust; red outputs under the issue's evidence, r2-red).
- The real-host cell took the plugin cache directory from the manifest's `name` and `version` without checking them, so a manifest whose version was `../` components and a directory name placed the package, and overwrote the files that were there, outside the run's temporary home; the silence cell judged only the invocation records of the fixture's observed tree (a fixture observes the roots it names, the diagnostic subtree is normally excluded, and the harness's own probe trees are never compared), so a hook that wrote a record while the switch was off or at `cxc` and exited 0 in silence passed; a runtime path that the scenario (`given.symlinks`) or an earlier step had already placed in the step's `HOME` was left as it was and the receipts and the latency identity named the build under test while the shell started the other file; and a PermissionRequest hook the host did start counted as a hook no declaration is due for, so the `permission/crw` cell failed on exactly the start that verifies it; port: fixed (the name and the version must each be one plain directory name and the entry must resolve below the home, checked before any cell is prepared; the seed reports every file under `<CODEX_HOME>/crw/hook-observations` that appeared during a run, where the seed is taken out and before the tree is observed, for fixtures and probes alike, and the silence cell fails on any; a pre-existing runtime path must hold the build under test (same sha256) or the seed refuses the step; the cell's accounting takes the PermissionRequest hook as an optional event judged for the event as a whole, either every declared hook of it started or none (a start of only some of several declared hooks fails the cell). Cases: TestRealHost_refusesAManifestWhoseNameOrVersionLeavesThePluginCache, TestSilence_aRecordTheFixtureDoesNotObserveIsFound, TestSeed_refusesARuntimePathThatHoldsAnotherBuild, TestJudge_aPermissionRequestHookTheHostStartedIsAccountedFor, TestJudge_aPartialStartOfTheDeclaredPermissionRequestHooksFails; red outputs under the issue's evidence, r3). The CXC 0.2.40 oracle has none of these surfaces: it has no switch, no installed runtime path and no plugin cache, they exist only in the CRW harness.
