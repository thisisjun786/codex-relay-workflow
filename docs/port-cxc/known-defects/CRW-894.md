# CRW-894 — the shell family behind a pipe, a here-string, a here-document and -c (re-check of 10-09 on dev 09e5c5bcc)

Source: the original `worktree-guard.ts` allows these shapes too (it reads no program position at all), so the defects are
the original's; the port reads them through the CRW-1028 reader (`internal/pabcd/shellir`). The 10-09 re-check of dev
09e5c5bcc (probes under `/state/crw/mgmt/recheck-20261009/`) and the independent verifier (c9(c), c10(c)) found that the
shell list of the reader (`isShell` in `internal/pabcd/shellir/policy.go`) held bash, sh, dash, zsh and ksh only. A program
piped or given to any other POSIX or Korn shell was a plain command the reader did not judge, so all three gates (the
memory write gate, the GitHub post guard and the worktree deletion guard) allowed it. The rows are
`internal/pabcd/hook/testdata/shellir/rows/18-crw-894-shell-family.txt` (CRW-894-sf-01..86, indexed in
`reproductions.tsv`); `TestReproductionRows` judges them and `TestShellFamilyThroughEntryPoints` sends the same rows
through `HandleWorktreeGuardPreTool`, `HandleMemoryWriteGate` and `HandleGitHubPostGuard`; the reader-level tests are in
`internal/pabcd/shellir/shell_family_test.go`.

- `printf 'rm -rf ../repo' | ash`, `| mksh`, `| hush` and the rest of the family (`pdksh`, `oksh`, `posh`, `yash`, `rbash`):
  allowed by all three gates; port: fixed (the names are shells wherever bash and sh are, so a shell without a
  `-c` string, script file or visible here-document is a program read from the pipe and is refused; rows sf-01..08).
- `| busybox ash`, `| busybox hush`, `| /bin/busybox ash`, `| /bin/busybox sh`: allowed (`busybox sh` and `busybox dash`
  were refused already); port: fixed (busybox is a wrapper whose first operand is the applet, and the applet is judged as
  the program of that name; rows sf-09..13).
- A bare `busybox` (or `/bin/busybox`) with no applet behind a pipe, a here-document or a here-string: allowed; port:
  fixed (it names no applet the reader can prove, so it is refused when standard input could carry a program; a bare
  busybox with no standard input, or with a file, only prints its usage and stays allowed; rows sf-14, sf-15, controls
  sf-79, sf-80; `TestBareBusybox`).
- The same shells behind the wrappers (`exec -a x ash`, `nohup mksh`, `env X=1 ash`, `sudo mksh`, `nohup busybox ash`),
  in a `-c` program or `eval` of a pipe shell (`| ash -c 'ash'`, `| mksh -c 'exec mksh'`, `| busybox ash -c 'ash'`,
  `| eval ash`), in `su -c` and `su --command=` (`| su -c 'ash'`), and through a descriptor alias of the pipe
  (`| ash </dev/stdin`, `| mksh 3</dev/fd/0 </dev/null <&3`): refused after the fix; port: fixed (rows sf-16..28).
- Programs the family shows: `ash <<< 'rm -rf ../repo'`, `mksh -c '...'`, `busybox ash <<'EOF'`, `su -c "ash -c '...'"`,
  `bash -c "ash -c '...'"`: the text is walked, so the removal is denied by the worktree guard and a memory write asks a
  grant; port: fixed (rows sf-44..72). `printf x | ash -c 'rm -rf ../repo'` is the removal its own `-c` string shows, not a
  program read from the pipe.
- The conditions that inherit the pipe (c10(c) of the verifier): `printf x | if false; then :; elif SH; then :; fi`,
  `| while SH; do :; done`, `| until SH; do :; done`, `| if SH; then :; fi`, `| ! SH` for SH in bash, ash and mksh; these
  were refused for bash already and are refused for the family now; port: fixed (rows sf-29..43 pin all of them, with
  the three control rows sf-84..86 for the same conditions around a program that is no shell, which stay allowed).
- Controls kept allowed: `ash -c 'echo hi'`, `mksh -c 'echo hi'`, `busybox ash -c 'echo hi'`, `printf x | ash -c 'echo hi'`,
  `printf x | busybox cat`, `busybox ls`, `printf x | (cd sub; cat)`, `printf x | cat ash`, `echo ash mksh busybox`; port:
  kept (rows sf-73..83).
- `printf x | python3 -m json.tool`: refused by the reader, which models no `-m` module; port: kept as the deviation already
  recorded in CRW-1028.md (row CRW-894-14, not a new gap).
- `python3 <<< 'harmless body'` (a Python program the here-string shows): allowed; port: kept (the reader reads the
  program and judges it; a harmful body is refused, a harmless one is not; this is the reader's design, "prove what runs
  or refuse", not a gap).
- `mksh` and the other names were added from the shell families' documented behaviour (a program on standard input, `-c`,
  a script operand); they were not run as installed binaries on the host (the host has no mksh), only read by the reader.
