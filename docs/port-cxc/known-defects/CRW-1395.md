# CRW-1395 — follow-ups of CRW-1373 and CRW-1374 (Argon V5): the target lookup stops at the child's own target, an archived rollout continues a lineage, a fault names the newest batch plan

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac, has no integration branch and no child push guard). The Go files are `internal/relay/dagsched/integration_target_receive.go` (`observedTargetOf`, `ReceiveTargetNotice`, `unobservedNotice`), `internal/relay/delivery/ack_target.go` (`withTargetNotice`), `internal/relay/hook/childlineage.go` (`rolloutOf`), and, for the reading, `docs/relay/dag-scheduler.md` (the receive and acknowledgement comparison). The relay schema, the fault classes (`contract/schema/fault-kinds.json`), the delivery state and the supervisor state are unchanged; the target table is not written by this change.

- `observedTargetOf` put a target into a step's result only when it had an observation, so a child whose own plan's target (step 1) or the target of a ref its plan's batch was recorded for (step 2) had no observation yet fell through to step 3 and could be compared with another integration ref that shares its baseline and was observed (CRW-1374.md, the first bullet; the Argon finding A1); port: fixed (a step stops the lookup as soon as it has a target the child belongs to, observed or not; step 3, the refs found by the baseline, is taken only when steps 1 and 2 have no target at all. Of the step's targets exactly one with an observation compares, as before; several with one compare nothing; none with one compares nothing, records nothing in the ledger, and the acknowledgement's output carries the warning `targetUnobserved` (`warning` `integration_target_unobserved`, `targets`, `baselineRevision`, `detail`) beside the record, where a move is `targetMoved`. Pinned by `TestReceiveStopsAtTheChildsOwnTargetWithoutAnObservation` (an unobserved own-plan target and an observed other ref on the same baseline), `TestReceiveStopsAtTheBatchRefsTargetWithoutAnObservation` (the same through step 2), the `no observation of the recorded target` case of `TestReceiveComparesNothingWithoutBothSides`, now with the warning, and `TestAckCarriesTheTargetNoticeAndProceeds`; `TestReceiveKeepsThePlansOwnTargetWhenAnotherRefSharesTheBaseline`, `TestReceiveComparesAChildOfALaterPlanOnTheSameIntegrationRef` and `TestReceiveDoesNotGuessTheTargetOfAChildNothingTiesToTheRef` are unchanged and pass).
- `rolloutOf` searched `archived_sessions` for a parent's rollout but found the Codex home only from an ancestor named `sessions`, so a lineage hop that started from an archived rollout, or went on from one, ended with `the rollout is not under a sessions directory` (fail-open, an unreadable-lineage warning) (CRW-1370.md, the fallback bullet; Argon A2); port: fixed (the Codex home is the parent of the nearest ancestor named `sessions` or `archived_sessions`; a path under neither says `the rollout is not under a sessions or archived_sessions directory`. Pinned by `TestChildBindingByLineageThroughArchivedSessions`: kid <- s2 (sessions) <- s3 (archived_sessions) <- s4 (sessions), read from s4 and from the archived s3).
- `ReceiveTargetNotice` replaced the plan of the newest batch on the integration ref (`recordedTargetHeads`) with `target.PlanID`, the plan that recorded the target first, so a fault found at the acknowledgement of a later plan's child named the first plan in its evidence and scope (Argon A3); port: fixed (the fault names the newest batch plan on the ref, as the push and the check already do. Pinned by `TestReceiveAttributesTheFaultToTheNewestBatchPlan`).
- `rolloutParent` read a first line without a newline whole before checking the 8 MiB bound (Argon A4); port: fixed in CRW-1387 (the same defect as CRW-1387 d2: `io.LimitReader(f, lineageMetaLimit+1)`; see CRW-1387.md, the first bullet, and `TestRolloutParentReadsAtMostTheLimitOfAFirstLineWithoutANewline`).
- Named limit. The warning `targetUnobserved` lives in the acknowledgement's output only: it is not a fault and leaves no ledger row (a new fault class would change the declared fault kinds of `contract/schema/fault-kinds.json`). The periodic `dag-integration-target-check`, the last step of every integrator pass, observes the target and the next acknowledgement compares it; port: kept.
