# CRW-1106 — the evidence retry counter: one reader, a tuple lock, exact session ownership

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/subagent-evidence.ts:97-114` (attemptsPath), `:185-206` (readAttempts), `:216-226` (writeAttempts), `:377`, `:408`, `:418-427` (the marker lookup and hasSpentBudget) and `:496-503` (the gate's read, increment and write). The Go side is `internal/pabcd/evidence/attempts.go` (`ReadCounter`, `WithCounterLock`, `WriteAttempts`), `budget.go` (`HasSpentBudget`, `counterOwner`), `unrecordable.go` (`markerMayBelong`), `lock.go`, `internal/pabcd/hook/subagentstop.go` (the gate under the tuple lock) and `internal/pabcd/cli/evidence.go` (resolve under the same lock). Found by the 10-10 CXC improvement review A3-01 and the combined review B1-02.

- The gate reads, increments and writes a child's counter with no lock, so stops of one child that arrive together each read the same count and each block: 32 concurrent stops blocked up to 32 times where the budget is three (subagent-evidence.ts:496-503); port: fixed. The whole decision of a stop runs under a lock of the exact (session, agent, turn) (`WithCounterLock`, an flock on a file in the state directory that the holder removes before it lets go, so nothing is left behind), and `crw pabcd evidence resolve` takes the same lock for the verdict it resolves. The one lock order is the tuple lock first and the session lock inside it. A lock that cannot be had leaves the counter and the verdicts of the tuple alone: a child with a valid receipt is released without clearing its counter or resolving its verdict (the holder may write them afterwards, and `crw pabcd evidence resolve`, which runs under the lock, settles what is left), and any other child is released with its negative verdict recorded. Pinned by `TestSubagentStopLockTimeoutLeavesTheCounterAlone`. Pinned by `TestSubagentStopCounterReservationIsSerialised` (sequential and barrier-started concurrent stops both block exactly three times) and `TestCounterLockLeavesNothing`.
- Supersedes known-defects.md, section "Found by the subagent evidence attempts port", item beginning "`readAttempts` reads a counter file that cannot be read or is not JSON as 0 attempts": now port: fixed (`ReadCounter` is the one side-effect-free reader of both gates: missing, active(n), exhausted, corrupt or unreadable. Only a file that does not exist starts at 0; a truncated, empty, `null`, string, array or unreadable counter is a terminal unresolved verdict: the child is released with a tombstone, the bytes stay, the goal-complete gate keeps refusing however often the child stops again, and a late valid receipt (the child's, or `crw pabcd evidence resolve`) clears both gates. Pinned by `TestSubagentStopCorruptCounterStaysTerminal` and the overrides of `TestReadAttempts`).
- Supersedes known-defects.md, section "Found by the subagent evidence markers, budget and directives port", item beginning "A counter file that is garbled or empty restarts the agent's budget in `readAttempts`": now port: fixed (both gates read `ReadCounter`'s classification, so one file means one thing).
- Supersedes known-defects.md, section "Found by the subagent evidence attempts port", item beginning "`writeAttempts` leaves its temp file behind when the rename fails": now port: fixed (a failed write removes the temp file of that call and nothing else; the `write_counter_is_directory` override of `TestWriteAndClearAttempts`).
- Supersedes known-defects.md, section "Found by the subagent evidence attempts port", item beginning "`attemptsPath` names a counter file from the sanitised session id": now port: fixed. CRW-1108 refuses a non-canonical or empty session id at the public evidence boundaries before reading, writing, clearing or taking a counter lock: reads answer spent/unreadable, writes fail, clears leave all old files alone, and locks return `state.ErrNonCanonicalSessionID`. This supersedes this lane's earlier non-canonical-session migration; `a/b` neither reads nor changes `a-b`'s budget, and a receipt cannot lift the non-canonical session's completion refusal. Pinned by `TestEvidenceBoundariesRefuseNonCanonicalSessionIDs`, `TestCounterLayoutBySessionShape`, `TestLegacyCounterOfANonCanonicalSession` and `TestSubagentStopLegacyCounterOfANonCanonicalSession`. CRW-1106 still keeps the oracle's file and bytes for canonical sessions with unchanged agent/turn ids, and stores counters of raw agent/turn ids in `evidence-attempts/v2/<session>-<digest of exact session>/<tuple digest>.json` with their identity repeated. Such tuples still read their own old flat counter until the next write migrates it or a receipt clears both; an unclassifiable legacy owner keeps denying. Pinned by `TestFreshCounterOwnershipWithRawActor`, `TestSubagentStopCounterSessionOwnership`, `TestCounterOwnerReadings` and every row of `TestAttemptsFileNames`.
- Supersedes known-defects.md, section "Found by the subagent evidence markers, budget and directives port", item beginning "The marker lookup and `hasSpentBudget` match a name prefix": now port: fixed (a counter name is this session's when a reading of the part after `<session>-` as an agent and a turn reproduces the name's digest, and another session's when a reading under a longer session id does, so s1-x's spent counter no longer refuses s1; a marker names its session in its body, so s1-x's marker no longer refuses s1 either. A counter name no reading explains (a file of an earlier version for an agent or turn id that sanitising changed) and a marker whose body cannot be read may be anyone's and still count, so a legacy file of unknown owner keeps refusing. Pinned by `TestSubagentStopCounterSessionOwnership`, `TestSubagentStopLegacyCounters` and `TestCounterOwnerReadings`).
- The gate counts every stop as an attempt and does not deduplicate a stop event delivered twice; port: kept. The hook payload carries no identity of the child's assistant event, and deduplicating by session and turn would merge a child's legitimate later attempts in the same turn; with the tuple lock a duplicate delivery can spend an attempt but can never lift the block count past the budget.
- A refusal to write the assignment record of a managed dispatch's packet (CRW-1115) used up the one-shot native-spawn issuance of its dispatch ledger although no spawn was allowed, and the attempt then refused every retry as already issued; port: fixed. The record is written before the issuance, so a record that cannot be written refuses the spawn while the attempt is still issuable, and the record is removed again when the ledger refuses the issuance. Pinned by `TestEvidenceAssignmentRecordFailureKeepsTheManagedSpawnIssuable`.
