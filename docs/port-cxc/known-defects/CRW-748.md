Source: `plugins/codexclaw/components/cxc-ops/src/doctor.ts` at v0.2.40 (commit 3c1459ac)
(`DoctorOptions` :47-62, `runInstalledRootCheck` :401-445, `runHookExecutionCheck` :448-467,
`runHookTrustCheck` :468-542), `plugins/codexclaw/components/cxc-ops/src/cli.ts`
(`parseHookOptions` :38-59) and `plugins/codexclaw/scripts/hook-observation.mjs`
(`readHookObservations` :86-129), through the ports in `internal/runtime/doctor/harness_report.go`
(`HarnessOptions`), `harness_install.go` (`harnessInstallCodexHome`, `HarnessInstalledRootCheck`),
`harness_hooks.go` (`harnessHooksCodexHome`, `HarnessHookTrustCheck`) and `harness_run.go`
(`harnessRunParseOptions`).

No new defect was found while making this change. The first of the three differences the CRW-616
record holds is gone — the two option readers now reproduce the oracle's `??` (`doctor.ts:402`,
`:469`, `:476`) — while the other two are still port differences and are re-stated below as kept,
because the superseded item bundled all three. The CLI cannot express an explicitly empty value,
because the oracle refuses an empty flag value (`cli.ts:49`, the `if (!value) throw` guard) and the
port refuses it too, so that case is reachable through the Go API only — parity, not a defect.

- Supersedes `known-defects.md`, section "Found by the hook observation reader and harness hook checks port (CRW-616)", item beginning "`options.pluginKey ?? ...` and `options.codexHome ?? ...`", for its explicitly-empty-option portion only: now port: fixed (parity restored, not a defect fix: `HarnessOptions.CodexHome` and `HarnessOptions.PluginKey` are `*string`, so a nil option falls through to `CODEX_HOME` and the home while a non-nil one — the empty string included — is used verbatim as the oracle uses it; `harness_options_empty_test.go` pins it red first. The item's other two differences stay kept, below).
- The superseded item's unresolved-home difference is unchanged: a Codex home that cannot be resolved (`HOME` unset and no account entry, which `homedir()` does not report) makes the execution check WARN with "invocation store unreadable" and the trust check FAIL with the error (source `doctor.ts:469`, `:479`); port: kept as a platform difference.
- The superseded item's freshness-field difference is unchanged: `now` and `maxAgeMs` are numbers in the oracle and `int64` here, so a non-finite value (`NaN`, `Infinity`), which the oracle refuses as "invalid freshness filter", cannot be passed (source `hook-observation.mjs:93`); port: kept as a platform difference.
