# CRW-794 — a vanished goalplan write lock is an error instead of a retry

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/goalplan.ts`,
`withGoalplanWriteLock` (:806-873): `mkdirSync` alone is the lock (:823) and an `EEXIST` is retried
until the delay budget is spent (:826-838), so a holder that removes the directory lets the next
attempt succeed. The port's `WithGoalplanWriteLock` (`internal/pabcd/goalplan/lock.go`, acquisition
loop :179-211) added an fd-bound descriptor check the oracle has no counterpart for: `openAt` opens
the held directory (`internal/pabcd/goalplan/open.go`:64-75) and `boundFile` (:46-62) compares the
descriptor path read through `descriptorPath` (`internal/pabcd/goalplan/open_linux.go`:10-12) with
the expected path.

- A writer waiting on the lock directory opened it (`lock.go:194`) and the holder released the lock
  and removed the directory (`open.go`:80-101, `unix.Unlinkat` at :99) between that openat and
  `boundFile`'s descriptor check, so the check reported `"<dir> (deleted)"` and the acquisition
  returned the descriptor-path error instead of retrying, as the oracle does; port: fixed by CRW-794
  (only the acquisition path of `WithGoalplanWriteLock` changed: a descriptor naming exactly the
  expected path plus the Linux `" (deleted)"` suffix now counts as a released lock and the existing
  retry budget is reused; `boundFile`, `openAt` and every other caller are unchanged, and a
  descriptor naming any other path is still an error).
- The recognition is name-based: a noncooperating actor that renamed the live lock to a sibling
  literally named `.goalplan.lock (deleted)` would satisfy the equality and be read as vanished. A
  cooperating writer may not remove or relocate an active lock (`open.go`:14-15), and the consequence
  is a retry-then-acquire inside the same plan directory rather than a containment escape; port: kept
  (deliberate, recorded) — superseded by `CRW-975.md` (CRW-976 folded in): the recognition now also needs the
  descriptor unlinked and the lock name absent or another inode, so a live lock under that name is an error.
- Darwin: `descriptorPath` uses `F_GETPATH` (`open_darwin.go`:13-22), which fails for an unlinked
  directory instead of returning a decorated path, so the re-read errors and the same race still
  fails there rather than retrying. The reproduction and CI are Linux, and the new test is tagged
  `//go:build linux` for the same reason; port: kept (out of the issue's scope).
- Two sibling windows keep their existing behavior because the issue scopes the change to the
  acquisition path only: the status probe's `openAt` (`lock.go`:72-78) can still return an error
  instead of `Exists=false` under the same interleaving, and the post-`mkdir` open (`lock.go`:185) has
  the window against a noncooperating remover; port: kept (out of scope, recorded).
