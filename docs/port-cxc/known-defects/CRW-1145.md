# CRW-1145 — a repeated enable keeps the flag ownership it had

Source: CXC v0.2.40, commit 3c1459ac — `plugins/codexclaw/components/config-guard/src/activate.ts` (the flag records rebuilt from the live flags at :220-246 while the managed keys are carried at :269-286), `deactivate.ts` (:99-103, :184-185) and `cli.ts` (:230-258). The Go port is `internal/runtime/install/configguard/activate.go` (`Activate`, `activationCarries`), `deactivate.go` (`Deactivate`, `DeactivateResult.Failed`, `DeactivateResult.Released`), `manifest.go` (`InstallManifest.ReleasedAt`) and `internal/runtime/install/features.go`. The finding is the 10-10 CXC improvement review A7-01 and the combined review B7-02 (repeated enable and disable).

- Every activation rebuilt the flag records from the live flags, so the second enable recorded the flags the first had turned on as pre-existing and the disable after it left all of them on; with four flags off, enable, enable, disable ended with four flags on (source `activate.ts:220-246`); port: fixed (an activation of the same install, a manifest naming the same config file that no deactivation released, carries each flag's first prior state and crw's ownership as it always carried the managed keys', and keeps the baseline's backup as the manifest's evidence. Another config file or a released manifest starts a new baseline; a flag already on that the earlier records do not own is never taken over. Pinned by `TestFeaturesEnableTwiceThenDisableRestoresTheOriginalFlags`, with a flag on from the start and an undeclared flag as controls, and `TestActivateRerunKeepsManagedPriorAndOwnership`).
- An enable that had nothing to change wrote a new backup and republished the manifest (source `activate.ts:217,299`); port: fixed (a carried activation with no flag to enable and no key to change publishes nothing and says so; a soft flag that failed before is off, so its explicit retry still runs, and the explicit enable still clears the self-heal opt-out. Pinned by `TestFeaturesUnchangedEnablePublishesNothingAndDisableStartsANewBaseline`).
- A disable that completes now records `releasedAt` in the install manifest (the records stay as evidence), so the next enable takes the flags and keys as they are then as its baseline, and a second disable has nothing to revert instead of turning off a flag the user set since. A flag that failed to disable or a key whose provenance could not be proven keeps the manifest live; port: fixed (new behaviour; the field is written only when set, so a manifest without it keeps the oracle's bytes. Pinned by `TestFeaturesUnchangedEnablePublishesNothingAndDisableStartsANewBaseline` and `TestDeactivateActivationRoundTrip`).

- Supersedes known-defects.md, section "CRW-499 — install features commands", item beginning "Repeated enable records the now-enabled flags as pre-existing": now port: fixed (see the first item).
- Supersedes known-defects.md, section "CRW-499 — install features commands", item beginning "Disable prints success and exits 0 when individual feature-disable calls fail": now port: fixed (each failed flag is reported with its exit code and Codex's message, the command exits 1, and the ownership stays recorded so a retry disables it. Pinned by `TestFeaturesDisableFailureIsReportedNonzero` and `TestFeaturesDisableBranches`).
- Supersedes known-defects.md, section "Found by the config-guard deactivation and marker port (CRW-497)", item beginning "A failed feature-disable exit is omitted from disabled without a failure field": now port: fixed for the failure field (`DeactivateResult.Failed`); the swallowed marker failure on an early uninstall return stays port: kept.
- A config set after the disable that released the manifest inherited the released records and committed a new key into a manifest the next disable returned from at once, leaving the key set; port: fixed (config set and unset refuse a released install and say to run `crw install features enable`, which starts the new baseline in which the key is owned and the next disable restores it. Pinned by `TestConfigSetAfterTheInstallWasReleased`).
