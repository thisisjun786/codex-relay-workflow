# CRW-1119 — an unusable helper role store is refused, not read as no override

Source: `plugins/codexclaw/components/subagent-config/src/store.ts` at v0.2.40 (commit 3c1459ac), `readRaw` (:152-167),
`reconstructRole` (:189-192), the primary model check (:86, :212) and `cxcHome` (:130), and `spawn-attach-hook.ts`'s outer catch
(:1111); the Go port's `StorePath`, `readRaw`, `readSettings`, `ReadSettings`, `ReadSettingsSnapshot` and `setRole` in
`internal/role/store.go`, `parseRole` in `internal/role/role.go`, `Validate` in `internal/role/patch.go`, `ResolveSpawnConfig` in
`internal/role/resolve.go`, the dispatch start in `internal/role/dispatch_ledger.go`, `createdCheckWithDB` in
`internal/role/created_check.go`, and `spawnHookSettingsDeny` in `internal/role/spawn/hook.go` with its callers in `hook_managed.go`
and `hook_route.go`. Found by the 10-10 CXC improvement review (A5-01, with the role-store part of B2-04).

- Supersedes known-defects.md, section "Found by the helper role store port", item beginning "`readRaw` turns every failure of a read into an empty config": now port: fixed (only a missing store is the empty config. A store that cannot be read (a directory, a file the process may not open) or parsed (not JSON, not an object, `roles` not an object, nested past encoding/json's limit) is an `UnusableSettingsError` naming the store, the reason and the repair; reads, the settings API (a 400), the MCP tools and `crw role helper` show it, a spawn of any role through the hook is denied with it, and a dispatch start is refused. The store keeps its bytes. Pinned by `TestUnusableSettingsAreRefusedAndTheStoreIsKept` and, through the hook, `TestSpawnHookDeniesARoleWhoseSettingsAreUnusable`; the recorded cases `read_not_json`, `read_roles_*`, `read_top_*`, `read_empty_file`, `read_trailing_garbage`, `read_bom` and `store_is_directory` of `TestOracleReplay`, and `resolve_malformed` of `TestSettingsOracleReplay`, are replayed as intentionally changed).
- Supersedes known-defects.md, section "Found by the helper role store port", item beginning "A primary model is valid when its length is above zero": now port: fixed (a primary model is trimmed as a fallback model is: a whitespace-only one is refused on write with "mode \"model\" requires a non-empty model id", and a stored one makes its role unusable, so the hook never spawns with it. A model id outside any catalog is still accepted. Pinned by `TestTrimEmptyPrimaryModelIsRefusedOnWrite` and `TestUsableSettingsStillInherit`; the recorded case `model_whitespace` and the executor of the full store in `get_global_full`, `response_get`, `resolve_full` and `update_inherit_resets` are replayed as intentionally changed).
- Supersedes known-defects.md, section "Found by the helper role store port", item beginning "A stored role value that is not an object": now port: fixed (a role that is not an object, or whose mode, model (in model mode), effort, prompt override or fallback cannot be spawned with, is an unusable role: `ReadSettings` refuses with one error per such role, while `ResolveSpawnConfig`, the dispatch start and the hook refuse only that role's routing, so the other roles keep theirs. A set is refused while any role is unusable, so a normalised copy never replaces what the operator wrote; a reset of the role is the repair and is written. Pinned by `TestUnusableRoleLimitsTheRefusalToThatRole`, `TestUnusableRoleIsRepairedByAResetNotByASet` and `TestPersistedRolesAreJudgedPerRole`; the recorded cases `read_partial_values`, `read_role_shapes` and `read_fallback_shapes` are replayed as intentionally changed).
- The spawn hook turned a settings read that failed into the oracle's empty output (its outer catch, :1111), so a recognized helper spawn whose routing could not be decided ran on the main model without a word (source `spawn-attach-hook.ts:892-926` and :1111); port: fixed (an `UnusableSettingsError` from the dispatch sources, the role resolution or the notice read denies the spawn with the store's message; an unusable role stops only a spawn routed to it, and a guarded message whose source depends on the roles' prompts is denied while any role is unusable. A home that cannot be found keeps the empty output, and an event that is not a spawn is untouched. Pinned by `TestSpawnHookDeniesARoleWhoseSettingsAreUnusable`).
- Supersedes known-defects.md, section "Found by the host-state reads port", item beginning "`CODEXCLAW_HOME` with surrounding whitespace names two directories": now port: fixed for the helper role store (`StorePath` follows the root rule of `internal/crwconfig` that CRW-1136 made the common boundary: a set, non-empty `CRW_HOME` is used as written, white space included, and must be absolute, and the path is joined as raw text with `crwconfig.JoinRoot`. A store left at the place the trimmed reading used is reported as an `UnusableSettingsError` naming both paths while the new place has none; it is never read or moved. Pinned by `TestStorePath` and `TestStorePathFollowsTheRootRule`).
- Supersedes known-defects.md, section "Found by the host-state reads port", item beginning "With an empty `HOME`, `os.homedir()` is empty": now port: fixed for the helper role store (an empty `CRW_HOME` is unset and the store is `.crw` below `host.HostHome`, the account home for an empty `HOME`; a store at `.crw` below the working directory is reported, never read or moved. Pinned by `TestStorePathFollowsTheRootRule`).
- Supersedes known-defects/CRW-1136.md, item beginning "`host.CodexSQLiteHome`, the oracle's reading, stays for the role package's created check": now port: fixed (CRW-1136 disposition d2: `createdCheckWithDB` resolves `host.CodexSQLiteRoot` once and lists and opens the newest database under `Root.Join`, so a root ending in `<symlink>/..` lists and opens the one directory the kernel resolves it to, and a relative root is refused. Pinned by `TestCreatedCheckNativeReadsTheDatabaseOfThePhysicalRoot` and `TestCreatedCheckNativeRefusesARelativeRoot`).
- The package comment's I6 no longer says that a stored role value that is not an object is replaced by a set: a set is refused while the role is unusable (I13 in `internal/role/role.go`).
