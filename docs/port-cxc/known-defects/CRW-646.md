# CRW-646 — the loop CLI's read verbs (init, show, validate, ready)

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/goalplan-cli.ts`:
`runReady` (:461-525) and the init/show/validate/ready branches of `runGoalplanCli` (:751-865), with the
`loop` dispatch in `src/cli.ts` (:169-180). Ported into `internal/pabcd/cli/loop.go`, `internal/harness/pabcd_cli.go`
and `internal/harness/pabcd.go`.

- The oracle guards a non-canonical `--session` id for the `ready` verb alone (:802-810), so
  `show --session a/b` and `validate --session a/b` address the state file of session `a-b` (state paths
  sanitize the id) and print or judge a plan the caller never named. Raised as a security finding by the
  pull request's Devin review (`"kind": "security"`), which the parity revision fixes during the port: the
  guard now covers every verb that resolves a plan through `--session`, and a test covers show, validate
  and ready. No corpus fixture drives a non-canonical `--session`, so no fixture is tagged for this
  deviation; port: fixed.
- The oracle asks only whether a plan LOADED, so a truncated or structurally invalid
  `<cwd>/.crw/goalplans/<slug>/goalplan.json` reads as absent and `writeGoalplan`'s rename replaces its
  bytes while a `created` ledger row is appended to the replacement (`goalplan-cli.ts`:764-767). The port
  refuses when slug's plan file is there but did not load, and the bytes stay for repair; a path the slug
  resolver itself refuses still reaches the write path and reports that refusal as the oracle does;
  port: fixed.
- The oracle binds a slug with `readState` then `writeState`, and `readState` answers a fresh IDLE state for
  a session file it cannot decode, so `loop init --session <id>` replaces a damaged session state with a
  default and loses the original bytes (`goalplan-cli.ts`:795-798 against `state.ts`). The port reads the
  state with the strict reader under the session lock and refuses an unreadable file, before anything is
  written; port: fixed.
- The oracle's `ready --json` is `JSON.stringify`, which leaves `<`, `>`, `&`, U+2028 and U+2029 as they
  are, while the first version of the port encoded that document with Go's `json.Marshal` and escaped
  them. Raised by the pull request's Devin and Codex reviews; the port now uses the package's
  JSON.stringify encoder, so the bytes agree with the oracle for any plan text; port: fixed.

No other defect was found in this issue's ranges: the ported units reproduce the oracle's answers through
the corpus replayer (19 fixtures, `contract/notes/cxc/CRW-646.json`) and through the ported TypeScript
cases.
