# CRW-1325 — cancel releases its binding without waking the upper layer; decision notes and measured times

Source: CRW's own flow and relay, not the CXC oracle. The changed owners are internal/flow/cli/cancel_binding.go and start.go, internal/relay/registry/scope_release.go, internal/flow/report/hook.go, internal/relay/decisions/answer.go and internal/relay/store/userdecision_notes.go.

- A cancelled run left its project binding active and sent a completion that could restart recovery; port: fixed. The start records the exact binding tenure and a journal pin before spawning. Once cancelled and its executions settled, the run retires that tenure and its links, recording scope_released. A changed tenure, a later start, or other live work is preserved. The cancelled finish sends no completion or pending escalation. TestCancelReleasesTheProjectBindingAndRecordsIt, TestOldCancelLeavesANewerRunBinding, TestCancelKeepsTheBindingWhileAnotherRunIsUnfinished and TestCancelFakeHostReleasesBindingWithoutWakingUpperLayer cover these paths with synthetic stores and a fake App Server.
- decision-answer refused an option with prose; port: fixed. answer_text keeps the option for decision-apply, answer_note holds the prose in an additive side table in the same transaction. Old records need no note. TestCRW1325OptionAndTextAreStored and TestCRW1325OptionAndTextApplyOnTheChoice read the SQLite roundtrip.
- Layer records could carry guessed times; port: fixed in the procedure. The shared tracking rule reads date immediately before recording an observation or names the relay event whose timestamp is copied; event and observation time remain distinct. This instruction does not prove live compliance.
- Limit: a run started before binding pinning keeps its binding. Already delivered notices are not withdrawn. A cancellation that reports other live work leaves the binding in place; repeat only after reconciling that work.
- The final review found that an integrated execution with no closure still counts as open, so integrated history can prevent a later cancellation from releasing its binding; port: pending (P2, recorded under the one-review P0/P1-only scope).
- The final review found that a start failing after it pins the binding can leave a newer pin without a started process, which protects the binding from an older cancel; port: pending (P2, recorded under the same scope).
- The final review's P1 cases are fixed: release takes the existing exclusive project lock before its transaction, and reads other runs with the canonical Summarize state in that transaction. TestReviewReleaseWaitsForManagedStart and TestReviewHeldRunKeepsBinding reproduce the earlier failures.
