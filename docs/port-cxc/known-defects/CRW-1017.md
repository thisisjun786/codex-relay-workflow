# CRW-1017 — an absolute receipt inside cwd refused as missing (port-introduced defect, fixed)

Source: Linear CRW-1017, the management evaluation of PR #595 (the CRW-633 final-gate guard port, P1, found by reading dev a850a3fcc; not reproduced by the evaluation). The oracle is `plugins/codexclaw/components/subagent-config/src/final-gate-guard.ts` at v0.2.40 (commit 3c1459ac), which reads a receipt path as written (source :91-100 and :119-123). The Go files are `internal/role/spawn/finalgate.go` (`spawnFinalGateReceipt`, the new `spawnFinalGateBelow`) and `internal/role/spawn/finalgate_test.go`. The hook that calls the library is not wired to production (CRW-392), so the defect closes the final gate more than necessary and weakens no check.

- The port refused a receipt given as an absolute path inside the working directory as "test receipt is missing" when cwd was `.` or any other relative path, because `filepath.Rel` cannot relate a relative base to an absolute target; the oracle reads it. port: fixed (cwd is made absolute and resolved through its links before `filepath.Rel`, and the base of the receipt path is the shortest ancestor of it that is the same directory as cwd by identity (`os.SameFile`, device and inode), so a relative cwd and an absolute receipt compare alike while the links below that base are left for `os.Root`; pinned by `TestCheckFinalGatePrereqsReadsAnAbsoluteReceiptInsideCwd`, red output `evidence/red-2-before-fix.log`, green `evidence/green-1.log`).
- The port refused the same absolute receipt when cwd was a symbolic link to the real directory and the receipt named the real path: the lexical `../` path leaves the `os.Root` of cwd. The oracle reads it. port: fixed (the same resolution; `TestCheckFinalGatePrereqsReadsAnAbsoluteReceiptInsideCwd`, the alias and relative-alias cases).
- A receipt spelled through the alias while cwd is the real directory, or through the real path while cwd is an alias, is read in both directions. The oracle reads both. port: fixed (the same resolution; the alias-by-real-path and real-by-alias cases of `TestCheckFinalGatePrereqsReadsAnAbsoluteReceiptInsideCwd`). On a case-insensitive file system (APFS, NTFS) a link resolves to the spelling its text holds, which can differ in case from the receipt's spelling of the same directory; the directories are compared by identity, not by resolved string, so that spelling is read too. Linux cannot create such a file system without privileges, so `TestCheckFinalGatePrereqsReadsAReceiptSpelledInAnotherCaseOfCwd` makes two directories of another case stat alike through the `spawnFinalGateSameDir` seam (red output `evidence/red-5-case-identity-before-fix.log`); no run on a case-insensitive file system was made.
- A receipt that leaves cwd by name, by an absolute path to a directory linked outside, by a directory link below cwd (an absolute one to a directory inside cwd, or a relative one that leaves cwd and comes back), or by a relative link out of cwd is refused, as before the fix: every read stays below the `os.Root` of cwd, where the oracle reads it wherever the path leads. port: kept (the security boundary of CRW-633; pinned by `TestCheckFinalGatePrereqsKeepsAReceiptOutsideCwdRejected`).
- An absolute link to a receipt inside cwd is refused, where the oracle follows it: `os.Root` refuses an absolute link even when its target lies below the root. port: intentionally-changed (the CRW-633 containment fix; the recorded oracle case "an absolute link to a file below the working directory is not followed" and the pin in `TestCheckFinalGatePrereqsKeepsAReceiptOutsideCwdRejected`).

Supersedes known-defects.md, section "Found by the CRW-633 final-gate guard port", item beginning "The oracle joins the slug of the session state": now port: fixed for an absolute receipt path inside cwd (the containment refusal reads "a path, absolute or relative, ... is unreadable" there; it now holds only for a path that leaves cwd or an absolute link, and an absolute path inside cwd is read below the real cwd, the oracle's answer).
