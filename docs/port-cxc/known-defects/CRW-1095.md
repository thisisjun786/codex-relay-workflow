# CRW-1095 — one reconciliation per record per hook event, and a byte budget for the wake text

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/bg-wake/src/hook.ts:45-50` and `:117-120` (SessionStart calls adoptOrphans, then hasAnyTask, and each lists the store), `registry.ts:67` (processStartToken runs `ps`), `registry.ts:147-157` and `:242-245` (reconcile asks `ps` for every running record with a token) and `describeRecord` (the whole command in every line). The Go files are `internal/relay/job/hook.go` (HandleSessionStart, CompletionText, fitWake, briefRecord), `internal/relay/job/registry.go` (deliver) and `internal/relay/job/verbs.go` (cliDrain). The tests are in `internal/relay/job/hook_budget_test.go`; the red run against the code before the change is `/state/crw/crw-lane-bg-job/evidence/red-1095/red.log` (160 `ps` calls for 80 running records in one SessionStart, and a SessionStart envelope of 400,565 bytes); the red run of the envelope budget is `/state/crw/crw-lane-bg-job/evidence/red-fix2/red.log` (a SessionStart envelope of 7,685 bytes for five jobs whose ids, commands and notes hold control characters).

- SessionStart listed and reconciled the whole store twice, once for the adoption and once for the has-task question, so every running record with a start token cost two `ps` calls per event (oracle and port alike); port: fixed (HandleSessionStart takes the store lock, lists the store once, adopts from that snapshot and answers has-task from it and the adoptions; Stop and UserPromptSubmit already listed once. A record whose exit file answers is never asked about with `ps`, then or later. Pinned by `TestBgHookEventReconcilesEachRecordOnce`: 80 running records cost 80 calls in each of SessionStart, Stop and UserPromptSubmit, and three finished ones none).
- The wake text described every job with its whole command, so five jobs with long commands put hundreds of kilobytes into the session's context; port: fixed (a command over 160 bytes and a note over 120 bytes are cut at a rune boundary with an ellipsis, and such a line ends with `(전체: crw relay job get <id>)`; the budget is measured on the text as it is handed over: the serialized envelope of a hook, where JSON spells a control character in six bytes, and the JSON string of a drain. A batch whose lines pass 2,048 bytes, or whose text passes 4,096 bytes, is written again without commands and notes, each line then `- <id> (<status>, exit <code>, <duration>) (전체: crw relay job get <id>)`; a batch that still passes 4,096 bytes (long ids, which appear twice per line) describes its first jobs that fit, and Stop, UserPromptSubmit and drain stamp only the jobs they described, so the others stay pending for the next wake; the SessionStart adoption keeps the count of all adopted jobs. One job always fits: a file name holds at most 255 bytes, so its line stays near 3 KB even with every byte escaped. Every job described keeps its id, status, exit code, duration and get, a line whose command fits and that has no note is DescribeRecord's line unchanged, so the recorded wake, adoption and drain texts are the same, and the record keeps the whole command. Stop, UserPromptSubmit, the SessionStart adoption and drain share `fitWake`. Pinned by `TestBgWakeTextKeepsABudget`: six jobs with 80 KB commands and notes give valid UTF-8 envelopes under 4 KiB that name each id and its get; and by `TestBgWakeEnvelopeBudgetCountsEscapesAndLongIDs`: five jobs whose 201-byte ids, commands and notes hold control characters give envelopes under 4 KiB over successive wakes that together deliver all five, each job delivered exactly when it was described, and a 250-byte id of control characters alone fits).
- A note was never shown in a wake; the brief line shows it, cut to its budget, in brackets after the command. Recorded deviation; port: fixed.
- No deadline is put on the reconciliation of one event: every running record is still asked about once per event, so none is left unobserved, taken for finished or dropped from the wake; a reading of the start identity from the OS without `ps` is not used, because the recorded start token is `ps`'s `lstart` text and the replayed corpus logs those `ps` calls. Port: kept.
