# CRW-1349 — an idle report the idle pass drained and then dropped on a store failure, and two tests that did not pin the shared subscription

Source: CRW's own design (CRW-1314 design section 3, the CRW-1334 follow-ups from its pre-merge review), not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no idle edge for the supervisor channel. The Go side is `internal/relay/daemon` (`idle_wake.go` `idle` and `carry`; the tests `idle_wake_carry_test.go` and `supervisor_wake_paths_test.go`).

- The idle pass takes the host's status reports off the App Server's channel before it applies them, and a store failure that is not corruption of `WakeBusyHead` or `WakeBusyRecipient` ended the tick and dropped the report that failed and every report after it in the same batch. A `busy_cap` or `attempt_cap` hold has no timer, so the lost report left the hold standing until the recipient's next edge or a readback (a delay, never a data loss) (daemon/idle_wake.go `idle`); port: fixed (the failed write still ends its own tick with its error and nothing after it writes (I-564), and the reports not applied, the failing one first, are kept in memory, each once, and applied at the next tick before the host's new reports; applying one again writes nothing, because a woken head and a due message are no-ops of the wake. A corrupting failure halts the store as before, so nothing is applied on it. The carry is bounded: a report whose wake fails on every pass (a per-report failure, not corruption) is tried on at most three passes (`idleReportPasses`), and the pass that fails it the last time still ends its tick on the error, drops it with a note naming it and carries only the reports after it, so one such report cannot end every later tick before the delivery pass and the supervisor channel run; its busy backoff, next edge or readback is then its trigger, as for every report before the carry. Pinned by `TestIdleWake_reports_a_failed_wake_did_not_apply_are_applied_on_the_next_tick` (both wakes failing, both caps) and `TestIdleWake_a_report_whose_wake_fails_every_pass_is_dropped_after_its_last_try` (both wakes refused for one report on every pass), with `TestIdleWakeHalt_*` unchanged).
- `TestIdleWake_a_recipient_waiting_in_both_channels_has_one_subscription` and `TestIdleWake_a_capped_supervisor_message_gives_a_shared_refused_hold_no_deadline` passed on a41dbb80 (an idle pass that never read `Channel.IdleWakeRecipients`) and with the `!seen` guard of `hold` removed: the first dispatched the supervisor message while the delivery head still waited and gave both channels the same thread, the second only looked at the delivery head's +300 deadline; port: fixed (both tests now run both orders, the supervisor channel waiting alone first and the delivery waiting first, with a delivery thread name different from the supervisor channel's, and assert which thread the one subscription is on and, for the refused hold, the supervisor-only zero deadline's own retry curve. Each fails on the a41dbb80 idle pass and on the guard removed, and passes on the current code; the mutation logs are kept with the lane's evidence).
