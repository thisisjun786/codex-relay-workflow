# CRW-1123 — recall storage and rollout collection sweep

Source: the recall port of CXC v0.2.40 (commit 3c1459ac): `recall/src/index-db.ts:20-22`, `paths.ts:32-38`, `sqlite.ts:29-31`, `threads-db.ts:41-52`, `repo-key.ts:38-56`, `rollout.ts:135-319`, and the Go side in `internal/recall` (`paths.go`, `indexdb.go`, `hookcontext.go`, `sqlite.go`, `threadsdb.go`, `repokey.go`, `remoteurl.go`, `rollout.go`, `chatscan.go`, `ingest.go`, `indexsearch.go`). Each item below was reproduced first (`evidence/crw-1123-red.log`), then changed. Every recorded oracle result that the change turns over is kept next to the port's in a `port-fixed.json` beside the oracle (`testdata/rollout`, `testdata/chatscan`, `testdata/hookcontext`), in `oracle-grid.json` (`classification: intentionally-changed`), or in the test that replays it.

- With an empty `HOME`, the default homes resolve against the working directory and recall creates `.crw` and reads `.codex` in the workspace (source `index-db.ts:21`); port: fixed (`recallHome` refuses an empty `HOME` with "cannot resolve the home directory: HOME is empty" in `indexPath`, `codexHome` and `hookContextHome`; nothing is created, and no other home is chosen. An unset `HOME` still falls to the account's home, and a named `CRW_HOME` or `CODEX_HOME` is used as given. `codexHome` also read the process's `HOME` and ignored the environment it was given; it reads the given one. `TestSweepEmptyHomeIsRefused`, `TestIndexPath`, `TestRecallHomeAndDirs`).
- `CRW_HOME` with surrounding whitespace is used as given (`TestIndexPath` pins it); port: kept (CRW-1123 defers this item to N15, the common resolved-root boundary for environment values in `internal/pabcd/host`, which is not in this tree; recall keeps asking `host.CRWHome`, so it follows that boundary and its diagnostic when it lands, and nothing here trims or migrates a stored profile).
- A directory or a link named like a database (`state_99.sqlite`) was eligible as the newest database and hid the usable one; port: fixed (`latestVersionedDb` takes a name only if it reaches a regular file, so a directory or a dangling link is skipped and a link to a file in the home is used. This reaches the memories store too: a directory named `memories_1.sqlite` is "no memories store found" where the oracle tried to open it and reported a disk I/O error. `TestSweepVersionedDBNeedsAUsableFile`; the `directory` and `open-failure` cases of `TestMemoryRequeueOracle` and `TestMemoryStatusOracle`).
- A home with a link followed by `..` listed the directory the system reaches and joined the names onto the lexical parent, naming another directory's database; port: fixed (`physicalHome` resolves the home once before it is listed and joined, and keeps the spelling when the cleaned path is already that directory. `TestSweepVersionedDBHomeIsResolvedOnce`, `TestRecallVersionedDBNamesTheListedDirectory`).
- A URI such as `file:x?mode=memory` overrode the read-only open, so the read-only API opened and wrote a private in-memory database (source `sqlite.ts:29-31`); port: fixed (`openDbReadOnly` refuses a `file:` URI with any `mode` parameter that is not `ro`. The check reads the URI the way SQLite does: split at the raw `&` and the first raw `=`, key and value percent-decoded, so `%6Dode=memory` and `mode=%6Demory` are modes, a repeated `mode` is judged each time (the last one wins in SQLite), and a query holding an encoded NUL is refused. Plain paths, `:memory:` and the empty path are read-only as before. `TestSweepReadOnlyRefusesURIOverrides`, `TestReadOnlyURIRefusesEncodedAndRepeatedModes`, `TestRecallSQLiteOpens`).
- The legacy-column retry caught every query error, so an unsafe integer in `git_origin_url` dropped the origin metadata silently when the shorter query succeeded (source `threads-db.ts:41-49`); port: fixed (the shorter query is run only for the error "no such column: git_origin_url"; any other failure is the reader's warning, as before. `TestSweepThreadMetaRetriesOnlyAMissingLegacyColumn`, `TestRecallThreadMetaWarningsAndCase`). The warning now covers a row that is unreadable: the thread metadata of that database is off, as it is for any other unreadable value.
- SQLite resolves column names without case, but row keys kept the declared spelling, so an `ID` column made every metadata row vanish without a warning (source `threads-db.ts:52`); port: fixed (the metadata columns are selected by alias, so the rows carry the canonical names. `TestSweepThreadMetaColumnNamesIgnoreCase`).
- An ambiguous bare named-parameter map threw on its first construction but left part of the alias map cached, so the next call bound the first alias; port: fixed (the aliases are checked whole and kept only when unambiguous, so the ambiguity is reported every time. `TestSweepAmbiguousAliasIsNotCached`, `TestRecallSQLiteNamedOrderAndCachedAmbiguity`).
- A named binding key with a NUL byte resolved by the prefix before the NUL; port: fixed (the key is refused: "Named parameter ... must not contain a null byte". `TestSweepNamedKeyWithNULIsRefused`).
- A local-looking colon path such as `C:\repo` was an scp remote and identified `c/repo`; port: fixed (`localDrivePath`: one letter, a colon and a separator is a drive path, so the cwd scope applies; `host:repo` and `git@host:path` are scp syntax as before. `TestSweepLocalDrivePathIsNoRemote`, `TestRepoKeyBaseOracle`).
- Decoding `%2F` before packing joined an encoded separator with a literal one, so `a%2Fb` and `a/b` shared a key; port: fixed (an encoded `/` or `\` stays encoded, in one spelling, `%2F` or `%5C`, so it keeps its path segment. A decoded percent stays encoded as `%25` too, so every escape in a key is a real escape: `a%252Fb` (a literal `%2F`) and `a%2Fb` (an encoded slash) are two keys, and so are the `%5C` pair. An scp path has no percent decoding, so its `%` is literal and is written `%25` in the key: `host:a%2Fb` equals `https://host/a%252Fb` and never `https://host/a%2Fb`. `TestSweepEncodedSeparatorKeepsItsSegment`, `TestRepoKeyLiteralPercentIsNotAnEncodedSeparator`, the `states` row `https://x/%2F.git` of the grid, `TestRepoKeyBaseOracle`).
- Listing checked only the `.jsonl` suffix: a directory or a link to nothing was listed, reading it threw, and an enumeration error escaped the whole listing and so every search and refresh; port: fixed (only a regular file, or a link that reaches one, is listed; a directory that cannot be read leaves its own files out; a refresh counts a rollout it cannot read in `IngestResult.Skipped` and goes on, and a scan reports it as a warning ("unreadable rollout") and goes on; the listing itself no longer fails for one entry. What a directory's failed read leaves out is not taken for removal: the listing reports the directories it could not read (`listRolloutFiles`), and a full refresh neither prunes nor counts as extra a file below one of them, and prunes a file only when it is absent at the moment of the prune (CRW-1154); `TestUnreadableDirectoryIsReportedAndNotPruned`, `TestListRolloutFilesReportsUnreadableDirectories`. `TestSweepUnusableEntriesAreFilteredPerFile`, `TestRolloutHeadReadAndFailures`, the `directory` case of `TestChatScanOracle`).
- Directory and archive-name dates were compared as strings without calendar validation, and a window past the range of dates produced `NaN-NaN-NaN`, which pruned every file of every source; port: fixed (the window is computed once: one that reaches before the representable calendar (infinite, `1e20`) excludes nothing; with a window, a directory or archive name whose date is not a calendar date has no age to compare and is left out, and without one it is listed. `TestSweepDaysAndFolderDatesAreValidated`, `TestRolloutLocalMidnightAndInvalidDays`, and the recorded `list` cases).
- A metadata first line past 1 MiB fell back to all-null main metadata even when the complete JSON would identify a subagent; port: fixed (the line is "unknown": `RolloutUnknown`, stored as source `unknown`; a main-only or subagent-only search leaves the file out and `--source all` lists it. `TestSweepOversizedMetaLineIsUnknown`, the recorded `meta` case).
- A text, name or arguments object with a non-callable `toString` made String coercion throw outside the JSON catch and ended the whole parse; port: fixed (the entry is dropped alone; the entries before and after it are kept, and `ParseRollout` no longer returns the coercion error. `TestSweepUnreadableEntryIsIsolated`, `TestRolloutParserJudgesDecodedLines`, and the recorded `parse` cases whose error was that coercion).
- The literal prefilters skipped valid JSON with an escaped type (`response_\u0069tem`) and a whole file whose decoded text matched but whose raw text did not (`\u0043I` for `CI`); port: fixed (a line that has a `\u` escape is parsed, and a scan judges a file on its content with every JSON escape decoded (`\u`, `\\`, `\"`, `\/` and the control escapes), so a scan finds what the index finds. `TestSweepEscapedMatchesAreDecodedBeforeTheyAreJudged`, `TestSweepEveryJSONEscapeMatchesLikeTheIndex`, `TestPrefilterTextDecodesJSONEscapes`, the `CI` case of `TestChatScanOracle`, the recorded `parse` cases 1109 and 1110). A file whose decoded content does not match is still skipped without being parsed.
- A complete metadata line that ended exactly at the 1 MiB read bound, followed by its line break, was taken for a cut line because the probe looked only for another byte; port: fixed (the probe reads that byte: a line break or the end of the file ends a complete line, any other byte means the line goes on. `TestRolloutMetaLineEndingAtTheReadBound`: below, at, one past the bound and at the bound with more content).
- A rollout directory that could not be listed was left out of the scan, the status and the verdict without a word; port: fixed (the scan warns, the freshness counts it in `UnreadDirs` and is incomplete, a refresh reports it, see CRW-1083; the rows below the directory still stay. `TestUnreadableDirectoryIsNeverReportedAsAComplete`, `TestUnreadableDirectoryIsReportedAndNotPruned`).
