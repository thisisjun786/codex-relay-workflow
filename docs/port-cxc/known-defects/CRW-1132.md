# CRW-1132 — the live catalog cache is keyed by the native source it resolves

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/subagent-config/src/live-catalog.ts:55` (`sourceKey`),
:64-68 (cache validation) and :83-119; `catalog.ts:67-75` (`nativeCatalogPath`), :102-105 and :112-121 (`readNativeCatalog`,
`nativeEntries`, `buildCatalog`); the Go port's `sourceKey`, `cachedCatalog` and `queryCatalog` (`internal/role/livecatalog.go`)
and `NativeCatalogPath`, `ReadNativeCatalog`, `BuildCatalog` (`internal/role/catalog.go`). Found by the 10-10 CXC improvement review
(A5-07). The oracle's differential probe (two homes, one shared `CRW_HOME`) answered `home-one` for both and read the native
catalog once.

- The source key hashed the raw `CODEX_HOME`, `CODEX_MODELS_CACHE_PATH`, `PATH` and `OPENCODEX_HOME`, so a shared `CRW_HOME` whose `HOME`
  alone changed (no `CODEX_HOME`, so `HOME/.codex` is the native home, or a configured `~/` catalog path) returned the other home's
  list as fresh and joined its pending request; port: fixed (the key is what the reader resolves: the native home, the native
  catalog path `NativeCatalogPath` selects, the `ocx` executable `PATH` finds and the `OPENCODEX_HOME` it runs with, or, while that is
  blank, the `HOME` it falls back to, each path as an absolute path against the process directory, as the readers open it, so
  one relative `CODEX_MODELS_CACHE_PATH`, `CODEX_HOME` or `OPENCODEX_HOME` text in two directories is two sources; the raw variables
  stay in the key; the project directory is still not part of it. The cache file
  is still one slot per `CRW_HOME`, so a read for another source replaces it. The first read after this change finds a key it does not
  know and discovers once more. Pinned by `TestLiveCatalogKeyFollowsTheResolvedNativeHome`,
  `TestLiveCatalogPendingDoesNotMergeAcrossHomes`, `TestLiveCatalogKeyKeepsTheCacheWhenHomeSelectsNothing`,
  `TestLiveCatalogKeyFollowsTheResolvedOcx` (same PATH text, the first `ocx` removed),
  `TestLiveCatalogKeyFollowsTheAbsoluteNativeSource` and `TestLiveCatalogSourceIdentityAndClock`).
- Cache validation coerced a `fetchedAt` of any type through `Date.parse`, accepted any `state` (or none), and accepted blank entry IDs
  and labels, so a cache no writer produces was returned as fresh; port: fixed (a cache is fresh only when `status` is `fresh`, the
  source is `ocx` or `native`, `state` is the one that source writes (`ocx-active`, `native-catalog`), `fetchedAt` is a string in the
  writer's spelling (`2006-01-02T15:04:05.000Z`) not more than a second ahead of the clock, every entry has a known source, an ID and a
  label that are not blank, IDs are unique, and the effort ladder is null or a list of strings. Anything else is no cache: the reader
  discovers again, which is the bounded refresh, and a success replaces the file. Members the validation does not name, in the
  catalog and in its entries, are returned as read, and the last successful list is still shown as `stale` while discovery keeps
  failing; `CatalogIsAuthoritative` accepts only a `fresh` catalog, so a stale list never proves routing. A role's model ID is not
  checked against the catalog, so a model outside it stays configurable. The Date.parse forms of the old cache (local zone, RFC,
  zone names, `24:00`, legacy numbers) are gone with `catalogDate`. Pinned by `TestLiveCatalogRejectsCachesAWriterCannotProduce`,
  `TestLiveCatalogValidation`, `TestLiveCatalogFetchedAtIsTheWritersSpelling` and
  `TestLiveCatalogKeepsExtensionFieldsAndShowsStaleWithoutAuthority`).

- Supersedes known-defects.md, section "CRW-501 — Helper role live catalog", item beginning "The source key omits the resolved native

- Supersedes known-defects.md, section "CRW-501 — Helper role live catalog", item beginning "`fetchedAt` is declared a string": now
  port: fixed (a number, a date-only text or any spelling but the writer's is refused, above).
- `nativeCatalogPath` decoded a TOML basic string with `JSON.parse`, so TOML-only escapes such as `\U0001F600` and `\e` made the
  configured catalog unavailable, while JSON-only forms (`\/`, a surrogate pair) selected a path TOML would refuse (source
  `catalog.ts:67-75`; `TestNativeCatalogPaths`); port: fixed (`tomlBasicString` reads the body with TOML's escapes: `\b \t \n \f \r \"
  \\ \e`, `\uXXXX` and `\UXXXXXXXX` for a Unicode scalar value, and a raw tab; a surrogate or out-of-range code point, any other escape
  and any other control character fail closed with no path, as before. TOML 1.1's `\xHH` is not read. No dependency is added. Pinned by
  the `toml-*` rows of `TestNativeCatalogPaths`).
- `nativeEntries` trusted an injected native list without deduplicating it and `buildCatalog` rejected only empty provider IDs, so
  native duplicates and a whitespace-only provider ID survived (source `catalog.ts:112-121,144-151`; oracle rows
  `native-duplicates`/`whitespace`); port: fixed (the native entries are deduplicated by exact ID and a trim-empty ID is dropped where
  `BuildCatalog` produces them, from an injected list as from the cache file, and a trim-empty provider ID is refused as an empty one is;
  `ReadNativeCatalog` already did both. Pinned by `TestCatalogEntriesShareOneConstruction` and the build rows of `TestCatalogOracle`,
  whose recorded oracle answers `portFixedBuild` adjusts).
- `buildCatalog` and `readNativeCatalog` gave the same cache entry different labels, and only the latter kept its effort ladder (source
  `catalog.ts:102,119-120`); port: fixed (one `newCatalogEntry` builds every entry: `ParseOcxModels` (the OCX roster), `ReadNativeCatalog` (through `nativeEntry`) and
  the library catalog. An entry the native reader and the library both produce is equal, label and ladder; the label of a native or provider
  entry is its ID, as the live reader gave it, so the library's " (native)" and " (ocx)" suffixes are gone, and `CatalogDeps` gets
  `ReadNativeEntries` for a caller that has the entries. Pinned by `TestCatalogEntriesShareOneConstruction` and
  `TestDefaultCatalogUsesProcessEnvironment`).
