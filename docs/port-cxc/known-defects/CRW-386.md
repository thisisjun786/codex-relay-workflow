# CRW-386 — the loop is withheld from a verified coordinating seat by every hook leg that gives it

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/hook.ts` `handleStop` (:1805-1873) and `buildGoalIdleBlock` (:1694-1738), and `plugins/codexclaw/components/cxc-ops/src/map-affordance.ts` (`runMapAffordanceSessionStart`, the loop pointer and the PostCompact restore of `runUserPromptAffordance`). None of them reads a session role: the oracle has no registry. The Go files are `internal/pabcd/hook/stop.go` (`StopHandleWithRole`, `stopGoalIdleBlock`), `internal/affordance/hook.go` (`RunMapAffordanceSessionStartWithRole`, `RunUserPromptAffordanceWithRole`), `internal/pabcd/hook/detect.go` (`PromptRole`, `Coordinates`) and `internal/harness/prompt_role.go` (`RegistryPromptRole`). The rule is decision 6 (a non-implementing seat does not run PABCD) and `plugins/crw/skills/crw-run/references/goal-mode.md` (the project parent never follows the crw-loop or crw-pabcd procedure).

- The Stop hook answers the goal-idle block (arm `orchestrate P`, or close the goal) to any session with an ACTIVE host goal, a bound goalplan with remaining work and no cycle in flight, so a project parent that holds a goal for its coordination was told to run a PABCD cycle it must not run, and a parent with a bound goalplan (the CRW-146 case) was blocked up to the three-per-phase and 24-per-turn caps (hook.ts:1805-1873, 1694-1738); port: fixed (the Stop leg takes the read-only registry reader `StopHandleWithRole` and, once every other release has been decided and only the goal-idle block is left, asks it once for the payload's session: a session whose live scope bindings are only a parent seat, or only a supervisor seat, is released with no output, no counter write and no state write, whether or not a goalplan is bound. A dispatched task (child), an unbound session, a session with two or more roles (parent and child, parent and supervisor), a store that cannot be selected or read within the 2 s read budget, and a leg with no reader keep the oracle's block byte for byte. The registry is read only for a Stop that would answer the goal-idle block, so a Stop with no goal, no bound plan, a decision wait, a context-pressure recovery, the total cap or a cycle in flight reads nothing, and the in-flight continuation of a parent that started a cycle itself is the oracle's. Pinned by `TestStopGoalIdleBlockIsSkippedForACoordinatingSeat` (parent and supervisor released and the state bytes unchanged, task and unknown and no reader equal to the reader-less block, in a git and a non-git workspace), `TestStopReadsTheRoleOnlyForAGoalIdleBlock` and, through the wired leg against a seeded registry, `TestStopLegGoalIdleFollowsTheRegistryRole` and `TestStopLegInFlightBlockIsNotRoleDependent`; red output `/state/crw/crw-lane-role-hooks/evidence/red-stop-386-145.txt`).
- The SessionStart map affordance gives every session the loop pointer ("Loop contract: for actual loop work load $crw:crw-loop + $crw:crw-pabcd ..."), a pointer that tells an implementer how to arm and run a loop (map-affordance.ts `runMapAffordanceSessionStart`); port: fixed (the leg asks the reader for the payload's session when the session id is valid and a reader is given, and a verified parent or supervisor gets the list without the loop pointer, in the answer and in the record of what the session was given (CRW-1146), so its own resume still re-issues the binding only. Every other pointer, the binding and the PATH banner are unchanged; a task, an unknown role, an invalid or missing session id and malformed input get the whole list as before. `RunMapAffordanceSessionStart` keeps the reader-less behavior. Pinned by `TestSessionStartLoopPointerFollowsTheRegistryRole`, `TestSessionStartReadsNoRoleWithoutAValidSession`, `TestCoordinatingSeatResumeKeepsTheRecord` and, through `RunHook` against a seeded registry, `TestWiredHooksReadTheRegistryRole`; red output `/state/crw/crw-lane-role-hooks/evidence/red-affordance-386.txt`).
- The PostCompact restore (`runUserPromptAffordance`) renders the loop pointer unconditionally when it consumes the compaction marker, so SessionStart withholding it from a parent would have been undone by the first prompt after any compaction (the verifier's correction of the triage); port: fixed (`RunUserPromptAffordanceWithRole` consumes the marker as before and, only then, asks the reader; a coordinating seat's restore omits the loop pointer, every other section and the single-consumer marker semantics are unchanged, and a prompt with no marker reads no registry. Pinned by `TestCompactRestoreLoopPointerFollowsTheRegistryRole` and the compaction half of `TestWiredHooksReadTheRegistryRole`).
- The role reader knew a parent and a child only; a supervisor seat (role `supervisor`, scope kind initiative or store) was an unknown role (the verifier's correction of the triage: `PromptRole` had no supervisor); port: fixed (`PromptRoleSupervisor` is added, `RegistryPromptRole` maps a session whose only live binding is a supervisor seat to it, and `PromptRole.Coordinates` is the one question every leg asks: parent or supervisor. UserPromptSubmit asks it too, so a verified supervisor's loop request gets the scope pointer (without the parent-only sentence, which says "registered as a project parent") and an explicit current-task implementation keeps the recipe as for a parent. A supervisor that also holds another seat is no role. The L0 manager is not a role this reader reports: it reads parent, supervisor and child bindings only. Pinned by the supervisor cases of `TestLoopArmScopeCases` and `TestPromptSubmitLegReadsTheRegistryRole`).
- Supersedes CRW-1084.md, item beginning "The production role reader": its closing sentence ("CRW-386 keeps the parent-role branches of the Stop and SessionStart hooks") is now done: the Stop, SessionStart map-affordance and compaction-restore legs read the same `RegistryPromptRole` as UserPromptSubmit (port: fixed, above). The reader's own rules, the 2 s budget and the read-only open of the store are unchanged; a slow or unreadable store stays an unknown role.
