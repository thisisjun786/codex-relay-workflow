# CRW-1064 — loops over harmless calls and the zsh chdir synonym

Source: the independent verification round 3 of CRW-894 (GPT sol, head 60ef281d4), whose two points are quoted in Linear CRW-1064 (P1 over-block, P2 chdir), with criteria c1 (harmless calls keep the directory, real directory changes stay unknown), c2 (red test first, the CRW-894 rows and TestShellWriteBenignAccounting unchanged) and c3 (this record). The Go files are internal/pabcd/shellir/shellir.go (forClause, the while clause, afterLoop, prescanLoop, stateChanges, wordsChange, dispatch, shellStateBuiltin). The tests are internal/pabcd/shellir/loop_state_test.go, the rows internal/pabcd/hook/testdata/shellir/rows/47-crw-1064.txt, and githubpost_test.go for the GitHub post guard.

- Over-block: a loop whose body called only a harmless function (f() { :; }) or wrapper (command true, builtin true, exec true) made the directory unknown after the loop, so a script file that runs after it (bash prog.sh, bash /dev/fd/0 </dev/null) was refused as resolved from an unknown directory. The reader made the directory unknown after every loop, and every function call and command, builtin and exec counted as a directory change. port: fixed (a call counts as a change only when the program it runs changes the directory or the variables: a function counts when its body does, a command, builtin or exec counts when the program it wraps does, and the directory is made unknown after a loop only when the loop body can change it; pinned by TestLoopKeepsDirectoryForHarmlessCalls and the CRW-1064-01, -02, -04 rows with their controls -11 and -12).
- Missed directory change: zsh chdir is the synonym of cd, which the reader did not treat as a directory change, so chdir sub; bash prog.sh and a loop around chdir were judged in the old directory. port: fixed (chdir is handled as cd, and it is a directory change inside a loop body; pinned by TestLoopMarksDirectoryChangeBehindCallsAsUnknown and the rows CRW-1064-08 and -09).
- Directory changes still reached through a function, a wrapper or a call chain stay unknown after the loop (function f() { cd sub; }, command cd, builtin cd, a function that calls a function that calls cd); port: kept (the same refusal as before, pinned by the rows CRW-1064-05, -06, -07 and -10).
- The GitHub post guard expectation "clean post after a loop closes" pinned the loop-unknown directory for a plain loop body. The case now uses a loop that changes the directory for the body-file refusal at the body file, and a plain loop for the refusal at the command, since the test creates no body file. port: fixed (githubpost_test.go changed in this issue; the verdict of the post is unchanged: refused).
