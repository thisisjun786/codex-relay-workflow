# CRW-932 — the doctor shim answered the start-up handshake before importing the original module

Source: the CRW-854 pre-merge evaluation of thisisjun786/codex-relay-workflow#786 (score 5, P1, the evaluation of dev after the merge). The defect is in the harness, not in the port or the oracle: the shim `internal/dev/cxcfuzz/testdata/doctor/shim.mjs` (its handler, after the input is parsed), the handshake test `TestShimsAnswerTheStartupHandshakeInertly` in `internal/dev/cxcfuzz/target_shims_test.go`, and the module skip `requireOracleModule` in `internal/dev/cxcfuzz/harness_test.go`. The oracle the shim imports is CXC v0.2.40 (commit 3c1459ac) `cxc-ops/dist/doctor.js`, which is unchanged.

- The doctor shim answered a worker's start-up handshake `{"id":N,"input":null,"root":""}` with a report. An empty root skipped `isolate`, and the input was not checked before the import, so the first import of `cxc-ops/dist/doctor.js` read the host's inherited environment rather than the case's homes. The shim now answers `{"id":N,"output":null}` for any input that is not an object (null, a scalar or an array) before `isolate`, the import and the answer. port: fixed (harness defect; pinned by TestShimsAnswerTheStartupHandshakeInertly/doctor, with an empty root, with the root set to an empty directory, and with the original root set to an empty directory (the empty oracle root), where the answer must be null and the working directory and the root must stay empty).
- The handshake test covered only the pyjson, state and goalplan shims, so the doctor shim was not checked. It now covers every target the registry runs through a worker shim, enumerated from the registry, and a shim whose original module is absent is skipped as CRW-708 c9 skips it (`requireOracleModule` names the module of each original-backed shim). port: fixed (harness; test coverage).
- A non-object input is not a case the doctor shim answers: the Go side builds an empty report for such an input, and the shim now answers null. No campaign generates a non-object input for the doctor target (its generator builds report objects), so no divergence is reported for it. port: kept (the handshake is answered inertly, not compared with the port).
- The shims state, goalplan, memorygate, shellwrite and worktreedel import their original module at their top level, before they read a request. With the original root set to an empty directory that import fails (ERR_MODULE_NOT_FOUND) and the handshake gets no answer. Their empty-oracle-root case is skipped in TestShimsAnswerTheStartupHandshakeInertly (startupImportTargets) and their handshake answer is not checked against an empty root. Answering before the import needs a change to each of the five shims, which is outside CRW-932's scope, so the issue's requirement that every original-backed shim answer null with an empty original root is open for the parent. port: pending (open item: the harness cannot show these five import nothing before answering).
- The issue states that the echo, shellwrite, memorygate, worktreedel and spawn shims do nothing on a null input. Their answers to the handshake are their own inert values, not null: memorygate "", shellwrite [], spawn "the input is outside the target's grammar", worktreedel {"decision":"allow","reason":""}. The brief forbids changing other shims' existing answers, so handshakeAnswers pins those values and the strict null expectation for these four is open for the parent. port: kept (the answers are the shims' existing inert contract, pinned by handshakeAnswers; the port has no comparison for a start-up handshake).
