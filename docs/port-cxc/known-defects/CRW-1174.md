# CRW-1174 — one definition of the hook switch file, and an installer that repairs the file it owns

Source: none in CXC v0.2.40: the hook switch (`<CODEX_HOME>/crw/switch.json`) is CRW's own activation gate (CRW-392, see `CRW-392.md`; the writer is CRW-201, see `CRW-201.md`). The Go files are `internal/hookswitch/hookswitch.go` (`State.check`, `Read`), `internal/hookswitch/write.go` (`Parse`, `Marshal`, `KeepAside`) and `internal/runtime/install/configguard/switch.go` (the `state` step of `RunSwitch`); the tests are in `internal/hookswitch/write_test.go` and `internal/runtime/install/configguard/switch_repair_test.go`. Found by the code review of CRW-201 at d4e8128e1.

- `crw install switch` failed before writing when `switch.json` was a dangling link, a FIFO, a directory or over 64 KiB, because the installer read the file with the hook's reader; the user had to delete it by hand; port: fixed (the installer owns the file: one it cannot read, or whose document it refuses, is kept beside it as `switch.json.crw-<ts>.bak` (`hookswitch.KeepAside`: a copy of the link made with `Symlink` for a symbolic link (the platform's `link(2)` may follow a link: Darwin does, so a dangling link would fail and a link to an unusable document would be kept as its target), a hard link for any other entry that is not a directory, so a hook never sees the switch absent while the rename replaces it, and for a directory, which a file cannot replace, a swap in one step (`renameat2` `RENAME_EXCHANGE` on Linux, `renamex_np` `RENAME_SWAP` on Darwin) with a placeholder file that a hook reads as on with a warning, so the path is never empty: a first version moved the directory away and left the switch absent, which a hook reads as off, so every guard behind the switch was silent until the publication (and for good if the process died); a filesystem that cannot swap refuses the repair and leaves the directory, as dev did) and replaced atomically; the notes of the report name the reason and the backup; a step after it that fails restores the entry to the byte or the kind it was, and a backup that cannot be made (the name exists, no hard link) stops the command before the file changes. The hook keeps its reading: unreadable or invalid is on with a warning, CRW-392 and CRW-1142. Pinned by `TestSwitchRepairsASwitchFileItCannotUse`, `TestSwitchRollbackRestoresTheBrokenSwitchFile`, `TestSwitchStopsWhenTheBrokenFileCannotBeKept`, `TestKeepAside*`).
- The installer's `Parse` took a document with a field it does not know (`"extra":1`) and content after the document, and with `active` equal to the target it did not write again, so the stranger's field stayed; the test for it had been deleted; port: fixed (`Parse` decodes with `DisallowUnknownFields` and refuses trailing content, so such a file is replaced at the next switch whatever its `active`. The hook reader stays lenient and ignores an unknown field: `TestHookReadsAnUnknownFieldWhereParseRefusesIt`, `TestParseRefusesWhatItCannotRead`).
- The rule for a valid state lived twice, in the hook's `Read` and in `Valid`/`Parse`; port: fixed (`State.check` is the one rule; `Read`, `Parse` and `Marshal` apply it and carry its text: `TestValidityIsOneRuleForReadParseAndMarshal`).
- `Write` published a state with an empty `changedAt` or `by`, a document without a source that `status` showed without error; port: fixed (`Marshal`, and so `Write`, refuses it; the hook still reads a hand-written document that has only `active`: `TestWriteRefusesAStateWithoutItsProvenance`).
- The package comment said the hook dispatch only reads the file; port: fixed (the comment describes both sides and the difference in strictness).
- `internal/dev/laneparity/switch.go` (`writeSwitch`) has its own writer of the document for the isolated parity harness; port: kept (it writes under a temporary home that no installer reads and the harness checks the bytes it wrote; it is not the installer's writer and is outside this issue).
- `crw install switch status` took the side it reported from the installer's strict `Load`, so a document the installer refuses but the hook reads (an unknown field, with `active` crw) showed neither the CRW hooks nor a live conflict with the CXC plugin; port: fixed (`ReadAt`, the hook's own reading, decides the selected side; the strict refusal is still reported in `switchFile.error` with a note: `TestInstallSwitchStatusFollowsTheHooksReadingOfADocumentTheInstallerRefuses`).
- The restore of an entry set aside (`Aside.Restore`, the undo of a repaired switch) and `Remove` (the undo of a first publication) renamed or removed without syncing the switch directory, so a power loss could bring back the selection a refused command had undone, where the dev undo went through `WriteRaw`; port: fixed (both sync the directory after the change and return `ErrNotDurable` when that fails, like `WriteRaw`; the restore of a directory swaps it back, so the path is not empty then either, and a backup name that cannot be removed after that swap does not skip the sync: the directory is synced first and both errors are returned, joined: `TestKeepAsideOfADirectoryNeverLeavesTheSwitchAbsent`, `TestKeepAsideOfADirectoryRefusesWhereTheSwapIsUnsupported`, `TestRestoreSyncsTheSwitchDirectoryAndReportsAFailure`, `TestRestoreOfADirectorySyncsWhenTheBackupCannotBeRemoved`, `TestRemoveSyncsTheSwitchDirectory`).
