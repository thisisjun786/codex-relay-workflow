# CRW-1180 — SessionStart output stacked twice by a resume→compact pair, and a dispatch card cell that pins an unusable model

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/cxc-ops/src/map-affordance.ts` (`runMapAffordanceSessionStart`), `plugins/codexclaw/components/subagent-config/src/fallback-dispatch-cli.ts:11-35` and `dispatch-card.ts:36-47`, the provider bridge hook and `plugins/codexclaw/components/config-guard/src/cli.ts:167-196`. The Go files are `internal/affordance/hook.go`, `internal/role/fallback_notice.go` and `dispatch_card.go`, `internal/provider/cli.go`, `internal/runtime/install/configguard/selfheal_report.go` and `internal/guidancerecord`. Found by the isolated real-use trial r2 (S4-F4b, S5-R2-F2).

- A resumed session whose first turn compacts runs SessionStart with `source` `resume`, then the compaction, then SessionStart with `source` `compact`. Codex keeps both outputs after the compaction record (about 7 KB in the trial's rollout), so the binding rule, the pointer list, the provider JSON, the flag warning and the dispatch card are in the context twice, because the oracle prints them for every source (`map-affordance.ts`, `fallback-dispatch-cli.ts`, `config-guard/src/cli.ts:167-196`); port: fixed (CRW-1146 already keeps a resume from repeating what the session was given, by the record of `internal/guidancerecord`. A resume that gives the whole text of a leg now also leaves a mark beside that leg's record (`<leg>.resume`, 0600, empty), and the first compact start that would say exactly the text the record names, within `guidancerecord.PairWindow` (15 minutes) of the mark and for the same session and leg, takes the mark and says nothing. The next compact, a compact with other text (the role store, `CRW_SPAWN_V1`, the catalog, the command the pointers name, the provider line or the flag state changed between the two), a compact of another session or without a usable session id, and a compact after a start, clear or any other whole output (which removes the mark) say the whole text as before, so a compaction of its own never loses the guidance. A resume that gave only the binding (the session was given the pointers before) leaves no mark and clears one, because the context it resumed holds the pointers only from before. The map-affordance leg and the subagent fallback leg use the record they already keep; the provider line and the self-heal flag warning, whose text is live state and which kept no record, say the line on every resume and record it only on a resume (a start writes nothing: it only removes a mark that is there), under the legs `provider-bridge` and `self-heal-report`; a record is written only after the hook wrote the whole answer, never after a failed or short write and never by a cancelled hook. The window is the only evidence of "the same turn" the hooks have: the SessionStart payload carries no turn id, so a compact within 15 minutes of a whole resume that was no pair would be silenced once while the context still holds the resume's output after the compaction, as the pair does. Pinned by TestCompactAfterAResumeRepeatsOnlyOncePerResume, TestCompactLongAfterTheResumeIsNotThePair, TestSessionStartCompactRightAfterAWholeResumeIsSilentOnce, TestFallbackNoticeHookCompactAfterAWholeResumeAnswerIsSilentOnce, TestHookCompactRightAfterAResumeDoesNotRepeatTheLine and TestSelfHealReportCompactRightAfterAResumeDoesNotRepeatTheWarning (red on 28a99e86c). The self-heal hook writes nothing at a start, as CRW-1150 pinned; on a resume it now writes the record under `<CODEX_HOME>/crw/session-guidance`, never a file of the config or the self-heal marker).
- The dispatch card's first cell (the Code Mode cell in the unresolved card and the `spawn_agent` call in the V1 card) pins `model:"command-code/deepseek-deepseek-v4.1-flash"` whatever the local catalog lists, and the parent runs the cell as printed: in one of seven trial sessions the host answered "Unknown model" and the turn was lost (`dispatch-card.ts:36-47`); port: fixed (`RenderDispatchCard` names in the cell the first alias, in the order deepseek, swe2, kimi, sol, luna, that the local Codex catalog lists and does not hide, which is the card's own "verified in local catalog" test. When none is listed the cell has no `model` key, so the role default applies, and one line says so ("No alias is verified locally: the cell sets no model (role default)."), which keeps the card inside its 1200 UTF-16 units with all five alias lines. A catalog that lists the deepseek alias renders the oracle's card unchanged. The four recorded cxc cases of the subagent fallback leg whose catalog lists no deepseek alias (baseline_empty_workspace, fallback_configured_protocol_precedes_card, spawn_v1_card; aliases_verified_in_local_catalog now names `devin/swe-2`) are claimed as intentionally changed in `contract/notes/cxc/CRW-1180.json`, moved out of `CRW-1146.json` because two claims cannot coexist; the record digest they expect is the SHA-256 of the new answer. Pinned by TestDispatchCardFirstCellNeverPinsAModelTheCatalogDoesNotList and the recorded goldens `card-missing*.golden`, `notices.json`).
