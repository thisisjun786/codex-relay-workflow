# CRW-744 — evidence resolve after a published state write

Source: the state writer is `plugins/codexclaw/components/pabcd-state/src/state.ts` `writeState` at CXC v0.2.40 (commit 3c1459ac): it writes a temp file, publishes it with a rename, and returns whatever the publication threw. The resolve path is `plugins/codexclaw/components/pabcd-cli/src/evidence-cli.ts` `runEvidenceCli`. The Go port is `internal/pabcd/state/write.go` (`writeState`) and `internal/pabcd/cli/evidence.go` (`RunEvidenceCLI`), with the callers listed below. The oracle never syncs the published file or its directory (`known-defects.md`, "Found by CRW-479 state publication durability"), so it cannot fail after the rename; CRW-479 added the directory fsync to the Go port, which is what makes a post-rename failure reachable and these callers observable. The oracle's own callers skip the same reconciling step, so the shape is faithful; the divergence the fix closes is that a published state used to be reported as a plain failure.

- Other `state.WriteState` callers that skip a reconciling step when the write reports a post-rename failure (`state.Published(err)` true). They were not changed by this issue, which fixes only `RunEvidenceCLI`; each would need the same published/warning split. The oracle's counterparts read the same way, so this is not a parity break (oracle `pabcd-state/src/state.ts` `writeState`; Go callers named below); port: pending.
  - `internal/pabcd/evidence/tombstone.go:94` and `:108` (`RecordTombstone`): a published-but-failed commit write is read as a failed commit, so the sentinel tier writes the state again and stamps `unverifiedCorrupt` on a healthy session whose tombstone was already published. The most consequential of the set.
  - `internal/pabcd/evidence/budget.go:93` (`ResolveTombstone`): reports `false` though the tombstone removal was published.
  - `internal/pabcd/cli/memory.go:89` (`RunMemoryCLI`): reports "could not record the grant" though the grant was published.
  - `internal/pabcd/cli/scan_record.go:103` (scan record): reports "scan record failed" though the round was published.
  - `internal/pabcd/hook/memorygate.go:124` (`memoryGateConsume`): denies the write though the grant was consumed. Fail-closed, so the direction is safe, but the deny note is then wrong.
  - `internal/pabcd/hook/session_hooks.go:84` and `internal/pabcd/hook/idleedit.go:91`: the error is discarded (`_ = lock(...)`), so they have no reconciling step to skip.
