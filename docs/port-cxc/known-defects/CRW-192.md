- handleStop writes the counter with writeState from an unlocked readState: an update a participating writer (the memory gate, the idle-edit
  counter, PostCompact, the turn stamp) lands between the read and the write is overwritten and lost, and the write-back rebuilds the state
  from the reader's normalised value, so a stored record the reader cannot keep (a tracker or an unverified-subagent list past its cap) is
  lost with it (hook.ts:1497-1521); port: fixed (data loss). The counter is read, judged and written inside the session lock on the state the
  lock found, and a state file the reader would not keep whole is not rewritten (the judgement PostCompact and the turn stamp use). A block the
  counter could not record (a lock that cannot be taken, a lossy file, a failed write) is never answered: the Stop releases, as the oracle's
  throwing writeState did. Pinned by TestStopKeepsAParticipatingWritersUpdate and TestStopNeverBlocksWithoutRecordingTheCounter.
- The oracle judges the phase, the cycle and the binding on one read and blocks on it; with the counter written under a lock the state can have
  moved in between (a transition, a D-close). A Stop whose phase, orchestrationActive or slug differ from the state the lock found is stale and
  releases, so a block never names a phase the session has left and the counter is never charged to the wrong phase; port: fixed (no duplicate
  transition: Stop itself moves nothing, TestStopNeverTransitionsTheCycle).
- With a cycle in flight under an active goal, the oracle blocks up to three times at a phase even when the bound plan's remaining work waits only
  on open decisions (a question the user has to answer); only the IDLE path asks remainingWorkAwaitsDecisions (hook.ts:1814). CRW-192 criterion 2 puts
  an approval wait before the continuation, so the in-flight path asks it too and releases without spending the budget; port: fixed (CRW
  customisation, TestStopReleasesWhileTheRemainingWorkAwaitsADecision).
- buildStopBlock inserts the session id with String.replace and a replacement string built from it, so a session id holding `$&` or `$1` is
  expanded as a replacement pattern (hook.ts:1590-1594); the id is inserted as text; port: fixed.
- buildStopBlock appends a friction advisory line from peakFrictionVerdict (.codexclaw/friction.jsonl, hook.ts:1862, 1604-1610). The ledger is
  written only by handleBashFrictionCapture, whose registrations (hooks/_deprecated/post-tool-use-capturing-shell-friction.json) are deprecated and
  absent from the manifest, and state-migration.md lists friction.jsonl as skipped with no Go store reader; no CRW store feeds the line, so it
  is not ported; port: kept (dormant, decision 9).
- After a per-phase release the counter is reset (stopBlockPhase null, count 0) and the next Stop at the same phase counts as progress, so the
  per-phase budget recharges and only the turn's total (24, reset by the UserPromptSubmit turn stamp) ends a chain; the total keeps advancing on
  every Stop after the cap and the systemMessage is announced once (stopBlockCapNotified). A release ends the host's turn, so the recharge
  starts a later turn's chain; port: kept (the oracle's bounded design, TestStopStallReleasesAfterThreeBlocksPerPhase,
  TestStopTotalCapEndsTheLoopAndIsAnnouncedOnce and the harness TestStopLegRepeatedEventIsBounded pin the bound).
- getGoalActiveStatus reads a goals database that cannot answer as unreadable, and handleStop treats only "active" as active, so an unreadable,
  missing or paused/budget-limited/complete goal releases and an unknown status is never read as active or as complete (the oracle; the
  interview firewall in the other hooks fails closed the other way); port: kept (corpus fixture unreadable_goal_db_releases,
  TestStopReleasesForAGoalTheUserOrTheHostStopped).
- Texts follow name-substitution.json: `cxc orchestrate` is `crw pabcd orchestrate`, `cxc loop init` is `crw pabcd loop init`, the receipt marker
  names `crw pabcd receipt test`, the state directory is `.crw`, the skill is `$crw-loop`, the cap message is "CRW Stop continuation cap (24)
  ..." (R25), and the backticked command is resolved to the crw invocation at emission (ResolveCRWInDirective), never in a constant.
- The render advisory of an interactive session is answered as the Stop hookSpecificOutput additionalContext by harness.ContextOutput ("Stop"), as
  buildContextOutput does; in a goal session it is appended to the block reason. The oracle's JSON re-parse of the block (hook.ts:1865-1872) is
  replaced by building the reason once; the bytes are the same.
