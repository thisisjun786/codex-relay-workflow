- handleStop writes the counter with writeState from an unlocked readState: an update a participating writer (the memory gate, the idle-edit
  counter, PostCompact, the turn stamp) lands between the read and the write is overwritten and lost, and the write-back rebuilds the state
  from the reader's normalised value, so a stored record the reader cannot keep (a tracker or an unverified-subagent list past its cap) is
  lost with it (hook.ts:1497-1521); port: fixed (data loss). The counter is read, judged and written inside the session lock on the state the
  lock found, and a state file the reader would not keep whole is not rewritten (the judgement PostCompact and the turn stamp use). A block the
  counter could not record (a lock that cannot be taken, a lossy file, a failed write) is never answered: the Stop releases, as the oracle's
  throwing writeState did. Pinned by TestStopKeepsAParticipatingWritersUpdate and TestStopNeverBlocksWithoutRecordingTheCounter.
- The oracle judges the phase, the cycle and the binding on one read and blocks on it; with the counter written under a lock the state can have
  moved in between (a transition, a D-close). A Stop whose phase, orchestrationActive or slug differ from the state the lock found is stale and
  releases, so a block never names a phase the session has left and the counter is never charged to the wrong phase; port: fixed (no duplicate
  transition: Stop itself moves nothing, TestStopNeverTransitionsTheCycle).
- Verification round 1 found the same window open for what the user can change while Stop waits for the lock: a pause of the goal, a decision that
  now awaits an answer, a bound plan that no longer reads (IDLE path) and a new user turn stamped by UserPromptSubmit (which resets the turn's
  total) were all judged only before the lock, so the stale event still spent the counter and answered a block (once with "Waiting on: ... awaits
  decision" in the text). Inside the lock the Stop now judges again that the goal is ACTIVE, that the bound goalplan does not wait on an open
  decision (IDLE: and still reads), and that the event belongs to the stamped turn: the turn stamp joins the stale-binding comparison, and the
  Stop payload's turn_id (StopPayload.TurnID, parsed by harness) is held against the stamp when both are present (an unstamped state, or a
  payload without turn_id, keeps the loop); any miss releases without writing; port: fixed (AC2 user stop and approval wait, AC5 stale events;
  TestStopReleasesWhenTheWorldMovedBeforeTheLock, TestStopReleasesAnEventOfAnEarlierTurn, harness TestStopLegReleasesAnEventOfAnEarlierTurn; red
  output /state/crw/crw-192/evidence/red-round1.log). The transcript tail is a file already written when the Stop starts, so it is not judged again.
