# CRW-786 — cli session rewrite guard and stored interview records

Source: the oracle CXC v0.2.40 (commit 3c1459ac) has no interview guard on any cli session writer: `orchestrate-cli.ts`
(:549-1131), `memory-cli.ts`, `evidence-cli.ts` and `scan-cli.ts` (:211-417) all publish the state the reader rebuilt. In the
port the loss is visible in `internal/pabcd/state/restore.go` (`ReconstructInterview`, :54) against
`internal/pabcd/interview/reconstruct.go` (`tail`, :10-16, and `cleanOntology`, :175-197), and the writers are
`internal/pabcd/cli/memory.go`, `evidence.go`, `scan_record.go` and `orchestrate_transition.go`. The hook already refuses the
same loss through `internal/pabcd/hook/session_hooks.go` `sessionHookStateRewritable`, now `state.RewriteKeepsInterview`.

## Defects

- The oracle has no guard against publishing a session rewrite that drops stored interview records: `ReconstructInterview`
  caps `contradictions` and `assumptions` at `interview.MaxTrackerArray` (drop-oldest) and `cleanOntology` drops an ontology
  entity with no name and a relationship with no target, so a rewrite that passes the cli guard `cliVerdictsIntact`
  (`internal/pabcd/cli/memory.go`) loses those records permanently. The cli writers named above had no interview check at all
  (`internal/pabcd/cli/memory.go`, `evidence.go`, `scan_record.go`, `orchestrate_transition.go`
  `orchestrateTransitionStateWritable`); port: fixed (this issue adds `state.RewriteKeepsInterview` and `cliInterviewIntact` and
  checks it in all four writers, a data-loss defect the parity rule revision of 2026-10-03 fixes during the port).
- `state.RewriteKeepsInterview` originally kept the hook's inherited reading of the raw document: a duplicate top-level
  `interview` key resolved to its first occurrence, where `state.decodeObject` keeps the last, and the helper did not require
  end of input after the top-level object where `decodeObject` does. A crafted duplicate-key document could therefore
  under-detect and let a rewrite truncate the tracker the reader actually rebuilt. The hook carried the same reading before the
  move; port: fixed (the shared guard now reads the document exactly as `state.decodeObject` does, so a repeated key keeps its
  last value and trailing content is refused, and the hook gets the same correction by delegation;
  `TestRewriteKeepsInterviewReadsTheDocumentAsTheReaderDoes` and
  `TestCLIRefusesARewriteWhenADuplicateInterviewKeyHoldsTheLoss` pin it).
- `memoryGateRewritable` (`internal/pabcd/hook/memorygate.go`) and `rewriteGuardLossy` (`internal/pabcd/hook/idleedit.go`)
  republish a rebuilt session state after checking only `state.RewriteKeepsUnverified`, so a stored interview tracker longer
  than the reader keeps is still lost by those two hook writers. Same defect class as the item above, outside this issue's
  fixed four-writer answer; port: pending (needs its own issue; `internal/pabcd/hook/prompt_submit.go` already covers the
  interview through `sessionHookStateRewritable`).
