# CRW-1199 — the flow journal in the store, the working snapshot and the effect proofs: what the decided design left to the code

Source: CRW's own design (0.5.0-alpha, issue F06), not the CXC oracle: the flow engine has no counterpart in CXC v0.2.40 (commit 3c1459ac). The Go side is `internal/flow/journal/{journal,recoverenv}.go` (the journal over `flow_runs`, `flow_calls` and `flow_events`, and the store and host the recover command opens), `internal/flow/ops/{gitsnap,proofs}.go` (the snapshot, the commit, the scope record, the proofs), `internal/flow/engine/{call,journal,resume,recovercli}.go` (the pending tree, the stored-row failure, the restored CallResult). `docs/flow/journal.md` describes it.

- The body's edit regions do not list `cmd/crw/main.go`, `internal/flow/backend/agent/{agent,git}.go`, `docs/flow/script.md` and `internal/flow/backend/agent/reconcile_test.go`; each is needed and kept small: `main.go` installs `engine.RecoverEnv` (the engine names no store and no network client), `agent.go` adds `NewHost` (a backend that only reads the host, for the recover command) and `git.go` makes `Allocator.Snapshot` call `ops.Snapshot`, so the pending tree a call records and the snapshot a proof compares it with come from one function; port: deviation, kept visible.
- `ops.Snapshot` is the body's `read-tree HEAD`, `add -A -- .`, `write-tree` in a private index, with `--sparse` on the `add` (a sparse checkout makes `git add` refuse its pathspec otherwise) and the skip-worktree entries of the real index whose file is absent marked in the private index before it, so a sparse entry is held and is not a deletion. This replaces the F04 snapshot, which started its private index from a copy of the real index and cleared the assume-unchanged and skip-worktree flags; the two agree on every worktree an executor leaves (nothing staged), and differ only for an entry that is staged, absent from HEAD and ignored, which the old one kept and the new one drops (an ignored file is outside the snapshot); `TestSnapshotKeepsSparseEntriesAbsentFromTheWorktree` and the other snapshot tests of `internal/flow/backend/agent` still pass unchanged; port: deviation, kept visible.
- The journal keeps the engine's run-wide `Seq` as the `event_seq` of a `flow_calls` row and the `seq` of a `flow_events` row, instead of numbering rows per call: the numbers the engine reads back after a restart are the ones it wrote, and the keys stay unique; the `kind` column holds the call's op, `result_artifact` is not used (a result is kept whole in `result_bytes`), and a row's Data is stored in the form the store returns (the JSON round trip, an empty Data as none) so a row reads the same live and after a restart. The members of a row that have no column of their own (the label, a flow row's kind, path, position and op) are reserved members of its JSON that start with an underscore; port: kept.
- The rows that are not dispatch intents wait in memory for the next intent, the end of a call, `started`, `finished` or `Flush`, and are then written in one transaction; the body says "batch transaction" and does not say when the batch ends. A crash loses the result rows after the last intent, which is what the intents are for (the reconcile pass finds a thread or a turn on the host from its intent); port: kept.
- A journal that cannot store a row is a `FailingJournal`: the engine checks it after every call row, ends the run with the error (`errorKind` `engine`) and sends no thread, fork or turn whose intent row could not be stored; the call then writes no terminal row (nothing can be stored) and its CallResult is `superseded`/`cancelled`. The body does not name this path; port: deviation, kept visible.
- Every terminal row now carries the `tokens` the call used and `repair_used` when it repaired (it used to be the completed row's alone), so that the CallResult of a held call is restored from its rows with the tokens it reported live; a completed executor call's row carries `pending_tree` and a held one's `p_held` (it already did). A backend without a placer, and a call of another family, record neither; port: kept.
- The rows the proofs read for verify, review, accept, integrate, gate, reviewer-final and the commit (`crw.verify`, `crw.review`, `crw.accept`, `crw.integrate`, `crw.gate`, `crw.reviewerFinal`, `crw.commit` and their members) are named in `internal/flow/ops/proofs.go`: the calls that write them are F08's, and this issue defines the functions and the row shape they judge, so the tests write the rows the way those calls will. The acceptance of an agent node reads `flow_calls` columns of the reviewer rows (`role`, `plan_id`, `node_id`, `execution_id`, `commit_sha`, `thread_id`, `turn_id`, `result_bytes`, and `criteria_digest` in `detail_json`) and the journal fills them from the `prepared` row of the call (`TestStoredRowsCarryTheColumnsTheRelayReads`); the `criteria_digest` and `execution_id` members are the call options F08 adds; port: pending (F08).
- The proof of a node's calls covers the calls of the node's current attempt (the node's last `prepared` row with a fresh or restore allocation, and the calls that run in that directory); a call of a retired attempt is never proven and its directory is never read (`TestRetiredAttemptWorktreeNotProven` records the directories git ran in). A `HEAD` that moved back before a recorded commit is a foreign commit like one that moved on. A snapshot that equals the pending tree of an earlier call and not the latest leaves the later calls unproven (their edits are gone); one that equals none breaks the proof from the latest call only, as the body says; port: kept.
- `crw flow run` still runs the fake backend on an in-memory journal; the persisted journal is reached through `journal.Open` (the run process of an App Server backend, F07 and the install), not through a flag of the fake run. `engine.Run` over a stored journal is proven by `TestPersistedJournalMatchesMemoryJournal`, `TestReplayRestoresCallResult` and the intent tests; port: pending (the run command of the App Server backend).
- A resume still replays only the calls the journal ended `completed`, `null_model`, `refused` or `outcome_unknown` (CRW-1198); a held call is restored by `journal.ReadCallResult` (`TestReplayRestoresHeldCallResult`) and replayed by the F07 rule, which this issue does not decide; port: kept.
- Supersedes CRW-1198.md, item beginning "`crw flow recover` exists in `engine.RunCLI`": now port: fixed (the binary installs `engine.RecoverEnv` with the stored journal and the App Server connection; CRW-1268.md).
- Correction round after the pre-merge evaluation of 036890ce (five findings; the flow engine has no CXC counterpart, so these are CRW defects of this change, port: fixed): (1) a recorded commit proved every call that preceded it by sequence; it now covers the calls up to the one whose pending tree it committed (`TestCommitOfAnEarlierTreeDoesNotCoverALaterCall`); (2) `RestoreCallResult` kept the terminal row of an earlier attempt when a later `prepared`, intent, started or `recovery_cleared` row reopened the call, and returned it with the new attempt's thread and `StartSeq > EndSeq`; a reopened call has no result (`TestReplayRestoresNothingFromAReopenedCall`, `TestStoredReaderIgnoresATerminalRowOfAnEarlierAttempt`); (3) `Run` checked the journal's error before its own `finished` write and not after; it checks again (`TestRunEndsWithTheErrorOfItsFinalWrite`); (4) `crw.tierStep` took the completed agent call at the same positional call id for its own record and wrote no row; the record must be of the operation (`TestTierStepIsRecordedWhereAnAgentCallCompleted`); (5) a completed executor turn whose snapshot failed ended `completed` with only a `pending_tree_error` in the journal; it is held for `worktree_failed` (reason set unchanged) and the row carries the error (`TestExecutorWhosePendingTreeCannotBeCapturedIsHeld`).
