# CRW-1313 — one thread title table, and the creator names each thread right after creation

Source: the 10-13 trial (a management thread with no name showed its first prompt sentence as its title in Jun's Codex app) and the CRW-1315 split (items 14 and 36a), not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no session layers and no relay. The table is `plugins/crw/skills/crw-canon/references/hierarchy.md` ("Thread titles"); the code is `internal/bridge/thread_title.go`, `internal/bridge/create.go` (`create_thread`) and `internal/bridge/worktree.go` (`create_worktree_thread`).

- No document gave the repository session (the old management session) a title, nobody was said to name a thread or when, and the title rules of the project session (crw-plan's app presentation) and the issue child (task-packet's Child task titles) were kept apart; port: fixed (hierarchy.md has the one table: 총괄 has no rule, CRW does not create it; 부모, the repository session, is `[CRW] 부모 · <owner>/<repo>`; 자식, the project session, keeps crw-plan's rule; an issue child keeps `ISSUE-ID · <title>`; subagents have no title; integrations.md, task-packet.md and crw-run's bridge reference link it, and no other document spells the repository session's title). Pinned by `TestThreadTitlesAreOneTable`.
- `create_thread` named a thread only when its caller passed a title, so a repository session created without one kept no name and the app showed its first prompt sentence; port: fixed (the creator names the thread with `thread/name/set` right after `thread/start` and before the first turn: the given title, or for role `supervisor` without one the table's title from the checkout's `origin`, read from an https, ssh or git URL or the scp form `[user@]host:owner/repo`, where an origin that names no repository, a local path, a file URL or an scp form whose host is not a host name (a space, a path separator, an empty host or user before the colon), gives no title and the warning `title_unset`; the managed start already sends an issue child's title with its issue key, and the project session's title is its caller's by crw-plan's rule). Pinned by `TestCreatorsNameTheThreadByTheTitleTable` (a fake host keeps the names and `thread/read` gives them back, for the repository session from an https and an scp origin, the project session and the issue child) and `TestRepositorySessionTitle` with `TestAnScpOriginWithABadHostNamesNoRepository`, and for `create_worktree_thread` by `TestWorktreeCreatorNamesTheThreadByTheTitleTable` (the repository session from the origin its worktree shares with the source, the project session and the issue child).
- A host that refused `thread/name/set` failed the whole creation before its first turn; port: fixed (decided default: a naming failure warns and records and never refuses: the receipt carries `titleWarning`, `title_not_set` for a refused name and `title_unset` when a repository session's checkout has no usable origin or a project session or an issue child comes without a title, the bridge writes it to standard error, and the first turn starts). A lost answer to `thread/name/set` stays the creation's unknown outcome, which the replay of the request settles, and the managed start's rename after a standby recovery keeps that rule (`TestReconcileNameFailureIsRetriedWithoutResending`). A creation with no role and no title is as it was. Pinned by `TestANamingFailureWarnsAndRecordsAndNeverRefuses` and, for `create_worktree_thread`, `TestAWorktreeNamingFailureWarnsAndRecordsAndNeverRefuses` (a refused name, a repository session without an origin, a project session and an issue child without a title); `Test_test_partial_failure_retains_created_id` keeps its point, the created id retained after a partial failure, with the failure moved to a refused first turn, since a refused name is no longer one.
- `create_thread` saves its receipt right before `turn/start`, and a process killed after `turn/start` leaves that save and no `attemptedEffects`; the managed start's reconciliation read that save only by its `title`, so a creation whose name the host refused, or that had no title to give, saved `titleWarning` instead, and its reconciliation sent the standby again to the thread or abandoned an unreadable one (I-473); port: fixed (decided default: the save before the first turn is recognised whatever the naming outcome: `savedBeforeFirstTurn` in `internal/relay/managed/reconcile.go` reads `title` or `titleWarning` on a receipt without `attemptedEffects`, and both `observe` and `creationMayHaveTurn` read it, so the creation stops at `standby_turn_unknown`; `docs/relay/dag-scheduler.md` names the warning beside the title). `create_worktree_thread` marks its save before the first turn whatever the naming (`phase` `dispatching_initial_prompt`, `initialPrompt` `outcome_unknown`), and no reconciliation reads its receipts; the worktree naming tests read that row at the moment `turn/start` reaches the host. Pinned by `TestReconcileReadsTheSaveBeforeTheFirstTurnWhateverTheName` (a real bridge's ledger row at the moment `turn/start` reaches the host, for a refused name, no title and a set name, reconciled with the thread readable and unreadable).
- Named limit: whether the Codex app's list shows a thread's `name` or its `preview` (CRW-1315 item 36a) is a host behaviour this change cannot see from the App Server; the name is set, and the trial reads the list.
