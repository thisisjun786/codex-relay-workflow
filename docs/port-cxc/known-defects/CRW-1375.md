# CRW-1375 — the bg store refuses a link anywhere in .crw/bg, and the shell's targets are created before it runs

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/bg-wake/src/store.ts:30-58` and `:80-87` (ensureDir, atomicWrite, appendLedger), `:111-117` (removePath) and `spawn.ts:91` and `:108-114` (buildShell, the clearing of `<id>.out` and `<id>.exit` before the start). The Go files are `internal/relay/job/store.go` (EnsureDir, confined, atomicWrite, appendLedger), `internal/relay/job/lock.go` (lockStore) and `internal/relay/job/spawn.go` (buildShell, createShellTarget, runBackground), on the shared checks of `internal/pabcd/crwdir` (EnsureSubdir, CheckTree, NotLink, OpenFile). The tests are in `internal/relay/job/link_refuse_test.go`; the red run against the code before the change is `/state/crw/crw-lane-safety-followups-1375/evidence/1375-d1-red.log`. The rule is CRW-475's: a symbolic link, dangling or not, where a directory or a file of the `.crw` tree belongs is an input error that names the link and says `symbolic link` (wrapping `crwdir.ErrLink`); nothing is written, created or removed through it and the link is left as it is.

- Supersedes known-defects.md, section "Found by the bg store port", item beginning "The path builders take any id": now port: fixed for links on writes (security: a link at `.crw` or at `.crw/bg` is refused by `EnsureDir`, `AtomicWrite`, `RemovePath`, the ledger append, the store lock and so by the spawn, the verbs and the hooks, whether it leads inside the workspace, outside it or nowhere, instead of being judged on its real path; `AtomicWrite` refuses a link at the file it publishes instead of replacing it, and the ledger's link is refused naming it). A path that is not a file directly inside `.crw/bg` is still `ErrOutsideStore`; reads still follow links, as the item says. Pinned by `TestTheBgWritersRefuseALinkAtTheBgDirectory`, `TestTheBgWritersRefuseALinkAtTheirFile` and `TestTheBgCLIRefusesALinkedBgDirectory`; `TestAtomicWriteFollowsAStoreLinkedInsideTheWorkspace` (`store_test.go`) is now `TestAtomicWriteRefusesAStoreLinkedInsideTheWorkspace`, and `TestAStoreThatLeavesTheWorkspaceIsRefused` takes the link refusal for both links.

Stale entries at the three names, links included, are still removed before the start as CRW-1134 made it.
