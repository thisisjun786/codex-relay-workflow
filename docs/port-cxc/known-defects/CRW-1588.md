# CRW-1588 — an empty or dangling .git is not a repository

The CXC managed-worktree detector confirms a checkout when it finds any `.git`
entry between the cwd and the managed slot root. An empty directory or a gitfile
pointing at a missing directory therefore confirms a checkout that Git cannot
read (the four `hook__session-start-detecting-managed-worktree__` cases
`extra_root_env_is_honored`, `managed_cwd_injects_identity`,
`pabcd_off_still_injects_subagent_silent` and `symlinked_cwd_resolves_into_slot`
use `/fake` gitdir targets); port: fixed in CRW-1588.

`internal/gitprobe` now owns the marker test and ancestor walk. A marker must
resolve to a directory with a regular HEAD and an objects directory, including a
linked worktree's commondir. Empty or malformed markers are ignored. The hook
keeps its managed-slot boundary and confirms only a valid checkout; the CI
TMPDIR preflight and other repository predicates use the same rule.

The recorded v0.2.40 fixtures remain unchanged. Their four claims move from
CRW-198's `identical` list to `contract/notes/cxc/CRW-1588.json`, whose `given`
overrides replace the dangling gitfiles with metadata under the case's TMPDIR.
The expected setup tree names those replacement files and added directories;
every recorded hook answer, call and other tree entry is still compared. This
keeps the existing positive identity, custom-root, symlink and subagent cases.
`TestResolveGitDir`, `TestRepositoryAbove`, `TestLooksLikeRepoRequiresARepository`
and `TestDetectManagedWorktree` cover markers that must no longer confirm a
repository, while `TestRepositoryAboveRealGitLayouts` holds actual Git layouts.
