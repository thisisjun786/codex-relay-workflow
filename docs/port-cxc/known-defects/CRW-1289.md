# CRW-1289 — fixtures that report through the relay daemon

Source: CRW's own design (CRW-1286: the relay daemon alone decides where a child's report is recorded), not the
CXC oracle. The recorded answers are the Python relay's (`contract/fixtures`, the delivery and cli goldens). The Go
side is `internal/relay/hook/control_child.go` (`ForwardChild`, `handleChildCommand`), `internal/relay/dispatch`,
`cmd/crw/child_owner_probe.go` and `internal/testsupport/childowner.go`.

- A child command crosses the daemon byte for byte: its arguments travel as base64, so an argument that is not UTF-8
  arrives as it was given, and the daemon answers the command's exit code with its stdout and stderr bytes, which the
  child writes as they are; port: fixed.
- A fixture's child command (`emit`, `intent-claim`, `intent-disposition`) reports through a relay daemon stand-in of
  its state (`testsupport.ChildOwner`: a crw built with `-tags childownerprobe`, the child's own working directory and
  environment, the program's composition). It runs the command on that state as the daemon does and answers what the
  built CLI answered when the child ran it itself. It skips the daemon handler's admission checks (borrowed store,
  caller-relative paths, the intent's store), which `TestChildReportStateLocationIsTheDaemons`,
  `TestAChildStateSelectionCannotRedirectTheDaemonsRecord` and `TestTheDaemonRefusesACallerRelativePath` pin on the
  real handler. A state that is not a directory the stand-in can read has no daemon; port: kept.
- `cli-shape/test_dispositions__test_a_blocked_child_is_enumerable_by_project`: the Python relay's `emit` wrote the
  store with no daemon; the port's `emit` exits 3 when no daemon serves the state, so the replay's `emit` step reports
  through the stand-in. The checks are the recorded ones; port: kept (deviation).
- `cli-shape/test_dispositions__test_a_child_with_no_work_report_says_the_separation_is_unavailable`: the same `emit`
  step, the same deviation; port: kept (deviation).
- `cli-shape/test_dispositions__test_a_staged_claim_is_recorded_progress_and_never_delivery`: the same; port: kept
  (deviation).
- `cli-shape/test_dispositions__test_an_event_in_an_earlier_generation_is_counted_not_listed`: the same; port: kept
  (deviation).
- `cli-shape/test_dispositions__test_an_unscoped_assignment_is_absent_by_project_and_present_by_relationship`: the
  same; port: kept (deviation).
- `cli-shape/test_dispositions__test_the_command_reads_a_blocked_child_through_a_subprocess`: the same; port: kept
  (deviation).
- `cli-shape/test_dispositions__test_the_project_selector_hides_what_is_not_live_and_the_relationship_selector_does_not`:
  the same; port: kept (deviation).
- `cli-shape/test_dispositions__test_the_three_statuses_that_share_one_outcome_stay_separable`: the same; port: kept
  (deviation).
- `mcp-tools/test_mcp__test_the_plugin_launched_bridge_reports_the_host_policy_and_checks_the_role`: the Python bridge
  created the `right-child` relay child with the default `read-only` sandbox; the port refuses a read-only relay child
  (CRW-1286), so the case creates it with `danger-full-access`. Its checks are the recorded ones; port: kept
  (deviation).
- `TestCLI_marker_preflight_answers_what_python_answers`, `claim/intent-store-state-unreadable` and
  `disposition/intent-store-state-unreadable`: Python answered the store's refusal (exit 2; the disposition published
  its marker fact first). A child cannot reach a daemon in a state directory it cannot search, so the port answers
  exit 3, `relay daemon unavailable; child report was not submitted: permission denied`, and publishes nothing; the
  two goldens hold that answer; port: kept (deviation).
