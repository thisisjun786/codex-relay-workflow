# CRW-1128 — recall memory search, stage1, trim, ranking and memory status residue

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/recall/src/`: `memory-status.ts`, `memory-search.ts` and `index-search.ts`. The Go side is `internal/recall/memorystatus.go`, `memoryrank.go`, `memorytrim.go`, `memorysearch.go`, `memorystage1.go`, `indexsearch.go` and `indexquery.go` (`wordSpellings`). The items are the 10-10 CXC improvement review's fix-now list for the memory lines of known-defects.md (A8 kept); each was reproduced before it was changed (the red output is in the lane's evidence directory, `red-1128.txt`). The cases of the recorded oracle grids whose answer the port changed are listed in `testdata/<suite>/port-fixed.json` (suites `memorysearch`, `memorystage1`, `memoryrank`, `memorystatus`, `indexsearch`), read by the replay in place of the recorded answer; the ranking grid (`TestRankAndTrimNodeOracle`) keeps the oracle's comparator as `oracleRankAndTrim` in the test and checks the repaired ranking against the recording where the oracle's order is consistent. The recorded CLI fixtures `cli__memory__search_*` are compared with equal hits ordered by path and without the warnings that the chat fallback now passes on (`recallCLIPortFixedFixtures`); their replay against the built binary is claimed in `contract/notes/cxc/CRW-567.json` (the two fixtures it already claimed, with the new stdout) and `contract/notes/cxc/CRW-1131.json` (`cli__memory__search_plain_envelope`, which CRW-567 claimed as identical).
