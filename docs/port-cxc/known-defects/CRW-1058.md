# CRW-1058 — GNU parallel templates and pipe- or descriptor-fed programs

Source: the CRW-1058 issue (Linear, created 2026-10-09; the CRW-1028 c1c residual, which CRW-1028 left refused). The items it supersedes are in CRW-1028.md (that file has no section headings, so each item is named by its opening words). The Go files are internal/pabcd/shellir/parallel.go (the GNU parallel model), pipeprog.go (a literal printf or echo as a pipe's producer, descriptor aliases and the here-document or here-string they set), carriers.go (interpreter and shell operands, -s and -), shellir.go (the pipe binding and stdinProgram), wrappers.go (the parallel wrapper), and internal/pabcd/hook/shellwrite_ir.go (the run-time carriers). Tests: internal/pabcd/shellir/crw1058_test.go, internal/pabcd/hook/memorygate_pipe_crw1058_test.go, and the rows in testdata/shellir/rows/43-crw-1058.txt.

- Supersedes CRW-1028.md, item beginning "parallel runs the programs its ::: operands name at run time": now port: fixed (a parallel template is read as the command lines its ::: sources make. Each combination of ::: and :::+ values is one line; {}, {N}, {#} and the path modifiers {.}, {/}, {//}, {/.} are modelled, and GNU's own joining of the template words is carried as shell text. A value that the shell would split or quote, a placeholder the reader does not model ({%}, {=...=}, {+}), a remote host (-S), a source file (:::: or ::::+), a file of arguments (-a), several arguments per run (-X, -m, --xargs), a quoted command (-q), stdin input (--pipe, no source), and an option outside the listed grammar stay unreadable. Pinned by TestCRW1058ParallelTemplates and rows CRW-1058-01 to -03, -09, -12, -14, -15, -18, -20, -21).
- Supersedes CRW-1028.md, item beginning "A recursive removal whose operands arrive at run time (xargs, find -exec and -execdir, parallel)": now port: fixed for parallel (its expanded removal is judged as the removal it is; xargs, find -exec and entr still arrive at run time and stay marked).
- Supersedes CRW-1028.md, item beginning "The memory gate ignored the carrier of a program that xargs, find -exec, find -execdir, find -ok or parallel runs": now port: kept for xargs, find and entr; parallel is no longer a run-time carrier because its expanded sources are in the text. Pinned by rows CRW-1058-09 and -12.
- Supersedes CRW-1028.md, item beginning "a pipe into a shell (printf ... | bash)" (the pipe refusal in the list that begins "unmodelled option (--foreground)"): now port: fixed for a simple command on the right of a pipe whose left side is one literal printf (only the plain format with \n, \t, \\, \", \' escapes and %%) or one literal echo (an optional -n, no leading option other than -n, no backslash). The bytes are read as the shell program, with the memory, GitHub and worktree gates judging them; a pipe whose shell has its own stdin redirection (</dev/null, 0<&3) stays refused, as the zsh MULTIOS rule requires (CRW-894-03). An ordinary stdout redirection of the shell (>file, >&2) leaves its stdin to the pipe, so the piped program is read (post-evaluation d8). A wrapper around the shell that carries a redirection (exec -a x >/dev/null bash) still refuses the pipe, as the frozen rows require. Pinned by TestCRW1058PipeProducers, TestCRW1058PipeWithStdoutRedirect and rows CRW-1058-04, -05, -10, -13, -16, -22, -34.
- Supersedes CRW-1028.md, item beginning "A Python, Node, Perl or Ruby interpreter whose script operand is a file-descriptor alias": now port: fixed for /dev/stdin, /dev/fd/N and /proc/self/fd/N or /proc/thread-self/fd/N whose descriptor the text sets by one here-document or here-string, by a copy of one (N<&M), or by the pipe on standard input (fd 0). The program is the text the descriptor carries. Other descriptors (another process's descriptor, a file, a process substitution, two bodies) stay unreadable. A copy onto descriptor 0 (0<&N) reads the body that descriptor holds (post-evaluation d9), except on a pipe's right side, where the pipe and the here-document or here-string would both feed the program; the alias form is refused there (post-evaluation d4). Pinned by TestCRW1058FdAliases, TestCRW1058StdinBodies and rows CRW-1058-06, -07, -08, -11, -17, -23, -30, -35, -36.
- Found while porting: bash -s foo was read as a script file named foo, so a program on standard input (a pipe or a here-document) ran unjudged; port: fixed (security). The operand is a positional parameter after -s, and the standard input is the program, as the shell runs it. A lone - ends the options as -- does, so the operand after it is the script file; bash, dash and zsh run it so (probed in a scratch directory, post-evaluation d3, row CRW-1058-29). The earlier statement here that a lone - makes the operand positional was wrong and is withdrawn. Pinned by TestCRW1058PipeProducers and rows CRW-1058-24 and -25.
- Kept: a printf with a conversion or an extra argument, an echo with a backslash or an option other than a leading -n, a pipe whose producer is anything other than a literal printf or echo, and a pipe into a shell or an interpreter behind a compound command (if, a brace group) or a redirected wrapper (exec with a redirection) stay unreadable. The reader does not follow those forms; each refuses rather than guesses (port: kept).
- Kept: an inline program in an interpreter the reader does not model (ruby, php, and the rest) is judged as the memory gate judges any unknown inline program: attempt, which needs a grant. A harmless ruby line such as puts 1 read from a pipe therefore asks for a grant (row CRW-851-11), not a silent allow; port: kept (fail closed).
- Deviations: the frozen rows below now get the verdict the reader gives, recorded with deviation= in their row headers. Every one keeps the refusal of the protected action it names: the removal of the managed checkout is refused by the worktree gate (none/allow/deny), and a memory write is an attempt that needs a grant (attempt/allow/allow). Rows: CRW-765-12 (a harmless here-document, now allowed, as CRW-1058 asks), CRW-851-07b, CRW-851-11, CRW-894-02, CRW-894-08, CRW-894-17, CRW-894-18, CRW-894-22, CRW-989-03, CRW-989-04, PR825-3113ad91-d3, PR825-3113ad91-d3b, PR825-3113ad91-d3c, PR825-350f75c1-d3, PR825-50ea729e-d3, PR825-50ea729e-d3b, PR825-50ea729e-d3c, PR825-50ea729e-d4b, PR825-8d7b38fe-d1, PR825-918798df-d1, PR825-918798df-d1b, PR825-918798df-d1c, LEDGER-CRW-726-d4b, CRW-1028-ev-d6-parallel, PR825-350f75c1-d5 (python3 reading a descriptor-0 copy of a here-document: the worktree refusal stays, post-evaluation d9), and PR774-6f0fcf3f-d1 (bash -s arg with a here-document that writes to memory: attempt).
- Changed expectations in existing tests: the parallel grader case (a parallel removal is read now, the worktree gate judges it); printf x | node --no-warnings (the piped text is the program node reads); echo hi | sh (now read) became curl x | sh (still unreadable); the GitHub post cases piped to a shell now give inline-github-body (denied) instead of unreadable-github-post; the memory gate pipe case moved to memorygate_pipe_crw1058_test.go, which asserts the write is judged; and printf 'echo x > memories/a' | exec -a x bash is W/A (the exec wrapper is kept, so the program is the echo that writes memory).
- Benign accounting: TestShellWriteBenignAccounting over the 1028 benign corpus gives a report identical to the dev base report (/state/crw/crw-951/evidence-1009/benign-full/base-report.txt, after the temporary-directory names are normalised). No allowed command was lost.

## Refresh over the landed reader changes

The refresh keeps CRW-894's shell family, -c precedence over -s, conservative option clusters, directory-aware descriptor alias recognition and unknown-input refusal, CRW-895's find/xargs operand feeds and pipeline output tracing, and CRW-851's Python callee checks. The literal pipe program is bound alongside the operand feed; each new pipe clears any inherited program binding. Both readers use the existing isDigits helper.

The new CRW-894 rows whose literal pipe runs only a checkout removal keep their original U expectation with a recorded none/allow/deny deviation: CRW-1058 reads that program, the worktree guard still denies the removal, and the memory and GitHub guards allow it. These are CRW-894-sf-01 through -13 and -16 through -20, and CRW-894-ev-25 through -29 and -31 through -35. The real-program controls now allow the four modelled, harmless -s pipes; unknown aliases, ambiguous clusters and MULTIOS input redirections remain refused. PR774-6f0fcf3f-d1 uses the landed W expectation because its here-document is read and its memory write requires a grant.

## Post-evaluation findings (crw1058-e83d8ec4)

The pre-merge evaluation of e83d8ec4 (record /state/crw/mgmt/pre-eval/crw1058-e83d8ec4.json) reported nine defects. Their red tests and rows are in commit 691012449, where they fail. The fixes are in e8e8b278f, where the same tests and rows pass. Each finding:

- d1 (P0): echo accepts every leading -n; any other option makes the program unreadable (echoText). Rows CRW-1058-26 and -27.
- d2 (P0): a function named echo is a modelled name (modelledName), so the pipe producer is never a shadowed echo. Row CRW-1058-28.
- d3 (P0): a lone - ends the options as -- does (carriers.go, shellCall), so the operand after it is the script file. Row CRW-1058-29 gives attempt/allow/deny: the removal is refused by the worktree guard, and the memory gate asks a grant for a script it cannot see into.
- d4 (P0): a descriptor alias on a pipe's right side is unreadable when the command's own input redirection also sets standard input (aliasProgram). Row CRW-1058-30.
- d5 (P0): each parallel job is walked as a shell of its own, from the directory and variables the text has at that point (parallelUnwrap returns one line per job; wrapped runs each from a copy of the state). Row CRW-1058-31.
- d6 (P0): {.} cuts the extension from the final path component only, and a name that is all extension gives an empty value that the caller refuses (parallelTransform). Row CRW-1058-32.
- d7 (P0): parallel under an operand feed from xargs or find is unreadable, because the feed adds ::: sources the reader cannot see (wrapped). Row CRW-1058-33.
- d8 (P1): an ordinary stdout redirection of a shell (>, >>, >&, >|) no longer refuses the pipe (hasStdinRedirect). A wrapper around the shell that carries a redirection on standard input or output still refuses it, as the frozen rows require (wrapRedirs). Row CRW-1058-34.
- d9 (P1): a copy 0<&N of a descriptor the text sets reads that body (stdinCopySource, stdinProgram), except on a pipe's right side. Rows CRW-1058-35 and -36.

Open, not changed by this round:

- A plain shell with a here-string or here-document on a pipe's right side (printf x | bash <<<'echo hi') is read as the body alone. Dev does the same: its stdinProgram returns the body without looking at the pipe. zsh with MULTIOS reads the pipe too, so the same hole exists under zsh. The interpreter form (CRW-765-g8-01, perl after a pipe) keeps that reading. The evaluation did not report this, and changing it would move the frozen g8 row and may remove allowed commands from the benign accounting, so it stays as it was and is listed for the parent as a candidate follow-up.
