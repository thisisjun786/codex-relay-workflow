# CRW-857 — CRW-703 differential-fuzz targets: input coverage (root substitution, generator grammar, absolute link targets, seeds)

Source: CXC v0.2.40 commit 3c1459ac. Oracle files:
`plugins/codexclaw/components/pabcd-state/dist/shell-write-destinations.js` (`shellWriteDestinations`, :25-36;
`scriptWriteDestinations` :532-549) and `plugins/codexclaw/components/pabcd-state/dist/memory-write-gate.js`
(`handleMemoryWriteGate`, :296-325). The harness itself (`internal/dev/cxcfuzz`) has no oracle counterpart and is
specified by the CRW-701/CRW-743 issue bodies; the recorder shims are
`internal/dev/cxcfuzz/testdata/{memorygate,shellwrite}/shim.mjs`.

This file records what this issue changed on the harness's input side and what the two 10-minute campaigns of the
new grammar found (seed 20261007, head recorded in the handoff): `crw-dev fuzz shellwrite --seconds 600` and
`crw-dev fuzz memorygate --seconds 600`. Both summaries are in the pull request body. No security miss (the oracle
refuses a destination the port accepts) appeared in either campaign; every difference is a class already recorded,
and each is pinned as a case in `internal/dev/cxcfuzz/testdata/<target>/cases.json` so it stays visible.

## Defects

- The ported harness substituted the case root in the serialized JSON text (`memoryGateGo`, `shellWriteGo`), while
  the oracle's shim substitutes it in the decoded value (`testdata/memorygate/shim.mjs:19-27`). A case root holding a
  quote, a backslash or an LF then made the two sides read different inputs, and the campaign could not see the
  forms the issue asked for (source `shim.mjs:19-27`; port: fixed by this issue, one shared value-level substitution).
- The oracle's `scriptWriteDestinations` reads `open(...)` and `Path(...).write_text` but not `os.rename`,
  `shutil.copy` or `shutil.copyfile`, whose destination is the second argument, and it reads neither a Python
  literal's `\x2f`/`\u002f`/`\057`/`\N{...}` escape nor a triple-quoted literal's physical line breaks; the port
  reads all of them (source `shell-write-destinations.js:532-549`; port: fixed by CRW-517/CRW-650/CRW-678, security,
  and now exercised by the widened generator; the divergences stay pinned `open`/`intentionally-changed`).
- The oracle's gate compares the destination text only, so a symlink in the workspace that leads into the memories
  root is allowed although the write lands in the root; the port follows the link and denies it (source
  `memory-write-gate.js:122-126,154-160`; port: fixed by CRW-518, security, pinned `intentionally-changed`).
- The oracle misses a destination a real shell write reaches whenever a wrapper word or option hides the writing verb,
  when the write hides in a nested `-c`/`eval` string, or when it follows `2>`/`<>`; the port names these (source
  `shell-write-destinations.js:276-311,209-235`; port: fixed by CRW-517, security, pinned `open`).
- Not measured by this target, and left to a follow-up: the memory gate's authorization legs (the CLI grant and the
  prompt marker) are exercised with a fresh grant-less session, so a divergence in grant or marker consumption is
  outside what this campaign could find (source `memory-write-gate.js:262-293`; port: unchanged, the existing
  `internal/pabcd/hook/memorygate_test.go` covers those legs).

## Supersedes

- Supersedes known-defects/CRW-703.md, section "Defects", item beginning "Not reachable by this target: the issue
  body asks for link targets that are relative *and* absolute": now port: fixed (the scenario builder accepts a
  symlink target that opens with the `${ROOT}` placeholder, substitutes the case root, checks containment and creates
  the link with the substituted absolute target; the memorygate generator mixes relative and absolute targets for its
  aliases and its 1-45 link chains, and the two seeds it asked for are pinned in `testdata/memorygate/cases.json`).
- Supersedes known-defects/CRW-703.md, section "Defects", item beginning "The oracle's reader does not read a
  triple-quoted Python literal's physical line breaks": unchanged in substance (port: fixed, security), and now
  carried by the two CRW-857 seed shapes as well.


## Divergence classes the widened grammar surfaced

Campaign summaries (seed 20261007, the head of this branch): `shellwrite` 46,511 cases (28,058 same,
18,453 extra, 0 miss, 0 differ, 0 timeout, 0 refused) and `memorygate` 7,219 cases (5,011 same, 2,093 extra,
115 differ, 0 miss, 0 timeout, 0 refused). Each class is pinned in `internal/dev/cxcfuzz/testdata/<target>/cases.json`.

- `os.rename`, `shutil.copy` and `shutil.copyfile` name their destination as the SECOND argument; the oracle
  reads neither argument, the port reads the destination (source `shell-write-destinations.js:532-549`; port:
  fixed by CRW-517, security; pinned `open` in `testdata/shellwrite/cases.json` as `crw857-rename-destination`,
  `crw857-copy-destination`, `crw857-copyfile-destination`).
- A destination slash written as a Python literal escape (`\x2f`, `\u002f`, `\057`, `\N{SOLIDUS}`) is decoded by
  the port and not by the oracle, so the port names a path the oracle misses (source
  `shell-write-destinations.js:532-549`; port: fixed by CRW-517, security; pinned `open` as
  `crw857-escape-x2f-destination`, `crw857-escape-octal-destination`, `crw857-escape-unicode-destination`,
  `crw857-escape-named-destination`).
- An f-prefixed literal whose destination sits inside a doubled brace is read by the port and missed by the
  oracle (source `shell-write-destinations.js:532-549`; port: fixed by CRW-741, security; pinned `open` as
  `crw857-fstring-brace-destination`).
- A write inside a subshell, a brace group, a command substitution or a backtick substitution is read by the port
  and missed by the oracle (source `shell-write-destinations.js:209-235`; port: fixed by CRW-517, security; pinned
  `open` as `crw857-subshell-write`, `crw857-brace-group-write`, `crw857-command-substitution-write`,
  `crw857-backtick-write`).
- The two sides deny the same memory write but name different destination text: the oracle's reader carries the
  substitution delimiter into the path it reports, while the port names the path the shell would write (source
  `memory-write-gate.js:238-258`; port: fixed by CRW-650, security; pinned `open` as
  `crw857-memorygate-deny-reason-differs`).
- The memory gate now reaches the widened grammar through the shared generator: a link followed into the memories
  root, an escape-decoded destination and a substitution-nested write are denied by the port and allowed by the
  oracle (source `memory-write-gate.js:122-126,154-160`; port: fixed by CRW-517/CRW-518, security; pinned `open` as
  `crw857-memorygate-rename-into-root`, `crw857-memorygate-escape-into-root`,
  `crw857-memorygate-substitution-write`).
