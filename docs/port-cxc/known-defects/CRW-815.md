# CRW-815 — one shared whole-state rewrite judgement

Source: CXC v0.2.40 (commit 3c1459ac). The oracle has no shared judgement: each whole-state writer in
`plugins/codexclaw/components/pabcd-state/src/` republishes whatever its reader rebuilt. In the port the
loss is visible in `internal/pabcd/state/restore.go` (`ReconstructUnverified`, :167-200) and
`internal/pabcd/interview/reconstruct.go` (`tail`, :10-16, and `cleanOntology`, :175-197); the writers are
`internal/pabcd/hook/session_hooks.go`, `prompt_submit.go`, `memorygate.go`, `idleedit.go`,
`internal/pabcd/evidence/tombstone.go`, `budget.go` and `internal/pabcd/cli/memory.go`, `evidence.go`,
`scan_record.go`, `loop.go`, `orchestrate_transition.go`.

## Defects

- The oracle republishes the state its reader rebuilt with no judgement that a stored record would be lost, so
  a write-back that only means to clear a cursor, spend an authorization or bind a slug can drop or change
  records: `ReconstructUnverified` stops at `MaxUnverifiedSubagents`, cuts `receiptClaimed` to
  `MaxReceiptClaimLen` and defaults a field of the wrong type, and `ReconstructInterview` caps every tracker
  array at `interview.MaxTrackerArray` (drop-oldest) and drops an ontology entity with no name and a
  relationship with no target; port: fixed (a data-loss defect the parity rule revision of 2026-10-03 fixes
  during the port: `state.RewriteKeepsStored` is now the one judgement every writer that rewrites the whole
  session file asks, replacing the copies `sessionHookStateRewritable`, `sessionHookInterviewKeepsStored` and
  `loopStateRewritable`; tests `TestRewriteKeepsStoredIsTheSharedDataLossJudgement`,
  `TestMemoryGateRefusesToRewriteALongInterviewTracker`, `TestIdleEditRefusesToRewriteALongInterviewTracker`,
  `TestEvidenceRefusesToRewriteALongInterviewTracker`).
- Supersedes known-defects/CRW-786.md, item beginning "`memoryGateRewritable` (`internal/pabcd/hook/memorygate.go`)":
  now port: fixed (this issue routes the memory gate, the idle-edit counter and the two evidence writers
  through the shared judgement, so they gain the interview class; a stored tracker longer than
  `interview.MaxTrackerArray` is refused instead of published cut, the file is left byte for byte, and no
  writer keeps a narrower copy of the judgement).
- Observation, base behaviour unchanged by this issue: a legacy D-close recovery marker is refused by the chat
  surface's `orchestrate reset` (`promptSubmitRewritable`, through the new `state.DcloseRecoveryLegacy`) while
  the CLI `orchestrate reset` clears it, because the CLI transition path never carried that refusal. Since
  CRW-648 the reader restores the stored `legacy` flag, so neither write loses the marker's distinction. The
  legacy class is deliberately NOT part of the shared judgement (decision 2026-10-07): the CLI reset is the
  operator's recovery for such a marker. Recorded here as an observation; changing either surface is a
  separate decision.
