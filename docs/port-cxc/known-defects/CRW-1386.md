# CRW-1386 — the switch's `cxc` definition says what the code does, the child pair names only the policy, stale comments, the skill limit 31

Source: the evaluation of the CRW-1352 bundle (carried c3 and d3, separable d4 and d5), not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no hook switch of this shape, no child pair line and no skill count limit. The code is `internal/runtime/install/switch_cmd.go` (`crw install switch`), `internal/skill/pair_choice*.go` (the pair names `Sonnet` and `SOL`) and the tests `internal/dev/ci/crw_only_docs_test.go`, `internal/dev/ci/issue_body_wording_test.go` and `internal/dev/ci/skill_count_test.go`.

- `docs/runtime-install.md` defined the switch's `cxc` value as the emergency stop and "the only meaning the value has", while the same section and the code (`switch cxc` puts back the CXC plugin key line and the CXC role files `switch crw` recorded, so an entry turned off from `enabled = true` comes back on) do more; port: fixed (decided default: the code stays; the one-line definition says `cxc` turns the ported legs off and puts back, byte for byte, only what `switch crw` recorded as changed, that such an entry comes back on, and that no file at all turns the legs off and puts nothing back). Pinned by `TestSwitchCXCDefinitionIsWhatTheCodeDoes`, which also reads the same words in the usage text of `switch_cmd.go`, so the definition and the code cannot move apart unnoticed.
- `crw-plan/references/integrations.md` named the two child pairs after the family of their model ("the declared pair whose model is a Claude Sonnet model"), and `TestIssueBodiesNameNoModel` read only the two SKILL.md files; port: fixed (`Sonnet` and `SOL` are the names the role policy gives its two child pairs, a name and not a model, and the line form reads `Child pair: <the policy's pair name, Sonnet or SOL>`; the names stay because `crw skill pair-choice` and its quota snapshot key them). The test now also reads every reference of crw-add-issue and crw-plan: outside code spans no model name other than the pair name, and no pair defined by its model.
- Stale comments: `internal/dev/ci/skill_canon_test.go` said 부모 is the initiative lead, and `internal/manage/checkpoint_test.go` named `crw-run-initiative` as the live skill that holds the checkpoint procedure; port: fixed (the level table's Korean words stay in hierarchy.md; the procedure is crw-run's long-run midpoint check, and the comments name the tests that read it).
- The skill count limit was 32 with 31 skills, so one skill could come back unnoticed; port: fixed (`TestSkillDirectoryCountAtMost32` is renamed `TestSkillDirectoryCountAtMost31`, limit 31, its fixtures 31 pass and 32 fail; renamed, not deleted).
