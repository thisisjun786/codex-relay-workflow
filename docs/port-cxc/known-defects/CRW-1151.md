# CRW-1151 — the hook-hint wording of crw-pabcd and the review observer's leg status after CRW-392 and CRW-564

Source: the 10-10 isolated real-use trial r1 (S2-F5, S3-F2) and the 10-10 CXC improvement review (A4-02, wording part). There is no oracle record for these: the words are the port's own documentation. The Go files are `internal/pabcd/hook/detect.go` (DetectTrigger), `internal/pabcd/hook/reviewobserver.go` (HandleReviewObserver) and `internal/harness/legs.go` (the registration, lines 146-147).

- Supersedes CRW-392.md, item beginning "One declared leg answers nothing": now port: fixed (CRW-564 filled the handler: `subagent-stop-observing-review` runs `HandleReviewObserver`, registered at `internal/harness/legs.go:146-147`, which records the review sign-off in the goalplan and writes no output; the leg-level statement in `docs/plugin-packaging.md` is corrected to match).
- The crw-pabcd skill said the hook hint fires on `interview` / `인터뷰` (`plugins/crw/skills/crw-pabcd/SKILL.md:31-32`). Two layers were conflated and the skill now states them apart. DetectTrigger (the detector) needs a request clause with the PABCD marker and a request verb, then picks the phase by pattern (I interview/인터뷰, P plan/계획, A audit/감사, B build/구현, C check/검증, `phase X`); with no phase pattern it falls back to P only when the request names `crw-pabcd` (any marker form containing it) or `pabcd로`, because the fallback pattern is `pabcd\s*로|\bcrw-pabcd\b` while the marker also accepts `pabcd phase`. Detector results (pinned by `TestDetectTriggerSkillHintExamples` in `internal/pabcd/hook/detect_crw1151_test.go`): `Use crw-pabcd`, `pabcd로 시작해줘` P; `Use crw-pabcd to start the interview` and `Start pabcd phase i` I; `Start pabcd phase`, `인터뷰 먼저 해줘`, `interview me first` and `pabcd로 인터뷰 해줘` none. The hook output is the handler's answer (`PromptSubmitHandle`), which the detector alone does not decide. The handler applies, in this order: (1) goal mode: with an active goal, or a goals database that cannot be read (fail closed), `DecideEntry` never promotes P to the interview, so a P hint is the plain P directive, and the I suppression at `prompt_submit.go:171-172` drops an I hint (silence) before the loop-arm branch runs, in an armed session too; (2) in a session that has not armed PABCD, the loop-arm branch (`DetectLoopArmRequest`: a loop mode or a bare `pabcd`/`ipabcd` word plus an action word) answers the ORCH-MANDATE-01 arming mandate instead of any hint, a P hint included; (3) a phase hint is the phase directive plus the trigger-authority note, the interview directive for P under the default `new-unit` policy (not once a cycle runs; `always` also inside a cycle, `off` never). In a fresh un-armed session without a goal, `pabcd로 시작해줘`, `pabcd로 인터뷰 해줘`, `Start pabcd phase` and `Start pabcd phase i` answer the mandate, `Use crw-pabcd` and `Use crw-pabcd to start the interview` answer the interview-directive hint, `인터뷰 먼저 해줘` and `interview me first` answer nothing. Under an active goal in the same session, `Use crw-pabcd` answers the plain P directive, `Use crw-pabcd to start the interview` and `Start pabcd phase i` answer nothing, and the three mandate examples keep the mandate. In an already armed session a prompt without a hint can still re-inject the phase directive or stage header (`internal/pabcd/hook/prompt_trigger.go`), unless the transcript tail holds the stage marker or shows context pressure, and in phase I under an active goal nothing is re-injected. The handler answers are pinned, as full expected outputs, by `TestPromptSubmitSkillHintExamplesInAFreshSession` and `TestPromptSubmitSkillHintExamplesUnderAGoal` (an active goal and an unreadable goals database); port: fixed (the skill states the code's condition and its handler outputs; the code is unchanged).
