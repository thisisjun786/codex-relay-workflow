- The crw-pabcd skill said the hook hint fires on `interview` / `인터뷰` (`plugins/crw/skills/crw-pabcd/SKILL.md:31-32`). Two layers were conflated and the skill now states them apart. DetectTrigger (the detector) needs a request clause with the PABCD marker and a request verb, then picks the phase by pattern (I interview/인터뷰, P plan/계획, A audit/감사, B build/구현, C check/검증, `phase X`); with no phase pattern it falls back to P only when the request names `crw-pabcd` (any marker form containing it) or `pabcd로`, because the fallback pattern is `pabcd\s*로|\bcrw-pabcd\b` while the marker also accepts `pabcd phase`. Detector results (pinned by `TestDetectTriggerSkillHintExamples` in `internal/pabcd/hook/detect_crw1151_test.go`): `Use crw-pabcd`, `pabcd로 시작해줘` P; `Use crw-pabcd to start the interview` and `Start pabcd phase i` I; `Start pabcd phase`, `인터뷰 먼저 해줘`, `interview me first` and `pabcd로 인터뷰 해줘` none. The hook output is the handler's answer (`PromptSubmitHandle`), which the detector alone does not decide: in a session that has not armed PABCD the loop-arm branch runs first (`DetectLoopArmRequest`: a loop mode or a bare `pabcd`/`ipabcd` word plus an action word), so `pabcd로 시작해줘`, `pabcd로 인터뷰 해줘`, `Start pabcd phase` and `Start pabcd phase i` answer the ORCH-MANDATE-01 arming mandate, `Use crw-pabcd` and `Use crw-pabcd to start the interview` answer a phase hint (the interview directive under the default `new-unit` policy, dropped for I while a goal is active), and `인터뷰 먼저 해줘` and `interview me first` answer nothing; in an already armed session a prompt without a hint can still re-inject the phase directive or stage header (`internal/pabcd/hook/prompt_trigger.go`), unless the transcript tail holds the stage marker or shows context pressure. The handler answers are pinned by `TestPromptSubmitSkillHintExamplesInAFreshSession` (probes at 6a5851f4f, at the fix-round head and at the post-evaluation head: `/state/crw/crw-lane-doc-sweep-after-392/evidence/` including `round4/`); port: fixed (the skill states the code's condition and its handler outputs; the code is unchanged).
