No defect was found in this slice when it was ported. The budget guard, the interview guard and the fail-closed
dispatcher reproduced the oracle's texts and decisions byte for byte, and the three recorded fixtures that exercise
them replayed identical (the budget guard has since been removed: see the first entry below and CRW-1133.md).
The two behaviours that read as odd are the oracle's design and were ported as they were,
so neither was a defect of the port:

- A create_goal carrying any key beside objective is denied, token_budget included, so the host's own
  budgeted goal cannot be created while this hook is installed (goal-gate.ts:105-125); port: fixed by
  [CRW-1133](CRW-1133.md) (this entry was `port: kept` when the port landed, because the guard exists to keep the
  goal unlimited and the deny text says so; CRW-1133 removed the guard, so the installed hook now answers nothing
  and a token_budget the user named reaches the host; the recorded case
  `hook__pre-tool-use-guarding-goal-budget__token_budget_denied` is tagged intentionally-changed in
  contract/notes/cxc/CRW-1133.json, so the byte-identical replay claimed above holds for the other fixtures only).
- A payload that does not parse is passed through rather than denied, so only a failure after the parse
  reaches the fail-closed deny (goal-gate.ts:316-324); port: kept, because the oracle's own test asserts the
  pass-through (goal-gate.test.ts:260-262) and the issue's parity rule wins.
