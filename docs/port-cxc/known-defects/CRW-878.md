# CRW-878 — the project root was created wider than private until the chmod after its mkdir

Source: the state-copy apply is CRW's own design, [docs/port-cxc/state-migration.md](../state-migration.md)
(the whole-scope preflight at :144-156 and the M3 write step at :184), and the code is the Go port in
`internal/runtime/install/migrate`: `publish.go` (`Publisher.EnsureProjectRoot`, whose destination-root
creation and mode chmod stood at :221-228 at the base commit f60a537b) and `roots.go` (`Pair.EnsureDest`
at :132-146 and `Dir.EnsureChild` at :476-502, where the parent directory is synced after the mkdir).
CRW-813 landed in dev while this issue ran and changed both to return `(dir, made, err)`, `made` true only
when the call's own mkdir created the directory; the merge with dev keeps that result beside this issue's
mkdir mode, so `EnsureProjectRoot` no longer derives `made` from `pair.Dest == nil`.
There is no CXC v0.2.40 oracle file for this: the state-copy apply is CRW's own design, so the pointer is
the design document and the port. The defect was found by the operator's pair evaluation of the merged
state-copy pull request (thisisjun786/codex-relay-workflow#738, score 4, P0) and confirmed on dev
f60a537b from the code.

- `EnsureProjectRoot` created the project root with a mkdir of 0o777 (0755 under umask 022) and narrowed
  it to the private marker mode 0o1700 with the chmod that follows, but `EnsureChild` syncs the parent
  directory between the mkdir and that chmod, so an EIO there or an interruption between the two steps
  returned with the root left at 0755; a rerun then finds that root as an existing one, `finishModes`
  leaves its mode alone, and the 0644 records copied into it (`ledger.jsonl`) are readable by other users
  where the source root was private (source `publish.go:222-228`, `roots.go:476-502`); port: fixed (the
  root's own mkdir is 0o700, so the root is at most 0700 from the moment it exists and no later failure can
  leave it wider, while the chmod to the private marker mode stays where it is, before the fallible
  `.gitignore` publication; the cases are `TestMigrateRootPrivateAfterAFailedRootSync` and
  `TestMigrateRootPrivateRerunAfterAFailedRootSync`, and `TestMigrateRootPrivateControls` pins that a run
  without a failure is unchanged).
- Accepted, not a defect: after such an interruption a rerun whose source root is 0755 can now end with the
  destination root at 0700, narrower than its source, and reports the directory it kept
  (`finishModes`, `apply.go:601-635`). The direction is the safe one — a root this run did not create is
  never widened — and the run's own root still finishes at the source mode when the run created it; port: kept.

- Not this issue's defect, recorded so the same privacy argument is not mistaken for an oversight:
  `crwdir.ensureDir` creates the project root `.crw` with `os.Mkdir(dir, 0o777)`
  (`internal/pabcd/crwdir/crwdir.go:27`), so outside the state-copy apply a root created there is 0755 under
  umask 022 with no chmod after it. That is exact parity with the CXC v0.2.40 oracle, whose
  `ensureCodexclawDir` calls `mkdirSync(dir)` with no mode at all (`P/codexclaw-dir.ts:13`, the helper at
  :7-26, in the copies bg-wake, cxc-ops, subagent-config and messenger-bridge share), so the parity rule keeps
  it; `crwdir` is outside this issue's edit regions and is unchanged here; port: kept.

- Supersedes `known-defects/CRW-812.md`, item beginning "Not a defect, recorded so the mode sequence is not
  mistaken for one": now port: fixed (that paragraph recorded the root being created 0o777 under the umask and
  tightened afterwards; the mkdir itself is now 0o700, so the widening it described no longer exists, and the
  private-marker chmod it also described is unchanged).
