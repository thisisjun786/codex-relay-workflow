# CRW-581 — the Darwin 0300 goalplan directory, and the role helper --global after a value flag

Source: the pair evaluations of the CXC port pull requests 515 (CRW-357, goalplan writes) and 512 (CRW-441, role helper CLI) on 2026-10-05; the grading notes are in the evaluation scratch and are not part of the repository. The Go files are `internal/pabcd/goalplan/open_darwin.go` (`directoryOpenFlags`, with the darwin-only test in `open_darwin_test.go`) and `internal/role/helper_cli.go` (`ParseHelperArgs`, `helperCLISetArgs`); the cases are in `internal/role/helper_cli_args_test.go` (`TestHelperArgsFlagValues`).

- A goalplan directory of mode 0300 (write and search, no read) refused a plan save and a ledger append with EACCES on Darwin, because the Darwin directory open was O_RDONLY (oracle: the write is allowed in that mode, CRW-357 evaluation, PR 515). port: fixed, intentionally changed from the oracle: the directory is opened search-only, O_EXEC | O_DIRECTORY (0x40000000 | O_DIRECTORY, O_SEARCH on macOS, the flag `internal/pabcd/cli` planDirectoryFlags and CRW-993 use), so the mode's own write and search permissions decide. The link refusal (O_NOFOLLOW) is unchanged. Runtime is not run on macOS: the Darwin path is compiled and vetted on Linux with `GOOS=darwin go vet`, and `TestGoalplanDirectoryOpenFlagsOpenASearchOnlyDirectory` (darwin-only) is not executed here; recorded as unverified at runtime, as CRW-993 records its Darwin test.
- Open on Darwin, not changed here (port: pending): the post-rename directory open that the publication syncs (`goalplanPublishedOpenDir` in `write.go`, `openAt(dir, ".", ..., unix.O_RDONLY|unix.O_DIRECTORY, ...)`) and the lock-directory reads (`open.go`, `lock.go`) still open with O_RDONLY on every platform. A mode-0300 directory may therefore still fail on Darwin at those points; only a macOS run can decide whether a change there is needed.
- `set reviewer --prompt '--model' --global` (oracle cli.ts:42): the oracle answered "unknown flag '--global'" because the trailing --global was not taken as the scope, and nothing was written. intentionally-changed: the port's CRW-1117 refusal now answers "--prompt requires a value; write a value that starts with '-' as --prompt=<value>" for the same argument list, and still writes nothing; `set reviewer --prompt=--model --global` (value form) selects the global scope as the oracle does. The left-to-right reading the pair evaluation asked for is what the port does now: a value flag never takes a dash-led token, so the trailing --global is the selector exactly when it is not the value of an earlier flag. port: fixed (superseded by CRW-1117; no code change in this issue, the cases are pinned by `TestHelperArgsFlagValues`).
