# CRW-1365 — the empty-base fallback of the acceptance and the tierStep test's id suffix were not pinned

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no flow engine, no stableBase and no tier step. The Go and script side is `internal/flow/ops/lane_land.go` (`crw.accept`, the base of a verification row that names none), `internal/flow/ops/lane_build.go` (`stableBase`), `internal/flow/workflows/lib/lane.js` (`tierStep`) and the tests of `internal/flow/scenario/correction_test.go`. Found by the pre-merge evaluation of CRW-1271 (/state/crw/mgmt/pre-eval/crw1271-7189cd8a.json). No product code changed.

- A verification row that names no base is judged over `stableBase` found at the acceptance (`lane_land.go`, `acceptOp.Run`), and no test pinned that path: the stableBase tests covered only rows that name their base; port: fixed (`TestVerificationWithoutBaseIsAcceptedOverCommonAncestor` drops the base from B's verification row after A has landed and checks that B is accepted over the commit B grew from, the merge-base of B's head and the moved tip, and that its premerge record stands on it; it fails when the fallback takes the integration tip).
- `TestTierStepConflictHandsRecordedIDToExecutorT1` built the expected id as the minted id with a `_` suffix and dropped the result of its first run; port: fixed (the test reads the id each `crw.stepRecord` row recorded, compares the executor-t1 call and the persisted rows with it, and checks that the first run ended at the kill; it still fails when `tierStep` hands the minted id instead of `recorded.id`).
- The same test moves the allocated worktree back with a manual `git reset --hard`; port: kept (no lab fixture moves a worktree back, and the reset is what unproves the fix commit so the resume reaches `tierStep` over a new checkpoint; a one-line comment says so).
