# CRW-1602 — followers wait for writers of stopped runs

CRW-1550 separates a run's state from the journal commit barrier. A writer can hold a completed, dead or held run while `Reader.Tail` returns its stopped state with `Live: true`. The CLI watch and GUI SSE consumers checked that barrier only for paused runs, so an empty page could end the subscription before the writer committed its last row.

Both consumers now use `Page.FollowDone`: the page is empty and drained, the state is stopped, and no run process or writer holds the commit barrier. Reader state calculation and the lock format are unchanged. The regression tests hold a real audit lock, prove that each consumer reads again, commit two final rows, release the lock, and require both rows before termination. The same states without a writer still terminate on the first empty page.

Port: fixed (consumer termination condition).
