# CRW-1360 — doctor model check honours catalogue freshness, flow show forgets an old repin, the SessionStart policy warning follows the launcher

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no execution policy, flow engine or doctor model check. These are the follow-ups the pre-merge evaluation of CRW-1324 recorded (`/state/crw/mgmt/pre-eval/crw1324-5cc0f1f7.json`, d1, d2, d3); the first design is in `CRW-1324.md`. The Go side is `internal/role/mcptools.go` (`CatalogAuthority`), `internal/runtime/doctor/role_models.go`, `internal/flow/cli/runs.go` and `read_cmds.go` (`recordedPolicy`, `printDetail`), `internal/pluginwiring/drift.go` and `launch.go` (`ReadPolicyDriftUnder`, `launcherOverride`) and `internal/affordance/policy_warning.go`; the references are `docs/runtime-install.md` (the doctor `roleModels` entry and the bridge policy section). Everything here is a warning or a record; nothing blocks a start, a spawn or a run, and the engine's `policy_repinned` write, the journal rows and the relay store are untouched.

- d1 (P2): with no OCX the doctor checked helper models against the native Codex catalogue without the freshness rule `role.CatalogIsAuthoritative` applies (the native file must be at most 24 hours old), so an old `models` file could warn "does not list" for a model the provider serves; port: fixed. `role.CatalogAuthority` is `CatalogIsAuthoritative` with the reason (`authoritative`, `not-fresh`, `native-no-path`, `native-missing`, `native-stale`; `CatalogIsAuthoritative` now calls it and answers as before). `ModelCatalogReading` carries `Freshness`; the production probe fills it from the catalogue it read, against the doctor's clock. A list that is not authoritative condemns nothing (decided default: suppress and record, which fails open): no warning, `roleModels.catalogue` gains `authoritative` and `freshness`, a model it lists is `listed` true and one it lacks is `listed` null. A probe that leaves `Freshness` empty counts as authoritative, as every reading did before. A fresh native list and OCX's live list still warn. Pinned by `TestDoctorDoesNotCondemnAModelOnAStaleNativeCatalogue` (stale, missing, fresh native, fresh OCX) and, through the production reader on a real file with a set mtime and no OCX on PATH, `TestDoctorReadsTheNativeCatalogueFreshnessFromTheFile` (stale, fresh, dated after the clock; the doctor writes nothing).
- d2 (P3): after a repin, the next `started` row that read the same digest left `crw flow show` printing the old "repinned from", and a `started` row from before `policy_source` was journaled printed "policy none (placeholder table...)"; port: fixed. `recordedPolicy` resets the repin at every `started` row (a repin is journaled after the start it belongs to, so a real repin after the start still shows). A `started` row with no `policy_source` key at all is "not recorded": `policy file not recorded  digest <digest>` when it has a digest, `policy not recorded` when it has none (`--json` adds `policy_unrecorded`); only a row that records an empty `policy_source` is the placeholder table. The journal is only read. Pinned by `TestShowClearsRepinnedFromOnALaterUnchangedStart` and `TestShowDoesNotCallAnOldStartedRowAPlaceholderTable`, beside the unchanged `TestShowNamesTheRecordedPolicyPathAndDigest` and `TestShowSaysARunHasNoPolicyFile`.
- d3 (P3): the `SessionStart` policy warning did not trim `CODEX_HOME`, ignored the launcher's `CODEX_THREAD_BRIDGE_EXECUTION_POLICY` and `..._DIGEST` overrides, and printed the recovery path unquoted; port: fixed. The Codex home is `CODEX_HOME` trimmed (blank is unset), as the installer trims it. The launcher's two comparisons of those variables with the record are one function in `internal/pluginwiring` (`launcherOverride`), used by the launcher's `policyEnvironment` (its refusal text is unchanged) and by `ReadPolicyDriftUnder`, which the hook calls with the two variables it has; an override that conflicts is reported before the file is looked at, with the variable, what it names, the way out (unset it, or register the file it names) and the register command. The path in every recovery command goes through `quote.Shell`. The hook only warns, as before. Pinned by `TestSessionStartPolicyWarningTrimsCodexHomeAndQuotesThePath` and `TestSessionStartPolicyWarningFollowsTheLauncherOverrides`, beside the unchanged drift tests.
- Named limit: the doctor judges the native file's age at the time of the report, so a catalogue that is 23 hours old warns today and not tomorrow; that is the rule the role helper uses. Port: kept.
- Named limit: the hook reads the two variables from the hook process's own environment; a launcher started with another environment (a service, a different shell) can differ, and the hook cannot know. Port: kept.
- Named limit: `printDetail` shows the latest start's policy only; the earlier starts of a long-lived journal stay in the journal. Port: kept.
