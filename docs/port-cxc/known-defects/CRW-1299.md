# CRW-1299 — the relay daemon alone decides where a child report is recorded

Source: CRW's own design (a child reports only through the relay daemon, CRW-1286.md), not the CXC oracle. The Go
side is `internal/relay/hook/control_child.go` (`handleChildCommand`) and `internal/relay/dispatch`
(`OwnedChildState`, `ExecuteOwnedChild`).

- The state location where a child's `emit`, `intent-claim` or `intent-disposition` is recorded is the relay
  daemon's own. The child's `--state`, its `CODEX_SESSION_RELAY_STATE` and its working directory only find the
  daemon's `control.sock`; they never move or redirect the record; port: fixed in source.
- Rule DROP: the daemon runs the command with `OwnedChildState` naming its own state directory, which replaces the
  caller's `--state` whatever the request names (another initialized store holding the same relationship, or a
  path relative to the child). The daemon does not resolve the caller's selection again; port: fixed in source.
- Rule REFUSE: a path relative to the child (`--socket`, `--workspace`, `--marker-root`, `--independent-review`) is
  refused with an explicit host error that names the option and says it is caller-relative; the daemon never
  interprets it in its own directory, records nothing and the child names the path absolute; port: fixed in source.
- `TestChildReportStateLocationIsTheDaemons` (an absolute flag, a relative flag and the child's environment, with
  the daemon's environment naming a decoy state), `TestAChildStateSelectionCannotRedirectTheDaemonsRecord` (a
  request naming another store or a relative state on the daemon's real handler) and
  `TestTheDaemonRefusesACallerRelativePath` (each of the four options) in
  `internal/relay/adapter/child_emit_linux_test.go` pin both rules, the child running the built CLI through
  `childIn` under the read-only seccomp model.
