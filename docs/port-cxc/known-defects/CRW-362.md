# CRW-362 — doctor retrust

Source: CXC v0.2.40, commit `3c1459acadeb1906d97c00a598e1457327ae372d` — `plugins/codexclaw/components/cxc-ops/src/hook-trust.ts:345-477` (insertMissingSections, writeAtomic, resolvedConfigPath, verifyCodexConfig, retrustHooks) and `plugins/codexclaw/components/cxc-ops/src/cli.ts:40-71,96-115` (parseHookOptions, resolvePluginKey, the hooks case).
Port: `internal/runtime/doctor/hooktrust_retrust.go` and the retrust dispatch in `internal/runtime/doctor/cli.go`.

- The oracle reads config.toml with `readFileSync(targetPath, "utf8")` and writes the rewritten document back, and its rollback writes `readFileSync(backupPath, "utf8")`, so every byte of the file that is not valid UTF-8 becomes U+FFFD on a successful write and again on a rollback: a settings file loses bytes it never asked to change (source `plugins/codexclaw/components/cxc-ops/src/hook-trust.ts:417,466,472`); port: fixed (a settings data-loss defect, fixed by decision: the port splices the byte offsets the reader returns and publishes the result through `crwdir.Publish`, and the rollback publishes the backup bytes it read, so every byte the rewrite does not name is preserved — `HookTrustRetrust`, `hookTrustRetrustRollback` in `internal/runtime/doctor/hooktrust_retrust.go`).
- The oracle writes the rewritten document and restores the backup without checking whether the file changed since it read it, so a settings writer that published in between (during the `codex features list` probe, which can take seconds) is silently replaced by the rewrite, and again by the rollback when the probe fails (source `plugins/codexclaw/components/cxc-ops/src/hook-trust.ts:466-473`); port: fixed (a settings data-loss defect, fixed after the Devin red finding: `hookTrustRetrustUnchanged` is the compare-and-swap the repository's other settings writer applies (`internal/role/registration.go` `registrationUnchanged`), and both `hookTrustRetrustReplace` and `hookTrustRetrustRollback` apply it, so a concurrent edit is reported and left in place — `HookTrustRetrust`, `hookTrustRetrustReplace`, `hookTrustRetrustRollback`).
- The oracle's rollback rewrites the target and, when that second write fails, throws with the rollback error alone, leaving the operator to find the backup by name (source `plugins/codexclaw/components/cxc-ops/src/hook-trust.ts:471-474`); port: fixed (J4, 2026-10-06: the failure text ends with ` (restored from backup <path>)`, or ` (rollback failed: <error>; backup kept at <path>)` when the rollback itself does not happen, so a failure always names the backup — `hookTrustRetrustRollback`).
- The oracle's `writeAtomic` takes the target's mode from `statSync(path).mode`, and a target the process cannot open for writing is replaced in place anyway; the port publishes through `crwdir.Publish`, which refuses a file it cannot open for writing and never replaces it in place (source `plugins/codexclaw/components/cxc-ops/src/hook-trust.ts:367-381`); port: kept (this is CRW-427's rule, not a defect of this port, and it is stricter than the oracle: a target the process cannot open for writing is refused rather than replaced, which changes which failures surface).
- The oracle derives its plugin package from its own module path (source `plugins/codexclaw/components/cxc-ops/src/cli.ts:28-32`), which a Go binary installed through the runtime pointer has no equivalent of; the port reads the host `PLUGIN_ROOT`, else `--plugin-root`, else the one plugin package under the Codex home plugin cache whose manifest declares hooks (`hookTrustRetrustPluginRoot`). An addition rather than a repair: without it the documented user-run command could not find the plugin package at all.
