# CRW-1160 — the transcript tail is read without reading the whole transcript

Source: `plugins/codexclaw/components/pabcd-state/src/transcript.ts` `readTranscriptTail` (:41-46) at CXC v0.2.40 (commit 3c1459ac). The Go side is `ReadTranscriptTail` and `readTranscriptBytes` in `internal/pabcd/host/transcript.go`, read by the R-11 guards of `internal/pabcd/hook/prompt_trigger.go` and the Stop leg `internal/pabcd/hook/stop.go` through `ReadTranscriptGeneration` (CRW-1090). Found by the 10-10 CXC improvement review (A1-01, A6-02).

- Supersedes known-defects.md, section "Found by the host-state reads port", item beginning "`readTranscriptTail` reads the whole transcript to keep its last 64 KiB": now port: fixed (the file is opened once with O_NONBLOCK, judged a regular file by fstat of that descriptor, and at most 65,536 bytes of the size the stat saw are read with one ReadAt: the raw tail is the last min(size, 65,536) bytes, and the window of whole records the R-11 guards and the Stop read is, for a longer file, the 65,536 bytes that end one byte before its end. The first of them says whether the window after it starts a record, so a reader of whole records drops the first line of a window only when it is cut (a window that starts at a record boundary keeps its first record, `TestReadTranscriptGenerationKeepsTheFirstRecordOfAnAlignedWindow`, `TestReadTranscriptGenerationKeepsAnAlignedRecordWithinTheBound`); the file's last byte is left unread: every landed record ends in a newline, so the record that ends there is kept whole, and the records kept are the whole records in the last 65,536 bytes; a record whose newline has not landed yet is still being written and is not counted until it lands (cut by its last byte, it is no JSON object), where a read of that byte could have counted one whose closing brace had landed. The byte suffix, the Node-compatible decoding of a window that starts inside a rune, the short and empty file answers and the fail-open "" are unchanged. On a 64 MiB transcript each reader touches at most 65,536 bytes (`TestReadTranscriptTailReadsAtMostTheWindow`, `TestReadTranscriptTailDoesNotLoadTheWholeFile`), and short, long, invalid and rune-split windows decode as the whole-file reader did (`TestReadTranscriptTailDecodesAsBefore`)).
- Supersedes CRW-645.md, item beginning "`readTranscriptTail` reads the whole transcript before slicing its last 65,536 bytes": now port: fixed (as above; the read has no deadline still, but it is one bounded ReadAt of a regular file).
- The oracle's `readFileSync` of a FIFO, or of any path whose open waits, holds the hook until a writer appears (source `transcript.ts:43`); port: fixed (a FIFO, a directory or any file that is not regular answers "" at once, and the descriptor is closed: `TestReadTranscriptTailRefusesAFIFOAtOnce`, the "released" case of `TestReadTranscriptTailUnderAChangingFile`). A file that changes between the stat and the read is read best effort from the open descriptor and never widened to the whole file: an append past the stat is not seen, a truncation leaves a short read, a rename keeps reading the renamed file (`TestReadTranscriptTailUnderAChangingFile`). No tail is cached across processes.
