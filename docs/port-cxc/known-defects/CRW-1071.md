# CRW-1071 — store halt: the kept-acknowledgement confirmation and the recipient-turn check stop on a corrupting failure

Source: the follow-up CRW-945 left in its last record line (the acknowledgement verification and the turn checks of the same tick still turn a failure into a note); the Python oracle (CXC v0.2.40, commit 3c1459ac) has no store halt (the halt is the Go relay's own safety rule, docs/relay/invariants.md I-564, CRW-848), so no oracle file applies. The Go files are internal/relay/delivery/hostcheck.go (ConfirmDelivery, TurnChecks.Pass, ConfirmKeptAcks) and internal/relay/daemon/daemon.go (Tick).

- The kept-acknowledgement confirmation turned a failure into a note, or into the `error` field of the confirmation's outcome, and went on to the next confirmation and to the acknowledgement verification of the same tick, so a failure of the corrupting class never reached the daemon's halt branch (hostcheck.go, ConfirmKeptAcks and ConfirmDelivery; CRW-945 follow-up); port: fixed (`ConfirmKeptAcks` returns `([]string, error)`: a failure the classifier calls corrupting - the listing of the kept acknowledgements, marked as an observation, a confirmation's own reads and writes with the mark of the statement that met them, and the failure of the reconciliation `ConfirmDelivery` ran, which it now returns instead of reporting as `error: reconcile: ...` - ends the pass with the notes made before it, and `Tick` halts on it before the acknowledgements are verified, the turns checked or anything is delivered; any other failure stays the note or the `error` field it was. The command-line callers of `ConfirmDelivery` (`AckCommand`, `VerifyAcksCommand`) already returned its error and now also return a corrupting reconciliation failure. Cases: TestConfirmKeptAcksHalt_*, TestConfirmDeliveryHalt_* and TestHaltHostCheck_aCorruptingKeptAckListingHaltsTheTickBeforeTheDelivery, red on 810dd329f with the output kept with the handoff).
- The recipient-turn check turned the failure of its listing and of a turn's check (a loss settled, an undecided name recorded) into a note and went on to the next turn and to the delivery pass (hostcheck.go, TurnChecks.Pass; CRW-945 follow-up); port: fixed (`Pass` returns an `error`: a failure of the corrupting class ends the pass, the listing's as an observation and a turn check's with the mark of the statement that met it, and `Tick` halts on it, after merging the counts and notes of the checks made before it, before the idle edge, the delivery pass and the supervisor channel; any other failure stays the note it was. Cases: TestTurnChecksHalt_* and TestHaltHostCheck_aCorruptingTurnCheckHaltsTheTickBeforeTheDelivery, red on 810dd329f with the output kept with the handoff).
- Supersedes CRW-945.md, item beginning "Not covered by this issue and left as found": now port: fixed for `ConfirmKeptAcks` and `TurnChecks.Pass` (the acknowledgement verification, `VerifyPendingAcks`, was already halted on its error).
