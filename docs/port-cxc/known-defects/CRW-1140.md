# CRW-1140 — a resume at another cwd opens an empty IDLE state machine beside the work in flight

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/pabcd-state/src/state.ts:327` (every state path is `cwd/.codexclaw/sessions/<id>.json`) and `plugins/codexclaw/components/pabcd-state/src/hook.ts:604-612` (`handleSessionStart` runs `ensureState` in the payload cwd); the resume side is CRW's own (the oracle has no relay). The Go side is `internal/pabcd/stateroot` (`Check`, `Guard`, `Bootstrap`, the anchor under `<CRW_HOME>/state-roots/`), `internal/pabcd/hook/session_hooks.go` (`SessionHookSessionStart`), `internal/bridge/mutations.go` (`SendMessageToThread`), `internal/manage/childresume.go` (`resumeRun`) and `internal/relay/adapter/transport.go` (`guardedSend`). Found by the 10-10 combined review (B2-03).

- PABCD state is addressed by cwd and the SessionStart bootstrap creates a fresh IDLE state in whatever cwd the payload names (state.ts:327, hook.ts:606), so a thread resumed at another cwd gets an empty IDLE state machine beside the one it left in flight, and its phase, epochs and bound goalplan are detached from the session it runs in; port: fixed for relay-managed threads (the canonical root of a thread is the cwd the host reports for it before anything is resumed. Every CRW resume path — `send_message_to_thread`, `crw manage child-resume` including its dry run, and the relay's delivery — compares the cwd it would send with that root before thread/resume and refuses `state_root_conflict` when the root holds the thread's state in a work phase or a state file that cannot be read; the refusal names the preserved state file, nothing is moved or copied, and no newest copy is chosen. A symbolic-link alias of the root is the root. A bound source worktree is never taken for the root, so a session whose source is a linked worktree B keeps its state at A. Each resolution of a thread with state is recorded as its anchor, and the SessionStart bootstrap of an anchored thread creates no state in a cwd that is not the anchored root while that root holds work in flight, answering a SessionStart context that names the preserved state and the `--cwd` to use. The anchor is a local file, so no hook needs a running relay; a thread without one, a standalone terminal session, bootstraps in its payload cwd as the oracle does. A host that reports no cwd for the thread gives no root to compare, and the resume goes ahead as before. Relocation is an explicit handover to a thread started at the new cwd.
