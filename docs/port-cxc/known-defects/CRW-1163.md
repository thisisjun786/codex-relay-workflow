# CRW-1163 — the switch file's directory sync is part of its publication

Source: none in CXC v0.2.40: the hook switch (`<CODEX_HOME>/crw/switch.json`) is CRW's own activation gate (CRW-392, see `CRW-392.md`; the writer is CRW-201, see `CRW-201.md`). The Go file is `internal/hookswitch/write.go` (`WriteRaw`, `syncDir`, `ErrNotDurable`); the tests are `TestWriteRawReportsADirectorySyncFailureAsPublishedNotDurable`, `TestWriteRawAcceptsAFilesystemThatCannotSyncADirectory` and `TestSyncDirReportsAnOpenFailure` in `internal/hookswitch/write_test.go`. Found by the CRW-1142 review comment, from the CRW-201 code at d4e8128e1.

- `WriteRaw` renamed the synced temporary file into place and then dropped the error of opening and syncing the directory, so `crw install switch` reported success when a power loss could still undo the rename, although the comment promised the directory was synced; port: fixed (both errors are returned as `ErrNotDurable`, which wraps the cause and whose message says the file is in place and its durability is not confirmed, so the failure is told apart from one that published nothing. `crw install switch` treats it as a failed step and undoes the steps before it. A directory that gives no sync at all (EINVAL, ENOTSUP, ENOSYS) is not an error, because there is nothing to confirm; every other error, including a directory that cannot be opened, is. Red on dc758b3c7).
