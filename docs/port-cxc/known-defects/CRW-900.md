# CRW-900 — shell-write reader: the destination of a Python copy, rename or link call

Source: CXC v0.2.40 commit 3c1459ac. Oracle files:
`plugins/codexclaw/components/pabcd-state/dist/shell-write-destinations.js` (`scriptWriteDestinations` :532-549, whose
three patterns read `open(...)`, `Path(...).write_text/bytes` and the JavaScript `writeFile*` family) and
`plugins/codexclaw/components/pabcd-state/dist/memory-write-gate.js` (`handleMemoryWriteGate`, which classifies a shell
command by the destinations `shellWriteDestinations` returns). Go files of the port:
`internal/pabcd/hook/shellwrite_verbs.go` (`shellVerbScriptWrites`, `shellWriteExecScan`, `shellVerbPythonNode`) and
`internal/pabcd/hook/memorygate.go` (`memoryGateClassify`, which feeds those destinations to the gate). The pinned
divergences live in `internal/dev/cxcfuzz/testdata/shellwrite/cases.json` and
`internal/dev/cxcfuzz/testdata/memorygate/cases.json`.

## Defects

- The oracle `scriptWriteDestinations` names only `open(...)` and `Path(...).write_text/bytes`, so the destination of
  `shutil.copy`, `shutil.copy2`, `shutil.copyfile`, `shutil.copytree`, `shutil.move`, `os.rename`, `os.replace`,
  `os.renames`, `os.link`, `os.symlink`, `Path(a).rename(b)`, `Path(a).replace(b)`, `Path(b).symlink_to(a)` and
  `Path(b).hardlink_to(a)` is invisible to it; a `python3 -c` program that copies or renames a file into the memories
  root therefore passes the oracle memory gate (source `shell-write-destinations.js:532-549`; port: fixed, security —
  the port names those destinations in its hardened program walk, so the gate denies the write, while the oracle own
  answer stays as it is and the divergence is pinned `intentionally-changed` as
  `crw857-gap-copy-destination-not-named` and `crw857-gap-memorygate-copy-into-root`).

## Supersedes

- Supersedes known-defects/CRW-857.md, section "Gap the widened grammar exposed", item beginning "The destination of
  `shutil.copy`, `shutil.copyfile` and `os.rename` is their SECOND argument": now port: fixed (security; the reader in
  `internal/pabcd/hook` names the destination of the copy, rename and link calls the issue lists, and the two pinned
  cases the gap left `identical` are re-pinned `intentionally-changed` with their record lines updated).
