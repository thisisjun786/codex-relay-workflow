# CRW-900 — shell-write reader: the destination of a Python copy, rename or link call

Source: CXC v0.2.40 commit 3c1459ac. Oracle files:
`plugins/codexclaw/components/pabcd-state/dist/shell-write-destinations.js` (`scriptWriteDestinations` :532-549, whose
three patterns read `open(...)`, `Path(...).write_text/bytes` and the JavaScript `writeFile*` family) and
`plugins/codexclaw/components/pabcd-state/dist/memory-write-gate.js` (`handleMemoryWriteGate`, which classifies a shell
command by the destinations `shellWriteDestinations` returns). Go files of the port:
`internal/pabcd/hook/shellwrite_verbs.go` (`shellVerbScriptWrites`, `shellWriteExecScan`, `shellVerbPythonNode`),
`internal/pabcd/hook/shellwrite_structural.go` (the write names the destination reader cannot attribute) and
`internal/pabcd/hook/memorygate.go` (`memoryGateClassify`, which feeds those destinations to the gate). The pinned
divergences live in `internal/dev/cxcfuzz/testdata/shellwrite/cases.json` and
`internal/dev/cxcfuzz/testdata/memorygate/cases.json`.

## Defects

- The oracle `scriptWriteDestinations` names only `open(...)` and `Path(...).write_text/bytes`, so the destination of
  `shutil.copy`, `shutil.copy2`, `shutil.copyfile`, `shutil.copytree`, `shutil.move`, `os.rename`, `os.replace`,
  `os.renames`, `os.link`, `os.symlink`, `Path(a).rename(b)`, `Path(a).replace(b)`, `Path(b).symlink_to(a)` and
  `Path(b).hardlink_to(a)` is invisible to it; a `python3 -c` program that copies or renames a file into the memories
  root therefore passes the oracle memory gate (source `shell-write-destinations.js:532-549`; port: fixed, security —
  the port names those destinations in its hardened program walk, so the gate denies the write, while the oracle own
  answer stays as it is and the divergence is pinned `intentionally-changed` as
  `crw857-gap-copy-destination-not-named` and `crw857-gap-memorygate-copy-into-root`).

- A compound statement's import on the same line as its header was dropped: `if True: from shutil import copy; copy("/w/a", m)`
  and `if True: import shutil as s; s.copy(...)` bound nothing, so the copy's destination went unnamed (CRW-900 pre-merge
  evaluation d1); port: fixed (a colon at depth 0 ends a compound header, and the statement after it is read on its own.
  Pinned by TestShellCopyDestinationCompletion and TestMemoryGateDeniesCompletedCopyShapes).

- An import alias named like a module was not read: `import shutil as os; os.copy(...)` and `import os as shutil;
  shutil.rename(...)` took the name's own module and ignored the alias (CRW-900 pre-merge evaluation d2); port: fixed (a call
  on a name an import bound is read as the module that import bound: `import shutil as os` reads `os.copy` as
  `shutil.copy`, and `import os as shutil` reads `shutil.rename` as `os.rename`).

- A from-import alias lost its function's keyword rules: `from os import renames as mv; mv(old=..., new=m)` took dst= rather
  than new=, and `from os import rename as renames; renames(src=..., dst=m)` took new= rather than dst= (CRW-900 pre-merge
  evaluation d3); port: fixed (a from-import binds the local name to module.function, and the destination keyword follows
  that function; a name bound to both os.renames and another copy function names the destination under either keyword).

- An import binding was outranked by the spelling rules for Path and open: `from shutil import copy as Path; Path("/w/a", m)`
  was read as the pathlib constructor, and `from os import rename as open; open("/w/a", m)` as the builtin open (CRW-900
  post-merge evaluation D4, LEDGER-CRW-900-d4); port: fixed (a call whose name an import bound to a copy function is
  classified as that function before the spelling rules for Path, open and exec).

- The binding decides a call before the spelling does (CRW-900 pre-merge evaluation of 0e215a28, findings d1 and d2). A call
  on a name an import bound reads only the modules that import bound, so `import json as shutil; shutil.copy("/w/a", m)`
  names no shutil destination, and an os or shutil alias of the other module names what that module does: `import os as shutil;
  shutil.rename("/w/a", "/w/b")` and `from shutil import copy as c; c(m, "/w/b")` are allowed without a grant. A binding to any
  other module makes a copy, rename or link call unknown, because that module's function may write where the reader cannot see.
  The memory gate (`shellIRStructuralWriteUnknown`, `shellIRPyUnattributedCall`) accepts a from-import of a copy, rename or link
  function of shutil or os (one name or a comma list, with or without an alias) when every use of the name it binds is a call,
  and an os or shutil alias of the other module when that alias is the only binding and the name is not a parameter or
  assignment. A name whose value is taken (`f = c`, `g(c)`) and a parameter named like a module stay unknown; port: fixed
  (the allowed controls pass, and the names that could write where the reader cannot see are denied as unknown).
  Pinned by TestShellCopyDestinationCompletion, TestMemoryGateDeniesCompletedCopyShapes and the reproduction rows
  CRW-900-D2-03..06, D4-03..06, C-04..C-08.

- The completion's test matrix covers the function-body and indented-block import variants, the json-as-os control and the
  list forms, and checks each named destination, not only that a write was attempted (CRW-900 pre-merge evaluation of
  0e215a28, finding d3).

## Deliberate reading

A copy, rename or link call on a name an import bound to a module other than shutil or os is unknown, not "no destination".
The reader cannot know what that module's function writes, so the control `import json as os; os.rename(...)` names the unknown
destination and is refused by the memory gate in a session without a grant. This is the fail-closed direction; the reader
names no concrete path for it.

## Relation to PR #837

and by the post-merge evaluation (LEDGER-CRW-900-d4). PR #837 merged the first part of the issue; CRW-900 carries the completion of

entries above record the fixes for d1 to d4.

## Limits kept

- A copy-named call that the reader cannot attribute stays refused in a session without a grant: a star import
  (`from shutil import *`), a name whose value is taken, a parameter named like a module, and a call on a name bound to a
  module other than shutil or os. Each is fail-closed over-blocking, not a bypass.
