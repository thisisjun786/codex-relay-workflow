# CRW-900 — shell-write reader: the destination of a Python copy, rename or link call

Source: CXC v0.2.40 commit 3c1459ac. Oracle files:
`plugins/codexclaw/components/pabcd-state/dist/shell-write-destinations.js` (`scriptWriteDestinations` :532-549, whose
three patterns read `open(...)`, `Path(...).write_text/bytes` and the JavaScript `writeFile*` family) and
`plugins/codexclaw/components/pabcd-state/dist/memory-write-gate.js` (`handleMemoryWriteGate`, which classifies a shell
command by the destinations `shellWriteDestinations` returns). Go files of the port:
`internal/pabcd/hook/shellwrite_verbs.go` (`shellVerbScriptWrites`, `shellWriteExecScan`, `shellVerbPythonNode`) and
`internal/pabcd/hook/memorygate.go` (`memoryGateClassify`, which feeds those destinations to the gate). The pinned
divergences live in `internal/dev/cxcfuzz/testdata/shellwrite/cases.json` and
`internal/dev/cxcfuzz/testdata/memorygate/cases.json`.

## Defects

- The oracle `scriptWriteDestinations` names only `open(...)` and `Path(...).write_text/bytes`, so the destination of
  `shutil.copy`, `shutil.copy2`, `shutil.copyfile`, `shutil.copytree`, `shutil.move`, `os.rename`, `os.replace`,
  `os.renames`, `os.link`, `os.symlink`, `Path(a).rename(b)`, `Path(a).replace(b)`, `Path(b).symlink_to(a)` and
  `Path(b).hardlink_to(a)` is invisible to it; a `python3 -c` program that copies or renames a file into the memories
  root therefore passes the oracle memory gate (source `shell-write-destinations.js:532-549`; port: fixed, security —
  the port names those destinations in its hardened program walk, so the gate denies the write, while the oracle own
  answer stays as it is and the divergence is pinned `intentionally-changed` as
  `crw857-gap-copy-destination-not-named` and `crw857-gap-memorygate-copy-into-root`).

- A compound statement's import on the same line as its header was dropped: `if True: from shutil import copy; copy("/w/a", m)` and `if True: import shutil as s; s.copy(...)` bound nothing, so the copy's destination went unnamed (CRW-900 pre-merge evaluation d1); port: fixed (a colon at depth 0 ends a compound header, and the statement after it is read on its own. Pinned by TestShellCopyDestinationCompletion and TestMemoryGateDeniesCompletedCopyShapes).
- An import alias named like a module was not read: `import shutil as os; os.copy(...)` and `import os as shutil; shutil.rename(...)` took the name's own module and ignored the alias (CRW-900 pre-merge evaluation d2); port: fixed (a call's module name is read together with every module an import bound to that name, and both readings count).
- A from-import alias lost its function's keyword rules: `from os import renames as mv; mv(old=..., new=m)` took dst= rather than new=, and `from os import rename as renames; renames(src=..., dst=m)` took new= rather than dst= (CRW-900 pre-merge evaluation d3); port: fixed (a from-import binds the local name to module.function, and the destination keyword follows that function; a name bound to both os.renames and another copy function names the destination under either keyword).
- An import binding was outranked by the spelling rules for Path and open: `from shutil import copy as Path; Path("/w/a", m)` was read as the pathlib constructor, and `from os import rename as open; open("/w/a", m)` as the builtin open (CRW-900 post-merge evaluation D4, LEDGER-CRW-900-d4); port: fixed (a call whose name an import bound to a copy function is classified as that function before the spelling rules for Path, open and exec).
- Kept: a copy or rename outside memories written through an alias (`import os as shutil; shutil.rename("/w/a", "/w/b")`, `from shutil import copy as c; c("<memories>/n.md", "/w/b")`) is refused by the memory gate as a destination it cannot read. The gate's shell-write destination reader does not resolve these aliases, so the refusal is fail-closed over-blocking and not a bypass; port: kept (outside the criteria of CRW-900; the allowed controls use the plain forms, which pass).

## Supersedes

- Supersedes known-defects/CRW-857.md, section "Gap the widened grammar exposed", item beginning "The destination of
  `shutil.copy`, `shutil.copyfile` and `os.rename` is their SECOND argument": now port: fixed (security; the reader in
  `internal/pabcd/hook` names the destination of the copy, rename and link calls the issue lists, and the two pinned
  cases the gap left `identical` are re-pinned `intentionally-changed` with their record lines updated).
