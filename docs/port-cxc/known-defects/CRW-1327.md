# CRW-1327 — the tokens of a run were shown without their cached part, and the design loop's caps were not written down

Source: CRW's own design, not the CXC oracle (CXC v0.2.40, commit 3c1459ac): the oracle has no flow engine and no design loop. The Go and script side is `internal/flow/engine/backend.go` (`Tokens`: `CachedInput`, `ReasoningOutput`, `Add`, `Sub`, `FreshInput`), `internal/flow/engine/budget.go` (`RowTokens`, `TerminalTokens`), `internal/flow/engine/call.go` and `session.go` (the parts summed and harvested), `internal/flow/backend/agent/session.go` and `turn.go` (the host's parts), `internal/flow/cli/runs.go` (`TokenSplit`), `read_cmds.go` (`ps`, `show`), `digest.go` (the budget line), and `internal/flow/workflows/project-lane.js` (`AUDIT_ROUNDS`, `DESIGN_TOKEN_CAP`, `DESIGN_TOKEN_WARN`, `auditedDesign`) and `internal/flow/workflows/lib/lane.js` (`explore`: the `tokens` of its explorers). Found by the 10-13 field trial (CRW-1315 items 34 and 39).

- The journal recorded a call's tokens as input, output and total: the rollout's `token_count` (CRW-1332's `sessionhost.Usage`) and the App Server's `tokenUsage` carry the cached input and the reasoning output, which the adapters dropped, so `crw flow show` printed 4,218,262 tokens for an architect call whose input of 4,171,534 was 4,006,518 cached; port: fixed (`engine.Tokens` has the host's parts, `cached_input` and `reasoning_output` in a row, left out when 0, so a row of an older version and a run whose host reports no cached input read them as 0 and write the rows they wrote. Session calls (CRW-1331) take the growth of the rollout total in every part, App Server calls the growth of the thread total. `crw flow show` prints the run's and each call's tokens with the split `cached input, fresh input (the input minus the cached), output, reasoning`, `crw flow show --json` and `ps --json` give `token_split`, `crw flow ps` has the columns `CACHED`, `FRESH` and `OUTPUT`, and the digest's token budget line carries the split. Pinned by `TestTokensShowCachedFreshAndOutput`, `TestSessionTokensKeepTheCachedSplit` and `TestSessionHostTokensKeepTheCachedSplit`).
- A reading of the run's tokens (`ps`, `show`, the digest) summed the completed, held, null_model and refused rows of a call; it now sums every terminal row of an agent call (`engine.TerminalTokens`), the rule the run's budget is held to (CRW-1278.md), so a superseded or unknown row that carries tokens counts there too; port: fixed.
- The caps of the design loop were in the code and nowhere else, and reaching them told nobody beyond the escalation of the round cap; port: fixed (they are written down in `docs/flow/script.md`, "The caps of the design loop", and beside the loop in `project-lane.js`: the round cap `AUDIT_ROUNDS` (3) stops the milestone with the `design_audit_rounds` escalation as CRW-1347 decided, and the token cap is `DESIGN_TOKEN_CAP` (5,000,000 tokens), or `DESIGN_TOKEN_WARN` (0.8) of `budget.total` when the run has a lower budget, so a run without a budget, as the 10-13 field runs were, has it too: when the calls of one loop (its architect, audit and fix calls and the explorers `crw.explore` spawns for its open questions, by their results' tokens) reach it, the loop raises the `design_loop_tokens` escalation, which asks nothing, goes up to the orchestrator thread like any escalation, and does not stop the loop. Either cap writes the log row `warn design_loop_cap ...`. Pinned by `TestDesignLoopCapsWarnAndTellTheOrchestrator`, with a run that has no budget and a loop whose explorer reaches the cap).
- Named limit: the trace export (`internal/flow/trace`) keeps input, output and total, so `crw flow measure` reads no cached input and its thread reuse figures stay the evidence of the cache; the trace golden is unchanged; port: kept.
- Named limit: `project-lane.js` changed, so a project lane or night batch started by an earlier binary is not resumed by this one (the script digest is not the run's), as for every change of the built-in workflow; such a run is finished by the binary that started it. A resume whose `--token-budget` narrows the budget changes `budget.total`, so the token cap of a replayed loop may be met at another round than in the process that ran it; port: kept.
