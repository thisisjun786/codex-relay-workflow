# CRW-1278 — the token budget of a night batch held each process, and a foreground resume did not pause

Source: CRW's own design (0.5.0-alpha, issue F12 follow-up), not the CXC oracle: the flow engine has no counterpart in CXC v0.2.40 (commit 3c1459ac). The Go side is `internal/flow/engine/budget.go` (`RunSpent`, `RowTokens`), `internal/flow/engine/engine.go` (`Config.SpentBefore`), `internal/flow/engine/resumecli.go` (`ResumeHold.Budget`), `internal/flow/cli/resume.go` (`runBudget`, `budgetLeft`, `resumeHold`, `pauseOnSignal`), `internal/flow/cli/answer.go` (`resumeDetached`) and `internal/flow/cli/process.go` (`execute`). Found by the last Opus verification of the CRW-1205 close round (head 09151552).

- Supersedes CRW-1205.md, item beginning "`crw flow resume RUN SCRIPT` is the engine's command": its last sentence said the budget was a ceiling of the process; now port: fixed (the budget is the run's. The tokens a run spent are the sum of the tokens of the terminal rows of its agent calls (`engine.RunSpent`): a call writes one terminal row in each process that ends it, with only what that process spent on it, so a resume counts each token once; a row written before CRW-1327 reads as before. A resume - `crw flow resume RUN` in the foreground or `--detach`, and `crw flow resume RUN SCRIPT` - allows the spec's budget minus that figure (`runBudget`); a `--token-budget` narrows the remainder and never widens it, and the spec's budget stays the upper bound (0, below 0 or above it is refused as before). The engine starts with the spent figure (`Config.SpentBefore`), so `budget_warning` and the pause at 100% are judged on the run's figure, and `budget.spent()` and the result's tokens are the run's. A run with nothing left is not resumed: the command reports `budget_exhausted`, the tokens spent and the decision, and says that more budget is a new decision; the run is not taken (no started row). `crw flow resume RUN --detach` and the resume of `crw flow answer` read the same figure before they start a run process (`budgetLeft`), so they refuse with that report and start none; the run process judges it again under the run lock. Pinned by `TestNightBatchResumeDoesNotRefillTheBudget`, `TestDetachedResumeRefusesAnExhaustedBudget`, `TestAnswerDoesNotResumeAnExhaustedBudget` (the answer is applied and its resume refused), `TestRunBudgetNarrowsTheRemainder` and `TestRunSpentCountsEachTerminalRowOnce`).
- A resumed run that started at or past 80% of its ceiling after an earlier process had written its `budget_warning` row wrote a second one at its first turn, since the warning was the process's; port: fixed (the run warns once: a run whose journal holds its `budget_warning` row starts warned, and one whose earlier processes never warned warns when it reaches 80% of its own ceiling. Pinned by `TestResumedRunWarnsOfItsBudgetOnce`).
- A foreground `crw flow resume RUN SCRIPT` had no SIGUSR1 handler and `crw flow resume RUN` did not listen for SIGUSR1, so `crw flow pause` ended the process by Go's default instead of pausing it; port: fixed (both bind the run to an `engine.Control` and answer SIGUSR1 with the pause `operator: crw flow pause` of the run process: the run writes `run_paused`, the calls end held `engine_paused`, the process returns, and a later resume goes on. The SCRIPT path binds a Control also when the spec has no deadline. Pinned by `TestForegroundResumePausesCleanlyOnSIGUSR1`).
- Named limit: the tokens a process spent on a call it never ended (it was killed mid-call, so it wrote no terminal row) are in no row, and the run's figure leaves them out; a reconcile's recovered turn records none either. The figure is what the journal proves; port: kept.
- `crw flow resume RUN SCRIPT` of a run without a spec (no `crw flow start` made it, or its spec is gone) started its figure at 0, the per-process figure this issue removes: the engine's command read what the run spent only through the spec's budget hold; port: fixed (`resumeCmd` counts `RunSpent` for every resume, so `budget.spent()`, the result's `tokensSpent` and the budget warning are the run's figure, and a `--token-budget` of such a resume is what it may spend on top of it, the ceiling being the spent figure and that many tokens. Pinned by `TestScriptResumeWithoutASpecCountsTheRunsSpending`).
- Named limit: a run that no `crw flow start` made has no spec and so no budget of the run: each resume of it is held to its own `--token-budget` (that many tokens more than the run spent). A run whose spec sets no budget gets none, and a `--token-budget` given to its resume allows the same, as the flag's help says (the tokens this resume may spend); port: kept.
