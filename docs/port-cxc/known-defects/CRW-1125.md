# CRW-1125 — recall query words, chat scan, query conditions and flag residue

Source: CXC v0.2.40 (commit 3c1459ac) `plugins/codexclaw/components/recall/src/`: `synonyms.ts`, `query-words.ts`, `chat-search.ts`, `index-search.ts` and `cli.ts`. The Go side is `internal/recall/synonyms.go`, `querywords.go`, `chatscan.go`, `chatsearch.go`, `indexquery.go`, `indexsearch.go`, `cli.go`, `cliflags.go` and `rollout.go` (the `foldCwdCaseSeam` test seam). The items are the 10-10 CXC improvement review's fix-now list for the recall query and chat-scan lines of known-defects.md (A8 kept); each was reproduced before it was changed, and the red output is under the lane's evidence directory. The recorded oracle corpora keep the oracle's answer and the cases the port answers differently are listed beside them in `testdata/oracle-query-words-port-fixed.json`, `testdata/chatscan/port-fixed.json` and `testdata/indexquery/port-fixed.json` (the CLI case is checked in `TestRecallCLIRecordedOracle`).

- Supersedes known-defects.md, section "Found by the recall query words port", item beginning "The 하-verbalizer tail rule": now port: fixed (the tail is judged at the leftmost 했, 하 or 해 among the last four syllables that leaves a stem, so a word that begins with one of them keeps looking: `해결했지` and `해결하다` give `해결`, `하배포해` gives `하배포`; a one-syllable stem is still refused (`이해`, `오하해하`, `하하하하하`). `KoreanStem` in synonyms.go; pinned by `TestSweep1125HaVerbTailKeepsAStem`, `TestKoreanStemOracleQuirks` and the stem and expand cases of `oracle-query-words-port-fixed.json`).
- Supersedes known-defects.md, section "Found by the recall query words port", item beginning "`isSymbolWord` takes any 7 to 40 characters": now port: fixed (a 7 to 40 character word of a to f and digits is a commit SHA when it holds a digit, or when it is twelve characters or longer; `defaced`, `deadbeef` and `decaffe` are ordinary words, searched as substrings instead of on token boundaries and not required, so the literal still finds itself inside a longer token. `isCommitShaWord` in querywords.go; pinned by `TestSweep1125HexWordIsNoShaWithoutADigit` and the symbol, required and expand cases for `defaced` and `deadbeef` in `oracle-query-words-port-fixed.json`).
- Supersedes known-defects.md, section "Found by the CRW-508 recall chat scan port", item beginning "Scan limits are applied": now port: fixed (the scan reads every rollout of the window and keeps the newest `limit` matches by timestamp, equal timestamps in the order found; the final order is unchanged. `scannedFiles` and `matchedFiles` therefore count every file read, not the files up to the limit. `searchViaScan` in chatscan.go; pinned by `TestSweep1125ScanLimitKeepsTheNewest` and the `chronology` and `dense` cases of `testdata/chatscan/port-fixed.json`).
- Supersedes known-defects.md, section "Found by the CRW-508 recall chat scan port", item beginning "Reaching the limit can report truncation": now port: fixed (a scan is truncated exactly when a further eligible match, one that passed the file, source, role, window and text filters, did not fit; another unread entry or file, and a limit reached on the last entry, no longer decide. Pinned by `TestSweep1125TruncatedNeedsAnotherEligibleMatch` and the recorded limit cases of `testdata/chatscan/port-fixed.json`).
- Supersedes known-defects.md, section "Found by the CRW-508 recall chat scan port", item beginning "A fractional context window": now port: fixed (the window is a whole number of entries: a fraction is floored, a negative one is zero, an infinite one is capped at 200 on each side, and NaN is refused with a message that names `--context`. The index path takes the same number. `normalizeChatScanShared`; pinned by `TestSweep1125ContextIsNormalized` and the context cases of `testdata/chatscan/port-fixed.json`).
- Supersedes known-defects.md, section "Found by the CRW-508 recall chat scan port", item beginning "Positive days outside": now port: fixed (a window whose start is no date is refused before anything is read, with `--days N is out of range: no date lies that many days before now`; the command line refuses it as a flag error before the query, the home or the index is looked at, and the scan refuses it also for an empty query. `chatScanCutoff`, `recallCLIChatSearch`; pinned by `TestSweep1125DaysOutOfRangeIsRefusedAtTheEntry`).
- Supersedes known-defects.md, section "Found by the CRW-508 recall chat scan port", item beginning "A NaN limit defeats": now port: fixed (a limit that is NaN or infinite is refused with a message that names `--limit`; a finite one is floored and held between 1 and 200 for the scan and for the index alike. `normalizeChatScanShared`; pinned by `TestSweep1125LimitIsFiniteAndCapped`).
- Supersedes known-defects.md, section "Found by the CRW-508 recall chat scan port", item beginning "The raw JSON file prefilter": now port: fixed (already by CRW-1123: the scan judges a file on its content with every JSON escape decoded, `prefilterText` in rollout.go, see CRW-1123.md; no change here. Shown again by `TestSweep1125EscapedQueryCharactersAreFound`, which finds `CI` for `CI` and an escaped quote through the scan).
- Supersedes known-defects.md, section "Found by the CRW-507 recall query-condition port", item beginning "Short words use SQLite's ASCII-only": now port: fixed (the SQL for a word of one or two letters keeps its ASCII LIKE and adds one case-sensitive `instr` per spelling of the word's letters that SQL cannot fold, `Ü` for `ü`, the Kelvin sign for `k`, `İ` for `i`, so no row the final Unicode predicate accepts is cut off before it. A word SQL folds completely (`ab`) keeps its recorded SQL. `wordCondition` and `shortWordSpellings` in indexquery.go; pinned by `TestSweep1125ShortWordsAreFoldedLikeTheFinalPredicate`, the word, group, filter and candidates cases of `testdata/indexquery/port-fixed.json`).
- Supersedes known-defects.md, section "Found by the CRW-507 recall query-condition port", item beginning "With cwd case folding enabled": now port: fixed (on a case-folding host the index lists the distinct stored cwd values, asks the scan's own predicate `CwdMatches` (folded) for each and scopes with `f.cwd IN (...)`, so the index and the scan accept the same sessions, `/Ü/child` for `/ü` included; a set of more than 10,000 distinct values keeps the SQL predicate. `resolveFoldedCwds`, `candidateFilterFor`; pinned by `TestSweep1125FoldedCwdScopesIndexAndScanAlike`, which runs the folding branch on any platform through `foldCwdCaseSeam`).
- Supersedes known-defects.md, section "Found by the CRW-507 recall query-condition port", item beginning "An embedded NUL": now port: fixed (a query word with a NUL is not sent to FTS5: the index returns `a query word holds a NUL character, which the index cannot search` before it is opened or refreshed, and `SearchChat` serves the query by the scan with that reason in its "index unavailable" warning. `planHasNUL`; pinned by `TestSweep1125NULWordIsServedByTheScan`).
- Supersedes known-defects.md, section "Found by the recall format and flag port", item beginning "Help detection scans every argument": now port: fixed (`WantsHelp` stops at the `--` terminator, so `crw recall chat search -- --help` searches for the word; the same holds for `-h`. Pinned by `TestSweep1125HelpStopsAtTheTerminator`, `TestRecallReadFlagsAndHelpPrecedence` and the `help` cases of `TestRecallFlagsOracle`).
- Supersedes known-defects.md, section "Found by the recall format and flag port", item beginning "Explicit home validation checks existence only": now port: fixed (`--home` must name a directory: `--home is not a directory: PATH`, before any reader opens it. `ExplicitHome`; pinned by `TestSweep1125ExplicitHomeMustBeADirectory` and `TestRecallExplicitHome`).
- Supersedes known-defects.md, section "Found by the CRW-381 recall chat-search entry port", item beginning "The entry computes a positive-days cutoff": now port: fixed (the entry and the scan judge the window for every query, an empty one and a forced scan included, before the origin callback, and name `--days` in the refusal instead of `Invalid time value`; the `invalid-days` case of `TestChatSearchRecordedOracle` expects the new message. `SearchChat`, `searchViaScan`).
