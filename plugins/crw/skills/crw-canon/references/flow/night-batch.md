
## The night batch

A night batch is a decision and a run. The parent selects the issues (`crw manage batch plan`, 1040a) and records the decision with `crw manage batch decide --plan FILE --flow-plan PLAN --milestone M --handoff FILE --token-budget N --deadline T`: a user-decision record (kind `policy`, options `run` and `skip`) whose context is the batch document (`crw-night-batch/1`: the label, the issues, the plan and milestone whose nodes they are, the token budget, the deadline, and the handoff the plan was compiled from by its path and sha256), raised and answered `run` through the relay's decision commands. `crw flow start night-batch --decision D` reads that record, refuses one that is not answered `run` or whose handoff file changed since the decision, pins the handoff, and starts the run for those issues with the decision's budget and deadline; `--token-budget` and `--deadline` may only lower the budget and bring the deadline forward, a larger budget, a later deadline and a negative budget are refused. The run is the project lane over the milestone, after a check that the milestone's nodes are exactly the selected issues; releases happen only inside it, so there is no freeze and no grant table. The run stops at its token budget (the calls that would send end held `budget_exhausted`) and pauses at its deadline; what did not land is carried, with the reason. A milestone whose nodes are not the selection releases nothing: the run asks the parent (`night_batch_selection`), stays `held`, and its digest lists every issue as needing a decision with the plan's difference. `crw flow digest RUN` and `crw manage batch report --digest FILE` make the morning report. A run whose process was killed is taken again by `crw flow resume RUN`, builds nothing it already landed, and goes on with the rest.
